# 基于证据的智能选图与多图交付（2026-10-30）

## 问题和目标

ChemClaw 已有原生 `show_view`（SVG + 7 种 ECharts）、GenUI `dsh-ui` 和按需渲染，但此前全局提示偏重单张、旧组件优先；回合交付检查只判断是否已经有**任意**视图。复杂问题可能丢失独立分析维度，用户点名热力图、桑基图、时间轴时可能以无关的折线图结束。

本次以低风险方式补齐**选择规则与可验证的显式需求**，不改 DSH/GenUI 插件内部实现、不新增模型请求、不修改用户数据或现有前端。

## 决策算法

1. **同轮内部 ChartPlan**：模型使用既有研究结果，识别独立问题、指标、数据维度、可用证据及最佳组件；不引入新工具或第二次 LLM 调用，也不把计划作为可见附件。基础事实只需一张小卡；复杂分析如价格趋势、区域矩阵、已量化流量、事件历史，可按独立关系交付多个互补视图，通常 2–5 张，更多只在确有独立价值时使用。
2. **类型优先**：原有 SVG 适合简单趋势/比较；ECharts `scatter/radar/heatmap/funnel/treemap/sankey/gauge` 只在符合数据条件时使用；GenUI 时间轴、流程图及复杂交互组件按需补充。只知道产业链边但不知道交易量时，用流程图而不是捏造桑基图流量。
3. **去重标准**：按分析问题与指标、维度和关系比较，不按图的外观或单纯行数判断。只有相同数据且同样目的才视为重复；供需热力图与价格趋势不是重复。多图可组合为一组原生视图、独立 `show_view` 调用或 GenUI 块，不强制更换旧图表。
4. **保留性能和限制**：无新常规模型请求；ECharts/GenUI 仍原有按需加载；交互独立于 LLM。尊重显式纯文字、取消、子代理、Bot 对 Bot、群中继和已有 GenUI 的修复预算。

## 回合末的有界验证

- 使用已经成功交付的 `show_view` 结构（正常执行时通过 `noteVisualDelivery`，重放时若事件附带输入则从已成功的工具结果还原）及可解析的 `dsh-ui` 块登记交付种类。
- 只有**用户明确要求绘制某一种支持的高级图表/时间轴**时，且成功交付了可识别、却不匹配的其他视图，才触发一次只补缺失视图的提醒。
- 没有图表时延续此前的通用一次补救；如果交付种类无法可靠识别，不将未知等同于失败，避免错误重复。
- 对无法完成的数据或渲染条件，只描述限制，不伪造观测值；不检查抽象的“模型心中计划”是否齐全，不根据文本多少硬凑图。
- 上游 GenUI 负责围栏自身的语法/渲染错误；Host 不判断 DOM 成功与否。前端 ECharts 仍保留失败时展示表格的路径。

## 边界和后续验收

当前“Advanced charts”是前端渲染开关：禁用后 ECharts 展示数据表；GenUI 非图表能力不在该开关控制范围。本 PR 不重新定义该设置或改动生成的 `client.js`；需要另行决定是否添加“交付偏好”并让前后端共享开关状态。也不承诺本次可自动审计模型遗漏的所有隐含分析维度：只能在模型提示层面要求自检、在 Host 检查可确定的用户点名图表。

须核对：
- 单点与多维问题、真实有缺口的数据及桑基图数量前提。
- 手动点名热力图/时间轴、无关图不算履约、用户禁图/内部对话等豁免。
- 私聊、群聊和普通 DSH Agent；GenUI 实际能力须来自安装环境，不能从 package.json 的依赖推断已运行。
- `npm test`、`npm run lint`、构建一致性与独立 mock smoke；真实模型是否自动选择多图还需要人工桌面验收并在 PR 中记录，未验收前不得宣称完全修好。
