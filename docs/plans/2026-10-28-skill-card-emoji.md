# 技能卡片与 Emoji

按用户此次界面评审，技能使用系统原生彩色 Emoji 与统一圆角底座，
不使用专家或群聊头像，也不引入第三方图标资源。

## 卡片

沿用专家与群聊的卡片、字体、间距与「你可以这样问」区块。
卡片显示名称、业务分类、用途、一个示例、安装来源及操作按钮。
交付文件仅保留在「查看详情」中。详情与卡片使用同一图标。

## 内置技能

`src/shared/skill-presentation.js` 按 118 个稳定技能 ID 逐项维护 Emoji
与具体示例问法，避免将岗位示例误配给岗位下的每个技能。
工厂为 🏭，行情为 📈，合同为 📜，成本测算为 🧮，客户跟进为 💬，
产业链结构为 🕸️，库存为 📦，分子分析为 🧬。
同类用途允许共用 Emoji，不强求每个技能都有不同符号。
自动图标由展示层读取，不改写原始 SKILL.md 或 Bot 的执行指令。

## 新建、导入与修改

1. 手动选择的 `emoji` 优先，并随技能索引保存；空字符串表示自动匹配。
2. 已知原始技能名的导入继承已有目录的用途、Emoji 和具体示例。
3. 未知技能先匹配名称，再匹配描述，最后按业务分类兜底；
   无法识别时用 🧰，不按名字随机分配，也不为分类调用模型。
4. 新建、导入预览和详情编辑都有图标预览与紧凑 Emoji 网格面板。
   用户可以随时改选，或恢复自动匹配；替换安装默认保留手动选择。
   面板宽 280px，桌面每行 6 个图标，默认只显示 12 个相关推荐；
   点「更多图标」才展示完整集合，展开内容限制高度并在内部滚动。
   小屏幕限制宽度，触屏每行 5 个以保留点击空间。支持点外部、Escape 关闭，
   键盘方向键移动与 Enter 选择；选择、Escape 和关闭按钮会恢复触发按钮焦点。
   表单保存后的滚动与布局变化会重新定位面板，避免刚打开就自动关闭。
5. 外部技能没有示例时，展示带任务需求与资料占位符的通用问法，
   不编造该技能支持的业务能力。

Emoji 的具体字形由操作系统提供，Windows 与 macOS 的绘制可能不同。
没有新增第三方美术资源或字体，也不需要额外下载。

## 验证

检查所有内置技能都有明确图标与示例，名称优先于描述，未知技能有兜底。
验证手动选择保存、重载、替换导入、已知技能继承及非法图标拒绝。
在隔离 mock bench 检查卡片、详情、新建和导入预览，不接触用户 DSH 数据。

本次验证结果：

- `npm test -- --test-concurrency=4`：1,243 通过、1 跳过、0 失败。
- `node scripts/build-client.mjs --check`、`npm run lint` 通过。
- Windows 隔离 mock bench：51 个 smoke 步骤全部通过。
- 真实浏览器：118 张卡片、详情中的交付文件、手动更换与刷新保留、
  恢复自动、未知技能导入兜底与选图、新建技能自动匹配均通过。
- 本次 UI 和 smoke bench 已关闭。

网格面板调整后重新验证全量测试、客户端一致性与 lint，结果通过。
浏览器验证了 280px 面板、桌面 6 列两行推荐、展开高度、选择保存与恢复自动、
方向键与焦点、Escape 与点外部关闭、新建/导入/详情三处入口、
390px 窗口边界以及触屏 5 列且点击目标不小于 44px。
