# 对话中的实时执行过程

用户反馈：只有“运行命令”等一句状态时，等待首段正文容易被误认为卡住。

沿用 DSH 公开会话节点和 session/event，不修改 DSH，不新建运行时。
Bot 私聊中的普通工具显示轻量执行记录：类别、描述或目标、运行/完成/失败状态；
展开单步查看工具名称和命令等说明字段。PTC 显示实际子调用，避免重复程序包装。
保留现有交付、问答、权限和群聊专用卡片，以及首次工具前的即时活动行。
按照经典 Agent 的方式逐条平铺显示，不增加“执行过程”标题、计数或外层折叠框。
每一条直接展示工具类别、描述和状态，仅原始命令详情在点击单条时显示。
完成后步骤保持可见；只适配 ChemClaw 的背景色、字体、间距与主题。

群聊从当前群的成员 Session 获取过程，不能用优先显示私聊的 work.bots 来代替。
服务端只在运行回合内保留最近 24 步摘要，记录工具开始和结束，群聊即使已有
正文草稿仍显示实际工具活动。回合结束后实时摘要撤下，当前群轮次保留平铺的
成员执行记录，随已有 group_relay 结果重载；私聊历史由已有 DSH 工具节点重建。
摘要只取说明、命令、路径、查询等展示字段，不传工具输出、
任意参数或思考内容，并清理凭据形态和已存密钥。

布局使用现有主题变量，支持窄屏、键盘展开和减少动态效果。

隔离验收入口：`node dev/bench-windows.mjs <name> --ui`，发送“执行过程验收”。
mock 只尝试安全测试命令，包含成功、失败和恢复步骤，并在步骤间模拟模型等待。
不能将 mock 的最终文案作为命令成功的证据，应核验真实工具状态。

验证：完整单元测试 1249 通过、1 项 Windows 平台跳过；最终相关回归 72 通过；
客户端构建一致性与 lint 通过（保留仓库既有警告）；独立 mock smoke 51/51。
Chrome 实际检查了 Bot 私聊的平铺历史、群聊正文前的实时命令、失败状态和
单条命令详情，并在 390px 窗口检查布局，随后恢复浏览器原尺寸。
