# 面向用户的回答与交互图表

Issue #32，属于 #25。用户明确要求尽可能主动呈现已有交互能力。

## 回答对象

交付不是群聊最后一条，也不限定管理员。用户中途 @ 任意成员问具体问题，该成员完成这次面向用户的回答时，就可以展示图表，其他任务仍可继续。Bot 相互派活、讨论、进度、核对数据时不展示图表。

`show_view` 新增回答对象 `audience: user`。群聊必须显式标记面向人；调用只暂存当前回答的展示内容。只有这次回答的 turn 成功完成后才将卡片与正文一起交给群聊，不在工具执行或思考途中展示。失败、取消、只写工具文本而重试的回合不发布，已结束答案不等待整个群聊关闭。展示卡不触发群成员接力，不把图表再传给其他 Bot；保存到群聊自己的工具结果以便刷新/历史恢复。可操作输入仅限本地计算，无群聊提交表单。

## 默认可视化

系统规则和工具描述共用规范，交付技能同步按答案形状主动选择视图。先给最小可用结论与数据，再补充已要求的文件；缺口明确标示，绝不生成示意行情来凑图。

采用用户最终确认的对话式可视化规范：按答案形状触发，不以用户是否说“画图”为条件。当前水平、贵不贵、能否接受的答案中至少两个指标用 metric（通常 2–4 张）；同对象至少三个时间点用 line，累积量用 area；同时点至少两个对象比较用 bar，名称超过六字或类别超过八项用 hbar；单一整体的 3–6 部分结构用 donut；至少三行三列明细用 table；完整度、进度、配额结论用 progress；风险、异常、口径冲突、缺口用 callout；反复试算用输入与公式；需先确认参数时使用支持提交的 options/confirm/form。用户明确要求文字或不画图时遵从。

主组件按时间轴、大小比较、占比、多字段、其他可量化关系的顺序选定，最后一类使用 HTML，不并列提供不同图形方案让用户选。取消单次回答的视图/指标卡总数上限、禁止图表与表格同时展示、必须在视图后说明口径三项限制；原有的单卡大小和沙箱安全校验继续适用。真实数据、单位与证据要求保留，说明放置随业务内容安排。

密集日期按可用像素抽稀刻度；完整日期和每个数据点保留在悬停、键盘、表格和 CSV。大量类别使用单条完整走势缩略时间轴：两端手柄调整起止日期，中间选区整体平移，点击空白区域平移到该处，双击恢复全部；支持鼠标、触屏及方向键、Home/End、PageUp/PageDown。与主图坐标区域对齐，避免两个独立系统滑块；只在缩放后显示当前区间和恢复按钮。日期同年时可简写月日；跨年保留年份。缺失数值使用 null 表示，线/面积断开、柱条缺失、表格和悬停显示缺失，禁止自动补零或插值。

## 验证

覆盖中途 @ 成员、Bot 讨论无卡片、成功/失败/取消、慢任务晚交付、刷新历史不重发、密集日期/跨年/手机宽度、范围选择和缺失值；真实 Electron 使用合成数据观察群聊与图表交互。

完整单元测试 1131 项通过、1 项 Windows 平台跳过；生成文件检查和 lint 通过（保留既有警告），独立 mock 冒烟 51/51。
真实 Electron 验收通过群聊 @ 回答、完整悬停日期、缺失值断线、鼠标调整/平移选区、390px 触屏拖动及刷新后的单次回放。
所有验收仅使用合成数据，不调用真实模型或用户的 DSH 数据。
