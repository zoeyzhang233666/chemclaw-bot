# 群聊产物链接的路径核实

用户发现聊天链接显示文件不存在，而同一文件从工作区能打开；表格文件名也没有入口。
私聊收尾的文件引用不覆盖群聊成员回帖；相对链接按群 Session 的目录解释，可能与
成员实际产物目录不一致，历史回复还可能只给出文件名。

在 ChemClaw 自有的聊天渲染层收集显式本地链接、行内代码文件名和表格中完整文件名，
通过只读 artifact-paths 接口核实。依据公开 Session inspect 元数据的 cwd、群目录、
作者 Bot 目录和团队工作区，返回已存在的普通文件绝对路径。规范化 Windows 盘符、
反斜杠和百分号编码。先核实完整路径，旧回复仅有文件名时进行有界查找；同名多份、
扫描不完整、文件不存在或目录越界都不猜测。跳过符号链接与数据目录。

链接转换仅作用于显示，不改持久聊天内容。流式输出、代码块、外部网站和普通叙述不
自动链接。文件的读取、权限、HTML 沙箱和预览仍走 DSH 已文档化的原生能力。
这修复群聊和历史回复的显示，适用于安装此源码的新版本；不编辑用户的既有 DSH 数据。

验证：完整测试 973 通过、1 个既有 Windows 平台跳过；客户端生成检查和 lint 通过，
独立 mock smoke 51/51。隔离群聊实际运行 chem_deliver，文件保存于带随机 ID 的
子目录；回复故意只给文件名和错误的工作区根目录链接，分别点击正文 HTML 与表格
XLSX 后均显示真实内容。没有通过工作区树绕过链接来完成验收。
