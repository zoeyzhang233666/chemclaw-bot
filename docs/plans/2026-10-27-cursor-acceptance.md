## 核心用例

| 路径 | 问题 / 操作 | 应检查 |
| --- | --- | --- |
| 单 Bot 私聊 | 甲醇现货价格和上下游产业链 | 有实质回答；取得真实序列时自动出图；缺数据明确说明；承诺文件实际存在并有可打开链接 |
| 主 Bot 派活 | 将同一问题交给专业 Bot，等待回复归来 | 原问题保持关联，成员结果回到派活者并面向用户交付；没有重复派活或仅反复确认 |
| 管理员模式群聊 | 同一问题，不额外追问“结果呢” | 最终用户回答、图表和文件实际出现；进度句不能算交付；PASS、错误、审批、接力暂停分别如实记录 |
| 群内插话 | 执行期间 @基差研究员 问一个具体问题 | 新问题得到对应回答；旧任务仍保持原路由；面向用户的回答可独立出图，Bot 内部讨论不出图 |
| 停止 / 继续 / 重启 | 分别覆盖用户停止、接力暂停后继续、专用测试进程重启 | 不重复执行已有副作用，不丢结果；明确区分原生接力暂停与已撤回的预算取消 |
| 文件打开 | 点击正文链接、表格中文文件名、交付卡 | HTML/Excel/PPT 指向实际文件；对话入口与工作区打开一致；PPT 转换错误原样记录 |

业务数值只能来自实际数据源，禁止用 mock 数字冒充业务验收。没有数据时不能为“通过”编造图表。用户要求纯文字时不强制画图。

## 结果记录

每例记录环境、提交、问题、开始/首个有效数据/最终交付时间、是否派活、最终产物及链接打开结果、通过/失败/阻塞。观测时限是测试的停止条件，不能成为产品运行时强制掐断的依据。单元测试通过、脚本输出“已生成”或进度消息都不能替代最终文件与可见交付。

失败时提取最小脱敏复现与症状，关联独立 Issue/PR。验收结论由用户通过共享文件或此聊天转交；不要通过未授权的渠道发送聊天内容。
