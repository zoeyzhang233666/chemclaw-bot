# 查海关商品编码候选（hs-code-candidates）

> 一个产品进来，出来的不是"一个码"，而是"几个候选 + 每个候选的成立条件 + 法条依据 + 还缺什么"。
> 归类错误的代价不是改个数字：退税率可能从 13% 变成 0%，监管证件可能从"无"变成"A/M"，还可能构成申报不实。

## 何时使用

用户表达以下意图时使用本技能：

- "帮我查一下这个产品的 HS 编码 / 海关商品编码 / 商品编码是多少"
- "这个产品出口报关用什么编码？"/"客户要 HS code"
- "XX 和 YY 到底归哪个编码？差别在哪？"
- "这个编码的退税率是多少？有没有监管条件？"
- "我们产品是混合物/制剂/聚合物，不知道归哪一类"
- 报价前需要确定编码，或客户清关编码与本国编码对不上

**不适用**：纯国内流通、非实物商品的税率咨询；目的国市场调研（用「研究一个目标国家市场」）；完整出口合规清单（用「查产品出口要求」，本技能的输出可直接带进去）。

## 输入要素（缺就一次问全，不要反复打断）

| 要素 | 为什么关键 | 缺失时怎么办 |
|---|---|---|
| 产品名称（中文 + 英文/INCI/IUPAC） | 锁定身份与检索入口 | **必问**；只有商品名/俗称时，先要求成分或 CAS |
| CAS 号 / 化学品登记号 | 交叉核对身份 | 建议提供；**不能单凭 CAS 定编码**（族类号覆盖多牌号） |
| 主要成分与含量（w/w，写清范围） | 决定章/品目（如含量门槛、单体比例） | **必问**；只有"混合物"没有比例时，只能给方向，不给 8 位以下 |
| 物理形态（固/液/粉/粒/片/膏/胶乳/溶液） | 决定"初级形状"与否、是否 39/40 章 | **必问** |
| 纯度 / 级别（工业级/食品级/电子级/医药级） | 决定是否按化学纯品还是制品 | 建议提供 |
| 是否混合物或制剂 | 决定是否走"配制品/未列名"品目 | **必问** |
| 主要用途（越具体越好） | 影响品目选择与申报要素 | **必问** |
| 是否零售包装 | 影响是否为零售包装制品（如 3808、3402） | 必问（可默认"否"，并在报告标注假设） |
| 是否硫化 / 是否加填料助剂 / 是否充油 | 聚合物类专用 | 聚合物、橡胶类必问 |
| 目的国（可选） | 决定是否给出目的国税则层级 | 有则给，无则只做中国层级并注明 |

可上传/补充：SDS、TDS、组成说明、以往报关单、用途证明、产品/包装照片。有 SDS 时优先从 SDS 第 1、3、9 节提取名称、成分与形态。

## 执行流程（八步）

### 第 0 步：先定口径，别急着给码

在动手查之前，先明确并写进报告首页：

- **HS 版本与年份**：如 HS 2022 /《中华人民共和国进出口税则（2026）》（税委会公告2025年第12号，2026-01-01 实施）
- **监管与税率口径**：税率取"最惠国 / 普通 / 协定 / 特惠"哪一栏；退税取哪一版文库（如 2026C 版，税总货劳函〔2026〕214 号）
- **查询日期**：所有数据的截至时点
- **查询方向**：出口（我方报关）/ 进口（客户清关）/ 双向

### 第 1 步：产品身份固化

1. 名称 + 别名 + CAS 三方交叉；CAS 只作辅助，不作唯一依据。
2. 从组成反推"化学身份"：单一化合物 / 混合物 / 聚合物 / 制剂 / 制品，选出对应的章考察范围。
3. 记录"决定性参数"：含量门槛、单体比例、是否充油、是否加填料、是否零售包装。

### 第 2 步：章 → 品目 → 子目 → 本国细分（不许跳）

按 **归类总规则一** 的顺序推：

1. **章**：先看类注、章注的排除条款（例如第39章注释二排除第40章的合成橡胶）。
2. **品目（4 位）**：看品目条文本身，不要看品目下的商品名。
3. **子目（6 位）**：HS 国际层，全球一致。
4. **本国细分（8/10 位）**：中国税则的本国子目注释与 10 位细分；目的国按该国税则另算。

> 归类只能在同一数级比较（总规则六）；不要拿 4 位品目去比较 10 位细分。

### 第 3 步：生成候选（2–8 个，分级）

每个候选用统一字段记录（见 `references/03-候选表字段与HTML模板.md`）：

- 编码（6/8/10 位）+ 品名（税则原文 + 数据库口径）
- 定位：首选 / 并列 / 兜底 / 条件性 / 形态分岔
- 成立条件（缺一不可，逐条列）
- 归类理由（一句话讲清"为什么是这个码"）
- 法律依据（引用到注释/子目条文）
- 风险点（什么情况下会被推翻）
- 置信度 + 证据等级
- 监管条件、检验检疫、出口退税、出口关税、最惠国/普通税率

**候选不是越多越好**：能被上一级条件直接排除的，写进"误配清单"而不是候选清单。

### 第 4 步：歧义单列

把"同一产品可能落入的相邻编码"和"检索时容易误命中的无关/过期编码"分开成两张表：

- 歧义对：如 `4002.1913 vs 4002.1914`（是否充油）、`40.02 vs 40.05`（是否加填料）
- 误配：别的产品的编码、已过期编码、俗称命中的编码

### 第 5 步：监管条件与税率

每个候选都要落到：

- 监管证件（A/B/4/x/y 等）与检验检疫类别（M/N/R/S/L/Q/P）
- 出口关税、增值税、出口退税率（**注明明文库版本**）
- 进口方向：最惠国、普通、协定、RCEP、特惠
- 两用物项 / 出口许可目录 / 危化品目录的排查结论（"不适用"也要写成"查过 + 理由"）

### 第 6 步：缺失信息清单

把"没确认就会改变编码"的字段单独成表，每条给：影响哪个编码决策、优先级、向谁要、补齐后后果。
**必须一次性给出最小参数集**，让用户一次问全技术与销售部门。

### 第 7 步：待确认问题（闭环）

每条写清：问题、影响哪项结论、找谁确认（报关行 / 属地海关 / 税务 / 目的国代理）、状态。
需要锁定时，给出**预裁定**路径（《海关预裁定管理暂行办法》：拟进出口 3 个月前向备案地直属海关申请，60 日内出决定书，有效期 3 年）。

### 第 8 步：对外话术

给业务一句可以直接对客户说的话，模板：

> "我们产品是【化学身份】，【关键参数：未充油/充油 X%/未加填料/未硫化】，以【形态】出口，按中国税则归入【10 位编码（品名）】；
> 贵国进口编码请在【HS 6 位】项下按贵国税则确认。最终以中国海关认定为准。"

## 输出物

| 文件 | 内容 |
|---|---|
| `海关商品编码候选研究报告_<产品>_<编号>.html` | 自包含交互页（零外部依赖）：归类路径 → 候选卡片（可筛选/搜索）→ 法律依据 → 歧义与误配 → 编码层级 → 监管条件与税率 → 缺失信息 → 待确认 → 来源 |
| `海关商品编码候选研究工作簿_<产品>_<编号>.xlsx` | 13 表：封面与口径、产品属性、候选编码、归类依据、缺失信息、歧义与误配、编码层级对照、关税税率、出口监管条件、申报要素填写、待确认问题、来源链接、校验与统计 |
| `checks.json` | 校验结果（条数、等级分布、错误与提示） |

## 证据等级（统一口径，贯穿全流程）

| 等级 | 含义 | 可否对客户说 |
|---|---|---|
| A 官方原文 | 税则/公告/法规原文、官方数据库接口 | 可以，需说明依据与版本 |
| B 二手/供应商文件 | 商业数据库、SDS/TDS、行业资料，已与官方交叉核对 | 可以说"据…"，不宜说"确定" |
| C 第三方数据库 | 未与官方核对的数据库、检索摘要 | 只能作定位线索 |
| D 待核验 | 拿不到原文、需专业判断 | **不得作为承诺依据**；进待确认清单 |

## 硬性纪律（违反即不合格）

1. **不强行给唯一编码。** 参数不足时，只给方向与候选，并写清缺什么。
2. **每个候选必须挂法条依据**（类注/章注/品目/子目条文原文），不能只写"按惯例"。
3. **不按商品俗称给码。** 俗称常常跨越多个品目（如"热塑性弹性体"至少跨 3902/3903/3907/3909/4002）。
4. **不单凭 CAS 给码。** CAS 是物质属性，编码是货品属性。
5. **不沿用过期编码。** 10 位细分随税则调整会停用；状态不明的编码必须核验状态。
6. **税率必须标版本与日期**（HS 年份、退税文库版本、查询日期）。
7. **"不适用"要写理由**：两用物项、出口许可、危化品等排查，写"查过哪份文件 + 结论"。
8. **交付物必须写明免责声明**：不构成法律意见，最终以海关认定为准。

## 工具与脚本

```bash
# 1) 校验案例数据（先跑，必须 0 error）
python scripts/validators.py examples/01-SBS热塑性弹性体/case.json --out examples/01-SBS热塑性弹性体/checks.json --as-of 2026-10-19

# 2) 生成 Excel 工作簿
python scripts/build_workbook.py examples/01-SBS热塑性弹性体/case.json --out <工作簿>.xlsx

# 3) 生成交互 HTML
python scripts/build_html.py examples/01-SBS热塑性弹性体/case.json --out <页面>.html

# 4) 一键全流程（校验 → Excel → HTML → 浏览器交互验证）
python scripts/build_all.py examples/01-SBS热塑性弹性体/case.json
```

脚本只依赖 Python 标准库 + `openpyxl`；`verify_page.cjs` 需要 Node + Playwright（可选，仅用于页面交互验证）。
