# 交付前质检清单

## A. 数据完整性

- [ ] `case.json` 通过了 `scripts/validators.py`（0 error）
- [ ] 候选 ≥ 2 个，且每个候选都有 `conditions`、`why`、`basis`、`vuln`
- [ ] 每个候选的 6 位 / 10 位编码格式正确（`4002.19` / `4002191300`）
- [ ] 所有候选都填了 mfn、gen、export_tax、rebate、reg、ciq
- [ ] 来源 ≥ 5 条，且至少 2 条 A 级
- [ ] 缺失信息 ≥ 3 条，且标注了优先级与补证路径
- [ ] 待确认问题 ≥ 3 条，且都有责任方

## B. 逻辑与纪律

- [ ] **没有**给出"唯一确定编码"的表述（除参数齐备且明确说明条件）
- [ ] 每条法律依据都引用到注释/条文级别
- [ ] 俗称/CAS 未被当作归类的唯一依据
- [ ] 过期编码未被用作候选
- [ ] 税率标明了版本（HS 年份、退税文库版本、查询日期）
- [ ] "不适用"项目都写了"查了哪份文件 + 结论"
- [ ] 报告含免责声明
- [ ] 有可直接对客户使用的三行编码写法

## C. 交付物

- [ ] HTML：9 个区块齐全，标签可切换，搜索/筛选可用，移动端不横向溢出
- [ ] HTML：无 JS 报错（`verify_page.cjs` 的 errors 为空）
- [ ] Excel：13 张表齐全，表头正确，无空表
- [ ] Excel：来源链接可点击
- [ ] 文件名含产品名与案例号
- [ ] ZIP 包含 SKILL.md、references、scripts、examples

## D. 业务可用性

- [ ] 销售能看懂"该用哪个码、还要问客户什么"（不需要归类背景）
- [ ] 报关行能直接拿去核对（条件、要素、争议点清晰）
- [ ] 报价环节能直接用（退税率与出口关税已写明，含核验状态）
- [ ] 下一步衔接已提示（查产品出口要求 / 算出口报价）

## E. 常见返工原因

| 现象 | 原因 | 修法 |
|---|---|---|
| 客户/报关行质疑编码 | 只给结论没给条件 | 补 conditions + vuln |
| 报价后利润偏差 | 退税率未核验或形态错判 | 补退税文库版本，确认形态 |
| 报告"看起来像模板" | 候选描述空泛 | 每段至少写一条产品专属细节 |
| 无法追溯 | 来源缺失或只有搜索摘要 | 补官方 URL 与核验日期 |
