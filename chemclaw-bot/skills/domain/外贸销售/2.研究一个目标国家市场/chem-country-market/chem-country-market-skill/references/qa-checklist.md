# 交付前检查清单（40 项）

自动化能查的用脚本查，查不了的（语义对不对、话说得专不专业）用这份清单人工过。

```bash
python scripts/validate.py case.json
python scripts/build_all.py case.json --render
python scripts/selftest.py --case case.json
```

---

## A. 数据与口径（最致命，先查）

- [ ] 1. 用的是**目标国自报的进口数据**，不是“中国对世界出口”或其他镜像口径
- [ ] 2. `reporterCode` / UN M49 与目标国一致（印尼 360，中国 156）
- [ ] 3. 金额单位确认是**美元**（不是千美元、不是千印尼盾）
- [ ] 4. 数量单位确认是**吨**（Comtrade 原始是 kg）
- [ ] 5. 数量未报送的年份是 `null`，没有插值、没有用金额÷单价反推
- [ ] 6. 份额的分母是同年同口径的进口合计，并且各伙伴份额之和 ≤ 100%
- [ ] 7. 单位价值落在合理区间（纯碱 200–400 USD/t），异常说明单位可能错了
- [ ] 8. CAGR 用的是首末年份，且首末年份都有数据
- [ ] 9. “中国对印尼出口”与“印尼自华进口”并列展示，没有强行对齐
- [ ] 10. 长序列（窗口外的年份）只用于对照，不混进主表

## B. 事实与来源

- [ ] 11. 每个数字都能点到 `sources[]` 里的一个 id
- [ ] 12. 每个板块至少有 1 个 T1/T2 来源
- [ ] 13. 所有机构估算的句子都带“估算”二字
- [ ] 14. 所有第三方汇总站的税率都带“第三方称”并标待核实
- [ ] 15. “本地无产能”有 ≥2 条证据，其中至少 1 条是 T1/T2
- [ ] 16. 在建项目的 `status` 与 `status_asof` 都写了，没有把“在建”写成“已投产”
- [ ] 17. 产能与产量分开表述（`capacity_basis` 写明是设计产能还是实测产量）
- [ ] 18. 企业事实是**原文摘录**，不是转述后加工
- [ ] 19. 引用的政策有时间点（签署 / 生效 / 实施 分开写）
- [ ] 20. `data_asof` 与来源日期一致，政策类超过 12 个月标了“需复核”

## C. 九问覆盖

- [ ] 21. 第 6 节“口径对照表”九行齐全，每行都能点到对应章节
- [ ] 22. 下游产业按分段写，每段都有来源与缺口
- [ ] 23. 主要来源国给了份额 + 单位价值 + 变化
- [ ] 24. 中国份额给了排名、份额、金额、增速
- [ ] 25. 本地产能给了在运/在建/中试三种状态
- [ ] 26. 关税表每行有状态列
- [ ] 27. 非关税措施逐条过（许可、标准、TKDN、贸易救济）
- [ ] 28. 与中国贸易关系有时间线
- [ ] 29. 公开研报段落带 caveat（方法不公开 / 只作方向参考）
- [ ] 30. 缺口表 ≥5 项，且每项有“怎么补”

## 常见返工原因（按出现频率）

1. **口径混用**：用中国出口数据算“当地份额” → 全表作废重算
2. **税率写死**：把第三方 0% 写进正表 → 改 `status: gap`
3. **数量插值**：为了让曲线好看补了 2023、2025 的数量 → 删掉，KPI 显示“未报送”
4. **产业链写成散文**：没有企业名、没有来源 → 补企业事实或降级为描述
5. **缺口写成免责声明**：只说“数据有限” → 改成“缺什么/为什么/怎么补”
6. **预测句**：“预计将成为主要供应国” → 改成“过去 5 年份额从 X 升到 Y，关键变量是 Z”
