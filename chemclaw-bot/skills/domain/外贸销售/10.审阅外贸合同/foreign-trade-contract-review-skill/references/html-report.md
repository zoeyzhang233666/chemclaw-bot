# HTML 报告：结构与交互

产物是**单个自包含 HTML 文件**：CSS 与 JS 全部内联，数据以 `window.__REVIEW__` 形式嵌入。
双击即可打开，可离线使用，可直接发给法务或客户（注意其中含合同原文）。

---

## 1. 页面结构

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：合同标题 · 我方身份徽标 · SIMULATED 标记 · 视图切换 · 导出 │
├────────────────────────────┬─────────────────────────────────┤
│  左栏：合同原文              │  右栏：风险与确认事项            │
│  ┌ 章标题（深底）            │  ┌ 筛选条：主题 chip / 等级 chip  │
│  ├ 条标题 6.1 Payment       │  ├ R-01  [高] [付款] 标题        │
│  │   段落正文…              │  │   ├ 原文位置 → 点此定位      │
│  │   ● 风险点标记（可点）    │  │   ├ 原文引用（逐字）         │
│  ├ 条标题 6.2 …             │  │   ├ 问题说明 / 商务后果      │
│  │                          │  │   ├ 需要确认（勾选清单）      │
│  │                          │  │   ├ 建议修改措辞（英文）      │
│  │                          │  │   └ 负责人/状态/备注  ← 可填  │
│  └                          │  └ R-02 …                       │
└────────────────────────────┴─────────────────────────────────┘
```

**三个视图**

| 视图 | 用途 |
|---|---|
| 对照视图（默认） | 左右双栏，审阅主界面 |
| 原文视图 | 只看合同，便于通读 |
| 总览视图 | 38 条问题的表格化总览，点行跳回对照视图 |

## 2. 核心交互

### 2.1 定位（两个方向都要能点）

```
右栏卡片「原文位置 →」按钮   ──点──▶  左栏对应段落高亮 + 滚动到居中
左栏段落上的 ● 风险标记      ──点──▶  右栏对应卡片展开 + 滚动到可视
```

实现要点：

- 左右都通过 `data-bid="<block id>"` 关联，**不靠文本匹配**
- 高亮用 `.active-highlight`，2.6 秒后自动移除
- 滚动用 `scrollIntoView({block:'center'})`，避免被顶栏遮住

### 2.2 筛选

| 维度 | 行为 |
|---|---|
| 主题 chip（付款/交付/质量/索赔/合规/争议/缺失） | 单选；点「全部」复位 |
| 风险等级 chip（高/中/低） | 与主题**叠加**（AND） |
| 状态下拉 | 与上面两个再叠加 |
| 搜索框（`/` 快捷键聚焦） | 在标题、说明、后果、确认事项中做全文匹配 |

计数实时更新为 `N / 总数 条`。

### 2.3 填写与保存

每条卡片底部三格：

- **负责人**（文本）
- **处理状态**（下拉：待处理 / 处理中 / 需法务确认 / 已解决 / 不适用）
- **备注**（文本）

保存到 `localStorage`，键名 `ftc-review:<合同号>`。
**只保存在本机本浏览器**——换电脑、清缓存即丢失。这是刻意的设计：
审阅记录不外传；正式流转以 Excel 为准。

### 2.4 导出

| 按钮 | 产物 | 用途 |
|---|---|---|
| 导出 CSV | 问题编号、主题、等级、条款、说明、后果、确认事项、负责人、状态、备注 | 贴进邮件/微信发给法务 |
| 导出 JSON | 全量数据 + 当前填写状态 | 归档、二次处理、回流到 Excel |
| 导出审阅清单 | 上述 CSV（含填写状态） | 业务 ↔ 法务的交接单据 |

## 3. 数据注入

构建时插入：

```html
<script>window.__REVIEW__ = { meta: {...}, issues: [...] };</script>
```

`issues` 就是 `data_issues_*.json` 合并后的数组，**原样嵌入**（含 anchors、confirm、legal_refs）。
因此：

- 改数据 → 必须重新构建 HTML，不能只改 JSON
- 想临时手改 HTML → 找 `window.__REVIEW__` 那段改，改完刷新

## 4. 视觉规范

| 元素 | 规格 |
|---|---|
| 顶栏 | 深色 `#101828`，白字，右侧操作区 |
| 纸张区 | 浅色 `#FFFFFF` / 底 `#F6F8FB`，圆角 10px，细边框 `#D8DEE9` |
| 字体 | 中文 微软雅黑/思源黑体；英文/条款 Georgia 或系统衬线；数字 tabular |
| 高风险 | 红 `#DC2626`，底 `#FEE2E2` |
| 中风险 | 橙 `#D97706`，底 `#FEF3C7` |
| 低风险 | 绿 `#059669`，底 `#D1FAE5` |
| 原文引用 | 衬线 + 斜体 + 左侧竖线，明确区分「合同写的」与「我们写的」 |
| 打印 | `@media print` 隐藏顶栏与按钮，双栏改为单栏 |

**一条重要视觉规则**：合同原文与我方评论必须**在字体上就不同**（衬线 vs 无衬线）。
审阅报告最大的沟通事故是「法务以为注释是合同条款」。

---

## 5. 打印与分享

- **打印**：Ctrl+P，样式已适配；建议横向、缩放到 90%
- **分享**：单文件，直接发附件。含合同原文，仅限内部
- **不支持**：IE、以及禁用了 localStorage 的嵌入环境（填写不保存，其余功能正常）

## 6. 自测

```bash
python scripts/cdp_test.py review.html
```

需要本机装 Chrome。会启动无头浏览器并检查 29 项行为：
卡片数量、锚点解析、双向定位、筛选叠加、搜索、localStorage 持久化、
总览视图、双栏宽度、横向溢出等。全绿才算交付。

> 该脚本用最小 CDP 客户端实现（不依赖 playwright），
> 若环境无 Chrome，可跳过，但**必须手动把定位、筛选、填写、导出各点一遍**。
