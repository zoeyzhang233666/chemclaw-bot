# 数据来源与取数规范

## 一、来源优先级

| 级别 | 来源 | 用途 | 可否作为报价依据 |
|---|---|---|---|
| A | **国家外汇管理局**人民币汇率中间价 | 历史序列、分位、走势 | 可作对照基准，**不是**结汇成交价 |
| A | **中国银行**外汇牌价（现汇买入/卖出） | 证明中间价与到手价的差异、估算点差 | 近似，实际以银行回单为准 |
| B | 中国外汇交易中心（CFETS） | 当日中间价交叉核对 | 同上 |
| C | ECB / Frankfurter / open.er-api 等 | **仅做数量级核对** | ❌ 不可 |

**决不用 C 级数据做任何测算。** 聚合器的换算路径（尤其 USD→CNY 经 EUR 或 USD 桥接）与境内结汇不是同一个市场，偏差可达 0.5% 以上，正好是这单毛利的一大块。

## 二、国家外汇管理局中间价

### 接口

```
GET https://www.safe.gov.cn/AppStructured/hlw/RMBQuery.do
    ?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD&queryYN=true
```

返回 HTML 表格。抓取要点：

1. **单次区间不超过 366 天**，超过会被截断或报错 → 按年切块循环；
2. 表头是币种名，行是日期；
3. 数值是**每 100 外币**兑人民币，**必须除以 100** 得到"1 单位外币 = X 人民币"；
4. **日元例外**：保持 "100 JPY" 口径，不要再除 100；
5. 缺失的行是**法定节假日**（非数据缺失），保留为空，**绝不插值**。

### 已知陷阱

| 陷阱 | 说明 |
|---|---|
| 单位 | 忘记除 100 → 所有金额差 100 倍 |
| 日元 | 日元本身就以 100 为单位报价，除 100 会差 100 倍 |
| 节假日 | 看着像"缺数据"，其实是休市；插值会凭空造出一个不存在的汇率 |
| 表头顺序 | 不同年份返回的币种列顺序可能变化 → 按币种名解析，不按列序号 |
| 编码 | 页面是 GBK/UTF-8 混杂，按字节读取后显式解码 |

### 质量检查（每次抓完必跑）

```
交易日数      合理范围：700~780（3 年）
重复日期      必须为 0
缺失工作日    ≈ 每年 11~13 天（法定节假日），且应能对应到具体节日
单日跳变      最大 |Δ| 一般 < 2%；超过 3% 要人工核对该日期
与当日公告比对 当日中间价应与 PBOC 9:15 公告一致
```

案例实测：735 个交易日、56 个缺失工作日（全部为法定节假日）、0 重复、最大单日跳变 0.938%。

## 三、中国银行外汇牌价

### 页面

```
https://www.boc.cn/sourcedb/whpj/
```

返回各币种的：现汇买入价、现钞买入价、现汇卖出价、现钞卖出价、中行折算价、发布时间。

### 三个重要提醒

1. **历史价格页面有验证码（gt4 CAPTCHA），不可抓取**。只能用当前牌价页面。这意味着：**历史"银行成交价"序列拿不到**，只能用中间价做历史分析——这正是为什么历史分位必须标注"基于中间价"。
2. 牌价**每几秒刷新**，必须记录**具体时刻**（案例：2026-10-19 16:27:56）。
3. 卖出价不是买入价加一个固定数，点差随币种、金额、时段浮动 ±0.25% 只是示例。

### 口径对照（案例实测，2026-10-19）

| 口径 | USD/CNY | 与中间价差 |
|---|---|---|
| 官方中间价 | 6.7208 | — |
| 中行现汇买入价 | 6.6701 | −0.75% |
| 中行现汇卖出价 | 6.6982 | −0.34% |
| 中行折算价 | 6.7208 | 0% |

读法：
- 出口结汇用**现汇买入价**，比中间价低 0.75% → 10 万美元少收约 5,070 元；
- 进口购汇用**现汇卖出价**；
- **折算价 ≈ 中间价**，是银行内部记账口径，不是任何人的成交价，不能拿来报价。

## 四、交叉核对

任何一次取数都至少做一次跨源核对，并**记录差异原因**：

| 核对 | 案例结果 | 差异原因 |
|---|---|---|
| SAFE 当日中间价 vs PBOC 9:15 公告 | 6.7208 一致 | — |
| SAFE vs Frankfurter(ECB) | 6.7208 vs 6.6862（差 0.52%） | ECB 参考汇率、不同时点、经 EUR 换算 |
| SAFE vs open.er-api | 6.7208 vs 6.69274（差 0.42%） | 聚合器路径不同 |

差异 0.4%~0.5% 是**正常且必须如实报告的**，不是"某个源错了"。这类差异本身就是很好的教学材料：告诉销售"不同来源的汇率能差半个百分点，所以报价单上必须写清用的是哪个口径"。

## 五、数据标签制度

每个数字都必须能被归类为以下三种之一，并在交付物里显式标注：

| 标签 | 含义 | 案例中的例子 |
|---|---|---|
| **真实** | 有可回溯来源、日期、时刻 | USD/CNY 中间价 6.7208（SAFE，2026-10-19 09:15）；历史 735 天序列 |
| **模拟** | 示例参数，不是该订单真实数据 | 人民币成本 600,000 元；结算日 2027-01-17；分批比例 30/40/30 |
| **估算** | 基于真实数据推算，但非官方报价 | 银行点差带 ±0.25%；费用率 0% |

界面与 Excel 用徽章区分：`真实`（绿）/ `模拟`（粉）/ `估算`（黄）。

`case.json` 里有一个 `simulated_fields` 字段列出所有模拟项，构建脚本会把它写进封面与说明区——**新增模拟参数时必须同步登记**。

## 六、取数留痕（08_实时汇率记录 表）

每次取数追加一行，七列缺一不可：

| 取数时间 | 来源 | 页面/接口 | 币种对 | 口径 | 数值 | 备注 |
|---|---|---|---|---|---|---|

为什么必须记时刻：盘中汇率随时变动。报价单上写"今日汇率 6.70"是不可追溯的；写"2026-10-19 16:27 中国银行现汇买入价 6.6701"才能在客户质疑时拿出依据。

## 七、有效期与刷新

| 数据 | 建议刷新频率 | 过期后果 |
|---|---|---|
| 当日中间价 | 每个报价日 | 分位、敏感性全部失真 |
| 历史序列 | 每月 | 分位趋势判断滞后 |
| 银行牌价 | 每次报价前 | 结汇/购汇价偏离实际 |
| 成本与目标毛利率 | 每次报价 | 平衡汇率失效 |

交付时应明确告诉用户："这份文件里的汇率数据截至 2026-10-19，之后需要重新取数。"不要让文件看起来永远有效。
