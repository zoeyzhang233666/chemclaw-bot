# 适配与扩展

本技能默认覆盖"单笔外币订单 + 一个币种 + 出口收汇"。以下是如何把它接到别的场景。

---

## 1. 接入报价系统 / CRM

`scenario.json` 就是接口。你的报价系统只需要读其中几个字段：

```json
{
  "rate": {"base_rate": 6.703998, "basis": "mid_x_band_estimate"},
  "one_pct_cny": 6704,
  "breakevens": {"zero": {"breakeven": 6.0}, "target_pct": {"breakeven": 6.666667}},
  "base": {"margin_cny": 70399.8, "margin_pct": 0.105012}
}
```

典型用法：

| 系统 | 读取字段 | 用途 |
|---|---|---|
| 报价单生成 | `rate.base_rate` + `breakevens.target_pct.breakeven` | 报价底线校验：低于平衡汇率就拦下 |
| CRM 商机 | `one_pct_cny` | 自动标注"本单每 1% 汇率浮动 ≈ 6,704 元" |
| 审批流 | `base.margin_pct` vs `meta.target_margin_pct` | 低于目标毛利率转人工审批 |

`09_报价带入` 表算的 `A_min = C / [(1 − m)(1 − t)R]` 可直接作为报价系统的**最低外币金额**字段。

> 接系统时把 `rate_used`、`basis`、`as_of` 一起落库。只存汇率数字、不存口径和时间，三个月后没人说得清当初按什么算的。

---

## 2. 换币种

### 已有币种（25 个）

只需在 `case.json` 里改 `currency`：

```json
"currency": "EUR"      // 或 GBP / JPY(写作 100JPY) / HKD / AUD ...
```

`run_case.py` 会自动从 `fx_series.json` 取该币种的序列，分位、走势、敏感性全部跟着换。

**日元特别注意**：口径是 `100 JPY = X CNY`。如果金额写的是 `100000`（日元），那么 `A = 100000 / 100 = 1000` 才能乘汇率。建议在 `case.json` 里直接把 `currency` 写成 `"100JPY"`，`amount_fx` 写"多少个 100 日元"。

### 新增币种

`build_fx_series.py` 里维护币种白名单，加一行即可：

```python
CURRENCIES = [("USD", "美元", 1), ..., ("XXX", "新币种", 1)]
```

然后重跑 `build_fx_series.py`（要重新抓 SAFE）。

---

## 3. 进口付汇

改 `direction`：

```json
"direction": "import",
"resale_cny": 4800000
```

系统会自动切换：

| 项 | 出口 | 进口 |
|---|---|---|
| 汇率 | 现汇买入价 | 现汇卖出价 |
| 符号 | `(1 − t)` | `(1 + t)` |
| 毛利率分母 | 收入 | 销售收入 |
| 平衡汇率 | `C / [A(1−t)]` | `(S − C_oth) / [A(1+t)]` |
| 关注方向 | 汇率**下跌**危险 | 汇率**上涨**危险 |

这是最容易出错的地方，务必在界面文案里把"危险方向"讲清楚。

---

## 4. 多币种订单

一笔合同涉及多种币种（如美元计价、欧元结算）时，本技能不直接支持。两条路：

1. **拆成多笔**：每个币种跑一次 `run_case.py`，最后把各笔的 `base.margin_cny` 与 `one_pct_cny` 相加。适用于两个币种各自独立暴露的情形。
2. **合成交叉盘**：若必须用第三币种，需自行取两组中间价合成 `EUR/CNY = EUR/USD × USD/CNY`，并把合成结果当作自定义序列喂进 `fx_series.json`。此时必须在交付物里标注"交叉汇率由两组中间价合成，非直接报价"。

---

## 5. 多笔订单汇总（订单池）

销售手里常有十几笔不同期限的订单。扩展方式：

1. 对每笔订单跑一次 `run_case.py`；
2. 汇总 `one_pct_cny` 得到总敞口；
3. 汇总 `margin_cny` 得到总毛利；
4. 计算**加权平衡汇率**：`R*_pool = Σ(C_i) / Σ(A_i × (1 − t_i))`；
5. 绘制"汇率变动 vs 组合毛利"曲线。

注意：不同币种的敞口**不能直接相加**（USD 与 EUR 对 CNY 的变动不同步）。跨币种汇总时只能加"人民币敞口金额"，且必须声明"假设各币种同向等幅变动"——这是一个额外的强假设。

---

## 6. 改变结算期限

`meta.settle_date` 改了，`horizon_days` 与交易日估算自动重算。典型用法：

| 场景 | 期限 | 用途 |
|---|---|---|
| 即期 T/T | 0 天 | 几乎无汇率风险，仅点差 |
| 30% 定金 + 70% 见提单 | 60 天 | 最常见的出口结构 |
| 90 天远期信用证 | 90 天 | 风险窗口最大 |
| 180 天 OA | 180 天 | 需重点关注 |

期限的作用有两个：一是"典型波动幅度"`σ × √(N/252)` 会随 N 增大；二是分批方案里各批的落点不同。

## 7. 自定义敏感性档位

`meta.shifts` 任意数组，例如只关心下跌：

```json
"shifts": [-0.10, -0.07, -0.05, -0.03, -0.01, 0]
```

或非对称大步长：

```json
"shifts": [-0.15, -0.10, -0.05, 0, 0.05, 0.15]
```

HTML 里也可以直接改输入框（逗号分隔），Excel 的 `02` 表是固定 9 档（为兼容性），要改档位直接改 B 列百分比。

## 8. 从"单次测算"升级为"持续监控"

把 `fx_series.json` 的刷新做成定时任务：

```
每天 09:30  → 抓 SAFE 当日中间价 → 更新 fx_series.json 最后一行
            → 对所有在途订单重跑 run_case.py
            → 检查每笔 balance：当前汇率距离平衡汇率是否 < 3%
            → 低于阈值则告警
```

注意：**告警只报告"距离平衡汇率还有多远"这个事实**，不说"建议你锁汇"。这是本技能的合规红线——发现问题可以，替人做决定不行。

## 9. 与其它技能组合

| 组合 | 做法 |
|---|---|
| 行情简报 | 用行情技能确认产品离岸价与国内成本，把成本填进 `cny_cost` |
| 客户线索 | 线索里的目标市场规模可用于估算订单量级，再作为 `amount_fx` |
| 项目型销售 | 项目分期付款天然形成分批结构，直接填 `batches` |

关键是**汇率这一层不掺入业务判断**：本技能只回答"给定金额、成本、期限，汇率变动会怎样"，产品该卖什么价由别的环节决定。

## 10. 常见扩展请求与回应

| 用户说 | 回应 |
|---|---|
| "帮我预测下个月汇率" | 本技能不做预测。可提供：历史分位、典型波动幅度、各情景下的盈亏——这些能帮你自己判断，但不给方向。 |
| "建议我锁多少比例" | 不做推荐。可提供：不锁汇 / 全锁 / 半锁三种情形下的**毛利数字对比**（前提是拿到远期点价，本技能不含远期报价）。 |
| "直接给我个报价" | 提供报价底线 `A_min` 与平衡汇率；最终报价由市场价格决定。 |
| "美元会跌到 6.5 吗" | 可回答：6.5 在历史上处于什么位置（是否到过、多少天到过），以及到 6.5 时你的毛利是多少。不回答"会不会到"。 |
| "手续费银行说 0.1%" | 填 `toll_rate: 0.001`，全表重算，平衡汇率会上移。 |
