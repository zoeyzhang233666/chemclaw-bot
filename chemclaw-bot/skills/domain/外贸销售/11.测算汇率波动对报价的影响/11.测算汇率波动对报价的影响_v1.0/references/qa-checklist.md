# 交付前校验清单

**原则：任何一个 FAIL 都必须修完才能交付。** "看起来没问题"不算通过。

---

## 一、数据真实性（最高优先级）

- [ ] 每个汇率数字都有来源 + 日期；盘中数据有具体时刻
- [ ] 历史序列来自官方原始数据，逐点可回溯
- [ ] 缺失交易日保留为空，**全文搜不到插值/平滑代码**
- [ ] 交叉核对至少做了一次，差异原因已说明（案例：ECB 与 SAFE 差 0.52%）
- [ ] 所有模拟参数都打了 `模拟` 徽章，且 `simulated_fields` 与实际一致
- [ ] 点差带标注为"示例/估算"，没有说成某家银行的真实报价

验证命令：

```bash
python scripts/check_workbook_static.py <xlsx> <scenario.json> <fx_series.json>
# 应看到：历史序列行数与官方数据一致 / 历史序列抽样与 SAFE 官方值逐点一致 3/3
```

## 二、合规边界

- [ ] 全文搜不到：`预计将上涨`、`看跌`、`大概率`、`建议锁汇`、`推荐远期`、`必涨`、`必跌`
- [ ] 没有出现"应该锁汇 X%""建议买入期权"这类动作指令
- [ ] 有明确的"仅做情景测算 / 不预测汇率走势"声明（HTML 页脚 + Excel 封面 + 免责页）
- [ ] 所有"若汇率为 R"都表述为**假设/压力测试**，不是预判
- [ ] 历史分位旁边有"分位低不等于会涨"的提示

`build_html.py` 内置了禁用词扫描，命中会直接构建失败。Excel 侧需人工搜一遍。

## 三、方向正确性（最容易错）

- [ ] 出口：`Rev = A × R × (1 − t)`，用**现汇买入价**
- [ ] 进口：`Pay = A × R × (1 + t)`，用**现汇卖出价**
- [ ] 切换方向后，表头从"人民币收入"变"人民币支出"，平衡汇率公式也跟着换
- [ ] 进口时毛利率分母是**销售收入**，不是支出
- [ ] 出口/进口的符号 `sign` 在公式里是 `(1 + sign × t)`，不是硬编码 `(1 − t)`

验证：

```bash
node scripts/qa_render.mjs <html>
# 应看到：切进口后公式切换为付汇 / 进口表头为人民币支出 / 进口毛利可计算
```

## 九、缺口清单必含 9 项

| # | 缺口 | 为什么重要 |
|---|---|---|
| 1 | 结汇/购汇手续费、电讯费 | 按笔收取，大额另议 |
| 2 | 银行点差 | 随币种/金额/时段浮动，示例 ±0.25% 不是真实报价 |
| 3 | 远期锁汇点价 | 远期汇率 = 即期 + 掉期点，本技能不取远期报价 |
| 4 | 交易日与节假日 | 长假顺延影响资金占用 |
| 5 | 多币种交叉盘 | 第三币种结算需两组中间价合成 |
| 6 | 合同条款 | 汇率调整条款、迟延利息改变实际暴露 |
| 7 | 成本端汇率联动 | 外币计价的原料/运费会随汇率变动 |
| 8 | 税务与退税 | 出口退税率影响成本折算 |
| 9 | 样本口径差异 | 历史是中间价，成交是牌价，跨口径比较会失真 |

## 十、交付话术

交付时在回复里必须包含：

1. 当前汇率（含口径、日期、时刻、来源）
2. 历史位置（1 年 / 3 年分位、距最高/最低）
3. 每 1% 敞口金额、±5% 的最大影响
4. 平衡汇率（毛利=0 / 保目标毛利率），以及距当前多远
5. **明确列出哪些参数是模拟的**
6. 一句"汇率数据截至 X 日，之后需重新取数"

不要只甩两个文件链接。销售要的是结论，文件是依据。
