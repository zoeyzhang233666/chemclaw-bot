# 汇率波动对报价的影响 · 测算与交付规范

## 这个技能解决什么问题

外贸销售报出一个外币价格，签的是三个月后才收汇的合同。这三个月里汇率会动，动的每一分钱都直接进或出毛利。销售需要的不是"汇率会涨还是会跌"，而是三句能给客户和自己交代的话：

1. **现在的汇率在历史上处于什么位置**（只用真实数据说话：到过哪里、现在在哪儿、多罕见）；
2. **汇率动 1%、3%、5%，我这单会多赚或少赚多少**（人民币金额，不是形容词）；
3. **汇率跌到什么程度，我这单就白干了**（平衡汇率），以及报价里应该留多少空间。

本技能把这些做成可重算的文件，而不是一张算完就过期的截图。

## 硬性边界（违反即返工）

| 必须做 | 绝不能做 |
|---|---|
| 每一条汇率数据带 **来源 + 日期**（盘中数据还要带**时刻**） | 预测汇率方向、给"看涨/看跌"结论 |
| 历史序列用**官方原始数据**，缺失的交易日如实保留为空 | 插值、平滑、用模型补齐历史缺口 |
| 区分**出口收汇**（看结汇价）与**进口付汇**（看购汇价）两套方向 | 用同一个公式套两种方向 |
| 模拟参数（成本、期限等）**显式标注「模拟」** | 把示例数字说成真实成交数据 |
| 明确列出**未计入因素**（手续费、点差、远期点价、节假日……） | 假装模型是完整的 |
| 只做情景测算（"若汇率为 R"） | 推荐远期、期权、掉期或任何具体避险操作 |

**关于"不推荐"**：可以做的是把不同口径、不同情景的**数字**摆出来供用户自己判断（例如"用中间价 vs 用银行实际成交价，毛利差 X 元"）；不能做的是"建议你锁汇 50%"这类动作指令。

## 交付物

### 1. 交互式 HTML 测算台（单文件，离线可用）

自包含：ECharts 内联，无任何外链，断网双击可开。四个页签：

| 页签 | 内容 |
|---|---|
| 测算台 | 6 张 KPI 卡（基准汇率、历史分位、人民币收入、每 1% 敞口、毛利额/率、平衡汇率）+ 趋势图（标注历史最高/最低）+ 历史位置条 + 敏感性表 + 敏感性双图 + 平衡汇率区块与毛利曲线 + 分批结算可编辑表与图 |
| 历史数据 | 1 年 / 3 年切换、走势图（可缩放）、分布直方图、区间统计表、735 天原始明细表 |
| 带入报价 | 报价底线（成本 ÷ [(1−目标毛利率)×(1−费用率)] ÷ 汇率）、导出 JSON 供报价单使用 |
| 公式与缺口 | 全部公式、未计入因素清单、数据来源、免责声明 |

实时重算：改金额 / 汇率 / 点差 / 成本 / 目标毛利率 / 档位 / 方向，全部即时更新，无需刷新。

### 2. Excel 工作簿（公式可运行，改输入即重算）

11 张表：`00_封面说明`、`01_输入参数`、`02_汇率敏感性`、`03_毛利测算`、`04_计算公式`、`05_分批结算`、`06_历史汇率序列`、`07_历史分位`、`08_实时汇率记录`、`09_报价带入`、`10_口径与免责`。

- **黄底 = 输入**，白底 = 公式，浅蓝 = 结论。只改黄底。
- `06` 表是唯一存放静态数值的地方（历史原始价，必须如此），其余全是公式。
- `07` 表的历史分位用 `SUMPRODUCT` + `AGGREGATE` 现场计算，**刻意不用 MAXIFS/MINIFS**（部分 Office 版本返回 `#NAME?`，已实测）。

## 工作流程

```
① 确认参数 → ② 取真实汇率 → ③ 算 → ④ 出两个文件 → ⑤ 跑校验 → ⑥ 交付
```

### ① 确认参数（缺什么就问，不要编）

必填：外币金额、币种、方向（出口/进口）、结算期限（交易日 + 结算日）。
选填但强烈建议：人民币成本、目标毛利率、银行点差、银行实际结汇价。

> 成本与目标毛利率通常拿不到真实值——**就用示例值，并在文件里标「模拟」**，同时告诉用户改哪里。不要因为缺数据就跳过毛利与平衡汇率板块，那恰恰是销售最需要的部分。

### ② 取真实汇率

按 `references/data-sources.md` 的优先级取数。核心顺序：

1. **国家外汇管理局人民币汇率中间价**（历史序列主来源，日频，可回溯到所需年限）
2. **中国银行外汇牌价**（现汇买入/卖出价，证明"中间价≠到手价"）
3. 第三方聚合器（**只做量级核对**，不作报价依据）

关键换算：SAFE 原始表是**每 100 外币**，除 100 得到"1 单位外币 = X 人民币"；日元保留 "100 JPY" 口径。

### ③ 算

用 `scripts/calculations.py`（纯函数、币种无关）或直接在 Excel / HTML 里算。公式见 `references/formulas.md`。七种核心输出：

1. 当前汇率 + 报价方向 + 数据日期 + 时刻 + 来源
2. 1 年 / 3 年序列、走势、当前分位
3. ±1% / ±3% / ±5% 的人民币收付变化
4. 毛利额与毛利率（给定成本与目标毛利）
5. 平衡汇率（毛利归零 & 保目标毛利率 & 保目标毛利额）
6. 分批结算敏感性与加权汇率
7. 未计入因素清单

### ⑥ 交付

HTML 双击即可开；Excel 打开后先点一次"全部重算"（Ctrl+Alt+F9）。在回复里给出关键结论（当前汇率、分位、每 1% 敞口、平衡汇率、最大风险档位），并明确标注哪些参数是模拟的。

打包成可分发 ZIP：

```bash
python scripts/package_skill.py --out "<目标目录>/11.测算汇率波动对报价的影响.zip"
```

## 关键口径（最容易错的地方）

| 事项 | 正确做法 |
|---|---|
| 出口收入 | `Rev = A × R_结汇 × (1 − t)`，`R_结汇 = 银行现汇买入价` |
| 进口支出 | `Pay = A × R_购汇 × (1 + t)`，`R_购汇 = 银行现汇卖出价` |
| 方向符号 | 出口 `−1`、进口 `+1`，代入 `(1 + sign × t)` 统一公式 |
| 平衡汇率（出口） | `R* = C / [A × (1 − t)]` |
| 保目标毛利率 | `R* = C / [A × (1 − t) × (1 − m)]` |
| 平衡汇率（进口） | `R* = (S − C_oth) / [A × (1 + t)]` |
| 历史分位 | `(低于当前数 + 0.5 × 等于当前数) / 样本数` |
| 窗口 | 自然日回看 365 / 1095 天，左开右闭 |
| 已实现波动 | `std(ln 收益率) × √252`，**只描述过去** |

完整推导与边界情形见 `references/formulas.md`。

## 什么时候必须停下来问用户

- 币种规模极不寻常（例如 JPY 用了 1 单位而非 100 单位口径）；
- 金额与结算方式提示可能是进口但用户说是出口；
- 用户要求"预测下个月汇率"或"推荐锁汇方案"——**说明本技能不做这件事**，并给出可做的替代（情景测算、平衡汇率、历史区间）。
