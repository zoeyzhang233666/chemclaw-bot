# 找海外候选买家（Overseas Buyer Discovery）

一句话：**把「谁会买这个东西」变成一张能打电话、能点开出处、能标清证据等级的表**；并且每个结论都能回答“证据到哪一层”。

这个 Skill 与具体产品和国别无关。输入换产品、换国家，流程、证据分级、报告结构不变；只有 §2 的“产业用途地图”和 §3 的“通道清单”需要重建。

---

## 0. 先定契约（不出声地问清楚，缺项用推荐值）

| 字段 | 说明 | 缺省处理 |
|---|---|---|
| 目标国家/地区 | 必须是具体国家或区域 | 不能是“全球”，最多选 1–3 国 |
| 产品与规格 | 品名 + 关键规格（含量、堆密度、形态、包装、HS 编码） | 先推导规格再搜，别用泛词 |
| 目标客户类型 | 终端生产企业 / 直接进口商 / 经销商 / 不限 | 推荐“不限 + 分层” |
| 优先产业 | 例如玻璃、洗涤剂、造纸 | 缺省按用量强度排序取前 4 |
| 企业规模 | 不限 / 中大型 / 上市公司 | 缺省不限，但优先有披露的 |
| 是否只要真实终端工厂 | 是＝只保留自己用该产品做生产的厂 | 缺省“分层列出” |

用 `ask_user_question` 一次性问完并给推荐项；用户已经给了的就不要再问。

**规格先行**（易被忽略、却决定线索质量的一步）：重质 vs 轻质纯碱、片碱 vs 粒碱、工业级 vs 食品级，对应的下游完全不同。规格判断错误会导致整张表全是伪线索。操作：先查该规格的典型用途与 HS 编码（见 [`references/product-intelligence.md`](references/product-intelligence.md)）。

## 1. 证据分级（本 Skill 的核心，任何情况不得混淆）

| 等级 | 名称 | 判定标准（须同时满足） | 可写进销售动作 |
|---|---|---|---|
| **A** | 有直接贸易证据 | 公开来源直接出现该企业就该产品（或明确同类品）的**采购、进口、消耗**记录，且能给出①产品②方向（进口国→目的国 / 终端消耗）③期间 | 可谈价格与供应结构 |
| **B** | 有产品或业务相关证据 | 来源能证明企业**真实存在**且业务与产品**强相关**：产品目录列明该品、工艺必然消耗、或配方/原料表出现该品；但**无交易记录** | 可发技术资料，先确认用量 |
| **C** | 仅根据行业关系推断 | 只能证明其属于相关行业，未取得任何产品或贸易层面证据 | 只能电话核实，禁止报价 |

硬规则：

1. 没有可点开链接的条目 → 证据等级标 `未核实`、置信度 `低`，并写明“未取得”。
2. 同行（自己也生产该产品）不是客户 → 走 §5 peer gate 剔除。
3. “网站上写着供应某产品”的分销商是 **B**，不是 A——除非另有进口/采购记录。
4. 付费墙后的贸易数据库只给标题、不给企业明细时 → 结论写“企业级贸易记录不可得”，**不要**用“行业推测的进口量”冒充记录。
5. 不得记录任何人名、个人手机、私人邮箱；只用企业总机、企业邮箱、官网表单、公开投资者关系渠道。
6. 每条线索必须写“还需验证的关键问题”，而不是给出确定的采购结论。

完整判定表、反例与打分：见 [`references/evidence-grading.md`](references/evidence-grading.md)。

## 2. 建“产业用途地图”，拆 lane（第一步真正的工作）

先回答：**这个产品在每个下游是“怎么被用掉”的**。为每个 lane 写四件事：

- 用途/工序位置（在哪一步、起什么作用、是主料还是助剂）
- 用量强度（★★★★★ 单客户万吨/年；★★★★ 千吨/年；★★★ 百吨/年；★★ 十吨/年；★ 零星）
- 规格匹配（重质/轻质、纯度、杂质限值、包装）
- 该国的产业集群与具名候选 5–8 家

至少 6 个 lane 才收手。必须包含两类“容易被漏”的 lane：

- **深加工型**：把这个产品当原料再加工的企业（纯碱→水玻璃/硅酸钠；烧碱→次氯酸钠；硫磺→硫酸）
- **复配型**：把它当配方单体再复配转售的企业（洗涤剂代工/贴牌、水处理药剂复配、混凝土外加剂）
- **渠道型**：本国的进口商、区域分销商、工业电商目录商

方法、模板与常见遗漏：见 [`references/industrial-usemap.md`](references/industrial-usemap.md)。

## 3. 探通道（先验证机器可用，再开始大规模抓取）

按强度排序，**每级先小样实测一次**，不可用就跳下一级，不要反复重试（会被封）。

| 级 | 通道 | 强度 | 说明 |
|---|---|---|---|
| A1 | 官方贸易统计（UN Comtrade / WITS / 本国统计局） | 强（国家层） | 只能证明“国家在进口”，不能证明“某企业在进口”；用于市场与来源国结构 |
| A2 | 上市公司年报/可持续发展报告“使用材料”表 | 最强（企业层） | 印尼、日本、欧洲上市公司常披露 Soda Ash 吨数；这是 A 级证据的金矿 |
| A3 | 交易所披露、招股书、环评报告（中国 cninfo/地方生态环境局） | 强 | 中国/部分新兴市场的主要来源 |
| B1 | 企业官网产品目录、关于我们、联系方式页 | 强（主体与业务） | 目录列明＝B 级 |
| B2 | 行业目录/电商（indotrading、kompass、thomasnet、EC21） | 中 | 只作线索来源，必须回到官网核实 |
| B3 | 第三方贸易数据库（Volza/Tendata/ImportGenius/Seair/ExportGenius） | 中，多为付费墙 | 免费可见的才可引用，并注明聚合器局限 |
| C | 新闻、行业报道、行业协会、展览会名录 | 弱 | 只作补充，不作唯一依据 |

本 Skill 附带可直接用的抓取工具链（离线可读，含搜索/批量抓取/PDF 文本提取）：[`references/toolkit-windows.md`](references/toolkit-windows.md)、[`scripts/`](scripts/)。

**产出一条“本次可用通道清单”**（哪几个能用、哪几个被封、哪几个是付费墙），写进报告附录——这是必须交付的内容之一。

---

## 4. 并行铺 lane（fan-out）

- 每个 lane 一个子代理；并发上限 8；每个 brief 必须含六件套：①产品与规格 ②本 lane 范围与具名候选 ③可用通道与 URL 模板 ④固定 JSON 字段 ⑤落盘路径 ⑥防上下文耗尽纪律（每 lane ≤40 次抓取、每 5 条增量落盘、只读落盘摘要）。
- 同时起一个 **peer gate 子代理**（§5）和一个 **market facts 子代理**（§6）。
- 子代理崩了不要原样重发：改成“枚举式 brief”（把候选名单与股票代码直接写进 brief，禁检索，只核实）。

Brief 模板：[`references/lane-brief.md`](references/lane-brief.md)。字段契约与合并规则：[`references/data-contract.md`](references/data-contract.md)。

---

## 5. Peer Gate（与 lane 并行的独立关卡）

对每个候选判定 `producer / future_producer / competitor_supplier / distributor_of_competitor / consumer`：

- 该国**新建产能/在建项目**必须查——今天的买家明天可能变成竞争者。
- 分销商页面上写的是“某品牌代理” → 是竞品渠道，可开发但不要在首次接触中泄露客户信息。
- 判定结果写入报告“排除与同业”章节，并在 Excel 独立工作表列出。

---

## 6. 合并、核验、出报告

1. **合并**：按归一化公司名去重（PT/PT./P.T./Ltd/Co., Ltd 归一化），冲突时保留证据等级更高的版本，并把冲突写进备注。
2. **质量闸（五道）**：[`references/gates.md`](references/gates.md) —— 链接可达、主体一致（公司名与网页标题匹配）、证据等级与证据类型匹配、联系方式为公开企业级、每家有“待验证问题”。
3. **出 Excel**：用 [`scripts/build_xlsx.py`](scripts/build_xlsx.py) 生成 11 个工作表（说明与规则 / 候选总表 / 证据明细 / 公开联系方式 / 后验清单 / 行业地图 / 进口数据 / 排除与同业 / 话术草稿 / 产业时间线 / 我的跟进档案）；没有脚本环境时按 [`templates/工作簿结构规范.md`](templates/工作簿结构规范.md) 手搓。
4. **出 HTML**：用 [`scripts/build_html.py`](scripts/build_html.py) 生成本报告模板（筛选器 + 卡片展开 + 生成询证邮件 + 本地线索档案）。模板说明见 [`templates/HTML报告模板指南.md`](templates/HTML报告模板指南.md)。
5. **最终回答**必须包含：条数与分布、证据分级与高等级凭什么、被剔除的同行、**未覆盖缺口与负结果**。

**一键重建**：把归一化后的 `leads_merged.json` 放进工作目录，跑 `python scripts/run_all.py <工作目录>`。它先校验（必填字段、等级合法性、证据是否有链接、有无未标注的个人手机号），有硬伤直接中止，然后依次生成 HTML 与 XLSX。

**自动验收**：`python assets/qa_report.py <报告.html> [chromium路径]` 会检查四种宽度无横向溢出、无 JS 报错、卡片数=线索数、筛选/展开/保存线索/生成邮件四个交互可用。**不通过不交付。**

## 7. 交付物结构

```
交付_<国家>_<产品>_候选买家_<日期>/
├─ <国家>_<产品>_海外候选买家调查报告.html     ← 交互式，可筛选/展开/生成邮件
├─ <国家>_<产品>_候选买家线索工作簿.xlsx        ← 11 个工作表，带证据链
├─ 方法说明与证据规则.md                       ← 通道清单、分级、负结果
└─ 原始证据/                                   ← 落盘的抓取文本与 PDF（可选，便于复核）
```

## 8. 完成判据（缺一不交付）

- [ ] 候选 ≥15 家，lane ≥6，类型至少覆盖“终端工厂”和“进口商/经销商”两类
- [ ] A 级证据均给出产品+方向+期间；A 级为零时必须明确写出“本期未取得企业级直接贸易证据”及原因
- [ ] 每家都有官网或至少一个可点开的来源链接；无链接的标注“未核实”
- [ ] 每家都有“还需验证的关键问题”
- [ ] 报告含：分布、分级依据、同行剔除、负结果与缺口
- [ ] 无个人联系方式、无编造交易记录（企业官网/商铺公开的业务号码须显式标注来源）
- [ ] `assets/qa_report.py` 全部通过（布局 + 交互 + 字段完整性）
- [ ] 报告 §0 有“本次没有拿到的东西”清单

打分口径与判定表：[`references/gates.md`](references/gates.md)。失败模式与修法：[`references/failure-log.md`](references/failure-log.md)。完整走查案例：[`examples/`](examples/)。
