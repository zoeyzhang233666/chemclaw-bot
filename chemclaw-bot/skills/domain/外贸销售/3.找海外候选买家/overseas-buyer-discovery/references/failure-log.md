# 失败模式库（按出现频率排序）

每条：现象 → 根因 → 修法 → 预防。

---

## F1 搜索引擎封禁（高频）

- **现象**：Brave 返回 captcha 页；Bing 结果与查询无关；DDG 返回 202。
- **根因**：短时间高频请求；未登录 Bing 会对印尼/东南亚类查询做语序切分。
- **修法**：立即切换到①直连企业官网②官方 PDF 年报③交易所镜像；等 15–20 分钟再试搜索。
- **预防**：搜索预算按 lane 分配（每 lane ≤12 次），优先"结果页直链 + 官网抓取"。

## F2 子代理上下文耗尽或超时

- **现象**：跑很久无落盘；或回来只有公司名清单。
- **根因**：一次读入整页 HTML；没有增量落盘；反复重试失败通道。
- **修法**：改"枚举式 brief"（把候选名单写进 brief、只核实、禁检索、≤30 次抓取）；要求每 5 条落盘。
- **预防**：brief 六件套必须含落盘路径与抓取上限。

## F3 官网对境外 IP 超时 / 403（印尼、印度、中东常见）

- **现象**：企业官网 `amfg.co.id`、`mulia-industrindo.co.id` 直连超时或 500。
- **修法**：换域（`muliaindustrindo.com`）、换路径（`/en/index`）、查 S3 托管 PDF、用行业目录页作 B 级证据来源。
- **预防**：同一主体准备 2 个入口；记录"需人工复核"。

## F4 误把同行当客户

- **现象**：名单里混入本产品生产商或其销售公司（如把"Asahimas Chemical（氯碱/PVC）"与"Asahimas Flat Glass（玻璃）"混淆）。
- **修法**：peer gate 独立子代理；名称高度相似的公司必须加"业务形态"列。
- **预防**：每家必答"它自己生产本产品吗"。

## F5 把"国家进口数据"写成"企业采购证据"

- **修法**：企业证据必须指向企业；国家数据只进"市场事实"章节。
- **预防**：evidence_list 里 `company_scope` 字段只允许 `企业` 或 `行业/国家`。

## F6 联系方式违规

- **现象**：写入个人手机、`@gmail` 邮箱、LinkedIn 人名。
- **修法**：一律删除，替换为官网表单/企业总机；Evidence 说明"官网未公开企业邮箱"。
- **预防**：Contact Gate 在合并时自动过滤（见 gates.md）。

## F7 PDF 下载得到 400 多字节错误页

- **现象**：年报"下载成功"但只有 434 字节。
- **修法**：检查文件头 `%PDF`，从交易所镜像或 S3 直链重下；用 `curl.exe -L` 跟随跳转。
- **预防**：下载后校验大小与 `%PDF` 头。

## F8 语言误判（印尼语/越南语/葡萄牙语）

- **现象**：搜 "soda kue" 得到食用小苏打卖家；"distributor kimia" 得到个人电商。
- **修法**：先做本地词表（工业碱 vs 食用碱；工厂=PT … Industri/Pabrik），再搜；用 HS 编码交叉验证。

## F9 证据过期

- **现象**：引用的年报是 2019 年的。
- **修法**：统一取最近一期；旧证据标注"历史 A 级"。
- **预防**：`evidence_period` 必填，合并时按年份排序。

## F10 付费墙误判为"无数据"

- **现象**：Volza/Tendata 只显示标题就写"未找到"。
- **修法**：明确写"企业级记录不可得（付费墙）"，并用替代证据（年报/进口商目录/供应商公告）降级支撑。
- **预防**：在报告中设"不可得清单"，把不是"找不到"而是"拿不到"的说清楚。

# 第二批：本次运行新增（F11–F18）

## F11 Windows 下的中文编码雪崩（本次最痛，务必先读）

**现象**：Python 脚本里本该是中文的字符串，打开后变成 `鍗板凹閲嶈川绾⒈` 这类乱码，或直接 `SyntaxError: invalid non-printable character U+E1BF`。

**根因**：中文在 UTF-8 与 Windows 默认代码页（GBK/936）之间被来回转码了一次以上。典型触发器：
- 用 `Out-File` 写 `.py`；
- 用 `Get-Content -Raw | Set-Content` 做"小修改"（读时按 UTF-8、写时按代码页，中文全毁）；
- PowerShell 控制台显示乱码，让人误以为文件坏了（**实际上文件可能是好的**）。

**修法**：
1. 先用 Python 确认坏没坏，不要相信控制台输出：`open(p, encoding="utf-8").read()` 不报错 = 文件本身是好的。
2. 若确实坏了，尝试反解：`t.encode("gbk", errors="replace").decode("utf-8", errors="replace")`。
3. 改中文文件一律用 Python 或 write/edit 工具，**绝不用 `Set-Content` / `Out-File` 覆写**。

**预防**：脚本里中文用 `\uXXXX` 转义或放独立 JSON；写入后 `assert "\ufffd" not in text`；控制台先设 `$env:PYTHONIOENCODING="utf-8"`。

## F12 用 `%` 或 f-string 套大段 HTML 模板

**现象**：`TypeError: not enough arguments for format string`，报错出现在模板正文。

**根因**：正文天然含 `99.2%`、`27.3%`、`30%`，JS 里还有 `%` 运算符，被当成占位符。

**修法**：模板用 `{{占位符}}`，渲染时循环 `str.replace()`。

**预防**：模板超过 50 行就别用 `%` / f-string。本次因此返工两次。

## F13 贸易站"索引页有、提单页没有"

**现象**：公司出现在 "soda ash importers" 索引页且带产品文本，但其公司页 `Sample Bill of Lading` 展示的是柴油、松木、酶制剂。

**根因**：贸易数据站每个公司页的"样例提单"是随机抽的一条，不保证是查询商品；真正的产品信息只在索引页那一行。

**修法**：
- 索引页有产品文本 → **A 级**；
- 索引页只有公司名、无产品文本 → **C 级**；
- 公司页提单是别的商品 → 它是活跃化工进口商（采购能力佐证），但那条提单**不能**当本品交易记录，置信度降为"中"。

**预防**：证据 `caveat` 里明确写"该页公示的提单样例非本品"。

## F14 采购方页面被误读为供应方证据

**现象**：分销商网站写 "Soda Ash Dense ex ANSAC USA"，被解读成"ANSAC 是我们的客户"。

**根因**：页面主语搞错——那个页面属于分销商，描述的是**它在卖谁的货**。

**修法**：竞品品牌出现在下游页面上，一律归为"该分销商代理该品牌"，是**竞品渠道**，进 peer gate，不进客户名单。

## F15 把集团名当同一法人（最隐蔽）

**现象**：看到 Mulia、Kedaung、Asahimas 就当成一家公司合并。

**实际情况**：
- `PT Mulia Industrindo`（玻璃，买纯碱）≠ `PT Muliakeramik Indahraya`（瓷砖）；
- `PT Asahimas Flat Glass`（玻璃，买纯碱）≠ `PT Asahimas Chemical`（氯碱，产烧碱）；
- `PT Kedaung Indah Can Tbk`（搪瓷）≠ `Kedaung Subur`（玻璃器皿进口商）。

**修法**：合并前先 `norm()` 归一化，再比对**业务形态**；名字相近但业务不同的一律分开，并在 `alt_names` 注明关系。

## F16 CSS Grid 用 `1fr` 导致整页横向溢出

**现象**：桌面正常，390px 宽时整页横向滚动（`scrollWidth` 912 > `clientWidth` 390）。

**根因**：`grid-template-columns: 1fr 1fr` 的轨道最小宽度是内容 `min-content`，里面的宽表格把轨道撑开。

**修法**：写 `minmax(0,1fr)`，子元素加 `min-width:0`；宽表格单独包一层 `overflow-x:auto`。

**预防**：QA 断言 390px 下 `scrollWidth <= clientWidth + 2`。

## F17 只凭"官网打不开"就判定企业不存在

**现象**：域名打不开，就写成"查无此企业"。

**根因**：印尼中小企业域名常年失效换域，但企业仍在地经营。

**修法**：写"官网无法验证（超时/域名失效），企业存在性待人工核实"，降级到 C；**不要**写"不存在"。

## F18 同一集团被拆成多条线索

**现象**：`PT Mulia Industrindo`、`PT Muliaglass`、`Muliaglass` 在合并后变成三条线索。

**根因**：各 lane 独立抓取，命名粒度不同（集团 vs 子公司 vs 品牌）。

**修法**：合并阶段用 `norm()`（去 PT/Tbk/Ltd、去括号、去非字母数字）做键；集团/子公司关系**显式合并**并在 `alt_names` 写"同集团：PT Muliaglass"；业务不同的同集团主体**不合并**（见 F15）。

**预防**：在 `leads_merged.json` 里保留 `alt_names` 与合并日志，便于回溯。

## F19 占位符替换漏了 `%(name)d`，页面上直接印出 `%(cA)d`

**现象**：用户报“卡片内容看起来是带 % 的乱码”——实际是 hero 与 KPI 区直接印着 `A 级 %(cA)d · B 级 %(cB)d`，页头徽章显示 `{14}`。自动化 QA 全部通过，因为它只查布局与交互，不查模板渲染是否干净。

**根因**：把 `%`-format 模板改成 `{{占位符}}` 时，只替换了 `%(name)s`，漏掉整数占位符 `%(name)d`；补替换时又写成三花括号，渲染出 `{14}`。

**修法**：
1. 用正则一次性覆盖全部类型，别手写替换：
   ```python
   t = re.sub(r"%\((\w+)\)[sd]", r"{{\1}}", t)
   ```
2. 修完立刻对**输出 HTML** 断言：不含 `%(`、不含 `{{`、不含 `>{14}<` 这种双花括号泄漏。

**预防**：`assets/qa_report.py` 已内置该静态检查。**布局测试全绿 ≠ 内容正确**——渲染类 bug 必须查源码，不能只靠截图和 DOM 尺寸。

## F20 卡片头部过高，看起来像“被抬头遮挡”

**现象**：用户觉得“抬头遮挡了第一排卡片，看不见全部”。

**根因**：`.card-h` 内边距偏大且未限制 `min-height`，标题与徽章组在中等宽度互相挤压，卡片头部撑到约 100px；再叠加 F19 的 `%` 残留，视觉上就像排版塌了。

**修法**：收紧内边距、加 `min-height:0`、标题 `white-space:nowrap` + `text-overflow:ellipsis`、徽章组 `flex:0 0 auto` 右对齐；仅 ≤900px 允许换行。桌面各宽度头部高度锁定在 88px。

**预防**：验收时量所有卡片头部高度，确认取值收敛（不能出现 88–220px 这种离散分布）。另：本项目从未设置过 `position:sticky` 的抬头，若用户仍说“遮挡”，先量 `getBoundingClientRect` 再改代码，不要凭感觉加 z-index。
