# Lane Brief 模板（六件套）

给每个 lane 子代理的 brief 必须包含以下六块，顺序固定。缺一块就会出现“回来一堆公司名、没有证据”。

---

```
你是 B2B 外贸线索研究员。任务：为【产品+规格】【目标国家】【lane 名】收集并核验候选买家，产出证据分级后的 JSON。

【① 产品与用途】
产品：<中文名 / 英文名 / 化学式 / CAS / HS>
规格：<形态、含量、堆密度、杂质限值、包装>
本产品在该 lane 的用途：<工序位置、作用、典型添加比例>
用量强度：★★★（单客户 ×× 吨/年）

【② 本 lane 的细分范围与候选企业】
范围：<明确边界，例如“浮法玻璃与玻璃容器厂，不含玻璃贸易商”>
候选（先列已知，需核实，不要盲信）：1) … 2) … 3) …
必须回答：这些企业里谁是终端？谁只是贸易商？是否同时是同行（自产本产品）？

【③ 可用通道与 URL 模板】
A. 官方统计：<UN Comtrade / WITS / 本国统计局 URL 模板>
B. 上市公司年报：<交易所披露页、IR 页面、常见 PDF 命名>
C. 企业官网：<域名猜测规则，但必须抓取验证>
D. 行业目录：<indotrading / kompass / 展会名录>
E. 贸易数据：<免费可见与付费墙区分>
工具：<工作目录的 web_cmd.cmd、fetch_many.ps1、python+pypdf，或你自己环境的等价工具>

【④ 固定 JSON 字段】
严格按 references/data-contract.md 的字段输出，每家企业一个对象；
证据分级严格按 references/evidence-grading.md：A=有直接采购/进口/消耗证据（含产品+方向+期间），
B=产品或业务强相关但无交易记录，C=仅行业推断。没有链接的写 evidence_tier="未核实"。

【⑤ 落盘路径】
leads_raw/NN_<lane>.json（数组，增量追加，每 5 条写一次）
notes/NN_<lane>_notes.md（通道可用性、负结果、死查询）

【⑥ 防上下文耗尽纪律】
- 总抓取 ≤40 次；单企业 ≤2 页；长网页只保留关键词上下文 200 字。
- 先落盘再汇报；最终回复 ≤400 字，只给“公司名 + 等级 + 文件路径”。
- 搜索连续 2 次返回空，换通道，不重试同一查询超过 2 次。
```

## 附：枚举式 brief（上一条崩溃后使用）

```
不使用任何搜索引擎。只允许打开下列 URL（每家 ≤2 页，总计 ≤30 次抓取）。
只用这些已知候选与股票代码，逐个确认：是否存在、是否为该品终端、是否自产该品（同行？）、有无公开采购/消耗证据。
候选：<公司名> (<代码>) / <公司名> (<代码>) / …
输出仍按 data-contract.md；无法确认的写 evidence_tier="未核实" 并说明卡在哪一步（403/超时/查无此页）。
每 5 条增量落盘。
```

---

## 子代理复盘时必须问的三件事

1. 哪几家你**没能**核实？卡在哪个通道？
2. 哪些候选最后发现是同行或竞品渠道？
3. 这个 lane 有没有你怀疑存在、但公开资料查不到的“隐形大用户”（如有，写进缺口清单）。
