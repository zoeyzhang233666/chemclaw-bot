# HTML 报告模板指南

报告是单文件、零外部依赖的（图标、样式、脚本全部内联），双击就能开，微信/邮件发出去也不会散架。

---

## 一、页面结构（7 个板块，顺序固定）

```
Hero          标题 + 产品/国家/目标客户 + 日期与统计徽章
KPI ×4        A/B/C 三级数量 + 剔除的同行数
§0  怎么读    证据三级定义表 + 三条红线 + "本次没有拿到的东西"
§1  市场背景  进口额/均价图表(SVG) + 分来源国表(两年对照) + 时间窗口提示
§2  候选企业  筛选器(类型/等级/地区/领域 + 搜索) + 50 张可展开卡片
§3  打法      三类客户(终端/进口商/经销商)各自的话术与踩坑
§4  peer gate 排除清单表(企业/判定/理由/来源)
§5  核验清单  4 大类 × 3 问的提问清单
§6  数据来源  事实表(类别/事实/数值/期间/置信度/来源链接)
Footer        免责声明
```

---

## 二、卡片（核心交互单元）

每张卡片折叠时显示：编号、企业名、一句话业务、类型徽章、证据徽章、地区、业务领域、置信度。

展开后显示 6 个区块：

1. **业务与产品相关性** — 为什么这产品与它有关
2. **证据摘要** + 期间徽章
3. **公开企业联系方式** — 官网/总机/企业邮箱/地址，表格形式
4. **建议核验路径**
5. **证据链** — 逐条罗列，每条带等级徽章、类型、期间、原文引用（等宽字体灰底）、局限说明、来源链接
6. **还需验证的关键问题** — 有序列表

底部 4 个按钮：`生成询盘邮件` / `加入我的线索档案` / `复制联系人卡片` / `企业背景核查`（外链 Google）。

---

## 三、必须实现的交互

| 交互 | 实现要点 |
|---|---|
| 多条件筛选 | 给每张卡片挂 `data-type / data-tier / data-region / data-lane / data-q`，筛选时用 `classList.toggle('hidden')`，实时更新计数徽章 |
| 关键词搜索 | `data-q` 里预先把公司名+业务+产品相关性+地区拼成小写串，搜索只做 `includes()`，不逐节点遍历文本 |
| 展开/折叠 | 点击标题栏给 `.card` 切换 `.open`，高度过渡用 CSS `max-height` |
| 生成询盘邮件 | 按 `evidence_tier` + `type` 选三套模板之一，拼 `mailto:`；没有企业邮箱时给出提示而不是静默失败 |
| 存入线索档案 | `localStorage` 键名固定（本轮用 `oceanLeads_v1`），存 `{company, type, tier, region, lane, website, next_step, added}`，重复添加要提示 |
| 复制卡片 | `navigator.clipboard.writeText`，失败时降级提示让用户手动选 |

## 四、图表规范（纯 SVG，不用图表库）

- `viewBox` 固定，`width="100%"` 自适应
- 柱状用 `<linearGradient>`，数值标在柱顶
- 第二指标（CIF 均价）用**虚线折线 + 空心圆点**叠加在双轴上
- 网格线 5 条，左侧刻度标数值
- X 轴标签下面再补一行数量（kt），避免读者只看钱不看量
- **必须给 `<svg id="chart">`**，否则自动化检查无法定位

## 五、响应式断点

| 断点 | 处理 |
|---|---|
| ≤1100px | `grid2` / `chartwrap` 单列 |
| ≤760px | Hero 缩小、KPI 两列、工具栏全宽、卡片内边距收紧、表格改为可横向滚动 |
| ≤430px | KPI 单列 |

**关键坑：** 用 `grid-template-columns: minmax(0,1fr)` 而不是 `1fr`。否则表格的 `min-content` 宽度会把整页撑出横向滚动条（这是本次实测踩到的）。

## 六、验收清单

交付前必须逐项过：

- [ ] 单文件，无 CDN/外链 CSS/JS，断网可开
- [ ] 四种宽度（1440/1024/768/390）无横向溢出（`documentElement.scrollWidth <= clientWidth`)
- [ ] 无控制台报错（`pageerror` 为空）
- [ ] 卡片数量 = 线索数量
- [ ] 每条线索都具备 `type/evidence_tier/region_short/lane/lane_label/main_business/why_related/evidence_summary/evidence_urls/confidence` 十个字段
- [ ] 筛选结果与总表一致（A 级数量两边相同）
- [ ] 邮件草稿能拼出可读的英文正文，三套模板各测一遍
- [ ] 点击保存后 `localStorage` 里确实多了一条
- [ ] 页面上**不出现任何个人姓名、个人手机、个人邮箱**
- [ ] §0 里写明"不确认任何采购关系"与"本次没有拿到的东西"
- [ ] 没有未经来源的数字（"预计""大约"这类词应当被替换或删除）

## 七、生成脚本约定

```
build_html.py <输出路径.html>
输入（同目录 JSON）：leads_merged.json / comtrade_series.json / comtrade_partners.json
                     peer_gate.json / market_facts.json / timeline.json
```

用 Python 生成时**不要用 `%` 或 f-string 直接套大段模板**——报告正文里天然含有 `99.2%`、`27.3%`、JS 里的 `%`，极易触发格式化错误。本次改用 `{{占位符}}` + 渲染后 `str.replace`，彻底避免了这个问题（见 `references/failure-log.md` 第 6 条）。
