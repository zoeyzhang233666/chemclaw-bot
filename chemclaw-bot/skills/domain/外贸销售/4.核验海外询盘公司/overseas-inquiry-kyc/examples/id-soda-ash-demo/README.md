# 案例：印度尼西亚 · 重质纯碱询盘核验（模拟）

> ⚠️ **本案例为方法演示，询盘主体为虚构。**
> `PT Sinar Kaca Nusantara`、`sinarkacanusa.co.id`、联系人 `Andi Pratama Wibowo`、
> 地址与电话均为编造，不对应任何真实企业。报告中出现真实机构（AHU / OSS / DJP / BSN 等）
> 仅为**官方检索入口**，不被表述为询盘发送方。

## 这个案例要演示什么

一封看起来挺像样的印尼询盘：

> 自称印尼玻璃制造商（两座浮法窑、年产能 120 万 m²），同时自称"official importer"并有港区仓库，
> 要买 25,000 吨/年重质纯碱，首批 500 吨，CFR Tanjung Priok / CIF Surabaya，
> 但**要求先签 NDA 才给证照**，只给了一个手机号。

销售最想问的是"这家是不是骗子"。本案例示范的是：**把这个问题拆成 24 个能逐一回答的小问题**，
然后给出 4 个已核实、2 个疑点、18 个未核实——以及"18 个未核实"为什么是**正常且有用的结果**。

## 结果概览

| 状态 | 条数 | 含义 |
|---|---|---|
| 已核实 | 4 | 产品形态与用途匹配、名称内部一致、邮箱渠道自洽、包装与物流匹配 |
| 存在疑点 | 2 | ① 地址口径（Cakung 办公 vs Bekasi 工厂）；② 规模口径（120 万 m²/年 与 25,000 t/年 对不上） |
| 未核实 | 18 | 缺 NIB / AHU 登记号 / 产能数据 / 收款账户等，全部转入资料索取清单 |

**没有 high 级疑点**，所以结论是"可以继续沟通并同步补齐资料"，而不是"暂停"。

## 精心的设计点（也是这个 case 的教学价值）

### 1. 疑点必须有边界
两条疑点都不是"造假"，而是"需要解释"：

- 地址：**办公室在 Cakung（雅加达东部）、工厂在 Bekasi（相邻行政市）是印尼制造业的常见布局**。
  所以判 `partial`，不是 `different`。把三/四个地址分开记录，而不是合并成一个"公司地址"。
- 规模：自述"两座浮法窑 + 120 万 m²/年"与"25,000 t/年纯碱"在数量级上不匹配。
  但算不通常见原因是口径不同（只算一条线、按成品面积算），所以要求补熔窑 t/d 数据，**不推断虚报**。

### 2. NDA 前置是 low 级疑点，不是高风险
很多 sales 会把"不肯先给证照"直接判成"心虚"。本案例的处置是：
**不拒绝 NDA，把"需要 NDA 的"（配方、客户名单、价格）与"不需要 NDA 的"（营业执照、NIB、官网页）拆开**，
并给出并行方案（今天签 NDA + 同步发表格信息，关键号码可打码）。

### 3. 18 个"未核实"是交付价值，不是失败
因为这 18 条完整构成了**下一步资料清单**（P0/P1/P2 + 英文表述 + 为什么要）。
报告不是用来"给结论"的，是用来**驱动下一轮沟通**的。

### 4. 一个正面的已核实项：邮箱没有跳转
`Reply-To` 与企业域名一致，没有跳 gmail —— 这是**加分项**，值得单独写一条 `verified`。
尽调报告里只写坏消息会让人误判。

### 5. 明确不给的东西
- 不给"诈骗概率"；
- 不以"域名注册时间"判真伪；
- 不把"查不到 AHU"写成"公司不存在"；
- 没有把任何同名企业的负面信息并到本主体。

## 换成你的印尼客户要改哪里

| 改这里 | 说明 |
|---|---|
| `meta.*` | 标题、基准日、产品、数量 |
| `meta.synthetic` → `false` | 删掉 `synthetic_note` |
| `inquiry.*` | 真实邮件原文 |
| `subject.*` | AHU / OSS 的检索结果 |
| `business_fit.keywords` | KBLI 码（23111 平板玻璃 / 46651 化工批发 / 46632 玻璃批发 / 52101 仓储） |
| `sources[]` | 官方入口保持不变，把 `retrieved` 改成你的检索日 |

框架、矩阵、话术、三分法全部照用。
