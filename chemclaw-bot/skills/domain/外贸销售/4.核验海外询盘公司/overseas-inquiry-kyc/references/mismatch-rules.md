# 联系方式一致性规则（Mismatch Rules）

> 这一页管的是"同一个事实，在不同地方说法不一样"。这是外贸尽调里最实用、也最容易被忽略的一环。

## 一、矩阵比对结果只有五种

| 值 | 中文 | 判据 |
|---|---|---|
| `same` | 一致 | 两处说法逐字可比且相符（允许大小写/空格差异） |
| `partial` | 部分一致 | 核心一致但有一处需要解释（如地址属不同行政区但相邻） |
| `different` | 不一致 | 两处明确矛盾，无法调和的解释 |
| `unknown` | 无法比对 | 只有一处说法，或缺另一方材料 |
| `misattribution` | 疑似错配 | 命中的是**另一个主体**（同名企业、相似域名） |

**"无法比对"是最常见的，也是最容易被写成"不一致"的。** 不许这样写。

## 二、12 类高频矛盾与处置

### 1. 域名 ≠ 公司名
例：`PT Sinar Kaca Nusantara` → `sinarkacanusa.co.id`（丢了 Nusantara 的 t）。
判：`partial`。缩写有解释空间，但要求对方**书面确认这是官方域名**，或在官网 Footer 确认。
**不出结论：**"域名与公司名不符 → 假网站"。很多印尼企业用创始人姓名或旧名做域名。

### 2. 邮箱后缀 ≠ 官网域名
A 真问题：官网是 `company.id`，邮箱是 `company.co.id`（两个域名）。
B 伪问题：官网用 `www.`，邮箱用裸域。
判：A → `different` 并要求解释；B → `same`。

### 3. Reply-To 跳到免费邮箱
这是**最经典的冒充手法之一**：From 用企业域名，Reply-To 指向 gmail/qq。
判：`different`，severity `high`。
> 注意：有些企业确实用 gmail 做二级邮箱，所以要看**是不是"Reply-To 单独跳走"**。

### 4. 签名地址 vs 注册地址 vs 工厂地址
三个地址本来就可以不一样（办公室/注册地/厂区/仓库）。
判：如果三处都能自洽解释 → `same` 或 `partial`；如果**没人解释**、且分属不同国家/大区 → `different`。
**永远把三个地址分开记录，不要合并成一个"公司地址"。**

### 5. 邮编与区域不符
例：`Cakung, Jakarta Timur 13910`。
判：核对邮编是否属于该区。属于 → `same`（表面自洽）；不属于 → `partial` + 要求说明。

### 6. 只有手机号，没有公司总机
中小企业常态，**不构成疑点**。但：
- 采购量很大（如万吨级原料）却只有手机 → `partial`，要求索取总机；
- 手机号与名片一致、官网上也是同一号码 → 可以给一条 `verified`（渠道一致）。

### 7. 职位与联系方式不匹配
例：名片写 Procurement Manager，邮箱却是 `sales@`。
判：`partial`。可能是共用邮箱，也可能是伪造。
**动作**：请对方用 `andi.pratama@` 直接回一封，或要求视频确认。

### 8. 联系人姓名拼写变体
`Andi Pratama` vs `A. Pratama` vs `Andi P. Wibowo`。
判：东南亚/南亚人名有省略中间名的习惯 → `partial` 即可，不必升级。

### 9. 网站内容与其他企业高度雷同
把官网截图与同类企业比对（About 段落、产品图、模板）。
判：文字/图片完全一样 → `misattribution` 风险，`high`。
（很多贸易商的模板站会互相抄，所以要**看图片里的工厂/设备是否也一致**。）

### 10. 官网 Contact 页没有地址 / 只有一个表单
判：`unknown`。要求索取。**不写"没有地址=不正规"**。

### 11. 电话区号与地址城市不符
例：地址在泗水（031），电话是雅加达（021）。
判：`partial`。集团总部/代理商常见。要求说明。

### 12. 邮箱域名的 WHOIS 注册人与企业无关
注册人是个人或代理商，**非常常见**。
判：`unknown`，只在 `note` 里记录。**不得据此判定企业真伪。**

## 三、发信认证（email_auth）怎么读

| 检查项 | 看到什么算"正面" | 看到什么算"需要注意" |
|---|---|---|
| SPF | 存在 `v=spf1` 且包含实际发信服务 | 完全没有（中小企业常见，不判假） |
| DKIM | 有签名头 `DKIM-Signature` | 无 |
| DMARC | `_dmarc` 有 `p=` 策略 | 无（很常见） |
| Reply-To | 与 From 同域 | 跳到免费邮箱/其他域 |
| Received 链 | 首跳 IP 与对方国家一致 | 首跳在中转商/异常地区（需结合上下文） |
| 显示名 | 与发件人地址相符 | 显示名是"CEO"，地址是随机串 |

> **纪律**：SPF/DKIM/DMARC 全缺，只能写"发信基础设施不完整"，
> 不能写"不是正规企业"。真正要做的是**换一个渠道（电话/视频）确认身份**。

## 四、一致性检查的执行顺序

```
1. 对方自述内部是否自洽？（邮件 vs 名片 vs 附件）
2. 对方自述 vs 官网是否一致？
3. 官网 vs 官方登记册是否一致？
4. 发信渠道是否可核（SPF / 回拨 / 视频）？
5. 所有"对不上"的项，能否用"注册地/厂区/仓库/代理"四种身份解释？
```

第 5 步是关键：**先找合理解释，再判定矛盾**。找不到解释才升级。

## 五、写进报告的标准句式

```text
【核对项】电话
【询盘中的说法】+62 812-3456-7890（手机）
【另一来源】官网/名片（未取得）
【比对】无法比对
【说明】仅提供手机号是中小企业常态；但 25,000 t/年 的采购通常有公司总机，建议索取。
【下一步】Q04 — 索取公司总机与采购部公共邮箱；关键确认走"邮件 + 回拨"双通道。
```

这五段（核对项 / 询盘说法 / 另一来源 / 比对 / 说明+下一步）就是 `matrix[]` 的字段结构。
