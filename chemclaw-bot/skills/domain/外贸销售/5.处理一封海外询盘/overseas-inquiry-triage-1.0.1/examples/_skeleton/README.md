# 空白骨架 · 换品类时整目录复制

```bash
cp -r examples/_skeleton examples/my-inquiry-2026
# 把客户邮件放进 examples/my-inquiry-2026/input/ （.eml 优先，没有就用 .txt）
python scripts/make_example.py examples/my-inquiry-2026
```

产物会生成在 `examples/my-inquiry-2026/` 下（01–07）。

---

## input/ 怎么放

| 文件 | 说明 |
|---|---|
| `询盘邮件.eml` | **推荐**。原始邮件，保留 Date / From / Subject，抽取最准 |
| `询盘邮件.txt` | 次选。正文 + 签名，第一段写 `Subject:`，第二段写 `From:` 也可以 |
| `询盘原文_合并.md` | 多份素材合并时用 `素材01` / `素材02` 分块（历史邮件、附件、内部资料） |

> 没有 `.eml` 也没关系：`.txt` 里把邮件头和签名照抄进去就行，字段照样能抽。

---

## 三个必须自己想清楚的问题（抽字段之前）

1. **这是客户原文，还是同事转述？**
   转述的内容不能当客户原话引用——客户说"需要 COA"，同事转述成"客户要全套单证"，
   后者写进邮件就是替客户加要求。

2. **有没有历史轮次？**
   上一轮客户已经答过的问题不要再问。历史邮件用 `素材02` 放进来，脚本会把它当"背景"，
   但**只有最新一轮是有效数据**。

3. **这封是模拟件吗？**
   是的话，`input/` 里要留标记（`.eml` 加 `X-Demo-Notice: SIMULATED` 头，或 `.md` 里写
   「模拟案例」），三处产物都会带「模拟」标注。真实询盘别加。

---

## 抽完必须人工过的四件事

| 看哪里 | 要确认什么 |
|---|---|
| `04_询盘审阅板.html` → 缺失与歧义页 | 歧义项是不是真歧义？有没有把客户说过的判成"缺失"？ |
| 同页 → 待确认问题页 | 问题是不是客户能一句话答？有没有问到客户上一轮已经答过的？ |
| 回复草稿页 | 复述段有没有把"我方猜测"写成"我方理解"？ |
| 下一步场景页 → 导出交接 JSON | 交给报价环节的字段干净吗？缺口标出来了吗？ |

改完在页面上点「客户已确认」或直接改字段值——**改的是 JSON，不是 HTML**，下次生成不会被覆盖。
