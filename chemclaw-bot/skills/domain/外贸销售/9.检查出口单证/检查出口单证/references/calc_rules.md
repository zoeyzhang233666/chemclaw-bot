# 计算关系核验：公式、容差与判据

> 跨文件比对只能发现"抄错"，计算核验能发现"算错"和"填错"。两者互补。

---

## C1 数量 × 单价 = 总金额

| 项目 | 内容 |
| --- | --- |
| 公式 | `quantity × unit_price ≈ amount` |
| 数据来源 | 优先取**同一份**单证上的三个值（CI 最常见）；同单证缺失时取跨单证众数 |
| 容差 | 相对误差 ≤ 0.5%（允许四舍五入与尾差），或绝对差 ≤ 1 个币种单位 |
| 单位处理 | 数量若为 `MT` 而单价为 `/KG` 报价，先统一到同一单位再乘 |
| 判据 | 超容差 → **S1 计算不符** |
| 典型事故 | 数量 1,000 MT × 520 USD/MT，发票金额却写 500,000（少算 20,000）——银行按发票金额议付，差额无处追讨 |

## C2 数量 ↔ 净重

| 项目 | 内容 |
| --- | --- |
| 公式 | `net_weight(KG) ≈ quantity(MT) × 1000` |
| 容差 | 相对误差 ≤ 0.5% |
| 说明 | 若合同另有约定（如按净重计价含水分扣减），以合同为准；工具只在偏差 >0.5% 时提示 |
| 判据 | 超容差 → S1 |

## C3 毛重 − 净重 = 皮重（包装重量合理性）

| 项目 | 内容 |
| --- | --- |
| 公式 | `tare = gross_weight − net_weight`；`per_bag_tare = tare ÷ package_count` |
| 合理区间 | 吨袋（1000 KG JUMBO BAG）单袋皮重 **1–10 KG**；25KG 编织袋 **0.1–0.5 KG** |
| 判据 | `per_bag_tare` 落在区间外 → **S1 计算不符**（多半是净重或毛重抄错一位） |
| 为什么这样判 | 1,000 袋、皮重合计 50,000 KG → 每袋 50 KG，一个吨袋不可能重 50 KG，说明数据有误 |
| 注意 | 若包装含托盘/木箱，皮重会升高；需要人工确认时不要强行判错 |

## C4 单件净重 = 净重 ÷ 件数

| 项目 | 内容 |
| --- | --- |
| 公式 | `net_weight ÷ package_count` |
| 判据 | 与合同/装箱单声明"每袋净重"比对；差异 >0.5% → S2 |
| 价值 | 能同时校验"件数"和"净重"两个数字是否自洽——若两者都抄错但比例不变，C2 通过而 C4 会暴露 |

## C5 体积 ≤ 柜型容量

| 项目 | 内容 |
| --- | --- |
| 公式 | `volume ≤ container_count × 柜型容量` |
| 容量基准 | 40'HQ ≈ 76 CBM（名义），实装约 67–68 CBM（重货再打折） |
| 柜数来源 | 从单证任意位置解析 `43×40'HQ` / `43 CTNR` / `共 43 个 40'HQ 柜`，取最大合理解 |
| 判据 | 超出容量 → **S1 计算不符**（装不下，属订舱/装箱错误） |
| 注意 | 体积明显偏小不一定错（重货按重量而非体积装柜），故**只做上限检查**，不设下限 |

## C6 单据编号自洽

| 项目 | 内容 |
| --- | --- |
| 检查项 | ① PI 号是否符合"字母-字母-年份-流水号"形态；② 编号末尾是否有多余字母后缀；③ 其它单证引用的编号是否与本体一致 |
| 例 | `HYE-PI-2026-0817A` 多了 `A` → 其它单证引用 `HYE-PI-2026-0817` 时对不上 |
| 判据 | **S1**（单证不符点） |
| 为什么单证内也要查 | 有些编号只在一种单证上出现（如 PI 号），跨文件比对无法发现，只能靠格式自洽检查 |

## 容差设置的依据

| 字段 | 容差 | 依据 |
| --- | --- | --- |
| 金额 | 0.01 或 0.5% | 发票金额到分位；大额合同允许四舍五入尾差 |
| 重量/数量 | 0.5% | 地磅/水尺计量误差 + 单位换算舍入 |
| 体积 | 只做上限 | 体积测量误差大，且重货远低于柜容量属正常 |
| 单价 | 0.1% | 单价通常精确到分，小数点错位必须暴露 |

> 容差写在 `scripts/compare.py` 的 `compute_checks` 里，可按行业习惯调整。
> **调宽容差前请想清楚**：容差越宽，真错误越容易漏过去。

## 计算核验与跨文件比对的关系

| 场景 | 跨文件比对 | 计算核验 | 结论 |
| --- | --- | --- | --- |
| CI 金额抄错，但 CI 内部单价×数量是对的 | 发现（与合同不符） | 该单证内通过 | 两处结合可定位"错在 CI 金额" |
| CI 单价、数量都对，金额算错 | 可能发现（与合同不符） | 发现 | C1 明确指出"应为 520,000" |
| 所有单证都用了同一个错金额 | **发现不了** | 发现 | C1/C3 能抓住这类"系统性错误" |
| 净重、毛重、件数三者比例失调 | 可能发现不了 | C3/C4 发现 | 计算核验的价值所在 |

**这张表说明了为什么两个都要做**：跨文件比对抓"抄错"，计算核验抓"算错"，单一手段都不够。
