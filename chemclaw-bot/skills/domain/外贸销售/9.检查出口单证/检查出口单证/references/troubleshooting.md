# 疑难处理：抽不到值、误报、扫描件

---

## 一、某字段显示「缺失」

先判断是哪一类：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 该单证本就不要求此字段 | 判据表不含它 | 应为「不适用」；若显示「缺失」说明词表需补，见下文 |
| 原件确实没写 | 漏填 | 让业务补录 |
| 原件有，但版式特殊 | 抽取器按版面位置匹配，露出的标签/位置不在预期范围 | 人工补录；把该单证的版式反馈进 `extract.py` 的标签别名 |
| PDF 是扫描件/图片 | 无文本层 | 先 OCR，或人工补录（见第三节） |

**排查命令**：把该页的文本行和坐标打出来，看标签和值是否在同一基线、是否被识别成"标签"：

```python
import sys; sys.path.insert(0, "scripts")
import extract as E
d = E.Document("某单证.pdf")
for pg in d.pages:
    for ln in pg.lines:
        print(pg.page_no, round(ln["bbox"][0],1), round(ln["bbox"][1],1), ln["text"][:60])
```

看值那一行与标签那一行的 `y` 差是否 < 3.5（同基线），或 0 < 间距 < 30（下一行/下一块）。

## 二、出现误报（明明一致却报「不一致」）

按这个顺序查：

1. **单位是否已归一**：`1,000 MT` vs `1,000,000 KG` 应判一致。若报不一致，检查 `values_match` 的 `parse_qty`。
2. **是否踩到"合理差异"**：对照 `field_checks.md` 的白名单。若属白名单但没被放过，
   在 `compare.py` 的 `values_match` 里加对应归一分支。
3. **是否把标签/占位符当成了值**：`TO BE ADVISED`、`-`、`AS PER B/L` 不应参与比对。
4. **是否同一个值被抓成两种形态**：如一边 `QINGDAO, CHINA(中国青岛)`、一边 `QINGDAO, CHINA`，
   检查 `norm_port` 是否去掉了中文括注。
5. **是不是"多数派"选错了基准**：若 2 份单证同为 A、1 份为 B，基准应是 A。
   逐格看 `note` 字段能确认系统认的基准是谁。

> 原则：**宁可放过，不可误杀**。若某条误报无法彻底消除，把它降级为「无法判断」而不是硬判「不一致」。

## 三、扫描件 / 图片型 PDF

本 skill 依赖 PDF **文本层**（`page.get_text("words")` 的坐标）。扫描件没有文本层，结果是：

- 页面文本为空 → 所有字段「缺失」；
- 不会产生**错误的**值（这是安全失败），但也不会有任何比对结果。

处理办法（按推荐度）：

1. **让业务提供原生 PDF**（ERP/Word 导出），这是根本解法；
2. 用 OCR 先做一层（如 PaddleOCR / Tesseract），把识别文本写回 PDF 文本层，再跑本 skill；
3. 人工把关键字段填进检查页的"修正为"输入框，点"保存修正并重新核对"——矩阵会按修正值重算。

**注意**：直接把 OCR 结果当"准确值"是有风险的（数字 8/3、1/7 易混）。
OCR 后的值应让**人过一遍**再进入比对，否则等于把一个新的误差源接进了流程。

## 四、单证类型识别错了

表现：某份文件被识别成错误的类型（如内部标准被识别成合同），导致字段抽取与比对全乱。

排查：

```python
import sys; sys.path.insert(0, "scripts")
import extract as E
d = E.Document("问题文件.pdf")
print(d.cls)      # 看 doc_type 与 evidence（命中依据）
```

若 `evidence` 显示命中来自"正文弱匹配"，说明标题区没提供有效信号。
可以在 `taxonomy.py` 的对应单证 `aliases` 里补该文件标题的真实写法。

**额外信号**：标题区含「模板 / 填制要求 / 范本 / 文件标准 / EXPORT DOC STANDARD」且不含本票实号码时，
会被判为参考文件并从比对中排除。若它本该参与比对，检查是否**误含**这些词。

## 五、参考文件没被排除

表现：模板/公司标准里的示例值（如 `quantity = 100`）出现在矩阵里。

检查 `run_check._is_reference_doc`：它只看**前 200 字**（标题区）。
若该文件的标题在第 200 字之后，或标题用了别的新说法（如"作业规范""业务手册"），
需要补进那个正则。

> 为什么只前 200 字：正文里出现"执行标准 STANDARD"（COA 常见）或"标准条款"（合同常见）会导致误排除。
> 曾因把判定范围放到前 900 字，导致 COA 被误判为参考文件、全部字段消失。

## 六、一票业务里混进了别票的单证

表现：某单证的大部分字段都与其它单证冲突，但看起来"自成一套"。

系统会做**锚点聚类**（`extract.find_anchor`）：按合同号/发票号把单证分组，
主导组之外的会列在 `anchor.variants` 里。看到 `variants` 非空时要问：

- 是**另一票业务混进来了**（应剔除后再跑）；
- 还是**这批单证里有一个编号抄错**（属于要找的错误）。

区分方法：看该单证的其他字段（品名、客户、港口）是否与主导组一致。
只有编号不同、其余都对 → 抄错，是错误；其余也都不一样 → 混票，剔除重跑。

## 七、性能

- 单份 3–10 页 PDF 秒级；一票 10–12 份通常 10 秒内；
- 若单证数量很大（如按年度对账），建议按票（一个目录一票）分开跑，输出的 JSON 再汇总。
