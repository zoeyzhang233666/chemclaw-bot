# 字段核对规则：同义归一、比对口径与「合理差异」白名单

> 这一页决定**报不报警**。误报比漏报更能摧毁信任，所以每条规则都写清了"为什么"。

---

## 一、比对的三个前置步骤

```
抽取值 → ① 格式校验（该字段能不能是这个形态）→ ② 同义归一 → ③ 语义比对
```

### ① 格式校验（`_value_fits`）

防止"值错位"：把紧邻单元格的内容当成了本字段的值。典型拦截：

| 字段格式 | 拒绝的形态 | 例子 |
| --- | --- | --- |
| `money` | 1–2 位纯整数、带 CTNR/CBM/KG 单位 | `43`（柜数）、`1,050 CBM` |
| `num` | 带 CTNR/BAGS 单位 | `1,010 BAGS` |
| `int` | 非纯数字 | `1,000 袋` |
| `cas` | 不符合 CAS 校验位规则 | `497-19-2`（校验位错，但仍会被抽出供人判断） |
| `hs` | 不是 6 位以上点分数字 | `2836` |
| `date` | 不含 `YYYY-MM-DD` / `YYYY/MM/DD` / `YYYY年MM月DD日` | `第 1 页` |
| `incoterm` | 不以 11 种贸易术语开头 | `FREIGHT & INSURANCE TO BE COVERED` |
| `package_type` | 是单据编号、是重量描述 | `No.: HYE-…`、`净重 1,000 KG` |

同时拒绝**占位符**：`-`、`—`、`/`、`N/A`、`TBA` 不当作有效值。

### ② 同义归一（`values_match`）

| 字段族 | 归一规则 |
| --- | --- |
| 公司名 | 去大小写/标点/`CO.` `LTD` `INC` `PT` 等法律后缀；**保留** `- GUDANG xxx` `- FACTORY xxx` 等地址段 |
| 编号（合同号/PI 号/CI 号/提单号/CO 号） | 去空格、大小写、连字符、标点后全等比较（`HYE-SC-2026-0817` = `HYESC20260817`） |
| 港口 | 去中英文括注、去国名、去 `PORT OF`、比城市名（`TANJUNG PRIOK, JAKARTA, INDONESIA` = `TANJUNG PRIOK`） |
| 贸易术语 | 取前三个字母（`CFR TANJUNG PRIOK (INCOTERMS 2020)` → `CFR`） |
| 数量 | 单位换算为 KG/MT/CBM 基准后比数值（`1,000.000 MT` = `1,000,000 KG`） |
| 重量 | 换算为 KG 后比数值，容差 0.5% |
| 金额 | 比数值，容差 0.01（分位） |
| 品名 | 去掉 `DISODIUM CARBONATE`/`SODA ASH`/`重质纯碱` 等中英同义段与括注后比核心词 |
| 日期 | 统一为 `YYYY-MM-DD` |

### ③ 语义比对

归一后仍不同 → **不一致**；归一过程本身不成立（如一边是指令性文本）→ **无法判断**，不给结论。

## 二、「合理差异」白名单（必须不报警）

| # | 现象 | 为什么不报警 |
| --- | --- | --- |
| 1 | 提单没有单价/金额 | B/L 是物权凭证与运输合同，本就不载明价格 |
| 2 | 提单没有贸易术语 | 运费是否预付体现在 `Freight Prepaid/Collect`，不写 CFR/CIF |
| 3 | PI 号 ≠ CI 号 | 两个不同阶段的两份文件，编号体系不同 |
| 4 | 合同没有通知方 | Notify Party 是运输环节概念，合同不涉及 |
| 5 | 装箱单没有单价/金额 | 装箱单只管件数、重量、体积 |
| 6 | 各单证**签发日期**不同 | 合同早于发票早于提单早于 CO，本就不同 → 只做单证内合理性检查，不跨单证比 |
| 7 | 提单品名比发票短 | 提单用"最简品名"，只要核心品名一致即可 |
| 8 | `SODA ASH DENSE` / `DISODIUM CARBONATE (SODA ASH DENSE)` / 重质纯碱 | 同一产品的不同法定/俗称写法 |
| 9 | `CFR` / `CFR TANJUNG PRIOK` / `CFR TANJUNG PRIOK (INCOTERMS 2020)` | 详略不同，术语本身一致 |
| 10 | `1,000.000 MT` / `1,000,000 KG` | 单位换算后相等 |
| 11 | 装箱单 `B/L No.: TO BE ADVISED` | 装箱单常在开船前出具，提单号后补；属正常占位 |
| 12 | 唛头在装箱单是多行文本、在提单是一行 | 只是排版不同，内容相同 |
| 13 | 港口带国名/中文括注差异 | `QINGDAO, CHINA(中国青岛)` = `QINGDAO, CHINA` |
| 14 | 参考文件（模板/公司标准）与业务单证"不一致" | 它们不是本票单证，已排除在比对之外 |

> 规则 5、6、7、11 在代码里分别通过「不上该单证的字段 → NA」「date 字段跳过跨单证比对」
> 「品名按核心词归一」「`TO BE ADVISED` 视为占位」实现。

## 三、必须报警的情形

| 现象 | 级别 | 为什么严重 |
| --- | --- | --- |
| 目的港/起运港不同 | **S1** | 提单与舱单不符，货物可能被卸错港 |
| 发货人/收货人不同 | **S1** | 物权与提货资格问题 |
| 收货人多了仓库后缀（`PT X` vs `PT X - GUDANG …`） | **S1** | 交货地址不同，需确认是分批提货还是笔误 |
| CAS 号不同 | **S1** | 化学品身份错，涉及归类、危规、目的国准入 |
| HS 编码前六位不同 | **S1** | 归类不同 → 关税与监管条件不同 |
| 数量/净重/毛重/件数不同 | **S1** | 海关与船公司视为申报不实 |
| 金额 ≠ 单价×数量 | **S1** | 结汇金额与合同不符，LC 项下必然拒付 |
| 合同号/发票号引用不一致 | **S1** | 单证不符点，银行可拒付 |
| 贸易术语与报关单「成交方式」不对应 | **S1** | 影响退税与运费核算 |
| 品名规格不同（重质 vs 轻质） | **S1** | 物性不同，属发错货风险 |
| 包装方式表述不同 | S2 | 一般可接受，但需确认单件重量与运输要求 |
| 某单证未载明应有字段 | S3 | 建议补录或人工确认 |

## 四、字段性质（kind）的含义

| kind | 含义 | 处理 |
| --- | --- | --- |
| `fact` | 事实字段，应当各单证一致 | 必须比对 |
| `role` | 角色字段（如通知方、最终目的地），只在特定单证出现 | 出现才比，不出现不算缺失 |
| `calc` | 派生值，由其它字段算出 | 交给计算核验，不做跨文件比对 |

## 五、无法判断（UNK）的典型场景

- 一边是具体值、一边是指令性文本：`For Buyer's Confirmation`、`TO ORDER OF SHIPPER`、`AS PER B/L`；
- 一边是范围、一边是点值：`0.95–1.10 g/mL` vs `1.02`；
- 单位体系不同且无法换算：`43 个 40'HQ 柜` vs `43×40'HQ`（后者是柜型描述，非件数）。

这些情况统一标「无法判断」并提示人工核对，**不自动下"不一致"结论**。
