# 检查出口单证

## 这个 skill 解决什么问题

一票化工品海运出口，单证由不同人、不同时间、不同系统出（销售出合同、船务出提单、质检出 COA、报关行进报关单），
字段名各不相同（`Port of Loading` / `装运港` / `起运港`；`Gross Weight` / `毛重` / `G.W.`），
一旦有一处对不上，轻则改单，重则卡在目的港清关或结汇被拒。

本 skill 把「靠人眼逐份对」变成「机器先对一遍，人只看有问题的格子」：

1. 自动识别每份 PDF 是什么单证、属于哪一票业务；
2. 抽出可比对的字段，同一字段跨单证排成矩阵；
3. 每题一格给结论：**一致 / 不一致 / 缺失 / 不适用 / 无法判断 / 计算不符**；
4. 核验数量×单价=金额、净重↔数量、毛重−净重=皮重、单件净重、体积≤柜容量等关系；
5. 每处差异定位到**原文件第几页、哪个字段**，并给出修改建议；
6. 产出交互式检查页与 Excel 工作簿，支持人工修正后重算、导出问题清单与修正记录。

## 三条铁律

| 铁律 | 含义 | 为什么 |
| --- | --- | --- |
| **不猜** | 看不清的数值、单位、公司名，一律标「需人工确认」，绝不填写推测值 | 猜错的重量/金额会直接变成申报不实 |
| **字段名不同 ≠ 内容冲突** | 先做同义归一（`Port of Discharge`=`卸货港`=`POD`；`1,000 MT`=`1,000,000 KG`）再比对 | 误报会把真问题淹掉，也会让人不敢信工具 |
| **合理差异不报警** | 提单不需要价格、PI 与 CI 编号本就不同、各单证签发日期本就不同 | 这些不是错误，标出来只是噪声 |

## 什么时候用

**适用**：化工/大宗品海运出口的单证自查；信用证交单前预审；报关前自查；客户投诉"单证不符"后定位原因。

**不适用**：单一文件的信息提取（直接读 PDF 即可）；信用证条款的合规性法律意见；非 PDF 扫描件（无文本层的图片需先 OCR）。

## 输入

- 同一票业务的 **PDF 单证**，放一个目录，或直接给多个路径；
- 支持类型：销售合同 SC、形式发票 PI、商业发票 CI、装箱单 PL、提单 BL、COA、SDS、
  原产地证 CO、报关单 CUSTOMS、信用证 LC、危包证 DGD、检验证书 INSP；
- 混入的**模板/公司标准/作业指引**会被自动识别并排除（标注为"参考文件，不参与核对"），不会污染比对结果。

## 输出

| 文件 | 用途 |
| --- | --- |
| `check_page.html` | **交互式检查页**（单文件，双击打开）：单证清单、跨文件矩阵、点格子看原文、修正后重算、导出问题清单与修正记录 |
| `出口单证检查结果.xlsx` | 6 页工作簿：`单证索引` `跨文件字段矩阵` `计算核验` `差异定位` `问题清单` `修正记录` |
| `issue_list.md` | 问题清单（Markdown）：可直接贴进邮件或工作群，按 S1/S2/S3 分级 |
| `check_result.json` | 结构化结果，便于下游系统对接或二次加工 |

## 怎么跑

```bash
# 1) 先自检环境（只需一次）
python scripts/verify.py

# 2) 检查一票单证
python scripts/check_docs.py ./单证目录 --out ./检查结果

# 3) 用示例票试跑（内含 14 处典型错误，可用于验收）
python scripts/verify.py --full
```

退出码：`0` 无阻断问题；`1` 存在 S1（必须改完才能交单）；`2` 运行错误。

## 判定口径

### 状态语义

| 状态 | 含义 | 处理方式 |
| --- | --- | --- |
| 一致 | 归一化后取值相同 | 无需处理 |
| **不一致** | 归一化后仍不同 | 必须核实，改正或说明原因 |
| 计算不符 | 重量/数量/件数/金额关系不自洽 | 必须复核，通常是某一处数字抄错 |
| 缺失 | 该单证按惯例应载明此字段，但未识别到 | 确认是否漏填；若原件是图片，人工补录 |
| 不适用 | 该单证本就不要求此字段 | 无需处理 |
| 无法判断 | 表述不可比（如 `For Buyer's Confirmation`） | 人工确认 |

### 严重度

| 级别 | 判据 | 典型例子 |
| --- | --- | --- |
| **S1 阻断交单** | 关键事实字段冲突，或计算关系不成立 | 提单目的港错、CAS 号错、金额与单价×数量不符 |
| **S2 需修正** | 影响结汇/通关但不至于拒载 | 包装方式表述与合同不一致 |
| **S3 建议核对** | 非关键字段、或需补录 | 某单证未载明通知方 |

### 视为「合理差异」、必须不报警的清单

详见 `references/field_checks.md`。要点：

- B/L 不需要载明单价、总金额、贸易术语明细；
- PI 号与 CI 号不同属正常（PI 是报价阶段、CI 是发货阶段）；
- 合同不载明通知方（Notify Party 是运输环节概念）；
- `SODA ASH DENSE` / `DISODIUM CARBONATE (SODA ASH DENSE)` / 重质纯碱 是同一产品的不同写法；
- `CFR` / `CFR TANJUNG PRIOK` / `CFR TANJUNG PRIOK (INCOTERMS 2020)` 视为一致；
- `1,000.000 MT` 与 `1,000,000 KG` 单位归一后一致；
- 各单证**签发日期本就不同**，不做跨单证比对（只做单证内合理性检查）。

## 工作流程

1. **收集单证** → 确认都在同一票业务下（用合同号/发票号锚定）。
2. **跑检查** → 看检查页顶部结论与 KPI。
3. **先处理 S1** → 按问题清单逐条核对原件，改单或确认。
4. **再处理 S2/S3** → 确认是否需要补录或说明。
5. **在检查页上修正** → 对已在原件改正的项写入新值，或标记"已人工确认"，矩阵状态实时重算。
6. **导出** → 问题清单 CSV 发给相关同事；修正记录作为本次核对留痕。

## 已知边界

- **依赖 PDF 文本层**。扫描件/图片型 PDF 抽不到值，会显示「缺失」——此时应人工补录或先 OCR。
- **字段抽取按版面位置**，对版式极为特殊的单证可能漏抽；漏抽表现为「缺失」而不是「错误值」，属于安全失败。
- 本 skill 只做**一致性核对**，不作合规性法律判断（如 HS 归类的正确性、印尼进口许可要求）。这类问题会标注「需人工确认」，不给出结论。
- 演示票中的企业、编号、航次均**为虚构**，仅用于说明检查流程，不代表任何真实业务或真实监管要求。
