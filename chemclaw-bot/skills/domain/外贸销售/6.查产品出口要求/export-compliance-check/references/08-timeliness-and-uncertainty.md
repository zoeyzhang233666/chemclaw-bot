# 08 · 法规时效性与不确定性处理规则（必读）

> 这两条是"查出口要求"最容易出错、也最容易糊弄过去的地方。
> 本技能的立场：**宁可标"待确认"，也不给一个看起来很专业的错误结论。**

---

## 一、法规时效性规则

### 规则 1 · 每条法规必须四要素齐全

```
法规名称 + 文号/版本 + 生效日期 + 现行状态
```
缺一项，该条结论降级为"参考信息"。

### 规则 2 · 必须标注"被替代"关系

例：
- Nghị định 26/2026/NĐ-CP 替代 Decree 113/2017/NĐ-CP
- Thông tư 01/2026/TT-BCT 替代 Circular 32/2017/TT-BCT
- 海关总署 2020 年第 129 号 废止 原质检总局 2012 年第 30 号

**看到旧法规的结论要显式标注"已失效（原生效期 起）"**，不能默默沿用。

### 规则 3 · 换版检查先行

对目的国法规，第一步永远是"是否刚换版"。典型信号：
- 新法律年度编号（如 69/2025/QH15）
- 配套决议/通告在几个月内集中发布
- 旧文件出现"hết hiệu lực"（失效）标注

### 规则 4 · 规则版本必须写明

| 领域 | 要写清 |
|---|---|
| 海运 | IMDG 42-24（2026-01-01 强制） |
| 空运 | IATA DGR 67th（2026） |
| 陆运 | ADR 2025 / JT/T 617 |
| GHS 分类 | GB 30000.14-2013（GHS 第 4 修订版） |
| 税则 | 2026 年税则 |

### 规则 5 · 核验日期与过期提醒

- 每条法规记录 `verified_on`（本条结论所依据的官方原文最后确认时间）
- 与本技能基准日相差 **> 180 天** → 自动标"需复核"
- 距基准日 **> 90 天**的交付物，对外使用前须重核

### 规则 6 · 过渡期

若某法规生效日晚于本报告基准日，必须写"过渡安排"，不能当作已生效。

## 二、不确定性处理规则

### 五级核验状态

| 状态 | 定义 | 能否对客户表述 |
|---|---|---|
| **已核实** | 已打开官方原文/一手来源，确认现行版本与适用条件 | 可以，须说明依据 |
| **参考信息** | 二手或商业数据库，用于定位，未取官方原文 | 只能说"据…资料"，不能说"确定" |
| **待确认** | 缺官方原文，或需专业判断（如扫描件、需专家意见） | **不能作为承诺**，列入待确认清单 |
| **不适用** | 有明确理由排除（必须写理由） | 可以，须给理由 |
| **不触发** | 条件明确不满足（如定向许可证 + 目的地不在清单） | 可以，但须保留依据备查 |

### 规则 A · 四类东西永远不给"确定结论"

1. **HS 编码** —— 只给候选
2. **UN 号 / 类别 / 包装类别** —— 只引危险货物一览表，拿不到就待确认
3. **许可结论**（要不要办证）—— 必须落到"列名 + 目的地 + 用途"三要素
4. **目的国名录归属**（如某物质属哪一类受管化学品）—— 名录不可解析就待确认

### 规则 B · "没搜到"≠"没有"

公开检索未发现列名，只能写：
> 未检索到列名证据，须由合规人员对现行清单原文逐条复核。

不能写"不受管制"。

### 规则 C · 扫描件 / 不可解析资料

- 无文字层、无 OCR 能力时：**不得推定内容**
- 处理：标"待确认"，写明"官方 PDF 为扫描件，无法解析"，指定责任方去核

### 规则 D · "待确认"必须闭环

每一个"待确认"条目都要在 `open_questions` 中登记：
```
问题 / 为什么不能确定 / 责任方 / 解除后影响哪些条目 / 闭环条件
```
正文里出现"待确认"但清单里没有 → 视为不合格（脚本会报错）。

### 规则 E · 确定性措辞白名单

标"待确认"的条目里，**禁止**出现："必然适用""确定需要""一定需要""肯定是"。
脚本会自动扫描并报错。

### 规则 F · 假设要显式声明

用户没给全的信息（如浓度、包装、用途）按常见情形假设时：
- 写在 `meta.assumption_notice`
- HTML 顶部可见
- Excel 封面第 3 行（黄色提示条）

## 三、脚本如何强制执行

`scripts/validators.py` 会检查：

| 检查 | 触发后果 |
|---|---|
| 条目无 `reg` / `effective` / `action` | ERROR（阻断） |
| "已核实"但无 `evidence` 链接 | ERROR |
| "待确认/需确认/参考信息"但不在 `open_questions.blocks` | ERROR |
| "待确认"里出现确定性措辞 | ERROR |
| 法规 URL 格式非法 | ERROR |
| 条目无 `reg_ids` 也无 `evidence` | ERROR |
| 法规核验日 > 180 天 | WARN |
| 法规 `relevance` 声明覆盖但条目未挂接 | WARN |
| 危化品目录被当作危险货物分类依据 | ERROR（混同检测） |

**交付前必须 `validators.py` 全绿（ok=true）。**

## 四、自我提问清单

在写下任何一个结论前，问自己：

1. 我这个结论的**依据**是什么？能不能给出 URL？
2. 这是**哪一版**？有没有被替代？
3. 适用**条件**是什么？浓度/用途/包装/目的地变了还成立吗？
4. 我是不是把**危险化学品**和**危险货物**混在一起了？
5. 我是不是在**猜** HS / UN / PG？
6. 如果这个结论错了，客户会损失什么？（退运？罚款？无法清关？）
7. 谁有资格确认这条？我有没有把它写进"待确认"？
