# 10 · 交付前质检清单

> 交付物在发给用户之前，逐项勾选。任何一项不通过，不得交付。

---

## A. 数据完整性（脚本自动）

- [ ] `validators.py` 返回 `ok: true`，无 ERROR
- [ ] 四个主题齐全：中国出口 / 目的国进口 / 运输 / 标签与包装
- [ ] 每条记录有：`id`、`item`、`finding`、`condition`、`reg`、`effective`、`status`、`action`
- [ ] 每条记录挂了 `reg_ids` 或 `evidence`
- [ ] 所有 `reg_ids` 在 `regs` 表中存在
- [ ] 法规表每条有：法域、名称、文号、生效日、状态、URL、核验日期
- [ ] 所有"待确认/需确认/参考信息"条目都出现在 `open_questions.blocks`
- [ ] 单证清单覆盖：合同、发票、装箱单、DGS/DGD、包装性能与使用鉴定、SDS、标签、产地证、目的国申报
- [ ] 角色覆盖：出口方、进口方、承运方

## B. 时效性（人工确认）

- [ ] 目的国法规做过"换版检查"
- [ ] 旧法规被替代的关系已写明
- [ ] 运输规则版本已写明（IMDG 42-24 / IATA 67 / ADR 2025）
- [ ] GHS 标准版本已写明
- [ ] 税则年度已写明
- [ ] `timeliness` 表每条都勾选"已核实"

## C. 不确定性（人工确认）

- [ ] HS 全部标"候选"，没有一条写成"确定"
- [ ] UN 号 / PG 均来自一览表；无来源的一律"待确认"
- [ ] 没有出现"必然适用/确定需要"等确定性措辞
- [ ] "没搜到列名"的表述是"未检索到证据，须复核"，不是"不受管制"
- [ ] 扫描件类资料都标了"无法解析，待确认"
- [ ] 每个"待确认"都有责任方

## D. 体系分离（人工确认）

- [ ] 危险化学品结论与危险货物结论分表
- [ ] 页面有"两者不得互推"的显式声明
- [ ] 没有用危化品目录推导 UN 号 / PG

## E. 适用条件（人工确认）

- [ ] 浓度口径写明 w/w 或 w/v
- [ ] 危化品门槛（如含量>8%）已写明
- [ ] 运输分档（8% / 20% / 60%）已写明
- [ ] 定向许可证的"目的地条件"已写明
- [ ] 用途（工业/食品）对结论的影响已写明

## F. 交付物质量

### HTML
- [ ] 单文件、无外部依赖（无 CDN、无外部字体/脚本/图片）
- [ ] 首屏可见：产品、目的国、CAS、HS 候选、UN 号、统计数字
- [ ] 主题筛选可用（4 个主题 + 仅看待确认）
- [ ] 搜索可用
- [ ] 条目可展开/收起，键盘 Enter 可操作
- [ ] 无横向溢出（桌面 1440 与移动 420 都检查）
- [ ] 法规链接可点击，指向真实来源
- [ ] 打印时条目自动展开
- [ ] 底部有"不构成法律意见"声明

### Excel
- [ ] 表数量 ≥ 14（封面/身份/HS/中国/目的国/运输/标签/单证/角色/法规/时效/汇总/风险/待确认/核对清单/样例）
- [ ] 封面有假设声明与使用边界
- [ ] 每表有标题带、表头冻结、自动筛选
- [ ] 状态列有颜色区分
- [ ] 法规 URL 可点击
- [ ] `check_office.py` 返回 pass

## G. 交互与服务验证

- [ ] `verify_page.cjs` 全部通过（DOM 结构、脚本注入、链接合法）
- [ ] `verify_interaction.cjs` 全部通过（展开/收起/筛选/搜索/键盘/布局）
- [ ] 三张截图（桌面首屏、全页、移动端）已生成

## H. 文风与可读性

- [ ] 结论先行，不写大段铺垫
- [ ] 每条结论都能一眼看到"依据 + 条件 + 状态"
- [ ] 待确认项措辞不吓人但明确（"需由 XX 确认"，不是"可能存在风险"）
- [ ] 不出现"大概""可能""据说""应该可以"这类模糊承诺
