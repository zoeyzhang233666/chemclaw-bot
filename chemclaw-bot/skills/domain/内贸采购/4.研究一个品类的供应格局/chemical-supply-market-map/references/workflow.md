# 十步工作流（详解）

主 agent 负责**编排、定口径、判断与交付**；产能/项目/画像的大批量采集可拆成 lane 交给子代理。
每步都给了「完成判据」——不满足就不要进入下一步。

---

## 步骤 0：建档

```bash
python scripts/new_project.py --dir work/<产品>-<地域>-<年> \
    --product "纯碱（碳酸钠，Na₂CO₃）" --short 纯碱 --cas 497-19-8 \
    --grades "重质/轻质" --region "中国大陆" --year 2025 --forward 2026,2028
```

产出 `project.json`（含 TODO 标记）、`plants.json`/`companies.json`/`projects.json`（各 1 行示例）、
`采集说明.md`（lane 分工与写入约定）。

- 完成判据：四个 JSON 文件都存在，`project.json.product.name` 已填。

---

## 步骤 1：定契约

用一次 `ask_user_question` 问全四件事（带推荐项）：

1. **产品与规格**：全名 + 主要等级（等级不同，产能与价格都不可混算）
2. **地域**：具体到国家/区域/省份，不接受「全球」
3. **基准年与前瞻年**：通常是「上一个完整年度 + 未来 1–2 年」
4. **采购方参数**（可选）：年用量、到厂价、运费、库存天数

- 完成判据：`product` / `scope` 全部非空；`basis_notes` 至少 1 条。

---

## 步骤 2：探通道

写下「本次可用的证据通道」，每级实测一次，记进 `采集说明.md`：

| 级别 | 通道 | 强度 | 典型用途 |
|---|---|---|---|
| A | 上市公司年报/公告/招股书（巨潮、交易所） | 最强 | 集团产能、产量、单吨成本、在建项目 |
| A | 产能置换公告、环评公示、能耗核查 | 强 | 净新增、淘汰、工艺与原料 |
| B | 协会年度报告、行业年度盘点 | 强 | 全国产能/产量口径、工艺结构 |
| B | 价格机构（生意社/卓创/隆众/百川） | 强 | 历史价格、区域价差、库存 |
| C | 期货公司研报、券商深度 | 中 | 供需平衡、成本曲线、项目进度 |
| C | 海关总署 / UN Comtrade | 中 | 进出口量价 |
| D | 行业媒体、企业官网、百科 | 弱 | 只作线索，不作唯一依据 |

- 完成判据：A 与 B 各实测成功一次（或写明为何不可用），并记下本次可用的检索式。

---

## 步骤 3：定口径（最容易翻车的一步）

先回答三个问题，答案写进 `metrics` 与 `scope.basis_notes`：

1. **全国产能有几个数字？** 把每个数字的来源、时点、口径都列出来，选一个作正文口径，其余并列展示。
   **不要取平均**——平均值在任何来源里都不存在。
2. **产量与产能对得上吗？** 开工率 = 产量 / 产能（同口径）。若跨口径相除，必须在报告里注明。
3. **样本能做到多少覆盖？** 样本加总 / 全国产能。低于 70% 时必须在报告显著提示集中度可能被低估。

- 完成判据：`metrics.capacity_total` 有值与来源；`basis_notes` 写清所有口径差异。

---

## 步骤 4：铺产能（plants.json）

一条 = **一个基地**（工厂），不是集团。做法：

1. 先列集团（10–30 家），再列每家已知基地。
2. 先做 5 条跑通 `--check`，再批量补。
3. 每条必须带 `source`（S 编号）。

规模建议：主力品种 20–40 条基地、覆盖 ≥70% 全国产能；小众品种 10–15 条即可。

- 完成判据：`--check` 无错误；`plants_without_source = 0` 或已在 gaps 登记。

---

## 步骤 5：补画像（companies.json）

只写**有公开依据**的内容。没有画像的集团可以不写（抽屉会退化显示基地汇总并标「数据缺口」）。
集团 `capacity_base` 不填时自动用 plants 加总，避免手工不一致。

- 完成判据：前 5 大集团都有 `procurement` 判断与至少 2 条 `dd`。

---

## 步骤 6：项目与净增（projects.json）⚠

这是采购规划真正依赖的一张表：

1. 先按年份拉清单：已投产、在建、已核准/拟建、规划。
2. 每个项目判 `type`：新建 / 扩建 / 技改 / 置换 / 搬迁 / 退出。
3. **置换/搬迁/技改必须填 `capacity_retired`**，否则净增会被高估。
4. 净增无法确认 → `net: null`，报告显示「待确认」，不进基准预测。
5. 顺手记录「哪一年没有大项目」——**空窗年往往比项目年更紧张**。

- 完成判据：每个项目有 `date` 与 `type`；置换类都有 `capacity_retired` 或 `net`。

---

## 步骤 7：价格与策略

- `prices.annual`：至少 4 年（含一个高点、一个低点）。峰值与均价分开写，不要用峰值冒充年均。
- `prices.current`：每个报价带日期 + 规格 + 地区。
- `markets`：区域价差，说明为什么该区域贵/便宜。
- `prices.outlook`：基准/上行/下行/采购含义四段。
- `strategies`：4 条左右，每条都要「具体做法 + 关键条款 + 可验收 KPI」。
- `supplier_mix`：建议比例（合计 1）。

- 完成判据：`prices.annual` ≥4 条、`current` ≥2 条、`strategies` ≥3 条。

---

## 步骤 8：体检

```bash
python scripts/build_all.py --dir work/<项目> --check
```

看输出里的 `[错误]` 与 `[警告]`。错误必须修；警告逐条判断是「要修」还是「已登记的缺口」。

- 完成判据：错误 0；每条警告都已处理或在 `gaps` 里有对应条目。

---

## 步骤 9：出表出图

```bash
python scripts/build_all.py --dir work/<项目>              # HTML + Excel
python scripts/build_all.py --dir work/<项目> --html-only  # 没装 openpyxl 时
```

- 完成判据：HTML 与 xlsx 都生成；文件名形如 `<简称>供应格局全景_<基准年>.html`。

---

## 步骤 10：交付前终检

```bash
python scripts/check_project.py --dir work/<项目>
python scripts/ui_check.py --html <报告.html>        # 有 playwright 时
```

再按 `references/delivery-checklist.md` 逐条过，最后口述四块：

1. **数字**：产能/产量/CR5/覆盖率各是多少、什么口径
2. **结构**：区域集中在哪几个省、工艺结构如何、头部是谁
3. **前瞻**：未来两年净增多少、哪年紧张、哪些项目待确认
4. **缺口与建议**：哪些数据没拿到、影响什么、下一步先补哪个

---

## 并行与预算纪律（有子代理时）

| 项 | 建议值 |
|---|---|
| lane 数 | 3–5（产能/画像/项目/价格/政策） |
| 并发 | ≤5 |
| 每条 lane 网络调用 | ≤30 次；每家最多 1–2 页，失败不重试 |
| 落盘 | 每 5 条覆盖写一次，**不要把大 JSON 贴回对话** |
| 主 agent 读入 | 只读脚本输出与统计，不读原始 lane JSON 全文 |

lane 分工与交接格式见 `references/lane-brief.md`（在 `templates/lane_brief.md`）。
