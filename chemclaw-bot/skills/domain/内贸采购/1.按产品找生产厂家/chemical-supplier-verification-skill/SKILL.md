# 化工品生产厂家核验 Skill

## 这个 skill 解决什么

输入一个化工品（最好带规格、数量、收货地），输出一个**生产身份经过核验的候选供应商池**：

- 谁是**生产厂家**，谁是**贸易商/代理**，每家给出判定依据；
- 每家生产基地在哪、产能多少、数据是哪一年、2025 年产量多少；
- 每条产能/产量/规格信息对应哪个公开来源；
- 规格逐项对照：哪些有公开标准/宣称，哪些没有公开数据；
- 按“生产确定性、规格匹配、规模、距离”排序，并解释排序；
- 明确数据缺口，不猜测、不用经营范围推断生产；
- 生成 **Excel + HTML** 两份附件，HTML 可点击、可筛选、可对比。

> 核心不是“搜到公司名”，而是把“生产身份”拆成可验证的证据链。
> 没有证据的产能，不写；没有批次 COA 的规格，不写“符合”。

---

## 什么时候用

触发词包括但不限于：

- “按产品找生产厂家”“找纯碱/烧碱/尿素生产厂”
- “供应商池”“候选供应商”“生产厂家名单”
- “区分生产厂家和贸易商”“排除贸易商”
- “这个产品谁在生产”“产能核验”“生产身份核验”
- “供应商准入初筛”“规格匹配”“能不能供”
- “producer verification”“chemical supplier sourcing”“manufacturer vs trader”

不适用：

- 只找下游客户/买家（用 lead-sourcing 类 skill）；
- 只查近期价格/行情（用 market-brief 类 skill）；
- 只查单个企业工商信息；
- 要求保证“最低价/唯一正确名单”的采购决策。

## 输入

### 必填

| 字段 | 说明 | 示例 |
|---|---|---|
| `product` | 产品名称，尽量带等级/形态 | 重质纯碱（光伏玻璃级） |
| `application` | 下游用途，决定规格重点 | 光伏玻璃 / 浮法玻璃 |
| `destination` | 收货地，至少到城市/园区 | 江苏·苏州工业园区 |
| `quantity` | 月需/年需，决定规模与物流筛选 | 2,000 吨/月 |
| `as_of` | 数据截止日 | 2026-10-19 |

### 选填

- 规格书 / BOM / COA 模板 / 现有合格供应商名单；
- 不能接受的地区、规模下限、工艺路线、认证要求；
- 包装方式（吨袋/散装/槽车/ISO 罐）；
- 账期、税率、到厂/出厂口径；
- 是否允许贸易商/代理商进入比价；
- 是否需要食品级、危化品、REACH、ISO、客户审厂等专项要求。

### 缺输入时

不要停下来空等。用**明确标注的示例 RFQ** 先跑通，并在标题、封面、HTML 顶部都写“示例需求，可替换”。缺什么，就在 `gaps` 里写什么。

## 输出

至少两份附件：

1. **Excel**：封面 + 候选池 + 证据明细 + 规格矩阵 + 工厂/产能 + 评分 + 贸易商排除 + 数据缺口 + 来源库 + RFQ/行动 + 口径冲突。
2. **HTML**：单文件、无外部依赖，含需求卡、筛选/排序、供应商详情抽屉、证据时间线、规格矩阵、准入清单、供应商对比、来源库。

同时保留：

3. `project.json`：结构化数据，可复核、可复现、可二次生成。
4. `README.md`：本次项目的口径、来源、缺口、使用说明。

文件命名建议：

```text
{产品}_生产厂家核验池_{收货地}_{YYYYMM}.xlsx
{产品}_生产厂家核验池_{收货地}_{YYYYMM}.html
project.json
```

## 六条硬规则

1. **生产身份优先于规模**：没有装置/产能/产量/环评/政府项目/官网产品页，不进入厂家池。
2. **经营范围不算生产证据**：营业执照、店铺 SKU、代理宣称、采购记录，最多是 C/D 级线索。
3. **产能≠产量，在建≠在产，集团≠单个基地**：分列、分年、分基地；联产装置不能把“双吨”直接当目标产品单吨。
4. **标准≠批次合格**：公开标准/宣称只能写“可对标/部分公开”，没有批次 COA 不能写“符合”。
5. **每条数字有来源**：产能、产量、员工、成立年份、地址、规格，都要有 `source_id`；没有就写“未披露/待核”。
6. **缺口要变成动作**：每个未披露项，落到 RFQ 追问、样品检测、现场审核或物流比价，不只写“缺失”。

## 工作流

### Step 0：锁定口径

先写一张 `meta` 表：

- 产品、CAS、HS、等级/形态、执行标准；
- 下游用途、关键规格、数量、收货地、包装；
- 数据截止日、样本范围、产能单位；
- 是否含贸易商、是否含在建产能、是否含集团合并口径。

把“本次不做什么”也写清楚，例如：不含报价、不含账期、不含运费、不覆盖全国全部企业。

### Step 1：建立企业全集

目标不是“搜几家”，而是先建立一个**可解释的样本框**。常用来源：

- 上市公司年报/半年报/招股书/债券募集说明书；
- 政府项目公告、环评/环评验收、排污许可、安全生产许可、能评、产能置换；
- 行业协会、园区管委会、招商项目清单；
- 期货交割厂库/交割品牌、海关进出口数据；
- 行业媒体、券商研报、专业咨询报告；
- 企业官网/IR/招聘/产品手册。

建议目标：15–30 家生产厂家；如果样本太小，在 `meta.sample_note` 写清楚“样本不是全市场”。

### Step 2：拆实体

把“集团—上市公司—生产基地—销售主体”拆开：

- 集团产能可能包含多个基地，不能重复加总；
- 上市公司可能只是集团的一个平台；
- 销售公司/贸易公司可能不是生产主体；
- 同一地址多个公司名，先查股权/历史沿革，再决定合并或分列。

输出字段至少包含：`group`、`legal_entity`、`plant`、`sales_entity`、`identity`。

### Step 3：验证生产身份

按证据强度分级，至少一条直接证据 + 一条交叉来源：

- **直接-A**：定期报告、政府公告、环评/验收、排污许可、安全生产许可、产能置换公告、项目备案；
- **直接-B**：官网产品页、IR 问答、招聘主页、企业手册中明确写“产能/装置/基地”；
- **间接-C**：新闻、行业统计、原料采购、招聘、物流招标；
- **仅工商-D**：营业执照经营范围、店铺 SKU、代理宣称。

判定为“生产厂家”的最低要求：

- 有明确的生产基地地址；
- 有装置/产能/产量/环评/政府项目之一；
- 有至少一个 A 或 B 级证据；
- 不是仅“经营范围含该产品”。

### Step 4：抽取产能/产量

每个基地记录：

```text
capacity, capacity_year, capacity_definition（设计/在产/在建/搬迁）
output, output_year, utilization
captive_use, external_sales, long_term_contract_share
```

不能用集团产能代替基地产能；不能用在建产能代替在产；不能把“纯碱+氯化铵”联产双吨直接当纯碱单吨。

### Step 5：规格匹配

把采购规格拆成 6–12 项可检测指标。每项记录：

```text
label, requirement, unit, method, criticality
status: 部分公开 / 未公开 / 待验证
public_info, gap, next_action
```

结论只允许三种：

- “有公开标准/宣称，可对标”；
- “部分公开，需批次 COA”；
- “未公开，需索取/检测”。

禁止在没有 COA 的情况下写“符合”“满足”。

### Step 6：评分与排序

默认权重：

```text
综合 = 生产确定性 35% + 规格匹配 30% + 规模 20% + 距离 15%
```

不同产品可换预设（见 `references/04-scoring.md`）：

- 大宗固体/普通液体：35/30/20/15；
- 危化品/液体散装：30/25/20/25，合规准入作为 gate；
- 精细化学品/电子级：25/40/15/20；
- 出口导向：30/30/20/20，另加 REACH/客户认证 gate。

距离用直线距离做初筛，**不替代运费**；外销可得性单独列，不进入分数但影响主供/备供判断。

### Step 7：生成数据

把所有内容写进 `project.json`，字段见 `references/03-data-model.md` 与 `templates/project.schema.json`。

最低要求：

- 每家公司至少 1 条直接证据；
- 每个产能/产量数字有 `source_id`；
- 每条证据有 `level`、`quote`、`url`、`date`；
- 每个规格项有 `status`、`public_info`、`gap`；
- `traders` 与 `companies` 分开；
- `conflicts` 并列保留冲突口径，不强行取一个数。

### Step 8：生成附件

```bash
python scripts/validate_project.py examples/soda-ash/project.json
python scripts/run_all.py examples/soda-ash/project.json --outdir examples/soda-ash/output
```

输出：

```text
output/{产品}_生产厂家核验池_{收货地}_{YYYYMM}.xlsx
output/{产品}_生产厂家核验池_{收货地}_{YYYYMM}.html
```

### Step 9：质检与交付

交付前必须过 `references/07-qa-checklist.md`：

- 17 家样本，是否每家都有生产证据？
- 有没有把经营范围当生产？
- 有没有把在建产能算进在产？
- 有没有把集团产能重复加总？
- 有没有“符合”但没有 COA？
- 每个数字能否点回来源？
- 贸易商是否单独列出？
- 数据截止日、样本覆盖、距离/运费边界是否写明？

## Excel 结构

至少 10 个工作表；推荐 12 个：

| 工作表 | 内容 |
|---|---|
| `00_封面` | 标题、RFQ、KPI、规格表、方法、边界 |
| `01_候选供应商池` | 17–30 家，排名、身份、基地、产能、距离、规格、证据、动作 |
| `02_生产证据明细` | 每条证据的等级、原文、来源、链接 |
| `03_规格匹配矩阵` | 企业 × 规格的宽表 |
| `03b_规格逐项明细` | 企业 × 规格的长表，可筛选 |
| `04_工厂与产能` | 每个基地一行，地址、坐标、产能、年份 |
| `05_评分与排序` | 分项分数、加权计算、敏感性 |
| `06_贸易商与排除名单` | 贸易商/代理/仅工商，判定依据 |
| `07_数据缺口与复核清单` | P0/P1/P2、影响、复核方法 |
| `08_来源库` | 来源 ID、机构、标题、日期、等级、URL |
| `09_RFQ与行动清单` | 追问清单、30 天行动、主供/备供建议 |
| `10_口径与冲突` | 同一指标不同来源的冲突与处理 |

## HTML 结构

- Hero + RFQ 快照 + KPI；
- 需求卡（可改产品/数量/收货地、上传规格书识别）；
- 关键规格表；
- 产能分布、工艺结构、距离×评分图；
- 候选池（筛选/排序/表格/卡片）；
- 供应商抽屉：总览 / 生产证据 / 规格匹配 / 准入尽调；
- 贸易商排除；
- 方法、缺口、冲突、30 天行动；
- 来源库；
- 对比托盘（最多 3 家）。

## 跨 agent / 跨电脑使用

这个包不依赖 DSH 路径，也不调用任何专有 API。要求：

```text
Python 3.10+
openpyxl >= 3.1
```

安装：

```bash
pip install -r requirements.txt
```

使用：

```bash
python scripts/validate_project.py path/to/project.json
python scripts/run_all.py path/to/project.json --outdir path/to/output
```

在不同 agent 中：

- **Codex**：把本目录放到仓库/技能目录，在 `AGENTS.md` 或任务提示中写“读取 `chemical-supplier-verification/SKILL.md` 并按其工作流执行”；
- **ChemClaw / WorkBuddy**：上传/挂载整个目录，先读 `SKILL.md`，再按 `references/` 执行；生成脚本用本机 Python 运行；
- **任意支持 Markdown 的 agent**：把 `SKILL.md` 作为系统提示或任务说明，把 `templates/project.schema.json` 作为输出约束。

不要硬编码本机绝对路径；脚本全部用相对路径和 `pathlib`。

## 不要做

- 不要用“经营范围含某产品”判定生产厂家；
- 不要把贸易商/代理混进厂家池；
- 不要把集团产能重复加到每个基地；
- 不要把设计产能/在建产能写成在产产能；
- 不要用标准值代替批次实测值；
- 不要编造员工数、成立年份、地址、产能；
- 不要用直线距离推算运费；
- 不要承诺“最低价”“唯一正确名单”；
- 不要在无来源时写“据行业统计”而不给来源；
- 不要把示例 RFQ 当成真实采购需求。
