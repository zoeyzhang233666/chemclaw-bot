# 数据契约（data.json）

渲染器只认这一个文件。先把事实整理成 `data.json`，再由脚本产出 HTML 与 Excel——这样同一份事实永远只有一处来源，改一次，两份交付物同时更新。

> 完整可运行示例：`examples/soda-ash-2026/data.json`；空白骨架：`templates/data.template.json`。

## 顶层结构

```json
{
  "meta":        { …报告元信息… },
  "procurement": { …采购需求，即"比较的统一标尺"… },
  "suppliers":   [ …2–5 家企业… ],
  "dimensions":  [ …比较维度（含自定义）… ],
  "terms":       [ …8 项商业条款… ],
  "evidence":    [ …证据索引… ],
  "quotes":      { …报价回收状态… },
  "intel":       [ …时间线… ],
  "intel_reach": { …本轮检索边界… },
  "findings":    [ …关键差异与不确定项… ],
  "next_actions":[ …下一步动作… ],
  "questions":   { "A": [ …逐家问询问题… ] }
}
```

## meta

| 字段 | 必填 | 说明 |
|---|---|---|
| `doc_no` | ✔ | 文档编号，建议 `SUP-CMP-年-月日-品类码` |
| `title` | ✔ | 报告名，如「供应商横向比较报告」 |
| `issue` | ✔ | 一句话主题，显示在首屏大标题 |
| `product` | ✔ | 产品全称 + 等级 + 标准 |
| `prepared_by` | ✔ | 编制方 |
| `version` | ✔ | 版本号，改一次事实就升一次 |
| `as_of` | ✔ | **数据截止日**。所有时效判断（许可到期、负面事件窗口）以此为基准 |
| `export_base` | | 导出文件名前缀（不含扩展名） |
| `use_note` | ✔ | 使用边界声明，写在报告页脚 |

`as_of` 是整个体系的锚点：证据日期晚于 `as_of` 就是作弊，晚于今天就是穿越。校验器在这两点上都会报错。

## procurement

| 字段 | 含义 | 常见错误 |
|---|---|---|
| `product` / `spec` | 标的与执行标准、关键指标 | 只写“纯碱”，没写轻质/重质与等级，后面所有比较都失焦 |
| `qty` / `qty_alt` | 年量 / 备选口径 | 只给年量，供应商用试单价报价 |
| `destination` | 收货地（省市区 + 园区） | 只写“华东”，运距与运费无法核 |
| `delivery_pref` | 散装/包装、运输方式、节奏 | — |
| `payment_pref` / `tax_pref` | 账期与票据 | — |

## suppliers[]（2–5 家）

| 字段 | 取值 | 说明 |
|---|---|---|
| `id` | `A`…`E` | 单字母代号，全表引用 |
| `short` | 2–4 字 | 表头显示，如「山东海化」 |
| `name` | 工商全称 | 必须与营业执照一致 |
| `group` | 文本 | 控股股东 / 实控人 / 集团归属 |
| `code` / `track` | 证券代码 / 上市板块 | 非上市写 `非上市` |
| `producer` | `producer` \| `doubt` \| `trader` \| `unknown` | 厂家身份判定，见 `evidence-standard.md` |
| `producer_note` | 文本 | **必须写判定依据**：许可持有人=生产主体=发货工厂？ |
| `site` | 文本 | 生产基地所在地 |
| `plant_to_dest_km` | `≈N km` | 一律带「≈」，并在 `distance_note` 说明是公路量级还是直线 |
| `evidence_note` | 文本 | 本企业的证据基础（有没有年报、环评、法院文书） |
| `summary` | 3–5 句 | 规模 + 优势 + 不确定项，不确定项**必须点名** |
| `tiers` | 4 组 `[代号, 名称, 结论, 依据]` | 固定在档案卡顶部 |
| `dims` | 见下 | 每个维度的单元格 |
| `certs` | 数组 | 许可/资质明细 |
| `quote` | 8 个条款对象 | 见「商业条款」 |

### dims 单元格

```json
"capacity": {
  "v": "纯碱设计产能 280 万吨/年，2025 年利用率 97.29%…",
  "lvl": "low",
  "note": "口径提醒（可选）",
  "ev": "V:E01,E27"
}
```

- `v` 允许极少量行内标签：`<b>`、`<br>`、`<span class="muted">`；**不要**塞 `<script>` 或外部链接。
- `lvl` 只用于 `risk` / `event` 维度：`high` / `mid` / `low` / `none`。含义是「对本次采购的潜在影响」，不是企业整体评级。
- `note` 用来放口径提醒（例如「这是披露口径，不是事实上的零诉讼」）。
- `ev` 是证据引用，语法见下节。

## 证据引用语法

```
V:E01,E02|原文摘录  ;;  U
```

- 一段引用 = `标签` + `:` + `证据编号(逗号分隔)` + 可选 `|摘录`。
- 一个单元格里有多个来源时用 ` ;; ` 分隔。
- 标签五选一：`V` 已核实 / `S` 企业自述 / `M` 媒体第三方 / `U` 无法核实 / `X` 风险事实。
- `V` `S` `M` `X` **必须**带至少一个证据编号；`U` 可以不带（它本身代表“没拿到”）。
- 编号必须存在于 `evidence[]`，否则渲染时会出现红色 `evmiss` 标记，校验器直接报错。

## 差异判定（系统自动）

同一维度下，三家单元格的“签名”相同即视为**没有实质差异**，报告里会用「只看实质差异」折叠掉它。签名规则：

| 维度类型 | 签名 | 含义 |
|---|---|---|
| `risk` / `event` | 等级 `lvl` | 等级相同即视为同一风险档位 |
| `licence` | 该单元格出现 4 位年份的个数；出现「未取得/待索取」则为 0 | 公开可查的许可条数相同即视为同一档 |
| `terms` | 报价状态 | 都是“待确认”就是无差异 |
| 其他 | 文本值（去标签、压缩空白） | 文本相同即无差异 |

这条规则很重要：它让报告**不必**为每家都写一遍相同的话，也让“哪一项真的不同”变成可复核的计算结果，而不是写报告的 人的印象。

## certs[]

```json
{"name": "排污许可证", "start": "2023.09.20", "end": "2028.09.19",
 "scope": "排污", "holder": "纯碱厂", "relevance": "core"}
```

`relevance`：`core`（本次必需）/ `related`（相关）/ `irrelevant`（无关但要列，用来证明清单完整）。
`end` 为空表示“未取得副本”，状态显示为「待核定」，不会伪装成“有效”。

## 商业条款（quote）

```json
"price": {"status": "pending", "v": "待确认", "ev": ""}
```

`status`：`confirmed`（已确认）/ `quoted`（报价待核）/ `pending`（待确认）/ `missing`（未提供）/ `risk`（有风险）。

**硬规则**：`quotes.status = "none"` 时，任何条款不得出现具体金额，校验器会检查 `\d+\s*元`。没拿到报价就写“待确认”，把它变成问询问题——这比填一个“行业价估算”诚实得多，也安全得多。

## evidence[]

| 字段 | 说明 |
|---|---|
| `id` | `E01`…`E99`，另保留 `U` 作为“未取得”登记 |
| `name` | 文件/页面名 |
| `source` | 来源站点或机关 |
| `date` | 发布或获取日期 |
| `type` | 见下表，校验器会据此校验标签一致性 |
| `url` | 原文链接（`U` 用 `#`） |
| `note` | 这条证据支撑了什么，越具体越好 |

`type` 与允许的标签：

| type | 只允许 |
|---|---|
| 上市公司年报 / 半年报 / 环评公示 / 法院文书 / 政府网站 | `V` |
| 企业官网（自述） | `S` |
| 媒体报道 / 行业媒体 / 第三方转载 / 第三方百科 | `M` |
| 缺口登记 | `U` |

把年报内容标成 `M`、把官网自述标成 `V`，是这类报告最常见的两类失真，所以直接在工具层面挡住。

## findings / intel / questions

- `findings[]`：`{id, dim, title, level, text, evid}`。`text` 必须回答三问：**为什么不同**、**对采购意味着什么**、**下一步核什么**。
- `intel[]`：`{date, tag, supplier, text, evid}`，`supplier` 留空表示行业级事件。
- `questions{A|B|C}`：`{dim, priority, q, why}`，`priority` 取 `高/中/低`。编号由渲染器生成（`A-Q01`），不用手写。

## 校验

```bash
python scripts/validate.py data.json      # 出报告前必跑
python scripts/build_all.py data.json --outdir out
```

校验会拦住：证据引用不存在、标签与来源类型冲突、维度单元格为空、风险维度缺等级、出现“最佳供应商/综合评分”这类结论性表述、未报价却填了价格、`as_of` 过期。**宁可少写一条，也不要写一条撑不住的。**
