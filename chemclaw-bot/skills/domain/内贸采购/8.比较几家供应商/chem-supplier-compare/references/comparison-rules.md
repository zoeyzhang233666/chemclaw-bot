# 比较规则：怎么"比"，以及为什么不能打分

## 一、本 skill 的比较哲学

大多数供应商比较报告失败的共同原因不是数据不够，而是**不分轻重地把所有信息堆在一起，再给一个分数**。分数看起来专业，实际上把判断责任从人转移到了一个没人能复算的数字上。

本 skill 选择相反的路：

1. **只呈现差异**。相同的东西不值得占用注意力，报告自动识别并折叠。
2. **保留冲突**。两家官网说 330 万吨、第三方说 220 万吨，就把两个都写出来，让问询去解决。
3. **不做加权、不做总分、不给结论**。评分表是空白的，权重由采购方自己填。
4. **可复核**。每一个判断都能顺着证据编号回到原文。

## 二、四层核验结构

| 层 | 核验什么 | 判定方法 | 不通过的后果 |
|---|---|---|---|
| T1 | 主体与厂家身份 | 营业执照主体 = 合同相对方；生产地址 = 发货工厂；许可持有人 = 生产主体 | 可能签了贸易商却以为是厂家 |
| T2 | 产品与生产能力 | 设计产能 × 利用率 ≈ 产量；装置清单与产品牌号对应 | 可能拿到的是转售货或产能虚构 |
| T3 | 资质与合规 | 排污许可（必需）+ 行业专项许可 + 体系认证的有效期 | 可能随时被停产整顿 |
| T4 | 经营与商业条款 | 司法/处罚/财务 + 八项商业条款 | 可能断供、涨价或无法履约 |

T1、T2 是硬门槛：不通过的企业，后面比较得再细也没意义。

## 三、"真正不同"的判定

系统用“签名”比较同一维度下各家的单元格：

| 维度类型 | 签名 |
|---|---|
| 风险 / 事件 | 等级（高/中/低/无） |
| 资质许可 | 公开可查的许可条数（0 条 = 无法核实） |
| 商业条款 | 报价状态 |
| 其他 | 去标签后的文本 |

签名全部相同 → 该维度标记为“无差异”，在报告里可以被一键折叠。

这条规则有一个重要副作用：**它逼你把话说具体**。「三家都是生产厂家」这种写法会让该维度被折叠；「两家是上市公司本体生产，一家是集团—基地结构、签约主体待定」才会显示为差异——后者才是采购真正需要知道的。

## 四、风险等级怎么定

等级衡量的是**对本次采购的潜在影响**，不是企业整体好坏。

| 等级 | 判据 | 例子 |
|---|---|---|
| 高 | 可能直接导致断供、质量事故、合同无法履行 | 主体资质缺失、被列为被执行人、主营产品停产 |
| 中 | 可能影响价格、交期、长期稳定性 | 子公司持续亏损、大额诉讼（即使胜诉）、重大资本开支期 |
| 低 | 有记录但已闭环，或不影响交付 | 已整改的环保处罚、无重大诉讼披露、常规体检式风险 |
| 无/未取得 | 可查性不足，无从判断 | 非上市企业无财报、无公示渠道 |

**同一个等级在不同企业的成因可能完全不同**，报告里必须写清成因。例如：

- 海化的“低”来自“披露口径无重大诉讼 + 亏损但产能真实”；
- 金山的“中”来自“有可核实的大额货款诉讼（身为原告）+ 非上市无财报 + 历史污染报道”。

把这两个“低/中”并列成一行数字是失职的，必须让读者看到成因差异。

## 五、差异要写成"三问"

每一条 `findings` 必须回答：

1. **为什么不同**——差异的根源（口径、工艺、规模、披露义务）；
2. **对采购意味着什么**——具体到我方的交付、成本、合规；
3. **下一步核什么**——落成一条可执行的问询或验厂动作。

只写第 1 条的，是资料整理；三条都写到的，才是采购情报。

## 六、不确定性怎么写

不确定项不是免责声明，而是**下一轮行动的输入**。写法要求：

- 点名具体是哪一项（不是“相关信息仍需核实”，而是“重质纯碱占纯碱总产量的比例未披露”）；
- 说明为什么拿不到（非上市 / 未在公示范围 / 口径冲突）；
- 给出获取路径（问询哪一条、验厂看什么、索取哪份文件）。

示例：

> **不确定项**：重质纯碱实际产量占比、粒径分布、散装发运能力均未披露（`U`）。
> **获取路径**：问询 A-Q04（要求提供分牌号月产量与典型粒径分布），并附 6 批次检测报告；验厂时查看散装装车线与成品堆场。

## 七、不能做的四件事

| 禁止 | 原因 | 替代做法 |
|---|---|---|
| 综合评分 / 加权总分 | 权重本身是决策，不该由报告替采购方决定 | 提供空白评分表，权重自填 |
| “最佳供应商”结论 | 取决于采购方的成本结构、风险偏好与战略 | 呈现差异 + 不确定项，让采购方选 |
| 用行业均价填报价 | 一旦编造，整份报告失去可信度 | 留“待确认”，转为问询 |
| 抹平口径冲突 | 冲突往往是最有价值的发现 | 两个数都写，标注来源与年份 |

## 八、报告读法（给使用者的一段话）

> 先看首屏横向比较表里带金色圆点的行——那是三家真正不一样的地方。
> 再看「真正不同的地方」，它把差异归成了几组。
> 然后逐家展开企业档案，重点看“许可”与“不确定项”。
> 最后看问询清单：把这三份问题发出去，收回来的答案就是这个比较真正的下半场。

## 九、可移植性

这套规则与品类无关。换产品时只需要改三样东西：

1. `dimensions` 里的自定义维度（工艺/质量相关）；
2. `questions` 里的行业特定问题；
3. `procurement.spec` 的指标。

`evidence-standard.md`、`quote-normalization.md`、本文件里的规则**不需要改**——它们约束的是“怎么说话”，不是“说什么”。
