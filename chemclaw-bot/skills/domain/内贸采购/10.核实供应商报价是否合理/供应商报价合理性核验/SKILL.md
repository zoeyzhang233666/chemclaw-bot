# 供应商报价合理性核验（内贸采购）

给内贸采购一份**能拿去和供应商对话、也能被审计复核**的报价核验底稿：把供应商报价标准化成
统一口径 → 找到真正可比的现货市场参考价 → 算偏离 → 算历史分位（含缺口）→ 拆口径差异 →
分清「有证据解释的差异」与「还欠供应商一句话的差异」，落成 **可交互 HTML 报告 + Excel 工作簿**。

适用于大宗化工品、精细化工品和中间体。**品种规则一律来自数据文件，不写死在脚本里**——
乙二醇只能用乙二醇自己的解析口径，不能变成所有品种的默认规则。

## 四条硬规矩（违反任何一条，本次交付作废）

1. **口径先于数字。** 没有统一成「同规格 + 同地区 + 同税费 + 同交付」的报价和参考价，不许相减。
   口径不一致就并列展示并打「不可直接比较」标签，不硬算偏离。
2. **每个价格数字六项齐全**：数值 · 规格/等级/含量 · 地区 · 含税与否 · 交付方式（出厂/到厂）·
   数据日期 + 来源。缺一项只能进「缺口」，不许进现货表。
3. **历史分位必须来自有效历史序列**，注明频率、样本数、覆盖区间。**不得用最高价、最低价简单推断分位**，
   不得插值、不得用不同频率序列拼接后冒充同序列。
4. **不替采购判断"应该还价到多少"，不预测未来价格。** 只给市场位置、偏离量、偏离比、可解释的差异、
   待确认清单。方向性表述（看涨、看跌、抄底、见底、还会跌、预计…）一律禁止出现在产物里。

## 九步

### 第 0 步：确认报价口径（不齐就先问）

从用户消息或报价单解析出这 12 个字段（缺哪个就问哪个，问不到就记 `unknown` 并在报告里标红）：

| # | 字段 | 为什么必须问 |
|---|---|---|
| 1 | 品种（中文名 + 英文/别名/MEG/EG 等） | 决定走哪一套解析规则 |
| 2 | 规格 / 等级 / 含量（≥99.9%？聚酯级？工业级？） | 同一品种不同等级价差可达数千元 |
| 3 | 报价值 + 单位（元/吨、元/kg） | 单位不统一是最高频错误，元/kg ×1000 才是元/吨 |
| 4 | 是否含税（13% 增值税？） | 含税与不含税差 13%，方向别搞反 |
| 5 | 交付方式（出厂/车板/送到厂/库提/自提/到港） | 出厂与到厂中间还有运费 |
| 6 | 交货地点（省/市/库区） | 决定匹配哪个区域口径 |
| 7 | 报价有效期 | 过期价不能当现行价比 |
| 8 | 数量（吨/批）与阶梯 | 低位价差对小单不适用 |
| 9 | 付款方式与账期（现款/电汇/承兑/30 天/60 天） | 承兑贴息、账期资金成本要折进可比价 |
| 10 | 包装（散水/吨桶/IBC/槽车） | 包装与灌装费不同 |
| 11 | 计价公式（固定价/随行就市/指数联动 + 升贴水） | 公式报价必须按公式重算 |
| 12 | 供应商性质（生产厂/贸易商/代理商） | 影响价差合理区间，但**不作为抬价理由** |

**完成标准**：12 项都有值或明确 `unknown`；`unknown` 项进入报告的「待确认清单」。

### 第 1 步：报价标准化（脚本算，别心算）

```bash
python scripts/normalize_quote.py <报价单原档.json> --spec meg --out work/quote_norm.json
# <报价单原档> 可以是 examples/*/input/quote_input.json 这种格式，也可以直接传 research.json
```

脚本把报价折成**四个可比的靶心**：`出厂含税`、`出厂不含税`、`到厂含税`、`到厂不含税`（元/吨），
每一步都输出公式与假设值（税率、运费单价、承兑贴息率、账期资金率），假设值可在 specs 里改：

- 单位换算：元/kg → 元/吨 ×1000；元/公斤同理。
- 税费：含税 → 不含税 = 含税 ÷ (1 + 13%)；不含税 → 含税 = ×1.13。（税率取 specs 的 `vat_rate`）
- 运输：到厂 = 出厂 + 运费单价 × 吨数（大宗散水按吨公里或按车；未给运价 → **该靶心记缺口**，
  不许用行业均运费顶替）。
- 账期/承兑：折现到现款价：`现款价 = 报价 × (1 - 年化资金成本 × 账期天数 / 365)`；
  承兑贴息按 specs 的 `acceptance_discount_annual` 计算，全部写成明示公式。
- 包装：散水与吨桶按 specs 的 `packing_adj` 加价，没数据就记缺口。

**完成标准**：`work/quote_norm.json` 里每个靶心都有 `value` 或 `null + gap_reason`，且带公式字符串。

### 第 2 步：市场价格匹配（这一条决定报告值不值钱）

按 [`references/market-evidence-playbook.md`](references/market-evidence-playbook.md) 的渠道优先级取证。
**只认能落到「同日、同规格、同地区、同税费、同交付」的参考价**，优先顺序：

1. 交易所/官方平台（大商所、郑商所、上期所；国家级价格监测平台）；
2. 产业资讯日更报价（隆众、卓创、我的钢铁网、生意社——**记下原文标题、发布时间、发布方**）；
3. 期货公司/协会日报中的「现货主流价 / 基差 / 港口库存」——一条常顶三条；
4. 公开商品指数（如生意社价格指数）——**只用于走势与分位，不能直接当现货成交价**；
5. 企业挂牌价/结算价（如中石化月度挂牌与结算）——**是企业定价，不是市场均价，必须标注性质**。

**现货参考区间**的构造规则（写进报告，别藏）：
- 同一天有 ≥2 个独立来源 → 取区间 [min, max]，中位数作参考中枢；
- 只有 1 个来源 → **按单点价处理整段区间**（`interval_type = "point"`），并明确"本报告未取得同日多源报价，不构成区间"；
- 只有指数没有价格 → 不进现货表，只走分位（`index_level` 用途）。

**期货价格的使用边界**：期货是**不含税、含交割/交割品标准的远期价格**，只能作为「同方向的价格位置参考」，
**绝不能直接减现货报价**。若要用，必须换算成"期货隐含现货"（期货 + 基差 = 现货，基差须取自同源资讯），
或干脆只把它画在走势图上做参照。

**完成标准**：每条参考价都有六项口径 + URL + 抓取时间；缺口写进 `gaps`。

### 第 3 步：偏离计算

```bash
# A. 有 research.json（推荐）：按 benchmark.interval_by_target 逐靶心算
python scripts/compute_deviation.py --research examples/01-meg-huadong/research.json --out work/deviation.json
# B. 只有几个数
python scripts/compute_deviation.py --quote 5900 --low 5580 --high 5665 --center 5635 --out work/dev.json
```

对每个**可比靶心**都算：

- 偏离金额 = 报价靶心 − 参考中枢；与区间下沿比 = 报价 − 区间低点；与区间上沿比 = 报价 − 区间高点；
- 偏离比例 = 偏离金额 ÷ 参考中枢 × 100%；
- 相对位置 = 报价在 [区间低点, 区间上沿] 中的分位位置（若区间按单点处理则不给该值）。

口径不匹配（规格/税费/交付任一不同）→ 输出 `comparable: false` 和 `mismatch_fields`，**不出偏离数**。

**完成标准**：每个数字都能在 Excel 的公式列里复现。

### 第 4 步：历史分位（含缺口声明）

```bash
# 单个序列、单个窗口
python scripts/compute_percentile.py examples/01-meg-huadong/series/ppi_benchmark_1y.json \
       --value 5900 --asof 2026-10-19 --window 1y --levels --out work/pct.json
# 一次算全部窗口：直接跑 model.py，它会按 windows_def 输出 3m/1y/1y_fut/3y
python scripts/model.py examples/01-meg-huadong/research.json --out work/model.json
```

- **3个月**：优先用日频现货序列；没有日频就用**逐日快照证据**（≥8 个交易日点），日期和来源逐条可查；
  少于 8 点 → 判「样本不足」，只给区间不给分位。
- **1年 / 3年**：优先日频/周频现货序列；**没有就明确写"未取得 1 年 / 3 年日频现货序列"**，
  可退而用：① 公开指数分位（注明是指数不是价格）；② 年度/季度锚点（注明是锚点不是序列，**不出分位**，
  只给"报价高于/低于某年锚点多少"）。
- 分位口径固定为：`P = (小于当前值的有效样本数 + 0.5 × 等于当前值的样本数) / 有效样本数 × 100%`，
  并在报告里写出这个定义。
- 同值（节假日、未更新日）要去重或标记，不许用重复值把分位做偏。

**完成标准**：三个窗口各自给出「有序列 → 分位 + 样本数 + 起止日期 + 频率」或「缺口 + 缺口原因 + 已尝试渠道」。

### 第 5 步：口径差异归因

逐项过 [`references/comparability-rules.md`](references/comparability-rules.md) 的十类口径，每类给出：

- 是否已知（`known/unknown`）、方向（抬高/压低报价）、能否量化、量化依据；
- 结论只落到三种标签：`可用证据解释`（有量化或可验证证据）、`可能解释但待确认`（方向清楚、金额未定）、
  `无法解释`（全部口径对齐后仍有残差）。

**品种规则只从 specs 读**：含量→价格的换算（比如聚酯级与工业级的价差方向）、规格术语映射、
包装加价、区域运费口径，全部放在 `specs/<产品族>.json`，**脚本里不出现任何具体品种的系数**。

### 第 6 步：写研究稿

复制 [`templates/research.example.json`](templates/research.example.json)，按
[`references/data-contract.md`](references/data-contract.md) 填。最容易漏、也最影响可用性的四块：

- `quote`：原始报价 + 标准化后的四个靶心 + 未确认项；
- `market`：每条参考价的六项口径 + 来源；`events`：近期已发生的行情变化（只写事实 + 日期 + 来源）；
- `comparability`：十类口径逐项判定；
- `gaps`：拿不到的序列、渠道试过哪些、为什么补不上。

### 第 7 步：生成 HTML + Excel

```bash
python scripts/build_report.py examples/01-meg-huadong/research.json           # 输出到该示例的 output/
python scripts/build_report.py <任意 research.json> --out out/                 # 指定输出目录
python scripts/build_report.py --example 01-meg-huadong                        # 用内置示例
```

产物（两个都必须交）：

- `output/<品种>-<地区>_报价核验报告.html`——单文件离线、零外链、内联 ECharts；首屏是
  **市场参考区间 + 供应商报价标记 + 历史分位条**；可切换历史窗口 / 区域 / 交付口径；同期走势图；
  点击异常价格阶段看事件；**不可比数据打醒目口径不匹配横幅**。
- `output/<品种>-<地区>_报价核验.xlsx`——含价格历史、报价比较、计算公式、数据来源、口径矩阵、
  待确认问题清单等表，与 HTML 同源同数。

**完成标准**：两个文件都生成；HTML 体积 ≈1 MB 以上（ECharts 内联成功）。

### 第 8 步：自检并交付

```bash
python scripts/check_output.py work/01-meg-huadong_model.json examples/01-meg-huadong/output
```

检查：占位符、外链、禁用词（预测/还价建议）、分位是否只来自序列、口径不匹配是否已标出、
Excel 与 HTML 同源。**必须 0 失败**。

交付时给：两个附件的绝对路径 + **3–5 句事实摘要** + **缺口清单** + **待确认问题清单**。
不要复述整份报告，采购要的是文件。

## 交付物结构（Excel 固定表）

| # | 表 | 作用 |
|---|---|---|
| 00 | 封面与结论 | 一句话现状 + 关键指标卡 + 使用前必读 |
| 01 | 供应商报价 | 原始报价 + 12 项口径 + 有效期 + 未确认项 |
| 02 | 报价标准化 | 四个靶心、每一步公式与假设 |
| 03 | 市场价格 | 每条参考价六项口径 + 来源 URL + 抓取时间 |
| 04 | 偏离比较 | 金额、比例、区间内外、可比性 |
| 05 | 历史分位 | 三窗口的序列信息、样本数、分位或缺口原因 |
| 06 | 价格历史 | 逐日/逐周序列（含来源列），供复核 |
| 07 | 事件与行情变化 | 已发生事件、日期、来源、影响的价格阶段 |
| 08 | 口径矩阵 | 十类口径逐项：已知/未知、方向、可量化性、标签 |
| 09 | 计算公式 | 每个数字的公式与参数（可复制到采购表格） |
| 10 | 数据缺口 | 缺什么、为什么缺、试过哪些渠道 |
| 11 | 待确认问题 | 要问供应商的原话（按优先级） |
| 12 | 来源清单 | 每条来源的标题、机构、日期、URL |

## 交付边界

| 必须做 | 绝对不能做 |
|---|---|
| 给市场区间、历史分位、偏离量与偏离比 | 给"应该还价到多少""目标价" |
| 列出可解释差异与待确认差异 | 预测未来走势、判断"见底/见顶" |
| 口径不齐时明确标注不可比 | 用近似值、行业均值、插值补数 |
| 把期货与现货分开展示 | 用期货价直接减现货报价 |

## 降级路径

| 情况 | 做法 |
|---|---|
| 拿不到同日同规格现货价 | 现货区间留空，只展示企业挂牌价/指数，并在首屏说明"本次未取得可比现货" |
| 拿不到 3 年序列 | 明确写缺口；只给 3 个月分位 + 年度锚点对比，不出 3 年分位 |
| 规格/税费/交付不一致 | 不出偏离数，只出口径矩阵 + 待确认问题 |
| 期货接口不可用 | 走势图只画现货与指数，并注明"本期未取得期货序列" |
| 报价单是 PDF/图片 | 先转文本再解析，原文截图留档；解析不确定的字段标 `unknown` |
| 供应商只给公式价 | 按公式重算当日价，并把公式原文贴进报告的"报价口径" |
