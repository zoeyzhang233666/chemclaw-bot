# 01 读入与字段映射

## 1. 支持的输入

| 格式 | 支持 | 说明 |
|---|---|---|
| `.xlsx / .xlsm` | ✅ | 多 sheet 自动选“命中字段最多”的 sheet，可用 `--sheet` 指定 |
| `.csv` | ✅ | 自动尝试 `utf-8-sig → utf-8 → gb18030`（国内 Excel 常导出 GBK） |
| `.json` | ✅ | 二维数组或对象数组 |
| `.pdf` | ⚠️ | 需先转表（见 §5），不要直接把 PDF 塞进来 |
| 图片 / 截图 | ⚠️ | 必须 OCR + 人工核对，OCR 结果不得直接进入矩阵 |

## 2. 表头自动识别

`lib_ingest.map_headers()` 在前 30 行里逐行打分：

```
命中字段数 × 2 − 未识别列数 × 0.5
```

取最高分那行作为表头。常见干扰：

- 第 1–2 行是标题/公司名/日期 → 分数低，自动跳过
- 第 3 行是合并单元格的大标题 → 同样跳过
- 表头有换行符（"物料\n名称"）→ 清洗后仍能命中

若自动识别失败：

```bash
python scripts/make_project.py 清单.xlsx --out project.json --header-row 5 --sheet "采购清单"
```

## 3. 字段别名表（`assets/field-map.json`）

必填：`raw_name`（或 `combination`，即“名称+CAS 挤在一格”）、`quantity`、`unit`。
其余字段缺失不阻塞，但会降低报告信息量并进入“需在询价中澄清”的提示。

关键设计：

- **`combination`**：很多清单把“乙二醇 107-21-1”写在一格 → 正则拆出 CAS 与名称，两者都做交叉验证。
- **`header_skip`**：`合计 / 小计 / 备注 / 以下空白 / 说明` 这类行自动跳过。
- **`unit` 与 `quantity` 分离**：不接受“600 吨”写在一格里（会在 §4 里被 `to_number` 拆出来，但仍建议分列）。

## 4. 脏数据的六种形态与处理

| 形态 | 表现 | 处理 |
|---|---|---|
| 数量带单位 | `600 吨`、`600t`、`0.6kt` | 拆分数字与单位；`kt` 记 1000 t |
| 单位不统一 | 一部分 `吨`、一部分 `kg`、一部分 `桶` | 全部折算到 `t`；`桶/袋/车/批` 无法折算 → P1 待确认 |
| 单位是“-”“/”“无” | 常见于占位行 | 判 `blocked`，P0 待确认 |
| 数量为 0 | 可能是预估行也可能是误填 | 判 `blocked`，问题写“请补齐实际需求量或删除该行” |
| 品名带后缀 | `烧碱(32%液碱)`、`双氧水 27.5%`、`甘油/99.5%` | 品名做字典匹配，括号内容进 `form` |
| 品名残缺 / 错字 | `烧碱?碱?`、`重酸`、`乙二醇（聚酯级）` | 能匹配字典则记“名称可对应…”；不能匹配 → `unrecognized`，P0 |

## 5. PDF / 图片清单的转表流程

1. 有文本层的 PDF：`pymupdf` 抽取表格（`page.find_tables()`），再用 §2 的方法校对表头。
2. 扫描件 / 微信截图：OCR → **必须人工比对原图**，尤其是 CAS 数字与小数点（OCR 常把 `0` 认成 `O`、`.` 丢失）。
3. 转完先跑一次 `make_project.py`，看 `parse_notes` 里有没有“未映射列”和“缺少物料名称已跳过”。

## 6. 合并单元格与多行同物料

清单里常见：

```
| 乙二醇 107-21-1 | 240 | t |     ← P05
|                 | 60  | t |     ← 合并单元格下半部分
```

- 名称列为空 → 沿用上一行名称，并记 `parse_notes`（info 级）。
- 名称相同、形态相同 → 记 `dup_of`，提示“疑似重复行或不同批次，需确认是否合并”，P2。
- 名称相同、形态不同（32% / 50% / 片碱）→ **不合并**，当作不同物料行，因为产线、包装、许可可能不同。

## 7. 解析产物的字段

```json
{
  "code": "P04",
  "raw_name": "过氧化氢 27.5%",
  "name": "双氧水",
  "cas": "7722-84-1",
  "form": "27.5%",
  "purity": 27.5,
  "qty": 300.0,
  "unit": "t",
  "unit_raw": "吨",
  "qty_annual": 3600.0,
  "status": "ok | ambiguous | conflict | unrecognized | blocked",
  "issues": ["未提供执行标准/质量指标，需在询价中澄清（不阻塞）"],
  "source_row": 7,
  "dup_of": null
}
```

`status` 决定这一行能不能进入比价：

- `ok` → 进入候选匹配
- 其余 → 生成待确认问题，**在问题解决前不给“推荐”，只给“若确认为 X 则可询价”**

## 8. 表里没写的字段怎么办

| 缺什么 | 影响 | 默认处理 |
|---|---|---|
| 无 CAS | 不能做 CAS 交叉验证 | 按名称补字典值，并加问题“请确认是否为该物质” |
| 无执行标准 | 无法判断品级是否匹配 | 不阻塞；在询价清单里列为必问项 |
| 无年用量 | 无法判断供方保障能力 | 用单次量 × 12 估？**禁止**；写“未披露”，在询价时问 |
| 无交付地 | 无法做运距/物流筛选 | 用项目级 `meta.delivery_point` 兜底，并在报告里注明 |
| 无现有供应商 | — | 正常，不影响 |
