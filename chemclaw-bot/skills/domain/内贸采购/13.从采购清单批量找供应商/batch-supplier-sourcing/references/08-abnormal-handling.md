# 08 异常清单处理手册（15 种脏数据）

采购清单来自不同的人、不同的系统，脏数据是常态。**核心原则：能算准的算准，算不准的问，绝不猜。**

| # | 现象 | 范例里的位置 | 判定 | 报告里的写法 |
|---|---|---|---|---|
| 1 | 数量带单位混写 | `600 吨` | 拆分数字/单位 | 正常处理，不提问 |
| 2 | 单位是 `-` | P13 `纯碱 99.2%` | `blocked` / P0 | “单位『-』无法标准化，请改为吨/千克，或给出单位净重” |
| 3 | 单位是计数（桶/袋/车） | P10 `甘油 8 桶` | `ok` + P1 提醒 | “需确认单位净重，按 250kg/桶 计为 2 t” |
| 4 | 数量为 0 | P21 `氯化钙 0 t` | `blocked` / P0 | “数量为 0，请补齐实际需求量或删除该行” |
| 5 | 数量缺失 | — | `blocked` / P0 | “数量缺失，请补齐” |
| 6 | CAS 校验位错误 | P19 `乙二醇 107-20-1` | `conflict` / P0 | “CAS 校验失败；清单 CAS 与字典 CAS 107-21-1 不一致，请以 MSDS 第 3 节为准” |
| 7 | 名称与 CAS 冲突 | 名称=烧碱、CAS=纯碱 | `conflict` / P0 | “名称与 CAS 指向不同物质，请确认哪一栏为准” |
| 8 | 未填 CAS | P11 `双氧水(50%)`、P12 `烧碱(片碱)?` | `ok` + P1 | “清单未填 CAS（已按名称补 7722-84-1），请确认” |
| 9 | 品名残缺/带问号 | P12 `烧碱(片碱)?`、P18 `烧碱?碱?` | `ok`（能匹配）或 `unrecognized` | 能匹配 → 按名称补并提问；不能 → P0 |
| 10 | 非规范名/行业黑话 | P20 `重酸` | `unrecognized` / P0 | “未在字典命中，请补充标准化学名、CAS、执行标准或 MSDS” |
| 11 | 同一物料多行（同形态） | P12 与 P18 都是烧碱 | 第二行标 `dup_of` / P2 | “与第 15 行同一物料/形态，疑似重复行，是否合并统计” |
| 12 | 同一物料多行（不同浓度） | P04 27.5% / P07 35% / P11 50% 双氧水 | **不合并** | 分别匹配，因为许可与产线可能不同 |
| 13 | 括号里藏规格 | `烧碱(32%液碱)` | 提入 `form` | 正常 |
| 14 | 合计行/小计行 | 末尾“合计” | 自动跳过 | `header_skip` |
| 15 | 表头不在首行 | 范例第 3 行 | 自动检测 | `header_row` 记录在方法页 |

## 1. 判定状态机

```
识别名称
  ├─ 命中字典 ──→ 有 CAS？ ──是──→ CAS 校验 ─┬─ 通过且一致 → status=ok
  │                            │            └─ 失败/不一致 → status=conflict (P0)
  │                            └─否──→ 补字典 CAS → status=ok (P1 提醒)
  └─ 未命中 ──→ 有 CAS 且能反查 → status=ok
              └─ 否则          → status=unrecognized (P0)

数量/单位
  ├─ 可折算 → 继续
  ├─ 计数单位（桶/袋/车） → status 不变，+P1
  ├─ 缺失/为 0/无法折算 → status=blocked (P0)
  └─ 负值 → status=blocked (P0)

重复行
  └─ 同物料同形态再次出现 → dup_of，+P2
```

## 2. 优先级规则

| 级别 | 定义 | 时限 | 例子 |
|---|---|---|---|
| **P0** | 缺了它无法寻源或无法比价 | 1 个工作日 | 单位 `-`、数量 0、CAS 冲突、名称无法识别 |
| **P1** | 影响规格匹配或价格可比性 | 3 个工作日 | 未填 CAS、计数单位、形态不明 |
| **P2** | 不影响寻源，但要归档 | 5 个工作日 | 重复行、备注缺失 |

## 3. 提问模板

每条问题必须包含四要素：

```
【问什么】单位『-』需要确认
【选项】① 600 吨 ② 600 千克 ③ 其他（请注明）
【为什么】无法折算就无法与厂家报价横向比价
【影响】不确认则该行不进比价，只能给“若为 600 t 则… ”的参考
```

坏问题：`请确认单位`（客户不知道怎么答）
好问题：`数量 600 的单位是“-”，请确认是吨还是千克？未确认前该行不参与比价。`

## 4. 禁止的“聪明”做法

| 禁止 | 为什么 |
|---|---|
| 自动把 `107-20-1` 纠正成 `107-21-1` | CAS 错一位就是另一种物质，错到报关/安全 |
| 把 `8 桶` 按“行业惯例 200kg/桶”折算 | 客户可能用 250kg 桶，差 20% 影响比价 |
| 把“重酸”当成硫酸 | 可能是磷酸、硝酸、混合酸，危险属性完全不同 |
| 把两行烧碱自动合并 | 可能是不同车间/不同用途，分开采购 |
| 用行业均价填补缺失单价 | 本工具不产出价格 |

## 5. 批量修复策略

行数很多（>50）时：

1. 先按 `status` 分组，把 `ok` 的先做（80% 的行通常能直接进入寻源）。
2. `blocked` 的行整理成一张表发给客户一次性确认，不要一行一行问。
3. `unrecognized` 的行让客户给 MSDS 或英文名，比让客户猜 CAS 快。
4. 若客户迟迟不回，报告里保留占位：`【待确认】烧碱？` + 说明“确认后可直接套用 P09 的候选池”。**不要直接删行**。

## 6. 交付时的措辞

> 21 行中有 9 行可以直接进入比价；其余 12 行需要您确认几个关键信息（单位、数量、CAS）。已确认的行不影响整体寻源进度，我们先把这 9 行推进，剩下的确认后 24 小时内补进来。

这比“您的清单有问题，请重填”更容易被接受。
