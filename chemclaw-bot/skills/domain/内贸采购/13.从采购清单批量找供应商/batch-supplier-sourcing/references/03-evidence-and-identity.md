# 03 证据分级与厂家/贸易商判定

这一篇决定报告的可信度。写错这一篇，整个矩阵就只是“看着很专业的猜测”。

## 1. 身份分级（Identity）

| 代码 | 名称 | 判定标准 | 是否计入“厂家覆盖” |
|---|---|---|---|
| **S** | 生产厂家 | 有自有生产装置的直接证据（许可证载明该产品产能 / 年报产销量的产品清单含该产品 / 环评批复的装置规模） | ✅ |
| **P** | 部分生产 | 只能证明“生产该产品”，但产能或规格缺失，或产品被合并披露 | ✅（但覆盖度最高 ◐） |
| **G** | 集团内生产主体 | 上市公司/集团本身不生产，但其披露的子公司/分公司生产该产品 | ✅（注明签约主体可能是子公司） |
| **T** | 贸易商 | 仅经营/分销，无生产证据 | ❌ 单列 |
| **I** | 综合集成商 | 多产品线打包供应、含贸易与加工，身份混合 | ❌ 单列 |
| **U** | 未证实 | 无任何可核验证据，或仅有客户口述/名片 | ❌ 不进候选池 |

**判定顺序**：先看有没有“许可证/环评/产线” → 再看“年报产品清单与产销量” → 再看“官网产品页” → 最后才看“新闻/第三方”。线上顺序决定身份上限：

```
许可证载明该产品产能        → S（最强）
年报产品清单 + 产/销量      → S
年报仅提到产品名（无数字）  → P
年报说“子公司生产”          → G
官网/媒体称“主要产品”      → P 或 G
只有“我们代理/配送”        → T
只有名片/微信/客户口述      → U
```

## 2. 证据分级（Grade）

| 级别 | 含义 | 典型来源 | 能支撑到什么结论 |
|---|---|---|---|
| **A** | 第三方权威 / 许可批文 | 应急管理部门的安全生产许可证、生态环境局环评批复、发改委项目核准、交易所交割品牌/厂库公告 | 直接支撑 S + direct |
| **a** | 企业法定披露原件 | 上市公司年报/半年报/招股书/重大合同（巨潮、上交所、深交所 PDF） | 直接支撑 S + direct（合并披露时降为 P） |
| **B** | 官方 / 交易所 / 政府网站 | 地方政府稿、交易所公告转载、协会名录、海关数据 | 支撑 S 或 G，通常可给 direct/partial |
| **C** | 媒体 / 第三方研究 | 财经媒体、券商研报、行业公众号、企查查类 | 只做交叉印证，最高 partial_spec |
| **D** | 无链接自述 | 客户转述、名片、微信截图 | 只能作线索（U 池） |
| **E** | 推断 / 间接 | “同一集团应该有”、“同装置族应该能做” | 不能单独成立任何覆盖结论 |

> **强制要求**：每条证据写 `quote`（原文摘录，不改写）、`url`、`date`、`org`。三个字段缺一，等级自动降到 D。

## 3. 覆盖度分级（Coverage）

| 代码 | 符号 | 判定 | 需要的证据 |
|---|---|---|---|
| `direct` | ● | 该企业确实生产**这个品规**（浓度/形态/等级对得上），且有产能或产量数字 | A/a/B + 规格对齐 |
| `partial_spec` | ◐ | 生产该**物质**，但清单要的浓度/形态/包装不确定 | A/a/B/C |
| `disclose` | ○ | 有披露（如许可证提到该产品或装置），但证据只到“存在装置”层面 | A/a/B（间接） |
| `dist_only` | ◆ | 仅贸易/配送，无生产证据 | 经营许可、客户线索 |
| `not_listed` | × | 有 A/a 级证据显示该产品**不在其产品清单** | 年报产品清单 |
| （空白） | | 本轮未评估 | — |

**关键区分**：`partial_spec` 与 `disclose` 的分界在于——能不能说出“它有这条产品线”。能说出 → ◐；只能说出“它有这个装置/许可” → ○。

## 4. 反向证据（防伪阳性）

报告必须能证明“它不是骗子”。至少放 1–2 个**反例**：

- 企业很强，但年报产品清单里**没有**该物料 → 标 `not_listed`，理由写“产品清单无该产品”。
- 企业自称“可供应”，但只有经营许可证 → 标 `dist_only`，理由写“无生产证据”。

范例见 `examples/northeast-china-batch/project.json` 中：

- `齐翔腾达 × 乙二醇` → `not_listed`（年报产品清单无乙二醇）
- `区域贸易商（示例）× 氯化钙` → `dist_only`（自述代理，无授权书）

## 5. 五个高频误判

| 误判 | 正确做法 |
|---|---|
| 集团名下的销售公司 → 当作厂家 | 判 G，并写清“集团内生产主体为 ×× 子公司” |
| “公司简介：主要产品有 A/B/C”→ 当作三种都能供 | 判 P；产能/规格缺失，覆盖度 ≤ ◐ |
| 上游原料当产品（硫磺之于硫酸厂） | 判 disclose，理由必须写“为主要原料而非产品” |
| 许可证口径 vs 年报口径不一致 | 两个都记，`conflict_with` 标注，结论写“按基地/按口径拆分询价” |
| 在建产能当现有产能 | 标 `在建`，不计入当前覆盖，只进“可达”并注明投产时间 |

## 6. 证据链最小单元

一条合格的证据长这样：

```json
{
  "id": "E-HH-02",
  "grade": "A",
  "org": "山东海化股份有限公司",
  "topic": "2025 年年度报告：安全/生产许可证载明产能与规格",
  "quote": "氢氧化钠30 万t/a……双氧水(折合27.5%计,含27.5%、35%、50%三种规格)20 万t/a（氯碱树脂公司）",
  "detail": "许可证口径直接列出氢氧化钠 30 wt/a、双氧水 20 wt/a（含三种规格），是合规层级的直接生产证据。",
  "url": "https://static.cninfo.com.cn/finalpage/2026-03-21/1225022066.PDF",
  "date": "2026-03-21",
  "items": ["P02", "P07", "P09", "P11", "P12", "P13"],
  "caveat": ""
}
```

`items` 的作用是把证据钉到具体物料行——`validate_project.py` 会检查每个 ● 关系是否至少有一条证据在 `items` 里命中了该物料，没命中就告警。

## 7. 交易层事实：一律不写

以下内容无论客户多想要，都不进报告正文（可另附“需人工补录”占位）：

- 联系人姓名/手机号/微信
- 统一社会信用代码、银行账户
- 具体报价、折扣、账期（除非客户自己给出且标注为“客户提供”）
- “该企业愿意供货”这类无出处的陈述
