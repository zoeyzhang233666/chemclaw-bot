## H. 常见事故复盘

| 事故 | 根因 | 防呆 |
|---|---|---|
| **表头压住第一行数据** | 表头写成相对页面 `sticky`（`top:44px`），导航栏高度一变就被挡住 | 表头只相对 `.scroll` 容器吸顶（`top:0`），容器 `position:relative` |
| **矩阵整列空白、格子点不动** | 列取自 `supplier_rank`，其字段是 `supplier_id` 不是 `id`，`s.id` 全为 `undefined`，查不到 link | 渲染前归一化成 `{id,label,meta}`；并在验收里断言“可点击格数 = 总格数” |
| 动态生成的表格没有筛选条 | `renderMatrix()` 直接写 `innerHTML`，没重跑包装逻辑 | 渲染后统一调用 `afterRender()` |
| 把待确认物料也给了“推荐供应商” | 没检查 `status` | 报告中 `status != ok` 的行隐藏推荐，只给“若确认为 X” |
| 覆盖率虚高 | 把贸易商算进厂家 | 两个计数器分开 |
| 客户说“这家不做这个” | 把官网产品页当产能 | 产品页最高给 ◐ |
| 客户发现数据过期 | 用了两年前的年报没标注 | 每条证据必须有 `date`，封面有 `as_of` |
| 询问清单发出去没人回 | RFQ 里没有具体品规 | RFQ 自动列覆盖判定与待确认项 |

## H. 自动化验收（建议每次改 HTML 都跑）

用真实浏览器跑一遍，不要靠肉眼：

```
可点击格数 == 总格数            // 防“整列空白”复活
每个 .scroll：首行 top >= 表头 bottom
任一表头筛选后：首行仍在表头下方
抽屉：证据数 > 0 且至少 1 个 http 链接
控制台：0 error
```

参考实现见技能仓库内的 `_qa_deep.js`（Playwright + 本机 Chrome）。
