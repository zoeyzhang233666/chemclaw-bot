# 内贸采购 · 检查采购合同风险点

把一份采购合同 / 框架协议变成三样东西：

1. **一份可追溯的条款索引**——每个条款都有 ID、编号、页码和逐字原文；
2. **一份按主题的风险清单**——每条都说清「合同写了什么 / 哪些没写清楚 / 可能造成什么采购业务后果 / 找谁确认」；
3. **两份可执行交付物**——交互式 HTML 审查页面 + 多表 Excel 工作簿（含采购、法务、供应商三张待办清单）。

核心只有一个词：**追溯（trace）**。每条风险都必须能点回合同原文的那一条、那一页。**没有原文出处的「风险」，一律不进总表。**

---

## 不可谈判的五条约束

1. **不得改写合同事实。** 引用必须是逐字摘录；改写、拼接、推测都不允许。要说明自己的理解，只能写在「业务影响」列里，并且标明这是判断而不是原文。
2. **缺失就是缺失。** 合同没写的，标「缺失 —— 未约定」，不要用「按行业惯例应为……」去补成合同内容。行业惯例可以作为「建议确认项」单独列，不能写成合同已有约定。
3. **不做法律结论。** 不评价条款「有效/无效」「能赢/不能赢」，只做业务提示与待确认清单。效力与责任分配的判断一律交法务/律师。
4. **法规标准必须核适用性。** 每条引用的法规、标准都要写明「现行/废止/被替代」+ 依据来源 + 核对日期。核不出来的，标「未核实」，不要凭记忆写。
5. **不替当事人做决定。** 给出的是「建议向谁确认、确认什么」，不是「应改成 X 条」。

## 第 0 步：定边界（一次问清）

用户只说「帮我审一下这份采购合同」时，先确认这五项（缺的用默认值并写明假设）：

| 要素 | 为什么必须有 | 默认 |
|---|---|---|
| **合同文件** | 审查对象；没有原件就不能审 | —（必须提供） |
| **我方身份** | 买方/卖方/代理，决定风险方向 | 买方（内贸采购默认） |
| **标的** | 决定要核哪套标准与法规（危化品/食品级/大宗液体各不同） | 从合同读取 |
| **合同类型** | 单次合同 / 框架协议 / 主协议 + 订单 | 从结构判断 |
| **交付要求** | HTML / Excel / 两者 | 两者都给 |

再问**可补充材料**（用户没有就标「未提供」，不要假装有）：公司标准合同模板、历史争议案例、技术附件/技术协议、内部采购政策与审批权限、供应商资质文件、过往订单与验收记录。

> 输出前先声明本次审查范围：「本次审查仅基于合同正文 + 附件 X，未取得乙方资质文件与承运方证照」。这句话要写进交付物首页。

## 第 1 步：识别合同结构，建立条款索引

### 1.1 识别顺序

1. **文件清单**：正文几页？有几个附件？有没有订单模板、报价单、技术协议、SDS？缺哪些标为「未提供」。
2. **章节**：合同首部 → 正文第 1~N 条 → 签署栏 → 附件一 ~ 附件 N。
3. **条款编号**：保留合同自己的编号（如「第一条 1.2」），**不要重编号**。自动编号缺失时用「第X条 第N款」并注明「原文未编号」。
4. **表格与说明**：附件里的技术指标表要拆成行级锚点（如 `A1-T3` = 附件一表1第3行），这样才能精确引用「这一格是空白」。

### 1.2 条款索引字段（必填）

```
条款ID | 章节 | 条款编号 | 页码 | 页内位置 | 原文全文 | 关联风险 | 是否被覆盖
```

- **条款ID** 是整个数据集的主键，全流程统一使用（`C01`…`Cn` 正文，`A1-xx` 附件）。
- **页码** 必须来自原始文件。PDF 用阅读器页码；Word 用页脚页码。**框架协议 + 订单** 要区分「主协议页码」与「订单页码」。
- **页内位置** 写「第2页 第4行」「第5页 表1 第2行」这一类可复核的描述。
- 索引做完先做一次**覆盖率检查**：有没有条款没被任何风险引用？没有被引用的条款要么补审，要么在「负结果」里说明「已审、未见风险」。

> 模板与字段说明见 [`references/contract-structure.md`](references/contract-structure.md)。

## 第 2 步：按 10 个主题逐条检查（化学采购主清单）

这是用户最关心的 10 个检查点。**每一项都要回答四个问题：写了什么 / 缺什么 / 写得不清楚在哪 / 业务后果是什么。**

| # | 主题 | 必须检查的要点 | 常见漏洞（仅作提示，不作结论） |
|---|---|---|---|
| 1 | **质量** | 产品名称、规格、浓度、等级、执行标准（编号+年份）、指标上下限、杂质项、检验方法版本 | 正文浓度与附件下限口径不一；杂质项留空；出现「或企业标准」；「出厂合格即视为合格」 |
| 2 | **数量** | 总量、单批允差、最小起送量、尾差处理、超量是否付费 | 只写「约 X 吨」；无允差；框架量是否构成最低采购承诺不清 |
| 3 | **验收** | 验收标准、抽样方法、检验机构、复检路径、异议期限与起算点 | 异议期过短；起算点未定义；「以卖方质检报告为准」；无第三方检验约定 |
| 4 | **交付** | 交货时间、地点、运输方式、风险转移时点、顺延条件与上限 | 「另行通知」「顺延不违约」；风险转移点表述模糊；泄漏责任推给承运人 |
| 5 | **价格税费** | 单价口径（净重/折百）、价格构成、税费承担、开票时点与类型、调价基准与上限 | 「暂定价」；卖方单方调价；税率变动风险单向；先款后票 |
| 6 | **付款** | 预付款比例与担保、付款节点、账期、质保金、抵扣与拒付权 | 预付款无担保；无质保金；「不得以质量争议拒付」 |
| 7 | **包装容器** | 包装形式、吨桶押金只数与退还条件、空桶返还、罐车清洗、装卸分工 | 押金「视情况退还」；数量未核定；清洗责任与举证不清 |
| 8 | **违约** | 双方违约金比例与上限、质量违约封顶、责任限制、排除条款 | 双向不对等；质量赔偿封顶过低；总责任上限过低且无例外 |
| 9 | **不可抗力与争议** | 不可抗力定义、通知与解除、退换货、争议解决机构与适用法律、送达 | 把检修/价格波动写成不可抗力；机构名称需核实；无送达地址 |
| 10 | **危化品专项** | 供应商资质（经营/生产许可）、运输资质与罐体适装、危险信息传递（SDS/标签）、装卸与应急分工、储存条件 | 资质未作附件；承运方证照未核；SDS 只给一次；无应急联络 |

**危险化学品专项**（涉及《危险化学品目录》内品种时必须做）：资质、运输责任、危险信息传递、安全管理四块，见 [`references/chem-hazmat.md`](references/chem-hazmat.md)。**不同化工品的共性 + 差异**（液碱、盐酸、甲苯、片碱……）见 [`references/chemical-products.md`](references/chemical-products.md)。

## 第 3 步：写每条风险（固定七字段）

每条风险条目（finding）必须同时具备以下字段，缺一项就不合格：

```json
{
  "id": "R04",
  "topic": "quality",                         // 主题（见 12 个主题枚举）
  "kind": "表述不清",                          // 缺失 | 表述不清 | 写了但对我方不利
  "title": "3 日质量异议期过短，且起算点未明确",
  "clause_ids": ["C04", "C11", "A1-T5"],       // 必填，至少 1 个，必须能在索引里找到
  "what_written": "合同在这里到底写了什么（转述+逐字引用）",
  "what_missing": "哪些事项没有约定（缺失类必须写，不得推测）",
  "business_impact": "对我方（买方）的业务后果，要落到具体环节与量级",
  "consequences": ["后果1", "后果2"],
  "to_confirm": ["向谁确认什么"],
  "owner": ["legal", "quality", "supplier"],
  "law_refs": ["GB/T 209-2018"],
  "severity": 4,
  "likelihood": 3
}
```

### 3.1 三种风险类型（不要混用）

| 类型 | 含义 | 判定口径 | 要求 |
|---|---|---|---|
| **缺失** | 合同中完全没有该约定 | 全文检索无对应表述 | `what_missing` 必填；页面打「缺失」标记；**不得**写成「应约定为……」（那是建议，放 `to_confirm`） |
| **表述不清** | 有约定但不明确、冲突、可作两种解释 | 前后条款冲突 / 起算点、口径、主体不明 | 要指出**冲突的两个原文位置** |
| **写了但对我方不利** | 明确约定，方向对我方（买方）不利 | 单向责任、单方权利 | 只描述业务影响，**不下「显失公平/无效」结论** |

### 3.2 严重度（1–5）怎么给

| 分值 | 名称 | 判断标准 |
|---|---|---|
| 5 | 极高 | 可能直接造成重大资金损失/停产/合规事故，且合同无任何兜底 |
| 4 | 高 | 大概率产生经济损失或履约受限，需要修约或补充协议 |
| 3 | 中 | 产生商务摩擦、成本增加或管理负担，可在执行中管控 |
| 2 | 低 | 影响有限，属优化项 |
| 1 | 提示 | 需关注但不构成风险 |

严重度是**业务影响 × 发生可能**的排序，不是法律结论。

### 3.3 业务影响的写法

差：`该条款对甲方不利。`
好：`散装液碱到厂即卸入储罐，卸后无法单独取样；3 日窗口内若外送检测未完成，异议权自动丧失。按 30 吨/车测算，单批若浓度偏低 1.5 个百分点即少 0.45 吨有效碱，约合 500 元/车；全年 67 车约 3.4 万元，且混罐后无法归属责任批次。`

要点：**落到角色（买方）、环节（卸车/入库/结算）、量级（吨/元/天）**。量级只能基于合同原文数字计算，并注明公式。

> 完整写法与反例见 [`references/checklist.md`](references/checklist.md)；输出格式见 [`references/output-spec.md`](references/output-spec.md)。

## 第 4 步：核法规与标准的适用性

1. 列出合同中引用的所有法规、标准、行业规范（含编号与年份）。
2. 逐条核：**是否现行**、发布日期、实施日期、是否已被替代、替代标准号。
3. 危化品还必须额外核：品种是否在《危险化学品目录》、是否属易制毒/易制爆、运输适用规则与罐体标准。
4. 记录「核验依据」：来源名称 + 核对日期。查不到就写「未能核实，建议签约前确认」。

推荐核验入口（均为公开渠道，结果以页面显示为准）：

- 国家标准：全国标准信息公共服务平台 `std.samr.gov.cn` / 国家标准全文公开 `openstd.samr.gov.cn`
- 行政法规与规章：应急管理部 `mem.gov.cn`、交通运输部 `xxgk.mot.gov.cn`、司法部/全球法规网
- 目录类：《危险化学品目录（2015版）》、易制毒化学品分类和品种目录（含 2025 年新增）

> 核对清单见 [`references/legal-refs.md`](references/legal-refs.md)（含一份 2026 年 10 月核过的样例）。

## 第 5 步：生成三张问题清单

同一批风险按「谁去办」拆开，避免把法律问题丢给采购、把商务问题丢给法务：

| 清单 | 谁 | 装什么 | 交付方式 |
|---|---|---|---|
| **内部采购待办** | 采购员 / 品类经理 | 商务谈判、供应保障、订单管控、资质收集、备选供应商 | Excel「06 采购待办」 |
| **法务待办** | 法务 / 律师 | 条款效力、责任分配、不可抗力、争议解决、修约建议 | Excel「07 法务待办」+ 简短说明 |
| **供应商问题清单** | 直接发给乙方 | 只需乙方回答的事实、文件、承诺 | Excel「08 供应商问题清单」，可作函件附件 |

每条清单项都要带：风险编号、优先级、引用条款、页码、问题时态（已确认/待确认）。

## 第 6 步：交付

### 6.1 交互式 HTML（主交付物）

```bash
python scripts/build_review_html.py --dir <案例目录> --out <输出.html> [--user-note "内部备注"]
python scripts/render_html.py      --case <案例目录> --out <输出.html>   # 通用版（任意合同）
```

页面要求：

- **双栏**：左侧合同原文（按章/条/页，条款带锚点），右侧风险卡；点击风险卡或「📍条款」按钮 → 高亮并滚动定位原文；点击原文里的风险编号 → 反向定位风险卡。
- **筛选**：按主题（质量/数量/交货/包装/计量/价格/付款/安全/违约/不可抗力/争议/通用）、按类型（缺失/表述不清/对我方不利）、按严重度、关键词搜索。
- **问题清单标签页**：采购 / 法务 / 供应商，可逐条勾选。
- **处理状态与备注**：每条风险可设状态（待处理/已确认/待供应商回复/已解决/不适用）并写备注，存 localStorage，可导出 JSON 汇总。
- 单文件、无外部依赖、可离线双击打开、可打印（打印时自动展开全部卡片）。
- 首页必须带「业务审查提示，不构成法律意见」声明；演示合同必须带「虚构演示合同」横幅。

### 6.2 Excel 工作簿

```bash
python scripts/build_review_xlsx.py --dir <案例目录> --out <输出.xlsx>
```

10 个工作表：`00 使用说明与边界`、`01 条款索引`、`02 风险事项总表`、`03 原文引用`、`04 法规标准核对`、`05 待确认清单`、`06 采购待办`、`07 法务待办`、`08 供应商问题清单`、`09 统计`。

### 6.3 演示合同（仅在用户没有原件时）

```bash
python scripts/build_contract_docx.py --dir <案例目录> --out <合同.docx>
python scripts/paginate_contract.py  --docx <合同.docx> --dir <案例目录>   # 核真实分页
```

演示合同必须首行就写「虚构演示合同」，并放在 `examples/` 下，不能与真实合同混放。

## 质量自检清单（交付前逐条过）

- [ ] 条款索引覆盖全部条款与附件行，无重复 ID
- [ ] 每条风险都有 ≥1 个 `clause_ids`，且都能在索引里找到
- [ ] 「原文引用」是逐字摘录，抽样 5 条与合同原件比对无误
- [ ] 每条「缺失」类风险都写了 `what_missing`，且没有把建议写成约定
- [ ] 每条风险都有业务影响、可能后果、待确认问题、办理人
- [ ] 严重度分布合理（不要全是 4/5，也不要全在 2）
- [ ] 法规标准全部标注现行状态 + 来源 + 核对日期
- [ ] 三张清单非空，供应商清单可直接对外发送
- [ ] HTML 与 Excel 的条数、分布、条款锚点完全一致
- [ ] 首页有「不构成法律意见」声明；演示合同有「虚构」标记
- [ ] 写明本次审查范围与未取得的材料（负结果也是结果）

## 常见失败模式

见 [`references/failure-log.md`](references/failure-log.md)。最常踩的六个：

1. **把行业惯例写成合同约定**——「业内通常 7 日异议期」是建议，不是合同内容。
2. **页码对不上**——从 PDF 复制文本后页码丢失，用章节序号冒充页码。
3. **只写「对我方不利」不写后果**——没有业务环节和量级的风险条目，业务同事无法判断优先级。
4. **漏掉附件**——附件里的技术指标表、框架使用说明往往是漏洞最集中的地方。
5. **法规凭记忆写**——标准已被替代（如 GB 12268-2012 → GB 12268-2025）却仍按旧版引用。
6. **越界给结论**——写出「该条款无效」「可以拒付」，这已经越过了业务提示的边界。

## 业务提醒与法律意见的边界

**本 Skill 输出的是业务审查提示（Business Review Notice）。**

| 本 Skill 可以做 | 本 Skill 不做（必须由法务/律师判断） |
|---|---|
| 说明合同写了什么、哪些没写 | 判断条款是否有效、是否显失公平、是否可撤销 |
| 提示可能的采购业务后果（成本、断供、合规、纠纷成本） | 判断诉讼/仲裁的胜负与赔偿范围 |
| 核对法规标准是否现行、是否与合同表述一致 | 判断某条标准是否对本合同当事人强制适用 |
| 列出需要确认的问题与建议办理人 | 替业务方决定是否接受合同、如何谈判 |
| 指出前后条款冲突并给出两个原文位置 | 决定冲突时法院/仲裁庭会采信哪一条 |
| 建议谈判切入点（不改写合同） | 起草正式修订条款与法律文件 |

免责声明必须原样出现在 HTML 首页、Excel「00 使用说明与边界」页和最终回复里：

> 本结果属于业务审查提示，不是法律意见，也不替代律师或法务的专业审查。涉及条款效力、是否可执行、法律责任分配等问题，必须以公司法务/外部律师意见为准。法规与标准的适用性核对于〔核对日期〕，正式签约或索赔前应再次核对权威渠道。
