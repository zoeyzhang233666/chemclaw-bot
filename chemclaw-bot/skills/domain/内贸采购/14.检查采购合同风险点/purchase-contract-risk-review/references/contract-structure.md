# 合同结构识别与条款索引

> 本文件回答两件事：**怎么把一份采购合同拆成可引用的条款**，以及**条款索引该有哪些字段**。
> 适用于 PDF、Word、扫描件转写稿；不依赖任何公司模板。

---

## 1. 文件层：先清点，再审查

审查开始前列出文件清单，并把缺失项写进交付物：

```
《XX采购合同》正文.pdf           6 页
附件一 技术协议.pdf              2 页
附件二 厂商资质复印件.pdf         1 页
────── 以上为已收到 ──────
□ 供应商营业执照               未提供
□ 危险化学品经营许可证         未提供
□ 承运方道路运输经营许可证      未提供
□ 罐车罐体检验合格证/适装介质列表 未提供
□ 报价单原件                   未提供
□ 公司标准合同模板             未提供
```

**为什么先清点**：附件里的技术指标表、订单模板、框架使用说明，往往是漏洞最集中的地方（例如附件写「≥30%」而正文写「32%」）。只看正文必然漏。

### 1.1 合同类型判断

| 类型 | 特征 | 审查重点 |
|---|---|---|
| 单次合同 | 有确定数量、单价与交货期 | 数量允差、交货期、验收 |
| 框架协议 | 「预计/约 X 吨」「以订单为准」 | 框架量是否构成最低承诺、订单要素、价格机制 |
| 主协议 + 订单 | 主协议约定通用条款，订单约定单次要素 | 订单与主协议的优先顺序、订单确认方式 |
| 技术协议单独成卷 | 正文只写「详见技术协议」 | 技术协议是否签署、是否作为附件、版本号 |

### 1.2 识别顺序（固定五步）

1. **首部**：合同编号、双方全称、地址、签订日期、签订地点。
2. **正文**：第 1 条 → 最后一条，逐条编号。
3. **签署栏**：盖章、授权代表、日期；有无骑缝章/页码连续性。
4. **附件**：附件一 ~ 附件 N，含表格。
5. **附属文件**：订单模板、报价单、SDS、资质文件等（列清单，未收到的标「未提供」）。

## 2. 条款层：编号规则

### 2.1 保留原编号（第一条）

合同写「第一条 1.2」，索引里就写「第一条 1.2」。**不要重新编号**——重新编号会让所有引用无法回查。

### 2.2 条款 ID 生成规则

| 位置 | ID 规则 | 示例 |
|---|---|---|
| 首部 | `C01` | C01 |
| 正文第 1~N 条 | `C` + 两位流水号 | C02, C03 … C37 |
| 附件表格行 | `A{附件号}-T{行号}` | A1-T3（附件一表1第3行） |
| 附件说明 | `A{附件号}-{序号}` | A1-T5（表下说明）、A2-01（附件二第1条） |

ID 一旦分配就固定，后续所有引用（风险、清单、Excel、HTML）统一使用。

### 2.3 无法编号时的处理

- 合同用自动编号（Word 列表）导致复制后丢失编号：用「第X条 第N款（原文自动编号）」，并在备注里说明。
- 扫描件无编号：按自然段顺序编号，同时在 `page_line` 写明「第3页 第2段」。
- 表格：拆到**行级**，空单元格也要成为锚点（例如 `A1-T3`「氯化钠含量：空白」），因为「空白」本身就是发现。

## 3. 页码与位置

### 3.1 规则

- **页码取自原始文件**，不是自己数出来的。PDF 用阅读器页码（在页脚显示的那个）。
- 扫描件没有页码时：写「第X页（按 PDF 页序）」，并注明「原件无页码」。
- 双面打印、附件单独编页时：写「附件二 第1页（原件页码 A-2-1）」。
- **页内位置**是可复核的描述：`第2页 第4行`、`第5页 表1 第2行`、`第6页 倒数第3段`。

### 3.2 Word 合同的页码核对

Word 合同分页依赖字体与页面设置，不同机器打开可能相差一页。正确做法：

1. 用固定字体（宋体/黑体）+ 固定页边距另存 PDF；
2. 把条款在 **PDF** 中的页序作为 `page`；
3. 在交付物里注明「页码以 XX 版 PDF 为准」。

本 Skill 提供 `scripts/paginate_contract.py` 做这件事：转 PDF → 抽取每页文本 → 定位每条条款所在页 → 与声明的 `page` 比对，输出差异表。

## 4. 条款索引（Clause Index）字段规范

| 字段 | 必填 | 说明 | 示例 |
|---|---|---|---|
| `条款ID` | ✓ | 主键 | `C04` |
| `章节` | ✓ | 章/条名称 | `第一条 产品名称、规格与质量标准` |
| `条款编号` | ✓ | 合同原文编号 | `第一条 1.3` |
| `页码` | ✓ | 原始文件页码 | `1` |
| `页内位置` | ✓ | 可复核的描述 | `第1页 第7行` |
| `原文全文` | ✓ | **逐字**，不改写、不省略 | `1.3 产品质量以乙方出厂检验结果为准；……` |
| `关联风险` | ✓ | 引用本条款的风险 ID 列表，无则 `—` | `R03, R04` |
| `是否被覆盖` | ✓ | 是/否；「否」需在负结果中说明 | `是` |

### 4.1 覆盖率检查

索引完成后必须回答：

- 有没有条款**未被任何风险引用**？→ 逐条复核：要么补审出风险，要么在「负结果」写明「已审、未见异常」。
- 有没有风险**引用了不存在的条款**？→ 构建脚本会直接报错。
- 同一主题的风险是否**跨条款**（如质量、验收、异议期分散在 1.2 / 1.3 / 3.1 / 3.2）？跨条款是常态，要在 `clause_ids` 里全部列出。

### 4.2 附件的处理

| 附件形态 | 拆法 |
|---|---|
| 技术指标表 | 每行一个锚点，含表头与空白格 |
| 框架使用说明 | 每款一个锚点 |
| 订单模板 | 每个字段一个锚点（数量/价格/交期/地点） |
| 资质证照 | 不拆条款，但记录「证照编号/有效期/经营范围」并单独核对 |
| SDS / 安全标签 | 记录版本号与日期，不拆条款 |

## 5. 数据格式（contract.json）

```json
{
  "demo": true,
  "demo_label": "虚构演示合同",
  "contract_meta": {
    "title": "工业用32%液碱（氢氧化钠溶液）采购合同",
    "contract_no": "XS-2026-LY-0715",
    "sign_date": "2026年10月12日",
    "buyer": "…（甲方）", "supplier": "…（乙方）",
    "review_as": "买方（甲方）",
    "files_received": ["…"], "files_missing": ["…"]
  },
  "sections": [
    {"id": "s1", "no": "第一条", "title": "产品名称、规格与质量标准", "page": 1,
     "clause_ids": ["C02", "C03", "C04"], "notes": "…"}
  ],
  "clauses": [
    {"id": "C04", "sec": "s1", "no": "第一条 1.3", "page": 1, "page_line": "第1页 第7行",
     "text": "1.3 产品质量以乙方出厂检验结果为准；……"}
  ],
  "attachments": [
    {"no": "附件一", "title": "产品技术规范", "page": 5,
     "table": {"caption": "表1", "cols": ["项目","指标"], "rows": [["…","…"]], "note": "…"}}
  ]
}
```

校验规则（`scripts/common.py`）：

- `section.clause_ids` 必须都存在，且 `clause.sec` 必须指回该 section；
- `clause.text` 不得为空；
- 同一文件内 ID 不得重复。

## 6. 提取工具与方法

| 源文件 | 方法 | 注意 |
|---|---|---|
| 可复制文本 PDF | `pymupdf` / `pypdf` 抽文本，保留页码 | 表格会被打散，需要人工重排 |
| 扫描件 PDF | OCR（如需要）后逐页校对 | OCR 错字不能直接进「原文引用」，必须与原件比对 |
| Word | `python-docx` 读段落与表格 | 自动编号丢失，需补编号 |
| 图片/截图 | 人工转写 | 转写后在备注写「据图片转写，待原件核对」 |

**原文引用铁律**：任何进入「原文引用」的文本，都必须与原件**逐字一致**。OCR 或转写的文本要加注「据 OCR 转写，未与原件逐字核对」。

中文文本比对时注意：全角空格（`　`）、制表符、软换行会造成「看起来一样但字符串不等」，比对前先归一化空白，但展示时保留原样。
