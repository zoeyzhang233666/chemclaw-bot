# chem-supplier-qualification · 化学品供应商资质证照核验

把一个采购问题——**"我要向 X 买 Y，这家能不能供、需要什么证、我该要哪些材料"**——变成一份可复核、可归档、可复用的核验底稿。

产物：**单文件交互式 HTML 报告** + **15 页签 Excel 台账**。

---

## 30 秒上手

```bash
cd chem-supplier-qualification

# 1) 看主示例长什么样
python scripts/build_all.py examples/hydrogen-peroxide-30/data.json
#   → examples/hydrogen-peroxide-30/out/*.html  /  *.xlsx

# 2) 做你自己的核验：复制模板，改数据，重跑
cp templates/data.template.json my-case.json
python scripts/build_all.py my-case.json --out ./out
```

环境：Python 3.9+，需要 `openpyxl`（Excel）、`Pillow`（可选，截图切片用）。
不需要联网、不需要浏览器、不依赖任何第三方库渲染 HTML。

---

## 它解决什么问题

| 传统做法 | 本技能 |
|---|---|
| 拿到一堆证照图片，凭印象判断"应该没问题" | 四态判定 + 逐字段交叉核验 + 证据编号 |
| 查不到公开信息就写"该企业无证" | 只能写"无公开信息"，并原样进索证清单 |
| "属于危险化学品"就完事 | 落到目录条目 + 条款 + 浓度适用条件 |
| 一张 ISO 证书证明"资质齐全" | 体系认证只算参考项，不替代行政许可 |
| 换个产品就要重做一套表 | 产品知识全在 `data.json`，脚本零硬编码 |

## HTML 报告包含什么

1. **封面**：记录号、基准日、一句话结论、评级徽标
2. **KPI**：证照总数 / 已核验 / 待核验 / 需反馈 / 距到期最近
3. **01 供应商主体识别**：信用代码校验、地址差异、关系链
4. **02 产品身份与监管分类**：逐项 findings（结论 + 判定 + 依据 + 适用条件）+ 目录核对清单
5. **03 供应商侧许可要求**：角色 → 证照矩阵（必须 / 视情形）
6. **04 采购方义务**：使用许可、流向报备、储存安全…
7. **05 证照核验表**：卡片网格 + **按状态/覆盖筛选** + 关键字搜索 + 点击看证载范围、字段来源、交叉核验（抽屉）
8. **06 公开信息交叉核验**：A 侧 × B 侧 × 结论
9. **07 疑点与异常观察**：事实 / 可能解读 / 如何核实
10. **08 索证清单**：P0/P1/P2 + 勾选进度（存本地）+ 自动派生项
11. **09 供应商补充资料请求**：可直接复制的邮件草稿
12. **10 风险与处置**：事实—后果—处置
13. **11 总体判定**：评级、放行闸门、可以写/不能写、时间表
14. **12 证据登记**：E01…En
15. **13 上传件与扫描件**：缩略图（模拟件显式标注）

交互：侧边导航滚动高亮、`Ctrl/⌘+P` 打印友好样式、`保存核验记录` 导出 JSON、`复制` 草稿。

## Excel 台账包含什么

| 页签 | 内容 |
|---|---|
| 00 封面与说明 | 台账身份 + **七条使用纪律** + 页签导航 |
| 01 主体识别 | 工商字段 + 信用代码校验结果 |
| 02 产品监管识别 | 物料档案 + findings + 分类核验清单 + 资料缺口 |
| 03 监管分类核验单 | 逐项打勾（判定列可下拉） |
| 04 供应商许可要求 | 角色—证照—依据—范围核验要点 |
| 05 采购方义务 | 义务 / 性质 / 依据 / 触发条件 / 落地动作 |
| 06 证照台账 | **核心表**：16 列，有效期判定为公式，状态/覆盖/应否具备三列下拉，底部公式汇总 |
| 07 有效期与范围比对 | 剩余天数公式 + 到期风险公式 + 覆盖/主体/业务一致性 |
| 08 交叉核验记录 | A/B/结论/处理 |
| 09 索证清单 | 优先级着色 + "已取得?"下拉 |
| 10 供应商资料请求草稿 | 整段可复制 |
| 11 风险与处置 | 事实—后果—处置 |
| 12 人工核验事项 | 无法自动化的清单 + 责任人与完成日期 |
| 13 证据登记 | E01…En + 可点击链接 |
| 14 附录·数据字典 | 字段取值与写法规矩 |

公式：`基准日` 为定义名称，改封面日期全表自动重算。

## 跨品类复用（关键设计）

**脚本里没有任何化学品的名字。** 产品知识只存在于数据的这两个位置：

- `product.findings[]`：结论、判定、法规依据、适用条件
- `classification_checklist[]`：逐项核对的轨迹

换品只改数据：过氧化氢 → 甲醇 → 盐酸 → 烧碱 → 双氧水 → 溶剂，模板、样式、自检规则全不动。
判定口径（`confirmed / not_confirmed / pending`、四态、覆盖四态）是**方法论**，不是产品结论。

---

## 三条使用红线

1. **查不到 ≠ 没有。** 只能写"无公开信息 / 待核验"，并进索证清单。
2. **不得推断。** 名称、经营范围、行业常识都不能推出许可状态；许可范围必须逐字比对。
3. **模拟件必须标注。** `gen_mock_scans.py` 生成的 SVG 带水印与 MOCK 编号，只用于演示；真实作业必须上传供应商给的原件。

`validate.py` 会把违反第 1、3 条的写法直接判 FAIL。
