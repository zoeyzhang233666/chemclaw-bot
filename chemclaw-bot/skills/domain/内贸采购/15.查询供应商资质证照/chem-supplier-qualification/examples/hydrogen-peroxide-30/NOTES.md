# 主示例：向华东供应商采购 30% 过氧化氢溶液

## 这个示例演示什么

一次**完整的真实感核验**：产品侧定性闭环、供应商侧主体可核但证照大量缺口、采购方义务清晰——正好覆盖"查得到的不多、但不能乱写"的常见处境。

| 要素 | 内容 |
|---|---|
| 采购标的 | 过氧化氢溶液 30%（工业级），首批 30 t，年用量 300–500 t |
| 供应商 | 杭州名鑫双氧水有限公司（真实企业，统一社会信用代码 91330100668020191W） |
| 我方（示例） | 华东某新材料企业（脱敏示例，不作为真实主体） |
| 基准日 | 2026-10-12 |
| 结论 | **G2 有条件推进（资料缺口型）**——P0 五项未关闭，不得下单 |

## 供应商侧的核心发现

1. **主体身份可核**：名称、信用代码、住所、法定代表人、注册资本、成立日期来自格林达（603931）2026-07-18 关联交易公告，本地 GB 32100 校验码复算通过。
2. **但一张证照影像都没拿到**：官网"相关证书"栏目公示 11 项（体系认证、营业执照、全国工业生产许可证、食品生产许可、消毒卫生许可、荣誉等），**唯独没有《危险化学品安全生产许可证》**。
3. **"不在注销名单"只是弱证据**：核对了浙江省应急管理厅 2024-01-31（29 家）与 2024-04-17（13 家）两份注销名单，均不含本公司——但绝大多数省份不逐条公示授予记录。
4. **角色判断**：官网自述三套双氧水生产线、年设计产能约 43 万吨 → 生产企业 → 核心证照是**安全生产许可证**，而非经营许可证。

## 刻意保留的"缺口"（这是示例的价值所在）

- 安全生产许可证、登记证、SDS、COA **全部为空**，状态为"待核验/未发现公开记录"——**没有编造任何证书编号、发证机关或有效期**。
- ISO 三体系证书：官网有影像但字段未读 → `pending`，不写"已认证"。
- 食品生产许可与消毒卫生许可：本单工业用途 → `need=none`、覆盖"未覆盖"（提醒不要把等级混用）。
- 易制毒、重点监管、重大危险源、运输分类：`pending`，明确写"未取得目录/标准原文"。

## 扫描件说明（重要）

`scans/` 下 9 个 SVG **全部是模拟演示件**：

- 顶部红色警示条 + 45° 水印写明"模拟演示件 · 非真实证照"；
- 证照编号一律 `MOCK-` / `SAMPLE` 前缀，企业名称用「［样例］XX化工有限公司」占位；
- **没有使用杭州名鑫双氧水有限公司的任何真实证照字段**（因为本来就是伪造出来的字段，绝不能让它们看起来像该企业的真证）。

它们只用来演示"上传扫描件 → 提取字段 → 与公示比对"这条流程。真实作业时上传供应商给的影像，按 `references/ocr-extract-schema.md` 录入。
