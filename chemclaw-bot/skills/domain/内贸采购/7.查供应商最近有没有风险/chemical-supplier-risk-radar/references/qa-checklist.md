# 交付前检查清单

按顺序打勾。任何一项 **STOP** 都不交付。

---

## A. 数据（最重要）

- [ ] `validate.py` 输出 `verdict: PASS`，没有 error。
- [ ] 供应商数、事件数、窗口计数与 `data.json` 一致。
- [ ] 每家供应商至少有一条结论；没有事件的供应商有“未检索到公开风险事件”说明。
- [ ] 每条事件 `date` 是**发生日期**，不是新闻发布时间。
- [ ] 每条事件有明确主体：公司/基地/产线/法人，不是“某集团”一笔带过。
- [ ] `fact` 只写可核事实；金额、产能、天数、负荷带单位。
- [ ] `why` 没有“将断供/必涨价/肯定停产”等推断；只写“可能影响/需确认”。
- [ ] 每条事件至少 3 个 `questions`，问题能直接问供应商。
- [ ] 每条事件有 `action`，是动作不是“关注一下”。
- [ ] `coverage_check` 六类齐全，明确“未检索到/待复核/渠道未覆盖”。
- [ ] 没有任何编造的企业、日期、金额、产能、财务。
- [ ] 非上市/未披露字段写“未披露/—”，不是 0 或空白。

**STOP**：发现一条编造事实、或把“未检索到”写成“无风险”。

---

## B. 来源与证据

- [ ] 每条事件 `url` 以 `http(s)` 开头。
- [ ] 随机抽 3 条点开：能打开，内容与 `fact` 对得上；打不开的已换链接或标“需登录/可能失效”。
- [ ] `evidence` 与实际来源匹配：公告/监管原文 A；媒体转述 B；论坛/聚合 C。
- [ ] C 级来源没有单独支撑“高风险”结论。
- [ ] `source_date` 与事件日期不矛盾；旧闻再版已识别。
- [ ] 同一事件多家转载只保留一条，来源选最接近原始的。
- [ ] `06_来源清单` 的链接数 ≥ 唯一来源数；没有空链接。

**STOP**：A 级来源点不开且没有替代；或媒体转述被标成 A。

---

## C. 覆盖与结论

- [ ] 六类都查过：工商、司法、处罚、安全环保、经营动态、重大股权变化（可并入工商）。
- [ ] 每类都有“查了哪些渠道”的记录，不只写“已排查”。
- [ ] `method.limits` 写清：非上市财务、地方公示、司法公开、付费库、时间滞后。
- [ ] 风险等级是采购视角标签，页面/Excel 有“不是信用评级”的说明。
- [ ] 没有把行业性亏损/检修直接归因于某一家。
- [ ] 结论能回答“买不买/续不续/要不要双源”，但不下绝对命令。

---

## D. HTML

- [ ] 双击能打开；无白屏；控制台无 JS error。
- [ ] 首屏：产品名、截止时间、供应商数、事件数、高/中/低、窗口正确。
- [ ] 切换 3m/6m/12m：计数变化正确；`chipEvents` 是总数，`chipInWindow` 是窗口数。
- [ ] 五个分类 pills 都能筛选/取消；计数与数据一致。
- [ ] 供应商下拉、关键词搜索、只看中高风险都生效。
- [ ] 点事件：弹窗有事实、why、来源、问题、证据等级；链接可点。
- [ ] 点供应商：弹窗有产能、财务（期间正确）、结论、覆盖、该供应商事件。
- [ ] 方法页：证据分级、六类覆盖、来源表、局限、免责声明都在。
- [ ] 打印预览：不截断、不显示按钮/筛选、事件卡不跨页。
- [ ] 手机宽度（375px）无横向滚动；长文本不溢出。
- [ ] 没有外部 CDN/字体/图片请求；断网可开。
- [ ] 没有 `%%...%%` 残留；没有 `undefined` / `NaN`。

---

## E. Excel

- [ ] 9 张表齐全，表名与顺序正确。
- [ ] 封面：产品、日期、默认窗口、供应商范围、事件总量、工艺、渠道、性质正确。
- [ ] `01_风险总览`：每家一行，合计行 = 窗口内事件数；风险色阶正确。
- [ ] `02_事件时间线`：事件数 = `data.events`；日期倒序；链接可点；长文本不压字。
- [ ] `03_分类汇总`：分类×严重度合计 = 窗口内总数；供应商×分类合计一致。
- [ ] `04_供应商画像`：财务期间 = `meta.financial_period`；非上市写“未披露”。
- [ ] `05_待核实清单`：P1/P2/P3 截止日按 query_date 推算，不是过期日期。
- [ ] `06_来源清单`：链接数 = 唯一来源数；无空行。
- [ ] `07_方法与口径`：六类覆盖、证据分级、局限、免责声明齐全。
- [ ] `08_行业背景`：2–4 条，来源/日期齐全。
- [ ] 冻结窗格、筛选、打印区域、列宽/行高正常。
- [ ] 打开无“修复”提示；无 `#REF!` / `#VALUE!`。

---

## F. 语言与边界

- [ ] 全文统一“未检索到公开记录”，没有“无风险/零风险/全面排查”。
- [ ] 全文统一“可能影响/需确认”，没有“必然/一定/将断供”。
- [ ] 数字单位统一（亿元/万元/万吨/吨），同比正负号正确。
- [ ] 公司名、证券代码、基地名一致；母/子公司不混。
- [ ] 免责声明包含：公开信息、滞后/遗漏、不构成法律/财务/投资意见、不替代尽调。
- [ ] 报告日期、数据截止时间、窗口边界一致。

---

## G. 文件与命名

- [ ] HTML 与 Excel 同一套 `name`，例如 `产品-2026-10.html` / `.xlsx`。
- [ ] 文件名不含 `/ \ : * ? " < > |`；中文可用。
- [ ] 交付目录只保留成品 + `data.json` + 生成脚本；没有 `_test` / `~$` / `__pycache__`。
- [ ] 如果附 PDF，注明由 HTML 打印还是 Excel 转换，版式可能不同。
- [ ] 给用户的说明包含：两个文件路径、窗口、供应商数、事件数、3 条最重要发现、3 个待确认问题。

---

## H. 一键命令

```bash
python scripts/validate.py data.json
python scripts/build_all.py data.json --out out --name 产品-2026-10
python scripts/qa.py data.json "out/产品-2026-10.html" "out/产品-2026-10.xlsx"
```

`qa.py` 通过只代表结构/注入/表数正确；**内容仍需人工抽检**（A/B/C 来源、事实与推断边界）。
