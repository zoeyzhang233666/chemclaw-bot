# 数据契约：input.json

一份 JSON 驱动两件套。**只改 JSON，不改产物**。字段只增不改，缺席字段由脚本补默认值。

- 唯一必填的是 `meta`、`dimensions`、`cases`；
- `materials` / `onsite` / `sources` 缺失时对应区块为空，但建议都填；
- 所有中文标点直接写，文件用 UTF-8（带 BOM 也能读）。

---

## 顶层

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema_version` | 建议 | 固定 `"1.0"`，不一致只告警不阻断 |
| `meta` | ✅ | 报告元信息 |
| `product_profile` | 建议 | 本产品的硬证据/伪证据/关键指标，决定方法适配 |
| `dimensions` | ✅ | 五个评分维度，权重合计必须 = 100 |
| `cases` | ✅ | 至少 1 个，建议 3—5 个 |
| `materials` | 建议 | 待索取材料清单 |
| `onsite` | 建议 | 验厂检查项 |
| `sources` | 建议 | 数据来源总表 |

---

## meta

| 字段 | 必填 | 示例 | 说明 |
|---|---|---|---|
| `report_id` | ✅ | `SV-2026-CN-NA2CO3-001` | 报告编号，页眉与 Excel 首行都会出现 |
| `as_of` | ✅ | `2026-10-19` | 判断时点，不是"最后一天查到资料" |
| `title` | ✅ | `纯碱供应商真伪核验` | 报告标题 |
| `product` | ✅ | `纯碱（碳酸钠 Na₂CO₃）` | 产品，含分子式更专业 |
| `product_spec` | 建议 | `轻质/重质；GB/T 210 Ⅱ类优等品` | 规格与标准 |
| `slug` | ✅ | `纯碱供应商真伪核验报告` | 输出文件名，不能含 `\ / : * ? " < > \|` |
| `lead` | 建议 | 一至两句 | 报告开头的引导语 |
| `h1` | 可选 | `查供应商是不是真厂家` | 默认即此句 |
| `disclaimer` | 建议 | 免责声明 | 页脚与 Excel 说明页 |

## product_profile

```json
"product_profile": {
  "category": "基础无机化工原料 · 非危险化学品",
  "regimes": ["排污许可证（行业类别：无机碱制造 C2612）", "环评批复 + 验收", "产能置换公示"],
  "not_evidence": ["营业执照经营范围", "官网“厂家直销”", "危化证（纯碱非危化品）"],
  "key_specs": ["Na₂CO₃ 含量", "氯化物", "粒度 / 堆积密度"],
  "note": "纯碱不是危化品，拿危化证判断厂家会错。"
}
```

| 字段 | 作用 |
|---|---|
| `category` | 品类与危化属性一句话 |
| `regimes` | **本产品什么算硬证据**；会渲染到 HTML 方法区、Excel 结论表 |
| `not_evidence` | 本产品最容易被误采信的材料，提醒自己不要归档错 |
| `key_specs` | 验货指标，写进索取清单 |
| `note` | 一句话行业提醒 |

## dimensions

```json
"dimensions": [
  {"name": "生产许可与环保手续", "weight": 30, "detail": "排污许可行业类别、环评/验收中的产品与产能……"},
  {"name": "产能与装置实据", "weight": 30, "detail": "……"},
  {"name": "产品与市场证据", "weight": 20, "detail": "……"},
  {"name": "运营侧痕迹", "weight": 10, "detail": "……"},
  {"name": "现场与第三方核验", "weight": 10, "detail": "……"}
]
```

权重合计必须 100；`cases[].dims` 的长度必须等于维度数。

## cases

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 英文/拼音短 id，用于 HTML 锚点与 JS，案例内唯一 |
| `company` | ✅ | 企业全名 |
| `short` | ✅ | 简称，用于标签与表格 |
| `unit` | 可选 | 分公司/基地/事业部 |
| `aliases` | 建议 | 检索用别名（股票代码、曾用名、品牌） |
| `product` / `spec` | ✅ | 该案例实际核验的产品与规格 |
| `verdict` | ✅ | **只能是**：`生产厂家` / `分装或复配` / `贸易经销` / `证据不足暂无法确认` |
| `confidence` | ✅ | `高` / `中高` / `中` / `低` |
| `score` | ✅ | 0—100，必须等于 `dims` 合计 |
| `dims` | ✅ | 五个整数，不超过对应权重 |
| `score_note` | 建议 | 2—3 句解释哪一维扣分、为什么 |
| `addr` | 建议 | 公开可查的厂址；查不到写"未披露" |
| `capacity` / `output` / `process` / `status` / `brand` / `listed` | 建议 | 关键事实，渲染成六张事实卡 |
| `headline` | ✅ | 一句话结论（说证据结构，不复述结论） |
| `verdict_detail` | ✅ | 3—5 句推理 |
| `facts` | ✅ | 六组 `["字段", "值", "注释"]`，少一条版面会不齐 |
| `direct` / `indirect` / `excluded` | ✅ | 三组证据数组 |
| `timeline` | 建议 | `[["2020-08", "事件", "备注"], ...]`，按时间正序 |
| `gaps` | ✅ | 3—6 条索取清单，按"能否独立证明装置"排序 |
| `next_action` | ✅ | 合作方式 + 一条风控动作 |
| `synthetic` | 建议 | `true` 表示脱敏/合成样例，页面会加警示条 |

## evidence（三组共用）

```json
{
  "code": "D1",
  "cat": "许可与环保",
  "strength": 3,
  "title": "排污许可证载明“无机碱制造”",
  "source": "潍坊市生态环境局 · 排污许可信息公开",
  "date": "2026-03",
  "url": "https://...",
  "quote": "行业类别：无机碱制造；生产经营场所地址：……",
  "why": "为什么它算证据（或为什么不算）"
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `code` | ✅ | 案例内唯一，建议 `D1…` / `I1…` / `X1…` |
| `cat` | 建议 | 四类：`许可与环保` `产能与装置` `产品与市场` `运营痕迹`；排除项留空 |
| `strength` | ✅ | `3` 强 / `2` 中 / `1` 弱 / `0` 不计分；**排除组必须为 0** |
| `title` | ✅ | 一句话说清这条证据证明了什么 |
| `source` | ✅ | 机构 + 文件类型；拿不到链接写"对方提供" |
| `date` | 建议 | 尽可能精确到月 |
| `url` | 建议 | 必须 `http(s)://` 开头；没有就留空并降级 |
| `quote` | 建议 | 原文摘录，保留数字与单位；不要改写 |
| `why` | ✅ | 采信或排除的理由，这是报告的灵魂 |

**硬规则**：
- 判 `生产厂家` 的案例，`direct` 不能为空；
- `excluded` 里任何一条 `strength` 不为 0，直接报错；
- 中/强证据没有链接 → 告警（合成样例豁免）；
- 同一案例内 `code` 重复 → 报错。

## materials

```json
{"id": "M1", "name": "排污许可证正副本", "priority": "P0",
 "purpose": "确认行业类别与装置在证", "look": "行业类别、主要生产设施、排放口",
 "script": "麻烦提供……", "scene": "所有供应商"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | `M1`、`M2`… 唯一 |
| `name` | ✅ | 材料名 |
| `priority` | ✅ | `P0`（不拿到不签约）/ `P1`（视场景）/ `P2`（合规参考） |
| `purpose` | ✅ | 核验目的 |
| `look` | ✅ | 关键看点（看哪几页、哪几个字） |
| `script` | ✅ | 可直接复制给业务员的话术 |
| `scene` | 建议 | 适用场景 |

建议 8—12 项，全部是**对方能提供**的材料；查公开数据库得来的东西不放进这里。

---

## onsite

```json
{"item": "厂址与门牌", "method": "不预约，导航到注册地址拍照",
 "pass": "门牌与许可地址一致", "fake": "写字楼或仅仓库"}
```

6—8 项，按"进门顺序"排：门牌 → 主装置 → 原料 → 包装 → 地磅 → 留证。

---

## sources

```json
{"id": "S1", "source": "巨潮资讯 · 公司 2025 年报", "type": "公告",
 "url": "http://static.cninfo.com.cn/...", "quote": "……"}
```

`type` 建议：`公告` / `官网` / `媒体` / `协会` / `交易所` / `标准` / `政府` / `第三方`。

## 最小可运行 JSON

```json
{
  "schema_version": "1.0",
  "meta": {"report_id": "SV-001", "as_of": "2026-10-19", "title": "XX核验",
           "product": "XX", "slug": "XX核验报告"},
  "dimensions": [
    {"name": "生产许可与环保手续", "weight": 30, "detail": ""},
    {"name": "产能与装置实据", "weight": 30, "detail": ""},
    {"name": "产品与市场证据", "weight": 20, "detail": ""},
    {"name": "运营侧痕迹", "weight": 10, "detail": ""},
    {"name": "现场与第三方核验", "weight": 10, "detail": ""}
  ],
  "cases": [{
    "id": "c1", "company": "XX有限公司", "short": "XX",
    "product": "XX", "spec": "XX", "verdict": "证据不足暂无法确认",
    "confidence": "低", "score": 0, "dims": [0,0,0,0,0],
    "headline": "……", "verdict_detail": "……",
    "facts": [["生产地址","未披露",""],["公开产能","未披露",""],["资质","未提供",""],
              ["沟通","仅线上",""],["价格","待核",""],["建议","按未认证处理",""]],
    "direct": [], "indirect": [], "excluded": [],
    "gaps": ["……"], "next_action": "……"
  }]
}
```

跑 `python scripts/validate.py input.json` → `[pass]`。
