# 价格数据标准（采购侧）

> 采购和销售看价格最大的区别：**采购关心"我在这买、按这个方式提货、开这个票，多少钱"，一切口径不同的数字都不能拿来比。**

## 1. 六项口径（缺一项即不可比）

| 字段 | 名称 | 说明 | 典型错误 |
|---|---|---|---|
| `point` | 采购点 | 我实际提货/收货的地点或市场：具体罐区、交割库、产区、厂门口 | 用"华东"当采购点，实际太仓和常州能差 250 元/吨 |
| `spec` | 规格 | 执行标准 + 等级 + 关键指标（纯度、水分、色度、牌号） | "甲醇 99.9%"与"合格品"混用；食品级与工业级混用 |
| `lo` / `hi` | 价格区间 | 原文给出的低价/高价；单点报价则两者相同 | 把区间中值当成交价；把最高价当市场价 |
| `tax` | 含税与否 | 含税（13%/9%）/ 不含税 / 未明确 | 含税价与不含税价直接相减 |
| `basis` | 提货方式 | 出厂（厂提）/ 送到（到厂）/ 罐区库提 / CFR / FOB | 出厂价与送到价相减，得出"地区溢价" |
| `date` | 数据日期 | 该报价对应的日期（不是文章发布日期） | 用"上周三"当日期；用发布日当报价日 |
| `src` | 来源 | 可点开的原始出处 | 用"某资讯"当来源 |

**额外字段（强烈建议填）**
- `quote_kind`：报价类型 —— 罐区现货报价 / 指数口径 / 厂商挂牌 / 竞拍成交 / CFR 到岸。
- `tier`：市场 / 产区 / 厂商 / 进口 / 指数。
- `conf`：高 / 中 / 低，并说明为什么（如"单一媒体转述"）。

## 2. 报价类型可信度排序（采购谈判时的引用次序）

1. **竞拍成交价 / 平台成交记录** —— 真实成交，最硬。可用于压供应商挂牌价。
2. **罐区现货成交区间**（资讯商日评）—— 反映当期成交，适合当"市场价"。
3. **厂商挂牌价（出厂价）** —— 只是报价，不一定成交；下滑行情中往往滞后且偏高，上涨行情中常低于市场。
4. **指数/基准价口径**（如生意社基准价、某交易所交割结算参考）—— 由模型或加权算出，含调整系数，只能用于"趋势"和"内部结算"，不能当成交价对外引用。
5. **期货价格** —— 不含税、含交割成本、锚定特定交割地，**只能与同日同口径现货构成"基差"，不能当采购价**。

> 报告里同时出现 4 个数字（区间、指数、挂牌、期货）是正常的，前提是每个都写清口径。

## 3. 采集前的"采购点画像"（5 问）

1. 我实际在哪提货？（罐区名/工厂名/仓库）
2. 谁送货、谁付运费？（决定看到的是出厂价还是送到价）
3. 开什么票、几个点？（决定含税/不含税比较基准）
4. 单批多少吨？（单笔小单常比整批贵 50–200 元/吨）
5. 有没有长协/框架价？（长协价与现货价是两套体系，不能互相套用）

把答案写进 `procurement` 与 `meta`，报告首屏据此选择"锚价"。

## 4. 口径冲突的处理流程

发现两个数打架时，**不要二选一，也不要取平均**：

1. **先判是不是同口径** —— 日期不同？含税不同？提货方式不同？规格不同？点位不同？
2. **同口径不同来源** → 都列出来，注明各自来源与时点，在 `caveats` 里写清差异原因（如"取样时点""单笔 vs 整批"）。
3. **不同口径** → 分列，禁止相减；若必须给一个"参考"，明确写"仅作参考，不可直接引用为成交价"。
4. **无法判断** → 进 `gaps`，状态写 `口径冲突`，写清"为什么冲突"和"要先确认哪张样本表"。

### 典型冲突对（记住这几组，几乎每个品种都会遇到）

| A 口径 | B 口径 | 为什么不能比 | 正确做法 |
|---|---|---|---|
| 港口库存（资讯商甲） | 社会库存（资讯商乙） | 样本范围不同 | 分列两条，注明样本 |
| 期货收盘价 | 现货含税价 | 税、交割成本、交割地都不同 | 只看基差，且必须同日 |
| CFR 美元价 | 人民币罐区价 | 汇率、关税、增值税、港杂、罐租 | 换算成"进口到岸折算价"再比，并列明汇与税假设 |
| 厂商挂牌价 | 竞拍成交价 | 一个是报价一个是成交 | 两个都列，用成交价校准挂价 |
| 周度开工率 | 月度产量 | 频率与样本不同 | 分开陈述，不做同比互换 |
| 出厂价 | 送到价 | 差一个运费 | 给运费区间后写"含运费折算"，运价缺失就标缺口 |

## 5. 缺口登记的三要素

每条缺口必须能直接指导下一步动作：

- `item`：缺什么（"10-19 当日华东罐区区间价"）
- `detail`：为什么缺（"公开渠道只到 10-16；资讯商日评需订阅"）
- `impact`：对采购决策的影响（"锚价只能用 10-16，若当日已变动，首屏会滞后"）
- `fix`：怎么补（"订阅 X 日评，或每日 17:00 前抓取"）

**状态三档**：`缺口`（完全没有）、`口径冲突`（有数但打架）、`待更新`（有旧值待刷新）。

## 6. 数据新鲜度的硬规则

| 数据类型 | 可接受的最旧日期 | 超期处理 |
|---|---|---|
| 现货价格（锚） | 3 个自然日 | 在首屏加"距数据截止日已 N 天，下单前须当日询价" |
| 库存/开工 | 7 天 | 注明周度口径与发布日期 |
| 成本/利润 | 30 天 | 注明"成本模型按期更新" |
| 装置动态（检修/投产） | 按事件发生日 | 必须写事件日，不写"近期" |
| 政策/公告 | 按发布日 | 尽量给原文链接 |

## 7. 采集时容易踩的坑

1. **文章发布日期 ≠ 报价日期**。资讯商早晨发的是昨天的价，落到哪天必须看文中"较昨日"字样反推。
2. **"较上周"的基数不明**。能确定具体日期就确定，不能就标 `待更新`。
3. **区间价的中值不是市场价**。中值只用于画图和算分位，谈判引用必须给区间。
4. **单位陷阱**：元/吨 vs 元/千克 vs 美元/吨；千标方（kNm³）vs 标方（Nm³）；千度 vs 度。`routes` 里的 `unit` 必须显式写。
5. **同一厂家不同装置的报价合并**。一个集团多套装置价格可能不同，需要按装置名分开记。
6. **把"上次报价"当"最新报价"**。厂商挂牌价长期不动时，必须写"挂牌价未调整，成交可谈"。
7. **只用一家资讯商**。至少两家交叉验证；只有一家时 `conf` 标"中"并在 caveats 说明。

## 8. 与销售侧技能的差异（避免混用）

| 维度 | 销售侧（看产品近期行情） | 采购侧（本技能） |
|---|---|---|
| 主线 | 期货序列 + 现货锚 | **现货报价序列**（期货仅参考） |
| 关心 | 我能卖多少、客户会不会嫌贵 | **我买得贵不贵、能不能调货/进口替代** |
| 区域 | 客户所在区域 | **多个候选货源点 + 运费口径** |
| 成本 | 毛利（路线对比） | **原料成本可算、加工费缺口** |
| 事件 | 影响我的销售节奏 | **影响我能不能按时、按价拿到货** |
| 结论 | 报价话术 | **对价依据 + 缺口声明** |
