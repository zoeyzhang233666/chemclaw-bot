# 产业链识别：工艺路线自证法

> 本文件**故意不提供任何品种的现成上下游表**。因为在化工里，"谁是谁的上下游"完全由**工艺路线**决定，不同路线、不同地区、不同年代的企业，链是不一样的。给你一张表，你就会把它套到不该套的品种上。
>
> 你要做的是：对一个具体品种，用下面五步把链**推**出来，并留下证据。

## 1. 为什么不能用"行业常识"罗列

化工里最容易犯的四类错误：

| 错误类型 | 例子（抽象化） | 为什么错 |
|---|---|---|
| 同板块误连 | 把同一大类的两个产品当成上下游 | 同属一个"板块"不代表有物质流动 |
| 同装置误连 | 同一套装置产出的两个产品，互相当原料 | 联产/副产不等于消耗关系 |
| 替代品误连 | 把可替代的两个原料当成上下游 | 替代是竞争关系，不构成成本传导 |
| 区域误连 | 某地产业链成立，就推广到全国 | 物流半径与装置布局决定链是否真的通 |

判断标准只有一句：**A 的价格变动，能否通过"用量 × 价格"这条算术链条传递到 B 的成本里？**

## 2. 五步自证法

### 第 1 步：列出全部主流工艺路线
对目标品种，先回答"这个东西是怎么做出来的"：

```
路线名称 | 主原料 | 关键中间体 | 主要消耗（吨原料/吨产品） | 路线产能占比（%） | 代表性产区
```

- 一个品种通常有 2–4 条路线（例如以煤/油/气/生物质/副产为起点，或以不同中间体为起点）。
- 路线占比必须来自公开统计或企业披露；拿不到就写"未知"，**不要用"一般认为"**。
- 路线之间成本结构差异往往就是这个品种价格波动的根源。

### 第 2 步：为每条路线写单耗（这是自证的核心）
```
主原料 A  →  单耗 q_A (吨 A / 吨产品)
中间体 B  →  单耗 q_B
公用工程  →  电/蒸汽/水（能折就折，折不了就列缺口）
```

- 单耗来自：企业年报/招股书、行业设计规范、公开工艺资料、期货公司成本模型。
- **不同来源的单耗要分别标注**，不要混算。
- 单耗 × 当期原料价 = 原料成本；加工费缺失就**只算原料成本，不合计**（本技能脚本严格执行这一点）。

### 第 3 步：往下游推（只看真实消耗）
对每个下游，回答三问：

1. **它把目标产品当原料参与哪个反应/配方？**（如氧化、酯化、烷基化、溶解、掺混）
2. **单耗多少？**（吨产品耗多少目标产品）
3. **它占目标产品总需求的多少？**（占比决定价格弹性）

占比 < 5% 的下游可以列但不必展开；占比最大的 1–3 个下游必须展开到开工率与产品价格层面。

### 第 4 步：区分"直接"和"间接"
- **直接**：目标产品是它的原料（成本项）。
- **间接**：影响终端需求节奏（如房地产竣工之于建材、油品价格之于调油组分）——只能作为"需求氛围"描述，不得算进成本传导。
- **同向竞争**：可替代品，价格高度相关但无消耗关系，**只能放"替代"栏，不能放上下游**。

### 第 5 步：写进 `chain_proof` 并逐条核对
```json
{
  "relation": "原料→产品",
  "from": "A（产地/牌号）",
  "to": "目标产品",
  "ratio": "1.55 吨/吨（工艺参数）",
  "share": "占该路线产能 XX%（口径：某机构 2025 年统计）",
  "evidence": "A 经 X 反应生成合成气/中间体后合成目标产品，属同一工艺路线；价格同步变动可由 Y 报告佐证。",
  "src": "某期货公司 2026-10-16 日报：A 价 XXX、该路线利润 XXX",
  "checked": true
}
```
`checked:false` 的含义：**关系成立但我拿不到中间证据**（典型是缺运费、缺税费、缺船期）。这类链路在报告里标红，并明确"其数字不可对外引用"。

## 3. 断点在哪：采购最常缺的三类中间证据

| 断点 | 缺什么 | 影响 | 怎么补 |
|---|---|---|---|
| 产区 → 销区 | 同期运价（汽运/铁水联运） | 价差无法拆成"运费+升贴水"，不能判断套利窗口 | 向 2 家物流商询吨公里价；或用地方物流指数 |
| 进口 → 国内 | 汇率、关税、增值税、港杂、罐租 | 进口折算价不可比 | 用当期汇率+明确税率假设，写清假设 |
| 装置 → 产量 | 检修损失量、开工率 | 事件影响量级说不清 | 装置产能 × 检修天数 × 开工率，注明这是估算 |

## 4. 单耗单位换算（脚本已内置）

`common.ROUTE_UNITS`：

| 输入单位 | 折算到"每吨产品"的系数 |
|---|---|
| 吨 / t / ton | 1 |
| 千吨 / kt | 1000 |
| 标方 / Nm³ / normal_m3 / 方 | 0.001（即 1000 方 = 1 千标方） |
| 度 / kWh | 0.001（按千度计） |

写 `routes` 时，`qty` 用"每吨产品耗多少该单位"，`unit` 按上表写法，脚本自动折算并标单位。

## 5. 下游需求弹性的判定（采购最需要的一段）

对每个主要下游，判断它对原料涨价的**接受能力**：

| 信号 | 含义 |
|---|---|
| 下游产品价格同步上涨 | 能传导，原料涨价的承接力强 |
| 下游产品价格不动甚至下跌 | 无法传导，下游会减产/停车 |
| 下游开工率下滑 | 需求实际在退（比价格更早） |
| 下游装置集中检修/停车 | 需求短期塌陷，通常伴随原料价格回落 |
| 下游新增产能投产 | 需求增量，通常支撑原料 |

把这些写进 `downstream[].logic`，并用当期开工率/产品价格数字支撑。**不要写"预计需求将…"**，只写已经发生的。

## 6. 自证清单（每条链都过一遍）

- [ ] 目标产品在该路线中确实是**原料**，不是催化剂、溶剂或副产物。
- [ ] 单耗有出处，且单位正确。
- [ ] 该下游占需求的比重有出处（或明确标"未知"）。
- [ ] 价格传导路径能写成一句算术（"原料涨 100 元 → 成本涨 155 元 → 产品价需涨 X 元才能覆盖"）。
- [ ] 中间证据（运价/税费/船期）是否有；没有就 `checked:false`。
- [ ] 是否混入了替代品或同板块无关品种？有就删。

## 7. 一个抽象例子（说明"怎么推"，不代表任何真实品种）

假设目标产品 P 有两条路线：

- 路线甲：原料 R 经气化 → 合成气 → P，单耗 1.6 吨 R/吨 P，占产能 70%
- 路线乙：原料 G 经转化 → 合成气 → P，单耗 1000 标方 G/吨 P，占产能 25%
- 路线丙：副产气回收 → P，占产能 5%

下游：
- 下游 D1（消耗 2.9 吨 P/吨 D1，占需求 55%）
- 下游 D2（0.45 吨 P/吨 D2，占 15%）
- 下游 D3（0.55 吨 P/吨 D3，占 12%）
- 其余分散（18%）

则自证表应写 5 条（R→P、G→P、P→D1、P→D2、P→D3），每条都有单耗、占比、证据。**"R 与 G 之间"不是上下游关系**，它们是同一产品的不同路线，互为竞争，不能连。

> 换到你的品种，把 R/G/D1/D2/D3 换成真实名字即可。链是推出来的，不是查表查出来的。
