# 结果呈现规范（HTML + Excel）

> 呈现的目标不是"好看"，而是**让一个没做过这个品种的人，在 90 秒内知道：现在多少钱、算贵还是便宜、凭什么、还缺什么**。

## 1. 首屏四件事（缺一不合格）

| 元素 | 必须包含 | 不合格示例 |
|---|---|---|
| 当前价（锚） | 数值 + 单位 + 日期 + 含税 + 提货方式 + 来源 | "甲醇 4000 元/吨" |
| 历史位置 | 分位 + 区间 + **样本数** | "分位 96%（不写样本数）" |
| 一句话现状 | 由脚本拼接的事实句，不含判断 | "市场看涨情绪浓厚" |
| 最大缺口 | 第一条 `缺口` 状态的项 + 影响 | 缺口全藏在附录 |

外加三条不可协商的标识：**数据截至日**、**"不预测价格"**、**口径提醒入口**。

## 2. HTML 结构（10 节，顺序固定）

| 节 | 内容 | 关键交互 |
|---|---|---|
| 顶部 | 标题、口径 pill 行、一句话现状、缺口警示条 | — |
| 吸顶控制条 | 采购点选择、时间窗（30/90/180/365/全部）、导出、带入沟通 | 点击即重算全部依赖图表 |
| KPI 卡（4–8 张） | 锚价 / 90 天分位 / 7 或 30 天变动 / 库存可支撑 / 同期价差 / 成本参考 | — |
| 01 价格走势 | 区间带 + 中值线 + 事件点 + 成本参考线 | 三种模式（区间带/蜡烛/多点对比）、事件点可点开抽屉、时间窗切换 |
| 02 区间涨跌与分位 | 两张表（涨跌表带基准日与样本；分位表带低高点日期） | — |
| 03 各采购点报价 | 六项口径逐条 + 报价类型 + 可信度 | 按日期倒序 |
| 04 区域价差 | 价差表（同日比较）+ 多点对比图 | 标注"当前货源/备选" |
| 05 成本拆解 | 成本线柱状图 + 工艺路线单耗表 | 分项不全时显式写"未合计" |
| 06 产业链自证 | 上游列表 / 下游列表 / 断点自证表 | 未通过标红 |
| 07 库存与开工 | 指标表（含口径与样本） | — |
| 08 事件时间线 | 类型过滤 + 事件卡 + 未采纳消息区 | 点卡片开抽屉（当时发生了什么/之后/对采购的含义） |
| 09 可用事实与沟通 | 事实卡 + 三套话术（微信/邮件/价格问询）+ 供应商问答 | 一键复制 |
| 10 缺口与来源 | 缺口卡（含影响与补齐路径）+ 口径提醒 + 可点来源 | — |

**样式铁律**
- 零外链：ECharts 内联，无 CDN、无外部字体、无 fetch。双击即开。
- 深色底 + 高对比数字；红=上涨、绿=下跌（国内习惯），颜色不是唯一信息载体（同时给符号与数值）。
- 表格在小屏改为横向滚动，不压缩字号；图表在窄屏降低高度。
- 单个 HTML 目标体积 ≤ 1.3 MB（含 ECharts）。

## 3. Excel 结构（12 表，顺序固定）

| 表 | 内容 | 谁用 |
|---|---|---|
| 00_封面与结论 | 一句话结论 + 指标卡 + 使用前必读 + 阅读顺序 | 老板/审批 |
| 01_现货报价明细 | 六项口径全字段，一条一行 | 核对、引用 |
| 02_报价序列与走势 | 每采购点一段序列 + 内嵌走势图 | 复核 |
| 03_区间涨跌与分位 | A 涨跌（带实际天数/样本）B 分位（带低高点日期） | 判断贵不贵 |
| 04_区域价差 | 同日价差表 + 多点对比数据与图 | 调货 |
| 05_上游成本拆解 | 上游价格 + 成本线 + 工艺路线单耗（合计/未合计） | 成本 |
| 06_下游需求与开工 | 下游列表 + 断点自证表 | 需求 |
| 07_供给库存与开工 | 库存/开工/进口/到港 | 供给 |
| 08_事件时间线 | 事件全字段 + 未采纳消息区 | 复盘 |
| 09_可用事实与话术 | 可引用事实（含锚价行）+ 供应商问答 + 我的采购参数 | 沟通 |
| 10_缺口与来源 | 缺口（状态分色）+ 可点超链接来源 | 交付 |
| 99_方法与字段口径 | 算法说明 + 禁用事项 | 审计 |

**格式铁律**
- 冻结前 3 行；表头深色底白字；数字右对齐用等宽字体；百分比用 `0.00%` 格式（存小数不存字符串）。
- 缺口必须写字（"缺口"或具体原因），不留空单元格。
- 未通过核对的链路整行标红。
- 每一行都要能回溯：备注列写口径，来源列写机构+日期。

## 4. 文案规范

| 场景 | 写法 | 反例 |
|---|---|---|
| 价格 | "3,983 元/吨（2026-10-16，含税现汇，罐区自提）" | "约 4000" |
| 变动 | "较 10-09 的 4,880 回落 18.85%（6 个交易日内 5 个报价点）" | "大幅下跌" |
| 分位 | "近 90 天 50% 分位（8 个报价点）" | "处于历史高位" |
| 缺口 | "10-19 当日罐区区间价：缺口（资讯商日评需订阅）" | "数据待补" |
| 事件 | "10-18 某装置停车（公开报道，产能 X 万吨/年）" | "装置扰动频繁" |

**"较""同期""之后"是安全词；"将""预计""有望""或将""建议"是危险词。**

## 5. 沟通话术的生成规则

三套模板（微信 / 邮件 / 价格问询），共同规则：

1. 只出现已发生事实 + 我方需求参数；
2. 每个数字后面括号内带日期与口径；
3. 必然包含"以上为已发生的公开报价，不含对后市的判断"这类声明；
4. 邮件版必须要求对方回：规格标准、含税、提货方式、结算账期、可供量、最迟发运；
5. 价格问询版必须问"数据日期与来源"，把对方的报价也变成可核验数据。

## 6. 可访问性与转发

- 报告要给"截图也能看懂"的段落：KPI 卡、事件卡、事实卡都自包含（不依赖上下文）。
- 每个抽屉/卡片都带来源行，便于被截屏后仍可追溯。
- 提供"导出当前视图数据"按钮，导出 CSV 供对方复算。
