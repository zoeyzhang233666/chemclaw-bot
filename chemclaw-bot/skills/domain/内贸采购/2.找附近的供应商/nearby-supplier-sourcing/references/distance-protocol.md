# 距离口径：直线、公路、降级与展示

## 1. 两个距离都要给

| 口径 | 算法 | 用途 | 误差来源 |
|---|---|---|---|
| 直线 | haversine | 客观基准，不受路网/封路影响 | 坐标精度 |
| 公路 | OSRM 路径规划 | 真实可跑里程，用于筛半径 | 路网时效、坐标 |

**只给一个数是不合格的**：只给直线会低估山区/绕行（天津—邢台 直线 352、公路 428，
差 21%）；只给公路则无法发现路径异常（例如绕行系数 >1.6 通常是坐标错了）。

## 2. haversine

```python
R = 6371.0088
dlat = lat2 - lat1; dlon = lon2 - lon1
a = sin(dlat/2)^2 + cos(lat1)*cos(lat2)*sin(dlon/2)^2
d = 2 * R * asin(sqrt(a))      # km
```

## 3. OSRM（首选）

```
http://router.project-osrm.org/route/v1/driving/{lon1},{lat1};{lon2},{lat2}
    ?overview=simplified&geometries=geojson
```

- 返回 `distance`(m)、`duration`(s)、`geometry`(路径点) —— 路径点直接给 HTML 画线
- 公共 demo 服务器有速率限制：串行请求，每次间隔 ≥1 s，14 家约 20 s
- 商用/内网部署可换自建 OSRM 或高德/百度/腾讯路径 API（返回结构不同，改
  `compute_routes.py` 的 `osrm()` 一个函数即可）

## 4. 降级方案（网络不可用时）

| 地形 | 系数 | 说明 |
|---|---|---|
| 平原/高速直达（长三角、华北平原） | 1.15–1.20 | 路网密、直线接近里程 |
| 丘陵/需绕行 | 1.22–1.30 | 如冀南—天津、鲁中 |
| 山区/跨江跨海 | 1.30–1.40 | 秦岭、西南、跨海 |
| 戈壁/矿区 | 1.20–1.35 | 路网稀疏但可直线走 |

使用降级时：`road_km = straight_km × factor`，并在 dataset 的
`item.distance_note` 与 HTML 距离页标注 **"估算（无路网数据）"**，
`distance_source` 字段写 `estimated`。**绝不能假装是路径规划结果。**

## 5. 半径筛选用哪个

用**公路里程**筛（`road_km <= ring`），因为要回答"能不能当天到"。
同时展示直线，避免用户误以为直线是实际里程。

边界案例要保留并解释：某企业 505.6 km，在 500 档被筛掉——这本身就是有价值的信息
（"刚好在边界外，值得单独议价"），在示例里显式说明这项规则。

## 6. 坐标精度分级

| 精度 | 误差 | 写法 |
|---|---|---|
| 厂门/库门 | ±0.5 km | "厂区大门定位" |
| 园区中心 | ±2–3 km | "园区中心点近似" |
| 区县中心 | ±8–15 km | "区县中心，未定位到厂区" |

`coord_note` 必填。区县级坐标算出来的 500 km 边界可能整体偏移 ±15 km，
所以**半径筛选结论的表述要留余地**（"约 500 公里内"）。

## 7. 在途时间

`hours = duration / 3600`（OSRM 平均车速），只是**纯行驶时间**。
页面必须注明"不含装卸、等待、过磅"，采购自行加 2–4 小时。
不要用它推算运费或承诺到货时间。

## 8. 多式联运怎么处理

铁路/水运不改变 M，也不硬算 L。做法：
- `road_km` 仍填公路口径（到最近发运点或按公路全程）
- 在 `action` / `mode` 里写"建议铁路整车，到站 XX，短驳 XX km"
- 缺口里写"铁路运费与站点未核实"

不要把铁路里程冒充公路里程，也不要把两者混在一个字段里。
