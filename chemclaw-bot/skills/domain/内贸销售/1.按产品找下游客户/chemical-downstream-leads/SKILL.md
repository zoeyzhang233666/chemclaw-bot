# 化工品下游需求工厂线索调研

把一个化工品的「下游应用结构」翻译成一张**按板块 × 省市 × 品类切开、每条都带可点开出处**的电话表。

适用于任何化工品（SBS、柠檬酸、钛酸酯偶联剂、CMC、黄原胶、阻燃剂、成核剂……），方法与环境、机器无关。

整个 skill 只围绕一个词：**trace（出处）**——每条线索都有一条能点开、能在电话里复述的来源。

## 三条不可谈判的约束

1. **没有 trace 的线索，`来源` 写「未核实」、`置信度` 写「低」。** 猜一个像样的官网域名填进去，比留空有害得多——销售点进去是博彩站，整张表就废了。
2. **peer 不是客户。** 自己也生产该产品的公司是同行。交付时要**报出被剔除的同行名单**。
3. **子代理的上下文是易耗品。** 一次把大 JSON 读进上下文就会杀死这一格任务。**先落盘，再汇报。**

---

## 第 0 步：定契约（一次问全）

用一次提问问全三件事，都带推荐项：

| 要素 | 说明 | 反例 |
|---|---|---|
| **产品** | 名称 + 形态/牌号（线型/星型、食品级/工业级……） | 「化工品」太泛 |
| **地域** | 具体到国家/省/市，最好给出**产业集聚地** | 「全球」不可执行 |
| **交付物** | 默认「Excel 四表 + HTML 报告」 | — |

---

## 第 1 步：先画「应用地图」，不要先搜企业

**这是最容易跳过、但决定成败的一步。** 应用地图 = 这个产品被用在哪些行业、在哪个工序、量级多大。

### 1.1 怎么拿到应用结构

按可靠性排序：

1. **行业媒体/协会的市场分析文章**——常直接给「下游消费结构」百分比（例：某年 SBS 道路改性沥青 44.2%、鞋材 17.8%、胶黏剂 14.2%、防水卷材 12.0%、聚合物改性 10.1%）。**这是最值钱的一段话**，它决定你把预算投在哪些 lane。
2. **上市公司年报/招股书/评级报告**的「行业情况」章节——同上，且通常给出产能、价格、竞争格局。
3. **券商研报、行业协会年鉴、化工信息中心类刊物**。
4. **海关/统计局数据**——判断进口替代与出口去向。

找不到百分比也不要停：用「这个产品的物性 → 什么行业必须用它」自己推，并在表里注明「按工艺推导」。

### 1.2 产出：8–12 个 lane（= 行业板块）

每个 lane 写清**四要素**：

| 要素 | 要求 | 例子（某热塑性弹性体） |
|---|---|---|
| **用料逻辑** | 在**哪个工序**、起什么作用、掺量区间 | 「与基质沥青在胶体磨中剪切、发育罐溶胀发育，掺量 3.5%~5.5%」 |
| **用量强度** | ★1–5，按**单一工厂年用量**标定，写清口径 | 5★=千吨级/年；4★=百吨级；3★=数十吨级；2★=十吨级 |
| **产业集聚地** | 省市，决定第 2 步的省市轴 | 「山东潍坊（寿光/临朐）、江苏、浙江」 |
| **候选企业方向** | 5–8 家具名或具名类型 | 「××防水科技、××新型建材……」 |

### 1.3 别忘了两类容易漏掉的 lane

- **复配/再加工型**：把这个产品当**配方单体**，复配后转售（复配添加剂厂、母粒厂、改性料厂）。它们单户用量不大，但**户数多、粘性高**。
- **深加工型**：把这个产品做成**另一种形态**再卖（把粉体做成颗粒、把树脂做成膜、把弹性体做成粒料）。它们往往是大户。

> 完整模板与两个不同产品的示例见 [`references/industry-map.md`](references/industry-map.md)。

## 第 2 步：三维切分法（本 skill 的核心）

把整个市场切成三个**正交轴**，一条线索 = 一个交点：

```
        板块（用途轴）  ×  省市（地理轴）  ×  细分品类（工序轴）
        例：建筑防水         山东/寿光           SBS 改性沥青卷材
```

| 轴 | 回答什么问题 | 为什么必须有 |
|---|---|---|
| **板块** | 用在哪、找谁 | 决定检索词与话术；也是交付表的第一层分组 |
| **省市** | 去哪查 | 政务公开**按省市发布**，且产业高度集聚——同一板块在不同省的查法不同 |
| **细分品类** | 什么工序、量多大 | 同一板块内不同工序的用量能差一个数量级；也是报价与卖点的落点 |

### 为什么必须切

**因为检索本身是三维的。** 一条检索式 = `原料词 × 工序词 × 文件词 × 地域词`。不切分，你只能搜出泛泛的行业新闻；切分之后，每一格都有明确的查询词组合与明确的产出文件。

### 执行时的切分粒度

**一个格子 = 一个子代理任务 = 一个落盘文件。** 格子要小到「一个子代理能在有限上下文里跑完并落盘」：

```
leads_raw/<板块编号>_<地域拼音>.json      例：01_daolu_jiangsu.json
leads_raw/<板块编号>_<地域拼音>_b.json    同一格补量时用 _b/_h 后缀，避免覆盖
```

板块编号用两位数前缀（`01_`…`12_`），合并脚本按前缀归板块，**不要让子代理自己拼板块名**。

## 第 3 步：检索式设计（最值钱的技能）

### 3.1 四个词槽

```
<原料词>  ×  <工序/设备词>  ×  <文件词>  ×  <地域词>
```

| 词槽 | 怎么造 | 例子 |
|---|---|---|
| **原料词** | 本名 + 别名 + 牌号 + 上游形态 + 英文缩写 | `SBS` / `苯乙烯-丁二烯-苯乙烯嵌段共聚物` / `热塑性弹性体` / `充油料` / `TPS` |
| **工序/设备词** | 从第 1 步的「用料逻辑」里抠出来 | `胶体磨` `发育罐` `密炼机` `双螺杆造粒` `充油` `熔融共混` `增粘树脂` `接枝` |
| **文件词** | 哪种文件会写吨位 | `环评` `环境影响报告表` `受理公示` `拟审批` `竣工验收` `年用量` `t/a` `招股书` `可研报告` `产能` |
| **地域词** | 省 / 市 / 县，**写全称** | `晋江市`（不是「晋江」）`潍坊市` `寿光市` |

### 3.2 命中率最高的五类组合（按证据强度排序）

1. **`<产品> 环评 年用量 <地域>`** → 环评报告表的「原辅材料表」会**直接写吨位**（`SBS 1075 t/a`）。这是最强证据。
2. **`<工序设备词> 环评公示 <地域>`** → 项目标题里**往往不出现产品名**，必须用工序词才能捞到（例：搜「胶体磨 发育罐 环评」比搜产品名更能命中改性沥青厂）。
3. **`<产品> 改性剂/添加剂/助剂 环评报告表`** → 产品以助剂身份出现。
4. **`<公司名> 环评公示` / `<公司名> 年报 产能`** → 已知企业的定点核实。
5. **`<产品> 招股书/可研 <行业>`** → 上市公司扩产信息，能拿到行业级产能与单厂规模。

### 3.3 短缩写产品的消歧（SBS / PVC / CMC / PA 这类）

短缩写会被同名噪音淹没（`SBS` 会撞上电视台、商学院、拉链品牌）。对策按优先级：

1. **用全化学名**，或「中文名 + 英文缩写」双写；
2. **加行业共现词**（下游品名：`防水卷材`、`鞋底`）；
3. **地名写全称**；
4. **限定文件类型/站点类型**（`环评`、`公示`、`site:gov.cn`）；
5. **换渠道**（见 3.5）。

> **判据：如果同一查询返回的结果与行业无关，不要反复换措辞试同一个引擎——换渠道。** 一个渠道不行不代表没有这个信息。

### 3.4 渠道优先级

| 级别 | 渠道 | 强度 | 用途 |
|---|---|---|---|
| **A** | 政府环评/审批/验收公示、交易所公告全文检索、**全国排污许可类平台**、企业官网、行业协会 | 一手 | 直接当证据，并抄吨位 |
| **B** | 通用搜索引擎 | 二手 | **只用于发现 URL**，不作为证据 |
| **C** | 招标网/文库/百科/聚合站 | 三手 | 兜底与线索发现；写进来源时必须注明它是什么 |

**铁律：搜索引擎给你的是「线索」，不是「证据」。证据必须是你打开过、能看到公司名与数字的那个页面或 PDF。**

### 3.5 两条不依赖搜索引擎的通路（非常重要）

搜索引擎在不少网络环境里会退化或不可用，这时靠下面两条照样能铺开：

1. **政务门户栏目直爬**：
   `省生态环境厅首页 → 正则抽取地市局域名 → 抽含「环评/公示/审批/受理」的锚点 → 抓列表页 → 用行业词筛（不要用产品名筛标题）→ 下载 PDF 附件 → 抽文本 → 检索吨位`
   关键认知：**列表页标题里不会有产品名**，只有项目名；所以筛选要用**行业词 + 工序词**。
2. **许可证/名录类平台枚举企业池**：全国排污许可、生产许可、行业准入名单等平台可按**行业类别**筛出企业名单（省/地市/单位名称/行业类别），是极好的「企业池枚举器」——拿到名单后再回到通路 1 或企业官网定点核实。

> 查询词表、逐省栏目发现方法、PDF 取吨位的完整动作见 [`references/search-queries.md`](references/search-queries.md)。

## 第 4 步：扇出执行

- **一格一个子代理**，并发上限 **8**；起满就等一个结束再补。
- 每个任务书必须含**六件套**：
  1. 产品与用途；2. 本格的细分范围与候选企业；3. 可用渠道与**检索式模板**；4. 固定的 7 字段 JSON 格式；5. **落盘路径**；6. **上下文纪律**（抓取上限、每 N 条增量落盘、先落盘再汇报）。
- **失败不要原样重发同一个任务书。** 改成**枚举式任务书**：把候选企业名单（有股票代码就带上）直接写进任务书，禁止检索，限定「每家最多抓 1–2 个页面、总抓取 ≤30 次、每 5 条增量落盘」。
- **同一格补量时换文件名后缀**（`_b`、`_h`），不要覆盖已有产出；合并脚本会去重。

> 任务书模板（可直接复制改写）见 [`references/fanout-briefs.md`](references/fanout-briefs.md)。

## 第 5 步：证据分级与防伪

### 5.1 固定 7 字段

```json
{"公司":"","细分行业":"","省市":"","需求点":"","规模线索":"","来源":"","置信度":"高|中|低"}
```

- **需求点**：必须落到**具体工序**（在哪个设备、什么温度/掺量、起什么作用）。若为工艺推导，句中写明「按行业工艺推导」。
- **规模线索**：只写**原文数字**（`年产 X 万吨`、`X t/a`、`X 条生产线`、`年产能 X 万平方米`）。没有就写「未见公开数据」，并降置信度。
- **来源**：**你实际打开过的** URL。
- **置信度**：
  - **高** = 原文出现该产品名（或等价物）作为原料/助剂 **且**有数字；
  - **中** = 主营与工序强匹配，但原文没写产品名（需求点须标「按行业工艺推导」）；
  - **低** = 仅品类匹配、或规模缺失。
- **没有可点开的来源 → `来源`="未核实"、`置信度`="低"**；抓不到就**丢弃**，不要降级硬写。

### 5.2 peer gate（同行剔除）

**自己也生产该产品的公司是竞争对手，不是客户。** 交付前跑一遍：把行业内的主要生产商列成名单，逐条比对剔除；名单要写进交付报告。

同时要写**板块专属排除规则**并下发给子代理，例如：
- 「纯卷材厂」不算「道路改性沥青厂」（同一产品、不同用途）；
- 「基质沥青炼厂」不算「改性沥青厂」（没有改性装置）；
- 「纯贸易商/物流商/施工队」不算（除非自有生产装置）；
- 氢化/加氢牌号（SEBS）与本体（SBS）要分清，不能混算。

### 5.3 诚实标注（比"好看"重要）

来源是**栏目页/列表页/站内检索页/文库预览页**时，必须写明它是什么、为什么给不出直达页（例如「该栏目只渲染最新 10 条，条目直链无法固定取得；原文已抓取存档」）。**宁可写清楚，也不要伪装成直达页。**

> 评分细则、常见造假陷阱、用量强度标定方法见 [`references/evidence-and-grading.md`](references/evidence-and-grading.md)。

## 第 6 步：合并与去重

1. **公司名归一化**（去括号内容、去「有限公司/股份/集团」等后缀）后去重。
2. **重复时保留更好的一条**，排序依据：`置信度更高 → 来源是完整 URL → 来源更具体（更长/更深）`。
3. **板块名规范化**：子代理可能填成 `06_ 塑料改性` 这种带文件名前缀的值，会把统计表拆成两行——合并时必须清洗成标准板块名。
4. **用量强度与优先级用规则表算**，不要手写：`优先级 = 用量强度 × 2 + 置信度分`（高 3/中 2/低 0），≥11 高、≥9 中、其余低。
5. 合并脚本要输出**分布自检**：按板块、按省市、按置信度、按强度。

```bash
python scripts/merge_leads.py --dir <任务目录>
```

---

## 第 7 步：抽检（link gate）

- 对**全部来源，至少 ≥40 条**，逐条实抓：**是否可达** + **正文/PDF 是否出现公司主体名**。
- **区分两类失败**：
  - **反爬拦截 / 需人机验证 / 登录态** → 浏览器里其实能打开，标注「建议人工复核」，不算坏链；
  - **真空页 / 404 / 跳转壳 / 报错** → 真坏链。
- 结论写回 `leads.json` 的来源列（形如 `…（⚠链接抽检：正文未见公司主体名）`）。
- **常见坑**：URL 后面紧跟中文说明会被当成 URL 的一部分 → 抽检前先把「URL 与全角括号说明」之间补一个空格；瞬时网络抖动要**重试一次**再判失败。
- **目标：通过率 ≥90%。** 未通过的必须注明原因。

```bash
python scripts/qa_links.py --dir <任务目录>
```

## 第 8 步：交付

### 8.1 Excel 四表

| 表 | 内容 |
|---|---|
| ① 说明与行业地图 | 编制目的、口径（用量强度/优先级/置信度）、为什么是这个地域（数据来源）、行业地图、数据来源与核验方法、**已剔除的同行**、**未覆盖的缺口**、使用边界 |
| ② 客户线索总表 | 序号 / 板块 / 细分行业 / 公司 / 所在地 / 用量强度 / 需求点 / 规模线索 / 优先级 / 置信度 / 来源 |
| ③ 重点客户TOP | 仅「优先级=高」 |
| ④ 分布统计 | 按板块 / 按省市 / 按细分品类 / 按置信度 |

### 8.2 HTML 报告

同一份 `leads.json` 再渲染一份**自包含 HTML**（可离线双击打开、可筛选、可打印），用于阅读、评审与转发。比 Excel 更适合长文本与快速筛选。

```bash
python scripts/build_workbook.py --dir <任务目录>
python scripts/build_html.py    --dir <任务目录>
```

### 8.3 交付报告必须含四块（缺一不可）

1. **条数与分布**（板块 / 省市 / 品类）；
2. **置信度分级**，并说明「高」靠什么证据撑住（举 2–3 条真实例子，带吨位）；
3. **被剔除的同行名单**（具名）；
4. **未覆盖的缺口与负结果**（哪个板块/哪个省检索为零、为什么；哪些客户只能电话核实）。

> 表格列宽、说明页字段、HTML 结构、`skill_config.json` 格式见 [`references/delivery.md`](references/delivery.md)。

## 质量自检清单（交付前逐条过）

- [ ] 板块数 ≥8，且**每个板块都有线索**（薄板块要在缺口里说明）
- [ ] 每个省市都有覆盖，或**写明为什么没有**（负结果也是结果）
- [ ] 每条都有可点开来源，或明确标「未核实 / 低」
- [ ] 高置信度条目**确实**在来源原文里出现过产品名（抽样复核 5 条）
- [ ] 同行已剔除，名单可报
- [ ] 抽检通过率 ≥90%，未通过条目已注明原因
- [ ] 说明页写清：用量强度口径、置信度口径、时间点、地域范围、使用边界
- [ ] 表格里没有孤立数字（每个数字都能在来源里找到）
- [ ] Excel 与 HTML 的条数、分布完全一致

## 常见失败模式

见 [`references/failure-log.md`](references/failure-log.md)。最常踩的五个：

1. 子代理把大 JSON 读进上下文 → 上下文耗尽、中途崩掉（解法：增量落盘）
2. 政务栏目是 JS 渲染 → 静态抓取拿到空壳（解法：换栏目/换入口/换省市；找栏目自身的检索接口）
3. 文库站环评预览只放封面页 → 拿不到原辅材料表（解法：优先政府原始附件 PDF）
