# 失败模式与修法（按踩坑频率排序）

> 每条格式：**症状 → 根因 → 修法**。这些是在真实项目里反复出现的，不是理论。

## 1. 子代理中途崩掉 / 没有任何产出

**症状**：跑了几十分钟，目标 JSON 文件不存在，或只有 `[]`。
**根因**：把已有的大 JSON 读进上下文；或陷入无休止翻页；或反复重试同一个失效渠道。
**修法**：
- 任务书里写死「**找到 3 条就先落盘**，再继续补」「一条都没有也要写 `[]`」；
- 给「总抓取 ≤30 次」的预算；
- 崩了**不要原样重发**，改**枚举式任务书**（见 [`fanout-briefs.md`](fanout-briefs.md) 第四节）——把候选企业名单直接写进去、禁用检索、每家最多 1~2 页。

## 2. 整个板块一条都搜不到

**症状**：某板块 × 某省，换了若干查询都是 0。
**根因**：三种可能——① 该地区确实没有这个产业；② 该地区门户是 JS 渲染/需登录；③ 查询词都是产品名，而列表页标题里只有工序词。
**修法**：先按 ③ 换成**工序词**再搜一轮；再按 ② 换入口（省厅转发页、区县页、`行政审批局` 而非 `生态环境局`）；仍为零则按 ① 记入**缺口清单**（这本身是有价值的负结果）。

## 3. 政务栏目抓到的是空壳

**症状**：页面 200，但正文只有导航，没有任何项目条目。
**根因**：列表由 JS 异步加载（AJAX）。
**修法**：① 找该站自己的**检索接口**（表单里常有隐藏字段与 JSON 接口）；② 换到「受理情况 / 拟审批公示 / 竣工验收」等其它栏目；③ 换同级的区县站点；④ 换省厅的转载页。**不要在这一个页面上耗超过三次尝试。**

## 4. 文库站只有封面页

**症状**：搜到 `年产1200万平方米…环评报告书` 很诱人，点进去只看到封面和目录。
**根因**：文库平台对正文做了付费墙/JS 门禁。
**修法**：把文库页当**发现线索**用（拿到项目名与大致年份），回找**政府原始附件 PDF**（公示页面里的 `P020…pdf` / `W020…pdf`）。找不到就按「中」置信度写，并在来源里注明。

## 5. 搜索引擎"语义失真"

**症状**：搜 `改性沥青 环评公示 江苏` 返回的是「改性」这个词的词典页。
**根因**：某些网络环境下的搜索接口只按**查询的首个词**匹配，并且忽略 `site:` 之类限定符。
**修法**：**只试一次**。不灵就换渠道（政务门户直爬 / 名录平台枚举 / 企业官网）。不要换 13 种措辞反复试同一个引擎。

## 6. 短缩写被同名噪音淹没

**症状**：搜 `SBS` 返回电视台、商学院、拉链品牌。
**根因**：缩写歧义 + 搜索引擎按词匹配。
**修法**：用**全化学名**或"中文名+缩写"双写；加**行业共现词**；地名写全称。见 [`search-queries.md`](search-queries.md) 第三节。

## 7. 同一家公司被多个格子重复收录

**症状**：合并后表里出现两三条同名公司，或总数虚高。
**根因**：不同批次的子代理覆盖范围重叠（例：一个负责"江苏+浙江"，另一个负责"浙江"）。
**修法**：合并脚本**按归一化公司名去重**；重复时保留「置信度更高 → 来源是完整 URL → 来源更具体」的一条。补量时用 `_b`/`_h` 文件名后缀，**不要让两个子代理写同一个文件**。

## 8. 板块名/地域名不统一，统计表被拆行

**症状**：④ 分布统计里同一个板块出现两行（`塑料与聚合物改性` 和 `06_ 塑料与聚合物改性`）。
**根因**：子代理把自己任务名里的前缀一起填进了 `板块` 字段。
**修法**：合并时**强制规范化**——去掉 `^\d{2}[_、.．]` 前缀，并校验取值必须落在标准板块集合内，否则回落到文件名前缀对应的板块。

## 9. 地域越界

**症状**：表里混进了区域外的企业。
**根因**：候选企业是集团总部在外省，实际产能在区域内（或反之）。
**修法**：校验脚本检查 `省市` 是否在目标区域内；越界的逐条人工判断——**按"生产实体所在地"算**，并在规模线索里注明主体与基地的关系。

## 10. 来源是列表页/检索页，抽检过不了

**症状**：抽检报「正文未见公司主体名」。
**根因**：子代理只找到了栏目页或站内检索页，没拿到条目页。
**修法**：派一个**专职修复子代理**，把未通过条目的来源逐条换成条目页或 PDF 直链；确实找不到的，改写成**可追溯的说明**（发布单位 + 文书标题 + 索引号/文号 + 一句实话），**绝不编 URL**。

## 11. 抽检把好链接误判为坏链

**症状**：明明能打开的链接被判失败。
**根因**：① 来源字段里 **URL 后面紧跟中文说明**（全角括号），URL 被解析成"URL+中文"；② 瞬时网络抖动。
**修法**：抽检前把「URL 与全角括号」之间**补一个空格**；失败条目**重试一次**再判失败。另外要区分：**反爬/人机验证/登录态**（浏览器能开，标"建议人工复核"）与**真空页/404/跳转壳**（真坏链）。
**还有一个隐蔽坑**：同一家公司在多个原始文件里带**不同的来源**，去重后留下的那条与抽检时那条不是同一个 URL，只按 URL 匹配会把抽检结论**漏标**。→ 合并脚本要**同时支持按公司名回退匹配**。

## 12. PDF 抽出来的文本字母被拆开

**症状**：明明有 SBS，检索却命中 0。
**根因**：PDF 表格逐字排版，抽文本后变成 `S BS`、`1 0 7 5 t / a`。
**修法**：检索一律用**容错写法**：`S\s*B\s*S`、`年\s*用\s*量`、`t\s*/\s*a`。这条能救回大量证据。

## 13. 数字张冠李戴

**症状**：把集团某个基地的产能安到了另一个主体头上。
**根因**：同一集团多主体、多基地，公开报道常混着写。
**修法**：数字必须与**主体**对应；跨主体引用时在需求点/规模线索里写明「该数字属其××基地」。不确定就换一条线索。

## 14. 同行混入

**症状**：表里出现了本产品的生产商。
**根因**：没跑 peer gate；或新增产能的项目名看起来像下游。
**修法**：每个任务书都带同行名单 → 交付前再跑一次全局比对 → **交付报告里具名报出**。见 [`evidence-and-grading.md`](evidence-and-grading.md) 第三节。

## 15. 为了凑数把"推导"标成"高"

**症状**：某板块全"高"，但抽检一堆失败。
**根因**：条数压力 → 降标准。
**修法**：**宁缺毋滥**是硬规则。能在表里如实写「中 / 按行业工艺推导」，比写一个假的"高"有价值得多——销售照着假证据打电话，比没有线索更糟。
