### 关于 HTML 报告的两级配置

| 级别 | 做法 | 适用 |
|---|---|---|
| **日常（推荐）** | 只维护 `skill_config.json`，四个脚本都读它；HTML 的标签、KPI、列定义、筛选选项全部由数据现算 | 绝大多数项目 |
| **进阶** | 在 `skill_config.json` 里加一个 `"html"` 键，覆盖 HTML 专属文案与标签（标题措辞、区块小标题、列名、KPI 卡说明等） | 需要精细控制报告文案时 |

两种方式共用同一份数据（`leads.json`），因此 **Excel 与 HTML 的条数、分布必然一致**。

### 脚本调用（统一以 `--dir` 指向任务目录）

```bash
python scripts/merge_leads.py   --dir <任务目录>     # 合并去重、规范化、算强度与优先级
python scripts/qa_links.py      --dir <任务目录>     # 抽检来源链接并写 _qa_report.json
python scripts/merge_leads.py   --dir <任务目录>     # 再跑一次，把抽检备注写进来源列
python scripts/build_workbook.py --dir <任务目录>    # 出 Excel 四表
python scripts/build_html.py    --dir <任务目录>     # 出 HTML 报告
```

## 三、Excel 四表结构

| 表名 | 内容 |
|---|---|
| ① 说明与行业地图 | 标题、编制目的、条数与覆盖、地域范围与理由、用量强度口径、优先级口径、行业地图表、数据来源与核验方法、**已剔除的同行**、**未覆盖的缺口**、使用边界 |
| ② 客户线索总表 | 11 列：序号 / 行业板块 / 细分行业 / 公司名称 / 所在地（省/市） / 用量强度 / 需求点（用产品的环节） / 规模线索 / 优先级 / 置信度 / 线索来源 |
| ③ 重点客户TOP | 同列，仅「优先级 = 高」 |
| ④ 分布统计 | 按板块 / 按省市（条数 ≥2）/ 按细分品类（归并后）/ 按置信度 |

格式约定：表头深底白字、冻结首行、总表加自动筛选、优先级列按档位填色、长文本列（细分行业/需求点/规模线索/来源）开自动换行并给足列宽。

## 四、HTML 报告结构

同一份 `leads.json` 渲染为**自包含单文件 HTML**（内联 CSS + 原生 JS，无任何外部依赖，可离线打开、可打印）：

1. **Hero**：产品名 + 副标题（地域/口径/时间）+ KPI 卡片（线索总数、高优先级、高置信度、覆盖板块、覆盖省市、来源可核验率）
2. **粘性目录**
3. **① 阅读说明**（口径与证据强度差异）
4. **② 行业地图**（表）
5. **③ 客户线索总表**（核心：关键词搜索 + 板块/省市/置信度/优先级筛选 + 只看高优先级 + 实时计数；窄屏自动变卡片；来源列自动识别 URL）
6. **④ 重点客户 TOP**
7. **⑤ 分布统计**（纯 CSS 条形图：板块 / 省市 / 置信度）
8. **⑥ 已剔除的同行**
9. **⑦ 未覆盖的缺口与负结果**
10. **页脚**（来源口径 + 生成时间）

```bash
python scripts/build_html.py --dir <任务目录>
```

## 五、交付报告（聊天里要说的四块，缺一不可）

1. **条数与分布**：总数、按板块、按省市、按品类；（可加一句与上一次交付的对比）
2. **置信度分级**：高/中/低各多少，并说明**"高"靠什么证据撑住**——举 2~3 条真实例子，**带吨位数字**；
3. **被剔除的同行名单**：具名列出（不要写"若干家"）；
4. **未覆盖的缺口与负结果**：哪个板块/哪个省是零结果、为什么；哪些客户只能电话核实。

**再加一段"下一步建议"**：建议人工复核哪些条目、外呼前补哪些信息（工商/联系人）。

```bash
python - <<'PY'

d = json.load(open("<任务目录>/leads.json", encoding="utf-8"))

PY
```

检查项：

- [ ] 总表行数 = 线索数 + 1
- [ ] HTML 行数 = 线索数
- [ ] Excel 与 HTML 的条数、分布一致
- [ ] 说明页四块齐全（口径 / 地图 / 同行 / 缺口）
- [ ] 没有占位符未替换（`{{...}}`、`None`、`nan`）
