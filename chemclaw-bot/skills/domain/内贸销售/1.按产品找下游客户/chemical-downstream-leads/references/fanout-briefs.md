# 扇出执行：任务书模板与崩了怎么办

## 一、并发与节奏

- **并发上限 8 个子代理。** 起满就先等一个结束再补下一个。
- 一个批次建议 **4~8 格**；按「板块 × 省市」切，优先切**百分比高的板块**。
- 每批跑完先合并一次看分布，再决定下一批补哪里（**不要一口气把 20 格全发出去**）。

## 二、任务书六件套（缺一件就会掉质量）

每份任务书必须含：

1. **产品与用途**（一句话，让子代理知道自己在找什么）
2. **本格范围与候选企业**（板块 + 具体到市的地域 + 5~8 家具名候选方向）
3. **可用渠道与检索式模板**（四词槽的具体查询串，至少给 5 条）
4. **固定 7 字段 JSON 格式**（原样贴出来，不要让子代理自由发挥）
5. **落盘路径**（绝对路径，精确到文件名）
6. **上下文纪律**（抓取上限、增量落盘、先落盘再汇报）

## 三、任务书模板（复制改写即可）

```text
你是<产品>的下游客户线索调研员。任务：找出<地域>境内**真正使用<产品>**的<板块>工厂。

【产品与用途】
<产品名>（<别名/缩写>），用于<一句话用途>。

【本格范围】
- 板块：<板块名，与落盘文件前缀一致>
- 地域：<省/市，逐个列出重点地级市>
- 目标条数：<N> 条（宁缺毋滥，但尽力凑够；尽量覆盖多个地级市）
- 候选方向（需自行核实，不要照抄）：<5~8 家具名或具名类型>

【检索式模板】（四词槽组合，照这个思路多换几组）
- `<产品> 环评 年用量 <省名>`
- `<工序/设备词> 环评公示 <市名>`      ← 列表页标题里不会有产品名，用工序词筛
- `<产品> 改性剂 环评报告表 <省名>`
- `<公司名> 环评公示` / `<公司名> 年报 产能`
- 短缩写被同名噪音淹没时：改用全化学名，或"中文名+缩写"双写

【可用渠道】
1) 政务门户直爬：省生态环境厅 → 地市局 → 「环评受理/拟审批公示」栏目 → 下载 PDF 附件
   （列表页用**行业词+工序词**筛，不要用产品名筛）
2) 许可证/名录平台按**行业类别**枚举企业名单，再逐家核实
3) 企业官网产品/产能页；上市公司年报/招股书
4) 通用搜索引擎：**只用于发现 URL，不作为证据**

【证据纪律】（违反即整条作废）
- 来源必须是你**实际打开过**、且正文/PDF 里能看到公司名的页面或 PDF；抓不到就丢弃，**绝不编 URL 和数字**
- 规模线索只能是原文数字（年产 X 万吨 / X t/a / X 条生产线 / 年产能 X 万平方米）；没有就写「未见公开数据」并降置信度
- PDF 表格里的字常被拆开（`S BS`、`1 0 7 5 t / a`），检索用容错写法（允许字间空白）
- 排除同行（本产品生产商）：<同行名单>
- 本板块专属排除：<如"纯卷材厂不算道路改性沥青厂">

【产出格式】写入绝对路径 <任务目录>\leads_raw\<NN>_<地域拼音>.json，UTF-8，JSON 数组：
[{"公司":"","细分行业":"","省市":"省/市","需求点":"","规模线索":"","来源":"https://…","置信度":"高|中|低"}]
- 需求点必须落到具体工序（设备、掺量、作用）；无原文佐证时句中写「按行业工艺推导」

【上下文纪律】
- 总抓取 ≤30 次；**找到 3 条就先写文件**，再继续补
- 一条都没有也要写 `[]`，不要不留文件
- 除目标 JSON 外不要改任何其它文件；临时文件放临时目录

【汇报】只回：文件路径、条数、置信度分布、每条一行摘要（公司 | 省市 | 一句话需求点 | 置信度 | 来源 URL）、哪些候选核实失败及卡点。
```

## 四、崩了怎么办（不要原样重发）

子代理常见崩溃模式：**把大 JSON 读进上下文**、**陷入无休止翻页**、**反复试同一个失效渠道**。

### 4.1 枚举式重开（首选）

把「检索」这一步去掉，直接给它名单：

```text
本任务**禁止使用任何搜索引擎**。下面是已经核实过的候选企业名单，你只做定点核实：
1. <公司全称>（<股票代码，如有>）
2. …
要求：
- 每家最多抓 1~2 个页面（优先：政府公示页 / 企业官网产品页 / 交易所公告）
- 总抓取 ≤30 次，每 5 条增量落盘一次
- 只写你确实看到公司与数字的条目；其余丢弃
- 输出格式与落盘路径：<同上>
```

### 4.2 缩小格子

一格太大（一个板块 + 半个中国）就拆成「一个板块 + 一个省」甚至「一个板块 + 两个市」。

### 4.3 降低目标

把「6~8 条」改成「3~4 条」，并要求**先把已确认的写下来**——产出比完美重要。

## 五、补量与命名

- 同一格要补量时，**换文件名后缀**：`01_daolu_jiangsu.json` → `01_daolu_jiangsu_b.json`（再来一轮用 `_h`）。
- **绝不要让第二个子代理写同一个文件**——后写的会覆盖先写的（这是最容易丢数据的方式）。
- 合并脚本按公司名去重，重复覆盖不会造成表内重复。

## 六、进度判断

- **什么时候可以停了**：连续两批新格子的"新增线索数"低于 5 条，且所有板块都已有覆盖 → 收口。
- **什么时候该放弃一格**：见 [`search-queries.md`](search-queries.md) 第九节（三条以上信号）。
- 放弃的格子**要记进缺口清单**，连同卡点原因（供交付报告使用）。

## 七、给子代理的"不要做什么"清单（有效降低返工）

- 不要调用不可用的检索工具反复重试（试一次不灵就换渠道）
- 不要把整份已有线索表读进上下文（要看分布就问合并脚本）
- 不要为了凑数写"按工艺推导"却标成"高"
- 不要改别人的落盘文件
- 不要用简称写公司名（必须完整工商名称，否则去重会失败）
