# 采购决策链分析（化工品内贸销售）

把"向某企业销售某化工品，该先找谁"这个问题，回答成一条**决策链**而不是一个人名。
本 skill 的两个核心资产：

1. **研究思路**（本文件 §2–§3）：证据先行 → 六步推导 → 标注推断；
2. **结果结构**（§5）：正文 = 角色链 + 部门卡；附件 = **Excel + 交互式 HTML（至少这两个）**。

> 跨环境使用：本文件遵循 agent-skills（SKILL.md）惯例。在不认识 frontmatter 的 agent
> （codex、自定义 agent 等）上，把本文件全文当作任务指令即可。需要可用的联网检索工具；
> 若无联网能力，改用用户提供的资料 + 模型知识，并把所有未核实项标注为"未核实/推断"。

## 0. 输入（模板填空）

```
我准备向【企业】销售【产品】，产品主要用于【用途/工序】，
属于【新导入 / 替换现有供应商 / 常规补充采购】。
```

- 任一字段缺失：先按产品推断典型下游客户并选一个真实企业做示范，向用户说明可替换；
- 用户补充了联系人、组织架构截图、历史沟通记录：在通用决策链上叠加"具体到人"的细化。

## 1. 研究流程（每个步骤的产出写进 chain.json 对应字段）

| 步骤 | 做什么 | 产出字段 |
|---|---|---|
| S1 企业核查 | 全称/性质（民营、国企、外资、集团子公司）/上市与否/实控人/规模/基地/主营/行业地位 | `meta` + `company_profile` |
| S2 采购模式 | 年报"采购模式"章节、投资者互动平台问答（采购方式、长协/招标）、新闻 | `company_profile` |
| S3 组织与岗位 | 招聘 JD（采购经理/采购员/化验员/工艺工程师）看职责、汇报线、集采关键词 | `company_profile` + `roles` |
| S4 技术权重 | 研发投入、专利（配方/工艺类）、认证体系 | `company_profile` |
| S5 成本地位 | 行业报告查单耗、原材料成本占比 → **估算年采购额**（单耗×产量×单价） | `company_profile` + `logic_chain` |
| S6 行业惯例 | 长协/框架占比、招标方式、账期、库存天数、认证周期、主流供应商 | `blocking_points` + `variants` |

检索词模板（按产品替换）：`{企业} 采购模式 年报`、`{企业} 招聘 采购经理 {产品}`、
`{企业} 投资者互动 {产品} 采购`、`{行业} {产品} 单耗 成本占比`、
`{行业} {产品} 采购 长协 招标 库存`。关键数字尽量两个独立来源交叉验证。

## 2. 六步判断逻辑（固化，逐步写进 `logic_chain`，每步标注 证据/推断）

1. **产品属性 → 采购类型**：大宗同质品 → 组织化集采、价格与保供驱动；技术/配方品 →
   研发主导、认证准入制；危化品 → 资质与安环前置。决定整个链的形状。
2. **金额 → 决策层级**：年采购额 = 单耗 × 产量 × 单价。千万级以上看集团/高管层；
   百万级部门负责人可定；十万级执行层即可。**金额量级决定拍板高度。**
3. **质量风险 → 守门员**：谁做入厂检验/认证/小试，谁握一票否决。同质品也怕批次波动。
4. **组织类型 → 老板的角色**：民营大集团 = 流程化、老板是助推器不是入口；中小民企 =
   老板即采购；国企 = 招标合规链、入口在采购部但节奏慢；外资 = 全球/本地采购 + 审计。
5. **供应格局 → 切入路径**：长协/框架为主 → 先进名录切现货再拿份额；独家供应 → 主打
   "第二货源"；完全市场化 → 比价即入。**没有缺口就创造窗口。**
6. **周期与时机 → 窗口**：跌价周期客户压价换供、涨价周期保供换供、新产线点火、
   长协到期前 1–2 个月、供应商事故/限产。

## 3. 角色链与部门卡

按 references/role-model.md 的角色库映射本企业：每个角色标注其在
**发起 / 评估 / 否决 / 拍板 / 执行** 中承担的职责，并生成部门卡，字段固定为：

```
编号 | 部门 | 岗位 | 职责(duties) | 是否第一入口 | 最关心的3个问题 |
先聊什么(opener) | 最值得确认的问题 | 依据(证据/推断) | 公开联系方式
```

第一入口的选择规则（详见 role-model.md §3）：**找"既管流程、又欢迎备选供应商"的角色**，
通常是集团/公司层面的大宗或品类采购负责人；老板层拍板但不做首触；技术守门员在采购
首肯后同步送样，不绕过采购。

## 4. 证据与红线（必须遵守，详见 references/evidence-rules.md）

- 每条关键判断标注 **证据**（带来源链接与日期）或 **经验推断 / 未核实**；
- 只输出**企业公开**联系方式（官网、总机、公开投资者热线、公开招聘邮箱）；
  **禁止**输出个人手机号、微信、私人邮箱等人对人的私人联系方式；
- 禁止编造人名、电话、指标数值；查不到就写"未核实"。

## 5. 产出契约（每次分析都完整交付）

1. **正文**：按 templates/report-template.md 的结构回复（填空设定 → 企业画像 → 判断逻辑
   → 角色链总览 → 部门卡 → 第一入口 → 卡点 → 场景变体 → 公开联系方式 → 证据vs推断清单）。
2. **附件（至少 Excel + HTML）**：
   - 按 templates/chain-data.schema.json 把分析结果填成 `chain.json`；
   - 运行：`python templates/build_deliverables.py <path>/chain.json [输出目录]`
   - 生成：`采购决策链-{公司}-{产品}.xlsx`（多工作表）与同名 `.html`（部门卡可点击、
     按职责筛选；企业/产品/场景信息在页首，可由上层平台继承上下文后替换）。
   - 无 Python 环境的降级路径：按 build_deliverables.py 内注释列出的工作表/分区清单，
     手工产出 CSV + 静态 HTML（部门卡用 `<details><summary>` 实现）。

## 6. 品类适配

不同化工品会改变决策链形状（技术权重、安环角色、认证环节），动手前先读
references/product-playbooks.md 确认本品类的调整项，再开始检索。

## 7. 示例

examples/soda-ash-kibing/：向旗滨集团销售重质纯碱的完整案例（chain.json + 生成的
xlsx/html），可作为 chain.json 填写质量的对照基准。
