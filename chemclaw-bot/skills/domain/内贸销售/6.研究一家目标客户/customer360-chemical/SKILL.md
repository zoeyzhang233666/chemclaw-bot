# 客户360画像（化工内贸销售 · 目标客户深研）

把一家目标企业研究成"销售可以直接拿去用"的一页画像：先回答销售最关心的三个问题，再给出证据与详细资料。研究思路固定、行业无关：**主体确认 → 销售 结论 → 四个分区（产品与工厂 / 项目与动态 / 采购关系 / 企业风险）→ 核实清单**，其中"采购关系"分区以用户自己的产品为视角做采购逻辑推断。

## 输入

开始前必须拿到（缺少就先问用户，不要猜）：

1. **目标企业名称**（哪怕不精确，允许"比如XX行业的XX厂"这类描述，由你先检索候选再确认）；
2. **用户自己销售的产品**（决定"它可能买什么、为什么买你"的判断口径；用户说不指定时，按通用采购品类出"通用版"，并在摘要中注明"待聚焦"）；
3. 可选：历史客户资料、CRM 导出、过往报价/沟通记录（有则优先采信并标注为内部资料）。

## 硬性边界（不可违反）

- **不输出**信用评级、授信额度、履约概率、违约概率或任何等价表述。风险只描述"公开事实 + 应对动作"。
- **先确认主体，再展开研究**：必须先锁定统一社会信用代码，列出同名/近名主体区分表（集团 vs 股份公司 vs 分公司 vs 子公司），防止查错、签错。
- **证据可溯源**：每个判断至少 1 条可点击来源（标题+日期+URL）；聚合平台（企查查/天眼查/爱企查等）数据必须标注"快照"及快照日期。
- **估算必须显式标注**：凡推算（如吨品耗原料 × 产能）一律标"估算"，写明计算口径，不得伪装成披露值。
- 完成后自查：全文检索"评级/授信/额度/概率"字样应为零；每条 status 为 ok/risk 的结论应有对应证据编号。

## 工作流

### Phase 0 — 明确输入
按上文"输入"收集公司名与销售产品；确认输出语言（默认中文）。

### Phase 1 — 主体确认
并行检索：`"{公司名} 统一社会信用代码"`、`"{公司名} 工商信息 法定代表人 注册资本"`、`"{公司名} 年报"`。
锁定：全称、信用代码、登记机关、法定代表人、注册资本、成立时间、上市信息（如有）。列出近名主体区分表。查询模板与陷阱清单见 `references/playbook.md` 第 1 节。

### Phase 2 — 七项核查（合规底盘）
逐项检索并记录状态（正常 ok / 待复核 warn / 关注 risk / 待办 todo）：
① 主体与经营状态（存续/注销/吊销、成立年限、迁址更名）② 注册资本与实缴、参保人数、股东与实控人、关联企业 ③ 实际业务（主营产品、生产地、公开产能、是否生产企业）④ 司法（被执行、失信、限高、买卖合同纠纷占比、涉诉金额）⑤ 经营异常、行政处罚、税务非正常、欠税 ⑥ 股权出质、动产抵押 ⑦ 近期负面舆情与停产。
查询模板见 `references/playbook.md` 第 2 节。

### Phase 3 — 业务与采购研究（画像的血肉）
- **产品与工厂**：主营产品与收入结构、生产基地与产线、公开产能、许可资质、产业链位置（上游原料→自身→下游流向）。
- **项目与动态**：近 18 个月的资本开支/技改/扩产/搬迁/参股/融资时间线，并**逐条翻译成"对用户产品的含义"**。
- **采购关系**（本 skill 的差异化价值）：用 `references/playbook.md` 第 4 节的"BOM 倒推 + 供应分层"方法，推断它对用户产品是否存在真实采购接口：需求量测算（标注估算）→ 供应三层结构（内供/长协/市场外购）→ 决策链推断 → 诚实结论（含"可能不是目标客户"的情况）。
- **销售结论**：三个问题各一段——是不是目标客户 / 可能买什么 / 为什么（需求逻辑链要带数字），外加一条风险横幅（含"给账期前必看"式动作建议）。

### Phase 4 — 固化数据
先读 `examples/README.md` 对照四个范例（真实大宗原料研究 / 直接原料正例 / "不是目标客户"反例 / 项目窗口期），理解判断口径后再动手；把全部事实按 `references/data-schema.md` 填成 `data.json`（每个区块内联 evidence 数组）。宁可字段留空，不要编造。

### Phase 5 — 生成交付物（Excel + HTML，均为必交）
```
python scripts/build.py data.json -o output/
```
产出：`客户360_{公司}_画像.html`（单文件交互式，点击展开证据）+ `客户360_{公司}_核查台账.xlsx`（≥10 个 sheet，含证据台账）。环境无 Python/openpyxl 时脚本自动降级为 CSV；完全没有执行环境时，按 `references/data-schema.md` 附录的"手工交付规格"直接产出等价文件，**结构与 sheet 划分不得增删合并**。

### Phase 6 — 回复与呈现
回复正文直接给出首屏摘要（三个问题 + 风险条 + 关键发现），随附 HTML 与 Excel 两个文件卡片。提醒用户：页面内估算数字需以年报原文与现场核实替换。

## 跨环境适配

- 本 skill 不依赖特定工具名：搜索/抓取用当前 Agent 可用的任何 web 工具；公告 PDF 抓不动时改用新闻稿、公告摘要页、交易所/巨潮检索页快照。
- 无 ask 用户能力的环境：把"输入"三项作为对话开场问题列出，等用户回复后再执行。
- 化工细分行业（农化/氟化工/锂电材料/涂料/聚合物等）可按 `references/playbook.md` 第 6 节扩展信息源，但七个分区与交付结构不变。

## 交付质量清单（发送前逐条勾选）

- [ ] 主体已确认，近名主体区分表在页面与 Excel 中均存在
- [ ] 首屏三问有结论、有数字、有证据
- [ ] 时间线每条都翻译了"对我的意义"
- [ ] 采购关系给出供应三层结构与决策链推断（推断标注"推断，需验证"）
- [ ] 七项核查完整，状态标记齐全，待复核项进入核实清单
- [ ] 估算全部显式标注口径
- [ ] 无评级/授信额度/履约概率表述
- [ ] Excel 证据台账编号与各 sheet 证据块一致
