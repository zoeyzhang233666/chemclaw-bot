# 案例 02 · 烧碱（山东）：查不到同口径报价时怎么办

这个案例演示**降级路径**——查不到可用的市场报价时，工具应该输出「无法验证」，
而不是编一个像样的市场价。

> ⚠️ **客户那句话是模拟的。**
> 「【模拟】山东这边32%液碱别家才800元/吨，你们报这么高？」
> **800 元/吨是测试输入，不是真实市场报价。**
> 本案例的真实情况是：**没有查到可用的同口径公开报价**。

---

## 一、输入：客户说了什么

```
【模拟】山东这边32%液碱别家才800元/吨，你们报这么高？
```

| 口径 | 客户说了 | 状态 |
|---|---|---|
| 数值 + 单位 | 800 元/吨 | ✅ |
| 规格 | 「32%液碱」 | ✅ |
| 地区 | 「山东」 | ⚠️ 太粗，需具体收货地 |
| 税费 | — | ❌ 未注明 |
| 交付 | — | ❌ 未注明 |
| 日期 / 来源 | 「这边」 | ❌ 既不是日期也不是来源 |

---

## 二、核验过程：为什么给不出结论

### 检索结果：两条线索，都不合格

| 编号 | 日期 | 来源 | 价格 | 问题 |
|---|---|---|---|---|
| SP-XH-0318-SD-RUMOR | 2026-10-18 | 行业群转述 | 800（点价） | ❌ 无原始页面，浓度/税费/交付全未注明 |
| SP-100PPI-1009-SD | 2026-10-09 | 生意社聚合页概要 | 860（点价） | ❌ 未标注税费与交付；距基准日 11 天 |

两条都被标记了 `exclude_reason`，**都没有进入主区间**。

### 按规则判定

`assemble.py` 拿不到任何可用的 `[low, high]` 区间，于是：

```
市场区间 = None
comparison.pos = "undecidable"
verdict = 无可靠市场数据，无法验证
```

### 报告里的表现

HTML 报告的三张图都显示明确的缺口说明，而不是画空图或假图：

| 图 | 显示内容 |
|---|---|
| 价格带图 | 「缺同口径市场报价，无法绘制价格带」 |
| 走势图 | 「无历史序列」 |
| 区域图 | 「无区域数据」 |

首屏 KPI 显示 `—`，不是 `0`，也不是任何估算数字。

---

## 三、结论

```
无可靠市场数据，无法验证

本次未查到 2026-10-20 山东 32% 液碱含税·到厂的可用公开日更报价，
因此本报告不给出市场参考区间，也不对客户所述的 800 元/吨做高低判断。

客户所述的 800 元/吨目前无法验证——不是因为它是错的，
而是因为缺少浓度、税费、交付、日期四项信息，任何比较都会建立在猜测上。
```

### 仍然给出的东西：确认清单

数据不足不代表什么都给不了。报告仍然给出 9 个要问客户的问题：

| # | 优先级 | 问题 |
|---|---|---|
| 1 | 高 | 800 是 32% 液碱吗？还是 50% 或其他浓度？ |
| 2 | 高 | 含税还是不含税？能开专票吗？ |
| 3 | 高 | 出厂还是送到？送到哪个厂？ |
| 4 | 高 | 哪天在哪看到的？能发截图或链接吗？ |
| 5 | 高 | 月用量多少？多久提一次？ |
| 6 | 中 | 槽车散装还是吨桶？ |
| 7 | 中 | 现汇还是承兑？账期多久？ |
| 8 | 中 | 要求离子膜法吗？执行什么标准？ |
| 9 | 低 | 还有别家在报价吗？ |

### 7 条数据缺口

包括：山东 32% 液碱当日公开日更报价、客户 800 的原始出处、浓度与工艺、
收货地与运输方式、近 3 个月历史序列、邻近地区报价、月用量与账期。

每条都写了「影响」和「补法」。

## 四、和案例 01 的区别

| | 案例 01（纯碱） | 案例 02（烧碱） |
|---|---|---|
| 市场数据 | 7 条报价，1 条主报价 | 2 条线索，0 条可用 |
| 历史序列 | 17 个点 | 0 个点 |
| 能否算偏离 | ✅ +275（+24.4%） | ❌ 无法计算 |
| 结论 | 明显偏高 | 无法验证 |
| 图表 | 3 张都正常渲染 | 3 张都显示缺口说明 |
| 首屏 KPI | `1,050–1,200 元/吨` | `—` |
| 价值在哪 | 给出价差与判断 | **说清楚缺什么、怎么补** |

**案例 02 才是最容易做错的**。很多工具在这个位置会：

- 拿那条 800 的群消息当"市场价" → 结论变成"客户说得对"
- 拿 860 的点价当区间 → 算出一个虚假的偏离
- 写"市场价约 800-860 元/吨" → 编造了一个不存在的区间

这三种都是把工具变成了猜测器。

### Excel 里的特殊处理

即使没有市场区间，Excel 的判定公式也不会乱来：

```excel
=IF(OR(下沿="", 上沿="", NOT(ISNUMBER(下沿)), NOT(ISNUMBER(上沿))),
    "无可靠市场数据，无法验证",
    ...其余判定...)
```

**这一条是必须的**：如果没有它，空的区间会被当成 0，
于是 800 会被判定为"明显偏高"——完全错误但看起来很正常的结论。

（这个 bug 是在自检阶段被 `check_xlsx.py` 抓出来的：
它跑降级案例时发现结论居然是"明显偏高"。）

## 六、这个案例教会我们什么

1. **查不到就说查不到。** 缺口是答案的一部分，不是失败。
2. **线索 ≠ 数据。** 群里的转述、聚合页的概要，没有六项口径就不能进主区间。
3. **"无法验证"仍然有价值。** 它告诉销售：这个价格你不该直接认同或反驳，
   该先去问那 9 个问题。
4. **空值很危险。** 程序里空的区间会被当成 0，必须在判定前先做「有没有数据」的检查。
5. **自检要覆盖失败路径。** 只测"数据齐全"的案例，永远发现不了这个 bug。
