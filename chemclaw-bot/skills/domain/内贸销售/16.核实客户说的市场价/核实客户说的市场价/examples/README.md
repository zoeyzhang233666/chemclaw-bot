## 每个案例里有什么

```
<案例名>/
├── README.md              # 输入 → 核验过程 → 结论 → 成品（人读的）
├── customer-message.txt   # 客户原话（模拟的带【模拟】）
├── research.json          # 研究数据（机器读的唯一来源）
├── build/
│   └── data.json          # 派生指标 + 计算过程
└── out/
    ├── *_报告.html         # 交互式报告
    └── *.xlsx             # 12 表 Excel
```

## 一个案例"完整"的标准

不是有提示词就叫完整。这四个都要有：

1. **完整输入**：客户原话（含模拟标注）+ 拆解出的口径 + 查到/没查到的市场数据
2. **核验过程**：来源、链接、口径、时间窗口、判定依据，逐步可追
3. **结论**：明确到什么程度（含前提和局限）
4. **成品文件**：能打开的 HTML + 能改公式的 Excel

## 两个案例的区别（为什么要有 02）

01 展示"数据齐全时怎么做"：有 7 条报价、17 个历史点，可以画图、算窗口、做地区对比。

02 展示"数据不全时怎么办"：只有两条口径不完整的报价，**不足以给出市场区间**。
这时候正确做法是：

- 结论写「无法验证」
- 不画价格带图（或画成空的并说明原因）
- 把缺什么、怎么补写清楚
- 照样给出确认清单，让销售知道该问什么

**这是最容易做错的地方**——很多人会在数据不足时"估一个大概"，
那就把工具变成了猜测器。02 就是为了把这条边界演示出来。

## 怎么做一个新案例

```bash
# 1. 复制一个最接近的
cp -r examples/01-重质纯碱-华东 examples/03-钛白粉-华南

# 2. 改数据
#    research.json 里改：meta、customer、spot、history、regions、
#    calibers、questions、facts、gaps
#    代码不用动——品种/地区/单位/税率全部来自数据

# 3. 校验 + 出报告
python scripts/validate.py examples/03-钛白粉-华南/research.json
python scripts/build_all.py examples/03-钛白粉-华南
```

### 改数据时的四个坑

| 坑 | 现象 | 解法 |
|---|---|---|
| `series_key` 没改 | 历史序列全空、价格带显示"样本不足" | 让 `meta.series_key` 与 `history[].spec` 一致 |
| 历史点 `point` 不等于区间中值 | 校验报警告 | 1050–1200 的中值是 1125，不是 1100 |
| 模拟消息没带【模拟】 | `validate.py` 直接 FAIL | 正文里必须出现「模拟」二字 |
| 客户价和市场价填成一样 | `validate.py` 判失败 | 这是"自证"，说明你可能把客户的话抄成了市场价 |
