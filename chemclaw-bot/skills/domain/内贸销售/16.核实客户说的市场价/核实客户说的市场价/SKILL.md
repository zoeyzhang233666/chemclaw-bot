# 核实客户说的市场价

## 这个 Skill 解决什么

销售报完价，客户回一句：

> 「现在市场才 1400，你们报价是不是太高了？」

这句话里其实藏着 5 个未声明的前提：**什么规格、哪个地区、含不含税、出不出厂、哪一天**。
这 5 个前提任意一个不同，1400 都可能"是真的"——但和你的报价不是同一个东西。

这个 Skill 做的事，就是把这 5 个前提一个个问出来、查清楚，最后给出一张
**同一把尺子下的价差表**：客户价 vs 市场区间，差多少钱、差多少比例，以及
**这个差距能不能下结论**。

它**不**做这些事（写死在流程里，也不能被要求放开）：

| 不做 | 原因 |
|---|---|
| ❌ 替你决定报多少、让多少 | 定价是销售与公司的决策，工具只给事实 |
| ❌ 判断客户在压价 / 在骗你 | 客户说的价可能真的来自别处，只是口径不同 |
| ❌ 把听来的个别成交当市场价格 | 无法核实的一手传闻不是市场，只能进「待核实」 |
| ❌ 把不同来源的报价做算术平均 | 来源、口径、时间都不同，平均出来的数不存在 |
| ❌ 缺运费/账期成本时硬折算 | 猜出来的运费会把结论带偏，必须显示「无法直接折算」 |
| ❌ 用固定百分比当"明显"的阈值 | "明显"的尺子是这份报价自己的区间宽度，不是 5% 或 10% |

## 八步流程

每一步都有对应的脚本或数据字段，**不许跳步**。

### 第 1 步 · 拆解客户这句话

把客户的话拆成六项口径，缺的就标「未说明」，**不要替他补**。

| 口径 | 客户说了吗 | 缺失时怎么办 |
|---|---|---|
| 数值 + 单位 | 必须 | 单位不是元/吨时，先问清换算关系 |
| 规格 / 纯度 | 常常缺 | 标「未细分」，在报告里高亮 |
| 地区 / 交付地 | 常常缺 | 标「未说明」 |
| 税费（含税/不含税） | 几乎总缺 | 标「未注明」，**不擅自加税** |
| 交付（出厂/送到/库提） | 几乎总缺 | 标「未注明」，**不擅自加运费** |
| 日期 / 来源 | 常常缺 | 「现在」不是日期，要问具体哪天、哪家平台 |

产物：`research.json` 的 `customer` 段。

### 第 2 步 · 查同日同口径的市场报价

**优先级顺序不能变**（越好越靠前）：

1. 同规格 + 同地区 + 同税费 + 同交付 + 同一天
2. 同规格 + 同地区 + 同税费 + 同交付 + 最近 3 天内
3. 同规格 + 邻近地区 + 同税费 + 同交付 + 最近 7 天内
4. 以上都没有 → **明确说无法直接比较**，不要拿别的口径凑一个数

每条报价必须凑齐：**数值 · 规格 · 地区 · 税费 · 交付 · 日期 · 来源 · 链接**。
缺任何一项，这条只能放「数据缺口」，不能进主区间。

具体去哪查、怎么判断来源可靠：见 `references/sources-playbook.md`。

### 第 3 步 · 算偏离金额与偏离比例

```
偏离金额 = 客户价 − 市场参考值
偏离比例 = 偏离金额 ÷ 市场参考值
```

市场参考值取**同一来源、同一天、同一口径**区间的中点，同时把
「相对上沿」「相对下沿」的差值都算出来，因为客户可能盯着上沿或下沿说话。

公式与注意事项：见 `references/formula-rules.md`。
对应字段：`data.json` 的 `comparison`。

### 第 4 步 · 判断接近 / 明显偏高 / 明显偏低 / 无法比较

**不用百分比阈值**，用这份报价自己的区间宽度当尺子：

```
半宽 = (上沿 − 下沿) / 2
```

| 情况 | 结论 |
|---|---|
| 落在 [下沿, 上沿] 内 | **接近市场参考区间** |
| 区间外、距最近端点 ≤ 半宽 | **略高于 / 略低于市场参考区间** |
| 区间外、距最近端点 > 半宽 | **明显偏高 / 明显偏低** |
| 口径不可比（缺税费/交付/运费） | **口径不一致，暂时无法直接比较** |
| 没有任何可靠市场报价 | **无法验证**（绝不编一个像样的市场价） |

再用**近 3 个月同口径价格带**做交叉核对：
客户价也超出历史带 → "明显"的判断更稳；
客户价落在历史带内 → 要写明"可能是不同日期的价格"。

完整判定树与边界情况：见 `references/verdict-rules.md`。

### 第 5 步 · 看 7 天 / 30 天 / 3 个月的变化

回答一个关键问题：**客户这个价，会不会是几个月前的？**

- 7 天变化：判断是不是"就这两天跌的"
- 30 天变化：判断本月的方向
- 3 个月变化：判断客户价是不是落在旧时间点

如果客户价恰好落在 3 个月前的区间里 → 这条要写进事实要点：
"您说的这个区间，出现在 2026 年 4–5 月，之后市场已回落/上行"。

对应字段：`data.json` 的 `windows`、`history_position`。

### 第 6 步 · 列口径差异表

九类因素逐条对照（不是泛泛而谈，要写"对价格往哪个方向影响多少"）：

规格与纯度 · 地区 · 税费 · 出厂/到厂 · 采购数量 · 包装 · 账期 · 物流费用 · 个别低价成交

规则与话术边界：见 `references/caliber-rules.md`。
对应字段：`calibers[]`、`factors[]`。

### 第 7 步 · 邻近地区比价（有数据才做）

只有拿到**同规格、同税费、同交付**的邻近地区报价才做对比；
并且必须写可比性说明：运距差多少、价差能不能被运费解释。
做不到就写「邻近地区无可比报价」，不要拿不含税的和含税的比。

对应字段：`regions[]` 的 `comparability`。

### 第 8 步 · 出两个交付物

| 交付物 | 内容 | 谁用 |
|---|---|---|
| **HTML 报告** | 价格带图、7d/30d/3m 走势、地区比价、口径差异表、确认清单；可切换口径重新计算 | 自己看、给主管看 |
| **Excel 工作簿** | 12 张表，**偏离公式是活的**，改客户价自动重算 | 存档、复核、换客户价再用 |

外加报告里的两个按钮产物：
- **与客户沟通的事实要点**（客观陈述，不含报价承诺）
- **润色后的微信 / 邮件草稿**（只陈述已核实事实 + 提出要确认的问题）

## 怎么用

### 最省事：一条命令

```bash
python scripts/build_all.py examples/01-重质纯碱-华东
```

它会依次：校验数据契约 → 算派生指标 → 生成 HTML → 生成 Excel → 双份自检。
任何一步不过就停，不会产出"看起来完整"的坏文件。

### 分步（要自己改数据时）

```bash
# 1. 校验你写的 research.json 是否满足契约
python scripts/validate.py examples/01-xxx/research.json

# 2. 算派生指标（区间、偏离、窗口变化、判定）
python scripts/assemble.py examples/01-xxx/research.json --out examples/01-xxx/build/data.json

# 3. 出报告
python scripts/build_html.py examples/01-xxx/build/data.json --out out/xxx报告.html
python scripts/build_xlsx.py examples/01-xxx/build/data.json --out out/xxx.xlsx

# 4. 自检
python scripts/check_html.py out/xxx报告.html examples/01-xxx/build/data.json
python scripts/check_xlsx.py out/xxx.xlsx examples/01-xxx/build/data.json
```

### 只想算一个数

```bash
# 客户价 1400 是含税出厂，市场是含税送到，运费 80 → 统一到送到口径
python scripts/normalize.py convert --price 1400 --tax 含税 --delivery 出厂 \
    --market-tax 含税 --market-delivery 送到 --freight 80

# 只有含税/不含税不同
python scripts/normalize.py tax --price 1400 --from 不含税 --to 含税

# 不给运费 → 直接告诉你「无法直接折算」，不会替你估
python scripts/normalize.py delivery --price 1400 --from 出厂 --to 送到

# 判断落在哪个区间
python scripts/normalize.py classify --price 1400 --low 1050 --high 1200
```

### 自检脚本本身

```bash
python scripts/selftest.py     # 27 项：换算、判定规则、三处实现同源
```

## 硬规则（不可协商）

1. **模拟数据必须标注。** 客户原话里带「【模拟】」，`customer.is_simulated = true`，
   `simulation_disclaimer` 写明"1400 元/吨仅为测试输入，不是真实市场报价"。
   `validate.py` 会检查，缺了就构建失败。
2. **不得用客户数字冒充市场价。** 如果某个 spot 条目的价格和客户所述价格完全一致，
   `validate.py` 直接判失败——因为你可能把客户的话抄成了"市场价"。
3. **缺口要显式。** 拿不到的数据写进 `gaps[]`，写明影响与补法；
   不要用估算值填坑，也不要在报告里假装数据齐全。
4. **口径不可比就说不可比。** 缺运费、缺税费时，输出「无法直接折算」，
   并在结论区列出缺哪一项，而不是给一个"大概差不多"的数。
5. **不预测。** 不写"预计下周还会跌""建议尽快锁价"。只描述已发生的价格与变化。
6. **不碰定价。** 报告里不出现底价、建议报价、让价幅度、谈判策略。
   HTML 里有禁用词扫描，`check_html.py` 会拦。
7. **序号不臆造。** 安装到带序号的技能目录前，先列目录确认真实序号，
   不要凭空写一个 `16.`。

## 降级路径

| 情况 | 怎么办 |
|---|---|
| 只能查到不含税价，客户是含税 | 用 `normalize.py tax` 换算，并在报告里写明换算系数 |
| 只能查到出厂价，客户要送到 | **必须**先拿到运费；拿不到就显示「无法直接折算」 |
| 只有点价（单个数字）没有区间 | 可以比，但报告要注明"该来源只给点价，不可当区间用" |
| 只有邻近地区有报价 | 可以做，但必须写可比性说明；不能代表客户所在地 |
| 完全查不到同规格报价 | 结论写「无法验证」，只给确认清单，不画价格带图 |
| 客户价来自几个月前 | 用 3 个月窗口说明"这个价出现在什么时候"，不指责客户 |
| 品种是小众中间体，公开报价很少 | 更多依赖企业挂牌价 + 行业群/客户交叉验证，来源可靠性写"中/低" |
