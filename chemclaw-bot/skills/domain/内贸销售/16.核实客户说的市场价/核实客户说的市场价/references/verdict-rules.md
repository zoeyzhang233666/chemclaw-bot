# 判定规则：接近 / 明显偏高 / 明显偏低 / 无法比较

这份文件定义"结论"是怎么从数字推出来的。**任何结论都必须能在这里找到依据**。

---

## 一、为什么不设固定百分比阈值

常见的做法是："偏离超过 10% 就算明显偏高"。

这种阈值在化工品上行不通，因为**不同品种、不同地区的正常报价宽度差很多**：

| 品种 | 典型日更区间宽度 | 宽度 / 中值 |
|---|---|---|
| 重质纯碱（华东） | 1050–1200，宽 150 | ≈13% |
| 甲醇（华东港口） | 常见宽 30–60 | ≈2% |
| 某些精细中间体 | 常见宽 500–2000 | 可能 >10% |

如果统一用 10%：
- 对纯碱来说，150 元的正常区间本身就是 13% 宽，"偏离 10%"根本不叫异常；
- 对甲醇来说，区间宽才 2%，"偏离 10%"已经是市场完全崩掉的程度。

所以判定尺度必须**取自该报价自己的区间宽度**。这就是"半宽"规则。

---

## 二、判定树

设市场参考区间为 `[low, high]`（同一来源、同一天、同一口径），
客户价为 `P`。

```
半宽 half = (high − low) / 2

┌─ P 落在 [low, high] 内？
│    是 → 【接近市场参考区间】
│
└─ 否 ── 算出距最近端点的距离 dist
          ┌─ high（P 高于上沿）→ dist = P − high
          └─ low （P 低于下沿）→ dist = low − P

          dist ≤ half ？
            ├─ 是 → 【略高于市场参考区间】/【略低于市场参考区间】
            └─ 否 → 【明显偏高】/【明显偏低】
```

### 前置检查（先做，任何一条命中就短路）

| 检查 | 命中时结论 |
|---|---|
| 没有任何同口径市场报价 | **无法验证**（不画价格带，不编数） |
| 客户税费口径与市场不同且无法换算 | **口径不一致，暂时无法直接比较** |
| 客户交付口径与市场不同且缺运费 | **口径不一致，暂时无法直接比较** |
| 客户价是空值/非数字 | **无法判定** |

## 三、近 3 个月价格带交叉核对

区间判定之后，再用**近 3 个月同口径历史价格带** `[band_min, band_max]` 做二次核对：

| 客户价位置 | 对结论的影响 |
|---|---|
| 当日区间外 **且** 历史带外 | "明显"的判断更稳，可以直接说"这个价市场近期没有出现过" |
| 当日区间外 **但** 历史带内 | 必须补一句"这个水平出现在 X 月，可能是不同日期的价格"，不能说"不可能" |
| 当日区间内 | 正常，无需额外说明 |

这一步是**防止冤枉客户**的关键：客户说"市场才 1400"，很可能他真的在两个月前见过 1400。

示例（本 Skill 的纯碱案例）：
- 当日区间 1050–1200，客户价 1400 → 高出上沿 200 > 半宽 75 → 明显偏高
- 近 3 个月价格带 1100–1200、6 个月最高 1250 → 客户价 1400 也超出历史带 150
- 所以结论可以说"1400 在近半年华东重质纯碱中未出现过"，而不仅仅是"今天偏高"

## 四、边界情况

### 4.1 客户价恰好等于端点

`P == low` 或 `P == high` → 算**区间内**（接近市场）。
理由：端点就是市场报价的一部分，客户拿到端点价是正常成交。

代码里加了 0.01 元容差，抵消浮点误差（例如区间中值 1125 恰好压线）。

### 4.2 只有一个点价，没有区间

可以比，但：
- 报告要显示"该来源为点价，不可当区间用"
- 结论只能写"高于/低于该点价 X 元"，**不能**给"明显/接近"的判定
- 因为点价可能是某天的中间价，也可能是某个市场的代表价，无法判断分布

### 4.3 区间宽度为 0（上下沿相同）

`half = 0`，只有 `P` 完全相等才算"接近"，其余全部"明显"。
这种情况要在报告里警告："该来源只给单一价格，无区间信息，判定可靠性低"。

### 4.4 客户价低于 0 或极端异常

比如客户说"市场 200"而市场是 1050–1200：
- 结论仍然是"明显偏低"
- 但要在事实要点里提示"请确认单位是否为元/吨、是否可能少写一位"
- **不要**直接说客户在乱说

### 4.5 多来源报价怎么合并

**不合并。** 不取平均，不取最大最小。

做法：
1. 选一条**主报价**（同日、同口径、可靠来源最高），标 `primary: true`
2. 其余报价作为"参考"，列在表里，标注口径差异
3. 如果两个来源同日同口径给出不同区间，报告里**并列展示**，说明分歧，
   主区间仍取可靠度最高的那一条，并在 `gaps[]` 里记录"来源间存在分歧"

## 五、反例：这些做法是错的

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| "客户价 1400 比市场 1125 高 24.4%，超过 20%，判定虚假" | 用了固定百分比，且"虚假"是对客户的指控 | 用半宽规则判"明显偏高"，只陈述价格事实 |
| "市场平均价 = (1050+1200+1150)/3 = 1133" | 三条报价的日期/地区/口径都不同，平均出来的数不存在 | 选主报价，其余并列展示 |
| "客户说 1400，我们查到 1400 附近有成交，判定一致" | 可能把自己记的客户数字当成了市场数据 | `validate.py` 会拦这种"自证" |
| "缺运费，按 80 元/吨估算" | 运费是猜的，结论继承了这个猜测 | 显示"无法直接折算"，把运费列为待确认 |
| "客户价低于市场，说明客户在压价" | 客户可能拿到的是出厂价、不含税价、或旧价格 | 只描述偏离，把口径问题列进确认清单 |

## 六、结论措辞规范

| 结论 | 推荐措辞 | 禁止措辞 |
|---|---|---|
| 接近 | "与市场报价区间一致，未发现明显差异" | "你的价格是合理的" |
| 略高/略低 | "略高于市场区间上沿 X 元，幅度小于该报价自身的区间宽度" | "贵了一点点" |
| 明显偏高 | "高于同日同口径市场区间上沿 X 元（约 Y%），该价位在近 3 个月价格带中未出现" | "客户在压价" / "这个价格不可能" |
| 明显偏低 | "低于同日同口径市场区间下沿 X 元（约 Y%），建议确认是否含税、是否出厂口径" | "客户在瞎报" |
| 无法比较 | "客户未说明含税/出厂口径，暂无法与市场送到含税价直接比较" | "数据不足无法回答" |
| 无法验证 | "未查到同规格同地区的可靠报价，本报告不给出市场参考价" | 编一个"市场价约 XXX" |

## 七、三处实现必须一致

同一条规则要在这三处给出相同结论：

1. `scripts/common.py` 的 `compare_to_range()` —— 命令行与 assemble 用
2. `scripts/templates/report.html` 里的 `recalc()` JS —— 页面上切换口径用
3. `scripts/build_xlsx.py` 生成的 Excel 公式 —— 销售改客户价用

`check_xlsx.py` 会用 `xleval.py` 把 Excel 公式算一遍，跑 4 个场景（区间内 / 明显偏低 /
缺运费 / 补齐运费）验证与 Python 一致。`selftest.py` 再验一遍 Python 侧。
改规则时这三处要同步改，否则自检会失败。
