# 数据契约：research.json

`research.json` 是**唯一数据源**。HTML 和 Excel 都从它（经 `data.json`）生成。
改数据只改这一个文件，不要改生成物。

`validate.py` 会校验这份契约，不通过就不让构建。

---

## 顶层结构

```json
{
  "meta":     { ... },   // 品种、地区、规格、基准日
  "customer": { ... },   // 客户说了什么
  "comparison_modes": [ ... ],  // 可选：多口径比对说明
  "spot":     [ ... ],   // 市场现货报价（含被排除的）
  "history":  [ ... ],   // 同口径历史序列
  "history_secondary": [ ... ], // 可选：副口径序列（如轻质）
  "futures":  { ... },   // 可选：期货参考
  "regions":  [ ... ],   // 邻近地区比价
  "calibers": [ ... ],   // 九维口径对照
  "factors":  [ ... ],   // 价格差异因素
  "drivers":  [ ... ],   // 可选：行情驱动
  "events":   [ ... ],   // 可选：企业/装置动态
  "questions":[ ... ],   // 要问客户的问题
  "facts":    [ ... ],   // 可引用的客观事实
  "gaps":     [ ... ],   // 数据缺口
  "method_notes": [ ... ] // 研究方法说明
}
```

---

## meta

| 字段 | 必填 | 说明 | 示例 |
|---|---|---|---|
| `product` | ✅ | 品种名 | `"重质纯碱"` |
| `spec` | ✅ | 完整规格描述 | `"重质纯碱（重碱），工业级 Na₂CO₃ ≥99.2%"` |
| `region` | ✅ | 客户所在地区 | `"华东地区"` |
| `region_scope` | | 地区范围说明 | `"华东（江苏/浙江/上海/安徽）"` |
| `base_date` | ✅ | 数据基准日 | `"2026-10-20"` |
| `series_key` | | 历史序列匹配键 | `"重质纯碱"` |
| `unit` | | 单位 | `"元/吨"` |
| `case_id` | | 案例编号 | `"SODA-EAST-2026-10-20"` |

**`series_key` 很重要**：spot 里的 spec 常带地区后缀（`"重质纯碱（华东）"`），
history 里的 spec 是干净的品种名（`"重质纯碱"`）。用 `series_key` 做匹配，
否则历史序列匹配不上，价格带和窗口全是空的。

---

## customer

| 字段 | 必填 | 说明 |
|---|---|---|
| `raw_text` | ✅ | 客户原话。模拟的必须带「【模拟】」 |
| `is_simulated` | ✅ | `true` / `false`，**必须显式声明** |
| `simulation_disclaimer` | 模拟时必填 | 说明这段文字只用于测试 |
| `stated_price` | ✅ | 客户说的数字（number） |
| `stated_unit` | | 默认元/吨 |
| `stated_spec` | | 客户说的规格，没说写 `"未说明"` |
| `stated_region` | | |
| `stated_tax` | | `含税` / `不含税` / `未注明` |
| `stated_delivery` | | `出厂` / `送到` / `库提` / `未注明` |
| `stated_payment` | | `现金` / `承兑` / `未注明` |
| `stated_quantity` | | |
| `stated_date` | | |
| `our_quote` | | 我方报价（选填，用于算"我方 vs 客户"） |
| `channel` | | 来源渠道（微信/电话/邮件） |

⚠️ **`stated_price` 绝不能等于任何 spot 条目的价格**——`validate.py` 会判失败，
因为这通常意味着把客户的话抄成了"市场价"。

## spot[]

每条市场报价：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一编号，如 `SP-MYSTEEL-1020-HD` |
| `date` | ✅ | `YYYY-MM-DD`，不得晚于 `base_date` |
| `spec` | ✅ | 规格 |
| `region` | ✅ | 地区 |
| `tax` | ✅ | `含税` / `不含税` / `未注明` |
| `tax_label` | | 原文表述，如 `"现金含税价"` |
| `tax_rate` | | 如 `0.13` |
| `delivery` | ✅ | `出厂` / `送到` / `库提` / `集港` |
| `payment` | | `现金` / `承兑` |
| `low` / `high` | 至少一个 | 区间端点 |
| `point` | | 点价（若来源只给单值） |
| `point_note` | | 点价的说明，如"该来源只给单值" |
| `unit` | | 默认元/吨 |
| `source` | ✅ | 来源名，转载要写清 |
| `source_type` | | `专业日更` / `门户转载` / `企业挂牌` |
| `quote_type` | ✅ | `区间报价` / `点价` / `成交参考` |
| `conf` | ✅ | `高` / `中` / `低` |
| `url` | ✅ | 可点击链接（http/https） |
| `verify` | | 原文摘录，用于复核 |
| `primary` | | 是否为主报价（建议恰好一条为 true） |
| `exclude_reason` | | 不可比较时说明原因（如"出口集港口径"） |

## history[]

| 字段 | 必填 | 说明 |
|---|---|---|
| `date` | ✅ | 升序排列 |
| `spec` | ✅ | 用干净的品种名（配合 `series_key`） |
| `region` | ✅ | 必须与主报价一致 |
| `tax` | ✅ | 必须与主报价一致 |
| `delivery` | ✅ | 必须与主报价一致 |
| `low` / `high` | | 区间 |
| `point` | ✅ | 该点的代表值；有区间时取中值 |
| `source` | ✅ | |
| `url` | | |
| `kind` | | `日更区间` / `点价` |

⚠️ `point` 必须落在 `[low, high]` 内（`validate.py` 会警告，因为常见笔误是把
1050–1200 的中值写成 1100 而不是 1125）。

## regions[]

| 字段 | 必填 | 说明 |
|---|---|---|
| `region` | ✅ | 地区名 |
| `low` / `high` | ✅ | |
| `date` | ✅ | |
| `tax` / `delivery` | | 应与主报价一致 |
| `comparability` | ✅ | 可比性说明，如"同规格同税基，运距约 400km" |
| `gap_to_basis` | | 与基准地区的价差，可手填或由脚本算 |

## calibers[]

九维口径对照，至少 5 条：

```json
{
  "dim": "税费",
  "customer": "未注明",
  "market": "含税（增值税 13%）",
  "same": "信息缺失",
  "impact": "客户若为不含税，1400 换算后为 1582，差异方向反转",
  "action": "追问是否含税；若不含税，按 ×1.13 换算后复核"
}
```

`same` 取值：`一致` / `不一致` / `部分一致` / `信息缺失` / `不可比`

---

## questions[]

```json
{ "q": "这个 1400 是含税还是不含税？", "priority": "高", "why": "税基差 13%，直接决定可比性" }
```

`priority`：`高` / `中` / `低`。至少要有 1 条"高"。

---

## facts[]

能给客户看的客观事实，每条必须带来源和日期：

```json
{
  "text": "2026-10-20 华东重质纯碱主流送到报价 1050–1200 元/吨",
  "src": "隆众资讯（经 mysteel 转载）",
  "url": "https://...",
  "date": "2026-10-20",
  "conf": "高",
  "note": "含税·现金"
}
```

---

## gaps[]

```json
{
  "item": "客户是否为出厂口径",
  "impact": "若是出厂价，需加运费后比较，当前结论可能偏严",
  "fix": "确认交付方式；若出厂，问物流报价后重算"
}
```

**至少 1 条。** 真实研究几乎总有缺口，写不出缺口通常意味着没查够。

---

## 校验

```bash
python scripts/validate.py examples/01-xxx/research.json
```

会检查：
- 必填字段
- 日期不晚于基准日
- `low ≤ high`
- `point` 在区间内
- 模拟案例带「【模拟】」
- 客户价不等于任何市场报价
- 城市/地区/税费/交付取值规范
- 禁用承诺性表述

`[warn]` 不阻塞构建，`[FAIL]` 会。
