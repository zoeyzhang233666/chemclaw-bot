# 公式与精度规则

所有数字都要能被第三个人用同样的输入复现。这份文件是"复现说明书"。

---

## 一、参考值与偏离

设市场主报价区间为 `[low, high]`，客户价为 `P`。

| 量 | 公式 | 说明 |
|---|---|---|
| 区间中值（参考值） | `ref = (low + high) / 2` | **只在单一来源的区间内取中值**，不跨来源平均 |
| 区间半宽 | `half = (high − low) / 2` | 判定"明显"的尺度 |
| 偏离金额（相对中值） | `delta = P − ref` | 正数 = 客户价更高 |
| 偏离比例（相对中值） | `pct = delta / ref` | 报告里显示为带符号百分比 |
| 相对上沿金额 | `P − high` | > 0 表示客户价高于市场最高报价 |
| 相对上沿比例 | `(P − high) / high` | |
| 相对下沿金额 | `P − low` | < 0 表示客户价低于市场最低报价 |
| 相对下沿比例 | `(P − low) / low` | |

`assemble.py` 里的 `steps` 数组会把每一步的公式、输入、结果都写进 `data.json`，
Excel 的「09_计算过程」表原样展示。

## 二、税费换算

| 方向 | 公式 |
|---|---|
| 不含税 → 含税 | `含税 = 不含税 × (1 + 税率)` |
| 含税 → 不含税 | `不含税 = 含税 / (1 + 税率)` |

**规则**：

1. 税率默认 13%（化工品增值税），品种不同请改 `--vat` 或 `research.json` 的 `tax_rate`
2. **只有两侧税基明确且不同才换算**：
   - 客户"不含税" + 市场"含税" → 换算
   - 客户"含税" + 市场"不含税" → 换算
   - 客户"未注明" → **不换算**，直接按市场税基比，并标注风险
3. 报告里必须显示换算系数（如 `×1.13`）

示例：客户价 1400 不含税，市场 1050–1200 含税
→ 换算后客户价 = 1400 × 1.13 = 1582 元/吨

## 三、交付口径换算

| 方向 | 公式 | 前提 |
|---|---|---|
| 出厂 → 送到 | `送到价 = 出厂价 + 运费` | **必须知道运费** |
| 送到 → 出厂 | `出厂价 = 送到价 − 运费` | **必须知道运费** |

**规则**：

1. 运费未知 → 不换算，输出「无法直接折算」，把运费列进待确认
2. **绝不**用"经验运费""一般 80 元"去补
3. 运费已知时，报告要写"运费 80 元/吨为已知值，未含装卸/资金占用"

## 四、时间窗口变化

| 窗口 | 起点取法 | 变化 |
|---|---|---|
| 近 7 天 | 基准日往前 7 天，取该窗口内**最早**的点 | `to_value − from_value` |
| 近 30 天 | 往前 30 天，取最早的点 | 同上 |
| 近 3 个月 | 往前 92 天，取最早的点 | 同上 |

变化比例 = `(to − from) / from`。

**注意**：
- 窗口内没有点时，该窗口显示"—"，不要用更远的点凑
- 起点用"最早的点"而不是"刚好 7 天前那天"，因为日更报价不是每天都有

## 五、近 3 个月价格带

```
band_min  = min(近 92 天所有同口径点的 point)
band_max  = max(...)
band_med  = median(...)
band_mean = mean(...)
band_n    = 点数
```

**门槛**：`n < 3` 时不画价格带，报告里写"样本不足"。

## 六、区域价差

以客户所在地区（主报价地区）为基准：

```
区域价差     = 该区域中值 − 基准区域中值
区域价差比例 = 区域价差 / 基准区域中值
```

**前提**：参与对比的区域必须是**同规格、同税费、同交付**。
日期可以差几天，但要在表里标出来。

## 七、精度与显示

| 场景 | 精度 | 示例 |
|---|---|---|
| 金额（元/吨） | 整数，千分位 | `1,125` |
| 偏离金额 | 带符号整数 | `+275` / `−25` |
| 比例 | 1 位小数，带符号 | `+24.4%` / `−2.2%` |
| 换算系数 | 4 位小数 | `1.1300` |
| 中间计算 | 保留完整浮点，只在显示时取整 | — |

**不要**在中间步骤四舍五入，否则 275 可能变成 274 或 276，复核时对不上。

## 八、可复现性检查

任何人拿到 `research.json` 应该能复现出全部数字。检查方式：

```bash
python scripts/assemble.py examples/01-xxx/research.json --out /tmp/check.json
# 对比 data.json 与 /tmp/check.json 应完全一致
```

`data.json` 里的 `steps` 数组就是给这个用的：每一步都有公式、输入、结果。

## 九、Excel 里的公式（活公式，不是常数）

Excel 不是把算好的数印上去，而是真的写公式，这样销售把客户价改掉就自动重算。

| 表 | 关键公式 |
|---|---|
| `01_客户报价输入` | `B25 = AVERAGE(B23:B24)` （区间中值） |
| `04_偏离计算` | `① 偏离金额 = B20 − B13`<br>`② 偏离比例 = B25 / B13`<br>`⑧ 半宽 = (B12 − B11) / 2` |
| `04` 判定 | `IF(口径不可比, "无法直接比较", IF(在区间内, "接近", IF(距端点<=半宽, "略高/略低", "明显偏高/偏低")))` |
| `06_区域对比` | `较基准价差 = D{r} − D${base}` |

改客户价只需要改 `01!B5`，其余全自动。

`check_xlsx.py` 会用自带的公式求值器跑 4 个场景，确认公式真的会随输入变化。
