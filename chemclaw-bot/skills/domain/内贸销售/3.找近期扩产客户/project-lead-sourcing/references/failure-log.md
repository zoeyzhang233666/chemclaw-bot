# 失败日志：崩溃模式与修法

每条都来自实战（纯碱华东那一轮 12 个 lane 的踩坑记录）。**修法已经内置到管线里**，但 agent 仍然需要知道为什么。

## 1. lane 上下文耗尽 → 零产出（最常见的崩溃）

**症状**：lane 跑了很久，`leads_raw/NN_*.json` 不存在或只写了一半。

**根因**：一次把大 JSON 或大段页面正文读进上下文。一个搜索接口 `pageSize=30` 返回的 JSON 就足够吃掉整个 lane。

**内置防线**（lane brief 里已经写了，不要删）：
- 目标条数有上限（默认 8~15 条），不贪多；
- **总工具调用 ≤35 次**；
- 每家公司最多 1~2 个页面，失败直接跳过、不重试；
- **每完成 5 条就增量落盘**（读回数组 → 追加 → 覆盖写）。

**仍然崩了怎么办**：**不要原样重发同一个 brief**——探索动作本身就是崩溃源。改用**枚举式 brief**：把候选企业名单（带股票代码）直接写进 brief，**禁用一切检索**，每家最多核验 1~2 个页面。模板见 [`lane-brief.md`](lane-brief.md)。

## 2. 明文 HTTP / HTTPS 跳转

**症状**：`web_fetch` 或脚本报"基础连接已经关闭: 接收时发生错误"，或长时间挂起。

**根因**：受限网络里只有**直接提供内容的明文 http** 可达；任何 `301/302` 跳 `https://` 的站点都连不上。

**诊断**（`tools/http.py` 故意不跟随跳转）：
```python
from tools import http
print(http.fetch('http://sthjj.xxx.gov.cn/...'))   # 看 status / final_url / note
# status=302, final_url='https://...', note='redirect->https'  → 不可达，别重试
```

**修法**：换用该站点的**明文 http 入口**（很多政府站点的地市级页面是 https，省级栏目页反而是 http）；或改走公告类通道。**不要反复重试同一个 https 地址。**

## 3. PowerShell 脚本的中文变成乱码/解析失败

**症状**：`Invoke-WebRequest` 抓回来的中文是"鍙揪浣嗕富浣撻渶澶嶆牳"这种；或 `.ps1` 报奇怪的字符串未闭合错误。

**两个不同的根因，别搞混**：
1. **响应头缺 `charset`** → PowerShell 5.1 按 Latin-1 解码 → 中文乱码。（判断"主体一致"时会**假阴性**）
2. **`.ps1` 文件本身是 UTF-8 无 BOM** → PS 5.1 按 ANSI 读源码 → 中文字符串字面量破坏语法。

**修法**：
- 优先用**本 skill 的 Python 工具**（`tools/http.py` 按 `charset → utf-8 → gb18030 → big5 → latin-1` 依次尝试），不要自己写 PowerShell 抓取。
- 如果确实要写 `.ps1`：**存成 UTF-8 with BOM**，并在脚本头加 `Set-ExecutionPolicy -Scope Process Bypass -Force`。

## 4. JSON 的 BOM

**症状**：`json.load(f, encoding='utf-8')` 抛 `Unexpected UTF-8 BOM (decode using utf-8-sig)`，而且如果被 try/except 吞掉，会**静默返回空**——表现是"所有条目都显示未抽检"，很难查。

**修法**：本 skill 所有 JSON 读取统一用 `encoding='utf-8-sig'`。**你自己写临时脚本时也要这样**。

## 5. merge 之后统计里某个桶是 0

**症状**：`by_timing` 三个桶塌成 `16 / 0 / 77`。

**根因**：`预计投产时间` 大面积未披露。这不是 bug，是数据现实——但**判定规则必须为它设计**。

**修法**：见 [`timing.md`](timing.md) 第 3 节（在建 + 未披露 → 3-6 个月）。

## 6. 抽检出现大量"需人工复核"

**症状**：抽检 40 条，9 条判为"可达但主体需复核"。

**根因**：通常是**假阴性**——编码问题（见第 3 节第 1 类）导致正文匹配不上，而页面其实是好的。

**修法**：用 Python 按字节级重新抓一遍再判断。纯碱那一轮 9 条假阴性重验后**全部**变成"可达且主体一致"（页面里确实有公司名，甚至有 6 次命中）。

## 7. 某个 lane 产出低于下限

**症状**：目标 8~15 条，只产出 6 条。

**处理原则**：**如实报告，不要为了凑数编条目**。产出低通常有两种原因，**都要写进第四块**：
1. **该方向确实在萎缩**（最有价值的负结果）——例如某板块主体在关停/拆装置而不是新建；
2. **通道没打通**（例如某省环评栏目是 JS 渲染，抓不到列表）——这决定覆盖率的偏差方向。

**区分方法**：看该 lane 的 `来源类型`。如果连公告都搜不到，偏向原因 1；如果只有公告、没有环评，偏向原因 2。

## 8. 母公司/子公司导致同一项目被算两次

**症状**：同一条产线，一条记录写"某某集团"，另一条写"某某集团某某子公司"，去重没抓到。

**根因**：`norm_company()` 去掉了括号内容与公司后缀，但如果两个名字差异不在这些位置（例如一个带地名"桐乡"一个不带），就会漏。

**修法**：这类交给**人工去重**（[`gates.md`](gates.md) 闸门 3 的"需要人工处理的重复"）。判定看**厂址是否一致**。

## 9. 引用了不存在的工具

**症状**：`fetch.ps1` 之类的辅助脚本在部分 lane 的 brief 里被引用，但项目目录里其实没有 → 那个 lane 只能用自带的 `Invoke-WebRequest` 兜住。

**教训（已改进）**：**brief 里引用的每一个脚本，必须在派工之前确认它存在**。本 skill 的做法是：brief 只引用 `scripts/` 下**随 skill 一起分发**的工具（`tools/http.py` / `tools/cninfo.py` / `tools/eastmoney.py` / `tools/eia.py` / `tools/pdftext.py`），不引用任务目录里的临时脚本，从而不可能缺失。

## 10. `send_message` 给正在运行的子代理失败

**症状**：`active teammate "<id>" not found`。

**根因**：只能给**已结束**的子代理继续发消息；正在运行的不能被追加指令。

**修法**：**派工前把 brief 写完整**——这正是 brief 要自包含的原因。发现 brief 有漏，等它结束再说，或另起一个 lane 补。

## 11. 幂等性

所有 `b2bctl` 子命令都可以重复运行：`merge` / `build` 覆盖输出，`probe` 覆盖 `channels.json`，`qa` 覆盖 `_qa_report.json`。
唯一的例外是 `new`——已存在 `config.json` 时会拒绝（加 `--force` 覆盖）。**不要在已有项目上盲目 `--force`，会清掉填好的配置。**
