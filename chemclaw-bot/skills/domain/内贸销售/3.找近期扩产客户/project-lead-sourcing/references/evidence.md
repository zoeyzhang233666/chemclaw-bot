# 证据纪律：trace 是唯一的硬通货

## 1. 一条线索最低要求

**业主企业 + 具体项目 + 建设阶段 + 本产品在该项目的关系（哪个工序、什么作用）+ 可点开的出处。**

少任何一项都不是线索：
- 只有公司名没有项目 → 那是公司名单，不是项目线索；
- 只有"经营范围包含 XX" → 那说明不了**新建**会带来新增需求；
- 没有出处 → `来源=未核实`、`置信度=低`，只能电话确认。

## 2. 置信度判定

| 级别 | 判据 |
|---|---|
| `高` | 来源原文**明确写出**该项目 + 产能或规模 +（如有）时间；链接点开能复核 |
| `中` | 企业业务与该工序可确认、项目存在，但**产能或时间细节缺失** |
| `低` | 主体或项目细节未核实；或来源为新闻/二手；或 `来源=未核实` |

**注**：`置信度` 关于证据强度，`用量强度` 关于需求规模，两者独立。一个"高置信度、低用量强度"的线索值得联系（确定性高但量小），一个"低置信度、高用量强度"的线索需要先核实再投入资源。

## 3. 严禁编造（最容易踩的四个坑）

1. **编 URL**。猜一个像样的域名填进去，销售点进去是博彩站/404，整张表就废了。**宁可写"未核实"**。
2. **编产能/日期**。"约 10 万吨""2027 年"这种看着合理的数字，如果原文没有，就是污染。
3. **编单耗**。见 [`method.md`](method.md) 第 4 节：有出处的粗算 >> 无出处的精算。
4. **拿记忆当证据**。模型对行业格局的记忆是有时效的、可能过时的。**必须用当次抓到的页面**。抓不到就报告"本环境无法取证"，不要用记忆补齐。

## 4. 链接抽检（link gate）

```bash
python scripts/b2bctl.py qa <项目目录>
```

- 抽样 **≥40 条**，优先抽**非聚合站**（如非 cninfo），样本更多样。
- 判定口径：`可达(PDF)` / `可达且主体一致` / `可达但正文未含主体名` / `反爬拦截-建议人工复核` / `坏链-404` / `坏链-仅HTTPS(本环境不可达)` / `抓取失败:<原因>`。
- **必须区分两类失败**：
  - **反爬拦截**（403/406/412/429）——浏览器里通常能打开，标"建议人工复核"即可，不算坏链；
  - **跳转 HTTPS / 空壳页 / 404 / 连接被重置**——这些是真坏链，要在交付说明里逐条列出。
- 结论写进 `抽检结论` 字段，**绝不拼进 `来源`**（会让 URL 变坏链）。

### 「主体一致」的假阴性（踩过的坑）

用 PowerShell 的 `Invoke-WebRequest` 抓政府/证券站点时，因为响应头缺 `charset`，PS 5.1 会按 Latin-1 解码，中文全变乱码，导致"主体一致"误判成"需复核"。
**本 skill 的 `qa` 是纯 Python 实现的**，按 `charset → utf-8 → gb18030 → big5 → latin-1` 依次尝试，并且**只做字节级包含判断**（`公司名关键词 in html`），不依赖控制台编码——就是为了避开这类假阴性。

## 5. 来源分级（取证优先级）

| 级别 | 类型 | 说明 |
|---|---|---|
| 最强 | 环评报告**原文** | 有"主要原辅材料"表，能直接读到本产品，且给出工艺与产能 |
| 强 | 上市公司公告原文（招股书/可研/募投/半年报） | 产能、投资额、建设周期、投产时间 |
| 强 | 备案/核准/招标公告 | 项目存在性与时间点 |
| 中 | 政府新闻、行业媒体 | 存在性可信，细节常缺，需回溯原始来源 |
| 弱 | 百科、企业黄页、聚合站 | 只作兜底，不作唯一依据 |

**环评是覆盖非上市企业的主渠道**——上市公司有公告，非上市企业往往只有环评。所以 EIA 通道的可用性直接决定非上市企业的覆盖率，这一点必须写进交付说明的缺口章节。
