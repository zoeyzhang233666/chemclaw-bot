# 记录 schema

`leads_raw/*.json` 与 `leads.json` 是**同一 schema 的 JSON 数组**。
`b2bctl collect` 会逐条校验，缺字段/枚举越界/非 URL 来源都会被报出来。

## 采集字段（lane 产出，18 个，缺一不可）

| 字段 | 说明 | 常见错误 |
|---|---|---|
| `公司` | 业主企业全称，可带括号注明母/子公司关系 | 只写简称，导致去重失败 |
| `细分行业` | 如 光伏玻璃 / 印染 / 锂盐 | 写成"化工"这种无信息量的词 |
| `省市` | `省/市`，必须落在 `region.provinces` 内 | 写成"长三角"；地区闸门会剔除 |
| `项目名称` | 项目全称 | 写成公司名；确实没有就写 `未披露（原因）` |
| `建设阶段` | 只能取 `拟建/备案/在建/试车/已投产` | **把环评受理写成"在建"**（应为 `备案`） |
| `项目产品` | 该项目产出什么 | 留空 |
| `设计产能` | 带单位 | 未披露就写 `未披露`，不要留空 |
| `预计投产时间` | `YYYY-MM` 或 `YYYYQn` 或 `未披露` | 写"2027 年"也可解析（按年中，粗糙） |
| `所在园区` | 园区/厂址 | 只写城市 |
| `需求点` | 本产品在**哪个工序**起什么作用 | 写成"用于生产"这种废话 |
| `产品角色` | 只能取 `config.product.roles_vocab`（默认 主原料/辅料/助剂） | 自造词 |
| `单耗依据` | 反应式 / 配合料配比 / 公告原文引用 | 直接给数字而不说来源 |
| `年需求量估算` | 算式 + 结果 + 假设 | 无依据却给数字 ← **最严重** |
| `规模线索` | 投资额、建设进度、建设周期 | 留空 |
| `来源类型` | `备案/环评/招标/公告/新闻` | 把环评写成"公告" |
| `来源` | **可点击 URL**；取不到写 `未核实` | 写域名首页；写搜索页 |
| `发布日期` | `YYYY-MM-DD` | 写成公告里的项目日期而非发布日 |
| `置信度` | `高/中/低` | 判定标准见 `evidence.md` |

## 派生字段（`b2bctl merge` 写入，lane 不得自行填写）

| 字段 | 来源 |
|---|---|
| `lane` / `lane_id` | 由文件名 + `lanes.json` 推出 |
| `用量强度` | `lanes.json` 的 `intensity`，渲染成 `★★★★★` **字符串** |
| `需求性质` | `直接` / `间接` |
| `销售时点` | 规则见 `timing.md` |
| `时点理由` | 判定理由，会显示在 HTML 抽屉里 |
| `优先级` | `高/中/低`，= 强度 × 置信度，间接降权 |
| `抽检结论` | 由 `b2bctl qa` 写入 |

**注意**：抽检结论**单独成列**，绝不拼进 `来源`。曾经把「可达且主体一致」拼在 URL 后面，导致 HTML 里的链接全部变成坏链——`来源` 必须保持是干净的 URL。

## 内部字段

`_intensity` / `_score` 是合并期排序用的中间量，下划线开头，不要外泄到交付物里。

## 校验

```bash
python scripts/b2bctl.py collect <项目目录>            # 全部 lane 文件
python scripts/b2bctl.py collect <项目目录> --file leads_raw/05_*.json
```

报出来的问题**必须修完再 merge**——否则要么被静默剔除（地区/peer），要么污染分布统计。
