# 数据契约（data.json）

一个区域市场研究 = **一个 JSON 文件**。`scripts/build_all.py` 读它，产出 HTML + Excel。
换产品、换区域时，只换这个 JSON，脚本一行都不用改。

JSON 用 UTF-8 编码，字段名一律 snake_case。数值单位统一写在 `meta` 里，正文不重复单位。

---

## 1. 顶层结构

```json
{
  "meta":       { ... },   // 必填：产品、区域、单位、价格锚点
  "summary":    { ... },   // 选填：不填则由 cities 自动汇总
  "provinces":  [ ... ],   // 必填：省级一行一条
  "cities":     [ ... ],   // 必填：城市/县域一行一条（研究的主战场）
  "lanes":      [ ... ],   // 必填：下游方向 8–12 条
  "companies":  [ ... ],   // 必填：具名样本（含同行与误判）
  "projects":   [ ... ],   // 必填：新建/扩建/技改/减产
  "prices":     { ... },   // 必填：区域价 + 区内价差
  "route":      [ ... ],   // 必填：走访周次
  "narrative":  { ... }    // 必填：结论、口径、缺口等文字块
}
```

## 2. meta

| 字段 | 类型 | 说明 |
|---|---|---|
| `product` | str | 产品全称，含规格，如「纯碱（重质/轻质，含食品级）」 |
| `region` | str | 区域全称，如「华东（沪苏浙皖闽赣鲁）」 |
| `asof` | str | `YYYY-MM-DD`，数据截止日 |
| `demand_label` | str | 需求量的叫法：「用碱量」「用量」「耗量」 |
| `demand_unit` | str | 默认 `万吨/年`；小程序可用 `吨/年`，但所有数值必须同单位 |
| `anchor` | obj | `{label, value, unit, date}` 价格锚点，如华东重碱主流价 1150 元/吨 |
| `title` | str | 浏览器标题 |
| `subtitle` | str | 首屏一句话（谁、在哪、这张图能干什么） |
| `tags` | [str] | 首屏 3–5 个标签，每条必须能被数据或结论支撑 |

## 3. cities（核心）

```json
{
  "city": "滁州·凤阳", "prov": "安徽",
  "firms": 41, "traders": 5, "demand": 150,
  "lon": 117.56, "lat": 32.87,
  "inds":  [{"id":"pv","name":"光伏玻璃","n":9,"share":0.61,"kt":90}],
  "parks": [{"name":"凤阳硅基新材料产业基地","ind":"光伏玻璃/日用玻璃","n":34,"firms":"福莱特、南玻"}],
  "head":  ["福莱特玻璃（凤阳基地）"],
  "smb":   "日用玻璃与深加工中小企业约 26 家……",
  "note":  "单城需求约 150 万吨，是区域第一大单一需求池……"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `city` / `prov` | ✔ | 名称；跨市县域写成「滁州·凤阳」 |
| `firms` | ✔ | 潜在生产型企业数（估算） |
| `traders` | ✔ | 贸易/分销商家数（估算） |
| `demand` | ✔ | 需求量，单位同 `demand_unit` |
| `inds` | ✔ | 下游结构；`n` 企业家数，`share` 占比（可省，脚本按 `n×单耗` 归一），`kt` 需求量（可省） |
| `parks` | ✔ | 园区/集聚区；`n` 园区内潜在家数 |
| `head` | ✔ | 代表企业（可空数组） |
| `smb` | ✔ | 中小企业集群描述（数量口径，别编企业名） |
| `note` | ✔ | 一句话判断：值得怎么打、难在哪 |
| `lon`/`lat` | – | 不填则用 `scripts/assets/city_centers.json` 匹配「城市名+市」，再退到省会坐标 |
| `score`/`rank`/`tier` | – | 不填则按公式自动计算（推荐不填，保证跨产品可比） |

## 4. lanes（下游方向）

```json
{"id":"pv","name":"光伏玻璃","share":23,"unit_txt":"0.18–0.22 t/t玻璃","intensity":5,
 "logic":"超白压延玻璃配合料中作助熔剂，引入 Na2O……",
 "who":"采购部/总经理","hook":"窑炉不停机，供应稳定性优先于单价",
 "misread":"组件厂不用该原料（用玻璃原片）"}
```

- `intensity` 1–5：单客户用量强度。5=千吨级以上/家，4=百吨级，3=数十吨级，2=十吨级，1=更低。
- `misread` 必填：这条下游最常见的误判是什么。没有就写「无」。

## 5. companies

```json
{"name":"","type":"生产|贸易|同行|误判","conf":"高|中|低",
 "prov":"","city":"","park":"","lane":"pv","scale":"","kt":60,
 "need":"在哪个工序用什么量、对什么指标敏感",
 "who":"对接部门","action":"首访动作","src":"证据来源"}
```

- **type 只有四个值**：`生产`（客户）、`贸易`（渠道客户）、`同行`（自己也生产该产品）、`误判`（下游但不消耗该产品）。
- `conf` 与 `src` 必须自洽：`高` 要能指向公告/年报/交易所/政府/园区/价格库；`低` 的 `src` 写「未核实（需电话确认）」。
- `kt` 未知填 `null`（脚本渲染成「—」）。

## 6. projects

```json
{"id":"P01","co":"","name":"","prov":"","city":"","type":"新建|扩建|技改|复产|减产（负向）|新建（区外）",
 "prod":"","cap":"","invest":"","status":"","start":"","ramp":"",
 "kt":2.8,"impact":"对本品需求的影响与接触时点","conf":"","src":""}
```

`kt` 为正=新增需求，为负=减产（如冷修、限产）。两者都要收，否则会高估增量。

## 7. prices

```json
{"notes":["..."],
 "regions":[{"name":"华东","v":1150,"why":"本地自产+港口到货"}],
 "internal":[{"name":"山东（潍坊/淄博）","range":"1000–1080","why":"产地运费最低","room":"低","advice":"别拼价格"}]}
```

`regions` 的第一条应等于 `meta.anchor`，脚本用它画柱状图。

## 8. route

```json
{"week":"第1周","base":"上海/无锡","seq":"上海 → 无锡 → 常州","focus":"贸易商+泡碱","why":"为什么这样排"}
```

`seq` 里的城市名要能在 `cities.city` 里匹配到，脚本据此算覆盖家数与天数。

## 9. narrative（决定文档能不能被信任）

| 字段 | 说明 |
|---|---|
| `conclusions` | 4–6 条，必须带数字，先说结论再说打法 |
| `usage` | 3–4 条使用说明（怎么读、怎么换数据） |
| `method` | `[{k,v}]` 口径块：企业数口径、需求口径、评分公式、置信度分级… |
| `peer_notes` | 同行说明（为什么不是客户 + 它们的真正价值） |
| `misread_notes` | 误判说明（哪几类企业最容易看错） |
| `gaps` | 负结果与缺口，必须点名具体行业或具体企业 |
| `cluster_advice` | 中小集群的通用打法（写进 06 表） |

---

## 10. 校验规则（`scripts/validate.py` 会查）

**致命（error，阻断构建）**
1. 缺顶层键或缺 `cities`/`lanes`/`companies`。
2. 城市出现重复名；`type`/`conf`/`intensity` 不在枚举值内。
3. `companies.conf == "高"` 但 `src` 含「未核实」「待核实」。
4. `demand_unit` 与数值量级明显不符（如单位是吨/年但城市需求写成 150）。
5. 占比类字段 `share` 不在 0–1。

**警告（warning，可构建但要修）**
1. `summary` 与 cities 汇总不一致（差 >2%）。
2. 某城市 `inds` 占比之和偏离 1 超过 0.05。
3. `route.seq` 里的城市名匹配不到。
4. 缺 `method`/`gaps`/`peer_notes`。
5. 有 `同行` 却一家都没写进 `peer_notes`。
6. `companies` 里 `生产` 类占比过低（<40%），通常意味着把同行/误判混进来了（跑一次 peer gate）。
