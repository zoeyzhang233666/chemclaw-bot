# 01 · 方法：从一句话到可发送文本

## 一、先分清三样东西

改写客户沟通时，绝大多数失误来自把三样东西混为一谈：

| | 是什么 | 能不能动 |
|---|---|---|
| **事实** | 已发生的事，有证据 | 不能动。只能换说法（换个顺序、换个主语） |
| **判断** | 我方对客户/市场的看法 | 可以弱化或删除。写进正文要有依据 |
| **承诺** | 我方将来会为对方做的事 | 只能收紧，不能放宽。收紧需降到"可兑现" |

润色的动作全部发生在"表达层"，**不许跨到"事实层"和"商业层"**。跨了就是编，编了第一次，后面每一句都要圆。

## 二、抽事实台账（F 编号）

### 拆句规则
1. 一句话里只要出现**两个动作**，就拆成两条。例："我们价格也发您了，您看了没" → F（已发报价）+ F（客户未回）。
2. 一句话里只要出现**数字**，单独一条，标出来。数字是最容易在改写中变形的东西。
3. 客套话（王工您好、打扰一下、感谢支持）不进台账——它们不是事实，是可增删的修辞。
4. 客户说的、我方说的、行业常识，**分三个来源**，不能混。

### 十二种需要识别的句型

| 原话形态 | 归类 | 处置 |
|---|---|---|
| "上次给您寄的样…" / "上个月发的 X 吨…" | 事实（已发生） | 可用，是本轮由头 |
| "价格我发您了" | 事实（已发出） | 可用，但要补单号/口径 |
| "不知道您看了没" / "怎么没回我" | 追问（敏感事实） | 不点破，改"您先看着" |
| "质量挺好的" / "很多厂在用" | 无据背书 | 删，或换成可核验项（试烧结果/质检单） |
| "价格可以再谈" | 越权让价 | 删，或【待填：经批准口径】 |
| "有什么要求都可以提，我们一定配合" | 无限承诺 | 降级为"我先记下，核实后给您准话" |
| "最近货源紧张" / "马上要涨" | 无据施压 | 删，或补真实依据（检修计划/调价函） |
| "我们会尽快安排" | 模糊承诺 | 改成"我核实后，今天/明天下午回您" |
| "您看什么时候方便" | 开放请求 | 改二选一（周三下午或周四上午） |
| "麻烦尽快" | 施压 | 改"这周能不能安排"，给具体动作 |
| "我们是行业第一" | 自我评价 | 删（除非有第三方可引用的依据） |
| "你们的要求我们都能满足" | 全称承诺 | 拆成"哪几条能做、哪条要确认" |

### 台账必备字段
`id`（F1…）· `text`（一句话说清）· `type` · `source` · `disposal` · `note`（对写法的提示）

## 三、六个改写算子

润色不是"换同义词"，是把句子放进下面六个动作之一。任何改动都应该能归到某一个算子里，否则就是自由发挥。

| 算子 | 动作 | 例 |
|---|---|---|
| **重排** | 把请求从开头挪到结尾，把由头提到开头 | "想问您个事…上次寄的样" → "上周二寄的样，车间试得怎么样？" |
| **降级** | 承诺 → 待确认；判断 → 事实 | "一定配合" → "我先记下，核实后给您准话" |
| **去压** | 删时间压力与追问，主动权交回对方 | "尽快回复" → "我按您的时间来" |
| **显责** | 把模糊主语句说清是谁做、什么时候做 | "会尽快处理" → "我今天下午核对完发您" |
| **分包** | 一条消息只留一个请求，其余拆下一次 | 三个诉求 → 只留"约半小时" |
| **锚时** | 补一个我方的动作 + 时间点（不是要对方承诺） | "如果这周不方便，我下周二上午再跟您确认一次" |

**判断标准**：改写后的每一句，都要能回答"这句是从原话哪一句来的"。答不上来的，就是新增，删掉。

## 四、主版本怎么定

四个版本不是四套话术，是同一份事实的四种排布：

| key | 定位 | 什么时候发 | 硬约束 |
|---|---|---|---|
| `A` 自然 | 默认推荐，口语但有序 | 微信首推 | ≤220 字，一个请求，结尾开放问句 |
| `B` 更短 | 结论先行，三句话 | 客户已读不回 / 偏好短消息 | ≤80 字 |
| `C` 正式 | 邮件体，分条留痕 | 要走流程、要抄送领导、要留证 | 必须有主题行、编号、口径、有效期 |
| `D` 缓和 | 低压力，选择权全给对方 | 客户反感催促、关系建立期 | 不出现任何时间要求 |

`P0` 是原文，必须原样保存——它是后面所有审计的基准，也是复盘时唯一的证据。

## 五、推进力与风险的取舍

| 版本 | 语气正式度 | 推进力 | 风险 |
|---|---|---|---|
| P0 原文 | 1 | 3（靠压力，不是靠理由） | 高 |
| A 自然 | 2 | 4 | 低 |
| B 更短 | 2 | 5 | 低（但显得公事公办） |
| C 正式 | 5 | 3 | 低（待填需补齐） |
| D 缓和 | 2 | 2 | 低（可能被无限期搁置） |

没有最优版本，只有**最匹配当下关系阶段**的版本。关系越浅，越要往前两个版本靠；流程越重，越要往 C 靠。

## 六、常见错误（自检用）

1. **把"催"换成"关心"就以为解决了**——换汤不换药，客户一样能读出来。真正的解法是给一个新的、对方也需要的议题（试烧反馈、到货节奏、口径核对）。
2. **一条消息塞三个请求**——回复成本变高，回复率下降。删到只剩一个。
3. **用"我们领导说了"来转嫁压力**——对方会直接要求跟领导谈，你失去了中间人价值。
4. **把占位符当省略号**——`【待填】` 不是"你自己看着办"，必须配确认人，否则就是延迟爆炸。
5. **替客户编需求**——"我知道您最近要备货"这类话，一旦猜错，专业形象直接归零。
