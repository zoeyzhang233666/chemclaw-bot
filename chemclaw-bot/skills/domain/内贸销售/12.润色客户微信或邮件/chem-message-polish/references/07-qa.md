# 07 · 质检与交付

## 一、脚本自动检查（`validate_case.py`）

| 代码 | 检查 | 级别 | 触发后 |
|---|---|---|---|
| `SCHEMA_MISSING` | 缺必需字段（meta/product_profile/facts/versions/audit/audit_summary/placeholders/scenarios） | ERROR | 补齐 `case.json` |
| `VERSION_INCOMPLETE` | 缺 A/B/C/D 任一个，或某版没有任何正文 | ERROR | 补齐 |
| `UNSOURCED_NUMBER` | 正文出现无法溯源的数字+单位 | ERROR | 删除或改【待填】，或把它登记进 `facts`／`allowed_numbers` |
| `UNSOURCED_NUMBER_CN` | 正文出现中文数量（两车、三批…） | WARN | 核对是否真有出处 |
| `BANNED_PROMISE` | 承诺词（一定/保证/绝对/可以再谈/给您申请/免费/包运费/最低价…） | ERROR | 降级或删除 |
| `FAKE_SCARCITY` | 稀缺话术（货源紧张/库存不多/马上涨价/最后两天…） | ERROR | 删除，或补真实依据 |
| `BANNED_PHRASE` | 命中 `product_profile.ban_phrases` | ERROR | 改写 |
| `PLACEHOLDER_MISMATCH` | 正文（A/B/C/D）【待填】处数 > 清单条目数 | ERROR | 补登记占位符 |
| `PLACEHOLDER_NO_OWNER` | 占位符没写确认人 | ERROR | 补 `owner` |
| `AUDIT_INCOMPLETE` | 事实未进审计表 | ERROR | 补齐 |
| `AUDIT_SYMBOL_MISSING` | 审计格为空 | ERROR | 不允许留空（判不了就填 `—` 并说明） |
| `BOUNDARY_NOT_ZERO` | `audit_summary` 里价格/折扣/交期/客户需求项不为 0 | ERROR | 回头删掉新增内容 |
| `CHANNEL_TOO_LONG` | A 版 > 220 字；B 版 > 80 字 | WARN | 压缩 |
| `MULTI_REQUEST` | 某一版问号 ≥ 3 个 | WARN | 拆成一条消息一个请求 |
| `EMAIL_NO_SUBJECT` | 有邮件版本但无主题行 | ERROR | 补 `email.subject` |
| `FACT_UNUSED` | 标为「可用」的事实，在四个版本里全为 `—`/`▲` | WARN | 复核是否漏用 |

> 刻意不提示的两类：标为「谨慎／建议删除／禁止直发／不进正文／作话题」的事实，
> 本来就该全部 `—` 或 `▲`，不触发 `FACT_UNUSED`；清单条目多于正文占位符也不报错
> （清单要覆盖场景版与邮件落款里的位置）。

`run_all.py` 在 ERROR 存在时**拒绝生成产物**。要强制生成，只有 `--force`，产物自检仍会如实报告。

## 二、人工复核（脚本查不了）

1. 每条 `✔` 是不是真的保留，而不是换个说法。
2. 每条 `▲` 的说明是否写了替代方案，而不是只写"已删除"。
3. `customer_profile` 里的**推断项**（如"偏好短消息""回复慢"）有没有被写进正文——推断只能用于内部判断。
4. 正文里有没有"看起来像事实，其实是语气"的句子（"您这边应该也在比价吧"）。
5. 客户读到第一句，能不能在 3 秒内知道"这条消息要我干什么"。
6. 假设这条消息被转发给客户的采购经理或副总，是否仍然得体。

## 三、交付前清单

- [ ] `run_all.py` 无 ERROR，且自检「通过」
- [ ] `audit_summary` 五个新增项全为 0
- [ ] 正文【待填】处数 ≤ 占位符清单条目数，且每条都有确认人
- [ ] 邮件版有主题行、编号、口径、有效期
- [ ] 微信版 ≤220 字，一条消息一个请求
- [ ] 客户/产品名与 `meta` 一致
- [ ] 若客户为虚构，页脚有声明
- [ ] 引用的国标/行业经验值有出处，并标注"非该客户实测数据"
- [ ] 产物命名：`<客户简称>_<场景>_沟通润色.xlsx / .html`

## 四、产物自检（`check_outputs.py`）

- xlsx：ZIP 结构完整、11 张表齐全且表名顺序一致、无空表、关键串存在（"边界审计""【待填】"）、审计行数与 `case.json` 一致
- html：单文件、无外链（`http` 引用与外部 `script/link` 为 0）、id 无重复、注入的 JSON 可解析且 `file_stem` 一致
- 建议另跑一次无头浏览器渲染（`msedge --headless=new --dump-dom` 或等价命令），确认
  各区块的 JS 渲染结果非空——纯静态检查看不出"脚本报错导致整页空白"。

## 五、常见误判（写给你自己看）

| 现象 | 其实是什么 | 怎么改 |
|---|---|---|
| 客户不回 | 多数不是"没时间"，是这条消息要他做的动作成本太高 | 把请求降到"回一个字"或"看一眼" |
| 客户说贵 | 一半是口径不同（含运费/含税/账期） | 先问口径，不先让价 |
| 客户说再看看 | 他在等另一家，或内部没预算 | 给一个不占他时间的资产（质检单、试用结果、行情口径） |
| 客户突然热情 | 他那边可能断供了 | 此时最要守边界：越热的客户越会要账期与让价 |
