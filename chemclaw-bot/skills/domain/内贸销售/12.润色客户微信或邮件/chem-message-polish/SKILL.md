# 化工品客户沟通润色（chemical-sales-message-polish）

把「我这条消息发不出去 / 发出去怕说错」变成一个**能直接复制、且每个字都有出处**的商务文本，同时交付 Excel + HTML 两份附件。

## 这个 skill 解决什么

销售写完一条微信或邮件，通常是三种毛病：三个诉求塞一条、催得太明显、顺手许了不该许的诺（可以再谈 / 一定配合 / 货源紧张尽快定）。
本 skill 不改用户的生意判断，只做三件事：**把事实拆开、把顺序排好、把越界标出来**。

| 输入 | 输出 |
|---|---|
| 一段原话 + 客户/产品背景（+ 上一轮沟通记录） | `out/<客户>_<场景>_沟通润色.xlsx`（11 表）<br>`out/<客户>_<场景>_沟通润色.html`（单文件可交互）<br>`case.json`（唯一真源，可复用、可改） |

## 什么时候用 / 不用

**用**：报价跟进、催款、解释涨价、送样安排、约见拜访、客户已读不回、要把口语版改成邮件版、要把邮件改得像人话。
**不用**：客户投诉/质量事故的正式回复（要走客诉流程与法务）、招投标文件、合同条款起草。这三类不属于「润色」，属于「责任文书」——直接告诉用户，别硬套。

## 五步流程

### 第 1 步：收料（一次问全）
必须拿到：**原话全文**、产品与规格、客户（企业+角色+决策链）、渠道（微信/邮件/电话/当面）、本次目标（约见/报价跟进/催款/涨价/送样）、背景、上一轮沟通记录。
缺哪项就**问一次**，别边写边问。用户没给的商业条款（价格、账期、交期、库存、月用量）**不许自己填**——见第 3 步的占位符规则。

### 第 2 步：抽事实台账（F1…Fn）
把原话逐句拆开，每条给三个属性：

| 属性 | 取值 | 说明 |
|---|---|---|
| 类型 | `事实` / `意图` / `承诺` / `推测` / `无据背书` / `无据施压` / `越权让价` | 后四类是要处理的对象 |
| 来源 | `原话` / `上一轮` / `客户档案` / `产品档案` | 决定它能不能写进正文 |
| 处置 | `可用` / `谨慎` / `需改写` / `建议删除` / `禁止直发` | 处置结论要能落到具体句子 |

判别口径（照 `references/01-method.md`）：
- **事实**：能拿出证据（寄了样、发了报价、客户说过什么）。
- **承诺**：任何"我方将来会为对方做某事"的表述。过宽的（一定配合、随时可发、给你留着）一律降级为"核实后回您"。
- **无据背书**：很多厂都在用、质量最好、行业第一 —— 换不掉证据就删。
- **无据施压**：货源紧张、马上涨价、最后两天 —— 没有库存表/检修计划/调价函就删。
- **越权让价**：可以再谈、给你申请、最低给你 —— 没有书面授权就删。

### 第 3 步：建产品档案，决定"哪些话能说"
这是**唯一需要化工行业知识**的一步，也是本 skill 能跨品类复用的关键。照 `references/03-product-profile.md` 填 `product_profile` 段：

形态（固/液/气）、是否危化品及资质要求、包装与运输方式、该品类客户通常卡哪几个验收指标、价格口径（出厂/到厂/库提、含税、承兑加价）、账期惯例、下游行业与工艺痛点、季节性风险、**该品类的禁语**。
例：纯碱不提"绝不结块"、液碱不提"永不结晶"、危化品不提"无证也能送"、尿素不替客户判断用肥季节。

产品档案的作用不是写进正文，而是**决定哪句话会变成事故**。`product_profile.ban_phrases` 会被校验脚本逐条扫正文。

### 第 4 步：出主版本 + 三个开关
写进 `case.json` 的 `versions`：至少 4 个版本，key 固定为 `A`（自然，默认推荐）、`B`（更短）、`C`（更正式/邮件）、`D`（更缓和）。原文放 `P0`。
- 微信版：一句一行、一行一个信息点、结尾留一个开放问题，**全文 ≤ 220 字**。
- 邮件版：主题行 + 分条（一、二、三）+ 落款，**必须留编号/口径/有效期占位**。
- 一条消息**只提一个请求**（约时间 / 要反馈 / 发单据，三选一）。

### 第 5 步：边界审计 + 占位符 → 跑脚本 → 交付
每个版本 × 每条事实给一个判定：`✔` 保留 / `◐` 弱化改写 / `—` 刻意未提 / `▲` 已删除。审计不是走过场：`▲` 必须能在文本里验证到"真的没有"。

然后：

```bash
python scripts/run_all.py --case case.json          # 校验 + 生成 Excel + HTML + 自检
python scripts/validate_case.py --case case.json    # 只跑边界守卫
```

`run_all.py` 会拒收以下情况（这是本 skill 的硬约束，别绕过）：
- 正文出现**未经提供的数字**（元/吨、吨、天、%、kg…）→ `UNSOURCED_NUMBER`
- 出现承诺词（一定/保证/绝对/可以再谈/给您申请/免费/包运费…）→ `BANNED_PROMISE`
- 出现稀缺话术（货源紧张/库存不多/马上涨价…）→ `FAKE_SCARCITY`
- 出现产品档案里的禁语 → `BANNED_PHRASE`
- `【待填】` 多于占位符清单条目 → `PLACEHOLDER_MISMATCH`
- 事实台账里有条目没进审计表 → `AUDIT_INCOMPLETE`

| `00_使用说明` | 四红线、五步法、工作簿导航、可复制提示词框架 | 页脚 RULE 01–04 |

| `04_边界审计` | n 条 × 4 版本逐格判定 + 新增项计数（必须全 0） | §06 审计 |
| `05_场景矩阵` | 约见/报价跟进/催款/涨价/送样，各一套可直接发 | §08 场景 |
| `06_占位符清单` | 每个【待填】的确认人与填错后果 | §07 待填 |
| `07_快速调整指令库` | "再短一点/更正式/更适合微信"命中的具体改法 | §05 调整 |
| `08_发送前检查清单` | 10–12 项，带下拉状态与通过计数 | §10 清单 |
| `09_追问应对` | 客户 5–6 种回法 + 禁止说法 | §09 追问 |
| `10_复盘看板` | 指标汇总 + 版本评分图 | §04 版本切换 |

HTML 是**单文件自包含**（CSS/JS 全内联、无外链），可离线、可发微信、可打印。

## 铁律

1. 用户的**原意与全部事实**必须保住——包括他写得不体面的那句，也只能改写不能消失（除非是越界项，那要显式标注后删除）。
2. 没提供的商业条款一个字不写。**宁可留 10 个【待填】，不许猜 1 个价格。**
3. 润色不做销售策略。客户值不值得让价、要不要放账期，是业务与财务的决定，脚本只负责不让它被一句顺口话许出去。
4. 客户是虚构就标虚构；引用了国标、行业经验值，就在页脚写清出处与"非该客户实测数据"。
