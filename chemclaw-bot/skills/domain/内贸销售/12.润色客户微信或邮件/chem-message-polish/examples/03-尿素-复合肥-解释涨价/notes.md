## 一、一句话说清这个案例在练什么

前两个示例处理的是「客户不说话」和「客户不付钱」，主动权在我们这边。
涨价不一样：**我们要主动递一个坏消息，而且递完之后客户会立刻追问两个数字——哪天生效、涨多少。**

这个案例的全部难点不在措辞，在这两件事：

1. 那两个数字，我们**还没有**（上游通知已到、正式调价函未出）；
2. 客户上月刚提过锁价，等于提前埋了一个「顺便给我锁一下」的钩子。

所以这一例的目标不是「把涨价说得软一点」，而是：**在数字还没有的时候，先建立一个可信的、可留痕的报价秩序。**

## 二、案例看点（五个）

| # | 看点 | 为什么值得看 |
|---|---|---|
| 1 | **主渠道是邮件，不是微信** | A 版与 C 版都是邮件体，HTML 里渲染成邮件卡片（主题行 + 分段），B/D 才是手机气泡。渠道一换，判据全变：邮件要留痕、要能被转发、要有编号；微信要短、要一句话一个信息点。 |
| 2 | **「敢写位置，不填数字」** | A/B/C 三版都把那两个关键数字的位置留着（`自【待填】起执行新价，幅度【待填】`），但一个字都不猜。含糊其辞（「下个月要涨，涨多少还在等」）反而让客户怀疑你在试探他。 |
| 3 | **缓冲窗口是这一版最值钱的一句** | `在此之前仍按现价执行，执行到【待填】为止` —— 它把「涨价」从一次单点通知，变成一个有开始有结束的窗口。客户真正要的从来不是「别涨」，是「给我时间安排」。 |
| 4 | **锁价：认领诉求，不给结论** | 客户上月提的锁价必须被看见（不认领＝不尊重），但只能写到「已记录、须审批、核实后书面回复」。三个动作，一个结论都不给。 |
| 5 | **四处越界显性处理** | 原料暴涨（编理由）、这两天先定（假期限）、尽量给您保持（越权让价）、亏了算我的（无限承诺）——全部 `▲` 删除，并在审计里写清替代方案。 |

## 三、四个版本为什么这么分工

| 版本 | 媒介 | 定位 | 关键判断 |
|---|---|---|---|
| **P0** | 微信 | 原文原样保留 | 不美化。P0 里那句「原料涨得没边了」是后面所有改写的靶子，删之前必须先被看见。 |
| **A** | **邮件** | 自然口语化的邮件版（默认推荐） | 五个短段：报备 → 日期与幅度 → 缓冲 → 锁价认领 → 可选动作。全文 203 字，克制在「一封不像公文的邮件」的长度里。 |
| **B** | 微信 | 更短，58 字 | 只留「报备—日期—幅度—缓冲」四个信息点。**幅度让位给正式函**：微信里报数，第二天就被截图转发出去了。 |
| **C** | **邮件** | 最正式的调价函预告版 | 四段：依据 → 执行口径 → 锁量与锁价 → 可选动作。函件编号、幅度、生效日、截止日、锁量、锁价期限六处全部留位，客户内部转发不用改一个字。 |
| **D** | 微信 | 缓和版 | 不设任何动作要求，只保住「不让您从别处听说」这一点体面。适合关系刚经历摩擦、或客户已明确反感「通知式涨价」。 |

**A 为什么是邮件而不是微信？** 因为这一轮要递的三件事（依据、日期、缓冲）都需要事后被引用。微信里的「我说过现价执行到某日」，一周后没人能证明。渠道升级规则在这里是硬性的：**涉及价格条款，一律补邮件。**

**A 与 C 的分工：** A 是「先跟人说一声」，C 是「可以入档的那份」。A 不主动对锁价表态（避免把话题引到钩子上），C 把锁价写成一段有边界的话（客户已经提了，不能装没听见）。

## 四、涨价沟通特有的三条边界

这三条是本案例最值得写进方法论的判断，也是这一例与前两例最不一样的地方。

### 边界一：不编涨幅，也不假借「原料暴涨」

原话里最顺口、也最危险的一句是「原料涨得没边了」。它有两个毛病：

- **来源不成立**：上游为什么涨，不归销售替它讲；讲了就是替别人编理由。
- **后果不可逆**：一旦正式函上的幅度小于「没边了」给人的预期，客户会认为自己被耍了一次——**下一次涨价，他连函都不会看。**

**合法替代**：`我司已收到上游调价通知（函件编号【待填】）`。一句话、一个可核对象、零解释。理由由函件说，不由销售说。

### 边界二：缓冲可以给，让价不能给——两者只差一句话

| 写法 | 性质 | 能不能写 |
|---|---|---|
| 「在此之前仍按现价执行，执行到【待填】为止」 | 调价函的**生效缓冲**，属政策事实，对全部客户一致 | ✅ 能写，且必须写 |
| 「价格上我尽量给您保持」 | 对**这一个客户**的个案让价 | ❌ 不能写 |

这一条最容易含混：两者听起来都是「帮你留住老价格」。区别在于——前者是政策，后者是授权。销售手里只有前者。

所以审计表里 F11（尽量给您保持）判定 `▲`，但 A/C 里保留了现价窗口，并在审计说明里写清：**它不是对个案的让价，且截止日必须由正式函确认。** 如果不写这句说明，读者会以为我们一边删让价、一边偷偷让价。

### 边界三：锁价、保底、锁量——只能报审批，不能报结论

客户提「锁一下价」，本质是让公司承担跌价风险。销售能做的只有三件事：**记下、上报、核实后书面回复**。

三个动作里有三个不能碰：

1. 不能替客户算「锁了能省多少」——那是替他做经营决策，而且暗示了幅度；
2. 不能给条件（「锁多少吨可以锁多久」）——条件本身就是一个报价；
3. 不能说「我去给您申请」——申请是内部动作，说出口就变成了对外承诺。

**合法写法**：`拟锁量【待填】吨、锁价期限【待填】……须经审批；能否执行及执行条件，我核实后书面回复，本函不作承诺。`
把「待填」放在正文里，把决定权交回给有权限的人——这才是专业，不是推诿。

### 附带一条（农化专用）：不替客户判断季节与备货

复合肥厂比销售更懂自己的配方与用肥节奏。「您这边该备货了」「春耕前得先把量锁住」这类话，看着像关心，实际是在替客户判断他的生意。本案例把它写进 `ban_phrases` 的邻近规则并落在审计 F6：**「客户为复合肥企业、尿素是主要氮源」这条事实，四个版本里一次都没进正文。** 它只用来决定议题，不用来说服。

## 五、数据核对

| 项 | 数量 | 说明 |
|---|---|---|
| 事实台账 | 12 条（F1–F12） | 覆盖：上游通知 / 我方成本与库存（待填）/ 客户锁价诉求 / 客户结算方式 / 我方报备意图 / 客户工艺 / 提货节奏 / 采购等级 / 四处越界表述 |
| 边界审计 | 12 行 × 4 版 = 48 格 | 每格都有文本依据；`▲` 六处均已在正文验证删除 |
| 占位符 | 10 条（P1–P10） | 正文【待填】合计 10 处，与清单一一对应，**不多不少** |
| 正文【待填】分布 | A=3 / B=1 / C=6 / D=0 | 涨幅、生效日、现价截止日在 A 与 C 双份出现；锁量吨数、锁价期限、函件编号只在 C 出现 |
| 字数 | A 203 / B 58 / C 370 / D 124 | A ≤220（邮件但不啰嗦）、B ≤80（微信一条） |
| 场景 / 追问 / 清单 / 规则 / 调整 | 5 / 6 / 12 / 4 / 7 | 场景含主场景「解释涨价」，另配锁量锁价、函件跟进、送样、约见 |

**为什么 A 只放 3 个【待填】、C 放 6 个？** 因为占位符总数受「正文【待填】≤ 清单条数」硬约束。分配原则是：**A（第一封信）只放客户最急的两个数 + 缓冲日；C（可入档那份）才把函件编号、锁量、锁价期限一并摆出来。** 一封邮件里塞六个空格，客户会觉得你没准备好；分到两封信里，就是「先报备、再细化」的正常节奏。

## 七、虚构与免责

本案例中的客户、产线与人员均为**虚构示例**（山东临沂 B复合肥有限公司 / 孙经理 / 王磊），用于演示涨价沟通的润色流程，不对应任何真实企业或个人信息。

唯一引用的真实背景：**GB/T 2440-2017《尿素》** 为现行国家标准；颗粒尿素的常规验收指标（N 含量、缩二脲、水分、粒度、颗粒强度）出自该标准与行业通行口径，**具体数值以本批质检单和客户合同为准，非该客户实测数据。**

复合肥配方中的氮素占比随配方变化，本工作簿**不引用任何用量经验值**；客户月需求量、锁量吨数、结算方式一律留空为【待填】——这不是遗漏，是规则本身。

上游调价函件编号、幅度、生效日期、现价执行截止日，在正式函出具前一律不得填写。**预告口径与正式函不一致，是涨价沟通里最常见、也最难挽回的事故。**
