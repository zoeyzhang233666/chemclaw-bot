# 整理客户跟进记录（化工品 · 内贸销售）

把一堆散落的微信截图、邮件、会议纪要、报价单，变成**一页能直接执行的跟进卡**：客户说过什么、反对什么、我们承诺了什么、还差什么没确认、现在卡在哪、下一步做什么。

适用于任何化工品（纯碱、甲醇、钛白粉、树脂、助剂、溶剂……），也适用于其他工业品内贸。方法与机器无关。

整件事只围绕一个原则：**证据不混层**——客户说的、我方说的、模型猜的，三样东西永远不能混在同一句话里。

## 三条不可谈判的约束

1. **客户没说过的需求，一个字都不补。**
   「客户应该也需要账期」「做涂料的肯定要 25kg 包装」——这类推断一律不得进入「客户需求」表。可以进「AI 摘要」并标明是推断。销售拿着编出来的需求去谈判，比没有跟进卡更糟。

2. **无法辨认的内容单独列，不许猜完混进正文。**
   模糊截图、没转写的语音、被遮挡的比价表、潦草手写、缺的附件——全部进「待确认」一节，并在提问里写清"需要你做什么"。

3. **AI 摘要必须与事实物理隔离。**
   单独的区块、虚线边框、"AI 推断 · 非客户原话"徽章。事实区不许出现"我判断""预计"这类字样。

---

## 第 0 步：收料与定契约（一次问全）

用户往往只会甩一句"帮我整理下"，所以先用一次提问把四件事问清，每件都给推荐值：

| 要素 | 为什么要问 | 推荐默认 |
|---|---|---|
| **产品与牌号** | 决定要抓哪些规格字段（纯度、细度、白度、粘度……） | 从素材里读，读不到再问 |
| **客户与厂区** | 多厂区客户必须分开记（泰州厂 ≠ 南通基地） | 全称 + 厂区 |
| **时间基准 as_of** | 停滞天数全靠它算 | **今天**，不要用素材最后一天 |
| **交付物** | 默认 Excel + HTML | Excel 工作簿 + 自包含 HTML 卡（+ 可选 Markdown） |

如果用户已经给了明确素材和产品，别啰嗦，直接进第 1 步，把不确定项放进「待确认」。

---

## 第 1 步：素材清点与证据编号

先建一张**素材清单**，给每份素材一个稳定的短编号——后面每条事实都要挂它。

```text
SOURCE 01  微信截图 OCR ×13   09-18 → 10-14
SOURCE 02  邮件往来 ×4        10-09 → 10-13
SOURCE 03  会议纪要 ×1        10-09 来厂考察（扫描件，第2页有手写）
SOURCE 04  报价单 ×1          10-12（页边手写）
```

编号规则：同一份素材内部按出现顺序编 `截图1…截图N`、`邮件1…邮件N`、`纪要1…纪要N`。**引用时精确到条**（"截图4"而不是"微信里"），否则三个月后没法复核。

清点时顺手标出三类"脏数据"，它们注定要进待确认：
- 语音未转写（OCR 抓不到，最容易漏掉关键条件）
- 截图被裁剪/遮挡（比价表、报价单最常被挡）
- 扫描件手写批注（数字最易糊：`1?30` 是 1630 还是 1530）

细节规则见 [`references/extraction.md`](references/extraction.md)。

---

## 第 2 步：抽时间线（先铺平，再分层）

按时间正序逐条抽，一条记录一行。字段固定：

| 字段 | 说明 |
|---|---|
| `no` `date` `time` | 只有月日时，按 as_of 推断年份 |
| `source` | 证据编号，精确到条 |
| `actor` | 客户 / 我方 / 双方 / 系统 |
| `category` | 见下方七类，**这是分层的锚点** |
| `text` | 原话用 `「」` 包起来；我方转述不加引号 |
| `flag` | 可选标记：停滞起点 / 最后一条 / 逾期 / 无法辨认 |

七类标签（前四类是事实层，后三类是动作层）：

`客户需求` `客户异议` `我方承诺` `待确认` ｜ `客户动作` `我方动作` `系统提醒`

**先铺平再分层**：不要一边读一边分类，容易把"客户问价"记成"客户需求"。先按时间排完，再回头打标签。

---

## 第 3 步：四类分层（本 skill 的核心）

这四类的边界最容易糊，判错一条整张卡的可信度就没了。

### ① 客户需求：客户**明确说出**的条件

收：品类、规格（含内控指标）、数量、价格预期、交期、付款方式、包装、交地、采购流程、质量验证要求、未来意向。

不收（这是最容易犯的错）：
- 客户只是**问价**，不等于有采购需求——记「客户动作」，不是需求
- 客户**没有反对**某项条件，不等于接受
- 我方在报价单里写的条件，是**我方立场**，不是客户需求
- 行业惯例（"化工都是月结"）不是客户说的

每条必须带 `confidence`：高（原话直述）/ 中（口头转述、纪要概括）/ 低（推断，需核实）。

### ② 客户异议：客户明确的不满、拒绝、条件对抗

判断标准：客户说了"不""太高""不行""担心"。

关键区分：**"已回应" ≠ "已解决"**。我方让了价，但客户没接受——状态还是"未解决"。状态只有四种：未解决 / 待验证 / 已解决 / 结构性（短期无解，如长约未到期）。

### ③ 我方承诺：我方说出口的、有交付物的

只要说了"X 日前给你""可以做""能写进合同"，就是承诺，**必须闭环**。

状态不做人工判断，由**截止日 vs as_of 自动算**：已兑现 / 未到期 / 今日到期 / 逾期 N 天。逾期的置顶提醒——这是这类工具最有价值的一个输出，因为业务员自己往往记不住。

注意：口头"介绍一下我们的产能"不算承诺；"把保供条款写进合同附件"算。

### ④ 待确认：还没定的事

包含四种来源：交易条款没谈拢、信息缺口（客户的罐容、月用量没给准数）、证据缺失（手写数字认不出）、流程不清（特批入库怎么走）。

必须写清 **卡在谁**：我方财务 / 客户采购 / 客户安环 / 需用户补料。写不出责任方的待确认项，等于没有。

> 完整判定口径、20 个易混案例见 [`references/extraction.md`](references/extraction.md)。

## 第 4 步：阶段判定与停滞计算

### 六阶段

`初次接触` → `需求确认` → `送样` → `报价谈判` → `合同` → `停滞`

判定看**证据**，不看感觉：

| 阶段 | 进入条件（必须能指到证据） | 常见误判 |
|---|---|---|
| 初次接触 | 建立联系、拿到需求线索 | 客户只问了一句价，不算需求确认 |
| 需求确认 | 规格/数量/包装/交地全部有书面 | 客户给了用量但没给规格，仍停在需求确认 |
| 送样 | 样品/小批量已发出 | 大宗液体无"样品"，用**试供**替代，同样算送样 |
| 报价谈判 | 正式报价已出，且客户有还价或明确反馈 | 报价了但客户没回，可能仍是报价谈判（看是否还价） |
| 合同 | 条款文本在双方流转 | **草稿发出 ≠ 合同阶段**，要有对方反馈 |
| 停滞 | 超过阈值无客户实质回复 | 详见下方"催办不算推进" |

### 停滞天数（唯一口径）

```
停滞天数 = as_of − 最后一次「客户实质回复」日期
```

- as_of 用**今天**，不是素材最后一天。素材给到 10-15、今天 10-19，就要按 10-19 算，并在卡里写明口径变化。
- **客户实质回复** = 客户方发出的、带业务信息或态度的消息。
- **催办不算推进**：客户 10-12 只发了句"资质文件什么时候给"，业务实质停在 09-28。这时应写"停滞 7 天（业务实质停在 09-28，共 21 天）"，两个数都给，别只挑好看的那个。

### 停滞原因要分型

不同型打法完全不同，别一律写"客户在犹豫"：

| 型 | 特征 | 打法 |
|---|---|---|
| 流程型 | 客户内部比价/审批/法务在过 | 给材料、给措辞，降低对方内部成本 |
| 价格型 | 明确还价且未接受 | 找价值锚，别裸降 |
| 资质型（危化品高频） | 安环/资质核验卡住 | 补文件，这是自己能动的事 |
| 结构型 | 长约未到期、产能锁死、项目未投产 | 不催单，做窗口前准备 |
| 我方型 | 我方承诺逾期、内部没批复 | 先修自己，别怪客户 |

原因库见 [`references/stages.md`](references/stages.md)。

## 第 5 步：字段确认（让用户点头，再出卡）

生成跟进卡前，先出一张**关键字段确认表**：字段 / 提取值 / 出处 / 置信度 / 标记。

置信度规则：
- **高**：客户原话直述，可引用
- **中**：口头转述、纪要概括、二手信息
- **低**：推断、或来源本身模糊（手写数字、被遮挡的截图）
- **无法辨认**：干脆读不出来，进待确认

低置信度的字段要显式标记"请确认"，不要让它悄悄混进结论。

## 第 6 步：生成交付物

数据先落成一份 JSON（契约见 [`references/schema.md`](references/schema.md)），再一条命令出全套：

```bash
python scripts/build_followup.py followup.json -o out/ --md
```

输出：

| 文件 | 内容 |
|---|---|
| `out/<slug>.xlsx` | 10 个工作表：跟进卡仪表盘、时间线、四类清单、阶段与下一步、待补素材、字段确认（带下拉）、图例口径 |
| `out/<slug>.html` | 自包含跟进卡：阶段轨道、可筛选时间线、四类 Tab、AI 摘要分区、勾选确认、联动面板，可打印 PDF |
| `out/<slug>.md` | 纯文本摘要，方便贴进 CRM 或周报 |

改数据就改 JSON 重跑，不要手改 Excel/HTML——单点修改会漏掉计数、停滞天数、逾期状态的联动。

交付前跑自检：

```bash
python scripts/selfcheck.py followup.json --outdir out/
```

它会核对：停滞天数与时间线是否自洽、逾期承诺是否与截止日一致、Excel 时间线条数是否对得上、HTML 标签是否闭合、有没有文字被行高裁切。

## 化工品适配：不同品类多抓哪些字段

同一个流程，字段重点随品类变。生成前对着这张表补：

| 品类形态 | 必须额外确认 |
|---|---|
| **危化品**（甲醇、烧碱液碱、双氧水…） | 危化品经营许可证、危险货物道路运输许可、罐车检验、押运员资格、MSDS、灌装与卸车条件、罐容 |
| **大宗固体袋装**（纯碱、元明粉…） | 包装规格（25/50/1000kg）、托盘与打膜、码垛、卸货能力、汽运/铁路 |
| **粉体填料**（钛白粉、碳酸钙…） | 白度、吸油量、细度、分散性、批批 COA、遮盖力 |
| **树脂/聚合物** | 牌号、熔指、软化点、包装（25kg 袋/吨包/散装槽车）、储存温度 |
| **助剂/小包装**（阻燃剂、偶联剂…） | 添加量、配伍性、小试支持、最小起订量 |
| **溶剂** | 纯度/水分、危化资质、闪点、桶装/槽车、退货与空桶回收 |

通用但高频的坑：含税否、含运费否（到厂价 vs 出厂价）、承兑贴息谁承担、账期起算点（验收日 vs 开票日）、报价有效期。

## 常见失败模式

| 症状 | 原因 | 修法 |
|---|---|---|
| 卡里全是"客户希望""客户倾向于" | 把推断写成了需求 | 删掉，移到 AI 摘要并标"推断" |
| 停滞天数算小了 | 用了素材最后一天当今天 | as_of 改成今天，全文重算 |
| 逾期承诺没提醒 | 只信人工写的状态 | 交给 `promise_state()` 按截止日算 |
| 同一条信息既在需求又在异议 | 没有先铺平再分层 | 回到时间线，一条记录只挂一个分类 |
| 客户三个月后问"这数字哪来的" | 缺 source | 每条事实挂到截图/邮件编号 |
| Excel 与 HTML 数字对不上 | 手改了其中一个 | 只改 JSON，两个都重新生成 |
| 客户说"我没提过这个" | 把我方报价条件当成客户需求 | 需求表只收客户原话 |

更多见 [`references/failure-log.md`](references/failure-log.md)。
