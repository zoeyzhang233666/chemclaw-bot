# 化工品采购商机研究 · 六步法

> **适用**：任意化工品/规格 × 任意目标地区 × 任意时间窗。本文正文规则**与产品无关**，「纯碱」只作举例。
> **输入**：我销售【某化工品/规格】，目标市场【地区】，最小订单规模【可选】。
> **输出**：近期采购商机清单 —— 「明确采购/招标」与「推断的潜在需求」两组分开，每条给出企业、事件类型、发布与截止日、涉及产品与数量、与我产品的关系、时效性、**可点原文出处**；附过滤规则与剔除说明。
> **配套**：[`product-profiling.md`](product-profiling.md) 建产品画像 ｜ [`channels.md`](channels.md) 通道清单与取数 ｜ [`gates.md`](gates.md) 六道闸门与优先级。

## 0. 六条铁律（先读完再开工；违反任一条，整批结果作废）

| # | 铁律 | 为什么（实测踩过） |
|---|---|---|
| **L1** | **每条线索必须有可点的原文出处。** 拿不到 → `证据来源=未核实`、`置信度=低`，单列到工作表「5 待核实（无原文链接）」，**不进正式商机池**。**严禁编造 URL、标题、企业名。** | 猜一个像样的域名比留空有害得多：销售点开是 404 或别人家的公告，整份清单立刻失信。宁可少几条。 |
| **L2** | **同行不是客户**，且**身份必须逐条核验年报业务分部**，绝不能看名字判断。两个方向相反的陷阱都要防。 | 名字像同行、实际是买方：**振华股份 603067** 是铬盐企业，公告自述纯碱为主要成本项、披露纯碱采购，属客户。名字像客户、实际是同行：**金晶科技 600586** 名字像玻璃客户，但其 2025 年报「纯碱业务」载明运营主体为控股子公司山东海天生物化工，是纯碱生产商。把同行当客户报给销售是最伤信任的错误；反向误杀则直接丢单。 |
| **L3** | **标题检索与全文检索必须都跑。** 任何异常为 0 的结果一律视为「未验证」，换参数/补请求头重试后再下结论。 | 实测同一词的公告标题命中 **0 条**、全文检索命中 **164 条**。只看标题会得出「没有需求」的错误结论；缺请求头还会**静默返回假 0**。 |
| **L4** | **一条公告可能同时含利空与商机，必须按产品拆条**，不能按公告整条判断。 | 实测一份《投建年产10万吨过碳酸钠及3万吨纯碱》公告：3 万吨纯碱部分＝同行新增供给＝利空；10 万吨过碳酸钠部分＝纯碱下游新增需求＝利好。按整条判，必丢一头。 |
| **L5** | **子代理的上下文是易耗品**：先落盘再汇报，限制抓取次数，**每 5 条增量落盘**。 | 上下文一旦被截断，没落盘的全丢；攒到最后再写＝随时归零。 |
| **L6** | **同一主体的一簇证据可能同出一份文档**，不得重复计为多个独立线索源。 | 实测某主体（含子公司与收购标的）的多条线索同出一份重组报告书/法律意见书，是 1 个主体而非 4 个独立来源；重复计数会虚增条数、误导销售。 |

## 第 1 步 · 定契约（一次问全，避免反复返工）

**做什么**：用**一次提问**问全下面 5 项，填进报告头（`report_header`）。缺项时给默认值并在交付物里写明「这是默认值」。

| 项 | 要问到什么程度 |
|---|---|
| 产品 | **学名 ＋ 俗名 ＋ 英文名 ＋ 规格**（纯度/牌号/目数/重质或轻质/工业级或食品级/包装形态），以及是否只做其中某个规格 |
| 目标区域 | 省/市**清单**（闸门用），并问一句「区外货源是否接受」 |
| 时间窗 | 绝对日期区间：发布日窗口 `WIN_START~WIN_END` ＋ 基准日 `TODAY`；默认近 90 天并单列近 30 天 |
| 最小订单规模 | 可选；客户留空时给一个默认门槛（例：≥ 300 吨/单）并在报告里声明是默认值 |
| （可选）已有客户名单 | 用来在 R1 里区分「已知买方/已知同行」，并在收口时避免把老客户当新商机 |

**完成判据**：5 项都能直接填进报告头；产品名能推出检索词库的种子（学名＋俗名＋英文名）；区域能推出「区内/区外」判定；时间窗能给出发布日区间与基准日。

**常见失败模式**：分多轮追问（每轮都让子代理返工）；只拿到商品名、没拿学名/英文名（**实测同一平台「碳酸钠」命中 6 条而「纯碱」命中 0 条**）；时间窗只写「近期」导致 R4 无法判定；最小订单规模空着不设默认，最后被零星试剂级采购淹没。

## 第 2 步 · 建产品画像 → [`product-profiling.md`](product-profiling.md)

**做什么**：不写字，先建「下游应用地图」。本文只规定它的**作用与产物**，写法与模板见 [`product-profiling.md`](product-profiling.md)。

产物四件：

1. **下游应用地图**：这个产品被谁用、用在哪个工序、是**直接投料**还是经中间体**间接**使用、有没有替代品（替代品是 R2 误配清单的来源）。
2. **吨耗系数表**：每个下游一行，`t 本产品 / t 下游产品`（或 kg/t），标来源、标区间、标「（估算）」。系数怎么来见 [`gates.md`](gates.md) 末节。
3. **同行名单 ＋ 同行判据关键词**：能生产本产品的主体名单（每个名字附原文依据），以及一套**工艺路线关键词**（用于 R1 兜底：名单没覆盖时靠路线词判新增产能）。
4. **检索词库**：学名、俗名、英文名、规格别名、上游中间体名、下游产品名，＋一类「事件词」（招标/询价/中标/采购/框架协议/复产/投产/试生产/点火/冷修/技改/扩产/达产/提负荷/环评）。

**完成判据**：每个下游方向都同时具备 ① 吨耗系数 ② 至少 1 个检索词 ③ 至少 3 家具名候选企业；同行名单每一项都能回答「凭什么说它是同行」（附原文出处）；词库里学名与俗名都在。

**常见失败模式**：把下游写成行业百科（落不了 lane）；吨耗系数不标来源、不标「估算」；同行只按名字列（违反 L2）；词库只有俗名（违反 L3）。

## 第 3 步 · 探通道并写下「本次可用通道清单」→ [`channels.md`](channels.md)

**做什么**：开工前先跑一次**可用性探针**，把本次真正能用的通道写成清单，供所有 lane 复用；清单里必须含：

- 通道分级（A＝官方一手且可全文检索 / B＝官方一手但只能列表翻页 / C＝二手聚合）＋ **可复制的取数命令/URL 模板**
- 每个通道的**检索参数**：标题检索还是全文检索、日期区间怎么传、分页、请求头、编码、关键词放哪个字段
- 每个通道**已验证的坑**：缺请求头会返回假 0、返回时间戳是 UTC（发布日要取原文链接路径里的日期）、并发会 403（需退避）、主体更名要跟进
- **已实测不可用清单**（含失败原因），避免所有 lane 重复试错

**完成判据**：每个通道都能回答三问 —— ① 能做全文检索吗 ② 能限定日期区间吗 ③ 返回里能直接拿到原文链接与日期吗；每个「0 条」结论都有**对照词**证明它是真零（例：对照词在同平台返回数百条，说明索引非空）。

**常见失败模式**：把「0 条」当结论（违反 L3）；重复试已知不可用通道；只记通道不记参数（子代理不会用，于是各写各的）；探针用本产品词、结果全 0 就判定通道不可用（应该用对照词判断通道本身是否活）。

## 第 4 步 · 分 lane 并发铺开

**做什么**：**一个 lane ＝ 一个下游行业方向**。按下面的规则生成 **8–12 个 lane**，每个 lane 一个子代理，**并发上限 8**。

lane 生成规则（产品无关的固定做法）：

- 从下游应用地图里，取**用量强度 ★★★ 及以上**的方向各出 1 个 lane；
- 再补 **3 个横切 lane**（与产品无关，任何产品都要有）：① 政采/公共资源交易平台的**明确采购**；② 上市公司定期报告/募集说明书/问询函回复里的**采购披露**（走全文检索）；③ 环评公示与投产/扩产（**生产变化**类）；
- 若用户要市场判断，再加第 4 个横切 lane：**同行与市场信号**（只出补货窗口与利空，必须标方向）。

**每个 lane 的六件必给件**（缺一即返工）：

1. **产品与用途**：本次产品＋该产品在本 lane 工序里的作用（直接投料/间接/配方级）
2. **本 lane 范围与候选企业**：细分范围 ＋ ≥3 家具名企业 ＋ 行业集群地名
3. **可用通道与 URL 模板**：只从第 3 步的可用通道清单里挑，写明检索词与参数
4. **固定 JSON 字段（字段契约）**：字段名、取值枚举、禁造字段 —— 见下
5. **落盘路径**：`leads_raw/NN_<lane>.json`，只写自己那一个文件
6. **防上下文耗尽纪律**：先落盘再汇报、单 lane 抓取次数上限、每 5 条增量落盘、收尾只回报条数/分组分布/命中通道/放弃通道与原因（**不贴 JSON 全文**）

**字段契约（固定，不得增删改名）**：

```
公司 / 事件类型 / 细分行业 / 省市 / 事件产品 / 数量或规模 / 发布日 / 截止日 /
与我产品的关系 / 分组 / 需求性质 / 时效性 / 证据来源 / 置信度 / （信号方向）
```

枚举：`分组`＝明确采购/招标｜扩产或复产需求｜其他潜在需求信号；`需求性质`＝明确采购需求｜推断的潜在需求；`时效性`＝仍可参与｜已过期｜仅作线索；`置信度`＝高｜中｜低；`事件类型`＝招标公告/询价公告/竞争性磋商/采购公告/中标公告/复产/复工/投产/试生产/点火/冷修/技改扩产/提负荷/环评公示/其他。**没有可点链接就把 `证据来源` 写「未核实」、`置信度` 写「低」。**

**完成判据**：lane 数在 8–12 之间；每个 lane 文件存在且字段齐全、枚举合法；lane 收尾报告含条数、分组分布、命中通道、放弃通道及原因。

**常见失败模式**：lane 数 <8（覆盖不足）或 >12（方向重叠、重复条目暴增）；两个 lane 范围重叠（收口要去重掉一大半）；契约不固定导致收口解析失败；子代理把整页 HTML 拉进上下文（几十次就烧穿，违反 L5）。

## 第 5 步 · 收口

**做什么**：五件事，按顺序做，全部可脚本化。

1. **六道闸门过滤**（[`gates.md`](gates.md)）：逐条判定，给出「剔除原因」，落 `剔除记录.json`。**执行顺序 R2 → R1 → R4 → R3 → R5 → R6**（R2 必须在 R1 前，否则「采购烧碱」会被主体名单误判成同行）。
2. **合并去重**：跨 lane 归一化去重。公司名归一化＝去括号内容 → 去掉「股份有限公司/有限公司/集团/公司」后缀；去重键＝`公司 + 事件类型 + 发布日`；**证据链接相同也判重**（跨 lane 最常见的重复形态）。重复时保留置信度更高的那条。
3. **同主体合并**：同一企业的同源证据按「企业 + 分组」合成 1 张卡（L6），`证据来源` 保留多条链接。
4. **字段归一与打分**：算 `区域`（区内/区外）、`时效性`（由截止日与基准日推出）、`置信度`（**无 http 链接强制=低，且 `证据来源` 改写为「未核实」**）、框出同行/市场信号的 `信号方向`。
5. **链接抽检**：随机抽 40–60 条，逐条验证「可达」与「主体一致」（链接通但指向别家也算不合格），落 `_qa_report.json`；不合格的**标注而非删除**（在 `证据来源` 后追加「（⚠链接抽检：…）」）。

**完成判据**：剔除记录里每条都有「闸门名 + 原因」；正式商机池里**没有**「未核实」条目；抽检报告含可达率与逐条备注；同一主体没有重复卡。

**常见失败模式**：把「未核实」混进正式池（违反 L1）；同源多条链接当成多条独立线索（违反 L6）；忘记按产品拆条（违反 L4）；抽检只数条数、不核主体一致；去重键只用公司名，导致同一家企业的不同事件被误并。

## 第 6 步 · 出表与交付

**做什么**：交付三件，缺一不可。

**① Excel（工作表名固定）**：`0 使用说明与过滤规则` ｜ `1 商机卡总表` ｜ `2 明确采购_招标` ｜ `3 扩产或复产需求` ｜ `4 其他潜在需求信号` ｜ `5 待核实（无原文链接）` ｜ `6 被剔除条目` ｜ `7 统计`。

**② 自包含 HTML 报告**：单文件、无外链依赖、带筛选、可打印成 PDF；排序默认按优先级分降序。

**③ 交付报告四块**（必须写，且**必须是本次实测数字**）：

| 块 | 内容 |
|---|---|
| ① 条数分布 | 总数、三组各几条、各 lane 原始产出、区内/区外、时效性分布、P1–P4 分档数 |
| ② 置信度分级依据 | 高/中/低各靠什么证据（定义见 [`gates.md`](gates.md)），并至少举 2–3 条**可自洽复算**的例子（如「吨数 × 均价 ≈ 披露金额」能对上） |
| ③ 被剔除的同行名单 | 企业、事件、日期、剔除理由、**原文链接**（同行身份的依据要能被销售复核） |
| ④ 负结果与覆盖缺口 | 哪些通道不可用、哪些方向是真零（附对照词）、本机/本次只能覆盖什么、建议的人工补口 |

**完成判据**：四块都有具体数字与原文链接；报告头写明哪些参数是**默认值**（最小订单规模、时间窗）；末尾给出复现步骤（换产品/换地区/换时间各改哪一处）。

**常见失败模式**：交付报告写成行业综述（没有本次数字）；不写负结果与不可用通道（下次还会重复试错）；把默认门槛当成客户要求；HTML 引用外部 CDN 导致离线打不开。

## 7. 换一个化工品时，到底改什么

原本容易写死在某个产品版本里的东西，全部参数化到上面六步：

| 写死形态（某产品版） | 泛化后的形态 | 实例化位置 |
|---|---|---|
| 具体产品的下游用料逻辑与吨耗数字 | **吨耗系数表**（每下游一行、标来源与「估算」） | 第 2 步 → [`product-profiling.md`](product-profiling.md) |
| 已知的同行企业名单 | **同行判据**＝工艺路线关键词 ＋ 年报业务分部核验协议 | 第 2 步 → [`gates.md`](gates.md) R1 |
| 具体检索词（学名/俗名） | **检索词库**（学名＋俗名＋英文＋规格＋上/下游产品名＋事件词） | 第 2 步 |
| 具体区域省市清单 | **区域参数**（省/市清单）＋ 区外标记规则 | 第 1 步 → R3 |
| 固定日期区间 | **时间窗参数**（`WIN_START`/`WIN_END`/`TODAY`） | 第 1 步 → R4 |
| 固定最小订单门槛 | **最小订单规模参数**（客户留空时给默认并声明） | 第 1 步 |
| 固定条数与固定方向的 lane 表 | **lane 生成规则**＝下游应用地图（★★★以上）＋ 3 个横切 lane | 第 4 步 |
| 某个接口的 `isfulltext`、`fields` 等参数 | **通道参数**（连同坑一起记在可用通道清单） | 第 3 步 → [`channels.md`](channels.md) |
| 具体产品的误配方向清单 | **误配清单的生成方法**（必须按产品重建） | [`gates.md`](gates.md) 末节 |
| 打分表里的行业→强度映射 | **用量强度 1–5 由吨耗系数表映射** | 第 2 步 → [`gates.md`](gates.md) 打分 |
