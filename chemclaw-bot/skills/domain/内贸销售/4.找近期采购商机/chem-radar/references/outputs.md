# 产物契约：字段、Excel 结构、HTML 结构、report_notes.json

本文件是**接口契约**。lane 子代理、合并脚本、出表脚本三方都按它对接；改字段名要三处同步。

---

## 一、线索记录的 14 项必填字段

每条原始线索是一个 JSON 对象，放在 `<任务目录>/leads_raw/NN_<lane>.json`（数组）。字段名固定，缺字段脚本会报出来。

| 字段 | 含义 | 取值要求 |
|---|---|---|
| `公司` | 事件主体 | 写全称＋股票代码（若有）。例：`亚星化学（潍坊亚星化学股份有限公司，600319）`。**同一公司在一堆公告里可能有多种写法**，config 的 `company_aliases` 负责归并 |
| `事件类型` | 发生了什么 | 用固定短语：`招标公告` `询价公告` `采购公告` `中标` `采购披露` `采购合同` `技改扩产` `投产` `点火` `复产` `提负荷` `检修` `停产` `环评公示` `其他`。**这一项决定读者第一眼怎么理解**，别写「公告」这种空话 |
| `细分行业` | 该主体所处行业 | 例：`浮法玻璃/药用玻璃`、`无机盐—铬盐`、`沉锂/锂盐` |
| `省市` | 所在地 | 省＋（市），例：`江苏（常州）`、`山东`。区外信号也要写清 |
| `事件产品` | 事件涉及的产品 | 例：`重质纯碱`、`碳酸钠（水处理剂）`。⚠ **混合标的要全列**（「纯碱、烧碱」），R2 错配闸门据此判定 |
| `数量/规模` | 涉及的量/金额/产能 | 硬数字优先：吨数、金额、日熔量、产能、单价。**拿不到就明写「公告未披露 X」**，不要编 |
| `发布日` | 公告发布日 | `YYYY-MM-DD`。⚠ **必须取 `adjunctUrl` 里的 `/finalpage/YYYY-MM-DD/`**，cninfo 的 `announcementTime` 是 UTC、会早一天 |
| `截止日` | 招标/询价截止日 | `YYYY-MM-DD`；非招标类留空。**这是判断「仍可参与」的唯一依据** |
| `与我产品的关系` | 用量逻辑＋量级估算 | **最关键的一栏**，见下文「关系栏怎么写」。R5 闸门会卡字数和空话 |
| `分组` | 归入哪一组 | 只能是：`明确采购/招标`、`扩产或复产需求`、`其他潜在需求信号` |
| `需求性质` | 是明确需求还是推断的 | 只能是：`明确采购需求`、`推断的潜在需求`。一般由分组决定，脚本会补默认值 |
| `时效性` | 现在还能不能用 | `仍可参与`（截止日未过）｜`仅作线索`（非招标类，只能当情报）｜`已过期` |
| `证据来源` | 原文链接 | **必须是真实抓取到的链接**。可多个，用 ` ｜ ` 连接。拿不到就写 `未核实`——脚本会自动降置信度为「低」并单列 |
| `置信度` | 证据强度 | `高`（读到原文正文且有硬数字）｜`中`（有原文但只有定性表述/产能）｜`低`（只有标题、间接转述或无可点原文） |

### 可选字段（lane 可写，脚本也会补）

| 字段 | 含义 |
|---|---|
| `信号方向` | `利好`｜`利空`｜`中性`。**同行与市场信号必须标**，写在「与我产品的关系」里用 `[利好]` 形式，闸门会自动提取。带标注的同行信号会被保留到「同行动态与市场信号」而不是删掉 |

### 派生字段（脚本计算，lane 不用写）

| 字段 | 怎么来 |
|---|---|
| `区域` | 命中 config 的 `region.keywords` 则 `本区`，否则 `区外`（可配）。区外行在 Excel/HTML 里灰置但不删 |
| `用量强度` | 按 config 的 `strength_rules` 正则打分（1–5★），命中多条取最高 |
| `优先级分` | `用量强度 × 置信度权重(高3/中2/低1) + 分组加成 + 时效加成 + 证据加成` |
| `优先级` | 按 config 阈值分档：`P1 立即跟进` ≥18 ｜ `P2 本周跟进` ≥13 ｜ `P3 备选池` ≥8 ｜ `P4 仅存档` |
| `来源备注` | 链接清洗时从「证据来源」里剥出的说明文字；跨条目合并时会追加合并说明 |

## 二、「与我产品的关系」怎么写（R5 闸门卡的是这一栏）

这一栏决定这条线索有没有用。**必须同时给出：① 用量逻辑（工艺上为什么用这个产品、用在哪一步）② 量级估算（大概多少）③ 估算依据**。

❌ 不合格（会被字数闸门或你自己判断卡掉）：
- 「该公司是玻璃企业，会用到纯碱」——没有工艺逻辑、没有量级。
- 「利好」——两个字。

✅ 合格示例：

> 浮法玻璃配合料中纯碱引入 Na₂O，该公司新点火产线设计日熔量 1,200 吨，按 0.18–0.22 吨纯碱/吨玻璃推算，年需纯碱约 7–9 万吨（估算），是千吨级以上单客户。

> 铬盐焙烧配料以纯碱为主（吨重铬酸钠耗纯碱约 0.5–0.8 吨），公告自身即把纯碱列为主要成本项，需求真实性高；但属区外（湖北），需评估运费后再决定是否跟单。

> [利好] 同行检修停产：供给收紧、区域现货趋紧，是我方补货窗口。该装置产能 X 万吨/年，检修期预计 Y 天，期间华东可流通量减少（估算）。我方应优先锁定长协客户。

**估算一律标「（估算）」**，并写清系数来源（化学计量／行业单耗／公告反推）。

## 三、Excel 结构（9 个工作表）

| 工作表 | 内容 |
|---|---|
| `0 使用说明与过滤规则` | **全部由 config 动态生成**：查询条件、怎么用这张表、六道闸门（含同行名单与误配清单）、用量强度与吨耗表、三分组判别口诀、置信度分级依据、本轮 lane 清单 |
| `1 商机卡总表` | 所有保留条目，含序号。超链接落在「证据来源」列，分组列按组填底色 |
| `2 明确采购_招标` | 第一组 |
| `3 扩产或复产需求` | 第二组 |
| `4 其他潜在需求信号` | 第三组中**不带**方向标注的 |
| `4b 同行动态与市场信号` | 第三组中**带**方向标注的（同行检修/停产/扩产、市场口径） |
| `5 待核实（无原文链接）` | 完全没有可点链接的条目，**不混进正式商机池** |
| `6 被剔除条目` | 每条都记录命中了哪道闸门、为什么 |
| `7 统计` | 按分组、需求性质、区域、省份、置信度、时效性、优先级、细分行业的分布 ＋ 剔除原因分布 |

格式约定：首行冻结；全表自动筛选；「数量/规模」「与我产品的关系」「证据来源」「来源备注」自动换行；**区外整行灰置**；「时效性」为「仍可参与」时绿色加粗、「已过期」红色。

## 四、HTML 结构（单文件自包含）

一个 `.html` 文件，**CSS/JS 全部内联，无任何外部资源**——拷到任何电脑、离线、发微信都能直接打开。九个章节：

1. **结果概览**：统计卡 ＋ 按优先级/置信度/省份/时效性的分布条 ＋ 链接抽检结论
2. **置信度分级依据** ＋ 六道闸门 ＋ 吨耗表
3. **第一组：明确采购/招标**（含两种形态的说明）
4. **第二组：扩产或复产需求**
5. **第三组：其他潜在需求信号**
6. **同行动态与市场信号**（带【利好】/【利空】）
7. **被剔除的条目与被剔除的同行**
8. **负结果与覆盖缺口** ＋ 通道清单
9. **怎么换一个产品再跑一遍**

顶部有**吸顶筛选条**：按分组／区域／置信度／时效性／关键词实时筛选，并显示「显示 N / M 条」。每张卡显示全部字段，证据链接可点。有 `@media print` 规则，可直接打印成 PDF。

## 五、report_notes.json 结构（由分析人员撰写）

机器算不出「负结果」「缺口」这类判断，所以它们放在这里，由 `build_html.py` 渲染进第 2、8 节。

```json
{
  "confidence_basis": [
    {"level": "高", "criterion": "读到公告原文正文且有可点链接，能拿到吨数、金额、合同期、采购均价。本批 X 条。"},
    {"level": "中", "criterion": "有可点原文，但只有定性表述或只有项目产能，年需求须靠吨耗系数估算。本批 Y 条。"},
    {"level": "低", "criterion": "只有标题或间接转述，或抓不到可点原文。本批 Z 条，其中 N 条已单列到「待核实」。"}
  ],
  "highlights": [
    {"company": "某公司", "why": "证据最硬：具体到什么量、什么价、什么合同期，以及为什么该先打。"}
  ],
  "negative_results": [
    "**标题检索命中 0 条、全文检索命中 N 条**——只看标题会得出完全错误的结论。",
    "上市公司基本不发该产品的招标公告，采购走询比价/长协，所以第一组里真正可投标的只有 N 条。",
    "省级公共资源交易平台检索真为零，已用对照词验证索引是通的。"
  ],
  "coverage_gaps": [
    "所有商业招标聚合平台与政府采购平台都够不着：具体列出原因。这意味着一定还有招标没找到。",
    "没有价格/库存数据：说明为什么缺、以及报告里的价格判断是从哪来的。",
    "未覆盖非上市中小企业：该产品的中小买方不发公告，只能电话核实。"
  ],
  "channels_used": [
    {"channel": "巨潮资讯 cninfo 全文检索接口", "status": "可用（本轮主力）", "note": "命中数与必需的请求头、间隔、日期修正说明"},
    {"channel": "巨潮资讯 cninfo 标题检索接口", "status": "可用但命中 0 条", "note": "0 条这个事实本身就是结论"},
    {"channel": "国家政府采购网 ccgp", "status": "不可用", "note": "反爬拦截"}
  ]
}
```

**写作要求**：
- 负结果要写成「**查了，是真没有**」，并给出验证方式（对照词、换词重试）——否则读者会把「没查到」当成「没有」。
- 覆盖缺口要**具体到通道名与失败原因**，不要写「受限于数据来源」这种空话。
- `highlights` 要说明**为什么先打这家**（量、价、合同期、需求上行），不要只写「关系密切」。

## 六、任务目录布局

```
<任务目录>/
├── product.json              # 产品配置（唯一需要行业知识的文件）
├── leads_raw/                # 各 lane 原始线索（下划线开头的文件被脚本跳过）
│   ├── 01_zhengcai.json
│   ├── 02_listco.json
│   └── ...
├── report_notes.json         # 你撰写的四块叙事内容
├── leads.json                # 闸门+去重+合并后的最终商机卡
├── 剔除记录.json              # 每条被剔除的条目及命中的闸门
└── out/
    ├── <产品><区域>_采购商机卡.xlsx
    └── <产品><区域>_采购商机卡.html
```

运行时还会生成 `leads_raw/_qa_report.json`（链接抽检报告）与 `leads_raw/_explain.txt`（闸门排查报告）——下划线开头，不会被当成线索再次读入。
