# 化工品采购商机雷达

把「我销售某化工品，最近有哪些公开采购信号」这个问题，变成一份**每条都能追溯到原文**的商机清单。

## 这个 skill 解决什么

输入一句话：**我销售【产品/规格】，目标市场【地区】，可接受的最小订单规模【可选】。**

输出两个文件：

| 文件 | 内容 |
|---|---|
| `<产品><区域>_采购商机卡.xlsx` | 8 个工作表：使用说明与过滤规则、商机卡总表、三个分组分表、同行动态与市场信号、待核实、被剔除条目、统计 |
| `<产品><区域>_采购商机卡.html` | 单文件自包含报告，可筛选、可离线看、可直接发人 |

外加一份 `<任务目录>/report_notes.json`（由你撰写），装着置信度依据、负结果、覆盖缺口、通道清单——这四块是机器算不出来的判断，HTML 会把它们渲染成报告的第 2、8 节。

## 三个分组（结果结构的核心）

| 分组 | 判据 | 需求性质 |
|---|---|---|
| **明确采购/招标** | 对方**已经在买**：招标/询价/采购公告，或定期报告、募集说明书、评级报告、问询函回复里披露的**采购量、采购金额、采购均价、年度采购合同** | 明确采购需求 |
| **扩产或复产需求** | 对方**在扩产或复产**：新装置投产、技改扩能、点火、冷修后复产、提负荷 | 推断的潜在需求 |
| **其他潜在需求信号** | 更间接：环评公示里的新建项目、同行检修/停产带来的补货窗口、下游景气变化 | 推断的潜在需求 |

**注意「明确采购/招标」这一组里要再分两种形态**，交付时必须讲清楚，否则客户会以为有十几个标可投：
① 真正可投标的**招标/询价公告**；② 公告里披露的**采购量/金额/均价/合同**——是「已经在买」的证据，不是「正在招标」的机会。

## 执行流程

### 第 1 步：定契约（一次问全，别反复返工）
产品（学名＋俗名＋规格＋英文名/CAS）、目标区域（省/市清单）、时间窗（近 30 天还是 90 天）、最小订单规模、已有客户名单（可选）。
用户没给最小订单规模和客户名单时，**给一个默认值并在交付物里声明**（例：「默认 ≥300 吨/单，用户未指定」）。

### 第 2 步：建产品画像 → 写进 config
这是整个流程里**唯一需要行业知识**的一步。照 [references/product-profiling.md](references/product-profiling.md) 做，产物是一个 `product.json`（模板见 `config/product.template.json`，实例见 `config/soda-ash-east.json`）：

- **产品标识**：学名、俗名、商品名、英文名、CAS、规格。⚠ 中文公告里可能**只出现学名不出现俗名**，检索词必须全覆盖。
- **下游应用地图（8–12 个 lane）**：每个 lane 写清用料逻辑、用量强度（1–5★）、5–8 家具名候选企业、产业集聚地。**主动找容易漏的渠道型 lane**：把该产品当配方单体复配转售的厂、拿它做深加工的厂。
- **吨耗系数表**：化学计量推算 ＋ 行业单耗经验值 ＋ 用公告披露的采购量反推。系数是估算，条目里要标「（估算）」。
- **同行名单**：自己也生产该产品的公司（含在建/拟建、垂直一体化）。
- **误配清单**：近名产品、不耗该产品的工艺路线、买成品而非原料的厂、期货/仓储类事项。

### 第 3 步：探通道，写下「本次可用通道清单」
照 [references/channels.md](references/channels.md)。主力是**巨潮资讯 cninfo 全文检索接口**（上市公司公告原文）＋ 省级公共资源交易平台的全文检索接口 ＋ 地方生态环境厅的环评公示接口。

**这一步的产物是 `report_notes.json` 里的 `channels_used`**：哪些通道实测可用、哪些不可用及原因。这是复现与交接的关键，也是交付报告第 8 节的内容。

搜索引擎只试一次，不灵就跳通道——别在它身上耗时间。抓取一律优先 https，失败回退 http（有些环境完全没有 TLS 能力，此时要在交付里如实写覆盖缺口）。

### 第 4 步：分 lane 并发铺开
一个 lane ＝ 一个下游行业方向，8–12 个。每个 lane 派一个子代理，**并发 ≤8**。给每个子代理的六个必给件：

1. 产品与用途（含吨耗系数，让它能算量）
2. 本 lane 范围与具名候选企业（5–8 家）
3. 可用通道与具体 URL/接口模板
4. **固定 JSON 字段**（见下）
5. 落盘路径 `<任务目录>/leads_raw/NN_<lane>.json`
6. 防上下文耗尽纪律：**先落盘再汇报、限制抓取次数、每 5 条增量落盘**

记录字段契约（14 项，`radarlib.FIELDS`）：
`公司` `事件类型` `细分行业` `省市` `事件产品` `数量/规模` `发布日` `截止日` `与我产品的关系` `分组` `需求性质` `时效性` `证据来源` `置信度`
（另有派生字段由脚本算：`信号方向` `用量强度` `优先级分` `优先级` `区域` `来源备注`）

### 第 5 步：收口（脚本自动完成）
```bash
python scripts/run_all.py --config config/<你的产品>.json --dir <任务目录>
```
依次是：套用六道闸门 → 去重 → 同主体合并成一张卡 → 链接抽检 → 出 Excel → 出 HTML。

六道闸门见 [references/gates.md](references/gates.md)，顺序固定 **R2→R1→R4→R3→R5→R6**：

- **R2 产品错配**：命中近名产品/无关工艺即剔除。⚠ 只看「事件标的」字段，**绝不能扫「与我产品的关系」**——那是分析人员的解释文字，常写「本工序主耗烧碱而非纯碱」来排除干扰，一计入就会把最好的线索误杀。
- **R1 同行闸门**：自己也生产该产品的公司是同行、不是客户。⚠ **必须核验年报的业务分部，不能看名字**——存在两个方向相反的陷阱：名字像同行实为买方、名字像客户实为同行。**反向用法**：同行检修/停产/降负荷＝供给收紧＝我方补货窗口，**保留**并标【利好】；同行扩产＝新增供给，标【利空】。带方向标注的同行信号一律保留到「同行动态与市场信号」，删掉等于丢情报。
- **R4 时间闸门**：发布日须落在窗口内；发布日更早但截止日仍在未来的招标**保留**并标「仍可参与」。
- **R3 地域闸门**：区外信号**保留但标注并灰置**，不删除——外地的强信号往往仍有价值。
- **R5 相关性闸门**：「与我产品的关系」必须写清用量逻辑＋量级估算，字数不达标不收。
- **R6 证据闸门**：证据必须是真实抓取到的链接；抓不到就写「未核实」＋置信度降为「低」＋单列到「待核实」工作表。

### 第 6 步：写 report_notes.json，重跑 HTML
四块必须写：**置信度分级依据**（高/中/低各靠什么证据支撑）、**负结果**（哪些方向查了是真没有）、**覆盖缺口**（哪些通道够不着、哪些客户只能电话核实）、**通道清单**。另可写 `highlights`（先打哪几家、为什么）。写完后 `python scripts/build_html.py --config ... --dir ...` 重出 HTML。

## 六条铁律（踩过坑才写下来的）

1. **每条线索必须有可点的原文出处。严禁编造 URL、标题、企业名。** 宁可少几条，也不许凑数。拿不到原文就写「未核实」＋低置信度＋单列。
2. **同行不是客户**，且同行身份只能靠核验年报业务分部确认，不能看名字。
3. **标题检索与全文检索必须都跑。** 实测某产品窗口内标题命中 **0** 条、全文命中 **164** 条。只看标题会得出「没有需求」的完全错误结论。任何异常为 0 的结果都当作「未验证」，换词/换窗口重试后再下结论。
4. **一条公告可能同时含利空与商机，必须按产品拆条**，不能按公告整条判断。（例：一份公告同时含「3 万吨本产品」＝同行新增供给＝利空，和「10 万吨下游深加工产品」＝本产品新增需求＝利好。）
5. **子代理的上下文是易耗品**：先落盘再汇报，每 5 条增量落盘。
6. **同一主体的一簇证据可能同出一份文档**，不要重复计为多个独立线索源。

## 换一个产品怎么改

**只改 config，脚本一行都不用动。** 需要重建的只有四样：产品标识与检索词、下游应用地图与吨耗系数、同行名单、误配清单。窗口、区域、最小订单规模、打分权重都在 config 里。详见 [references/method.md](references/method.md) 末节的参数对照表。

## 脚本清单

| 脚本 | 作用 |
|---|---|
| `scripts/radarlib.py` | 公共库：配置、取数（https→http 自适应）、六道闸门、去重、优先级。所有脚本的地基 |
| `scripts/fetch_cninfo.py` | cninfo 标题/全文检索取数（含假 0 复核、UTC 日期修正、退避重试） |
| `scripts/fetch_pdftext.py` | PDF 正文抽取（纯标准库，取吨数/金额/合同期） |
| `scripts/merge_leads.py` | 套用六道闸门 ＋ 去重 → `leads.json` / `剔除记录.json` |
| `scripts/consolidate.py` | 同主体合并成一张卡（保留全部来源链接） |
| `scripts/qa_links.py` | 链接抽检（区分「反爬拦截」与「真坏链」） |
| `scripts/build_workbook.py` | 出 Excel |
| `scripts/build_html.py` | 出单文件 HTML |
| `scripts/explain.py` | **排查闸门误杀**：某条为什么被剔除、闸门是不是杀错了 |
| `scripts/compare_runs.py` | 对比两次运行（换窗口/换区域后看变了什么） |
| `scripts/run_all.py` | 一键跑完整条流水线 |

## 依赖

- Python 3.7+（用到了 `reconfigure`）。**出 Excel 需要 `openpyxl`**：`pip install openpyxl`
- 只用标准库做取数（`urllib`/`zlib`），不需要 requests、pdfminer 等第三方库
- **可移植性已在代码里处理**：中文 Windows 的 stdout 默认是 GBK，打印「↳」「≈」这类字符会直接抛 `UnicodeEncodeError` 把脚本打断——`radarlib` 在 import 时统一把 stdout/stderr 切成 UTF-8。控制台里中文仍可能乱码，**所有中文产出都落 UTF-8 文件再读**。

## 交付前自检

- [ ] 每条都有可点链接，或明确标了「未核实」＋低置信度并单列
- [ ] 「明确采购/招标」组里区分了「可投标招标」与「采购量披露」两种形态
- [ ] 同行名单逐条核验过年报业务分部，没有靠名字判断
- [ ] 标题检索与全文检索的结果都记录了（含那个 0）
- [ ] 区外信号是标注＋灰置，不是删除
- [ ] `report_notes.json` 四块齐全，尤其负结果与覆盖缺口
- [ ] 链接抽检跑过，失败项区分了「反爬」与「真坏链」
- [ ] 吨耗估算都标了「（估算）」
