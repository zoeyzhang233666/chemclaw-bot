# 化工品采购商机雷达（AGENTS.md）

> 本文件是给 Codex / 其他读 `AGENTS.md` 的 agent 用的操作说明，与 `SKILL.md` 同源。
> 改内容时两份都要同步，避免漂移。

## 任务

用户会给一句话：**我销售【产品/规格】，目标市场【地区】，可接受的最小订单规模【可选】。请查找最近【30/90天】与该产品直接相关的公开采购信号。**

你要产出一份**每条都能追溯到公开原文**的商机清单，交付 **Excel + HTML**。

## 交付物

1. `<任务目录>/out/<产品><区域>_采购商机卡.xlsx` —— 8 个工作表
2. `<任务目录>/out/<产品><区域>_采购商机卡.html` —— 单文件自包含报告，可筛选、可离线看
3. `<任务目录>/report_notes.json` —— 由你撰写：置信度依据、负结果、覆盖缺口、通道清单

## 结果结构：三个分组

| 分组 | 判据 | 需求性质 |
|---|---|---|
| 明确采购/招标 | 对方**已经在买**：招标/询价/采购公告，或定期报告、募集说明书、评级报告、问询函回复里披露的采购量、采购金额、采购均价、年度采购合同 | 明确采购需求 |
| 扩产或复产需求 | 对方**在扩产或复产**：新装置投产、技改扩能、点火、冷修后复产、提负荷 | 推断的潜在需求 |
| 其他潜在需求信号 | 更间接：环评公示里的新建项目、同行检修/停产带来的补货窗口、下游景气变化 | 推断的潜在需求 |

**「明确采购/招标」组里必须再分两种形态并讲清楚**：① 真正可投标的招标/询价公告；② 公告披露的采购量/金额/均价/合同（是「已经在买」的证据，不是「正在招标」的机会）。不区分的话，客户会以为有十几个标可投。

## 执行步骤

1. **定契约**：产品（学名＋俗名＋规格＋英文名/CAS）、目标区域、时间窗、最小订单规模、已有客户名单（可选）。用户没给后两项时给默认值**并在交付里声明**。
2. **建产品画像 → 写 config**：照 `references/product-profiling.md`。这是唯一需要行业知识的一步。复制 `config/product.template.json`，主要内容是：产品同义/检索词、下游应用地图（8–12 个 lane，每个带用量强度 1–5★ 和 5–8 家具名候选企业）、吨耗系数表、同行名单、误配清单、区域、时间窗、打分权重。
3. **探通道**：照 `references/channels.md`。主力是巨潮资讯 cninfo 全文检索接口 ＋ 省级公共资源交易平台全文检索接口 ＋ 地方生态环境厅环评公示接口。搜索引擎只试一次就跳。抓取优先 https、失败回退 http。
4. **分 lane 并发**：8–12 个 lane，每个一个子代理，并发 ≤8。每个子代理必须拿到：产品与吨耗、本 lane 范围与具名候选企业、可用通道与 URL 模板、**固定 14 项 JSON 字段**、落盘路径 `leads_raw/NN_<lane>.json`、防上下文耗尽纪律（先落盘再汇报、每 5 条增量落盘）。
   - 14 项字段：`公司` `事件类型` `细分行业` `省市` `事件产品` `数量/规模` `发布日` `截止日` `与我产品的关系` `分组` `需求性质` `时效性` `证据来源` `置信度`
5. **收口**：`python scripts/run_all.py --config <你的 product.json> --dir <任务目录>`
6. **写 `report_notes.json` 后重跑** `python scripts/build_html.py --config ... --dir ...`

## 六道闸门（脚本已实现，顺序固定 R2→R1→R4→R3→R5→R6）

- **R2 产品错配**：命中近名产品/不耗该产品的工艺即剔除。⚠ 只看「事件标的」字段，**不能扫「与我产品的关系」**——那是解释文字，常写「本工序主耗烧碱而非纯碱」排除干扰，一计入就会把最好的线索误杀。事件标的里同时出现目标产品时不算错配（混合标的公告）。
- **R1 同行闸门**：自己也生产该产品的公司是同行、不是客户。⚠ **必须核验年报业务分部，不能看名字**——有名字像同行实为买方的，也有名字像客户实为同行的。**反向用法**：同行检修/停产/降负荷＝供给收紧＝我方补货窗口，保留并标【利好】；同行扩产标【利空】。带方向标注的同行信号一律保留到「同行动态与市场信号」。
- **R4 时间闸门**：发布日须落在窗口内；发布日更早但截止日仍在未来的招标保留并标「仍可参与」。
- **R3 地域闸门**：区外信号保留但标注并灰置，不删除。
- **R5 相关性闸门**：「与我产品的关系」必须写清用量逻辑＋量级估算，字数不达标不收。
- **R6 证据闸门**：必须是真实抓取到的链接；拿不到就写「未核实」＋置信度「低」＋单列到「待核实」工作表。

## 铁律

1. **每条线索必须有可点的原文出处。严禁编造 URL、标题、企业名。** 宁可少几条，不许凑数。
2. **同行不是客户**，同行身份只能靠核验年报业务分部确认，不能看名字。
3. **标题检索与全文检索必须都跑。** 实测某产品窗口内标题命中 **0** 条、全文命中 **164** 条。只看标题会得出「没有需求」的错误结论。异常为 0 的结果一律当「未验证」，换词/换窗口重试后再下结论。
4. **一条公告可能同时含利空与商机，必须按产品拆条**，不能按公告整条判断。
5. **子代理上下文是易耗品**：先落盘再汇报，每 5 条增量落盘。
6. **同一主体的一簇证据可能同出同一份文档**，不要重复计为多个线索源。
7. **中文 Windows 控制台是 GBK，中文会乱码**。产出统一落 UTF-8 文件再读，不要靠 stdout。

## 常见失败与对策

| 现象 | 原因 | 对策 |
|---|---|---|
| cninfo 检索返回 `total=0` | 漏了 `Referer` / `X-Requested-With` 头，服务器静默返回假 0 | 补齐请求头并退避重试；本质为 0 时用对照词验证 |
| 检索结果日期比实际早一天 | `announcementTime` 是 UTC | 发布日一律取 `adjunctUrl` 里的 `/finalpage/YYYY-MM-DD/` |
| 连续请求后全 403 | 并发触发限流 | 15–20 秒间隔 + 退避重试 |
| 只搜俗名查不到 | 公告里只写学名 | 学名、俗名、商品名、英文名全列进 config 的 aliases |
| 把买方当同行剔除了 | 靠名字判断同行身份 | 逐条核验年报业务分部 |
| 闸门杀错了线索 | R2 扫了「与我产品的关系」等 | 用 `python scripts/explain.py --kv <关键词>` 查判定过程 |
| 换机器后脚本报 `UnicodeEncodeError` | 控制台编码不是 UTF-8 | 已由 `radarlib` 在 import 时接管；若仍报错设 `PYTHONIOENCODING=utf-8` |
| `openpyxl` 缺失 | 未安装 | `pip install openpyxl` |
