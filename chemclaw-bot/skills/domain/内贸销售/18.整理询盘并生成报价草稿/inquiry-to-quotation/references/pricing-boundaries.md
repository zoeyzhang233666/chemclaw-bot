# 价格红线与四道锁

这个 skill 的价值不在"会不会算"，而在"**永远不替销售定价**"。
下面每一条都有代码层面的落点，不是口号。

## 三条红线

1. **不产生价格。** `price.unit_price` 由空变有值，只有一条路径：销售在界面上填写，或命令行传 `--price`
   且同时传 `--ack`。代码里没有任何默认价、参考价、区间价、市场价、上次成交价。
2. **不推演价格。** 不做"按当前纯碱市场价估个 1500 左右"这类动作。市场行情可以单独查、
   单独给链接，但不能流进报价单的单价格。
3. **不改价。** 生成草稿之后，任何字段/价格变动只会把草稿标成"已过期，需重新生成"，
   不会静默重算并覆盖已审阅的版本。

## 四道锁（缺一不可）

| 锁 | 条件 | 界面表现 | 脚本表现 |
|---|---|---|---|
| 1 字段锁 | A 类字段全部有值且状态不是"缺 / 待客户确认" | 行标黄、按钮灰 | `_common.blockers()` 返回"缺：…/待确认：…" |
| 2 税费锁 | `gate.tax_mode` 已由我方选择 | 口径卡片未选中 → 灰 | 同上 |
| 3 运费锁 | `gate.freight_mode` 已由我方选择 | 同上 | 同上 |
| 4 价格锁 | 单价 > 0 且勾选确认语 | 勾选框未勾 → 灰 | 无 `--ack` → `exit 2` |

四道锁全开，界面按钮文案从"生成报价草稿（还差 N 项）"变成"生成报价草稿"；
命令行输出"通过：单价与口径均已由你确认"。

## 谁能改什么

| 角色 | 可以 | 不可以 |
|---|---|---|
| 客户 | 给需求、给指标、给期望价 | 决定我方报价（进入"期望价/比价参考"，不进单价） |
| 销售 | 填单价、选税费/运费口径、改 B 类假设、确认字段 | 让系统代填单价 |
| 系统 | 抽字段、算金额、排版、标缺失、标假设 | 定价、改价、补字段、补条款承诺 |
| 销售负责人 | 审阅、批准对外发送、批账期/锁价 | —（审批记录留在 05 表备注与邮件） |

## 客户的"期望价/比价参考"怎么处理

客户说"我们上次拿的 1530，你能做吗"——这是**客户期望价**，不是我方报价。

- 记进 `notes` 或字段 `note`：`客户期望价线索：1530 元/吨（来源：微信截图3）`；
- 不写进 `price.unit_price`；
- 手写的 `1?30` 认不清 → 进 `unreadable`，让销售回微信确认，**不要按 1530 或 1630 任选其一**。

## 数字只做算术的边界

系统允许计算的全集：

- 金额 = 单价 × 报价数量
- 不含税金额、税额、价税合计（按销售选定的税率）
- 有效期截止日 = 报价日期 + 有效期天数
- 容量/包装折算（如 200 吨 ÷ 1 吨/包 = 200 包）

系统**不允许**做的：给单价打折/让利、按量阶梯自动降档、按客户等级套价、
按竞品价倒推、按成本加成定价。
