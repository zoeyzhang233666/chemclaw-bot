# 整理询盘并生成报价草稿（内贸销售 · 化工品）

把一条散装询盘（微信三句话 + 一封邮件 + 一张 PDF/Excel 需求表），变成**一张能逐项点头的字段确认表**，
再在销售自己确认单价与口径之后，变成**一份可以拿去审阅的报价草稿**。

整件事只围绕一句话：**价格是销售的决定，不是系统的输出。**

## 0. 这套技能解决什么 / 不解决什么

| 解决 | 不解决 |
|---|---|
| 把微信/邮件/PDF/Excel 里的询盘抽成 10 个标准字段 | 不判断这个客户值不值得做（另用客户筛选技能） |
| 标出缺失项，分 A 类“必须补充” / B 类“可按假设” | 不替销售决定成交价、折扣、返利 |
| 给 A 类缺口一句能直接发客户的问法 | 不查客户真实付款能力/信用（走信用审批） |
| 销售填价后，按公司/默认模板排版报价 | 不生成合同正文（可转合同审阅） |
| 输出 HTML 工作台 + 7 表 Excel + Markdown 草稿 | 不把草稿自动发给客户 |

## 1. 给 agent 的读取顺序

1. 本文件（流程 + 硬约束）；
2. `references/field-schema.md`（字段判定）；
3. `references/extraction-rules.md`（切块/置信度/脏数据）；
4. `references/quotation-template.md`（报价七要素写法）；
5. `references/pricing-boundaries.md`（价格红线）；
6. 换品类时读 `references/product-profile-schema.md` 和 `products/<product>.json`；
7. 交付前读 `references/qa.md`。

不要先写 HTML/Excel，再倒推字段；顺序反了，缺失项会被“排版需要”填上。

## 2. 三条不可谈判的约束

1. **系统不产生价格。** 没有默认价、参考价、区间价、建议价、市场价挂靠、历史价回填。
   单价永远是空输入框；空着就显示“待填单价”，报价金额跟着空着。脚本层还有闸：
   没有确认语（`--ack`）直接退 2。
2. **抽不到就留空，标“待客户确认”。** 不拿行业惯例、同类客户数据、“做这行肯定要……”去补齐。
   单价、税额、运费、账期一旦猜错，业务员会拿着编出来的价格去谈，比没有报价单更糟。
3. **两类分桶不许混。** A 类缺一项就不能报价；B 类可以带假设先出草稿，但每一处假设都要在报价里
   写成“（我方假设 · 待客户确认）”。混在一起，等于把“我不知道”包装成“客户要求”。

## 3. 输入契约

用户可能只给一个文件，也可能给一堆。先收料、编号、保留原话：

| 输入 | 处理 |
|---|---|
| 微信截图 `.png/.jpg` | OCR 后按消息顺序切块；被裁切/遮挡/手写数字单独标“无法辨认” |
| 邮件 `.eml/.txt` | 保留发件人、时间、主题、正文；签名里的公司名可能仍是简称 |
| PDF 需求表 | 文本型直接抽；扫描件先 OCR；表格跨页要合并单元格语义 |
| Excel 需求表 | 读单元格，不读公式显示值；空白格就是空白，不按“相邻行”补 |
| 公司报价模板 | 有就套用；没有就用 `templates/报价模板_默认.md` |
| 产品资料 | 规格书、包装标准、常用贸易条款；缺了就按询盘原话，不补 |

同一客户多渠道信息冲突时，**两处都留着**，让人判断；不要替客户合并。

## 4. 流程（两次停下等人）

### 第 1 步：素材清点与证据编号

每份素材一个稳定短编号，后面每条提取值都挂它：

```text
素材01  微信截图 OCR ×6   10-18 → 10-19
素材02  邮件 ×1           10-19 14:32
素材03  PDF 需求表 ×1     10-19（扫描件，第 2 页有手写）
```

顺手标三类脏数据：语音未转写、截图被裁切/遮挡、手写数字（`1?30` 是 1630 还是 1530）。

### 第 2 步：抽 10 个字段 + 2 个口径

字段清单固定，不要临时加：产品、规格/牌号、数量、交货地点、客户名称（A 类）；
包装、交期、付款条件、运输方式、报价有效期（B 类）；
税费口径、运费口径（C 类，**只能由我方选**，不从询盘单向推断）。

判定要点（完整版见 `references/field-schema.md`）：

- **数量**：必须拆开“试单量 / 月用量 / 年用量”。`先试单 200 吨，月用量 800 吨` → `试单 200 吨；月用量 800 吨`。
  报价按试单量算，月用量只做口径说明。把月用量写进首单价格，是做亏的最快方式。
- **规格**：收客户给的内控指标原话（`Na2CO3 ≥ 99.2%`、`180 目筛余 ≤ 5%`），不做单位换算、不补漏项。
- **交货地点**：要落到“省市 + 厂区/仓库”。`你们送过来就行` 不算地点，标待客户确认。
- **客户名称**：只抓到简称（“盐城华宇玻璃”没有“有限公司”）时，标“待客户确认 · 开票主体全称待补”，
  不要自己补成有限公司——抬头错一个字，发票就废。
- **付款条件**：客户没说的就是没说。可以用我方标准口径做假设，但必须打“（我方假设）”。

### 第 3 步：两类分桶 + 黄色高亮

| 桶 | 含义 | 成员 | 处理 |
|---|---|---|---|
| **A 类** | 必须补充后才能报价 | 产品、规格、数量、交货地点、客户名称、税费口径、运费口径、单价 | 缺一项 → 生成按钮不可点 |
| **B 类** | 可先按假设准备 | 包装、交期、付款条件、运输方式、报价有效期 | 带假设出草稿，逐条标注“我方假设 · 待客户确认” |

每行都要有：提取值、**出处原句**、置信度（高/中/低）、状态（已提取 / 待客户确认 / 我方假设 / 缺）。
缺失与待确认在 HTML 里黄色高亮，在 Excel 里条件格式标黄。**状态是销售签字的地方，不是系统自说自话的地方。**

> **第一次停下**：把字段表交给用户逐项确认。不要在这一步直接生成带价格的报价。

### 第 4 步：缺口清单 → 建议问法

A 类缺什么，要给出一句能直接发给客户的话，而不是“请补充资料”：

| 缺 | 建议问法 |
|---|---|
| 数量 | 首单多少吨？后续月用量与年度计划大概多少？ |
| 规格 | 能否提供贵司验收指标（纯度、杂质、粒度）？ |
| 交货地点 | 收货厂区具体地址、是否需要预约卸车、有无地磅？ |
| 客户名称 | 开票主体全称、纳税人识别号、是否需要专票？ |
| 付款条件 | 贵司常规付款方式是款到发货还是月结？账期多少天？ |

### 第 5 步：价格与口径闸门（四道锁）

同时满足才允许生成报价草稿，缺一项按钮就是灰的，并列出“还差哪几项”：

1. A 类字段全部有值且状态不是“缺 / 待客户确认”；
2. 税费口径已由我方选择（含税 13% 专票 / 不含税 / 普票…）；
3. 运费口径已由我方选择（到厂价含运费 / 出厂价不含运费 / 送到站）；
4. **单价已由我方填写，并勾选“我确认该单价为我方销售价格”**（脚本等价物：`--ack`）。

系统在这里只做算术：数量 × 单价、税额、价税合计。改价只会让已生成的草稿标“已过期，需重新生成”。

> **第二次停下**：只有四道锁全亮，才生成报价草稿。销售没确认价格，就不生成带价格的文本。

### 第 6 步：生成报价草稿（七要素）

固定七段，缺一段不算报价单：

1. 商品明细（产品 / 规格 / 数量 / 单位 / 单价 / 金额）
2. **价格与口径**（税费口径文字 + 运费口径文字 + 价税构成）
3. **数量与执行口径**（试单量 vs 月用量，正式合同以书面数量为准）
4. **交付条件**（交货地点 / 运输方式 / 交期 / 包装）
5. **付款条件**
6. **报价有效期**（起止日期 + 逾期处理）
7. **待客户确认事项**（所有假设与缺口，一条不落）+ 备注与生成说明

写法细则、三种税/运费口径的标准表述见 `references/quotation-template.md`。

### 第 7 步：交付与审阅

- HTML 工作台：上传、字段确认、价格闸门、报价预览、复制/导出/打印/转合同审阅；
- Excel：走内部审批、留痕、给别人填；
- Markdown：贴邮件/企微，或喂给合同审阅；
- `fields.json`：系统对接，不含价格。

## 5. 产品研究：把行话查清楚，但不碰价格

报价专业不专业，不靠猜价，靠把**产品、标准、包装、物流、票据、验收**说准。
研究顺序：产品身份 → 验收指标 → 包装单证 → 物流卸货 → 税务合规 → 商务条款。

- A 级来源：国标/行标、法规、客户原文、供方 COA；
- B 级来源：行业协会、上市公司公告、权威行业媒体；
- C 级来源：贸易商报价、匿名帖子、比价截图——只作线索，不进报价承诺。

公开行情只用于判断**报价有效期**和**波动风险**，不得写进报价单，也不得用来填单价。
详见 `references/research-playbook.md`；纯碱示例见 `products/soda-ash.json`。

## 6. 换品类：只换画像，不换结构

复制 `products/_template.json` 为 `products/<product>.json`，填：

- 品名/别名/CAS、标准、等级/牌号；
- 客户常见验收指标、包装、单证、储存/运输；
- 税率/票种、HS 编码（如涉出口）；
- 商务默认值（有效期、单位、口径）——**仍然只是默认建议，必须销售确认**。

然后改 `scripts/extract.py` 顶部的 `PRODUCTS` / `GRADE_PATTERNS` / `PACK_PATTERNS` 词表。
字段结构、A/B 分桶、四道锁、报价七要素、HTML/Excel 版式全部不变。

## 9. 失败模式（踩过的坑）

| 症状 | 根因 | 改法 |
|---|---|---|
| 报价单里出现一个没人认过的价格 | 为了“先看看效果”给占位价 | 占位价一律禁止；要看效果让对方自己填一个数，或标 DEMO |
| 月用量被当成首单量报出去 | 数量字段只要一个值 | 数量必须两段式：`试单 X；月用量 Y`，报价取 X |
| 客户名称是简称，发票开错 | 用正则补全“有限公司” | 简称只能标“待客户确认” |
| “送到我们厂” 被当成到厂价 | 运费口径从询盘单向推断 | 运费口径必须我方选；询盘线索只作提示 |
| 假设被客户当成承诺 | 草稿里没标“我方假设” | B 类必须逐条标注，且进“待确认事项” |
| 手写 `1?30` 被读成 1630 | 猜数字 | 进“无法辨认”清单，让用户补录 |
| 报价有效期写了 30 天 | 照抄模板 | 纯碱等大宗随行就市，默认 7 天，锁价走审批 |
| Excel 里金额显示 `#VALUE!` | 单价空着直接乘 | 全部用 `IF(单价="","待填单价",...)` |
| 演示价被当成默认价 | 示例文件里放了 1,180 | 文件名/页面/工作簿都标 DEMO；文档反复声明“不是建议价” |
