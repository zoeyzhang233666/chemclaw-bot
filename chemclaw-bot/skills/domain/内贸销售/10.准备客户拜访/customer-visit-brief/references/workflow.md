# 六步工作流 · 完成判据与降级

> 主 agent 全程可独立完成（无需子代理）。研究量大时可用子代理并行四个研究面，但每面的产出必须落盘回 `visit_data.json`。

## 步骤① 输入契约（落盘）

- 复制 `templates/visit_data.template.json` 到 `work/<项目>/visit_data.json`。
- 先填 `meta` 五件套；`history_note` 写明"已上传 N 份记录"或"未上传记录"。
- **完成判据**：文件存在且 `meta.customer / our_product / visit_purpose` 非空。
- 用户没给全 → 一次问全（带推荐项）；`customer` 缺失必须问，不得自选演示对象。

## 步骤② 取证研究（四个研究面，可并行）

按 `references/research-playbook.md` 的检索模板与来源优先级执行：

- **A 客户是什么**：官网 → 最新年报/半年报 → 评级报告/券商研报 → 政府与行业媒体。
- **B 为什么适配**：产品 → 客户行业的用点、单耗（经验值须标注）、规格红线；写"可讲卖点"与"切入时机"。
- **C 近 6–12 个月大事**：点火/冷修/投产/中标/业绩/评级/行业事件；每条 = 日期 + 事件 + 对拜访的意义 + 来源。
- **D 行情**：我方产品现价、主要原料现价、客户产品景气；每条 = 价格 + 单位 + 数据日期 + 来源(±URL) + 变化方向。

**完成判据**：A 至少 5 个维度有来源；C 至少 5 条；D 至少覆盖我方产品 1 个主流市场 + 原料 1–2 个品种；所有 URL 打开与主体一致。

## 步骤③ 内容组装（六节 + 三级标注）

- 公开信息：写来源；推断：写"推断·待验证"；用户提供：写"客户确认（依据：文件名）"。
- 第⑤节：逐条来自上传记录；**无记录 → 空态文案 + 首访基线采集清单**。
- 问题清单：每个版本 5–8 问，每问附"为什么问"；采购版默认适合首访。

**完成判据**：`visit_data.json` 能被步骤④无报错消费。

## 步骤④ 出 Excel

```bash
python scripts/build_visit_workbook.py --data work/<项目>/visit_data.json --out work/<项目>/拜访背景卡.xlsx
```

- **完成判据**：生成 8 表；打开无损坏；提问清单有状态下拉；行情/来源表超链接可点。
- 无 Python/openpyxl → 按 `output-spec.md` 的 8 表规范手工建表（列结构与样式要点都在）。

## 步骤⑤ 出 HTML

- 母版：`examples/soda-ash-flat-glass/拜访背景卡_*.html`，复制后替换内容，保留：头部渐变+徽章、KPI 看板、三版本标签页与各版目标横幅、时间轴、行情表、⑤空态框、来源折叠列表、打印按钮。
- 无浏览器校验条件时：确保单文件、内联 CSS/JS、零外链资源（来源链接是 `<a href>`，不算外链资源）。
- **完成判据**：双击打开即读；三个标签页可切换；打印样式适配 A4。

## 步骤⑥ 交付前体检（逐项打勾）

1. 每个价格都有"数据日期 + 来源"？（第④节一行都不能空来源）
2. 每条大事都有日期与来源？链接打开与所述主体一致？
3. 无上传记录时，第⑤节是否为空态而非编造内容？
4. 推断项是否都标了"推断·待验证"？
5. 三个版本各 5–8 问？每问有"为什么问"？
6. 文件名规范：`拜访背景卡_<客户>_<产品>_<日期>.{xlsx,html}`。
7. 回复只给摘要 + 两个文件卡，不重复粘贴全文（先落盘、再汇报）。

## 拜访后闭环（给用户的提示，不属本次交付）

拜访结束把纪要/微信记录喂回来：第⑤节从空态变为"已确认/未解决"台账，下一张卡的问题清单自动个性化（未解决问题→定向追问）。
