# 客户切入点扫描（化工品内贸销售）

把"泛泛的建议加强沟通"变成"为什么是现在、找谁、说什么"的可执行事件卡。本 skill 只固化**研究思路**和**结果结构**，不限定化工品和客户行业。

## 1 何时使用 / 何时不用

用：用户给出（或希望你帮选）一家具体的下游企业 + 一种化工品，要近期开发动作。
不用：客户名单式拓客（lead list）、项目级潜客挖掘（CAPEX 项目库）、行情分析报告——那些是另外的任务，本 skill 只做"单个客户 × 单个产品"的近期切入点。

## 2 需要的输入（缺省直接按默认执行，不要反复追问）

| 输入 | 默认 |
|---|---|
| 客户企业全称（有股票代码更好） | 必须有，没有则先与用户确认 |
| 我方产品（化工品名，有牌号/规格更好） | 必须有 |
| 扫描窗口 | 最近 6 个月（可选 3 个月）；以执行日为锚点 |
| 我方身份（生产商/贸易商）、目标区域 | 可选，影响话术与角色建议 |

## 3 研究流程（七步，严格按顺序）

**第1步 产品→客户关系锚定。** 弄清该产品用在客户哪个生产环节、大致量级、对应哪些基地/产线。量化只能来自证据或明确标注为推断（规则见 `references/quality-and-inference.md`）。

**第2步 分层检索。** 按 `references/methodology.md` 的检索清单与关键词模板执行，五个层面都要碰一遍：
A 公司一手（公告/评级/业绩说明会）；B 产能与供应链事件（点火/冷修/招标/认证）；C 经营与资金（业绩/转债/增资）；D 行业与市场（供需/价格/政策）；E 区域与竞品（基地动态/竞品事故）。
每条发现必须记录：**日期、来源、URL、性质（一手/二手）**——这就是证据清单。

**第3步 筛选 3–5 个切入点。** 排序分 = 时机咬合度 × 与产品相关性 × 可操作性（谁拍板、多久落地）。每张卡至少 1 条**窗口内**证据；窗口外事件只能当背景并标注。

**第4步 按五段式写卡。** 事件 → 与产品的关系 → 为什么现在值得联系 → 推荐接触角色 → 证据；另加"推断标注"与"建议下一步动作"。角色写**职能**（如"集团采购中心·大宗原料采购负责人"），严禁编造人名、电话、邮箱。

**第5步 写数据文件。** 按第4步产出填写 `cards.json`（UTF-8），字段以 `templates/scan_data.schema.json` 为准。这是报告的唯一数据源——研究结论不要只留在聊天里。

**第6步 生成附件。**
```bash
python templates/build_deliverables.py cards.json -o 输出目录 -n 文件名前缀
# 产出：<前缀>.xlsx 和 <前缀>.html，依赖仅 openpyxl（pip install openpyxl）
```
没有 Python 环境时：按 `references/output-schema.md` 手工构建——Excel 固定六个 Sheet；HTML 用 `templates/report.template.html`，把其中 `__SCAN_DATA_JSON__` 替换为 cards.json 的 JSON 内容即可。

**第7步 质量自检。** 过一遍 `references/quality-and-inference.md` 末尾的自检清单，全部通过才交付；不通过就回到第3步砍卡或补证据。

## 4 交付规范

- **必交付：Excel + HTML 两个附件**（用户额外要数据时附 cards.json 副本）。
- 命名：`{产品}客户切入点扫描_{客户简称}_{YYYY-MM-DD}.xlsx / .html`。
- 语言跟随用户（默认中文）；证据链接必须可直接点开。

## 5 通用红线

1. 公开信息看不到客户的真实供应商名单/份额——一切"打进去"的判断都要标注需首访验证。
2. 测算（单耗×产能）、行业惯例（认证提前期、长协窗口）、行情预测、政策推演，四类内容一律放"推断标注"，不得当事实表述。
3. 窗口外事件不得伪装成"最近发生"。
4. 每个关键数字 ≥2 个独立来源交叉验证，或降级为"单一来源、待核实"。
