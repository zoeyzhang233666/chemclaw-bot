# 证据分级、推断标注与质量自检

这个任务的公信力全在"事实与推断分得清"。本文件是唯一裁判标准。

## 1 证据分级

| 级别 | 来源 | 可用于 |
|---|---|---|
| L1 一手 | 交易所/巨潮/披露易公告、评级报告、业绩说明会官方纪要、公司官网 | 支撑全部关键事实 |
| L2 专业二手 | 券商研报、期货行业周报、行业协会数据、卓创/隆众/百川等产业资讯 | 支撑行业数据与行情判断（注明出处） |
| L3 权威媒体 | 财经媒体报道（每经、证券时报、智通、格隆汇等） | 支撑事件发生；关键数字最好回溯到 L1 |
| L4 弱来源 | 自媒体、论坛、股吧、聚合站 | 只能引出**线索**去查证，不得支撑任何关键数字 |

规则：
- 每张卡至少 1 条**窗口内**的 L1–L3 证据；纯 L4 支撑的卡直接砍。
- 关键数字（利润额、产能、价格）≥2 个独立来源，或降级标注"单一来源、待核实"。
- L1 永远压过 L2/L3 的同一事实转述。

## 2 日期规则

- 扫描窗口默认为执行日前推 6 个月；**卡的"事件"必须发生在窗口内**。
- 窗口外的有用事实（如 Q1 点火而窗口从 Q2 起）只能作为背景，写明原日期并说明与现在的连续性（"X 月点火，当前正处爬产期"）。
- 政策类事实按"生效日"记日期，标注"施行中"。

## 3 推断类型学（写进卡的 inference 时对号入座）

| 类型 | 例子 | 标注措辞 |
|---|---|---|
| 测算类 | 单耗×产能估需求 | "为按…测算，需以实际…修正" |
| 惯例类 | 认证提前3–6个月、Q4长协窗口 | "为行业惯例推断，需向对方求证" |
| 行情类 | 低价将持续、复产将回升 | "为行情判断，跟踪…验证" |
| 政策推演类 | 某线适用点火大限 | "为政策推演，公告未披露，需求证" |
| 归因类 | 竞品事故→客户受益 | "为因果推演，勿当事实表述" |
| 信息边界类 | 看不到供应商名单 | 放入快照警示，提示首访求证 |

铁律：
1. 每张卡 inference 数组 ≥1 条（确无推断才可写"无"），HTML 琥珀框、Excel 推断列、推断边界表三处同源（都来自 cards.json），不许互相矛盾。
2. 话术中推断的**标准句式**："我们了解到行业普遍…，贵司实际情况是？"——把推断变成提问。
3. 禁止编造：人名、电话、邮箱、供应商名单、采购份额、未公开的采购价。

## 4 常见错误 Top 8（review 时逐条对照）

1. 把研报测算口径当成客户披露事实引用。
2. 把窗口外事件写成"最近"发生。
3. 竞品/市场事件硬归因到客户身上而不标注。
4. 全是"建议加强沟通"式的空卡，没有"为什么是现在"。
5. 证据链接失效或根本没打开过（幻觉 URL）。
6. 角色建议写成具体人名或"联系张总"。
7. Excel/HTML/JSON 三处数字不一致（改了一处忘了同步）。
8. 卡片数量凑数——5 张平庸卡不如 3 张扎实卡。

- [ ] 3–5 张卡，每张按"事件→关系→为什么现在→角色→证据"完整展开
- [ ] 每张卡 ≥1 条窗口内证据，链接全部真实可点开
- [ ] 每张卡有 inference 标注；涉及测算的注明测算口径
- [ ] 无编造人名/电话/邮箱/供应商信息
- [ ] 事实与推断分离：正文事实都有证据编号支撑
- [ ] cards.json 通过 schema 校验（或对照 schema 逐字段核对）
- [ ] Excel 六个 Sheet 齐全、超链接有效；HTML 单文件可离线打开、筛选/排序/弹窗可用
- [ ] 附件命名符合 `{产品}客户切入点扫描_{客户简称}_{日期}` 规范
- [ ] 交付说明里提醒用户：先联系谁、本周可做的第一个动作
