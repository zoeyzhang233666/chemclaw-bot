# 结果结构规范：cards.json → Excel + HTML

核心设计：**研究结论 = 一份 cards.json**；Excel 和 HTML 都是它的渲染产物。换产品、换客户、换 agent，结构不变。

## 1 cards.json（唯一数据源，UTF-8）

字段以 `templates/scan_data.schema.json` 为准，要点：

```jsonc
{
  "meta": {
    "title": "纯碱内贸 · 客户切入点扫描｜福莱特玻璃集团",       // 报告大标题
    "task_line": "我要开发「福莱特…」，销售「纯碱（重碱）」",     // 任务句
    "customer": {"name": "...", "codes": "601865.SH / 06865.HK", "profile": "一句话画像"},
    "window": {"start": "2026-04-15", "end": "2026-10-15", "label": "最近6个月"},
    "generated": "2026-10-15",
    "badges": ["扫描窗口：…", "基地：…", "信息源：…"],            // 顶部横幅小字
    "kpis": [{"num": "5", "label": "切入点数"}, ...],            // 4个左右
    "file_base": "纯碱客户切入点扫描_福莱特_2026-10-15"          // 附件文件名前缀
  },
  "snapshot": {"rows": [["公司","…"], ...], "note": "⚠ 看不到供应商名单…"},   // 客户快照
  "cards": [ /* 3–5 张，按优先级排序 */
    {
      "no": "P1", "prio": 1, "stars": "★★★",
      "type": "客户事件",                    // 客户事件 | 行业与市场 | 辅助信号
      "typeTag": "cust",                    // cust | mkt | aux（配色）
      "dates": "2026-08-25 / 09-07",
      "title": "一句话标题（含钩子）",
      "event": "发生了什么。可含 <b> 强调。",   // 允许少量内联HTML标签 b/strong/br
      "relation": "与产品的关系",
      "whyNow": "为什么现在值得联系",
      "roles": [{"r": "职能角色", "d": "作用一句话"}, ...],
      "evidence": ["E1","E2"],              // 必须指向 evidence 数组中的 id
      "inference": ["哪些内容只是推断，…"],     // ≥1条；确无推断写["无"]
      "next_action": "建议下一步动作",
      "visit": {"goal": ["拜访目标…"], "ask": ["必问问题…"], "bring": ["带的材料…"], "risk": "风险红线"},
      "message": {"to": "建议对象与渠道", "body": "可直接发送的消息草稿"}
    }
  ],
  "evidence": [{"id":"E1","date":"YYYY-MM-DD","source":"来源","kind":"一手公告|评级报告|券商研报|媒体|期货周报|行业深度|说明会纪要","tag":"src1|src2","title":"内容要点","cards":"卡1 卡3","url":"https://..."}],
  "market": {
    "rows": [["指标","数值/变化","时点","证据","备注"], ...],
    "chart": {"title":"2.0mm玻璃价格（元/平）","caption":"…",       // 可选，无图则省略chart
              "points":[{"label":"2025Q1峰值","value":13.75,"display":"13.75","highlight":"base"}, ...]}
  },
  "inferences": [["I1","推断内容","依据类型","如何验证/使用限制"], ...],
  "roles": [["R1","角色/部门","层级定位","对应卡片","沟通目标","建议开场/话题"], ...],
  "footer": {"methodology": "…", "disclaimer": "…", "prompt_template": "…"}
}
```

写卡要求：
- `event/relation/whyNow` 中引用证据直接写编号（如"（E1、E5）"），编号必须存在于 `evidence`。
- `inference` 一张卡通常 1–4 条；把"测算/惯例/行情判断/政策推演/信息边界"分开写清。
- 所有 URL 必须是研究时真实抓取过的。

## 2 Excel 交付规范（固定六个 Sheet，顺序不变）

| # | Sheet 名 | 内容 | 关键格式 |
|---|---|---|---|
| 1 | 使用说明 | 扫描对象/产品/窗口/范围/信息源元数据 + 工作表导航 + 优先级图例 + 免责声明 | 标题合并行、图例色块 |
| 2 | 事件卡总览 | 每行一卡：优先级/星级/类型/主题/关键日期/事件/与产品关系/为什么现在/推荐角色/证据编号/推断标注/建议下一步 | 优先级列色块(P1红→P5灰)、冻结窗格、自动筛选、整行自动换行 |
| 3 | 证据清单 | 编号/日期/来源/性质/内容要点/支持卡片/超链接 | G列真超链接、性质列底色区分一手(绿)/二手(蓝) |
| 4 | 行业背景数据 | 指标/数值变化/时点/证据/备注（含可选图表数据） | — |
| 5 | 推断边界 | 编号/推断内容/依据类型/验证方式 | 红线性质，置于证据之后强调 |
| 6 | 接触角色与行动 | 编号/角色部门/层级/对应卡片/沟通目标/开场话题 | — |

通用：深蓝表头(#123A5F 白字加粗)、斑马纹(#F4F8FC)、细边框、横向打印、按宽度缩放。生成脚本 `templates/build_deliverables.py` 已实现全部格式，不要手搓。

## 3 HTML 交付规范

单文件、零外部依赖、离线可开。必须包含：
1. 深色页头：标题 + 任务句 + 窗口/基地/信息源横幅
2. KPI 条：切入点数、证据数、推断数、核心亮点
3. 客户快照 + 信息边界警示
4. 工具栏：类型筛选 chips、排序（优先级/时间）、关键词搜索
5. **事件卡**：展开/收起；五段式分区 + 角色徽章 + 证据列表(可点开) + 琥珀色推断框；每卡两枚按钮——「用这个切入点准备拜访」（弹出目标/必问/带材料/红线）与「润色一条我准备发送的消息」（弹出生成好的消息草稿，可编辑可复制）；弹窗顶部显示"已带入任务上下文 → 卡号+标题+证据"，复刻把事件带入后续任务的语义
6. 证据清单表（可点原文）、行业数据表 + 可选条形图、推断边界表、角色地图表
7. 页脚：方法论、免责声明、可复用提示词模板
8. 打印样式（隐藏交互控件、卡片全展开）

`templates/report.template.html` 已实现 1–8，数据驱动：只替换 `__SCAN_DATA_JSON__` 一个占位符。

## 4 命名与语言

- 附件：`{产品}客户切入点扫描_{客户简称}_{YYYY-MM-DD}.xlsx / .html`（即 meta.file_base）
- 语言跟随用户；中文报告内数字与日期用 `YYYY-MM-DD`
