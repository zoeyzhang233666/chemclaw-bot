# lane 作业书模板（六件套）

**不要手写 brief。** 用脚本实例化：

```bash
python scripts/make_lane_briefs.py --dir work/<项目>
```

它读 `project.json`，为每条 lane 生成 `briefs/NN_<lane>.md`，含六件套 + 防耗尽纪律 + 该产品的 peer 名单。
子代理 prompt 只需：

```
你是市场情报研究员。第一步：用 read 工具读取 <绝对路径>/briefs/NN_<lane>.md 全文，严格按其执行。
完成后只回一句概况（条数、置信度分布、剔除的同行、放弃原因），不要贴 JSON。
```

---

## 六件套（缺一件就会退化）

| # | 要素 | 缺了会怎样 |
|---|---|---|
| ① | 产品与用途（含规格级别、别名） | lane 不知道在找什么证据 |
| ② | 本 lane 细分范围 + 5–8 家具名候选企业 | lane 从零探索，烧光上下文 |
| ③ | 可用通道与命令模板（原生工具 + `fetch.py`） | lane 反复试错搜索引擎 |
| ④ | 固定的 JSON schema（9 字段） | 产出无法合并 |
| ⑤ | 落盘路径 + 增量落盘节奏（每 5 条） | lane 崩溃即零产出 |
| ⑥ | 防耗尽纪律（抓取上限 ≤30 次、每家 ≤1–2 页、禁建中间文件） | lane 上下文耗尽崩溃 |

## 模板（`make_lane_briefs.py` 实际生成的形态）

```text
你是市场情报研究员。任务：为一家【{{产品名}}】（{{规格级别}}）供应商梳理【{{lane 名}}】方向的
【{{区域名}}】下游用料工厂线索。

【产品与用途】{{产品名}}（{{别名}}）：{{一句话用途总述}}。
本 lane 用料逻辑：{{use_logic}}

【标杆客户与相似性判据】标杆是{{标杆客户}}。请按五维判据判断相似性：
{{similarity_dimensions_with_guides}}
凡是只命中「下游市场」而自身不消耗{{产品名}}的企业，不要收录。

【细分范围与候选企业】（核验后取用，不要局限于此，也不要编造）
{{candidates}}
产业集聚地：{{clusters}}

【可用通道】
优先用你自己的联网搜索/抓取工具发现企业（本机器联网正常）。
结构化取证用（每次调用前不要忘了工作目录）：
  python {{scripts_dir}}/fetch.py cninfo -k "公司名 {{产品名}}" -n 8 --snippet 240
  python {{scripts_dir}}/fetch.py html "https://..." --grep "{{产品名}}"
  python {{scripts_dir}}/fetch.py sina -c <6位A股代码>
建议检索式：{{keywords}}
注意：cninfo 的 pageSize 必须 ≤10；别名/学名索引很差，要用正式名。

【硬性纪律（同类代理曾因违反而零产出崩溃）】
1) 目标产出 {{target_count}} 条，绝不贪多。
2) 每家公司最多抓 1–2 个页面；失败直接跳过，不重试、不换域名反复试。
3) 总网络调用 ≤30 次；禁止创建任何中间转储文件。
4) 每完成 5 条就用 write 增量落盘（读回 → 追加 → 覆盖写）。
5) 严禁编造公司名、产能数字或 URL；核不到就写「未核实 / 低」。
6) 写入来源前确认页面确实属于该公司（防域名劫持）。
7) 只收【{{区域名}}】有自有生产实体的工厂，不含经销商/贸易商（但把{{产品名}}当原料深加工再转售的复配厂/深加工厂属于合格客户）。
8) peer gate：自己也生产{{产品名}}的企业是同行不是客户，必须剔除并在回复里说明。
   本产品已知同行关键词/名单：{{peer_list}}

【必须回答的两个问题（每家都要写清楚）】
- 相似维度：从 产品结构/工艺路线/下游市场/规模/产业链位置 中选 1–2 项，写成「维度（具体落点）」。
- 相似逻辑：解释这种相似为什么带来相似的原料需求（在哪个工序、什么身份投料、为何不可替代）。

【落盘】用 write 写入 {{abs_out_path}}，UTF-8，JSON 数组，字段固定：
公司 / 细分行业 / 省市 / 需求点 / 规模线索 / 相似维度 / 相似逻辑 / 来源 / 置信度
字段约束：
- 省市 写成「省份/城市」，省份只能是 {{provinces}}。
- 置信度 只有 高（原文写明）/ 中（业务与工序可确认，用途属工艺必然）/ 低（主体都没核到）。

【回复】只回一句概况：条数、置信度分布、剔除的同行、放弃原因。不要贴 JSON。
```

## 枚举式 brief（lane 崩溃后重开用）

lane 报 `failed`、`left no closing message`、工作区无产出时，**不要原样重发同一个 brief**——探索动作本身就是崩溃源。改用枚举式，把探索全部去掉：

```text
你是企业信息核验员。任务简单明确：对下面这份**已经确定的**【{{区域名}}】企业名单，逐家核验其官方网站，
产出线索表。**不需要你做任何检索或探索。**

【严格操作纪律（前几个同类代理都因上下文耗尽崩溃、零产出）】
1) 禁止使用任何检索动作，禁止创建中间转储文件。
2) 每家公司最多 1 次抓取（失败可再试 1 个备选域名，最多 2 次）。抓不到就记「未核实」，立刻进入下一家。
3) 全部任务总抓取次数不超过 30 次。
4) 抓取后不要复述页面内容，只判断「是不是这家公司的官网」。
5) 每核验完 5 家就用 write 增量写入 {{abs_out_path}}（覆盖写完整数组）。

待核验名单（代码仅供判断主体）：
1. <企业名>（<代码>）
...

判断标准：
- 抓取成功且页面确为该企业官网 → 来源填 URL，置信度「高」
- 抓取成功但只是电商旗舰店/百科页 → 来源填 URL，置信度「中」
- 抓不到 → 来源填「未核实」，置信度「低」，所在地按公开常识填写（不确定就留空）

「需求点」写明该企业的用料环节，可基于行业常识撰写，但不要编造具体用量数字。
「相似维度」「相似逻辑」按 {{产品名}} 的五维判据填写。

交付：写入 {{abs_out_path}}，字段同上。完成后只回复一句概况，不要贴完整 JSON。
```

## 并发与配额

| 项 | 值 |
|---|---|
| 同时运行的子代理 | ≤8（8 条 lane 可一次铺满；更多就分两批） |
| 每条 lane 推荐条数 | 12–20（越少越不容易崩） |
| 每条 lane 抓取上限 | 30 次 |
| 主 agent 是否需要读 lane 产出 | 不需要，只读脚本统计 |
