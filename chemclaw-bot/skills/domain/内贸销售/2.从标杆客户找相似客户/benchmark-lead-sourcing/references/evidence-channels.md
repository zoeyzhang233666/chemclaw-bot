# 证据通道与取证命令

原则：**宿主原生联网工具负责「发现」企业，结构化脚本负责「取证」**。发现靠模型产业知识 + 搜索；取证靠可点开的原文。

---

## 1. 通道阶梯（每级只试一次）

| 级别 | 通道 | 用途 | 置信度上限 |
|---|---|---|---|
| A | 上市公司公告全文检索（巨潮资讯 cninfo；港股公告同库） | 年报/招股书/可研/募集说明书/问询函回复里「该原料」的原文 | 高 |
| B | 企业官网直连 | 确认主体、业务板块、产线 | 高（能确认主体与业务板块）／中（用途属推断） |
| C | 交易所/财经站公司资料页 | 全称、注册地、主营、官网域名 | 中 |
| D | 百科、协会名录、行业报道、排污许可/环评公示 | 兜底；非上市企业的主要来源 | 中/低 |

非上市企业（大多数下游厂）往往 A 级为零命中 → 走 B/D，并如实标 `置信度=中`（主体与工序可确认、但无原文）。**不要为了好看调高置信度。**

### 特种通道（按行业补充）

- **环评/排污许可/清洁生产审核公示**：省级生态环境厅、地市生态环境局网站；能拿到「原辅材料表」，对非上市工厂极有效。
- **地方统计/园区招商/行业协会名录**：用于定位集聚地（cluster）。
- **海关/贸易数据**：仅用于验证用量规模，不作主体证据。
- **招标/中标公告**：可证明采购行为（如「XX 公司纯碱采购中标公告」）。

## 2. `scripts/fetch.py` 命令手册（Windows/macOS/Linux 通用，仅标准库）

```bash
# A 级：上市公司公告全文检索（返回 代码|名称|日期|标题|高亮片段|PDF链接）
python scripts/fetch.py cninfo -k "公司名 产品名" -n 8 --snippet 240
python scripts/fetch.py cninfo -k "产品名 行业词" -n 8
python scripts/fetch.py cninfo -k "公司名" -n 5              # 核实主体是否存在

# B 级：抓网页正文（自动去脚本/样式/标签、压缩空白、探测乱码编码）
python scripts/fetch.py html "https://www.example.com/" --max 1200
python scripts/fetch.py html "https://www.example.com/" --grep "产品名"   # 只看关键词上下文

# C 级：交易所/财经站公司资料页（新浪财经，按 6 位 A 股代码）
python scripts/fetch.py sina -c 601636

# 链接抽检（link gate）：批量检查可达性与 PDF 有效性，直接产出 _qa_report.json
python scripts/fetch.py check --file leads_raw/_qa_todo.json --out leads_raw/_qa_report.json
python scripts/fetch.py check --file leads_raw/_qa_todo.json --sample 40
```

### cninfo API 关键参数（脚本已封装，改脚本时注意）

| 参数 | 取值 | 说明 |
|---|---|---|
| `isfulltext` | **必须 `true`** | `false` 时返回 0 条 |
| `pageSize` | **≤10** | 开大后单次返回几百 KB，是子代理上下文耗尽的主因 |
| `searchkey` | 产品**正式名** | 别名/学名索引很差（如「枸橼酸」只命中个位数）；中文需 URL 编码 |
| 语义 | 分词级 AND + 相关性排序 | 不支持短语检索，引号无效；短公司名会被模糊匹配污染，必须逐条判读片段 |
| 正文 | `announcementContent` 自带 `<em>` 高亮 | 清除标签后可直接作为引用证据 |
| PDF | `http://static.cninfo.com.cn/` + `adjunctUrl` | **二进制无法自动解析**：只能确认文件存在（200 + `application/pdf`），正文细节需人工点开 |

### 关键词策略

| 做法 | 效果 |
|---|---|
| 产品正式名（「纯碱」） | 命中数万条，广度最好 |
| 公司名 + 产品名（「福莱特 纯碱」） | 定域检索，最相关（首选） |
| 产品名 + 行业词（「印染 纯碱」「脱墨 纯碱」） | 用来发现新的下游行业 |
| 公司名 | 核实主体是否存在/是否披露过 |

## 3. 抓取失败的分类（决定「剔除」还是「标注」）

| 现象 | 判定 | 处理 |
|---|---|---|
| 302 跳到反诈页/影视站/博彩站/域名出售页 | 域名劫持 | **剔除该 URL**，`来源` 改「未核实」 |
| 403 / 验证码 / 安全验证（百度百科、爱企查壳页） | 反爬拦截 | **保留**，备注「建议人工复核」——浏览器里能打开 |
| 空页 / 跳转壳 / 站点故障 / 连接重置 | 坏链 | 保留公司，标注链接不可用 |
| 超时、连接被关闭 | 出网受限 | 先设 `HTTPS_PROXY`/`HTTP_PROXY` 重试一次；仍失败就换通道，**不要反复重试** |

`fetch.py check` 已按上表分类，并只把「劫持/坏链」视为未通过。

## 4. 沙箱/受限环境的降级顺序

1. 宿主原生 `web_fetch`/`web_search`（正常机器首选）。
2. `python scripts/fetch.py`（走宿主操作系统的网络栈；某些沙箱里 `web_fetch` 被拦但 Python 出网正常，反之亦然——**两边各试一次**）。
3. 宿主 shell 直连（`curl`/`iwr`）作最后手段。
4. 全都不可用：把「待核验 URL 清单」交给用户，在浏览器里代抓；名单仍可交付，但报告里必须写明取证限制，并整体降一档置信度。

> 实测教训：某环境里 `web_fetch` 工具因 DNS 解析到非公网 IP 而全部失败，`web_search` 无 API Key，但同一台机器上 Python/`Invoke-WebRequest` 直连 cninfo 完全正常。**不要因为一个工具失败就断定「没网」。**
