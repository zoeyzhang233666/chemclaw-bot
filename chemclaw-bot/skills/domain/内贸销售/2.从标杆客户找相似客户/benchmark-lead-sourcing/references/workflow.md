# 九步工作流（详解）

主 agent 只做**编排、画像研究、lane 设计、质检与交付**；单条 lane 的企业核验交给子代理。
每一步都给了「完成判据」——不满足就不要进入下一步。

---

## 步骤 0：建档

```bash
python scripts/new_project.py --dir work/<项目> \
    --product "纯碱" --benchmark "旗滨集团（601636）" \
    --region "华东:山东,江苏,浙江,安徽,上海" \
    --lanes 10 [--customer-list 历史成交客户.xlsx]
```

产出项目骨架：

```
work/<项目>/
├── project.json            ← 唯一事实来源（产品/区域/标杆/lane/强度规则/归并/报告文案）
├── benchmark_profile.json  ← 标杆客户画像（六要素 + 证据 URL + 五维判据）
├── report_notes.json       ← 剔除名单、缺口与负结果（交付报告的第 6–7 节）
├── leads_raw/              ← 每个 lane 一个 JSON
├── briefs/                 ← make_lane_briefs.py 生成的作业书
└── tools/                  ← 可选的抓取包装脚本
```

用户若上传了历史成交客户表：把每个成交客户当作**标杆候选**，挑公开资料最全的 1–3 家做画像，取相似性判据的**交集**（交集越干净，第二批名单越准）。

- 完成判据：`project.json` 存在，`product` / `region` / `benchmark` 三项非空。

---

## 步骤 1：确认契约（若用户输入不全）

用一次 `ask_user_question` 问全四件事，带推荐项：**所售产品（含规格级别）**、**标杆客户**、**目标区域**、**交付物形式**。

- 完成判据：四项都有明确答案；区域是具体国家/区域/省份，不是「全球」。

---

## 步骤 2：探通道

写下「本次可用通道清单」，并**每级只实测一次**：

| 级别 | 通道 | 强度 | 怎么用 |
|---|---|---|---|
| A | 上市公司公告全文检索（巨潮资讯 cninfo 等） | 最强：年报/招股书/可研/募集说明书/问询函原文 | `python scripts/fetch.py cninfo -k "<关键词>"` |
| B | 企业官网直连 | 强：确认主体与业务板块 | 宿主 web_fetch，或 `fetch.py html <url>` |
| C | 交易所/财经站资料页 | 中：确认全称/注册地/主营/官网 | `fetch.py sina -c 601636` |
| D | 百科/行业报道/协会名录 | 弱：只作兜底、不作唯一来源 | 宿主搜索工具 |

宿主有搜索工具时，**用它发现企业（这一步模型知识 + 搜索最有效）**，用 A/B/C 核验。

- 完成判据：写出通道清单，且 A 与 B 各实测成功一次（或写明为何不可用）。

---

## 步骤 3：画应用地图，定 lane

一个 **lane = 一条下游用料通道**（不是工商行业门类）。列 **8–12 条**，每条写清五件事：

1. `use_logic`：在哪个工序、起什么作用（助熔剂 / 化学计量反应物 / 中和成盐 / 脱硫剂 / 复配单体……）
2. `strength`：用量强度 5 星=单客户千吨级/年，4 星=百吨级，3 星=数十吨级，2 星=十吨级及以下
3. `candidates`：具名、可查证的候选企业 5–8 家（带股票代码更好）
4. `clusters`：产业集聚地（省市/园区）
5. `keywords`：3–5 个检索式（建议「公司名 + 产品名」定域检索）

**必须主动找两类容易漏掉的 lane**：

- **渠道型 lane**：把该产品当配方原料/单体，深加工或复配后转售的厂（如泡花碱厂、复配添加剂厂、洗涤助剂厂）。用量集中、决策链短。
- **深加工 lane**：该产品本身就是其主原料、且产物仍是大宗品的厂（如碳酸锂、白炭黑、硅酸钠）。

- 完成判据：lane 数 ≥8，每条 ≥5 家具名候选企业，且至少 1 条渠道型 lane。

---

## 步骤 4：生成 lane 作业书

```bash
python scripts/make_lane_briefs.py --dir work/<项目>
```

它把产品、区域、标杆、通道、JSON schema、落盘路径、防耗尽纪律**实例化**成 `briefs/NN_<lane>.md`，避免每条 brief 重复几千字。

- 完成判据：`briefs/` 下的文件数 = lane 数，且每条都含六件套。

---

## 步骤 5：铺 lane（fan-out）

每个 brief 起一个子代理。**并发上限 8**；起满就等一个结束再补。

子代理 prompt 只需两段：

```
你是市场情报研究员。第一步：用 read 工具读取 <绝对路径>/briefs/NN_<lane>.md 全文，严格按其执行。
完成后只回一句概况（条数、置信度分布、剔除的同行、放弃原因），不要贴 JSON。
```

- 完成判据：每个 lane 要么有 `leads_raw/NN_*.json`，要么在报告里写明放弃原因。
- 崩溃恢复（lane 报 failed 且零产出）：**不要原样重发**。用 `references/lane-brief-template.md` 的**枚举式 brief**重开——把候选企业名单连同代码直接写进 brief，禁用一切检索，每家最多 1–2 次抓取、总量 ≤30 次、每 5 条增量落盘。

---

## 步骤 6：收 lane 与体检

```bash
python scripts/validate.py --dir work/<项目>
```

检查：文件数与条数、字段是否齐全、区域是否越界、置信度是否在枚举内、未核实条数。

- 完成判据：11/11 或 N/N 个 lane 文件无解析错误；越界与非法值清单为空或已修正。

---

## 步骤 7：合并与抽检（link gate）

先抽检样本，再合并（合并会把抽检结论标注进 `来源`）：

```bash
python scripts/merge_leads.py --dir work/<项目> --make-qa-todo   # 生成 leads_raw/_qa_todo.json
# 抽检可由子代理执行，或用 fetch.py 直接批量核：
python scripts/fetch.py check --file work/<项目>/leads_raw/_qa_todo.json \
       --out work/<项目>/leads_raw/_qa_report.json
python scripts/merge_leads.py --dir work/<项目>                  # 正式合并
```

抽检数量：≥40 条。若 A 级（公告 PDF）链接占多数，把 A 级链接也纳入抽检（验证 200 + `application/pdf`），而不是只抽 HTML 页。

- 完成判据：`_qa_report.json` 落盘且条数 = 抽检数；合并后 `leads.json` 条数 = 各文件条数之和 − 去重数。

---

## 步骤 8：出表出报告

```bash
python scripts/build_workbook.py   --dir work/<项目>
python scripts/make_html_report.py --dir work/<项目>
```

- 完成判据：Excel 5 个表齐全、总表行数 = 线索数 + 1；HTML 单文件可离线打开，含筛选与全部 9 节。

---

## 步骤 9：交付汇报（四块缺一不可）

1. **条数与分布**（板块 / 省份 / 品类 / 用量强度）
2. **置信度分级**，并说明高置信靠什么证据（点名公告类型）
3. **被剔除的同行名单**（哪几家是同行不是客户）
4. **未覆盖的缺口与负结果**（哪些行业检索为零、哪些只能电话核实、哪些因区域限制未纳入）

最后附：交付物路径 + 使用建议（先打哪个板块、话术怎么起手）。
`python scripts/check_project.py --dir work/<项目>` 会把上述交付前体检一次跑完。

---

## 并行与预算纪律

| 项 | 建议值 |
|---|---|
| lane 并发 | ≤8（超出就分两批） |
| 每条 lane 子代理的网络调用 | ≤30 次，每家最多抓 1–2 页，失败不重试 |
| 每条 lane 产出 | 12–20 条（宁少勿滥） |
| 增量落盘 | 每 5 条覆盖写一次（崩溃也有产出） |
| 主 agent 读入 | 不读 lane 原始 JSON 全文，只读脚本输出的统计 |
