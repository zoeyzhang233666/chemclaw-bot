# 做新增产能事件研究

把一个"某装置投产了"的新闻，变成一套**可复核的证据链 + 可检验的统计骨架**。

本 skill 只解决一个问题：**新增产能投产前后，市场到底发生了什么变化，这个变化能不能与噪声区分开。**

---

## 铁律（违反任何一条，结论即不可用）

| # | 铁律 | 为什么 |
|---|---|---|
| 1 | **不得把设计产能当作投产当天的新增实际产量** | 装置投产后要爬坡 3–10 个月。设计 60 万吨/年的装置，第 1 个月实际产出往往不到设计负荷的 1/3。把设计产能当当天增量，会系统性高估供给冲击。 |
| 2 | **先核实真实投产日，不得把新闻里的"计划 X 月投产"当投产日** | 延期是常态。计划 2023 年投产、实际 2025 年才投产的项目大量存在。用计划日做事件日，等于在研究一个没发生的事件。 |
| 3 | **不同信息节点是不同事件，禁止混为同一种事件** | 宣布/环评/开工/试车属于**预期信息**，正式投产/合格品/商运属于**供给兑现信息**。市场对两者反应机制完全不同。合并求平均 = 两个相反的效应相消 = 结论为 0，看起来"没影响"，实际是被平均掉了。 |
| 4 | **事件密集时必须说明相互影响，不得假装样本独立** | 扩能期一个季度多个项目并行投产，事件窗口高度重叠。必须报告"±120 日内其他项目数"，并用相对日历对齐的反事实扣掉同期共同成分。 |
| 5 | **样本 < 3 不给 t 值、不给显著性、不写"显著"二字** | n=1 的"平均变化"没有统计意义，写出来会误导决策。 |
| 6 | **不得插值、不得编造、不得用"合理假设"填数据缺口** | 缺口就写缺口。爬坡曲线若为假设，必须显式标注"工程假设，非项目披露值"。 |
| 7 | **只有公开来源明确写出"一次开车成功/产出合格品/打通全流程"才算正式投产** | "试生产运行""阶段性达产""投产仪式""计划投产"都不是正式投产日。 |

## 九步工作法

| 步 | 做什么 | 产出 | 关键检查 |
|---|---|---|---|
| 1 | **圈定样本边界** | 产品、区域、时间窗、最小规模门槛（如 ≥20 万吨/年） | 门槛写下来。规模太小的项目对市场无影响，混进来只会稀释效应。 |
| 2 | **逐项目核实事实链** | `项目名/业主/地点/工艺/设计产能/上游配套/各节点日期/来源URL/原文引句/证据等级` | 每个日期必须有一句**能直接引用的原文**。引不出原文的日期不登记。 |
| 3 | **给日期分层** | 十个阶段：宣布→备案→环评→开工→中交→试车→**正式投产**→打通全流程→商运→达产 | 同一项目在不同阶段是**不同事件**，各自一行。 |
| 4 | **标注证据等级与单一来源** | A=政府批文/上市公司公告/央企官网；B=权威媒体；C=行业资讯机构；D=自媒体 | 只有 1 个来源的日期单独打标，统计时降权。 |
| 5 | **出候选表给用户确认** | 候选新增产能项目表 + 证据 | **先给表再跑统计。** 用户的行业知识经常能纠正自动化抓不到的错。 |
| 6 | **确认后建事件时间线** | 事件库 JSON | 检查：是否有项目只有"试车"没有"投产"？这类要单独归到 commissioning，不能当 startup。 |
| 7 | **计算事件窗口** | ±20/±60/±120 交易日，三个口径（累计/超额/突变） | 期货用交易日、周度库存用自然日，不能用同一套 k 观测口径。 |
| 8 | **统计 + 安慰剂检验** | 均值/中位/标准差/t/符号检验/bootstrap CI/随机平移 p 值 | 三个口径不同向 → 结论写"无稳健证据"。安慰剂 p 值 >0.1 → 效应与噪声无法区分。 |
| 9 | **出报告，写清限制** | 交互式 HTML + Excel + 混淆因素清单 | 必须写：市场提前反映、爬坡、同期其他项目、成本端驱动、检修对冲、季节性、日期精度不齐。 |

## 三个口径必须并列（别只报一个数）

设事件日为 0，后第 k 期为 +k：

| 口径 | 计算 | 含义 | 陷阱 |
|---|---|---|---|
| **累计变化** `cumulative` | 后 k 期值 / 事件前 1 期值 − 1 | 从事件前到事件后总共变了多少 | **含事件前的趋势漂移**。若事件前已在下跌，累计跌幅会被误算成"事件的效应"。 |
| **超额变化** `abnormal`（主口径） | 累计变化 − 同期"相对日历对齐"的市场平均变化 | 扣掉大盘/共同成分后的净效应 | 需要一个反事实基准。用全部事件的同期平均曲线做基准，能吃掉"同期别的项目也在投产"的污染。 |
| **突变** `surprise` | 累计变化 − 事件前同长度前段变化（二阶差分） | 是否在事件点**改变了原有趋势** | 对噪声敏感，样本小时不稳定。 |

**判读规则：三者同向才稳。** 若累计显著但超额不显著 → 那是市场整体趋势，不是这个项目。

## 窗口对齐：日频 vs 低频，两套口径

| 数据类型 | 对齐方式 | 用哪个函数 |
|---|---|---|
| 期货日线、日频现货 | **相对交易日**（第 k 个观测） | `compute_paths()` |
| 周度库存、周度开工率、月度产量 | **自然日**（事件后 n 天内最近的观测） | `compute_paths_by_days()` |

低频序列用"第 k 个观测"会退化成"事件后第 k 周"，而 120 天需要 17 个观测点——稀疏序列根本凑不出来，会返回空。**必须用自然日版本**，并报告 `obs_count`；`obs_count < 2` 判为不可计算，不要写 0。

## 统计口径与判读

```
n ≥ 3 : mean, median, sd, t(mean/sd·√n), 符号检验(精确二项), bootstrap 90% CI
n < 3 : 只给 mean/median，t/CI/p 全部置空，标 insufficient
```

- **符号检验**：n≤25 用精确二项分布，不要用正态近似。
- **bootstrap**：有放回重抽 2000 次，取 5%/95% 分位。不装 numpy 也要能跑。
- **安慰剂检验**：把每个事件日随机平移 ±180 天，重复 400 次，看真实事件均值落在随机分布的哪个分位。p 值大 = 效应只是噪声。

### 本类研究的典型结果（诚实预期）

新增产能投产对**价格的短期效应通常很弱**。实测 PP 27 个正式投产事件：

| 序列 | ±60 日超额 | t | 安慰剂 p | 结论 |
|---|---|---|---|---|
| 期货（3071 点，2014起） | −0.44% | −0.35 | 0.58 | 与噪声无法区分 |
| 现货（1887 点，2019起） | −0.20% | −1.04 | 0.55 | 与噪声无法区分 |

**两条完全独立的价格序列给出了一致的"无显著效应"结论**——这不是数据不够造成的，
而是本类现象的真实特征：单个装置的投产在价格上被成本波动、宏观情绪、同期其他项目对冲掉了。

分层后有方向性信号（中交 ±60 日 −2.47%；试车 ±120 日 期货 −9.02% / 现货 −7.40%，t≈−2.1至−2.3），
方向符合"供给兑现→价格承压"，但 n=3 不足以支撑强结论。

所以真正有用的输出是：
① 库存/开工率的**方向性**变化（供给确实增加了）；
② 逐项目的**结构性差异**（原料自给 vs 外购，成本曲线位置不同）；
③ 哪个项目在**特定区域**造成了真实压力；
④ **年度新增产能合计 vs 需求增速**的量级判断（这才是供给冲击的主战场，不是单项目窗口）。

## 常见失败模式（踩过的坑）

| 现象 | 原因 | 修法 |
|---|---|---|
| 期货事件全空 | 事件日期格式是 `YYYYMMDD` 而解析器期望 `YYYY-MM-DD` | `to_date()` 已兼容；自己写时注意 |
| 库存/开工率统计全空 | 用了 k-观测窗口，但序列只有 12–29 个点 | 改用 `compute_paths_by_days()` |
| 大量 0.0000 变化 | 事件落在序列覆盖区间外，被当成"前后相等" | 加 `obs_count < 2 → None` 的闸门 |
| 基差百分比出现 140% | 基差是绝对值差额，接近 0 时百分比失真 | 基差看绝对变化（元/吨），价格才看百分比 |
| HTML 白屏 | JS 的 TDZ 错误（const 声明晚于使用） | 用 node 跑一遍语法 + DOM 桩执行 |
| 报告里出现 `undefined` | 字段名不一致（`grade` vs `evidence_grade`） | 统一使用事件库的字段名，渲染前用 `||` 兜底 |
| 中文字段乱码 | 控制台 GBK 编码 | 设 `$env:PYTHONIOENCODING="utf-8"`，文件本身用 UTF-8 |
