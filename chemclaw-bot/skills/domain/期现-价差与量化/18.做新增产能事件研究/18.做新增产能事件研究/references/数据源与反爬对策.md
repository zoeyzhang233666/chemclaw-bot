## 二、生意社 100ppi 的三个关键发现

### 发现 1：必须用 Firefox UA

默认 Python UA 或简单 Chrome UA 会返回 **660 字节的 JS 反爬壳页**。

```python
HDR = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:121.0) "
                     "Gecko/20100101 Firefox/121.0"}
```

换成上述 UA 后同一 URL 返回 **78,245 字节**正常页面。

**这不是"JS 反爬"，是 UA 过滤。** 早期有子任务误判为 JS 反爬并放弃，实际是没换 UA。

### 发现 2：分页上限 50 页（硬限制）

| 尝试的 URL 形式 | 结果 |
|---|---|
| `list-15-1217-{N}.html`（N≤50） | ✅ 正常 |
| `list-15-1217-51.html` | ❌ 静默返回第 1 页 |
| `list-15-1217-1.html?page=100` | ❌ 静默返回第 1 页 |
| `list-15-1217-50.html?p=100` | ❌ 仍返回第 50 页 |

**结论**：50 页 × 50 条 = 2500 条资讯 ≈ **2026-04-09 至今**。更早的现货基准价**无法通过列表页获得**。

### 发现 3：detail 链接的正则

```python
ENTRY = re.compile(r'/news/detail-(\d{8})-(\d+)\.html"[^>]*>([^<]{0,120})</a>')
```

深层页面的链接是裸相对路径 `detail-...`，需要补前缀：

```python
def build_url(href):
    if href.startswith("http"): return href
    if href.startswith("/"):    return "https://www.100ppi.com" + href
    return "https://www.100ppi.com/forecast/" + href
```

⚠️ 早期 bug：无条件补前缀导致 `.../forecast/forecast/detail-...` 双前缀，全部 404。

## 二·五、⭐ 关键突破：生意社「商品主力基差表」日快照

**这是拿长历史现货价的正确入口。** 此前一直在新闻列表页里找出路（受 50 页限制，只能回溯 7 个月），
实际上生意社有一个按日期永久保存的快照页体系。

```
https://www.100ppi.com/sf2/day-YYYY-MM-DD.html
```

每页是"YYYY年MM月DD日 **商品主力基差表**"，表内有聚丙烯行：

| 列 | 含义 | 用途 |
|---|---|---|
| 现货价格 | **要的就是这一列** | 事件研究的现货锚 |
| 主力合约价 | 同日主力期货价 | 可校验基差 |
| 主力基差 | 现货 − 主力 | 直接得基差序列 |
| 180日基差最高/最低/平均 | 附带统计 | 分位参考 |

### 反爬要点：必须先 Session 预热

**直接 GET 快照页会返回 660 字节的 JS 壳。** 必须先访问首页建立会话：

```python
import requests, time

HDR = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:121.0) "
                     "Gecko/20100101 Firefox/121.0"}
s = requests.Session()
s.headers.update(HDR)
s.get("https://www.100ppi.com/", timeout=20)          # ← 预热，关键一步
time.sleep(0.5)

r = s.get("https://www.100ppi.com/sf2/day-2020-06-15.html", timeout=25)
print(len(r.content))   # 预热后 >20KB；未预热约 660B
```

间隔 **0.55 秒**稳定，2036 个工作日的连续抓取未触发封禁。

### 三源交叉验证（已验证一致）

| 日期 | 本方法解析 | akshare `futures_spot_price` | akshare `futures_spot_price_previous` |
|---|---|---|---|
| 2020-06-15 现货 | 7783.33 | 7783.33 | 7783.33 |
| 2020-06-15 主力 | 7303 | 7303.0 | 7303 |

另：2026-10-20 = 10733.3，与 `/sf/718.html` 图表页数值一致。

### 缺口特征（如实保留，不插值）

请求 2036 个工作日，命中 1887：

- **147 个缺失是法定节假日**——工作日但不是交易日，100ppi 不出表。**这不是数据缺口。**
- **真实站点缺口仅 2 个**：
  - `2025-03-26`：该页仅 36 行（邻日 52 行），聚丙烯整行缺失
  - `2026-09-25`：快照页未生成
- **T+1 延迟**：当天快照次日才生成；要最新数据需按日增量爬。

### ⚠️ 区域口径警告（写报告必须注意）

**100ppi 快照页未明示区域。** 行业惯例视为华东，但页面上**没有写**。

- 报告只能写「生意社 PP 现货价」，**不得写成"华东拉丝 T30S"**
- 需要严格区域+牌号口径时，只能走付费数据商（隆众/卓创）
- 可与「PP(拉丝)基准价」序列在重叠区间做一致性校验

### 适用性

该快照页是**全品类**基差表，不止 PP。换产品时把表格行名换掉即可
（聚乙烯、PVC、甲醇、PTA 等都在同一张表里）。这是本 skill 最有复用价值的数据入口。

## 三、基本面数据获取策略

### 策略 A：从行业经评正文抽取（推荐，已验证）

生意社的 PP 月度/半月经评文章正文里，会明确写出：

> "长假后的行业负荷推测在65%左右。当前周均产量不足70万吨，**库存位置继续下滑致不足49万吨**处于低位。"
> "前半月**总体开工率接近70%**，较前期相比大稳小动。"
> "截止9月30日，生意社PP拉丝基准价报盘价格**9933.33元/吨**。"

抽取模式：

```python
PATTERNS = [
    ("inventory",  r"库存[^。]{0,40}?(?:不足|降至|至|达到|为|报)?\s*(\d{1,3}(?:\.\d+)?)\s*万吨", "万吨"),
    ("operating",  r"(?:行业|装置|总体|平均)?开工率[^。]{0,25}?(\d{1,2}(?:\.\d+)?)\s*%", "%"),
    ("downstream", r"下游[^。]{0,15}?(?:负荷|开工率)[^>]{0,15}?(\d{1,2}(?:\.\d+)?)\s*%", "%"),
    ("spot_lasi",  r"PP拉丝基准价[^。]{0,20}?(\d{4,5}(?:\.\d+)?)\s*元/吨", "元/吨"),
]
```

**必须加合理性闸门**，否则会把"环比变动值 1.79"误当成"产能利用率 1.79%"：

```python
if field == "inventory" and not (10 <= v <= 300): skip
if field in ("operating","downstream") and not (30 <= v <= 100): skip
if field == "spot_lasi" and not (4000 <= v <= 20000): skip
```

### 策略 B：forecast 区 ID 遍历（慢，谨慎）

`forecast` 区（分析评论）与 `news` 区（资讯）是**不同的 ID 空间**。

实测校准：
- news 区：2026-10-20 → id 6368701；2026-04-09 → id 5507768（≈4,438 id/日，全站）
- forecast 区：2026-10-01 → id 207868；2025-10-29 → id 201034（≈**20 篇/日**）

**forecast 区 ID 密集，可以用 ID 遍历**，但：
- URL 的日期前缀必须**与文章实际日期完全一致**，差一天就 404
- 单个请求约 1.5 秒，串行太慢，必须多线程（14–16 并发）
- 估算 id 有漂移（实测 2026-10-14 估算 208131，实际 208326，偏差约 200）

**建议**：先用已知锚点校准，再做 ±400 的有界扫描，不要做无限窗口。

## 五、抓取纪律

1. **并发上限 16**，单请求超时 25 秒，失败重试 2 次
2. **每条数据存 `source_url` + `retrieved_at`**，不要只存数值
3. **存原始 HTML 到 `data/raw/pages/`**，首行写 `<!-- SOURCE_URL: ... -->`，便于事后复核
4. **不要绕过付费墙**，403 就记录为缺口
5. **区分"没找到"和"不存在"**，报告里写"未获得公开序列"，不要写"该数据不存在"
