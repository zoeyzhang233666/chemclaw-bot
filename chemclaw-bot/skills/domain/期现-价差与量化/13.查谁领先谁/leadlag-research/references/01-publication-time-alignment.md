# 发布时点对齐（Publication-Time Alignment）

## 为什么这是整个研究的第一性问题

领先滞后研究要回答的是「信息何时可用 → 价格何时反应」。

绝大多数周度/月度产业数据的公开文档里给的是**统计期**（如「截至 2024-10-23 的库存」），而研究者往往把统计期结束日直接当作「知道了这个数据的时点」。这两者之间通常相隔 **0–7 天**，在周度研究里这可能等于 20%~100% 的一个 Lag 周期。

造成的后果：

- **前视偏差（look-ahead bias）**：样本中混入了当时尚不可得的信息，把「事后才知道的库存变化」与「已经发生的价格变动」配对，人为制造出「库存领先价格」的假象。
- **反向偏差**：如果实际公布时间晚于统计期，那么正确做法是滞后 1 期；不滞后会系统性高估领先性。
- **无法复现**：不同研究者对「公布日」定义不同，结论不可比。

## 前提：必须拿到发布时间，而不是猜

优先级从高到低：

1. **数据源页面/API 的发布时间字段**（精确到秒最佳）。如资讯网站的文章列表 API 通常带 `publishTime` 时间戳。
2. **官方发布日历**（统计局、交易所、行业协会的固定发布日）。
3. **第三方镜像的转载时间**（可用于交叉验证，但取最早可见时间）。
4. **组织内部的接收记录**（邮件/群推送时间戳）。

**禁止：**用统计期结束日、用「一般周三发布」这类经验规律代替实际记录。规律可以用来**校验**（例如发现 3 期在周四），但不能用来**填充**。

## 标准做法

### 1. 建立双时间轴表

每期数据必须有两个字段：

| 字段 | 含义 | 示例 |
|---|---|---|
| `stat_date` | 统计期截止日（数据描述的时点） | 2024-10-23 |
| `pub_time` | 实际公开时间（精确到分钟，含时区） | 2024-10-23 14:06 CST |

以及对每个价格锚点：

| 字段 | 含义 |
|---|---|
| `P_before` | 公布前最后一个可交易的定格价 |
| `P_after` | 公布后的第一个收盘价 |

### 2. 判定公布落在交易时段的哪个位置

以国内商品期货（日盘 9:00–11:30 / 13:30–15:00，夜盘 21:00–23:30）为例：

| 公布时刻 | `P_before` | `P_after` | 说明 |
|---|---|---|---|
| 09:00 前 | 前一交易日收盘 | 当日收盘 | 开盘即反应 |
| 09:00–11:30 | 当日 11:30 定格价 | 当日收盘 | 盘中公布，午前部分已反应 |
| 11:30–13:30 | 当日 11:30 定格价 | 当日收盘 | 午休公布 |
| 13:30–15:00 | 公布时刻前一档价（或 11:30 定格价） | 当日收盘 | 最典型情形 |
| 15:00 后 | 当日收盘 | 次日收盘 | 盘后公布，次日反应 |

**收益构造：**
```
r_announce = ln(P_after / P_before)      # 公布当日的价格反应
```

**不要**用「统计期结束日收盘 → 次日收盘」来构造，除非公布确实发生在盘后。

### 3. 校验（必做，写进报告）

```
assert (pub_date == stat_date).all()          # 统计日 = 公布日？
pub_hours = pub_time.dt.hour.value_counts()   # 是否集中在某一时段
n_missing = n_expected_periods - n_observed   # 有无缺期
gap_days = stat_date.diff().dt.days           # 有无超长间隔（节假日）
```

甲醇案例的校验结果：

- 101 期全部满足 `统计日 = 公布日`
- 公布时刻：14 点 100 期、13 点 1 期 → 集中在盘中 13:00–15:00
- 3 期落在周四（节假日顺延），8 处 6/8/14/15 天的超长间隔（春节、国庆）

结论：可以采用「当日 11:30 定格收盘 → 当日 15:00 收盘」作为公布日反应，无需额外滞后。

### 4. 若公布晚于统计期，怎么处理

用**保守滞后**：把数据的可得时点整体推后到下一期，`effective_available_date = next_period_end`。这会损失一部分样本，但保证无前视偏差。宁可低估领先性，不可高估。

## 频率统一

- **高频对低频**：把高频数据**采样**到低位指标的公布日（收盘价），**不要**对低频数据做前向填充再插值。前向填充会让「同一个库存值」在多个价格观测上重复出现，人为提高相关性和有效样本量假象。
- **日线 → 周度**：按公布日分组取当天收盘，不聚合整周。
- **样本量**：`n = 有效配对数`，而不是日历周数。

## 时区与交易日

- 统一换算到交易所时区（北京时间 UTC+8），并在报告注明。
- 节假日会导致公布日顺延，需允许 `stat_date` 与实际工作日错位，但不能因此丢失该期数据。
- 若某期公布日无交易（周末），`P_after` 取下一交易日收盘，并记录这一偏差。

## 交叉验证技巧

1. **多源对照**：同一数据常被多个资讯商转载，取最早可见的转载时间作为公布时点的上界。
2. **数值对照**：用新闻稿中引用的数字核对你的解析结果（注意口径差异：不同资讯商的样本港口范围不同，甲醇案例中 2026-10-08 一家报 24.82 万吨、另一家报 30.51 万吨）。**必须锁定单一来源**，不可混用。
3. **分项加总**：若数据有分项（华东/华南），校验 `总量 = Σ分项`，防止解析错位。
