# 领先滞后关系研究（Lead–Lag Research）

## 这个 Skill 解决什么问题

业务方常见的问题是：**「库存能不能预测价格？」「开工率下降多久后价格才反应？」「是现货带动期货，还是期货带动现货？」**

这个问题的**错误做法**极其普遍，而且结果看起来很专业：

- 只报告 25 个 Lag 中相关系数最大的那个 → 必然能找到「显著」
- 用统计期结束日当作公布日 → 引入最多 7 天的信息泄漏
- 忽略重叠样本导致的自相关 → p 值虚低
- 用库存水平和价格水平做相关 → 两个 I(1) 序列的伪回归，r 高达 0.6 却毫无意义
- 不分阶段 → 一个平均数字掩盖了方向完全相反的不同时期

本 Skill 的全部设计都是为了**让这些错误无法被无意犯下**，并在结论中如实说明「没有发现稳健领先关系」也是一种有效结论。

## 核心原则（不可协商）

1. **一切以真实发布时点为准。** 每个指标必须有「统计期」和「实际公布时间」两个字段。研究样本的信息集只能包含 T 时刻已公开的数据。若数据源不含发布时间，必须去原文页面/公告 API 抓取，**不允许用统计期结束日代替**。
2. **完整报告 Lag 曲线，禁止只报最大值。** ±K 周内每个 Lag 都要给出 r、p、有效样本量 n。禁止挑选。
3. **多重比较必须校正。** 扫描 25 个 Lag 就是在做 25 次检验，必须给出 FDR (BH) 与 Bonferroni 校正后的 q 值。
4. **重叠样本必须用 HAC 标准误。** Lag≠0 时样本重叠，朴素 t 值系统性偏大，必须用 Newey-West。
5. **Lag 符号必须显式定义。** 报告首页写明 `Lag=+k → A 领先 B k 期`。
6. **水平序列只能作为反例。** 库存/价格水平之间的高相关必须作为伪回归案例呈现，不能当作发现。
7. **统计领先 ≠ 因果 ≠ 可预测。** 结论措辞不得越界，不得给出交易建议。
8. **稳定性检验是结论的一部分。** 按年度与市场阶段分段，比较「最优 Lag」的位置与符号是否一致。位置漂移即视为不稳定。

## 执行流程

### 第 0 步：明确口径（写下来，别默认）

先回答这 6 个问题，写进报告的「指标定义」章节：

| 问题 | 示例（甲醇案例） |
|---|---|
| 指标 A 精确口径 | 中国甲醇样本港口库存总量（万吨），隆众资讯，华东+华南 |
| 指标 B 精确口径 | 郑商所 MA 主连收盘价，对数收益 |
| 频率与统计窗口 | 周度，统计日为周三，值截至当日 |
| A 的实际公布时间 | 统计日当天 14:00 前后（盘中披露） |
| B 的可用时点 | 日盘 15:00 收盘 |
| 历史覆盖 | 2024-10-23 ~ 2026-10-14，101 期，无缺失 |

**关键判断：** 若 A 在统计日盘中公布（如 14:00），则「当时的市场价格」应取当日 11:30 的定格价格，而非当日收盘价。若 A 在收盘后公布，则当日收盘价即为「公布前价格」。这个细节决定样本是否有前视偏差。

详见 [`references/01-publication-time-alignment.md`](references/01-publication-time-alignment.md)。

### 第 1 步：数据变换

- 先做 ADF 单位根检验。非平稳则差分。
- 收益用对数收益 `ln(P_t/P_{t-1})`，注意锚点落在「公布前 → 公布后」。
- 库存变化同时准备两种口径：绝对量（万吨）与百分比（对低库存期更公平）。
- 保留一份「水平 × 水平」设定，仅用于伪回归对照。

详见 [`references/02-data-transforms.md`](references/02-data-transforms.md)。

### 第 2 步：Lag 扫描（±K）

用 `scripts/leadlag.py` 的 `lag_scan()`。对每个 `k ∈ [-K, K]`：

```
配对 (a_t, b_{t+k})
r = pearson(a, b)
n = 有效配对数
t = r√(n-2)/√(1-r²)          朴素 t
t_nw = Newey-West 稳健 t       (Bartlett 核, L ≈ ⌊1.5|k|⌋+1)
n_eff = n · (1-ρ_aρ_b)/(1+ρ_aρ_b)   自相关修正后的有效样本量
```

输出表必须包含以上全部列。**不要**在这个阶段筛选。

### 第 3 步：多重检验校正

- BH-FDR：`q_i = min_{j≥i} p_j·m/j`
- Bonferroni：`p·m`

判定标准：**只有 q < 0.05 才能声称「存在领先关系候选」**，且仍需第 4 步稳定性支持。若所有 q 都 ≥ 0.05，结论就是「未发现稳健领先关系」——这是本 Skill 最常见的正确结论。

### 第 4 步：稳定性检验

1. **按年度**分组重做完整 Lag 扫描。
2. **按市场阶段**分组（阶段应按价格/库存路径客观切分，并写明切分依据与起止日）。
3. 比较各组的「最强 Lag」：位置是否接近？符号是否一致？q 值是否显著？
4. 画「Lag × 时期」热力图，看是否存在**竖条纹**（同一 Lag 在所有时期都显著）。斑块状 = 不稳定。

### 第 5 步：稳健性与安慰剂

- **变换稳健性**：至少 6 种变换组合，看最强 Lag 是否漂移。
- **伪造时点安慰剂**：把 A 的可得时点提前 1–2 期（现实中不可能），重做扫描。若「领先关系」依然出现，说明它是噪声/方法伪影。
- **滚动相关**：窗口 26 期（约半年），画时间序列并标注近似显著带 `±1.96/√(n-3)`。
- **预测回归**：`b_{t+L}` 对 `Δa_t` 及控制变量做 NW 稳健回归，报 R² 与系数 t 值。可加入需求侧/供给侧对照指标，检验「库存变化本身」是否真有解释力。

### 第 6 步：交付

| 交付物 | 要求 |
|---|---|
| HTML 报告 | 自包含单文件，含交互式 Lag 曲线、点击 Lag 查看对齐明细/散点/滚动/逐年、矩阵热力图、多重检验警示 |
| Excel 工作簿 | ≥12 个工作表：原始 A、原始 B、发布日期与可得时点、研究样本、Lag 对齐明细、Lag 扫描、分段逐年、滚动、回归稳健性、公式口径 |
| 脚本 | 可复现的 `leadlag.py` + 项目 `pipeline.py` |

模板见 `templates/`，完整案例见 `examples/methanol-port-inventory/`。

## 结论怎么写（措辞模板）

**发现显著且稳定时：**
> 在 ±12 周窗口内，Lag = +k 周处相关系数为 r（n=…，FDR q=…），且在 Y 个分阶段中有 M 个同号显著。该关系在 [变换 A/B] 下稳健。但这仅是统计相关性，尚不能推断因果或可交易性；需进一步用样本外数据与事件研究验证。

**未发现稳健关系时（常见）：**
> 在 ±12 周窗口内，25 个 Lag 的最小未校正 p 值为 …，FDR 校正后 q 值为 …，无任何 Lag 通过多重比较校正。分阶段得到的「最优 Lag」在 −12 到 +12 之间漂移且方向不一致，分段样本量（n=…）不足以支撑方向判断。因此现有证据不支持「A 领先 B」或「B 领先 A」的稳定关系。
>
> 这一点本身有信息价值：A 与 B 的同期相关接近零，说明 A 的信息在公布时已被价格吸收，或 A 并非边际定价因子。

**必须写进报告的局限声明：**

- 统计相关不等于因果关系，也不等于可交易的预测能力；未做样本外或收益验证。
- 样本量（n=…）、覆盖区间（…）有限，可能不足以代表长期规律，结构断点未知。
- 指标为特定资讯商口径，与其他口径不可混用。
- 不构成投资建议。

## 常见陷阱清单

| 陷阱 | 后果 | 规避 |
|---|---|---|
| 用统计期结束日当公布日 | 前视偏差，夸大领先关系 | 抓真实发布时间，逐条校验 |
| 只报最大相关系数 | 25 次检验至少 1.25 个偶然显著 | 报告全部 Lag + FDR 校正 |
| 忽略重叠样本 | p 值虚低 2–4 倍 | Newey-West HAC |
| 水平对水平相关 | 伪回归，r 可虚高至 0.6+ | ADF 检验 + 差分 |
| 用日线数据当周度 | 样本重复计数 | 按 A 的公布日聚合，不填充 |
| 「提前知道」的伪领先 | 把噪声当信号 | 伪造时点安慰剂 |
| 分段后仍当结论用 | n=25 时 r=0.5 的 CI 宽达 ±0.35 | 分段结果只作方向参考 |
| 单一资讯商口径混用 | 数值矛盾（如 24.82 vs 30.51） | 锁定单一来源，交叉核对 |

## 脚本

- `scripts/leadlag.py` — 统计内核：`lag_scan` / `split_scan` / `rolling_corr` / `fake_release_scan` / `predictive_regression` / `p_fdr_bh` / `p_bonferroni` / `ci_r`，纯 numpy+scipy。
- `scripts/pipeline.py` — 端到端模板。**只改 CONFIG 区的 3 个路径与列名映射**即可用于新课题；输入为两个 CSV（A 必须含 `stat_date` 与 `pub_time` 两列）。

运行自检与示例：

```bash
python scripts/leadlag.py --selftest        # 合成数据验证：应恢复 +3 lag
cd examples/methanol-port-inventory
python pipeline.py                          # 应输出：0 / 25 通过 FDR
```

该案例的 `pipeline.py` 已用真实数据跑通，输出与主分析完全一致（n=101、Lag=−6、p=0.0243、q=0.609），可作为复现基线。
