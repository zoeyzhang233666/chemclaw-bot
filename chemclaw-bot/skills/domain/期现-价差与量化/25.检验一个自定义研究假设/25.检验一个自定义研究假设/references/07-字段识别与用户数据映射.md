# 07 字段识别与用户自有数据映射

## 一、为什么要做这一步

公开数据往往拿不到（本项目：港口库存只能抓到 3 周的 live edge），而用户手里常常已经有
内部数据库导出的完整表。此时正确的做法不是"用模拟数据顶上"，而是
**直接把用户的表接进同一套引擎**。

## 二、一条命令

```bash
python scripts/map_user_data.py --file 我的库存与基差.xlsx --sheet Sheet1 --out build/user_mapping.json
```

支持 `.xlsx / .xlsm / .csv`。输出：

```
sheet=4-原始数据-库存 rows=228 freq=周度
  观测日        -> asof        conf=0.95
  发布时间      -> pub_ts       conf=0.80
  港口总计      -> inventory    conf=0.80
  华东          -> east         conf=0.95
  ...
需要确认：
  - 列「来源类型」未识别，请说明它是什么指标（以及单位）。
  - 没有识别到价格/基差列：请指出现货价、期货价各是哪一列。
```

## 三、识别逻辑

1. **表头行定位**：前 10 行里非空单元格最多的一行。
2. **字段匹配**：每个字段配一组别名正则，`完全匹配`得分 0.95，`包含`得分 0.8。
3. **日期识别**：兼容 `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYYMMDD`、`YYYY年M月D日`，
   并识别 Excel 序列号（纯数字 5 位）。
4. **频率推测**：日期列相邻间隔的中位数 → 5–10 天为周度，≤3 天为日度。
5. **单位推测**：按数值量级猜（全在 30–250 → 万吨；>800 → 元/吨；0–3 → 比例），
   但**一律标为猜测**。

## 四、字段别名库（节选）

| 规范字段 | 中文名 | 别名 |
|---|---|---|
| `asof` | 观测日 | 日期 / 统计日 / 观测日 / 截止 / asof / date |
| `pub_ts` | 发布时间 | 发布 / 公布 / pub_ts |
| `inventory` | 库存 | 库存 / 港存 / 总计 / 合计 / 总量 / stock |
| `east` / `south` | 华东 / 华南 | 华东 / 华南 |
| `region` | 分区域 | 江苏 / 浙江 / 广东 / 福建 |
| `spot` | 现货价 | 现货 / 基准价 / 出罐 / 出厂 |
| `fut` | 期货价 | 期货 / 近月价 / 主力 / 盘面 |
| `basis` | 基差 | 基差 / basis / 基差率 |
| `coverage` | 覆盖率 | 覆盖率 / 样本 |

## 五、必须人工确认的情形

| 情形 | 处理 |
|---|---|
| 置信度 < 0.8 | 必须用户确认，不得自动进入检验 |
| 同一字段匹配到多列 | 列出全部候选，让用户选 |
| 日期列缺失 | 阻断：频率无法确定 |
| 单位不明 | 阻断：万吨与吨差 10000 倍，会让所有结论失真 |
| 数值列含 "—" / "暂无" | 视为缺失，不插值，计入 gap |
| 表中同时有港口总计与分区域 | 用总计做 X，分区域仅作诊断 |

## 六、接入流程

```bash
# 1) 识别
python scripts/map_user_data.py --file 我的表.xlsx --out build/user_mapping.json

# 2) 按映射把用户表转成引擎要求的列名（total / asof / near_fut / near_basis / spot）
python scripts/normalize_user_data.py --mapping build/user_mapping.json \
    --out data/user_inventory.csv data/user_price.csv

# 3) 审计 → 确认 → 检验（与标准流程完全一致）
python scripts/run_hypothesis_test.py audit --design build/research_design.json
```

## 七、给用户的填写说明（可直接转发）

> 请提供两张表：
> 1. **库存表**：至少两列 —— 统计日期（YYYY-MM-DD）、库存数值（注明单位：万吨/吨）
> 2. **价格表**：至少三列 —— 日期、现货价、期货价（注明是哪个月份合约或主力）
>
> 如果能提供**发布时间**（几点几分公布），前视偏差的处理会更严格；
> 如果没有，我们默认按"收盘后可得"处理，并在报告里写明这一假设。

## 八、隐私与合规

* 用户数据只在本地脚本处理，不上传任何服务器。
* 报告中只呈现聚合结果与字段统计，不逐条复述原始业务数据（除非用户要求）。
* 若数据来自付费数据库，需用户自行确认使用条款。
