# 06 自然语言假设解析规则

## 一、总体原则

解析器 `scripts/hypothesis_parser.py` **只做可回溯映射，不做判断**：

* 每个识别出的变量都带 `evidence`（原文命中的词）与 `confidence`
* 低置信度 / 多候选 → 写入 `open_questions`，标 `blocking: true`
* 解析器**不接触数据、不做统计**，只产出设计草稿

## 三、四条关键规则

### 规则 1：抽象词必须落地为可计算口径

「走强」不可检验。解析器给出 6 个候选：

| 候选 | 定义 | 适用 |
|---|---|---|
| `basis_level` | 基差绝对值 Δbasis>0 | 最直观 |
| `basis_rate` | 基差率上升（可跨年份比较） | 基差水平差异大时 |
| `basis_change` | 基差比前值变化 | 周度口径 |
| `basis_rank` | 基差滚动 250 日分位上升 | 最贴近"强弱"本意 |
| `fut_return` | 期货收益率 | 非基差口径 |
| `spot_return` | 现货价变化 | 只看现货 |

**除非原文明确写了"基差率"或"分位"，否则 `need_confirm = true`。**

### 规则 2：「连续 N 周」的严格解读

* 「连续」= 相邻两期，且间隔 5–10 天
* 「下降」= 严格小于 0（0.01 也算下降）
* 「任何下降都算」还是「降幅要超过 1 万吨」——**必须问**，默认严格符号

### 规则 3：「更容易」= 比例比较，不是均值比较

「更容易走强」字面是**概率**（P(Δ>0) 更高），但实务上也常被理解为**幅度**更大。
解析器两个都登记（P2 方向一致率 + P1 均值差），不让用户事后挑。

### 规则 4：对照组不能是"其它所有周"就完事

默认对照组容易混入季节性/库存水平差异。必须给出**等价过滤**：
同季窗口（ISO 周 ±3）、同库存分位带。否则差异可能只是"库存低位时基差本来就高"。

## 四、必须反问的 8 个问题

| 编号 | 问题 | 不确认的后果 |
|---|---|---|
| Q1 | 品种与现货区域 | 数据源对不上 |
| Q2 | 库存口径（港口/厂库/社会） | 三个口径方向常相反 |
| Q3 | 「随后」多久 | 窗口随意 → p-hacking |
| Q4 | 「走强」的统计口径 | 结论不可证伪 |
| Q5 | 用哪个期货合约计价 | 近月会换月 |
| Q6 | 入场时点（当日收盘/次日开盘） | 前视偏差 |
| Q7 | 样本区间、是否剔除极端阶段 | 结果不可比 |
| Q8 | 会试几个口径（用于多重检验登记） | 假阳性 |

其中 Q1–Q4 为**阻断性**：没回答不能出正式结论。

## 六、多假设场景

用户一次给多个假设时：

1. 每个假设**独立**生成设计文件（`design_{i}.json`）
2. 各自登记检验，但**合并做 BH 校正**（总检验数 = 各假设检验数之和）
3. 报告中分开陈述，禁止「三个里有一个显著就宣布有效」
