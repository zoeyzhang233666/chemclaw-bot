# 05 数据源与字段规范

## 1. 抓取器（fetch_data.py）

```bash
python scripts/fetch_data.py --raw raw --start 2019-01 --end 2027-12 [--skip-spot|--skip-futures|--skip-verify]
```

产出三个文件 + 一个元数据：

| 文件 | 内容 | 字段 |
|---|---|---|
| `raw/spot_methanol_100ppi_benchmark.csv` | 生意社甲醇基准价 | `date, price, source_url, title` |
| `raw/MA_MA*.json` | 郑商所逐合约日线（每合约一个文件） | `d, o, h, l, c, v, oi, settle` |
| `raw/verify_100ppi_basis_rate.csv` | 100ppi 主力基差率（口径核验用） | `date, rate` |
| `raw/_sources.json` | 抓取时间、来源、覆盖范围 | — |

### 100ppi 反爬处理

生意社有 JS 挑战页（"正在进行安全检查"）。抓取器做法：

1. 从页面 JS 中取出静态 token
2. 设为 cookie `HW_CHECK=<token>`
3. 先对 `https://www.100ppi.com/` 做一次暖机 GET
4. 再访问 `www.` / `me.` / `graph.` 子域

token 可能随站点改版失效。失效时：重新打开一个商品页，从 JS 里找 `HW_CHECK` 的值。

### 新浪期货接口限制

逐合约 K 线接口对**过老合约返回 null**（甲醇约 MA1905 之前）。
如果现货序列起点更晚，这个限制实际不构成影响。

## 2. 自带数据的字段规范

最小可用字段（CSV 或 Excel 均可）：

### 现货文件 `raw/spot.csv`

| 列 | 必需 | 说明 |
|---|---|---|
| `date` | ✅ | `YYYY-MM-DD` |
| `price` | ✅ | 数字，元/吨，与期货同单位同税基 |
| `source_url` | 建议 | 便于追溯 |
| `title` | 可选 | 原文标题 |
| `region` | 建议 | 地区（华东/太仓/…） |
| `spec` | 建议 | 品级/规格 |
| `tax` | 建议 | `included` / `excluded` |

### 期货文件 `raw/fut_<CODE>.csv`

| 列 | 必需 | 说明 |
|---|---|---|
| `date` | ✅ | 交易日 |
| `close` | ✅ | 收盘价（**不要用结算价混用**） |
| `oi` | ✅ | 持仓量（选主力必需） |
| `volume` | 建议 | 成交量（流动性判断） |
| `settle` | 可选 | 结算价 |

一份合约一个文件，文件名带合约代码：`fut_MA2501.csv`。

## 3. 字段校验（进引擎前必做）

```
□ date 唯一、单调递增、无重复
□ price/close 全为正数、无 0、无空串（空串会变成 NaN 污染全流程）
□ oi ≥ 0，且不能大面积为 0
□ 现货与期货单位一致（都用元/吨，不是元/千克）
□ 税基一致（都用含税或都用不含税）
□ 现货日期 ⊆ 期货交易日（否则对齐后会大幅缩水）
□ 合约代码能解析出交割年月（如 MA2501 → 2025-01）
```

引擎会在对齐时打印：

```
[DATA] 现货 1083 点 (2022-08-17 ~ 2026-10-20)；合约 101 个
[DATA] 可对齐交易日 1004 (2022-08-17 ~ 2026-10-20)
```

**如果"可对齐交易日"远小于现货点数**，说明现货大量落在非交易日
（周末/节假日报价），要回头检查数据源的时间戳口径。

## 4. 缺数据的原则

**三不原则：不插值、不填充、不平移。**

| 情形 | 错误做法 | 正确做法 |
|---|---|---|
| 某天没有现货 | 用前一天价格填 | 该日从对齐序列里去掉，`N` 减 1 |
| 某合约某天无成交 | 用结算价代替 | 该日不进入该合约的有效样本 |
| 现货序列中间缺一段 | 线性插值 | 保留缺口，报告里标出来 |
| 期货数据源缺老合约 | 用近似合约拼接 | 缩短样本区间，在报告里说明 |
| 节假日无数据 | 补一个均值 | 只保留双方都有值的交易日 |

**理由**：插值会人为制造"零变化"日，稀释极端值，
让分位计算系统性地向中间收缩，直接削弱本应检验的极端分位效应。

## 5. 数据源清单（甲醇案例）

| 项目 | 来源 | 覆盖 | 口径 |
|---|---|---|---|
| 现货 | 生意社 100ppi「甲醇基准价」 | 1083 点，2022-08-17 起 | **全国**交易指导价、含税、元/吨（模型价） |
| 期货 | 新浪财经逐合约 K 线 | 101 个合约，MA1905 起 | 郑商所 MA，收盘价 + OI |
| 口径核验 | 100ppi 主力基差率 | 4505 点，2014 年起 | 与现货同源 |

### 现货口径的降级说明（必须原样保留）

公开免登录渠道**没有**华东（太仓/江苏）甲醇现货的日频历史序列：

- 隆众（OilChem）、卓创（Sci99）、钢联（Mysteel）：华东价格需付费或注册
- Mysteel 列表页遇 163dun 验证码
- 甲醇网（jiachunwang.com）：SSL 主机名不匹配
- 100ppi「甲醇商品报价动态」日评：有按省份的贸易商报价（如江苏 3800 元/吨），
  但**稀疏且口径不一致**，无法构成长序列

因此本案例实际口径是 **全国基准价 − 郑商所主力**，
报告的每一处都必须写成"华东（降级：全国基准价）"，不能伪装成华东实盘。

## 6. 抓取时间戳

`raw/_sources.json` 记录 `fetched_at`。
报告页脚显示这个时间——因为**数据源会修订历史值**，
不同时间跑出来的数字可能略有差异，时间戳让结果可复现。

## 7. 新增品种的适配清单

换一个品种（如纯碱 SA、玻璃 FG、尿素 UR）需要改的只有：

1. `fetch_data.py` 里的现货源与合约代码前缀
2. `spec.json` 里的窗口/阈值（一般不用改）
3. `report_template.html` 里的品种名、合约规则表
4. `references/01` 里的合约规则（交易单位、最后交易日、交割品级）

**引擎代码完全不用改**——它只认 `date / spot / fut / oi / contract` 五个字段。
