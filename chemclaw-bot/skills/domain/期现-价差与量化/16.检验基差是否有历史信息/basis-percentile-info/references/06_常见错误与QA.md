## C. 统计类错误

| # | 错误 | 后果 | 检查方法 |
|---|---|---|---|
| C1 | 重叠样本当独立算 t 检验 | p 值小一个数量级 | 有没有块自助 |
| C2 | 只用均值不报中位 | 厚尾下均值误导 | `mean` 与 `median` 是否同号 |
| C3 | 不做退化保护 | 块长吃光样本，p 荒谬变大 | `len(a) <= 2*b` 应返回 None |
| C4 | 只报有利的组合 | 选择性报告 | 敏感性表要全铺开 |

| C6 | "显著"说成"能赚钱" | 越界 | 报告里搜"建议/信号/买入" |
| C7 | 不报样本量 | 读者无法判断可信度 | 每张表都有 `n` 列 |

## F. 一个真实修过的 bug（供参考）

**症状**：分组后低分位 943 条、中间 60 条、高分位 0 条。

**排查过程**：

1. 打印分位分布 → min `−0.079`、max `0.321`、median `0.017` —— 分位不是 (0,1)！
2. 定位 `_rank_of` 返回 `less/n`（如 `0.0054`）
3. 发现调用处又把它喂给了 `percentile_linear(sorted(hist), rank)`
   —— 相当于"对秩再取分位"，把秩压缩到了低端
4. 修复：`pct = _rank_of(hist, b)`，**秩本身就是分位，不要再套一层**

**教训**：分位实现完，第一件事是打印 `min/max/median` 三件套。
正常情况应该是 `≈0 / ≈1 / ≈0.5`。三个数不对，立刻停手排查，
不要往下算统计——后面的所有数字都会是垃圾。

`tests/test_statistics.py` 的 `T01a~T01g` 就是这次事故留下的护栏。
