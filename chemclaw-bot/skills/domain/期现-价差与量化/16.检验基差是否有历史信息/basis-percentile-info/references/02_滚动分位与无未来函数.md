# 02 滚动分位与无未来函数

> 这一章是整份研究的**诚信基础**。分位算错，后面所有统计都在自我欺骗。

## 1. 为什么要滚动分位

用户真正问的是"**当时**基差处在什么位置"。这里的"当时"是硬约束：

- 2023-05 的交易员只能用 2023-05 及之前的数据
- 用 2026 年才看到的分布去给 2023 年贴"低分位"标签，等于用未来信息
- 这样得出的"低分位之后会涨"必然显著——因为极值本身就是事后确认的

**全样本分位 + 事后贴标签 = 典型的数据窥探（data snooping）。**

## 2. 分位公式（百分位秩）

```
P_t = ( #{B_j < B_t} + 0.5 × #{B_j = B_t} ) / N
```

其中 `{B_j}` 是窗口 `j ∈ [t−W, t−1]` 内的历史值，`N` 是窗口内有效样本数。

### 三个设计选择

**① 为什么用「秩」而不是「分布拟合的分位」**

秩分位不假设分布形状，对厚尾、双峰、跳跃都稳健。
甲醇基差是个有明显厚尾与结构性漂移的序列，正态假设会严重错估尾部。

**② 为什么并列取中点**

若 `B_t` 在窗口中出现多次（现货报价不常变时很常见），
`less`/`n` 会系统性地偏向低分位（当前值被排在所有并列值之前），
`(less+n_below+1)/n` 又会偏向高。`0.5` 中点是无偏的标准竞争秩。

**③ 当前值不在窗口内时的 `less/n`**

因为窗口是 `[t−W, t−1]`，严格来说 `B_t` 不在样本里，此时 `equal=0`。
取 `less/n`（落在第 `less` 与 `less+1` 个之间）与带并列时的中点口径**连续一致**：

```
值在样本内（并列 equal=e）：  (less + 0.5e)/n
值不在样本内（equal=0）  ：  less/n
```

这样"当日值等于历史中位数"时恰得 0.5，"高于全部历史"时得 `(n−0.5)/n`——
在 `k=0.1` 阈值下仍能进"≥0.9"的高分位组。

> **踩过的坑**：早期实现用了 `(less − 0.5)/n`，导致历史最大值只能得到
> `1 − 0.5/n`。在 `k=0.1` 阈值下，`n=250` 时 `0.998` 仍 > 0.9 没问题，
> 但 `k=0.005` 级别的极严阈值下会永远进不了高分位组，且与并列口径不连续。
> `tests/test_statistics.py` 的 `T01g 最大值可达高分位` 就是防这个。

## 3. 三道闸门

### 闸门一：窗口严格滞后

```python
hist = values[max(0, i - window) : i]     # 注意：到 i 为止，不含 i
pct[i] = rank_of(hist, values[i])
```

窗口里是 `i-W … i-1`，共 W 个。`values[i]` 只作为**被比较的值**，不进窗口。

最小样本数门槛：`N < 20` 时不给分位（样本太少，秩没有意义）。
本 Skill 用 `MIN_HIST = 20`。

### 闸门二：未来收益不得出现在因子里

两种口径都要算，都要报：

| 口径 | 因子时点 | 收益区间 | 回答的问题 |
|---|---|---|---|
| **信息检验** `info` | t | `[t, t+h]` | 分位状态之后**未来**会发生什么 |
| **可操作** `deploy` | `t−h` | `[t−h, t]` | 站在 t 时，**过去**这 h 天发生了什么 |

`info` 口径是标准的"事件研究"口径，回答"有没有信息"。
`deploy` 口径把所有时点压到 t 之前，回答"是不是只有事后才知道"。

**两者方向一致**才说明信息不是时点对齐造成的错觉。
本 Skill 的引擎对两种口径分别产出 `bucket_info` / `bucket_deploy`。

### 闸门三：数据末端必须标"当时未知"

序列最后 W 个点，站在当时只可能看到部分窗口。
把它们算出来的分位当作"历史可复现的信号"是错的。

处理：
1. 照常计算并显示（用户要看"当下在哪"）
2. 打标记 `point_in_time_known = 0`
3. **时间稳定性检验（逐年、逐月、逐结构）中剔除**

```
若 t > T − W ：point_in_time_known = 0
```

本 Skill 实测边界：`W=250` 时最后 250 个点（2025-10-09 起）为回填，
`W=500` 时 2024-09-19 起，`W=750` 时 2023-09-06 起。

## 4. 分组

```
低分位   P_t ≤ k
高分位   P_t ≥ 1 − k
中间分位  k < P_t < 1 − k
```

**阈值必须左右对称**（`k` 与 `1−k`），否则低分位组和高分位组的样本量不可比，
"低减产减高"的差值会把"组大小不对称"混进"位置效应"里。

- `k=0.2` 时每组约 20% / 60% / 20%
- `k=0.1` 时更极端，样本少但信号更纯
- `k=0.4` 时接近三分，样本多但差异被稀释

默认报 `k ∈ {0.1, 0.2, 0.3, 0.4}`，看结论是否单调。

## 5. 怎么在报告里"看见"计算过程

HTML 报告第 3 节 + 第 5 节要有：

1. **公式块**：把上面的式子直接印出来
2. **窗口示意**：某一天的窗口起止日期、样本数、小于/等于个数、最终秩
3. **交互明细**：点任意一天，看到它是怎么被分到低/中/高的

Excel 的 `02_滚动分位计算` 表把每个有效日的
`窗口起始日 / 窗口结束日 / 样本数 / 小于个数 / 等于个数 / 百分位秩` 全部列出来，
秩列用**真公式** `=(F5+0.5*G5)/E5`，用户可以改数字验证。

`01_基差日度` 表的 J 列更进一步，用 Excel 的
`COUNTIF(G..:G..,"<"&G{r})` 从基差率列独立重算分位，
与本 Skill 计算出的 I 列并排——**两列必须完全一致**，否则就是实现有 bug。

## 6. 常见错误清单

| 错误 | 症状 | 修法 |
|---|---|---|
| 窗口包含当日 | 分位分布略偏，极值日分位不到 1.0 | `[i−W, i−1]` |
| 用全样本 min/max 归一 | 未来信息漏入，信号"异常显著" | 滚动窗口 |
| 用全样本 P20/P80 | 同上，且随时间漂移 | 滚动分位 |
| 分位后再做 z-score | 破坏秩的稳健性 | 直接用秩 |
| 窗口内插值补缺 | 稀释极端值，分位被平滑 | 只用有效值，`N` 可以小于 `W` |
| 不设最小样本 | 前 3 个点也出分位 | `N ≥ 20` |
| 末端回填不标记 | 稳定性检验把回填当历史 | `point_in_time_known` |
| 阈值不对称 | `P≤0.2` 与 `P≥0.7` 组大小差 10%+ | `k` 与 `1−k` |
| 用固定元/吨阈值 | 价格翻倍后"高基差"定义失效 | 用分位不用绝对值 |
| 换月日不处理 | 基差伪跳变被算成"回归" | 标记 `roll_day`，单独量化 |

## 7. 复杂度与性能

朴素的滚动秩是 `O(n·W·log W)`。1000 天 × 250 窗口约 250 万次比较，
Python 里秒级完成，不需要优化。

如果序列到 10 年（约 2400 天）× 窗口 750，仍是一秒内。
**不要为了性能引入近似排序或分桶**——那会引入不可解释的偏差。
