# 基差分位信息检验（basis-percentile-info）

## 这个 Skill 解决什么问题

用户问出下面这类问题时用它：

- 「甲醇基差现在在历史 94% 分位，历史上这种时候之后一般会怎么走？」
- 「检验一下华东甲醇现货和期货的基差有没有历史信息。」
- 「基差低分位之后现货涨还是期货跌？帮我分清楚。」
- 「不同分位阈值、不同观察窗口，结论一样吗？」

**它产出什么**：一份可直接打开的单文件交互 HTML 报告 + 一份 13 表 Excel 工作簿 + 全部可复算的中间数据。
**它不产出什么**：不给交易建议、不给信号、不给持仓或点位。研究口径固定为「历史已实现统计」，报告里必须保留免责声明。

## 三个最容易做错的地方（本 Skill 的核心价值）

这三条做错，后面所有数字都不成立。

### 1. 用全样本分位当"当时的信号"（未来函数）

最常见的错误：拿整段数据的 P20/P80 当阈值，然后说"过去处在低分位时会怎样"。
问题在于：2023 年的交易员不可能知道 2026 年的基差分布。

**正确做法**：滚动分位，窗口严格滞后。

```
P_t = ( #{B_j < B_t} + 0.5·#{B_j = B_t} ) / N ,   j ∈ [t−W, t−1]
```

窗口只取 t **之前**的 W 个交易日，t 当日只作为被比较的值，不进入窗口。
另外：数据最后 W 个点的分位本质是"用未来的数据回填出来的"，
显示可以，**做时间稳定性检验时必须剔除**（本 Skill 用 `point_in_time_known` 标记）。

### 2. 只算基差、不分拆现货与期货

基差变化 = 现货变化 − 期货变化。
同一个"基差从高分位回落"，可能是现货跌出来的，也可能是期货涨出来的，
两者的价格风险敞口完全不同。**只报基差变化等于没回答用户的问题。**

**正确做法**：每个分组同时给三列 —— 现货收益、期货收益、基差变化，并给出期货贡献占比。

### 3. 把日度重叠样本当独立样本算 p 值

1 个 20 日窗口的记录，相邻 20 天共享 19/20 的路径。直接算 t 检验，p 值会小一个数量级。

**正确做法**：循环块自助（块长 = h），并额外用"每 h 天取一个"的非重叠子样本复核。

## 标准流程

```
0. 口径会诊   → 基差符号、现货口径、期货映射，写进报告第 1 节
1. 抓数据     → scripts/fetch_data.py（或用户自带 CSV/Excel）
2. 算引擎     → scripts/basis_core.py   → research_data.json + basis_daily.csv
3. 压缩报告数据 → scripts/report_data.py → report_data.json
4. 出 HTML    → scripts/build_html.py   → 报告.html（单文件、内联数据、无 CDN）
5. 出 Excel   → scripts/build_xlsx.py   → 数据表.xlsx（13 表、含真公式）
6. 自检       → tests/test_statistics.py（47 项断言，必须全过）
```

一键：`python scripts/run_all.py --case examples/methanol-east-china`

## 使用步骤（详细）

### 第 0 步 口径会诊（不可跳过）

在写任何代码前，先把下面四件事钉死，写在报告的「口径」一节：

| 项目 | 必须明确 | 常见坑 |
|---|---|---|
| 基差符号 | `基差 = 现货 − 期货`（正=现货升水） | 中途翻符号，结论直接反 |
| 现货口径 | 地区、品级、含税、交割地/出厂、日频来源 | 用全国基准价冒充华东实盘 |
| 期货合约 | 主力连续怎么定义、换月规则 | 用指数合约却自称可交割 |
| 收益口径 | 信息检验 [t,t+h] vs 可操作 [t−h,t] | 混用后声称"可交易" |

**口径降级必须写出来。** 如果拿不到目标口径（例如华东实盘），
就明确写"本报告实际用 X 口径代替，影响是什么"，**不要把降级口径伪装成目标口径**。
参考 `references/01_口径定义与合约规则.md`。

### 第 1 步 数据

两种入口：

**A. 用内置抓取器**（以甲醇为例，已验证可用）
```bash
python scripts/fetch_data.py --raw raw --start 2019-01 --end 2027-12
```
产出：`raw/spot_*.csv`（每行带原文链接）、`raw/MA_MA*.json`（逐合约日线）、`raw/verify_*.csv`。

**B. 用户自带数据**：放到 `raw/` 下，按 `references/05_数据源与字段规范.md` 的字段名整理。
核心字段：`date, spot, fut, oi, contract`。

**缺数据就标缺口，绝不插值、绝不填 0、绝不用相邻月份平移。**
参考 `references/05_数据源与字段规范.md`。

### 第 2 步 计算引擎

```bash
python scripts/basis_core.py --raw raw --out out [--spec spec.json]
```

`spec.json` 可覆盖：

```json
{
  "main_window": 250,
  "windows": [250, 500, 750],
  "horizons": [5, 10, 20, 60, 120],
  "thresholds": [0.1, 0.2, 0.3, 0.4],
  "bands": [[0.2, 0.8], [0.3, 0.7], [0.1, 0.9]],
  "basis_mode": "ratio",
  "n_boot": 8000
}
```

引擎产出 `out/research_data.json`，包含 12 个模块的统计：
`bucket_info`（信息口径分组）、`bucket_deploy`（可操作口径）、`diff`（低−高+自助）、
`sensitivity`（阈值×窗口×观察期）、`stability`（年/月/结构）、`overlap`（重叠）、
`roll`（换月）、`delivery`（交割临近）、`verify`（口径核验）、`alt_rules`（映射对照）。

### 第 3–5 步 出报告

```bash
python scripts/report_data.py --data out/research_data.json --raw raw --out out/report_data.json
python scripts/build_html.py  --data out/report_data.json --template templates/report_template.html --out out/报告.html
python scripts/build_xlsx.py  --data out/report_data.json --out out/数据表.xlsx
```

HTML 报告必须包含这 11 节（模板已实现，只需换数据）：

0. 一页结论（由数据生成，不是手写）
1. 口径与合约规则
2. 数据可得性与缺口
3. 无未来函数的三道闸门
4. 历史基差与滚动分位
5. **可调参数交互面板**（口径/窗口/阈值/观察期/收益口径，改动即重算）
6. 阈值×窗口×观察期敏感性
7. 稳定性（年度/月份/市场结构/分组×年度）
8. 偏差清单（换月/交割/口径/重叠，每条给实测数字）
9. 不同合约映射对照 + 合约日历核验
10. 公式与复核口径 + 免责声明

交互面板要能让用户点着看：分组后续表现表、箱线图、差值图、单样本明细（可导出 CSV）、
以及"分位是怎么算出来的"（`references/02_滚动分位与无未来函数.md`）。

### 第 6 步 自检（必须过）

```bash
python tests/test_statistics.py --out out --xlsx out/数据表.xlsx --html out/报告.html
```

47 项断言分 13 组，其中关键几条：

- `T04a 未来数据不影响历史分位` —— 篡改未来值后历史分位必须一字不变
- `T05a 基差收益=现货收益−期货收益` —— 恒等式
- `T07a 分组统计可独立复算` —— 用原始数据独立算一遍，与引擎输出比对
- `T08a 同分布假阳性率合理` —— 同分布重复 25 次，显著率不得超 20%
- `T09a 块长≥样本半数判退化` —— 退化时宁可空着 p 值，也不硬给数
- `T11a/T11b 末端回填标记正确`

**全过才交付。** 有失败先修实现，不要改断言迁就结果。

## 交付前的强制检查清单

- [ ] 基差符号全篇一致，且在报告第一屏可见
- [ ] 现货口径的真实来源写清楚；降级了就明说降级到什么程度
- [ ] 滚动分位严格滞后，报告里能看到计算过程
- [ ] 末端回填点在稳定性检验中被剔除
- [ ] 每个分组都同时给 现货收益 / 期货收益 / 基差变化
- [ ] 所有 p 值都注明用的是块自助（及块长）
- [ ] 样本量在每张表里可见（n=…），不藏
- [ ] 退化情形写明"不给 p"，不编数字
- [ ] 换月、交割临近、样本重叠各有实测数字，不是"已注意"
- [ ] 报告含免责声明：历史统计、非预测、不含交易建议
- [ ] `tests/test_statistics.py` 47/47 通过
- [ ] HTML 无外链（无 CDN/字体/图表库），双击可离线打开
- [ ] Excel 打开无修复提示，公式列能算出数

## 完整案例

`examples/methanol-east-china/` —— 华东（降级：全国基准价）甲醇 × 郑商所 MA，2022-08-17 ~ 2026-10-20，
1004 个对齐交易日，含 `raw/`（原始抓取）、`out/`（报告、Excel、JSON）、`CASE.md`（完整解读）。

**这个案例最值得学的一点**：基差低−高差值在 4 周达到 +6.47%（p<0.0001），
但拆开看，现货端贡献 +7.72%（p=0.0001），期货端只有 +1.25%（p=0.44）。
**如果只报"基差有信息"，就会误导成"可以做基差回归"——
实际上信号几乎全部来自现货端的口径与粘性，期货端几乎没有反应。**
这正是本 Skill 坚持必须分拆现货/期货的原因。

## 边界与不做的事

- **不判断"这个策略能不能赚钱"**：不扣交易成本、保证金、滑点、流动性。
- **不做跨品种推广**：每个品种要重跑，结论不能借用。
- **不用超过 3 年的样本下强结论**：报告的稳定性一节会自己说功效有限。
- **不覆盖付费数据**：拿不到华东实盘就明说，不臆造。
- **不调整免责声明**：这是历史统计报告，不是投资建议。
