# 07 · 报告与工作簿规格

## 1. 交互式 HTML 报告（单文件、无外链）

### 1.1 硬性技术要求

| 要求 | 说明 |
|---|---|
| 单文件 | CSS 与 JS 全部内联，**不得引用任何 CDN** |
| 数据内嵌 | `const D = {...}` 一次性写入，页面不发请求 |
| 双击可看 | 断网可用 |
| 无第三方库 | 图表用原生 SVG/Canvas 绘制 |

### 1.2 交互控件（用户必须能切换）

```
[开工率指标]  总开工率 / 电石法 / 乙烯法
[未来窗口]    1 周 / 2 周 / 4 周
[工艺路线]    全部 / 电石法 / 乙烯法
[分组规则]    绝对水平 / 周度变化 / 历史分位
```

### 1.3 必须有的七个板块

| 板块 | 内容 |
|---|---|
| ① 数据口径 | 定义、样本企业数、产能基数、样本调整事件、原文链接 |
| ② 时点管理 | 统计周期 / 发稿时间 / 基期三列对照表 |
| ③ 总览 | 开工率与价格的时间序列叠加（双轴） |
| ④ 三族分组结果 | 每组 n、均值、中位数、四分位 |
| ⑤ 未来收益分布 | 分组箱线图或点图 |
| ⑥ 年度稳定性 | 逐年方向与幅度 |
| ⑦ 结论与失效区间 | 明确写出"数据不足/不稳定/无关系"的区间 |

### 1.4 点击观测点显示原始数据

每个数据点绑定该期原始行：

```js
point.onclick = () => showPanel({
  统计周期: row.window, 发稿时间: row.pub_ts, 基期: row.base_date,
  开工率: row.util_total, 周变化: row.chg_pp,
  未来1周: row.fwd_ret_1w, 未来2周: row.fwd_ret_2w, 未来4周: row.fwd_ret_4w,
  原文: row.url
});
```

### 1.5 报告自检（发布前必须跑）

```bash
node scripts/check_report.js output/报告.html
```

必须全部通过：

- `payload OK` —— 内嵌 JSON 可解析
- `malformed number tokens: 0` —— 没有 `-0.0111-1288` 这类被污染的数值文本
- `render JS: syntax OK` —— 渲染脚本无语法错误
- `series` / `groups` 行数符合预期

## 2. Excel 工作簿（14 张表）

| 表 | 内容 | 关键要求 |
|---|---|---|
| `00_使用说明与质量声明` | 口径说明、质量门清单、结论摘要 | 首屏就能读到"数据是否足够" |
| `01_开工率原始` | 逐期原始值 + 原文链接 | 保留 `sample_n`、`capacity_base_wt` |
| `02_因子构造` | 三族因子与分组标签 | 每列有公式说明 |
| `03_未来收益` | 逐期 1/2/4 周收益 | 含 `base_date` |
| `04_公式与参数` | 全部公式、阈值、常数 | 可复核 |
| `05_分组统计_绝对` | F1 分组表 | 空组保留 |
| `06_分组统计_变化` | F2 分组表 | 同上 |
| `07_分组统计_分位` | F3 分组表 | 无历史时保留表头+说明 |
| `08_显著性` | IC、p、HAC p、BH q、安慰剂 p | 五项齐全 |
| `09_年度与阶段` | 年度/阶段切片 | 含"样本不足"标注 |
| `10_安慰剂与同向性` | 安慰剂分布、同向性 | — |
| `11_月度交叉验证` | 月度数据旁证 | 无数据时写明 |
| `12_期货连续合约` | 日线 + 换月标记 | 含 `roll_flag` |
| `13_期货月线` | 月度 K 线数据 | — |

### 2.1 工作簿里的数字格式

**所有浮点数写入必须经过 `float_numbers.py`**，因为本运行时的 `repr`/`str` 会把
部分数值的尾数渲染成错误字符。写 CSV 用 `dataframe_to_csv`，写 JSON 用 `dumps`。

### 2.2 公式表必须能复算

`04_公式与参数` 表中每条公式都要写成：

```
名称 | 公式 | 参数取值 | 说明
分位 | expanding_pct_rank(u, min_periods) | min_periods=52 | 只用已公布样本
未来收益 | adj_close[base+h]/adj_close[base]-1 | h=5/10/20 | base 严格晚于 pub_ts
MDES | (1.96+0.84)/sqrt(n_eff) | — | 80% 功效
```

## 3. 报告叙事（narrative.json）的必备字段

```json
{
  "title": "...",
  "lede": "一句话结论",
  "chips": ["数据期数", "覆盖区间", "样本企业数"],
  "data_gap_note": "缺失与不可得的说明",
  "quality_gates": [{"item": "...", "pass": true}],
  "verdict_note": "统计结论的完整表述",
  "findings_ok": ["能成立的说法"],
  "findings_ng": ["不能成立的说法"],
  "failure_periods": ["明确失效的区间"],
  "limits": ["研究边界"],
  "declarations": ["合规声明"],
  "one_line": "最终一句话"
}
```

> `findings_ng` 与 `findings_ok` 必须**等权重呈现**。只写正面发现的报告不合格。

## 4. 视觉与可读性要求

- 配色：中性灰底 + 单一强调色，避免用红绿暗示"买卖"
- 所有图表标注**样本数**
- 空数据区域显示「无可用数据」而非空白
- 长表格固定表头
- 数值统一保留 2 位小数（百分比）或 4 位（收益率/IC）

```
数据工作簿.xlsx        # 或 <品种>开工率因子研究_数据工作簿.xlsx
res_*.csv / summary.json
raw/util_gaps.json
```
