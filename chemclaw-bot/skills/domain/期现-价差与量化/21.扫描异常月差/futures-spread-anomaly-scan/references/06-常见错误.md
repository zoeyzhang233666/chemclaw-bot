# 06 常见错误

这个技能在打磨过程中真实踩过的坑。每条都写明**错误做法**、**后果**、**正确做法**。

---

## 错误 1：用"±N 周窗口"构造可比样本

**错误**：在当前剩余期限附近取前后各 2 周的日度观测，每年得到约 20 个样本。

**后果**：这 20 个日度点高度自相关（相邻交易日价差变化只有几元）。
样本量从 5 虚增到 57，标准差被严重低估，导致：

- Z 分数虚高（出现过 Z = 8.37）
- 分位被压缩到中间，真正的极端值显示成 80 分位

**正确**：**每个历史年份只取 1 个样本**。N = 独立年度数。宁可 N=5，不要虚假的 N=57。

修正后 SA 1–5 组合的样本是：2022: +165 / 2023: +282 / 2024: +82 / 2025: −107 / 2026: −85。

---

## 错误 2：把不同月份组合合并成一个分布

**错误**：把 SA 1–5、SA 5–9、SA 1–9 的样本混在一起算分位。

**后果**：比的是完全不同的交割季节性。SA 1–5 有春节前后的刚性特征，SA 5–9 是夏季检修季，
两者分布形态不同，混在一起做的分位没有经济含义，看起来"正常"其实是把两堆数据搅匀了。

**正确**：**每个 (近月, 远月) 组合一个独立分布**。这也是用户明确要求的口径。

---

## 错误 3：用主力连续合约算月差

**错误**：取主连合约的价格，或直接对两个"近月/远月主连"相减。

**后果**：主连在换月日有拼接跳空，这个跳空是合约拼接的产物，不是市场变化。
用它算出的"月差变化"里混入了换月噪音，整条历史序列被污染。

**正确**：逐合约取价，只在同一天、同一对合约都有有效报价时才产生观测点。

---

## 错误 4：用端点相减判定 contango / backwardation

**错误**：`末月价 − 首月价 > 0` 就判 contango。

**后果**：只要曲线中段有个别月份跳变，就会误判。
实测把纯碱 SA 判成了 contango —— 而 SA 实际是逐月递增的 backwardation（斜率 +14.35 元/月，r = 0.984）。

**正确**：对整条曲线做 OLS 回归，`SLOPE(价格, 距交割月数)`：
`< −3` 判 contango，`> +3` 判 backwardation，并附单调性相关系数 r。

---

## 错误 5：组合枚举时两侧用同一个 range

**错误**：
```python
for i in range(n): for j in range(n): ...
```

**后果**：产出大量倒序对（近月晚于远月），打印出来像"近月2850 − 远月2800"，
但两个合约的先后关系是反的，月差符号全错。

**正确**：`for j in range(i+1, n)`，并让 `check_pair` 兜底返回 `ORDER_REVERSED`。

---

## 错误 6：样本不足还硬算分位

**错误**：N=1 或 N=2 时照样算 percentile 和 Z。

**后果**：N=1 时"分位"只能是 50%，N=2 时只能是 25/75，这些数字看起来精确，
实际毫无信息量，会误导决策。

**正确**：N < `min_n`（默认 3）→ 只报当前月差 + "样本不足"，分位/Z/评级全部留空。
**不要为了让 N 变大而放宽剩余期限窗口**（见错误 1）。

---

## 错误 7：不同机构的库存口径互相算环比

**错误**：拿隆众上期数据减卓创本期数据算"去库 X 万吨"。

**后果**：口径差异被当成了库存变化。甲醇港口库存同时有隆众 30.51、卓创 37.41、金联创 30.44，
三者统计范围和时点不同，互相相减没有意义。

**正确**：同一环比只能用**同一机构、同一口径**的两期数据。多口径并存时全部保留并标注。
口径不明时可信度降为 C。

---

## 错误 8：把异常月差直接写成交易建议

**错误**："PP 1–5 月差分位 100%，建议做空近月做多远月。"

**后果**：这违反本技能的核心红线。分位 100% 只说明**当前结构比历史少见**，
不说明它一定会回归。可能的原因包括：真实的交割资源紧张、新增产能即将投放、
或市场已充分定价。任何一项都会让"回归"不成立。

**正确**：只描述位置 + 给出研究线索（该查哪些库存、仓单、装置、产能）。
成本项（仓储费、资金成本、交割费、品质升贴水、地区升贴水）都还没扣。

---

## 错误 9：跨品种直接比月差的绝对元数

**错误**："PP 月差 531 元，比 MA 的 161 元更极端。"

**后果**：PP 1 手 5 吨、MA 1 手 10 吨，价格水平也不同（PP 约 9,000，MA 约 3,000），
绝对元数不可横比。

**正确**：**跨品种比的是分位**（各自历史分布中的位置），不是元数。
看板榜单排序用的就是极端度（基于分位），不是价差数值。

---

## 错误 10：静默降级数据源

**错误**：交易所官网抓不到，就悄悄换成别的网站，但不标注。

**后果**：口径变了（结算价 → 最新价），使用者不知道，可能把两种口径的数据相加。

**正确**：降级必须**显式记录** `price_basis` 与 `source`，并在 HTML/Excel 上标注。
本项目的 PP 就是这种情况：大商所官网返回 HTTP 412，改用东方财富最新价，全程标注。

---

## 错误 11：对未解释的异常编故事

**错误**：PTA 仓单 10-08 约 1,002 张 → 10-09 约 36,187 张，于是写"大幅累库，供应过剩"。

**后果**：抓取到的页面**都没有解释原因**，可能是数据修订、可能是集中注册、
也可能含了有效预报。直接下"累库"结论是编故事。

**正确**：只记事实，标 C（口径不明），并提示"需进一步核实"。

---

## 错误 12：用 f-string 生成含 CSS/JS 的 HTML

**错误**：把整段 CSS 和 JavaScript 套进 Python f-string，导致 `{` `}` 必须写成 `{{` `}}`。

**后果**：漏改一处，CSS 的 `:root{` 变成 `:root{{`，**整个样式表失效**；
或者 JS 里残留 `${{...}}` 直接语法报错。而且这类错误不会在生成时暴露，只在浏览器里白屏。

**正确**：CSS 与 JS 放在**普通字符串**里（`r"""..."""`），只在真正需要插值的地方用拼接。
生成后必须**实际执行一次** JS 逻辑验证，而不是只看语法：

```bash
node scripts/check_html.js build/dashboard.html
```

---

## 错误 13：只在生成 PDF/图片上"看一眼"

**错误**：生成完 HTML 就当好了，或者只截个图看看。

**后果**：截图能看出排版，看不出"切换品种后图表不更新""筛选后表格空了"这类逻辑错误。

**正确**：用 DOM 桩**真实执行**页面脚本，断言关键区域都渲染出预期内容。
本技能的 `check_html.js` 做了 10 项断言（KPI、榜单、明细、图表说明、产业面、事件、规则、说明）。

---

## 错误 14：交易所三位数月份代码解析成年份错误

**错误**：郑商所日报里 `MA610` 这种三位数代码，直接按两位年份解析 → 得到 2006 年。

**后果**：合约年份错位，月差配对全乱，甚至出现"2006 年的合约"这种明显错误的记录。

**正确**：三位数代码第一位是年份尾数，需要结合当前十年推断：
```python
y = 2000 + int(mo[0]) + (int(date[:4]) // 10) * 10
```
两位数代码 `MA2701` 则直接 `2000 + int(mo[:2])`。
