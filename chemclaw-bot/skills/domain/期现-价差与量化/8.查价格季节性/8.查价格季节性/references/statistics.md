# 统计方法

所有派生数字都由 `scripts/seasonality_core.py` 计算。**不要手算，也不要在报告里手写数字** ——
手写必与序列不一致，且无法被复核。

---

## 1. 经验分位（唯一允许的分位算法）

```
pctile(v, q):
    v 升序排列
    h = (n - 1) * q
    lo = floor(h); hi = ceil(h)
    return v[lo] + (h - lo) * (v[hi] - v[lo])
```

这个线性插值定义**三方等价**，已在 `selftest.py` 里逐项验证：

| 实现 | 写法 |
|---|---|
| numpy | `np.percentile(a, q)`（默认 `method='linear'`） |
| Excel | `PERCENTILE.INC(a, q)` |
| R | `quantile(a, q, type=7)` |

**输出 p10 / p25 / p50 / p75 / p90**，外加 `IQR = p75-p25`、`spread = p90-p10`、`CV = std/mean`。
`p50` 与 `median` 数值相同，两个都留是为了让 Excel 里 `MEDIAN()` 与 `PERCENTILE.INC(...,0.5)`
可以互相校验。

**边界保护**：经验分位在极端离群下可能因采样误差略微越出 `[min, max]`，
引擎会把分位夹进观测区间 —— 分位数不可能超出样本范围。

## 2. 小样本：这是本 skill 最重要的诚实点

真实情况往往是：某个同期位置只有 **3–5 年**样本。此时：

- p10 与 p90 之间是**插值出来的**，不是"历史上有 10% 的年份低于此"。
- `z` 值（标准化距离）在 n<10 时几乎没有统计意义，只能当"离得远不远"的粗略尺子。
- 用 4 个样本算出的 p90，换个样本就可能是 p60。

**因此强制要求**：
1. 每个统计行必须带 `n`（样本年数）；
2. `n < min_years`（默认 3）→ 标 `样本不足`，不用于形态判断；
3. 报告里对"100% 分位 / z>6"这类读数，必须同时给出 n，并写明"弱样本强读数"；
4. **不要**给出基于这些样本的置信区间 —— 样本量撑不起。

## 3. 均值 vs 中位数：必须并列，且给出差额

- **均值**会被单一年份拉走。某一年因为一次事件飙到 4,700，均值可能整体上移 20%。
- **中位数**抗异常，但在样本少时"跳档"（4 个样本的中位数是中间两数平均，异常一点点就跳）。

所以三列一起给：`均值`、`中位数`、`均值−中位数`。
经验判据：`|均值−中位| > 0.15 × 中位数` → 该位置分布明显右/左偏，
**均值不可单独使用**，报告里要用醒目色标出。

**杠杆量化**（Excel「05/06」里叫"剔除最高年后均值变化"）：
```
mean_ex_hi = 去掉该位置最高值那一年后的均值
leverage_hi = (mean_ex_hi - mean) / mean
```
一个位置如果剔除一年均值就移动 >15%，说明这个"历史同期均值"其实是一年的故事。

## 4. 季节性强度 R²（形态到底有多强）

不要只看图觉得"好像有季节性"，要量化：

```
grand_mean = 所有 (位置, 年份) 观测的均值
within_SS  = Σ_位置 Σ_年 (v - 该位置均值)²      # 同一位置内部的跨年波动
total_SS   = Σ_位置 Σ_年 (v - grand_mean)²
seasonal_SS_share = 1 - within_SS / total_SS
```

含义：**"知道是第几周/几月"能解释价格差异的百分之多少**。

| R² | 解读 |
|---|---|
| ≥ 50% | 季节形态主导，同位置跨年比较有意义 |
| 25%–50% | 季节性与年份波动并重 |
| < 25% | **季节性弱，年份间价格水平漂移主导** —— 季节性只能当形态参考 |

> ⚠ 实现坑：曾经写成 `seasonal_ss = Σ w·(mean_p - grand)²` 再除以一个凑出来的分母，
> 结果恒等于 1.0，看起来"季节性极强"。必须用 `total_SS - within_SS` 的关系算，
> 且分子分母都基于**同一批观测**。甲醇现货实测 R² ≈ 13%（周度）/ 12%（月度）——
> 这告诉我们：甲醇价格主要由年份水平决定，季节形态很弱。**这个如实结论比一张好看的图重要。**

## 5. 当前年位置（剔除当前年本身）

计算"今年这一刻在历史同期排第几"时，历史样本**必须剔除当前年**：

```
hist_values = 该位置、除当前年以外所有年份的值
hist_mean / hist_median / p10..p90 = 基于 hist_values
pctile_of_current = #{v in hist_values : v < current} / n_hist   （并列计 0.5）
rank = #{v : v < current} + 1 ，共 n_hist 个
z = (current - hist_mean) / std(hist_values)
```

**为什么剔除**：如果不剔除，今年这个值既在被评估、又在定义基准 ——
今年暴涨时会把 p90 抬上去，让"今年处于极端"看起来没那么极端。这是自证式的错误。

> 注意：Excel「05/06 统计表」的 `样本年份` 列**是含当前年的**（那是完整分布展示），
> 而「08 当前年位置」**不含当前年**。两处口径不同且**都有明确标注**。
> 这不是 bug，是两种用途；但必须在页面上讲清楚，否则读者会以为算错。

## 6. 数据审计（每次都做）

- **重复日期**：视为一条（保留先出现者），计数并记录。
- **空值**：直接跳过，不写 0。
- **工作日缺报**：列出日期，扣除 `cn_market_holidays.txt` 里的停市日。
- **跳变**：`|Δ| > 8%` 的相邻日报价，逐条回原文核实是源数据跳变还是解析错误。

## 7. 复算校验（交付前必做）

1. **引擎内部**：`selftest.py` 8 组不变式。
2. **独立重算**：用**不共享引擎代码**的脚本重算一遍周度均值/中位数/样本数，
   逐个位置比对（本案例 52/52 完全一致）。
3. **Excel 重算**：LibreOffice `recalculate` 后，用 openpyxl `data_only=True` 读取公式结果，
   与引擎 JSON **逐位置逐列比对**（52+12 个位置全部一致）。
