# 期货研究规则回测（futures-rule-backtest）

## 这个技能解决什么问题

用户给出一句"有明确触发条件 + 持有期"的研究规则，例如：

> 甲醇港口库存连续两周下降，且甲醇基差高于过去3年滚动80%分位时，
> 在信号可获得后的下一交易日建立甲醇期货多头，持有10个交易日。

要回答的**不是**"这策略能赚多少"，而是四个可被复核的问题：

1. 这句话到底被翻译成了什么可执行规则？（信号/入场/出场/持仓/合约/成本）
2. 每个输入在**哪一刻**才真的可得？有没有用到未来数据？
3. 在真实挂牌合约、真实换月、真实成本下，历史上到底发生了什么（含亏损）？
4. 这个结论有多脆弱？（参数敏感性、样本外、少数时期主导、数据缺口）

## 铁律（违反任何一条，产出即不可用）

| # | 铁律 | 原因 |
|---|---|---|
| 1 | **禁止自动搜索最赚钱参数并把它当结论** | 那就是过拟合。敏感性网格必须在运行前声明，全表报告，含亏损格。 |
| 2 | **禁止把回测结果表述为未来收益保证** | 历史≠未来。报告里必须有明确边界声明。 |
| 3 | **禁止用后复权连续合约充当可交易价格** | 连续价会抹掉换月价差，虚增收益。必须映射真实挂牌合约并显式换月。 |
| 4 | **禁止使用 as-of 日期当作可得时点** | 指标常在 as-of 日 13:00–18:00 发布，收盘后才知道。可得时点必须是原始发布时刻。 |
| 5 | **数据不可得就展示缺口，不得编造** | 缺失的发布时刻、缺失的合约、缺失的价格，一律标注为缺口或"假设"，并说明影响。 |
| 6 | **模拟数据必须显著标记** | 用合成数据测引擎时，报告标题与页面配色必须写明"模拟数据，非真实策略收益"。 |
| 7 | **不实盘、不给买卖建议** | 本技能只做研究复现，不输出可执行交易指令。 |

## 执行流程

### 第 0 步：先出规则与数据需求，等用户确认（不要直接跑）

产出两份东西给用户看，然后**停下来等确认**：

- **结构化规则表**：把自然语言拆成 信号条件 / 价格条件 / 可得时点 / 入场 / 出场 / 持仓上限 / 成本 / 合约映射 / 换月，每条都写成无歧义的机器可读描述。特别要显式回答自然语言里含糊的地方，例如"连续两周下降"是"两次环比为负"还是"较两周前低"。
- **数据需求清单**：每个字段 → 来源 → 频率 → 可得时点 → 是否已取得 → 缺失部分如何处理。

这一步的模板见 `references/01_rule_specification.md`。**歧义要在这一步问清楚，而不是在结果里解释。**

### 第 1 步：核实数据时点（最容易出错的一步）

对每个输入逐项确认"最早何时可知"：

- 周度库存/开工/产量类数据：找**原始发布页面的发布时间戳**，不要用 as-of 日期，也不要用数据商页面上的"更新时间"（那可能是多年后回填的）。
- 日度现货价格：默认按当日收盘后才可得（`next_session`），除非能证明有盘中报价。
- 期货结算价/收盘价：当日收盘后可得。

核实方法、常见陷阱与判定清单见 `references/02_lookahead_and_timing.md`。
无法核实的历史区段，必须在配置里切成 `strict` / `backfill_assumed` 两种模式并**两种都跑**，主结论只认 `strict`。

### 第 2 步：写规则规格文件（唯一事实源）

所有参数写进一个 JSON/YAML 规格文件，包含 `provenance` 块，逐项标注依据类型：

```json
"provenance": {
  "contract_spec":  {"basis": "assumed_czce_standard", "note": "..."},
  "margin_rate":    {"basis": "assumed", "value": 0.10, "note": "..."},
  "fee_per_lot":    {"basis": "assumed", "value": 2.0, "note": "..."},
  "slippage_ticks": {"basis": "assumed", "value": 0.5, "note": "..."},
  "indicator_publication": {"basis": "partially_verified", "note": "..."}
}
```

校验：`python scripts/run_backtest.py validate --config <spec>.json`
字段全表见 `references/03_config_reference.md`；完整示例见 `examples/methanol-inventory-basis/`。

### 第 3 步：跑回测 + 敏感性 + 样本外

```bash
python scripts/run_backtest.py analyze --config configs/x.json --out out/
python scripts/build_reports.py --config configs/x.json --out out/
```

产物：`out/research_platform.html`、`out/backtest_workbook.xlsx`，以及全部中间 CSV/JSON。

### 第 4 步：写结论（按证据强度分级）

结论只能用下面四种措辞之一，且必须给出支撑数字：

| 等级 | 措辞 | 成立条件 |
|---|---|---|
| A 稳健 | "在该样本内，规则在多数相邻参数下同向，样本外未失效" | 网格中 >60% 变体同向 **且** 样本外同向 **且** 无单一年份贡献 >60% |
| B 弱证据 | "方向一致但样本不足，不足以支持结论" | 笔数 <30，或自助检验 P(均值>0) <0.8 |
| C 不成立 | "在该样本内未表现出稳定优势" | 网格多数变体反向，或样本外反向 |
| D 数据不足 | "数据缺口导致无法判断" | 可核验发布时刻覆盖不足，strict 模式下笔数 <10 |

**默认落点是 B 或 D，不是 A。** 周频指标 + 10 日持有 + 数年样本，天然只有十几到几十笔交易。

## 常见失败模式

- **把 as-of 日当发布日** → 信号提前一天甚至一周，收益虚高。
- **用回填数据的时间戳** → 出现"2024-07 才发布、却用于 2022 年信号"的时间倒流。
- **用连续合约** → 换月价差被平滑掉，10 日持有期的收益被系统性高估。
- **只报最好的参数** → 网格里 20 个变体挑 1 个，等于 p 值造假。
- **样本外当验证集反复调参** → 样本外就变成样本内了。
- **手数放大掩盖一切** → 1 手/20 万 与 100 手/20 万 的回撤完全不同，必须固定资金口径。
- **忽略涨跌停** → 信号次日涨停时，回测里"开盘买入"根本成交不了。

## 明确不做

- 不搜索引擎最优参数组合。
- 不生成对外发布的交易信号或评级。
- 不接实盘、不下单。
- 不承诺、不暗示任何未来收益。
