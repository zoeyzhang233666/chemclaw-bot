# 04 · 真实合约、换月与成本建模

## 为什么不能用后复权连续合约

后复权连续价是把不同合约的价格**拼接**成一条连续曲线，并把换月价差吸收进历史价格。它适合做长周期趋势图，但**不能用来回测**，因为：

1. **换月价差被抹掉了。** 你实际上必须"卖出旧合约、买入新合约"，这个价差是真实成本/收益。连续价假装它不存在。
2. **价格水平失真。** 后复权价格可能变成负数或远高于真实价格，导致"基差""分位"这类依赖价格水平的信号全部失真。
3. **不可交易。** 连续价不是任何一个能下单的合约。

正确做法：**每个交易日映射到一个真实挂牌合约**，换月显式处理。

## 合约映射规则

引擎（`frbt/contracts.py`）对每个交易日 d：

1. 取**前一交易日**的合约快照（避免用当日未来已知的持仓量）。
2. 过滤掉已进入禁交易窗口（交割月前 N 自然日）的合约。
3. 按持仓量降序（同持仓量按成交量），取第 k 名。
4. 只接受当日有报价的合约；否则回退到当日重新选。
5. 若目标合约与当前持仓合约不同 → 标记 `roll_flag`。

导出字段：`trade_contract`, `roll_flag`, `roll_from`, `next_contract`。

## 换月的两种处理

| 模式 | 行为 | 何时用 |
|---|---|---|
| `exit_on_roll_when_contract_changes: true` | 换月日直接平仓离场，不等持有期到期 | 研究"持有 N 个交易日"的纯价格效应；换月后已是不同标的 |
| `false` | 换月日平旧开新，持仓继续计时 | 研究"持续暴露于该品种"的策略 |

两种都会产生**两笔**手续费 + 两笔滑点，并体现在 `rolls.csv` 与 `trades.entry_fee` 中。

**关键**：换月价差本身（`spread_cost`）必须计入。旧合约平仓价与新合约开仓价之差乘以手数，就是真实的换月成本。

## 成本建模

每边（开仓、平仓、换月各算一次）：

```
手续费 = max(commission_min_per_lot, fee_per_lot) × 手数
滑点   = slippage_ticks × tick_size × multiplier × 手数
```

成交价：

```
买入价 = 报价 + slippage_ticks × tick_size / 2
卖出价 = 报价 − slippage_ticks × tick_size / 2
```

即 `slippage_ticks` 表示**买卖价差的总宽度**，单边承担一半。

### 成本敏感性的意义

| 费率倍数 | 滑点（跳） | 用途 |
|---|---|---|
| 1× | 0.5 | 基准乐观假设 |
| 1× | 1.0 | 保守（实盘常见） |
| 2× | 2.0 | 压力测试 |
| 3× | 4.0 | 极端 |

若结论在 2× 成本下就翻负，说明**它不是一个可交易的规则**，而只是成本估计的产物。

## 保证金与资金口径

三种 sizing：

| sizing | 手数计算 | 适用 |
|---|---|---|
| `fixed_lots` | 固定手数 | 想看清每笔单位收益（本例） |
| `pct_equity_notional` | `目标比例 × 权益 / (价格 × 乘数)` | 固定名义敞口 |
| `pct_equity_margin` | `目标比例 × 权益 / (价格 × 乘数 × 保证金率)` | 固定保证金占用 |

引擎还会用 `max_margin_utilisation` 与可用现金二次约束手数，防止过度杠杆。

**报告里必须写明口径。** 1 手 / 20 万 与 20 手 / 20 万 的收益率、回撤、Sharpe 完全不同。

## 未建模的部分（必须披露）

- **涨跌停无法成交**：信号次日开盘涨停时，回测里"开盘买入"实际不成立。
- **盘中强平**：保证金不足被强平，未模拟。
- **流动性冲击**：大单在远月合约上可能只能分批成交。
- **交割与仓单**：未考虑实物交割、仓单注销。
- **期权/期货组合**：不在本技能范围。

这些不建模不是疏忽，而是"过度建模会带来虚假精确感"。正确做法是**在风险页逐条列出**。
