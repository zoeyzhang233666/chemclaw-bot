# 01 · 把自然语言规则转成可回测规格

## 为什么要先出规格、再跑回测

一句"库存连降两周且基差偏高时买入持有 10 天"，至少有 **14 个**需要钉死的自由度：

1. 库存数据的口径（港口/厂库/社会库存）、单位（万吨/吨）、地区
2. "连续两周"= 两次环比为负？还是较两周前更低？允许中间有一次持平吗？
3. 基差的定义：现货 − 期货 还是 期货 − 现货？用哪个合约？用结算价还是收盘价？
4. 现货价格的地区、含税/不含税、品级、运费口径
5. "过去3年"= 756 个交易日还是 156 个自然周？滚动窗口含不含当日？
6. "80%分位"的相对比较基准是同一序列的历史分布吗？
7. 两个条件必须同时成立，是否允许"库存条件成立后 3 天内基差条件成立"？
8. 信号在哪一刻可得？发布时点是什么？
9. "下一交易日"是 T+1 开盘还是 T+1 收盘？
10. 持有"10 个交易日"是从建仓日算起还是从信号日算起？
11. 持有期内出现新信号怎么办？加仓、忽略、还是重置持仓计时？
12. 用哪个合约？主力/N 月/近月？换月规则？
13. 成本假设：手续费、滑点、保证金率
14. 资金口径：固定手数还是固定资金比例？

这些没钉死，回测跑出来的数字就不可复核——同一条规则两个人跑出两个结果。所以**先确认规格**。

## 规格填写模板

| 项目 | 必须回答的问题 | 本次示例的答案 |
|---|---|---|
| 标的 | 交易所 + 品种代码 | 郑商所 MA（甲醇） |
| 方向 | 只做多 / 只做空 / 双向 | 只做多 |
| 指标 | 数据源、口径、单位、频率 | Mysteel 港口库存，万吨，周度 |
| 指标条件 1 | 具体判定式 | 近两次周度变化均 < 0 |
| 指标条件 2 | 具体判定式（可选） | 当前值等于近 2 期通道下沿 |
| 组合方式 | and / or | and |
| 价格条件 | 基差定义 + 分位窗口 + 阈值 | 现货 − 主力结算价，756 日滚动，≥80% 分位 |
| 可得时点 | 原始发布时刻 + 允许的交易时点 | as-of 日 13:00–14:33 发布 → 次一交易日开盘可交易 |
| 合约 | 选哪个、怎么换月、临近交割怎么办 | 前一交易日持仓量第 1 名，交割月前 10 自然日移出 |
| 入场 | 价格（开盘/收盘/结算）+ 订单类型 | 次一交易日开盘价，市价 |
| 持有 | N 个交易日，从哪天算 | 10 个交易日，从建仓日起算 |
| 出场 | 到期 / 止盈 / 止损 / 换月 | 仅到期 + 换月 |
| 重复信号 | 持仓中再来信号怎么办 | 忽略 |
| 仓位 | 固定手数 / 资金比例 / 保证金比例 | 固定 1 手，初始资金 200,000 元 |
| 成本 | 手续费、滑点、保证金率、最小变动价位、乘数 | 2 元/手/边、0.5 跳、10%、1 元/吨、10 吨/手 |
| 样本 | 起止日期与切分点 | 全部可得样本；切分点 2025-07-01 |

## 消歧时的三条原则

**原则 1：选更保守的那个解释。**
"连续两周下降"若可以理解为"两次环比为负"或"较两周前低"，选前者（更难触发）。条件更难满足时如果结论仍成立，才更有说服力。

**原则 2：把含糊处写进规格，不要写进结论。**
规格里保留 `label` 字段写清中文语义，例如"最近两次周度变化均为负（连续两周下降，严格口径）"。评审时看到的是规格，不是事后解释。

**原则 3：数值单位必须显式。**
"基差高于 80% 分位"里没有任何绝对数值；而"库存连降"里 `threshold=0.0` 的单位是**万吨**。在规格中写成 `threshold_units: "万吨"`，否则参数敏感性一格 0.25 到底是 0.25 万吨还是 25%，无法解释。

## 从自然语言到 ops 数组

引擎把指标侧条件表达为 `ops` 列表，每个 op 有自己的类型与参数：

```json
"signal": {
  "indicator": "methanol_port_inventory_wan_ton",
  "combine": "and",
  "min_history": 8,
  "ops": [
    {"type": "change_run", "weeks": 2, "direction": "down", "label": "连续两周下降"},
    {"type": "channel_change", "n": 2, "threshold": 0.0, "channel_mode": "low",
     "label": "落于近2期通道下沿"}
  ]
}
```

支持的 `type`：

| type | 语义 | 关键参数 |
|---|---|---|
| `change_run` | 连续 N 期同向变化 | `weeks`, `direction`（down/up） |
| `channel_change` | 相对近 N 期通道的回落/抬升幅度 | `n`, `threshold`, `channel_mode`（low/high） |
| `level` | 与常数比较 | `cmp`, `threshold` |
| `zscore` | 相对滚动均值/标准差的 z 值 | `threshold` |

`combine` 决定各 op 如何合并；`min_history` 是预热期（样本不足时不产生信号）。

## 价格侧条件：基差分位

基差分位不是"指标序列的分位"，它依赖两条序列（现货、期货）在特定日期的取值，因此单独放在 `price_filter` 块：

```json
"price_filter": {
  "enabled": true,
  "type": "pct_quantile",
  "side": "above",
  "threshold": 0.8,
  "lookback_points": 756,
  "basis_mapping": "spot_minus_fut",
  "warmup_min_points": 120
}
```

要点：

- `lookback_points` 是**交易日**数（756 ≈ 3 年 × 244）。若你的数据是周频，就写 156。
- 分位窗口**严格早于当日**，绝不含当日或未来（引擎 `precompute_basis` 保证）。
- 当日基差用"前一交易日现货 − 当日该合约结算价"，因为现货当日收盘后才可得。
- `warmup_min_points` 是分位可计算所需的最小历史样本数，不足时不产生信号（而不是当作 0 分位）。

## 常见歧义清单（逐条问用户）

- 库存数据的发布方是谁？同一周内换过发布方吗？
- 现货报价是哪个地区、含税吗、有没有品牌/品级差异？
- "主力合约"是按持仓量还是成交量？换月时点怎么定？
- 持有期遇到长假怎么办？（按交易日计数，跳过休市）
- 信号当天已有持仓，算不算重入？
- 用多少资金？如果按百分比，是按名义价值还是保证金占用？

确认后的规格写入配置文件，并记录 `meta.declared_before_running: true`，表示它在任何回测结果产生之前就已经固定。
