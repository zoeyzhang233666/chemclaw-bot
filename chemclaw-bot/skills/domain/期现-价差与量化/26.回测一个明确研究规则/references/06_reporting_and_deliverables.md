# 06 · 报告与交付物规范

## 交付物清单

| 文件 | 用途 | 谁看 |
|---|---|---|
| `research_platform.html` | 单文件离线交互平台 | 研究者自查、向他人演示 |
| `backtest_workbook.xlsx` | 11 表可复核工作簿 | 复核者、审计 |
| `trades.csv` / `daily_equity.csv` / `signal_alignment.csv` | 机器可读原始产出 | 二次分析 |
| `stats.json` / `sensitivity.json` / `oos.json` | 结构化结果 | 自动化比对 |
| `rule_spec.json` | 规格与指纹 | 版本管理 |

## HTML 平台必须包含的八个页面

1. **总览** — 8 个核心指标卡 + 权益曲线 + 分年度柱状图 + 分年度表
2. **权益与回撤** — 回撤曲线（负值向下）+ 可检索的逐日权益表
3. **逐笔成交** — 每笔的信号日/可交易日/合约/价格/费用/净额，可按平仓原因与盈亏筛选
4. **信号与时点对齐** — 审计表，证明没有未来函数（可筛选：触发/可核验/假设/不可用）
5. **参数敏感性** — 热力色阶全表 + 成本敏感性表
6. **样本外与稳健性** — 样本内/外对比 + 自助检验 + 逐年剔除
7. **规则与成本假设** — 自然语言到显式规则的逐条映射 + 假设溯源表
8. **风险与数据缺口** — 逐条列出边界与未建模项

### 硬性技术要求

- **单文件**：无 CDN、无外部脚本、无外部样式表。可离线打开、可邮件发送。
- **图表用内联 SVG**：Python 生成，不依赖 JS 图表库。
- **数据模式横幅常驻**：截图也不能把"假设时刻"说成"可核验"。
- **颜色语义固定**：绿 = 盈、红 = 亏，不得只靠颜色传达（同时有正负号）。

## Excel 工作簿必须包含的 11 张表

| 序号 | 表名 | 内容 | 关键要求 |
|---|---|---|---|
| 00 | README | 摘要 + 结论边界 + 重跑命令 | 结论边界必须显式 |
| 01 | Rule_Spec | 全参数扁平化 + 假设溯源 | 区分事实/假设 |
| 02 | Raw_Quotes | 真实合约原始行情 | 未做任何复权 |
| 03 | Indicator | as-of 日、发布时刻、可交易日 | 时刻来源列 |
| 04 | Signals | 逐条条件判定理由 | 保留判定细节 |
| 05 | Fills | 逐笔成交 | 手续费与滑点分列 |
| 06 | Daily_Equity | 逐日盯市 | **收益与回撤用 Excel 活公式** |
| 07 | Annual | 分年度 | |
| 08 | Sensitivity | 全网格 | 不删减 |
| 09 | Cost_Sens | 费率×滑点 | |
| 10 | OOS | 样本内外 + 稳健性 | |
| 11 | Formula_Doc | 每个字段的算法 | 与代码逐条一致 |

**为什么 06 表要用活公式**：复核者可以改一个权益数字，看到收益与回撤自动重算，从而确认公式正确、不是硬编码。

## 结论表述规范

必须遵守：

- 使用四级措辞之一（A 稳健 / B 弱证据 / C 不成立 / D 数据不足）。
- 每个结论附支撑数字（笔数、网格占比、样本外结果）。
- 明确写"历史回测不代表未来收益"。
- 数据缺口单独成段，不埋在脚注里。

禁止：

- "该策略年化收益 X%"（隐含可推广）
- "验证有效"（无样本外支撑时）
- 只报最优参数
- 把模拟/假设数据的结果混进主结论
