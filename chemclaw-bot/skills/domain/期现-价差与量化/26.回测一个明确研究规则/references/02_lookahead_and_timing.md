# 02 · 无未来函数：数据可得时点核实

回测里最贵的错误不是参数选错，而是**用了当时还不可能知道的信息**。收益虚高、胜率虚高、结论全错，而且从结果表面完全看不出来。这一页是实操清单。

## 核心定义

对每个输入，问一个问题：

> 如果我在那一天的真实世界里坐在交易台前，**几点几分**能在屏幕上看到这个数字？

答案记成 `publish_dt`。然后：

```
可交易时点 = publish_dt 之后第一个交易日
```

如果 `publish_dt` 晚于当日收盘（15:00），那么当日不能交易，只能次日。

## 分级：三种"可得时点"证据强度

| 等级 | 证据 | 处理方式 |
|---|---|---|
| **A 可核验** | 原始发布页面带有发布时间戳（"发布时间：2025-05-21 14:12"），且该页面是当次发布，不是多年后回填 | 直接使用该时间戳 |
| **B 可间接推断** | 数据商页面 URL / 元数据里编码了原始发布时刻（如 URL 含 `/26101414/` = 2026-10-14 14 时），且日期与 as-of 日一致 | 可用，但记录 `pub_source` 说明推断方式 |
| **C 不可核验** | 页面的发布/更新时间远晚于 as-of 日（回填发布、历史归档） | **不得使用该时间戳**，只能标为"假设"或排除 |

## 判定 C 级的信号

- 页面上的发布时间比 as-of 日晚了几个月甚至几年 → 数据商在后来统一回填。
- 同一批数据的发布时间集中在同几天（例如 2024-07-28 一次性发布 2022–2024 全部周度值）。
- 页面 URL 的日期段与 as-of 日不一致。
- 数据商站点是移动版/镜像站，正文时间被后台重置。

一旦判定 C 级，这个时间戳**绝对不能**用来做"信号何时可得"，否则会出现时间倒流：2024 年才发布的数据被用于 2022 年的信号。

## 双模式设计（推荐做法）

对存在 C 级区间的数据，配置里提供两个模式，并且**两个都跑**：

```json
"data": {
  "publication_mode": "strict",          // 主结论：只用 A/B 级
  "assumed_publish_time": "14:00",       // 对照模式使用的假设时刻
  "backfill_alternative_mode": "backfill_assumed"
}
```

- `strict`：只保留可核验的观测，样本变短但结论可信。
- `backfill_assumed`：对不可核验的观测假设"as-of 日 14:00 发布"，样本长但含假设。

**关键**：如果两种模式结论方向不同，这本身就是最重要的发现——说明结果对数据时点极度敏感，不能作为业绩引用。示例项目里正是这种情况：strict 模式下 9 笔盈利，assumed 模式下 16 笔亏损。

## 日频价格数据的时点

| 数据 | 保守假设 | 理由 |
|---|---|---|
| 期货收盘价 / 结算价 | 当日收盘后可得 | 收盘价 15:00 才确定 |
| 期货开盘价 | 当日开盘时可得（可用于当日入场） | 开盘集合竞价成交 |
| 现货报价（当日一个价格） | **次日**才可用于交易决策 | 现货报价常在收盘后发布，且无法证明盘中可得 |
| 夜盘数据 | 归入下一交易日 | 避免重复计数 |

`timing.spot_availability = "next_session"` 就是落实这条。

## 常见陷阱与自查

**陷阱 1：用 as-of 日当发布日。**
周度数据 as-of 周三，但实际周三下午才发布。信号被提前到周三开盘 = 用了未来 6 小时的信息。

自查：`availability_session > asof_date` 必须恒成立。引擎导出的 `signal_alignment.csv` 逐行满足这一点，测试里也有对应断言。

**陷阱 2：用数据商页面的"更新时间"。**
很多财经站点会刷新 `updated_at`。用它会得到"当前时间"，等于全样本都用最新信息。

自查：检查 `publish_dt - asof_date` 的分布，若大量为负或大量集中在同一天，就有问题。

**陷阱 3：分位/均值窗口含当日。**
计算"过去 3 年 80% 分位"时，如果把当日也放进样本，就用了当日信息（虽然是很小的泄漏，但会让信号略偏）。

自查：窗口应为 `[t-lookback, t-1]`。引擎 `precompute_basis` 用 `vals[lo:i]`（不含 i）。

**陷阱 4：修订版本。**
指标可能被事后修订（初值 vs 修正值）。若用修正后序列，等于用了未来信息。

处理：优先保留初值；若只有修正值，需在规格中说明并按"可能存在小幅前视"标注。

**陷阱 5：交易日历错误。**
用自然日计算"N 个交易日后"，会把节假日算进去。

自查：所有持有期计数必须基于交易日历（`calendar.csv`），不是自然日。

## 产出物：时点对齐审计表

回测必须导出一张表，每行一个观测：

| as-of 日 | 指标值 | 发布时刻 | 时刻来源 | 可交易日 | 跳过交易日数 | 是否触发 |
|---|---|---|---|---|---|---|

这张表是"没有未来函数"的**唯一证据**。评审时先看这张表，再看收益。

- HTML 平台的"信号与时点对齐"页可筛选：仅触发 / 仅可核验 / 仅假设 / 仅不可用。
- Excel 工作表 `03_Indicator` 含同样字段。
