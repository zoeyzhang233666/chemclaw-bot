# 08 · 交付前检查清单（QA Checklist）

逐条打勾。任何一条 ❌ 都不许交付。

## A. 事件表（根基）

- [ ] 每个事件都能回答：谁、哪套装置、什么产品、产能多少、哪里、什么时间、什么原因
- [ ] 三种日期**分列存放**，没有互相顶替
- [ ] 每条至少有一个日期（首次获知日或实际停车日）
- [ ] 事件日已做**交易日顺延**，且顺延被登记
- [ ] 产能口径为**单套**；合计产能已注明拆分方式（如 396/3 = 132）
- [ ] 产品经正文核验，无跨品种混入
- [ ] 每条有 `quote`（能在 `source_url` 里逐字搜到）
- [ ] 剔除样本有能站得住的剔除理由

## B. 去重与重叠

- [ ] 重复报道已合并，保留最早披露日
- [ ] 同日多套装置已合并为 1 个事件
- [ ] 滚动报道只取首次
- [ ] 窗口重叠已检测，去重叠子样本已单独计算
- [ ] 全样本与去重叠子样本结论不一致时，已在报告中说明

## C. 价格与口径

- [ ] 主力连续已做**换月复权**，并验证换月日收益 = 旧合约真实涨跌
- [ ] 流动性门槛生效（未使用临近到期小合约的报价）
- [ ] 事件日若为非交易日，已顺延到首个交易日
- [ ] 事件日紧邻长假时已标记节日效应
- [ ] 复权后与未复权版本都保留（可对照）
- [ ] 缺失窗口标注“越界/缺失”，**没有填 0 或插值**

## D. 统计

- [ ] 每个窗口都给了 n
- [ ] 同时给均值与中位数（不只报均值）
- [ ] 分位数在 n<20 时标注“仅供参考”
- [ ] 符号检验仅在 n≥6 时使用
- [ ] **未对 n<10 的样本使用“显著”一词**
- [ ] 自助法 CI 已给出（或说明样本不足）
- [ ] 至少跑了：锚定日切换、窗口切换、去重叠、基准切换 四种稳健性

## E. 基准

- [ ] 有基准时：基准成分、权重、覆盖区间、自建说明已写入报告
- [ ] 无基准时：明确写“未计算异常收益”，未编造替代
- [ ] β、α 的估计窗口与样本数已披露

## F. 因果边界

- [ ] 报告包含“同期其他重大事件”清单
- [ ] 报告包含因果免责段落
- [ ] 没有出现“证明/导致/显著为正”等因果宣称
- [ ] 下游装置停车被列为需求端干扰，未计入供给事件

## G. 呈现

- [ ] HTML 单文件、离线可开、ECharts 内联
- [ ] 样本表可编辑（日期可改、可取消勾选、可删除）
- [ ] 点击事件能展开企业/装置/原因/引文/来源
- [ ] 口径切换后全页重算
- [ ] n<10 时**首屏**有醒目样本量警告
- [ ] 缺失值显示为“—/缺失”，不是 0
- [ ] Excel 11 张表齐全、可打开、无列错位
- [ ] 表名/文件名符合规范

## H. 自动化自检

```bash
python scripts/check_report.py --project <项目> --html <报告> --xlsx <工作簿>
```

必须输出 `自检通过：0 项失败`。

## I. 结果可信度自查（人工）

- [ ] 随机抽 2 个事件，手工用原始行情算一遍 t+5 收益，与报告一致
- [ ] 抽 1 个事件，打开 `source_url` 确认引文原文存在
- [ ] 换个锚定日重跑，看结论是否大变——大变就要在报告里点明
- [ ] 去掉最大/最小各一个事件，看均值是否翻号
