# 07 · 样本确认协议（含“演示 vs 结论”标记规则）

## 1. 为什么这一步不能省

事件研究的结果对样本极度敏感：多一个事件、改一个日期，均值可能从 +1% 变到 −3%。
如果不等用户确认就出结论，用户拿到的是一份**无法反驳也无法采信**的报告。

因此本技能把流程切成两段：

```
[第一段] 建事件库 → 出“待确认样本表” → 停，等用户确认
[第二段] 用户确认 → 跑正式研究 → 出报告
```

## 2. 第一段：向用户提什么

出一份 `事件样本确认表.html`，并明确请用户核对 **8 件事**：

1. ✅ 每个事件是否真的属于本品种（企业同时有别的产品装置）；
2. ✅ 产能是单套还是合计；
3. ✅ “市场首次获知日”是否真是盘面第一次反映那天；
4. ✅ 三种日期有没有被互相顶替；
5. ✅ 有没有同一次停车被拆成两条；
6. ✅ 区域级/跨月滚动事件有没有被硬塞进单一日期的框；
7. ✅ 每条是否都有能在原文搜到的原文摘录；
8. ✅ 剔除样本的理由是否站得住。

## 3. 用户没确认时怎么交付

**可以用，但必须全套标记。** 规则：

| 位置 | 标记方式 |
|---|---|
| 文件名 | 后缀 `_演示` 或 `_DEMO` |
| HTML 首屏 | 红色横幅：“本页样本未经确认，下列结果仅用于展示方法与版式，**不得作为研究结论引用**” |
| 每个图表标题 | 前缀 `[演示]` |
| Excel 00 表 | 首行红底提示 |
| 对话回复 | 第一句就说“这是演示版，样本未确认” |

**反向禁止**：只在一个角落写小字、而在正文用“研究表明”“可见”这类措辞，等于伪装成结论。

## 4. 用户确认后：需要记录的确认凭据

把确认结果落到 `project.json` 或 `events.csv` 的 `notes` 字段：

```json
{
  "confirmed_by_user": true,
  "confirmed_at": "2026-10-20",
  "confirmations": [
    "产能按单套口径，396 万吨/3 套按 132 万吨折算",
    "EV-REJ-02 为乙二醇，剔除",
    "事件日统一用市场首次获知日"
  ]
}
```

报告据此去掉演示标记，并在 00 表记录确认时间与要点。

## 5. 确认过程中常见的返工

用户在确认表上做的修改，通常集中在这几类，脚本需要能承接：

| 用户改动 | 脚本是否自动处理 | 说明 |
|---|---|---|
| 改日期 | ✅ 直接在表里改，导出后生效 | 日期会重新做交易日顺延 |
| 取消勾选某事件 | ✅ `include_flag=否` | 该事件不进可比集 |
| 删除整行 | ✅ 从 `events.csv` 移除 | |
| 改产能 | ✅ 影响阈值判定 | |
| 拆分一个事件为两个 | ❌ 需手工加行 | 脚本不做自动拆分 |
| 合并两个事件 | ❌ 需手工合并 | 保留最早披露日 |

## 6. 与用户沟通的话术模板

> 我先把候选事件整理成了一张**可编辑的确认表**（8 条候选，其中 2 条建议不纳入）。
> 在正式计算价格路径之前，麻烦您核对四类问题：
> ① 有没有把别的品种的装置（如乙二醇）误收进来；
> ② 产能是单套还是合计（这条会直接改变阈值判定）；
> ③ “市场首次获知日”对不对（我默认取媒体首次披露日并顺延到首个交易日）；
> ④ 有没有同一次停车被拆成了两条。
>
> 您可以在表里直接勾选/改日期/删除，导出后我再跑正式的路径与分布统计。
> 如果您希望先看看结果长什么样，我可以出一份**明确标注为演示**的版本——但它不能当作结论使用。
