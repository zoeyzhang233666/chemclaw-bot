# 02 数据源与取证清单

## 优先顺序

1. **交易所 / 官方统计**（最权威，口径最清晰）
2. **付费资讯商周报原文**（隆众、卓创、钢联等，行业最常用）
3. **行业协会 / 海关**（进出口与表观消费）
4. **公开转载页**（次要，但便于核对标题与增减额）

先用 1 定口径基准，用 2 拿高频数据，用 3 做交叉验证。

## 取证清单（每一期都要能回答）

- [ ] 截止日（是数据截止日还是发布日期？两者不同！）
- [ ] 原始数值与单位
- [ ] 原文标题（含日期戳，如 `(20261014)`）
- [ ] 原文链接／文号
- [ ] 是否给出“较上期增减额”
- [ ] 是否给出分区（华东/华南）增减额
- [ ] 表格是否为逐地区（江苏/浙江/广东/福建）还是只有合计
- [ ] 该期是否为局部采样（缺少部分港口时表格值会失真）

把以上落到 `a_sample.pkl` 对应列，报告中的每一行数字都能点回原文。

---

## 关键区分：截止日 vs 发布日期

- **截止日**：数据统计的时点（通常为周二或周三）
- **发布日期**：文章上线时间（通常为周三 14:00 前后）

做周次对齐用**截止日**；判断披露是否延迟用**发布日期**。
两者混用会让同一周数据错位一到两周。

## 抓取与反爬的实操经验（血泪版）

1. **移动端页面常与 PC 端字段不同**：PC 版有完整表格，移动版可能只有正文。
2. **链接是 post_id 拼接**：形如 `/a/{post_id}_abc.html`，`post_id` 递增，可据此枚举历史。
3. **正文增量抓取**：先拉列表页拿 `post_id` 与标题，再按需拉正文，避免全量重爬。
4. **失败必须记“缺失”，不许估算**：
   - `net::ERR_CONNECTION_CLOSED`（DNS/网络故障）→ 该期标记未取到
   - 404 / 登录墙 → 标记无权限
   - 空正文 → 标记解析失败
5. **绝对不要**因为某期抓不到就用“插值”或“按比例估算”补上——那会把真实缺口伪装成完整样本，分位随之失真。
6. 抓完做**完整性断言**：期数 = 预期周数 − 记录在案的缺失数。

## 交叉验证的三条硬标准

| 验证项 | 通过标准 |
|---|---|
| 总量一致性 | 原文总量 vs 表格合计，差 < 0.02 万吨 |
| 增减额一致性 | 原文增减额 vs 两期表格差，差 < 0.05 万吨（若超，查是否局部采样） |
| 分区一致性 | 华东 + 华南 ≈ 总量变化 |

任一项长期不通过，说明数据源本身口径混乱，必须先查清再用。

---

## 数据截止与“最后一次可得”的记录方式

当某种披露停止（如逐地区水平不再公开），必须记录：

```json
{
  "east_available_last": "2026-07-29",
  "level_missing_from": "2026-07-30",
  "level_missing_weeks": 11,
  "still_available": ["全国港口总量", "华东增减额", "华南增减额"]
}
```

报告里对缺失期只能说“水平值不可得，可用增减额描述变化”，不得把替代值写成公布值。
