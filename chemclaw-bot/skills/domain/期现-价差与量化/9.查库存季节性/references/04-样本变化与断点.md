# 04 样本变化与断点

## 为什么这是最容易翻车的一环

季节性分析的本质是“拿今年和往年比”。一旦**往年的样本和今年的样本不是同一个东西**，
所有分位都建立在错误前提上——而且出错时数字看起来完全正常。

本案例就踩到了最典型的一种：**披露方式在年中降级**，
逐地区水平值突然停更，只剩下总量和分区增减额。

---

## 五类断点

### B1 统计范围变更（Sample Universe Change）

- **表现**：样本港口/厂家增减，历史序列在新起点跳变
- **识别**：新旧期数之间的水平差无法用披露的增减额解释
- **处理**：把范围变更日登记为断点，两侧不合并；如需长序列，只做敏感性对照

### B2 披露方式降级（Disclosure Downgrade）

- **表现**：原来有逐地区表格，后来只有总量 + 分区增减额
- **识别**：`prov_full` 从 True 持续变 False；`east_table` 计数停止增长
- **处理**：记录“最后可核验水平日”，此后的水平值标 `不可得`，只用增减额

### B3 局部采样（Partial Sampling）

- **表现**：某期表格只覆盖部分港口，数值偏小；下期补齐后跳回
- **识别**：`|原文增减额 − 表格差分| > 0.05`
- **处理**：**增减额一律取原文披露值**，表格差分仅作核对

### B4 数据中继/口径断裂（Series Break）

- **表现**：早期序列由另一套体系统计（如简报式一行数据），与现行不可比
- **识别**：早期记录缺少分项、单位或口径说明；数值量级或波动结构与现行段明显不同
- **处理**：单独存为 B 样本，**永不拼接**，只在敏感性场景里做对照

### B5 发布节奏变化（Cadence Change）

- **表现**：春节等假期出现双周报；或临时停更数周
- **识别**：`gap_days` 分布
- **处理**：
  - 10–16 天 → 视为双周报，**不剔除**
  - \> 16 天 → 记为缺报，在完整性中披露

> 本案例曾把春节前后的双周报误判成缺报（18 处），
> 修正后按 >16 天判定，缺报为 0。这是典型的“过度清洗”错误。

---

## 识别方法：三条量化检验

### 检验 1：增减额 vs 表格差分

```python
gap = ev_east_chg - (east_t - east_t-1)
flag = |gap| > 0.05
```

命中即为 B3。本案例 230 期中命中 7 期，最大差额 +7.48 万吨。

### 检验 2：披露完整性的时间序列

按周/按月统计：

| 指标 | 含义 |
|---|---|
| `prov_full` 比例 | 四省齐全的期数占比 |
| `ev_region_split` 比例 | 正文给出分区增减额的期数占比 |
| `east_table` 非空比例 | 华东能由表格直接算出的期数占比 |

三条同时掉到 0，就是 B2 断点。本案例 2026-08 起三线全掉。

### 检验 3：覆盖漂移

```
south_share(t) = (port_total - east) / port_total
```

按年中位数逐年比较。若某年占比明显跳档（如从 17% 跳到 28%），
说明样本口径变了——此时“全国港口总量”的同比也不可信。

本案例占比：2022 年 17.3% → 2025 年 28.5% → 2026 年 25.1%，存在结构性抬升。

## 断点登记模板（写进 config.json）

```json
"breakpoints": [
  {"date": "2018-05-24", "kind": "数据中继", "effect": "早期简报式序列到此结束，与 2022 年起的样本不可拼接", "treat": "单独存为 B 样本"},
  {"date": "2022-04-06", "kind": "统计范围变更", "effect": "现行样本起点，此后才有逐地区表格", "treat": "A 样本从此开始"},
  {"date": "2026-07-01", "kind": "披露变更", "effect": "正文改为只给总量与分区增减额", "treat": "仅用增减额"},
  {"date": "2026-07-22", "kind": "披露断档", "effect": "逐地区表格水平值停止更新，华东水平不可得", "treat": "分位止于最后可核验期"}
]
```

字段说明：

| 字段 | 必填 | 含义 |
|---|---|---|
| `date` | 是 | 断点生效日 |
| `kind` | 是 | 五类之一或自定义 |
| `effect` | 是 | 对统计的具体影响（要能指导计算，不能写“有影响”） |
| `treat` | 建议 | 处理方式 |
| `evidence` | 建议 | 原文链接或数据截图出处 |

## 敏感性场景（必做）

同一指标在不同样本下的分布差异，用来证明结论不是被某个样本切法造出来的：

| 场景 | 目的 |
|---|---|
| 全部可得周次 | 基准 |
| 剔除异常段 | 检验极端年份是否主导结论 |
| 仅近 2 个完整年 | 检验近期格局权重 |
| 仅逐地区完整披露的周次 | 检验局部采样期是否污染分布 |
| B 样本（断裂的早期序列） | 检验长周期水平差异 |

若五个场景给出的中位数差异 < 10%，说明结论稳健；若差异很大，必须在报告中写明“结论依赖样本选择”。

## 异常年份处理

### 预登记异常窗口

在 config 里写下已知的极端时期（如某轮极端下行/上行），
在报告里注明“该段不剔除出样本，但解释时需单独说明”。

### 逐年去季节偏离统计

对每年计算：平均偏离、偏离标准差、|z|>2 的周占比、最大偏离周。
本案例结果：

| 年份 | 平均去季节偏离 | 标准差 | 最大单周偏离 |
|---|---|---|---|
| 2022 | +0.7% | 31.6% | −61.4%（W43） |
| 2023 | +3.6% | 11.4% | +29.5%（W14） |
| 2024 | −1.0% | 16.8% | −45.4%（W13） |
| 2025 | −4.2% | 24.1% | −48.2%（W20） |
| 2026 | +1.2% | 30.0% | −80.4%（W29） |

**读法**：历史各年平均偏离都在 ±5% 内 → 季节模型没有系统性高估/低估；
但 2026 年单周偏离达 −80.4%，属于格局级别的事件，不是季节性。

---

## 断点前后不可做的四件事

1. 不要把断点前后的数据接成一条曲线做分位带
2. 不要用断点后的替代值回填断点前的真实值（或反之）
3. 不要把不同口径的增减额相加
4. 不要在报告里对断点一带而过——断点必须出现在**首屏**与**结论句**里
