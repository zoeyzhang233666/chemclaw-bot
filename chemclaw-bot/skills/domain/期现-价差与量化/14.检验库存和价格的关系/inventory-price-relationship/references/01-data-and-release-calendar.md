# 01 · 数据口径与真实发布日历

> 目标：在任何统计计算开始之前，把「这条库存数据什么时候被公开」固化为可审计的时间戳。

## 1.1 必须记录的五列

| 字段 | 含义 | 示例 |
|---|---|---|
| `source_id` | 数据源唯一标识（机构 + 系列名） | `隆众-中国甲醇样本港口库存周数据统计` |
| `asof` | **统计截止日**（库存计量的时点） | `2026-10-14`（周三） |
| `pub_ts` | **真实公布时点**（数据可被公众获取的时刻） | `2026-10-14 14:00` |
| `url` | 原文链接（可回溯、可举证） | `https://nenghua.m.mysteel.com/a/26101414/XXXX_abc.html` |
| `def_note` | 口径备注（样本范围、覆盖率、单位、含税/不含税、是否含保税） | `40家库区实时物理库存，覆盖率98%，含保税` |

**只有 `asof` 没有 `pub_ts` 的数据，不能用于任何时点敏感的检验。**

## 1.2 口径必须逐项问清楚的 8 个问题

1. **统计的是谁？** 港口库存 / 企业库存 / 社会库存 / 交易所仓单 —— 四者含义完全不同。
2. **样本覆盖多少？** 例：40 家库区、覆盖率 98%。覆盖率变化会造成序列断层。
3. **单位与含税** 万吨？吨？含税还是不含税？
4. **是否含保税/在途/在卸？** 例：甲醇港口样本"含保税区内库存""个别在卸船货已全量计入"。
5. **统计切片时点** 每周三早间？周五收盘？月度最后一天？
6. **更新时间与频率** 周更还是日更？节假日是否顺延？
7. **是否回头修订？** 多数商业机构周报**不修订**；但第三方转载会出错。
8. **同期有无口径变更？** 例：2016–2018 为"分地区列示"，2022 后为"40 家库区样本" —— **不可拼接**。

## 1.3 发布时点的三种典型情形

| 情形 | 特征 | 处理 |
|---|---|---|
| **A. 固定节假日历** | 每周固定星期 + 固定钟点（如周三 14:00） | 建发布日历，节假日顺延需逐期核对 |
| **B. 随发文走** | 无固定时点，随新闻稿发布 | `pub_ts` 取**首次公开可检索时间** |
| **C. 事后回填** | 网站在某日批量补发历史周报 | `pub_ts` 会远晚于 `asof` → **必须标记**，该类样本在"实时可得"子样本中应剔除 |

### C 类的识别与处理

```python
# 回填识别：转载/发布时间比 asof 晚超过 3 天
df["is_backfill"] = (df["pub_ts"] - df["asof"]).dt.days > 3
```

若某段历史**只有回填样本**，则：
- 可以用它做**描述性对照**；
- **不能**把它当作"当时可得"的数据参与主检验；
- 报告中必须写明该区间为"回填重建"，而非实时样本。

## 1.4 缺口处理：宁可留白，不要编造

甲醇案例的真实情况：

| 区间 | 可得性 | 用途 |
|---|---|---|
| 2016-08 → 2018-05 | 同源但分地区列示，34 周且间断 | 仅作口径对照 / 稳健性参照 |
| 2019 → 2023初 | **无可获得连续公开周报** | 不做任何推断 |
| 2022-04 → 2026-10 | 连续 228 周，含原文与发布时间 | **主样本** |

> 若强行用第三方引用把 2019–2023 拼成连续序列，会引入大量"日期错位 + 口径混用"，得到的相关性无法解释。**留白是结论的一部分。**

## 1.5 价格侧口径同样要记录

| 字段 | 说明 |
|---|---|
| 现货口径 | 哪个机构、哪个地区、含税否（例：生意社 华东 MA 基准价，元/吨，不含税） |
| 期货口径 | 主力连续 / 近月 / 结算价 or 收盘价（例：100ppi 主力合约价，与 MA 主连日收盘 ρ=0.99918） |
| 基差定义 | **现货 − 期货**（多数化工品）；基差率 = 基差 / 期货价 |
| 价格发布时点 | 例：生意社每日 16:30 后公布 → 当日收盘价在 16:30 前**不可得** |

### 为什么价格发布时点会改变结论

若库存周三 14:00 公布、价格 16:30 才定，则**同日收盘价已经包含了库存消息的影响**。
用它做基期，会把"公布瞬间的价格跳变"从未来收益里**剔除掉**，人为压低关系强度。

正确做法：基期 = **公布后第一个交易日收盘**（周三 16:30 的消息 → 周四收盘为基期）。
本案例即采用该口径，可复现。

## 1.6 素材归档要求

- 每期原文 HTML 或正文文本落盘（`raw/`），文件名含 asof
- 解析出的数值、正则匹配片段一并保存，便于人工抽检
- 抽检建议：按年随机抽 3 期，人工比对原文数字与解析结果，记录抽检结论
