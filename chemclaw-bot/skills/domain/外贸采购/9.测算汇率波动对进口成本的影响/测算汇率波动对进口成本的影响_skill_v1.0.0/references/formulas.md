# 公式推导与边界情况

本文列出全部公式，说明每一步为什么这样写，以及什么情况下会失效。

---

## 1. 币种方向

```
FC_CNY = 1 / CNY_FC          （输入为 CNY/FC 时）
FC_CNY = quote / 100         （如 100JPY/CNY 这类百单位报价）
```

**失效场景**：报价方向未声明。引擎的 `quote_direction_guard()` 要求输入显式声明 `quote_direction`，否则报错而不是猜测。

---

## 2. 人民币付款额

```
P = A_fc × R
```

- `A_fc`：外币金额
- `R`：`FC_CNY` 口径汇率

**这是本 Skill 最基础的一步，也是唯一在“只给了金额”时必须给出的结果。**

---

## 3. 敏感性

```
R(Δ)  = R_base × (1 + Δ)
P(Δ)  = A_fc × R(Δ)
ΔP    = P(Δ) − P_base
ΔP%   = ΔP / P_base
```

**关键性质**：`P` 对 `R` 是严格线性、过原点的关系，所以 `ΔP%` 恒等于 `Δ`。这是校验公式正确性的一个好工具——如果算出的变动幅度不等于变动率，说明有项没乘汇率或多乘了。

方向判定：
- `Δ > 0`（汇率数值上升 = 人民币贬值）→ `ΔP > 0`，**成本上升**
- `Δ < 0`（人民币升值）→ `ΔP < 0`，**成本下降**

> **这是最容易错的地方。** “汇率上升”对进口方是坏消息，对出口方是好消息。本 Skill 只处理进口，所有方向判定统一按“人民币贬值 → 进口成本上升”。

---

## 4. 完税价格

```
DV = (CIF 外币合计) ÷ R_base × R_customs
```

- `CIF 外币合计` = 货值 + 国际运费 + 保险费 + 其他外币费用
- `R_customs`：申报月份对应的海关计征汇率（上月第三个星期三的中间价）

**为什么除以 `R_base` 再乘 `R_customs`**：外币金额本身不变，先还原成“以基准汇率计的人民币等值”，再按法定计征汇率折算。等价于 `CIF_fc × R_customs`（当 `R_base` 就是纯外币计价时，两者相同；此处写法保留了基准汇率显式项，便于追踪）。

> **失效场景**：`R_customs` 缺失。回退为 `R_base` 并打 `customs_rate_fallback: true` 标记，报告中必须提示“计征汇率未取到，已按基准汇率近似，税款可能有偏差”。

---

## 5. 税费

```
关税     Duty = DV × 关税率
消费税   CDC  = DV × 消费税率
进口增值税 VAT = (DV + Duty + CDC) × 增值税率
```

**注意**：
- 增值税的计税基础是 `(完税价格 + 关税 + 消费税)`，不是完税价格。
- 消费税从价计征时才适用上式；从量/复合计税需另算，本 Skill 只支持从价。
- 反倾销/反补贴税若适用，应并入关税率或单列，本 Skill 不自动判断是否适用。

**增值税是否计入成本**：

| 口径 | 处理 | 适用 |
|---|---|---|
| `deductible`（默认） | 增值税入成本 = 0，仅占资金 | 一般纳税人，取得合规增值税专用缴款书 |
| `cost` | 增值税入成本 = 全额增值税 | 小规模纳税人、进项不可抵扣 |

两者对到厂成本的影响是 **13% 量级**（案例：可抵扣 7,204,900 元 vs 不可抵扣 8,126,548 元，差 921,648 元）。

---

## 6. 到厂成本

```
LC = 货值 + 运费 + 保险费 + 其他外币费用
   + 关税 + 消费税 + 增值税入成本
   + 人民币固定费用
```

**人民币固定费用** = 港杂费 + 报关代理费 + 内陆运输费 + 仓储及其他 + 银行手续费及汇兑费用。

**这些项不乘汇率**——这是最容易犯的错误。它们本身就是人民币金额，与汇率无关。

汇率相关成本占比：

```
share = (LC − 人民币固定费用) ÷ LC
```

案例：`(7,204,900 − 91,800) / 7,204,900 = 98.73%`。也就是说，汇率每动 1%，到厂成本动 0.9873%。

> 若某批货的国内费用占比很高（如冷链、危化品运输），这个比例会明显低于 100%，敏感性会相应被稀释。

---

## 7. 毛利

```
不含税售价 = 含税售价 ÷ (1 + 增值税率)        （当 revenue_basis = tax_included）
不含税收入 Rev = 不含税售价 × 数量
非汇率成本 OC = 单位非汇率成本 × 数量
总成本      TC = LC + OC
毛利额      GP = Rev − TC
毛利率      GM% = GP / Rev
```

**为什么用不含税收入**：增值税是价外税，比较毛利时收入与成本都应在不含税口径。

**边界**：
- `Rev = 0` 时毛利率返回 0（避免除零）。
- 售价或数量缺失 → 跳过整个毛利模块，`missing` 列表中记录原因。

---

## 8. 盈亏平衡汇率

### 推导

设：
- `R0` = 不含税收入
- `FX0` = 到厂成本中的汇率相关部分（正比于汇率）
- `NF` = 不随汇率变动的全部成本 = `(LC − FX0) + OC`
- `m` = 目标毛利率
- `λ = 新汇率 / 基准汇率`

汇率变动后：
```
成本(λ) = NF + FX0 × λ
毛利(λ) = R0 − NF − FX0 × λ
```

令毛利率等于目标值：
```
R0 − NF − FX0λ = m × R0
FX0λ = R0(1 − m) − NF
λ* = [R0(1 − m) − NF] / FX0
```

平衡汇率：
```
R* = R_base × λ*
```

汇率缓冲空间：
```
headroom = (λ* − 1) × FX0
```

### 边界与适用性

**必须做适用性判断**，否则会算出无意义的负数或荒谬值：

| 情形 | 判定 | 输出 |
|---|---|---|
| `FX0 ≤ 0` | 没有汇率敞口 | `feasible: false`，说明“汇率相关成本为 0” |
| 基准毛利率 < 目标毛利率 | 当前已不达标 | `applicable: false` + 原因说明 + `reference_rate`（标注仅供参考） |
| `λ* ≤ 0` | 即使汇率趋零也无法达标 | `applicable: false` + 原因 |
| 其他 | 正常 | `applicable: true` + `breakeven_rate` |

> **曾经的 bug**：早期版本计算 `base_margin` 时漏掉了非汇率成本 `OC`，导致基准毛利率被高估（5.73% vs 实际 1.87%），把本已不达标的 5% 目标误判为“适用”。修复方式是给 `breakeven_rate()` 增加 `other_fixed_cny` 参数，并把它并入 `NF`。Excel 侧同步用 `((LC − FX0) + OC)` 表达 `NF`。

**案例结果**（基准毛利率 1.8668%）：

| 目标毛利率 | λ* | 平衡汇率 | 相对当前 | 适用性 |
|---|---|---|---|---|
| 0% | 1.0201 | **6.8788** | +2.01% | ✔ 适用 |
| 5% | — | — | — | ✘ 不适用（基准已低于目标） |
| 10% | — | — | — | ✘ 不适用（基准已低于目标） |

**读法**：人民币需贬值 2.01%（USD/CNY 从 6.7435 升到 6.8788）才会把毛利压到 0。这不是预测，是敞口大小的度量。

## 9. 分批付款

```
各批金额ᵢ = 比例ᵢ × A_fc × Rᵢ
合计 = Σ 各批金额ᵢ
```

- `Rᵢ` 可取情景汇率（按结算时点 × 变动率），也可取“已锁汇率”（手工填入）。
- 比例之和必须为 100%，否则校验报错。

**案例**：
- 预付款 30%，结算日 2026-11-19：`0.30 × 1,000,000 × 6.7435 = 2,023,050`
- 尾款 70%，结算日 2027-01-18：`0.70 × 1,000,000 × 6.7435 = 4,720,450`
- 合计 = 6,743,500 ✓（等于一次性付款）
- 全部 +5% 情景：6,743,500 × 1.05 = 7,080,675

## 10. 舍入规则

本 Skill 使用 **Decimal + ROUND_HALF_UP**，而不是 Python 内置 `round()`。

原因：`round(2.5) = 2`（银行家舍入），与财务惯例的“四舍五入”不符，会让校验用例在 `.5` 边界上失败。

```python
from decimal import Decimal, ROUND_HALF_UP

def r2(x):
    return float(Decimal(str(x)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))
```
