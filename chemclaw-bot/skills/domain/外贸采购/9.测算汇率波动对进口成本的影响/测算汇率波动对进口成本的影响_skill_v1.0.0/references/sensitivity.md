# 敏感性与分批付款的设计逻辑

---

## 1. 为什么用 ±1% / ±3% / ±5% 三档

不是随机选的。这三个量级对应三类现实波动：

| 档位 | 对应现实 | 用途 |
|---|---|---|
| **±1%** | 单日到一周的日常波动 | 判断“晚两天付款”的影响 |
| **±3%** | 一个月到一季度的正常波动区间 | 判断 90 天账期的核心风险 |
| **±5%** | 季度级别的较大波动 | 压力情形，判断“会不会亏” |

**这不是预测。** 三档只是等距的探针，用来把“汇率 → 成本”的映射关系画出来。报告里严禁写“汇率可能上涨 5%”。

---

## 2. 敏感性表的构造

对每档 `Δ`：

```
新汇率   R(Δ) = R_base × (1 + Δ)
付款额   P(Δ) = A_fc × R(Δ)
变动额   ΔP   = P(Δ) − P_base
变动幅度 ΔP / P_base
方向     Δ>0 → "人民币贬值·成本↑"；Δ<0 → "人民币升值·成本↓"
```

案例（基准 6.7435，金额 1,000,000 USD）：

| 汇率变动 | 新汇率 | 人民币付款额 | 变动额 | 方向 |
|---|---|---|---|---|
| −5% | 6.4063 | 6,406,325 | −337,175 | 人民币升值·成本↓ |
| −3% | 6.5412 | 6,541,195 | −202,305 | 人民币升值·成本↓ |
| −1% | 6.6761 | 6,676,065 | −67,435 | 人民币升值·成本↓ |
| **0%** | **6.7435** | **6,743,500** | **0** | **基准情景** |
| +1% | 6.8109 | 6,810,935 | +67,435 | 人民币贬值·成本↑ |
| +3% | 6.9458 | 6,945,805 | +202,305 | 人民币贬值·成本↑ |
| +5% | 7.0807 | 7,080,675 | +337,175 | 人民币贬值·成本↑ |

**记忆锚点**：1,000,000 USD 的合同，汇率每动 1%，就是 **67,435 元**人民币。这个数字比任何百分比都直观。

## 3. 到厂成本敏感性（非线性部分）

到厂成本不是纯线性的，因为关税、增值税会放大货值的变动：

```
到厂成本(Δ) = 货值(Δ) × (1 + 关税率) × (1 + 增值税系数) + 消费税 + 人民币固定费用
```

案例：汇率 **+5%** 时，付款额增加 **337,175 元**，但到厂成本增加 **355,655 元**——多出的 18,480 元来自关税（5.5%）与进口增值税随完税价格同步放大。汇率 −5% 时同理反向。

**这就是为什么不能只看付款额。** 关税与增值税会按完税价格同比放大/缩小，使得到厂成本对汇率的敏感度比付款额高出约 5.5%（等于关税率）。对需要垫付税款的进口商，增值税的现金流影响虽然（可抵扣时）不计入成本，但占用资金。

## 4. 汇率相关占比：稀释效应

```
share = (到厂成本 − 人民币固定费用) ÷ 到厂成本
```

案例：`(7,204,900 − 91,800) / 7,204,900 = 98.73%`

含义：汇率每动 1%，到厂成本动 **0.9873%**，不是 1%。

**什么时候这个比例会明显下降？**
- 国内运费占比高（危化品、冷链、远距离）
- 仓储费高（液体罐区、特殊储存条件）
- 银行手续费高（小币种、小额高频）

若 `share` 只有 70%，说明三成成本对汇率免疫——此时单纯看付款额会高估风险。

## 5. 分批付款：为什么要按批次算

一份 90 天账期的合同，如果 30% 预付、70% 尾款，那么：

- 预付款按 **签约后 30 天** 的汇率结算
- 尾款按 **90 天** 的汇率结算

两批不是同一个汇率。**用单一汇率算整个合同，会低估或高估真实敞口。**

### 5.1 计算方式

```
各批金额ᵢ = ratioᵢ × A_fc × Rᵢ
合计 = Σ 各批金额ᵢ
```

`Rᵢ` 的来源有两种：

| 模式 | `Rᵢ` 取值 | 用途 |
|---|---|---|
| 情景模式 | 基准汇率 × (1 + 情景变动率) | 看“如果到期时汇率是 X” |
| 锁定模式 | 该批的 `locked_rate` | 看“已锁定的部分不受影响” |

### 5.2 案例

| 批次 | 比例 | 金额（USD） | 结算日 | 基准人民币 |
|---|---|---|---|---|
| 预付款 | 30% | 300,000 | 2026-11-19 | 2,023,050 |
| 尾款 | 70% | 700,000 | 2027-01-18 | 4,720,450 |
| **合计** | **100%** | **1,000,000** | — | **6,743,500** |

情景矩阵（全部批次同向变动）：

| 变动 | 预付款 | 尾款 | 合计 | 较基准 |
|---|---|---|---|---|
| −3% | 1,962,358.50 | 4,578,836.50 | 6,541,195 | −202,305 |
| 0% | 2,023,050 | 4,720,450 | 6,743,500 | 0 |
| +3% | 2,083,741.50 | 4,862,063.50 | 6,945,805 | +202,305 |
| +5% | 2,124,202.50 | 4,956,472.50 | 7,080,675 | +337,175 |

### 5.3 锁定部分的效果

若预付款在签约时锁定 `6.7000`：

- 预付款固定为 `300,000 × 6.7000 = 2,010,000`，**不再随情景变化**
- 只有尾款 700,000 USD 暴露在汇率风险下
- +5% 情景下合计 = `2,010,000 + 4,956,472.50 = 6,966,472.50`，比全部暴露时的 7,080,675 少 **114,202.50 元**

> **注意措辞**：本 Skill 只展示“锁定部分如何降低敏感度”这个**数学事实**，不推荐任何锁定工具、不评价“该不该锁”。是否锁定、用什么方式锁定，属于用户的商业决策。

## 6. 预算汇率情景

若用户提供 `budget_rate`（内部核算或报价时用的汇率），额外算一档：

```
λ = budget_rate / R_base
新汇率相关成本 = FX0 × λ
新到厂成本 = FX0 × λ + (LC − FX0)
毛利变化 = 新毛利 − 基准毛利
```

案例：预算汇率 6.80

- λ = 6.80 / 6.7435 = 1.00838（较基准汇率高 0.8378%）
- 到厂成本 = **7,264,496.67**（较基准 +59,596.67）
- 毛利额 = **83,083.58**（较基准 −59,596.67），毛利率 **1.087%**

**读法**：按 6.80 做预算或报价，相当于提前认定“人民币会贬到 6.80”。若汇率最终停在 6.7435，账面毛利比预算多 5.96 万元——这 5.96 万元就是**预算汇率与市场汇率之间的隐性缓冲**。反过来，若实际汇率走到 6.80，毛利就只剩 1.087%，安全垫被吃掉一半以上。这是内部核算与市场现实的差距，不是预测。

---

## 7. 输出呈现原则

1. **每一档都要有方向判定文字**，不能只给数字。
2. **0% 那行必须高亮**，作为锚点。
3. **变动额与变动幅度并列**，前者给绝对值，后者验算线性。
4. **不写“建议”“应当”“考虑锁定”**等措辞。
5. 情景表的标题写 **“若汇率为 X”**，不写“汇率将到 X”。
