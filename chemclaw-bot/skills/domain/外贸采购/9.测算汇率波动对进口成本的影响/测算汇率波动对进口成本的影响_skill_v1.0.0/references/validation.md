# 三层校验体系

> 一个测算结果只要没人复核过，就不该拿去做决策。本 Skill 内置三层校验，`verify_calc.py --all` 一条命令跑完全部 **32 项断言**。

---

## 为什么需要三层

常见的问题是“看起来对”：

- Python 算对了，但 Excel 公式写错了行号——用户在 Excel 里改了参数，结果全错；
- Excel 和 Python 都对，但用的是同一个错误的公式——两边一致地错。

所以要分别校验：**公式本身对不对 → Excel 实算与引擎是否一致 → 改参数后是否还一致**。

---

## 第 1 层：引擎自检（V1，13 项）

验证物理与法规逻辑，不依赖任何外部文件。

| # | 断言 | 为什么重要 |

## 第 2 层：Excel 公式真实重算（V2，13 项）

把生成的 `.xlsx` 用内置的 **纯 Python 公式求值器**（`scripts/xlsx_recalc.py`）重算一遍，与引擎结果比对。

**为什么不直接用 Excel 校验**：CI/离线环境通常没有 Excel，也没有 LibreOffice（本机实测 `C:\Program Files`、`C:\Program Files (x86)` 均无）。自己写一个足够用的求值器，反而可控。

### 求值器支持范围

- 解析 `xl/sharedStrings.xml`、`xl/styles.xml`、`xl/workbook.xml` 及各 sheet XML
- 日期序列号识别（styleId 14–22/45–47，或 numFmt 含 `y/m/d`）
- 函数：`SUM` `AVERAGE` `MIN` `MAX` `COUNTIF(S)` `SUMIFS` `AVERAGEIFS` `MINIFS` `MAXIFS` `IF` `AND` `OR` `NOT` `ABS` `ROUND/UP/DOWN` `INT` `INDEX` `MATCH` `TEXT` `LEN` `IFERROR` `ISBLANK` `ISNUMBER` `ISTEXT` `CONCATENATE`
- 跨表引用 `'01 参数与汇率'!B29`
- 数组常量 `{"a";"b"}`
- 循环引用检测

### 比对项

| 项目 | 容差 |
|---|---|
| 采购金额 = 引擎输入 | 精确 |
| 基准汇率 = 银行购汇价 | 精确 |
| 付款额 = 外币金额 × 汇率 | 1 元 |
| 7 档敏感性表逐行一致 | 1 元 |
| 到厂成本 | 1 元 |
| 单位到厂成本 | 0.01 元 |
| 关税 | 1 元 |
| 增值税 | 1 元 |
| 毛利额 | 1 元 |
| 毛利率 | 0.01% |
| 盈亏平衡（含“不适用”留空） | 0.001 |
| 分批合计 = 付款额 | 1 元 |
| 近 3 年中间价分位 | 0.5 个百分点 |

> **分位容差说明**：Excel 用 `COUNTIFS(dates,">="&B7)` 按单元格日期筛选，引擎用 Python 日期比较。两者对“区间起始日是否包含”的处理可能差 1–2 个观测点，在 1,743 个样本上表现为 0.01–0.1 个百分点。案例实测 Excel 4.58% vs 引擎 4.59%，属正常口径差异，已在断言中注明。

## 第 3 层：公式联动独立性检验（V3，6 项）

**这是最关键的一层。** 前两层可能“共同犯错”，第三层通过改参数强制公式重算，暴露硬编码。

| 用例 | 改动 | 预期 |
|---|---|---|
| 1 | 金额翻倍 → 2,000,000 | 付款 13,487,000；到厂 14,318,000 |
| 2 | 银行购汇价 → 7.0000 | 付款 7,000,000；到厂 7,461,400 |
| 3 | 预付款比例 → 50% | 付款不变；合计仍为 100% |
| 4 | 预付款锁定 6.7000 | 该批不再随情景变 |
| 5 | 关税率 → 0% | 到厂 6,835,300（少 369,600） |
| 6 | 增值税不可抵扣 | 到厂 8,126,548（多 921,648） |

每个用例都是：**改 input.json → 重建 xlsx → 重算 → 与引擎对比**。若某个公式里写死了数字而不是引用参数，这里必然失败。

## 自行复核的方法

不想跑脚本时，手工验算这几个数：

```
1. 付款额      = 1,000,000 × 6.7435           = 6,743,500      ✓
2. ±1% 影响     = 6,743,500 × 1%               = 67,435         ✓
3. 完税价格     = 1,000,000 × 6.72            = 6,720,000      ✓
4. 关税        = 6,720,000 × 5.5%             = 369,600        ✓
5. 增值税      = (6,720,000 + 369,600) × 13%  = 921,648        ✓
6. 人民币费用   = 38000+12000+26000+9000+6800  = 91,800         ✓
7. 到厂成本     = 6,743,500 + 369,600 + 91,800 = 7,204,900      ✓
   （增值税可抵扣，不计入）
8. 单位成本     = 7,204,900 ÷ 1136.4           = 6,340.11 元/吨 ✓
9. 汇率相关占比 = (7,204,900 − 91,800)/7,204,900 = 98.73%       ✓
10. 不含税收入  = 7600/1.13 × 1136.4           = 7,643,044.25   ✓
11. 总成本      = 7,204,900 + 260×1136.4       = 7,500,364      ✓
12. 毛利额      = 7,643,044.25 − 7,500,364     = 142,680.25     ✓
13. 毛利率      = 142,680.25 / 7,643,044.25    = 1.8668%        ✓
14. λ*(0%)     = (7,643,044.25 − 91,800 − 295,464) / (7,204,900 − 91,800)
               = 7,255,780.25 / 7,113,100      = 1.02006        ✓
15. 平衡汇率    = 6.7435 × 1.02006             = 6.8788         ✓
```

第 14 步注意 `NF = (LC − FX0) + OC = 91,800 + 295,464 = 387,264`，`FX0 = 7,204,900 − 91,800 = 7,113,100`。

## 历史 bug 记录（为何规则是这样定的）

| 症状 | 根因 | 修复 |
|---|---|---|
| Excel 敏感性表引用错行 | `write_formula(r, ...)` 的 `r` 是 0-based，公式里直接用 `{r}` 少一行 | 统一改为 `{r+1}` |
| 03 表 `B6 = B6*B7` 循环引用 | `RATE_CELL` 是 02 表地址，跨表未加表名前缀 | 引入 `RATE_X = "'02 付款额与敏感性'!" + RATE_CELL` |
| 盈亏平衡给出 3.19 这种荒谬值 | 基准毛利已低于目标仍强行求解 | 增加 `applicable: False` + 原因 |
| 基准毛利率算出 5.73% 而非 1.87% | `breakeven_rate()` 漏掉非汇率成本 `OC` | 增加 `other_fixed_cny` 参数并并入 `NF` |
| `round(0.5)` 得 0 而非 1 | Python 银行家舍入 | 改用 Decimal + ROUND_HALF_UP |
| 分位 0% | 日期写成文本，`COUNTIFS` 日期比较失效 | 改为 `write_datetime` 真日期类型 |
| 公式单元格全部返回 None | 求值器 `t` 属性分支优先于公式检测 | 把 `f is not None` 判断提前 |
| 目标毛利率显示 500% | 写入 5.0 却按百分比格式显示 | 统一 `/100.0` + `0.0%` 格式 |

> **经验**：改完脚本务必清 `__pycache__`，否则旧字节码会让改动看起来“没生效”。
