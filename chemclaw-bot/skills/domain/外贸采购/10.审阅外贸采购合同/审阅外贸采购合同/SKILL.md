# 审阅外贸采购合同（进口方视角）

> **本 Skill 输出的是商务审查提醒（Business Review Notice），不是法律意见。**
> 它说明「合同写了什么、哪些没写、可能产生什么业务后果、该找谁确认」；
> **不**判断条款是否有效、**不**预测争议结果、**不**替用户决定签不签。
> 条款效力、管辖与适用法律、危化品属性与进口许可要求，一律标注「需法务/EHS/报关行确认」。

---

## 什么时候用

| 场景 | 用 |
|---|---|
| 海外供应商发来英文合同/PI 条款，要我方签署前把关 | ✅ |
| 已签合同，要评估某一条的执行风险 | ✅（缩小范围，只审相关条款） |
| 中英对照合同，要确认中文版是否吃亏 | ✅ |
| 要我方起草对外采购合同 | ⚠️ 可用本 Skill 的清单做自查，但起草不是主打 |
| 要我判断「这场官司能不能赢」 | ❌ 超出边界，请转法务 |

**前提输入**（缺任何一项都要在报告里列为「未取得」）：

1. 合同全文（英文或中英对照）——**必须是原件，不要用摘要**
2. 我方身份（买方/卖方）、标的与规格
3. 已知的商业条件（预算、付款能力、授信、库存计划）
4. 附件与往来文件：形式发票、邮件里的规格书、SDS、COA 模板

## 交付物（四件套）

| # | 交付物 | 文件 | 用途 |
|---|---|---|---|
| 1 | **交互式 HTML 审阅报告** | `外贸采购合同审阅报告-*.html` | 左原文 × 右中文解释/风险/待确认；可筛选、定位、填写负责人与状态、导出 CSV/JSON |
| 2 | **Excel 问题清单** | `外贸采购合同问题清单-*.xlsx` | 9 张表：条款索引、风险总表、原文引用、法规核对、待确认清单、中英对照问题、修改建议、统计 |
| 3 | **中英对照合同** | `模拟合同-*-中英对照.docx` | 用户没有真实合同 PDF 时作为审查对象与示例附件 |
| 4 | **英文澄清函** | `英文澄清函草稿-*.txt` | 逐条向供应商提问与要求修改，可直接作为邮件正文/附件 |

四件套由同一份 `contract.json` + `review.json` 渲染，**HTML / Excel / 函件三处口径必须完全一致**。

## 工作流程

```
0 定边界 → 1 建索引 → 2 提原文 → 3 走 12 项 → 4 追主线
→ 5 核数字 → 6 查法规 → 7 定严重度 → 8 写后果 → 9 列确认
→ 10 出白话(英文) → 11 标负结果 → 12 自检 → 渲染四件套
```

### 第 0 步：定边界（不写进这一步，后面全跑偏）

- 我方是**中国买方/进口商**：办证、清关、缴税、口岸查验、境内运输、中文标签都在我方。
- 标的产品、等级、用途（同一种化学品，纤维级与防冻液级验收指标不同）。
- 贸易术语与**版本**（`CIF Ningbo, Incoterms® 2020`，缺年份与地点就是风险）。
- 合同语言版本与优先文本。
- **已收 / 未收文件清单**（未收的直接影响审查深度，必须写进报告）。

### 第 1–2 步：把合同变成数据

把合同录入 `contract.json`：

```
clauses[] = { id, sec, no, page, page_line, text(逐字原文), zh(中文对照), kind }
sections[] = { id, no, title, page, clause_ids[] }
```

铁律：
- `text` **逐字**，包括错字、大小写、标点错误（错字本身可能就是风险点，如 CAS 写错）。
- **附件逐行拆条**（规格表每行一个 `A1-Tn`），否则缺陷无法定位。
- 每条都要有 `page` + `page_line`，能翻回原件。
- 中文 `zh` 是**我方理解**，不是官方译文，不替代原文。

### 第 3 步：12 项核对（骨架见 `references/01-review-method.md`）

| # | 核对项 | 关键追问 |
|---|---|---|
| 1 | 当事人、品名、CAS、规格/标准 | 签约主体=实际供货主体吗？CAS/EC/HS 对不对？标准有版本年份吗？ |
| 2 | 数量、单位、溢短装、计量依据 | ±X% 谁选？装运港还是目的港计量？短量允差与赔偿？ |
| 3 | 价格、币别、贸易术语、指定地点、版本 | CIF 后面有没有地点？写了 2020 吗？港口费用谁担？ |
| 4 | 预付款/信用证/尾款/节点/单据 | 付款路径是否**唯一**？预付款有担保吗？单据清单穷尽吗？ |
| 5 | 交货期、装运港/目的港、分批、转运 | 交货期起算点系于卖方收款吗？有最迟装船日吗？ |
| 6 | 包装、唛头、SDS、COA、单证 | SDS 什么时候给？中文标签谁做？罐体清洗谁证？ |
| 7 | 第三方检验、异议期、短量、索赔、举证 | 异议期够不够卸货+取样+检测？谁指定机构？COA 终局吗？ |
| 8 | 风险转移、所有权、保险、货损 | **风险≠所有权**；风险绑在「收到提单」上吗？保单被保险人是买方吗？ |
| 9 | 迟延、质量不符、违约、赔偿范围 | 违约金率/上限换算是多少？责任上限是合同额几成？有解约权吗？ |
| 10 | 不可抗力、准据法、仲裁/诉讼、语言 | 不可抗力含商业事由吗？仲裁地/规则/准据法自洽吗？ |
| 11 | 危化品、包装、运输、合规 | 是否属目录？由 EHS 确认；合同把义务错配给买方了吗？ |
| 12 | 原文定位 + 对我方影响 + 待确认事项 | 无原文不立论；无后果不列项 |

### 第 4–5 步：三条主线 + 换算成钱

**主线 A｜付款-单据-交付闭环**：钱出去的每个动作换回什么？（详见 `03-payment-documents-ucp.md`）

**主线 B｜风险-所有权-保险三时点**：CIF 装船时风险转移 / 合同写「收到提单」/ 保单被保险人是卖方——三者不一致时，货损无人赔。（详见 `05-shipping-risk-incoterms.md`）

**主线 C｜责任上限与救济**：上限 ÷ 合同额 = 最坏情况能拿回几成。（详见 `06-breach-liability-force-majeure.md`）

必做的换算（写进报告，比形容词有用）：

```
合同金额 × 日违约金率        = 每天多少钱
上限比例 ÷ 日费率            = 几天触顶
责任上限 ÷ 合同金额          = 能拿回几成
短量允差 × 数量 × 单价       = 短量损失金额
```

### 第 6 步：法规核对（纪律见 `10-regulation-verification.md`）

只核合同真正涉及的对象，每条记录：**全称 + 现行状态 + 核验依据（文号/日期/来源）+ 核对日期**。
查不到就写「未逐条核对」——**绝不补全**。

### 第 7–9 步：严重度、后果、待确认

- 严重度：5 直接锁定付款风险 / 4 显著压缩救济 / 3 失衡可谈判 / 2 表述瑕疵 / 1 提示
- 后果：落到「中国买方 + 进口环节 + 量级」
- 待确认：拆成 **法务 / 采购 / 供应商** 三张清单，一条一个问题

### 第 10 步：英文问题（对外可发）

- **全英文**，不夹中文；条款定位也译成英文（`Clause 8.3, Section 5, p.3`）
- 三档标签：`[AGREEMENT REQUIRED]` / `[AGREEMENT PREFERRED]` / `[INFORMATION]`
- 只问**事实、文件、承诺**，不问法律结论；不写「你必须」
- 附条文原文（可截断加 `[...]`）

### 第 11–12 步：负结果与自检

- `negative_results`：把没被列为风险的条款逐一交代（覆盖率必须 100%）。
- 自检：`python scripts/selfcheck.py`（逐字引用、数字复算、覆盖率）+ 浏览器打开 HTML 看控制台无报错。

## 生成命令

```bash
# 0) 校验数据（引用逐字、法规登记、统计一致）
python scripts/selfcheck.py --dir examples/MEG-saudi-CIF-ningbo-cn-en

# 1) 交互式 HTML
python scripts/build_review_html.py --dir <案例目录> --out <报告.html> \
        --letter <英文澄清函.txt>

# 2) Excel 问题清单
python scripts/build_review_xlsx.py --dir <案例目录> --out <清单.xlsx>

# 3) 中英对照合同（仅模拟合同；--with-tags 标注风险编号，对外勿用）
python scripts/build_contract_docx.py --dir <案例目录> --out <合同.docx> [--with-tags]

# 4) 英文澄清函
python scripts/build_clarification_letter.py --dir <案例目录> --out <函.txt> \
        --date 2026-10-20 --deadline 2026-11-05
```

依赖：Python 3.10+、`openpyxl`、`python-docx`。HTML 为单文件零依赖。

## 质量标准（交付前逐条过）

- [ ] 每条风险都有 **条款ID + 条款编号 + 页码**，引用是原文**连续子串**
- [ ] `kind=缺失` 的条目**没有**编造原文，只说明「全文未见」
- [ ] 所有金额与天数**可从合同数字复算**，并写明口径
- [ ] 法规有**核对日期**与来源；未核对项显式标注
- [ ] 出现「无效/违法/胜诉/属于危险化学品」等法律判断 = 返工
- [ ] 负结果覆盖其余全部条款（覆盖率 100%）
- [ ] HTML：控制台无报错、左右双栏、点风险能定位、筛选计数与 Excel 一致
- [ ] Excel：9 表齐全、状态列有下拉、必需列无空值
- [ ] 三处声明可见：**模拟标识**（若 demo）、**不构成法律意见**、**核对日期**
- [ ] 英文函件 0 个中文字符

## 常见坑（真实踩过）

| 坑 | 后果 | 规避 |
|---|---|---|
| 把 L/C 与「验收后付款」并列当成双保险 | 卖方选 L/C，质量救济落空 | 查付款路径是否唯一 |
| 把「风险转移」和「所有权转移」当一件事 | 货损无人赔 | 三时点分开画 |
| 异议期只看天数不看起算点 | 技术上无法行使 | 对齐「卸货+取样+检测」耗时 |
| 责任上限写「不超过已收预付款」 | 索赔天花板=30% 货值 | 换算成「能拿回几成」 |
| 引用的规格书只在邮件里 | 完整协议条款把它排除了 | 查所有 refer to 是否并入附件 |
| 仲裁地写成机构所在地 | 管辖权先打一架 | 仲裁地/规则/准据法分别核 |
| 把 GHS 毒性当成「危险货物」 | 定性错误 | 三套体系分开，交 EHS 确认 |
| CAS/HS 写错当笔误 | 报关、SDS、COA 全对不上 | 硬标识逐一核对 |

## 最后一句

> 用户拿到 HTML 后，**不读合同原文也能在 10 分钟内说出**：
> 钱什么时候出去、回来靠什么、货不对时能不能停付、出了争议在哪里打；
> 并且知道**每一条该找谁去确认**。
