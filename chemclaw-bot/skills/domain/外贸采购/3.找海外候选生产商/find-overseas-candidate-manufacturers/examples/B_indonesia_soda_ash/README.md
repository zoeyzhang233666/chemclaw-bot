# 案例 B（方法演示）：假设"从印度尼西亚进口纯碱（Na₂CO₃）"

> ⚠️ **本案例仅用于演示"换一个国家、换一个品类"时方法如何迁移**。其中的企业名称是基于公开常识的**示意**，产能、认证、联系方式**未经本次核验**，不得作为真实采购依据。
> 真实执行时必须按 SKILL.md 的六步流程逐家取证，并把本示例的所有数值替换为可回溯来源。

---

## 二、这个方法要怎么"换档"

| 环节 | 沙特 MEG 案例的做法 | 印尼纯碱要改什么 |
|---|---|---|
| 工艺链条反推 | 乙烯 → EO → MEG | 盐/卤水 → 氨碱/联碱，或天然碱矿 → 加工 |
| 关键装置 | 乙烯裂解 + EO/EG | 氨碱装置（石灰窑+氨回收）、联碱装置、煅烧/重灰装置 |
| 候选来源 | 石化集团 affiliates、EPC（EO/EG 承包商） | 盐化工集团、氨碱 EPC（中国工程公司常见）、矿业公司（天然碱） |
| 关键区分点 | MEG vs DEG/PG/聚醚多元醇 | 纯碱 vs 烧碱（NaOH）、小苏打 |
| 特有证据 | 装置级 EO/EG 产能、EO 外售模式 | 卤水/盐矿权、碱厂工艺（氨碱 vs 联碱）、重灰能力 |
| 贸易救济 | 中国对进口 MEG 的相关措施 | 印尼、东盟相关贸易安排，中国对纯碱的进出口管理 |

## 三、演示：一份"正确的、尚未取证"的骨架长什么样

下面这个骨架**故意保持"未核验"状态**，用来演示"没有证据时报告应该长什么样"——这是本 Skill 与"随便列名单"最本质的区别。

| 企业（示意） | 主体性质 | 证据等级 | 判级理由（演示口径） | 下一步 |
|---|---|---|---|---|
| 某盐化工集团（示意） | 合资制造企业 | **B（待核验）** | 行业资料显示其在东爪哇有氨碱装置，但本次未取得官网产品页/产能表/EPC 记录 | 索取装置产品清单 + ISO 证书 + COA |
| 某矿业公司（示意） | 制造企业 | **B（待核验）** | 天然碱矿权公开可查，但未见纯碱成品厂公开资料 | 核实是否加工为成品碱或仅出矿 |
| 某贸易/分销公司（示意） | 一般贸易商 | **D** | 无装置，仅代理 | 若接受贸易商则保留，否则排除 |
| 某烧碱企业（示意） | 制造企业 | **C（近似品）** | 生产 NaOH，非 Na₂CO₃ | 排除，保留为防误判记录 |

> 注意：**没有任何一家被标为 A**——因为本次没有做真实取证。这正是正确状态。

## 四、迁移时必须改的三处代码

1. `case_output.json` 里 `capacity.meg_mtpa` 改为 `capacity.expr`（如 `"1,200 kt/a（重质+轻质合计，待核验）"`）。
2. `meta.product.related_products_excluded` 改为 `["烧碱 NaOH", "小苏打 NaHCO3"]`。
3. `meta.evidence_grade_legend` 保持 A/B/C/D 定义不变（这是通用的）。

`scripts/build_report.py` 与 `build_workbook.py` **无需改动**——它们只读 JSON 契约。

## 五、这个示例想说明什么

1. **方法可迁移**：证据分层、判级、主体分离、产能口径，与产品无关。
2. **"没有 A 级"是合法结果**：如果一家都没取证，报告就该显示"全部待核验"，而不是凑数。
3. **近似品陷阱普遍存在**：MEG↔PG、纯碱↔烧碱、苯酚↔双酚A……每个品类都有自己的"看起来很像"的邻居。
