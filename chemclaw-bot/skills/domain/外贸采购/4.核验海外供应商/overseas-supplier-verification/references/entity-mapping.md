# 主体映射：集团 / 生产 / 交易 / 收款

> 本文解决这一类问题：**"名字都很像，到底谁是谁？"**

---

## 一、为什么必须做主体映射

一笔跨境采购至少涉及 **4 个"谁"**：

| 角色 | 回答什么问题 | 依据文件 |
|---|---|---|
| 合同主体（卖方） | 出现纠纷我告谁？ | PI / 销售合同签署页 |
| 生产主体 | 货从哪个装置出来？ | 工业许可证 / COA / 原产地证 |
| 出口主体 | 谁在提单上发货？ | 提单 B/L 发货人 |
| 收款主体 | 钱付到哪个法人？ | 付款指令 / 银行确认函 |

**这四个角色可以合法地分属四个不同法人**（尤其大型跨国化工）。

**但四个角色能不能对上文件，是另一回事。**

## 二、四层结构模板

```
┌─ 股东层 ──────────────────────────────────────────────┐
│  最终控制人（国有 / 家族 / 上市公众股东）              │
└───────────────────────────────────────────────────────┘
                        │ 持股
┌─ 集团层 ──────────────────────────────────────────────┐
│  集团母公司（往往不直接签合同）                        │
│  · 提供统一产品目录、质量体系、品牌                    │
└───────────────────────────────────────────────────────┘
           │ 全资 / 控股 / 合资                │ 销售协议
┌─ 生产层 ────────────────────┐   ┌─ 交易层 ───────────┐
│  生产公司 A（装置 1）        │   │ 集团销售公司        │
│  生产公司 B（装置 2）        │   │ 区域贸易公司        │
│  合资公司 C（JV）            │   │ 授权经销商          │
└─────────────────────────────┘   └────────────────────┘
                                        │
                                  ┌─ 收款层 ───────────┐
                                  │ 区域资金中心账户    │
                                  │ 关联贸易公司账户    │
                                  └────────────────────┘
```

## 三、逐层取证清单

### 3.1 股东层

| 要确认的 | 证据 | 备注 |
|---|---|---|
| 是否国有控股 | 年报 / 交易所公告 | 影响制裁筛查与政治风险 |
| 是否上市 | 交易所官网发行人名录 | 上市 = 信息披露义务 = 更多可核材料 |
| 最终受益人 | UBO 声明（向供应商索取） | 反洗钱与制裁合规必需 |

### 3.2 集团层

| 要确认的 | 证据 |
|---|---|
| 集团名称与注册号 | 集团财报"公司资料"章节 |
| 产品线覆盖拟采购品 | 集团官网产品页（最好带等级名） |
| 下属公司清单 | 年报"主要子公司"章节 |

> 集团层证据**不能替代**生产层证据。集团有产品 ≠ 这个厂生产。

### 3.3 生产层

| 要确认的 | 证据 | 强度 |
|---|---|---|
| 装置名称 + 地址 | 工业许可证、官网 About | 强 |
| 工业许可证号与产品范围 | 许可证扫描件 | 最强 |
| 装置产能 | 年报、行业数据库（GlobalData/ICIS） | 中 |
| 投产/检修记录 | 交易所公告、行业媒体 | 中 |
| 实际生产批次 | 批号级 COA | 最强（针对本批货） |

### 3.4 交易层

| 要确认的 | 证据 | 强度 |
|---|---|---|
| 合同抬头 | PI / 合同签署页 | 强 |
| 签署人权限 | 签字人姓名 + 职务 + 授权书 | 最强 |
| 发货人 | 提单 B/L | 强（装运后才有） |
| 收款账户 | 付款指令 + 银行确认函 | 最强 |

## 四、六类常见交易结构（以及各自的风险点）

| # | 结构 | 典型场景 | 需要什么 |
|---|---|---|---|
| 1 | 生产商直签直收 | 大厂直销 | CR + 装置证明 + COA |
| 2 | 生产商签约、集团销售公司收款 | 集团资金归集 | **付款授权书 + 银行确认函 + 关系声明** |
| 3 | 集团销售公司签约、工厂发货 | 垄断性渠道 | 生产公司对销售公司授权 + B/L 发货人 |
| 4 | 授权经销商签约 | 区域代理 | 授权书（产品/区域/期限）+ 生产商 COA |
| 5 | 一般贸易商签约、第三方生产 | 贸易撮合 | 货源披露 + 生产商供货确认 + COA |
| 6 | 贸易商签约、第三方收款 | 结构最复杂 | 上述全部 + 强化 KYC |

**结构 2、5、6 不是异常，但都必须用文件把链条连起来。**

## 五、主体一致性矩阵（报告必填表）

| 核对项 | 交易文件所载 | 官方/公开基线 | 判定 |
|---|---|---|---|
| 合同/卖方主体 | PI 抬头 | 官方登记名称 | 名称一致？注册号一致？ |
| 生产主体 | COA 上的生产商 | 工业许可证主体 | 同一法人？ |
| 发货主体 | B/L 发货人 | 卖方或其授权方 | 是否授权？ |
| 收款主体 | 银行信息户名 | 卖方名称 | 是否一致？是否有关联？ |
| 开户地 | 银行所在国 | 卖方注册国 | 是否合理？ |
| 联系邮箱 | 邮件域名 | 官网域名 | 是否同域？ |

## 六、收款主体 ≠ 合同主体：标准处置

### 6.1 先明确一句话（写进报告）

> **收款主体与合同主体不一致，本身不构成欺诈证据；这是必须进一步验证的阻断项。**

### 6.2 三件套（缺一不放款）

1. **付款指令（Payment Instruction）**：卖方公司抬头纸 + 有权签字人签名 + 职务 + 日期
2. **银行确认函（Bank Confirmation Letter）**：收款银行出具，确认账户名/账号/SWIFT
3. **关系声明（Declaration of Relationship）**：说明收款方与卖方的关系（母公司/关联公司/授权收款代理）

### 6.3 回呼验证（关键）

**不要**在本邮件线程里确认账户。改走：
- 官网公布的联系表单 / 官方电话；
- 与你此前独立获得的名片/合同上的号码（非本邮件提供）；
- 必要时要求对方安排视频会议。

### 6.4 高风险形态（需要更强动作）

| 形态 | 说明 | 动作 |
|---|---|---|
| 首次合作即要求第三方收款 | 高 | 优先 L/C，避免 T/T 预付 |
| 「账户变更」通知 | 极高（账户变更欺诈高发） | 双通道验证 + 冻结原流程 |
| 收款方在无关联第三国 | 高 | 要求银行确认函 + 关系声明 |
| 催单 + 限时优惠 + 要求预付 | 高 | 暂停，回到尽调 |

## 七、输出格式（project.json 片段）

```json
"entity_map": [
  { "layer": "集团层", "entity": "Group Parent Ltd", "kind": "group_parent",
    "jurisdiction": "Saudi Arabia", "evidence": "E03", "state": "已核实", "note": "" },
  { "layer": "生产层", "entity": "Manufacturing Co", "kind": "manufacturer",
    "jurisdiction": "Saudi Arabia", "evidence": "E04,E05", "state": "已核实", "note": "" },
  { "layer": "交易层", "entity": "合同卖方", "kind": "contract_party",
    "jurisdiction": "Saudi Arabia", "evidence": "F01", "state": "未核实", "note": "缺 CR 号" },
  { "layer": "交易层", "entity": "收款户名", "kind": "beneficiary",
    "jurisdiction": "UAE", "evidence": "F02", "state": "存在疑点", "note": "与卖方不同，需授权" }
]
```

`kind` 取值：`group_parent` / `manufacturer` / `manufacturer_jv` / `contract_party` / `exporter` / `beneficiary` / `agent` / `distributor` / `trader`
