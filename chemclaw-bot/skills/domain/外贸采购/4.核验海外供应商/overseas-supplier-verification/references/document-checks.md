# 交易文件逐项核对清单

> 覆盖：PI / 注册证书 / 产品认证 / SDS / COA / 形式发票 / 包装单 / 银行信息 / 名片 / 公司介绍
> 每条都给"看什么"与"不合格怎么写"。

---

## 通用核验顺序

```
先看主体 → 再看要素 → 再看一致性 → 最后看真伪痕迹
```

---

## 一、形式发票 / PI（Proforma Invoice）

| # | 检查项 | 合格标准 | 不合格处理 |
|---|---|---|---|
| 1 | 卖方法定全称 | 与注册证书一致 | 要求更正 |
| 2 | 卖方注册号 | 载明 CR/Company No. | 标"未核实"，索取 CR |
| 3 | 卖方注册地址 | 与登记一致 | 标"未知" |
| 4 | 买方名称 | 与合同一致 | 更正 |
| 5 | 品名/规格/等级 | 与本方需求一致，含等级名 | 索取 TDS |
| 6 | 数量/单位 | 明确 MT / kg / L | 更正 |
| 7 | 单价与总价 | 一致，含币种 | 更正 |
| 8 | 贸易术语 | 明确（FOB/CFR/CIF…）且含地点 | 更正 |
| 9 | 装运期 / 装运港 | 明确 | 补充 |
| 10 | 原产国 | 明确 | 补充 |
| 11 | 付款条件 | 明确（T/T、L/C、预付比例） | 讨论 |
| 12 | 有效期 | 明确 | 补充 |
| 13 | 收款账户 | 户名与卖方一致 | 见"三、银行信息" |
| 14 | 签字人 | 姓名 + 职务 + 签名 | 要求补充 |
| 15 | 签章 | 实体章或授权电子签 | 要求补充 |
| 16 | 适用法律/争议解决 | 明确且合理 | 讨论 |

### 高风险信号（不等于欺诈，但要停）

- 100% 预付 + 首次合作
- 缺少 CR 号
- 收款方为第三国第三方
- 只有电子章，无签字人
- "限时优惠、先到先得"式催单
- 卖方名称与官网/注册名有细微差异

## 二、注册证书（CR / Certificate of Registration）

| # | 检查项 |
|---|---|
| 1 | 编号格式符合该国规则（见 `country-registries.md`） |
| 2 | 公司名与 PI 完全一致（含标点/缩写） |
| 3 | 注册地址与合同地址一致 |
| 4 | 状态为"存续/Active" |
| 5 | 签发机关正确 |
| 6 | 签发日期合理（不是"当天刚注册"却称 20 年经验） |
| 7 | 是否含 QR/验证码，能否扫描验证 |
| 8 | 图像是否有拼接痕迹（字体不齐、印章偏移、边缘重影） |
| 9 | 经营范围是否覆盖拟采购品 |
| 10 | 法定代表人/管理者姓名（用于比对签字人） |

---

## 三、银行信息（Bank Details）

| # | 检查项 | 说明 |
|---|---|---|
| 1 | 户名 = 合同卖方？ | 不等 → 三件套（见 entity-mapping.md） |
| 2 | 开户国 = 卖方注册国？ | 不等 → 需解释（资金归集/代理收款） |
| 3 | 是否附银行确认函 | 无 → 不付款 |
| 4 | IBAN/SWIFT 格式正确 | 校验位数 |
| 5 | 账号与 SWIFT 是否匹配国家 | 常见伪造点 |
| 6 | 是否与本邮件线程之外核对过 | 回呼原则 |
| 7 | 是否"账户变更"性质 | 双通道验证 |
| 8 | 是否有中间行信息（必要时） | 影响到账 |

> **绝不**仅凭邮件附件里的账号付款。银行确认函（Bank Confirmation Letter）是标准做法。

## 四、SDS（安全数据表）

| # | 检查项 |
|---|---|
| 1 | 版本号与日期（是否最新，通常 ≤5 年） |
| 2 | 生产商名称与地址（与 COA/官网一致？） |
| 3 | 第 1 节：产品标识（名称、CAS 号） |
| 4 | 第 2 节：危害识别（GHS 分类） |
| 5 | 第 3 节：成分（浓度范围） |
| 6 | 第 7–8 节：操作与防护 |
| 7 | 第 9 节：理化性质（与规格是否自洽） |
| 8 | 第 14 节：运输信息（UN 编号、包装类别） |
| 9 | 语言/法规版本是否符合目的国要求 |
| 10 | 是否被修改过（对比官方公开版本） |

**MEG 常见参照**：CAS 107-21-1；UN 3082（环境有害液体，III 类包装）。

## 五、COA（分析证书）

| # | 检查项 | 不合格含义 |
|---|---|---|
| 1 | 生产商抬头 | 无抬头 → 无法绑定生产主体 |
| 2 | 批号 | 无批号 → 无法追溯 |
| 3 | 生产日期/检测日期 | 缺失 → 可能是旧批或模板件 |
| 4 | 检测项目 = 合同规格项 | 缺项 → 规格未闭合 |
| 5 | 实测值 vs 规格限值 | 必须有对应 |
| 6 | 检测方法（ASTM/ISO/GB） | 无方法 → 结果不可比 |
| 7 | 检测机构（自检/Lab第三方） | 第三方更有力 |
| 8 | 批号与装箱单/提单是否一致 | 不一致 → 存在疑点 |

### 典型缺项（化工品）

纯度（Purity）、水分（Water）、二甘醇（DEG）、色度（APHA/Hazen）、紫外透光率（UV transmittance @275/350nm）、酸度。

### 规格表的写法建议

```
| 项目 | 规格 | 实测 | 方法 |
|---|---|---|---|
| 纯度 | ≥99.9 % | 99.93 % | GC |
| 水分 | ≤0.10 % | 0.04 % | ASTM E1064 |
| DEG | ≤0.08 % | 0.03 % | GC |
| 色度 | ≤10 APHA | 5 | ASTM D1209 |
```

## 六、产品认证（ISO / REACH / Halal / Kosher 等）

| # | 检查项 |
|---|---|
| 1 | 证书编号 + 认证机构名称 |
| 2 | 覆盖范围（是否含该产品/该厂） |
| 3 | 有效期 |
| 4 | 持证主体（是否即卖方或生产商） |
| 5 | 能否在认证机构官网查到 |
| 6 | REACH：是否有唯一代表（OR）、注册号 |

**注意**：ISO 证书"持有"不等于"产品认证"，很多贸易商持有 ISO 但不生产。

## 七、产品目录 / 公司介绍

| 类型 | 判断 |
|---|---|
| 宣传语（world-class / leading / 20 years） | 不算证据 |
| 有具体数字但无标识符（capacity 1.2 MT/yr） | 仅作线索 → 「未核实」 |
| 有等级名 + 规格表 | 可进入「未核实（待TDS）→ 已核实」 |
| 有装置名 + 许可证号 + 产能表 | 强证据 |

## 十、模拟件（Simulated Documents）纪律

本 Skill 允许制作**明确标注为模拟**的 PI / 银行信息 / 名片 / 介绍 / 目录，用于演示一致性检查。规则：

1. 文件头必须有醒目声明："模拟文件 / SIMULATED — 非真实"
2. 价格、账号、人名一律用占位符（000.00 / XXX / [Name]）
3. 报告与 Excel 中必须以 `mock` 分级出现，**绝不**进入"已核实"行
4. 报告中写明："本演示中的报价单与银行信息均为模拟件，不代表任何真实企业曾向我方报价或提供文件"
5. 不得把模拟件当作对真实企业的指控材料传播
