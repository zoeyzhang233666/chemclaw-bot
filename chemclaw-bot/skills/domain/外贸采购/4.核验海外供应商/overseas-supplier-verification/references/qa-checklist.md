# 交付前自检清单（QA Checklist）

> 每次交付前逐条过。**任何一条打不开勾，就不要发出去。**

---

## A. 结论纪律（最容易被违反）

- [ ] 报告里**没有**任何风险分数、信用评分、"综合评分"数字
- [ ] 报告里**没有**"低风险/中风险/高风险"标签
- [ ] 没有把"未检索到负面信息"写成"无风险"
- [ ] 没有根据官网宣传认定真实产能 / 资金实力 / 履约能力
- [ ] 收款主体 ≠ 合同主体处，写的是"需进一步验证"，**没有**写"欺诈/骗子"
- [ ] 总体结论使用了四选一（仅识别身份 / 可推进但需补证 / 暂停推进 / 证据不足）
- [ ] "本报告不下的结论"一节有内容

## B. 证据可追溯

- [ ] 每条结论都能点到证据编号
- [ ] 每条证据都有：来源、发布时间、访问时间、**逐字原文摘录**、用途
- [ ] 「已核实」项 = 官方来源 或 ≥2 个独立来源
- [ ] 没有用单一二手来源直接判"已核实"
- [ ] 三手来源（百科/名录）只作线索
- [ ] 证据超过 3 年的，已提示需刷新

## C. 主体一致性

- [ ] 报告开头先做了主体映射（集团/生产/交易/收款四层）
- [ ] 区分了「合同主体」「生产主体」「出口主体」「收款主体」
- [ ] 没有因名称相似而把不同法人混为一谈
- [ ] 主体一致性矩阵（matrix_map）齐全，每行有状态与证据
- [ ] 收款不一致给出了三件套动作（授权书 + 银行确认函 + 关系声明 + 回呼）

## D. 制造能力

- [ ] 明确了供应商属于哪类（制造商 / 集团销售公司 / 经销商 / 贸易商）
- [ ] 产能数字注明了口径（综合体 / 装置 / 可供量）
- [ ] 「本批次可用量」没有被当成公开信息可用（默认应为"未知"）
- [ ] 工厂证据没有使用通用图库照片

## E. 联系与官网

- [ ] 比对过官网域名 vs 邮件域名（近似域规则）
- [ ] 免费邮箱 / 仅手机 已标记
- [ ] 地址能够对到注册地址或说明差异

## F. 文件核验

- [ ] 每份文件都有逐项 ✓/✕
- [ ] 缺失文件进了补件清单
- [ ] **模拟件全部标注"模拟"**，且没有被当作事实
- [ ] 报告中写明"模拟件不代表真实企业曾报价或提供文件"

## G. 输出完整性

- [ ] HTML 报告 7 个区块齐全：企业身份 / 产品能力 / 工厂与生产证据 / 官网与联系信息 / 交易主体一致性 / 公开风险 / 待索取材料
- [ ] 证据索引可点开查看原文
- [ ] 状态筛选可用（已核实 / 存在疑点 / 未核实 / 未知）
- [ ] Excel 8 个工作表齐全
- [ ] 英文询证清单 ≥14 条，覆盖 主体/收款/工厂/产品/文件/合规
- [ ] 报告有编号、基准日、编制人、复核人

## H. 机器校验

```bash
python scripts/validate.py project.json --strict   # 必须 0 阻断、0 警告
```

## 常见返工点

| 现象 | 根因 | 修法 |
|---|---|---|
| validate 报 F03 | 表格行标了"已核实"但证据列写了 `—` | 补证据，或降级为「未核实」 |
| validate 报 F05 | 已核实行引用了 F0x 模拟件 | 换成真实来源，或把状态降级 |
| validate 报 F06 | JSON 里有 `score`/`rating` 字段 | 删除 |
| validate 报 F08 | 有「未知」但 gaps 为空 | 为每个未知写 gap |
| validate 报 W05 | 有 PI 但没 matrix_map | 补一致性矩阵 |
| HTML 表格列错位 | `rows` 列数 ≠ `columns` 列数 | 数一遍 |
| HTML 出现"未知"胶囊在错误列 | 该表没有状态列却按位置推断 | 检查该表是否应为 4 列还是去掉状态列 |
| Excel 打不开 | openpyxl 缺失 | `pip install openpyxl` |
| 中文乱码 | 控制台编码 | `set PYTHONIOENCODING=utf-8` |

## 交付前最后一句话

把报告给同事看一遍，只问一个问题：

> **"如果我照着这份报告去付款，我最可能栽在哪？"**

如果报告能直接回答这个问题（而不是给一个分数），它就过关了。
