# 七步法详版（含判断分支）

本文是 `SKILL.md` §2 的展开。**任何步骤的判断，都以「能不能挂上可追溯证据」为唯一标准。**

---

## 步骤 0：固定输入

开查之前，把这几件事写下来，否则后面全是空转：

| 输入 | 为什么必须 |
|---|---|
| 拟采购品 + 规格/等级 | 决定"产品匹配"怎么判 |
| 数量 + 贸易术语 + 目的港 | 决定"供货能力"要不要专门查 |
| 供应商自报名称（中英）+ 国家 | 决定查哪个登记系统 |
| 已提交文件清单 | 决定文件核验范围 |
| 核验基准日 | 全文唯一时间基准，之后变化要重查 |

把基准日写进报告页脚。**没有基准日的核验报告是不可复核的。**

## 步骤 1：识别主体（四层）

### 1.1 为什么必须先做

典型错误顺序：先搜"这家公司怎么样"→ 看到官网很漂亮 → 认定是大厂 → 再看 PI。
**正确顺序**：先确定"哪几个法人参与这笔交易"，再逐个查。

### 1.2 四层拆解

```
股东层    ← 谁最终控制？（国有/民营/上市/家族）
  │
集团层    ← 属于哪个集团？集团有哪些产品线？
  │
生产层    ← 哪家法人真正生产？装置在哪？
  │
交易层    ← 谁签合同 / 谁发货 / 谁收款？（可以三个都是不同法人）
```

### 1.3 常见陷阱（真实发生过的高频错误）

| 陷阱 | 表现 | 正确做法 |
|---|---|---|
| 把集团当法人 | "SABIC 卖 MEG，所以 SABIC 是卖方" | 集团 ≠ 合同主体；要问"合同抬头写哪家" |
| 把子公司当母公司 | "ABC Petrochemical 是 ABC Group 的分公司" | 查是否为独立法人（很多 JV 是独立公司） |
| 同集团不同装置混用 | 把 A 厂产能当成 B 厂产能 | 产能必须落到"装置 + 地址 + 许可证" |
| 名称高度相似 | ABC Chemical 与 ABC Chemicals 是两家 | 用注册号而不是名称识别 |
| 交易主体≠生产主体 | 贸易公司签、工厂发货 | 正常业务，但必须看授权链 |
| 收款主体是第三国 | 沙特卖方、阿联酋收款 | 正常也可能，但必须验证（见 matrix） |

### 1.4 判定分支

- 供应商明确是**集团销售公司** → 要集团股权/隶属证明 + 生产公司对销售公司的授权。
- 供应商是**授权经销商** → 要授权书（产品、区域、期限、授权方签章）。
- 供应商是**一般贸易商** → 不视为缺陷，但必须披露真实货源与生产商 COA。
- 供应商**说不清自己是谁** → 直接进「暂停推进」。

> 输出：`entity_map` 表（层级 / 角色 / 主体 / 注册地 / 状态 / 证据）

## 步骤 2：查注册与身份

### 2.1 查什么（7 要素）

1. 法定全称（本地语言 + 拉丁转写）
2. 注册号（各国叫法不同，见 `country-registries.md`）
3. 注册地址（街道级）
4. 法人形式（LLC / JSC / GmbH / Pvt Ltd …）
5. 存续状态（在业 / 注销 / 吊销）
6. 经营范围（是否覆盖拟采购品）
7. 注册资本 / 成立日期（如可得）

### 2.2 检索顺序（优先级从高到低）

1. **官方登记系统**（商工部/公司注册处/税务局）→ 一手
2. **上市公司监管披露**（年报、交易所公告）→ 一手
3. **企业官网**（若披露注册号与地址，且可被第三方复核）→ 一手
4. **行业数据库 / 协会名录** → 二手
5. **财经媒体 / 行业媒体** → 二手
6. **百科 / 黄页 / B2B 平台** → 三手，只作线索

### 2.3 官方系统打不开怎么办

标注为「未知」并**记录原因**（如「本次网络环境下 mc.gov.sa 直连失败」）。
**不要**用第三方名录替代官方登记，也不要在报告里写成"已核实"。
做三件事：
- 在报告里写清检索了哪些渠道、什么时间；
- 在补件清单里要求**供应商提供官方登记证书扫描件**（原件通常可直接可见 QR/查询码）；
- 在有条件时（换网络环境、委托当地代理），完成官方系统核验并更新报告。

### 2.4 注册号"长什么样"（防伪造）

先用已知真实样本建立参照，再比对供应商提供的号码：

| 国家 | 常见格式 | 参照来源 |
|---|---|---|
| 沙特 | 10 位数字，前 2 位对地区（10xx 利雅得、2055 朱拜勒一带） | 上市公司官网披露 |
| 阿联酋（迪拜） | 7 位数字（License No.） | 官方门户 |
| 印度 | 21 位字母数字（CIN）/ 15 位 GSTIN | MCA / GST 门户 |
| 德国 | HRB + 数字 | Handelsregister |
| 英国 | 8 位数字 | Companies House |

> 号码位数/前缀明显不符 → 「存在疑点」，要求重提供。

## 步骤 3：查产品匹配

### 3.1 三层匹配

| 层 | 问题 | 证据 |
|---|---|---|
| 品类 | 集团/公司产品线有没有这个产品？ | 官网产品页 |
| 等级 | 有没有我方要求的等级/牌号？ | 产品页等级列表 / TDS |
| 交付 | 包装、运输形态（散装/ISO tank/桶）是否支持？ | TDS / 装箱单 |

### 3.2 常见"看起来匹配、实际不匹配"

- 官网说"ethylene glycols"，但你买的是 **MEG（单乙二醇）**，对方主力是 DEG/TEG；
- 官网列了等级，但目录里写的是通用"Fiber Grade"，无法对应批号；
- 集团有产品，但**这个国家的这个装置不生产**（集团在全球有同类装置）；
- 应用场景不符（工业级 vs 纤维级 vs 高纯级）。

### 3.3 判定

- 品类匹配 + 等级明确 + TDS 到手 → 「已核实」
- 品类匹配 + 等级不明 → 「未核实」，索取 TDS
- 品类不匹配 → 「存在疑点」或直接排除

## 步骤 4：查制造关系

### 4.1 核心问题

> **不是**「它是不是大公司」，而是 **「这批货是不是它生产的、能不能证明」**。

### 4.2 四类身份与取证

| 身份 | 必备证据 | 缺证的后果 |
|---|---|---|
| 实际制造商 | 装置名 + 工业许可证 + 产能表 + 批号级 COA | 无法证明货从哪来 |
| 集团销售公司 | 集团股权证明 + 生产公司授权 | 无法证明它有权卖 |
| 授权经销商 | 授权书（产品/区域/期限）+ 生产商 COA | 可能卖的是二手货/掺混货 |
| 一般贸易商 | 真实货源披露 + 生产商供货确认 | 来源不明，质量与索赔难追 |

### 4.3 产能数字的三种口径（极易混淆）

| 口径 | 含义 | 能否当"可供量" |
|---|---|---|
| 综合体总产能 | 整个工业园所有产品合计 | ✗ 不能 |
| 装置产能 | 单套装置单产品 | 只能当上限参考 |
| 分配给我方的量 | 合同约定 / 装运计划 | ✓ 这才是真正能交的量 |

**公开信息几乎永远只能拿到前两种。** 第三种只能靠 PI + 装运计划 + 舱位确认。

### 4.4 制造关系的证据强度排序

1. 工业许可证（含产品范围）+ 装置编号
2. 上市公司年报/公告提及其装置与投料时间
3. 行业数据库列示其装置与产能（GlobalData/ICIS 等）
4. 行业媒体记录其投产/检修事件
5. 官网"我们有工厂"的表述 ← **不算证据**

## 步骤 5：查官网与联系一致性

### 5.1 比对矩阵

| 项 | 官网 | 邮件域名 | 名片 | 是否一致 |
|---|---|---|---|---|
| 域名 | sabic.com | @sabic.com | @sabic.com | ✓ |
| 域名（反例） | sabic.com | **@petrokemya-sabic.com** | 同上 | ✗ |

### 5.2 近似域识别（必查）

- 加连字符：`abc-group.com` vs `abcgroup.com`
- 换 TLD：`abc.com.sa` vs `abc.com` / `abc.net`
- 免费邮箱：`abc@example.com` / `abc@mail.example.com` / `abc@example.cn`
- 同形字符：`rn`→`m`、`l`→`I`、`0`→`O`
- 多一层子域：`abc.secure-mail.com`

### 5.3 电话与地址

- 区号是否与注册城市一致（如 +966 13 = 沙特东部省）
- 是否只有手机号（大企业通常公开固定电话）
- 地址能否在地图上定位到工业区/街道

### 5.4 处置

落入任一近似域 → **不回复、不付款、不签**，改由官网公布渠道（联系表单/官网电话）回呼确认。
在确认前，该邮箱发来的"账户变更""紧急发货""限时优惠"一律不采信。

## 步骤 6：查公开风险

**只列查得到的事实，不评级。** 详细检索法见 `risk-screening.md`。

| 维度 | 查什么 | 常见来源 |
|---|---|---|
| 制裁/管制 | OFAC SDN、EU 综合名单、UN 1267、BIS 实体清单 | 官方名单库 |
| 司法 | 诉讼、仲裁、破产、被执行 | 法院公告、RegTech 平台 |
| 行政 | 处罚、吊销、环保违规 | 监管机构公告 |
| 供应 | 不可抗力、停产、检修、事故 | 行业媒体、交易所公告 |
| 贸易救济 | 反倾销/反补贴/反规避 | 商务部/欧委会公告、WTO |
| 负面报道 | 欺诈、伪造单据、劳资纠纷 | 调查报道、行业媒体 |

### 输出纪律

- 「未检索到」写成「未检索到」，**不写「无风险」**；
- 制裁筛查必须写清**用的什么名字、什么号、什么时间**；
- 没有精确标识符做不了筛查 → 写「未知」，并把它列进补件清单。

## 步骤 7：文件比对 + 询证单

逐件核对（详见 `document-checks.md`），然后：

1. 把每个 ✕ 变成一条补件动作（Gap Register：缺口/影响/动作/责任人/优先级）；
2. 生成英文询证清单（`rfi-standard.md`），要求对方**公司抬头纸 + 有权签字人**回函；
3. 明确"补到什么程度可以推进"。

## 判断分支总览

```
官方登记可查 + 产品匹配 + 制造可证 + 收款一致
        └─→ 可推进（仍需按合同条款约束）

官方登记可查 + 制造关系不清
        └─→ 未核实：要工业许可证/装置编号/生产商COA

无官方登记 + 无制造证据 + 近似域邮箱
        └─→ 暂停推进（HOLD）

收款主体 ≠ 合同主体
        └─→ 阻断付款，补三件套（授权书+银行确认函+关系声明+回呼）
            ※ 不因差异认定欺诈

什么都查不到
        └─→ 证据不足：换候选或要求先提供线下可验证材料
```
