# 进口资料准备与合规核验（chem-import-dossier）

## 这个技能解决什么

进口一批化学品，**在报关之前**要回答的问题：

1. 这东西**是什么**（身份），海关该按**哪个编码**收税（归类）；
2. 现在**管不管**、管到什么程度（监管条件、许可、检验）；
3. 要交**多少钱**（关税、增值税、有无优惠）；
4. 运输时算不算**危险货物**（和「危险化学品」是两件事）；
5. 包装和标签要**改成什么样**；
6. 手上这些文件**够不够**，还差什么，**找谁要**；
7. 哪些话我现在**不能**说，必须找人确认。

输出物：**一份 HTML 底稿（可交互、可打印）+ 一份 Excel 工作簿（可销项、可算税）+ 一份英文索取清单**。

## 硬纪律（违反即不合格）

| # | 纪律 | 落地方式 |
|---|---|---|
| 1 | **每条结论必须有来源 + 适用条件 + 查询日期** | `sources[]` 里每条带 `accessed`；监管项与 HS 候选必须写 `source` |
| 2 | **不得把通则套到所有化学品上** | 用四态判定（适用/视条件适用/待核验/不适用）；「不适用」必须有排除条款 |
| 3 | **不得仅凭商品名判定** | 必须落到 CAS + 浓度 + 组成 + 形态 + 用途 + 包装 + 运输方式 |
| 4 | **「不知道」不等于「不适用」** | 三值逻辑：True/False/None，None 只能输出「待核验」 |
| 5 | **危险化学品 ≠ 危险货物** | 两套体系分别判定、分别写后果，见 `references/dangerous-goods-vs-hazchem.md` |
| 6 | **不确定的必须显式标记** | 每项待确认都要写「谁确认 / 怎么核实 / 判断错的代价」 |
| 7 | **不许承诺** | 禁用：保证通关、100% 合规、绝对、肯定、没问题 |
| 8 | **换产品只改数据，不改脚本** | 所有结论放在 `data.json`，脚本保持产品无关 |

---

## 输入要求

至少需要这七项，缺项就先问，不要猜：

```
来源国家 | 产品名称(中/英) + CAS + 浓度/组成 | 用途 | 包装 | 运输方式
（加分项：供应商、数量、贸易术语、起运/目的港、执行标准、拟到货日期）
```

若用户只给了商品名（如「双氧水」），必须先追问**浓度与组成**——同一商品名在不同浓度下结论完全不同。

## 流程 P0–P8

### P0 · 建立底稿与时间基准

- 确定 `as_of`（本次核验的基准日），**所有时效判断相对此日**，不使用「今天」。
- 复制 `templates/data.template.json` 为新的 `data.json`。
- 记住 `meta.product_scope_note`：把本底稿绑定的产品要素写进去。后面任何结论只对这组要素成立。

### P1 · 产品身份确认

逐项锁定并在 `product_identity.confirmed / unconfirmed` 中分开记录：

- 中英文品名、CAS、**浓度（质量分数还是体积分数）**、完整组成（**稳定剂/添加剂必须逐个列出名称+CAS+百分比**）、物态（是否水溶液）、等级、执行标准、用途（越具体越好）、包装（容器材质与规格）、运输方式、数量、贸易术语。

**判定身份状态**：
- 全部已证实 → `confirmed`
- 有任一项依赖供应商口头或未提供 → `partial`（绝大多数情况）
- 关键事实全缺 → `pending`

**必须写 `risk_points`**：每个未确认要素都要说清「为什么是风险 + 怎么补」。

> 为什么组成要细到稳定剂：危险化学品目录中「溶液」条目的适用前提是「仅含稳定剂/惰性化学品」。缺这一项，结论只能停在「视条件适用」。

### P2 · HS 编码候选与归类

按 `references/hs-classification.md` 的六步法：

1. 按**报验状态**确定商品实际构成（不是按用途）；
2. 找**章注 / 子目注释**（优先级高于品目条文）；
3. 读**品目条文**（有列名不走兜底）；
4. 走子目与八位/十位，并核对 **CIQ 扩展码**；
5. 写**成立条件**（可被第三方验证）；
6. 写**推翻路径**（不成立时去哪）。

输出至少 2 个候选（含备选/兜底），每个带 `confidence`（高/中/低）。`hs_verdict.uncertainty` 必填。

### P3 · 监管与许可逐项比对

按 `references/regulation-map.md` 依次比对，**每一项都要写 case**：

```
危险化学品（目录哪一项、含量条件、添加剂条件）
易制爆（是否列入、哪一档、购买与报备义务）
危险货物（运输分类，见 P4）
检验检疫（是否在 129 号公告范围、报关填什么、随附什么）
两用物项（当年目录比对结论）
包装容器（UN 包装证明、国内包装生产许可适用性）
新化学物质（是否现有化学物质）
储存安全（重大危险源辨识）
经营许可（自用 vs 转售）
用途专项（食品/消毒/药品/涉军）
```

每项输出：`verdict / conclusion / basis / condition / impact / owner / source / confidence`。

### P4 · 危险货物与危险化学品分开判定

按 `references/dangerous-goods-vs-hazchem.md` 的模板填 `danger_distinction`：

- `chemical`：目录条目、阈值、后果
- `goods`：UN 编号、类项、次要危险、包装类别、正确运输名称、阈值、后果
- `matrix`：**至少 3 行**，覆盖阈值两侧（低于/区间内/高于/配方型）
- `common_errors`：本产品最易犯的混淆

再填 `transport`：IMDG/GB 规则、类项标志、包装指令、隔离与积载、EmS、运输方式限制。

> 铁律：GHS 的「类别 1/2/3」与运输的「包装类别 I/II/III」是两套分档，**不得互抄**。

### P5 · 包装与标签

- 中文危险公示标签（GB 15258 + GB 30000.1）：品名、**成分及含量**、象形图、信号词、H 码、P 码、供应商信息、**24 小时中文应急电话**、进口产品境内责任人。
- 运输标志：UN 编号 + 正确运输名称 + 类项标志 + **包装 UN 标记**。
- 包装：UN 认证、材质相容性、排气设计、单件净重合规。
- 逐条列出上传标签存在的问题与整改动作。

> H/P 码写「建议口径」，须由供应商按 GB 30000 分项确认，不得照抄他国标签。

### P6 · 单证清单与已上传文件核查

按 `references/document-matrix.md` 建 `documents[]`，分四层：
`海外供应商资料 / 中文合规文件 / 进口报关资料 / 运输与到货资料`。

每份文件写：`required`（必须/视情形/建议）、`basis`、`content_check`（必备字段）、`status`（六态）、`issue`、`owner`、`source`。

对每份**已上传文件**（`uploaded[]`）做三件事：

1. **字段提取**：`field / value / page_ref` —— 必须写清来自哪一节，否则不可复核；
2. **要件核对**：`item / result（pass/fail/warn/na）/ note`；
3. **结论**：`usable / usable_with_fix / not_usable` + 一句话理由。

然后做**交叉一致性检查**（CAS、浓度、运输信息、贸易术语、包装规格、语言合规、版本时效），每处不一致单独成条。

> 模拟件必须显式标注（`is_mock: true` + `mock_note` + 文件名带「模拟」）。

### P7 · 缺口、责任与待确认

**`gaps[]`**（按 `references/request-list-method.md`）：
- P0 = 不取得不得报关/不得使用；P1 = 影响税费时效质量；P2 = 档案完善。
- 每条必须写：`why`（为什么必须）、`ask`（怎么要）、`owner`、`related_doc`、`blocking`。

**`responsibilities[]`**：四类主体分开写（海外供应商 / 进口商 / 承运人 / 报关代理），可加第三方检测机构与监管机构。

**`to_confirm[]`**：五字段齐全（`topic / why / who / how / impact_if_wrong`）+ `severity`。
「谁确认」必须是具体主体，不能写「相关人员」。

### P8 · 渲染与交付

```bash
python scripts/validate.py examples/<case>/data.json          # 硬纪律校验，必须 0 FAIL
python scripts/render_html.py examples/<case>/data.json -o examples/<case>/report.html
python scripts/render_xlsx.py examples/<case>/data.json -o examples/<case>/dossier.xlsx
python scripts/check_outputs.py examples/<case>/report.html examples/<case>/dossier.xlsx
```

或一键：`python scripts/build_all.py examples/<case>/data.json`

## 交付物规格

### HTML（单文件，离线可开）

区块顺序（16 节）：

```
00 报头与结论          01 放行闸门
02 产品与归类          03 HS 编码候选      04 税费与优惠
05 监管与许可          06 危险属性双轨
07 包装与标签          08 单证清单         09 已上传文件检查
10 缺失资料            11 责任划分         12 待确认事项
13 时间线              14 英文索取清单     15 法规来源
```

交互：来源抽屉（点 `S01` 看原文与查询日期）、表格筛选与搜索、缺口勾选（localStorage 保存）、导出英文清单、打印。

### Excel（12+ 表）

```
00 封面与结论  01 产品属性   02 HS候选     03 法规依据
04 单证要求    05 已上传文件 06 缺失资料   07 责任主体
08 待确认事项  09 危险属性对照 10 税费测算  11 进度看板  12 法规来源
```

必须含：状态下拉、缺口勾选（☑/☐）、实时公式（完备度、税额、情景对比、跨表统计）、条件格式。

### 英文索取清单

```
title / intro / items[{no, doc, detail, due}] / closing
```

按 P0→P1→P2 排序，紧急项标 URGENT，`detail` 写到可验收粒度。

## 跨品类复用

**不要改脚本。** 换产品的正确姿势：

```bash
cp templates/data.template.json  examples/<新案例>/data.json
# 编辑 data.json：inputs / 组成 / HS 候选 / 监管项 / 危险属性 / 单证 / 缺口 / 待确认 / sources
python scripts/build_all.py examples/<新案例>/data.json
```

校验器会在以下情况报错，确保不会「填错还过审」：

- 监管清单缺「危险化学品 / 运输 / 检验检疫 / 用途专项」任一层
- 危险化学品与危险货物被写成同一套体系
- 单证清单里没有任何中文文件
- 缺 `basis` 或 `source`
- 结论只有 C 级来源支撑
- 出现禁用表述
- 税额试算不自洽
- 单证状态取值非法、上传件引用不存在

## 边界（明确不做的事）

| 不做 | 改做什么 |
|---|---|
| 替用户做最终归类决定 | 给候选 + 依据 + 置信度，建议报关行复核或申请预裁定 |
| 替用户判断是否需办许可证 | 给比对方法 + 指出必须书面确认（待确认事项 Q0x） |
| 承诺通关或合规 | 给「按现有资料可满足哪些要求」+ 残余风险 |
| 出具法律意见 | 标为「准备性核验，不构成法律意见」 |
| 虚构法规条文 | 找不到就标「待核验」并写明去哪查 |
| 用第三方税率直接算成本 | 标注 `disputed` 并放进待确认事项 |

## 常见失败模式

| 症状 | 根因 | 修法 |
|---|---|---|
| 报告通篇「适用/不适用」 | 缺三值逻辑 | 凡是依赖未知事实的，改「视条件适用」或「待核验」 |
| 危险属性只写了一段 | 把两套体系合并 | 分别填 `chemical` 与 `goods`，各自写后果 |
| 单证清单只有英文件 | 忘了中国法定中文文件 | 必须有「中文合规文件」分组 |
| 分级永远是 D | 把「不完整」当「缺失」 | partial → pending，只有 missing/expired 才 fail |
| 待确认事项写「需进一步核实」 | 没落到主体 | 写谁、怎么核、判错的代价 |
| 换产品后脚本报错 | 直接改脚本 | 回 `data.json` 改，脚本保持产品无关 |
| 报告看起来对但没法复核 | 缺 `page_ref` / `source` | 每个字段标注出自哪一节、每条结论挂来源编号 |
