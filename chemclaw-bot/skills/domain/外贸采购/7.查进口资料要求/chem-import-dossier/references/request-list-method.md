# references/request-list-method.md — 缺口的「要法」与英文索取清单

> 找到缺口只是第一步。**把缺口变成一条供应商能立刻照做的请求**，才叫可执行。

---

## 1. 缺口的分级

| 级别 | 定义 | 后果 | 处理时点 |
|---|---|---|---|
| **P0** | 不取得不得报关 / 不得合法使用 | 阻断 | 发货前必须闭环 |
| **P1** | 影响税费、时效或质量 | 损失金钱或时间 | 到货前闭环 |
| **P2** | 档案完善、可追溯 | 无即时后果 | 归档前补齐 |

**判断 P0 的三个问句**：
1. 没有这份文件，海关会不会拒单/查验不过？
2. 没有这份文件，货物到厂后能不能合法储存/使用/转售？
3. 没有这份文件，包装或运输是否无法合规？

任一为「是」→ P0。

---

## 2. 一条合格请求的四个要素

```
① 要什么（文件名 + 版本要求）
② 里面必须有什么（可逐条验收的内容清单）
③ 什么时候要（相对时点 + 绝对时限）
④ 为什么要（引用法规/合同条款，让对方知道这不是随意加码）
```

**反例**：「请提供 SDS。」——供应商会回一份旧的、或只给英文的。

**正例**：
> Please provide the Safety Data Sheet (English) in 16 sections, **with version number and revision date**.
> Section 3 must give the exact chemical name, CAS number and percentage of every stabiliser.
> Section 14 must state UN number, class, subsidiary risk, packing group and marine pollutant status.
> Timing: URGENT — within 3 working days.

## 3. 按缺口类型给标准「要法」

| 缺口类型 | 标准句式（中） | 关键点 |
|---|---|---|
| SDS 缺版本/要素 | 「请提供带版本号与修订日期的 SDS，第 3 节需给出每个稳定剂的名称、CAS 与精确百分比，第 14 节需与 UN 编号/类项/包装类别一致」 | 必须指定**节号** |
| 缺稳定剂声明 | 「请出具书面声明：本产品除稳定剂/惰性物质外不含其他功能性添加剂，并附稳定剂清单（名称+CAS+精确添加量）」 | 「书面」+「签署」 |
| 缺中文文件 | 「中文 SDS 与中文标签由我方制作，但**分类、H/P 码、应急电话**需贵方确认并签字」 | 翻译不是免责 |
| 缺包装证明 | 「请提供 UN 包装性能检验证书，以及桶体 UN 标记清晰照片（含包装代码、包装类别字母、生产年份、制造厂代号）」 | 照片要能看清标记 |
| PI 不一致 | 「请重出 PI：统一贸易术语为 FOB（或 CIF 并拆分运保费），补列 HS 编码、装运港、目的港、原产国」 | 指出**具体哪几处**矛盾 |
| 缺 COA 项 | 「请在 COA 中增列 Fe、氯化物、TOC 检测项，并注明检测方法编号」 | 说清下游用途 |
| 缺原产地证 | 「请确认能否出具中国—韩国 FTA 原产地证书；若可，请确认货物自釜山直航上海」 | 同时确认直接运输 |
| 缺危险货物申报 | 「请提供 IMDG 危险货物申报单（DGD）与船公司 DG 订舱确认，注明 UN、类项、PG、件数、毛净重、24 小时应急电话」 | 与 SDS 第 14 节勾稽 |

## 4. 英文清单的组织

生成英文索取清单时：

1. **按 P0 → P1 → P2 排序**，紧急项标 `URGENT`；
2. 每条含 `no / doc / detail / due` 四个字段；
3. `detail` 要写到「可验收」的粒度（节号、字段名、证书号）；
4. 结尾写清**联系人、参考号（PO/合同号）**；
5. 附一句说明法规背景（让对方理解为什么突然要这么多），但**不要**长篇大论；
6. 不要承诺「给了就能通关」；
7. 不要在清单里夹带商务谈判内容（价格、罚则）。

---

## 5. 模板骨架

```
Documentation Request — <product + UN no.> Import into P.R. China — Ref. <PO>

Dear Sir or Madam,

<2–3 句：我们在做什么、依据哪条法规、为什么需要这些文件。>

1. <Document>                      [URGENT — within 3 working days]
   Detail : <必须包含的内容，逐项列>
2. ...

Please send all items to <email> referencing <PO>.
<一句：技术内容必须由贵方确认，我方只负责中文翻译。>
```

---

## 6. 发出之后要做的三件事

1. **登记回执**：谁在什么时候给了什么版本 → 记到「已上传文件」表；
2. **复核一致性**：新到的文件是否与既有文件冲突（CAS/浓度/贸易术语/运输信息）；
3. **销项**：缺口勾掉，同时更新单证状态，让分级自动变化。

> 缺口清单不是一次性的。每轮补件后重跑校验，分级应当**变好**——如果一直不动，
> 说明有人在填表，没人在解决问题。
