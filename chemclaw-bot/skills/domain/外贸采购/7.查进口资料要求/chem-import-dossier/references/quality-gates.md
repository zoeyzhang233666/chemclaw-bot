# references/quality-gates.md — 六道放行闸门与分级

> 「能不能报关」不是感觉，是六个可以算的是/否。任何一项 fail 就不能出结论说「资料齐了」。

---

## 闸门定义

| 闸门 | 名称 | 判定规则 | 典型 fail 原因 |
|---|---|---|---|
| **GATE-1** | 身份闸门 | 产品身份要素（CAS/浓度/组成/形态/用途/包装/运输方式）是否齐备且已确认 | 缺稳定剂明细、浓度口径不明 |
| **GATE-2** | 归类闸门 | 是否有首选编码 + 章注依据 + 置信度 + 备选路径 | 只有编号没依据；置信度低且未申请预裁定 |
| **GATE-3** | 监管闸门 | 监管清单是否覆盖危险化学品/运输/检验/用途四层，且无「待核验」 | 有 pending 项未落实书面结论 |
| **GATE-4** | 运输闸门 | 危险货物是否有 UN/类项/PG/正确运输名称/标签/隔离 | 判为危险货物但缺 UN 或 PG |
| **GATE-5** | 文件闸门 | 必须件是否齐备 | 中文 SDS/标签/符合性声明/包装证明缺失 |
| **GATE-6** | 税费闸门 | 税率是否已核实（含协定税率冲突是否澄清） | 协定税率存在数据冲突未实查 |

---

## 状态与总体分级

```
gate: pass | pending | fail

D = 存在 fail，或「必须件」中有缺失/过期的
C = 待确认闸门 ≥ 3
B = 待确认闸门 1~2
A = 全部 pass
```

**注意一条**：「必须件**不完整**（partial）」≠「缺失」。
文件已到手、只是要补正的，属 `pending`，不直接判 D。
只有「完全没有」或「版本已失效」才判 fail。

> 这条区分很关键：把所有不完整都判成 D，会让报告永远显示「不可放行」，
> 反而失去指示作用——决策者需要知道的是「还差什么、差到什么程度」。

---

## 每个闸门的说明文字怎么写

说明文字**由状态自动生成**，不写死在数据里（避免与实际判定脱节）：

- GATE-1 pending → 「身份为部分确认，尚缺 N 项要素：……」
- GATE-5 fail → 「必须件缺失 N 项（D02、D04…），不补齐无法报关」
- GATE-6 pending → 「N 项协定税率存在数据冲突，须以单一窗口实查后锁定」

---

## 分级与行动建议的对应

| 分级 | 能不能下单/发货 | 建议动作 |
|---|---|---|
| A | 可以进入报关准备 | 归档、按时间线执行 |
| B | 可以有条件推进 | 并行推进待确认项；到货前闭环 |
| C | 暂缓 | 先解决 ≥3 项待确认，再评估 |
| D | 不可放行 | 先补必须件（P0 缺口），逐项销项 |

## 交付前的三道自检

### 自检 1：结论层
- [ ] 首页一眼能看到分级、P0 数量、高优先级待确认数量
- [ ] 有「可以写 / 不能写」的口径对照
- [ ] 每条结论都有来源编号

### 自检 2：可执行层
- [ ] 每个缺口都有「为什么 / 怎么要 / 谁负责」
- [ ] 每个待确认项都有「判断错的代价」
- [ ] 有英文索取清单，可直接发供应商
- [ ] 有时间线（T-45 → 到港后）

### 自检 3：可用层
- [ ] HTML 离线可开（无外部依赖）
- [ ] HTML 在 1440 / 1180 / 900 / 420 宽度下无横向溢出
- [ ] 正文对比度 ≥ 4.5:1
- [ ] Excel 打开无警告，公式无 #REF!
- [ ] 勾选进度可保存（HTML 用 localStorage，Excel 用下拉）
- [ ] 模拟件均显式标注
