# 检查进口单证（IMPORT DOCUMENT VERIFICATION）

一票货物的单证之间必须"互相咬合"：数量、单价、金额、重量、件数、批号、收货人、品名规格、港口、船名、贸易术语，任何一处对不上，都可能在付汇、报关、查验、提货、验收任一环节卡住。
本技能把这件事做成**可复现的流程 + 可交付的看板与台账**，而不是靠人眼逐张比。

## 什么时候用

- 海外供应商发来一整批单证（5–15 个文件，PDF/Word/Excel/扫描件），需要在下单付款/报关前审核一遍；
- 已发现某个数字对不上（如"发票金额和单价×数量不符"），要系统查清还有哪些地方连带不一致；
- 银行开信用证、需要做单证相符审核；或报关行要求补资料；
- 需要给海外供应商发一封"要更正/要补单"的英文函件。

## 三条硬规矩（决定这份工作是否可信）

1. **不猜**。扫描件模糊、缺页、没有文字层，就写【无法判断】并说明"需 OCR / 需原件"，绝不用常识填空、不凭印象给数字。
2. **不把"本来就该不同"当错误**。形式发票 vs 商业发票金额、SDS 第 14 节的"标准装运"件数与重量、通知方 vs 收货人、生产商 vs 卖方、报价期条款 vs 合同条款——这些一律判【无法直接比较】并写明原因（见 `references/02_可比性与不可比清单.md`）。
3. **不下"海关一定退单"这类结论**。只说"该处不一致会影响到 X 环节；是否构成退单/查验由海关/银行按其规则裁量"。

## 输入

| 输入 | 必需 | 说明 |
|---|---|---|
| 单证文件（一个目录） | 是 | 支持 `.pdf` `.docx` `.xlsx` `.png` `.jpg`；同一票货物的全部文件 |
| 字段抽取结果 `fields.json` | 是 | 每个文件的字段值 + 页码 + 行号 + 原文片段。可用 `scripts/extract_fields.py` 自动抽取后人工确认，也可直接用模板手填 |
| `manifest.json` | 建议 | 批次基础信息（品名/CAS/HS/数量/单价/金额/港口/买卖双方）+ "应有单证清单"，用于判定【缺失】 |

## 流程（5 步）

```text
① 归集 → ② 识别与抽取 → ③ 交叉核对 + 计算校验 → ④ 判定与定位 → ⑤ 出看板/台账/更正函
```

### ① 归集与分类
把一票货的所有文件放同一目录，按文件名编号（`01_采购合同_…`、`02_形式发票_…`）。分类顺序按"最具识别性关键词"打分，见 `references/01_单证类型与必备字段.md`。

### ② 抽取字段
```bash
python scripts/extract_fields.py --input <单证目录> --out extracted.json
```
- PDF/Word/Excel 走文字层；**图片或扫描件必须配 `<同名>.ocr.txt`**，否则该文件返回 `NEEDS_OCR`，不得凭图像猜字段；
- 自动抽取是"尽力而为"，**必须人工复核**：把结果整理成 `fields.json`（结构见 `examples/01_MEG_沙特_宁波/expected/fields_MEG.json`），每个值都带 `page`/`line`/`snippet`；
- 定位必须真实：用 `scripts/verify_docs.py --check-locate` 逐条回查页码与行号（脚本会对不上就报错）。页码以**渲染后 PDF** 为准（DOCX 用 LibreOffice 转 PDF 后取页）。

### ③ 交叉核对 + 计算校验
```bash
python scripts/verify_docs.py --fields fields.json --manifest manifest.json --out report.json
```
引擎做四件事：
1. **字段矩阵**：41 个标准字段 × 各单证，归一化后比对（编号去符号、金额去千分位、公司名去 Co./Ltd、港口去括号城市码、贸易术语只取三字母）；
2. **可比性裁决**：命中"不可比清单"的差异判【无法直接比较】/【待确认】，不产生问题项；
3. **计算校验**：`单价×数量=金额`、`毛重−净重∈(0,15%净重)`、`净重÷件数`合理性、`数量÷件数`单件装载量；
4. **齐全性**：`manifest.expected_documents` 中未收到的单证判【缺失】。

### ④ 判定与定位
每条问题必须同时具备：`状态`（一致/不一致/缺失/计算错误/待确认/无法判断）+ `涉及单证` + `页码/行号` + `各文件原值` + `影响的业务环节` + `建议处理`。
"影响的业务环节"只能从这五类里选：对外付汇/单证相符、进口报关、清关提货、到货验收、合同履约。对应表见 `references/04_问题分级与业务影响.md`。

### ⑤ 交付
- **HTML 核对看板**：`scripts/render_report.py --report report.json --docs <单证目录> --out 看板.html`（自包含、无外网依赖、可离线发给同事）；
- **Excel 台账**：同上脚本 `--xlsx 台账.xlsx`（6 页：单证索引/字段矩阵/计算校验/问题定位/修正记录/待确认）；
- **英文更正函**：看板"要更正函"页签自动生成，或 `scripts/make_letter.py --report report.json --out letter.txt`。

## 字段与口径（摘要）

| 组 | 字段 |
|---|---|
| 单证编号 | 合同号、形式发票号、商业发票号、装箱单号、提单号、COA 号、订单号、信用证号 |
| 主体 | 卖方、买方、收货人、通知方、发货人、生产商、原产国 |
| 货物 | 中英文品名、CAS、HS、规格/含量、数量、单位、批号、唛头、UN 号、危级 |
| 价格 | 单价、金额、币种、贸易术语、起运港、目的港 |
| 运输 | 船名、航次、提单日期、ETA、件数、包装方式、毛重、净重 |
| 结算 | 付款方式（T/T、L/C、账期） |

**必检算术**：`金额 = 单价 × 数量`、`毛重 > 净重 且皮重 < 净重15%`、`数量/件数 = 单件装载量（合理区间）`、`发票金额大写 = 小写`。

## 常见坑（真实业务里最容易漏的）

- 发票改小了"数量"但没改"金额"→ 单价×数量≠金额（本技能示例正是这一条）；
- 提单批号与 COA/装箱单批号不一致 → 到货验收与索赔时会扯皮；
- 合同写 T/T、发票写 L/C → **不是**单证不符，而是**要确认付款路径**（判【待确认】）；
- 收货人名称多了/少了一个 "CO., LTD."、"LTD" vs "LIMITED" → 提单收货人必须与报关经营单位/信用证申请人完全一致；
- 毛重填成净重（两者相等）→ 说明皮重被吞掉，报关毛重会错；
- SDS 第 14 节件数与实际件数不同 → 通常**不算**不符，除非该 SDS 是卖方就本票货出具的运输说明。

## 使用示例

```bash
# 1) 抽取（尽力而为）
python scripts/extract_fields.py --input examples/01_MEG_沙特_宁波/documents --out work/extracted.json
# 2) 人工复核成 fields.json 后核对
python scripts/verify_docs.py --fields examples/01_MEG_沙特_宁波/expected/fields_MEG.json \
    --manifest examples/01_MEG_沙特_宁波/expected/manifest.json --out work/report.json --check-locate
# 3) 出交付物
python scripts/render_report.py --report work/report.json \
    --docs examples/01_MEG_沙特_宁波/documents --out work/看板.html --xlsx work/台账.xlsx
python scripts/make_letter.py --report work/report.json --out work/letter.txt
```

## 交付前自检

- [ ] 每份文件都有类型与编号；图片类都有 OCR 来源说明；
- [ ] 每个字段值的页码/行号都经过 `--check-locate` 回查（0 失败）；
- [ ] 不一致项都能指到"哪份文件第几页写了什么"；
- [ ] 不可比项都写了原因，没有被算进问题数；
- [ ] 缺失项都说明"为什么应该有"（合同条款/信用证/报关要求）；
- [ ] 结论里没有"海关一定会退单/罚款"这类断言；
- [ ] 全部示例材料都带【模拟】标识。
