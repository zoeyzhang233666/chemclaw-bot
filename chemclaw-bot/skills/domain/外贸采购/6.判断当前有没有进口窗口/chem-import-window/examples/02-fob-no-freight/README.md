# 示例 02 · 进口甲醇（FOB 波斯湾）→ 华南：**降级路径验证**

这个示例不是用来回答"甲醇有没有进口窗口"的，而是用来回答一个更重要的问题：

> **当关键数据拿不到时，这套工具会不会编一个数字出来？**

答案是：**不会。** 它会把"算不出来"明确地写在页面最显眼的位置，并说明缺什么、怎么补。

## 本案例刻意保留的两个缺口

| 缺口 | 后果 | 引擎行为 |
|---|---|---|
| 报价术语为 **FOB**，但**没有任何运价** | FOB 只到装运港，缺运费就无法形成到岸成本 | 返回 `blockers: NO_FREIGHT`，**拒绝给出价差** |
| 海外报价、国内价、汇率**各仅 1 个点** | 无法构建任何时长 >1 天的序列 | 历史视图显示"数据不足"，**不插值、不画线** |

此外还保留了保险费率、境内费用、税率未核验三项常规缺口，共 5 项。

## 页面上会看到什么

| 区域 | 显示 |
|---|---|
| ① 海外报价卡 | `268.0 美元/吨 · FOB` |
| ② 进口成本卡 | **`— 不可折算`**（不是 0，不是估算值） |
| ③ 国内现货卡 | `2,380.00 元/吨` |
| ④ 理论价差卡 | **`— 不可计算`** |
| 结论条 | "关键数据缺失，无法计算价差" + "存在不可比项" |
| 04 敏感性 | 显示"当前参数下无可用敏感性结果" |
| 05 历史 | 显示"没有可配对的历史点位 — 按纪律不生成曲线" |
| 08 缺口 | 5 项，其中 G1 标注为"**结论性缺口**" |

## Excel 上会看到什么

`2-进口成本折算` 的每一行都显示 **`待补`**，而不是算出 0。
`5-敏感性` 显示"待补"，并注明"缺关键参数时一律不按 0 计算"。
`9-引擎校验` 的判定为"两侧均无值"，不报"复核"。

## 把它变成真案例

只需三步：

1. **补运费** → `data/case.json` 里 `freight.usd_per_ton` 填实盘运价（美元/吨），`quality` 改为 `actual`；
2. **补历史** → 往 `quotes_hist`、`domestic_hist.rows`、`fx.rows` 里按日期补齐；
3. **补税率** → 查当年暂定税率表确认 `29051100`，把 `provisional` 改为 `false`。

补完后重新生成，页面会自动从"不可计算"变成完整看板 —— **代码一行都不用改**。

## 验证它确实"算不出来"

```bash
node ../../scripts/validate.js data/case.json
# → verdict=not_calculable，并提示 "报价为 FOB，成交前必须加国际运费；当前没有可用运费数据，不做估算"

node ../../scripts/cross_check.js data/case.json
# → 两侧一致地拒绝计算
```

## 模拟情景

本案例带一个明确标注的模拟情景 `S-SIM-FRT`：假设运费 45 美元/吨，用于验证"补上运费后计算器能否正确折算"。
该值**是人为设定的**，不是真实运价，页面上有"模拟"徽章，不得用于对外汇报。
