# 06 常见错误案例（真实踩坑记录）

> 每一条都来自本项目实际发生过的错误。
> 用途：遇到类似现象时，直接对照排查，不必重新踩一遍。

## 案例 1｜辅料成本从 12 元变成 24,405 元

**现象**：触媒成本算出 11,400 元/吨，占总成本 80%。

**原因**：单耗单位是 `kg/吨`（1.2 kg），单价是 `元/吨`（9500）。
代码直接 `1.2 × 9500`，把 1.2 kg 当成了 1.2 吨，放大 1000 倍。

**修正**：引入 `_price_basis()` 统一解析单位后缀：
```python
if unit.startswith('kg'): k = 0.001      # kg → 吨
elif unit.startswith('kwh'): k = 1       # 元/度 直接乘
else: k = 1                              # 吨 → 吨
```

**教训**：**凡是辅料，先问"这个数字量级对吗"**。单个辅料超过 100 元/吨就要怀疑。

## 案例 2｜敏感性矩阵所有列完全相同

**现象**：双因素矩阵横向 5 列数值一模一样，只有纵向变化。

**原因**：`sensitivity()` 里写的是
```python
r = compute(shock={ids[0]: a, ids[1]: b})   # ids[1] = 'product'
```
而 `compute()` 内部读取产品价用的是 `p['product']['price']`，
shock 的键 `'product'` 从未被消费，所以列方向没有生效。

**修正**：
```python
product_price = p['product']['price'] * (1 + shock.get('product', 0.0))
```

**教训**：**敏感性分析必须存在"两向都变"的证据**。若矩阵任一行或列恒定，立即怀疑 shock 键名没被读取。
本案例后续加了断言：`产品 +10% → 利润上升`，且矩阵必须单调。

## 案例 3｜把加工价差叫成"利润"，结论完全反向

**现象**：报告初稿写"电石法 PVC 利润 1083 元/吨"，而实际同期第三方毛利为 −619 元/吨。

**原因**：1083 元是**只扣原料**的加工价差，未扣电价、汽价、触媒、人工、折旧。

**修正**：三层指标分离后：
- 理论加工价差 +1083
- 理论制造利润 −431
- 企业实际利润：不输出

**教训**：**价差和利润必须用不同的词**。差值 1500 元/吨足以让结论反转。

## 案例 4｜电石占比 93%，与文献 65–75% 严重不符

**现象**：自检断言 `电石占原料成本 65–75%` 失败，实际 93%。

**原因**：占比的分母用的是"原料成本"（只有电石 + HCl），
而文献里的 65–75% 是**占总成本**（原料 + 能源 + 辅料 + 制造费用）。

**修正**：同时输出多个口径的占比，并明确每个对标哪条文献：
```python
shares['_raw_electric_total'] = 电石 / 总成本     # 对标 65–75%
shares['hcl']                  = HCl / 总成本     # 对标 14–15%
shares['_energy']              = 能源 / 总成本    # 对标 5.9–6%
shares['_raw_basket']          = (电石+HCl) / 总成本
```

**教训**：**做合理性校验前，先确认自己和文献的分母是同一个。**

## 案例 5｜Excel 公式自引用（B12 = B8 − B10 − B11 − B12）

**现象**：Excel 里理论制造利润恒为 780（等于制造费用），加工价差恒为 4865（等于产品价）。

**原因**：用相对偏移拼公式：
```python
'=B%d-B%d-B%d-B%d' % (spread_row, spread_row + 2, spread_row + 3, spread_row + 4)
```
偏移量算错，最后一个引用了自己所在行，形成循环。

**修正**：全部改为**按名字取行号**再拼接：
```python
r_profit = R3['⑥']
'=B%d-B%d-B%d-B%d' % (r_spread, r_energy, r_aux, r_mfg)
```
并加断言：改输入电价后，结果必须变化。

**教训**：**公式里不要出现魔法偏移量**。且必须有"改动输入 → 输出变化"的回归测试。

## 案例 6｜Excel 敏感性矩阵漏了辅料项

**现象**：矩阵中心格 963，与引擎 1083 差 120。

**原因**：矩阵公式写成 `产品价 − 电石成本`，漏了"其他原料"（此处 HCl 被分为辅料但进入了原料篮子）：

**修正**：减去"原料小计 − 电石成本"：
```
='01'!$B$7*(1+B$4) - ('01'!$C$13*$E$13*$G$13*(1+$A13)/'01'!$B$8) - ('02'!$G$18 - '02'!$G$5)
```

**教训**：**矩阵与主表必须用同一个成本口径**。校验方式：矩阵中心格必须等于主表的基准值。

## 案例 7｜加计联产烧碱让偏差变大

**现象**：假设"漏了烧碱收益"，加上 0.75 t/t 抵减后，
与第三方毛利的平均绝对偏差从 155 恶化到 278，偏差均值从 −92 变成 +64。

**原因**：第三方"电石法毛利"口径**并不按烧碱计价**（其样本企业多为外购电石、氯由配套装置平衡供应但收益未计提）。

**处理**：**撤掉该抵减**，把它降级为"氯碱一体化情景"，在 HTML 的勾选项里单独提供。

**教训**：**当数据不支持你的假设时，改假设而不是改数据。**
并且这个"被证伪的过程"本身应该写进报告——它证明了模型不是拟合出来的。

## 案例 8｜无价格区间的强行插值

**现象**：2025 年 11 月至 2026 年 1 月没有电石日价，初版按月均值线性填充，做出了一条平滑曲线。

**问题**：这段时间跨冬季，电石受电力成本与运输影响大，平滑曲线是虚构的。

**修正**：只使用文章明确披露的 6 个锚点，在锚点之间插值，锚点之外**留空**。
图表上该段显示为空白区域并加灰底标注"无可靠电石价格，不做外推"。

**教训**：**空白比假曲线诚实**。留空不会让报告变差，编造才会。

## 案例 9｜沙箱环境下浏览器截图失败

**现象**：`chrome --headless --screenshot` 无输出，Playwright 报 `PermissionError: WinError 5`。

**原因**：受限环境下 Chromium 的 mojo IPC（命名管道）被拦截，浏览器进程无法完成初始化。

**降级方案**（可复用到其他项目）：
1. 用 `py-mini-racer`（V8）真实执行 HTML 内嵌的 JS，配合 Python 端 DOM 桩；
2. 断言 KPI、表格、图表配置是否生成；
3. 模拟输入事件，验证联动；
4. Python 引擎与 JS 引擎逐值比对。

**教训**：**验证"能渲染"不等于"能截图"**。DOM 桩 + 真 JS 引擎已能覆盖逻辑正确性；
视觉层应在有图形环境时再验一遍。

## 案例 10｜PowerShell 批量替换破坏 UTF-8 中文与转义

**现象**：用 `-replace` 批量改写 Python 源码后，中文字符串变成乱码 `��`，`\u2212` 被当字面量。

**原因**：PowerShell 的字符串替换对编码与转义的处理与源码期望不一致。

**修正**：涉及中文与转义字符的代码修改，**一律用精确编辑工具（按原文字符串匹配替换），不要用 shell 批量替换**。

**教训**：代码文件的批量改写要用能保证原样读写的工具。
