# 05 · 布局规则与渲染规范

> 一张产业链图的价值，一半在数据，一半在"读者能不能顺着线看懂"。
> 本 Skill 把布局做成**可计算的**：坐标在 Python 端算好，几何质量可断言、可回归。

---

## 1. 为什么坐标不用浏览器算

D3/力导向布局的问题是：**同样的数据每次画出来不一样，而且重叠了没人知道**。
本 Skill 的做法：

```
data/*.json  →  tools/chain_layout.py（确定性布局 + 几何自检）  →  坐标 JSON  →  chain_graph.js（只负责画）
```

好处：
- **确定性**：同一份数据每次生成同一张图，便于评审与版本对比。
- **可断言**：重叠/越界/穿线/斜线 都是可数的整数，能进 CI。
- **可降级**：几何不达标时自动切表格视图，而不是交一张歪图。

## 2. 网格模型

```
        ┌──────────── 一列（column）────────────┐
        │  列头 label（HEADER_H = 32）           │
        │  ┌────────┐  ← row 0                 │
        │  │ 节点   │                          │
        │  └────────┘  ROW_GAP = 14            │
        │  ┌────────┐                          │
        │  │ 节点   │                          │
        │  └────────┘                          │
        │      ↕ BAND_GAP = 22（不同 node_role 之间）│
        └────────────────────────────────────────┘
             ↕ COL_GAP = 72（列间距）
```

| 常量 | 值 | 含义 |
|---|---|---|
| `NODE_W_MIN` / `NODE_W_MAX` | 192 / 268 | 节点框宽，按名称长度自动选 |
| `NODE_H` | 56 | 节点框高（两行文字：名称 + 副标题） |
| `ROW_GAP` | 14 | 同列相邻节点间距 |
| `BAND_GAP` | 22 | 不同 `node_role` 分段之间的加宽间距 |
| `COL_GAP` | 72 | 列间距（容纳走线轨道） |
| `PAD_X` / `PAD_TOP` / `PAD_BOTTOM` | 26 / 58 / 44 | 画布内边距 |
| `HEADER_H` | 32 | 列头高度 |
| `TRACK_STEP` | 9.0 | 同类走线轨道的错开步长 |
| `HOOK` | 26.0 | 出入节点的水平短折段长度 |
| `DETOUR_MARGIN` | 26.0 | 绕行走线绕出列外的距离 |

### 列内排序

同列节点按 `BAND_ORDER` 排序（`raw → byproduct → intermediate → monomer → auxiliary → target → compound → article → system → derivative → same_family → substitute → end_market`），再按 `id` 稳定排序。
这样每列内部自然形成"上游在上、下游在下"的语义分区。

## 3. 走线（routing）算法

每条边按下列顺序尝试，取第一个无冲突的方案：

```
1. straight   同一行，直接水平连接
2. elbow      水平出 → 垂直 → 水平进（单次折）
3. ladder     折线但垂直段落在列间空档的"梯子"上（多目标共用通道）
4. orthogonal 两次折（S 形），水平段走列间中缝
5. detour     绕出列外（用于跨列/逆序/长距离）
```

### 每一步的验收条件

一段走线只有在**不穿过任何节点框**、**不与其他边走线共线重叠**、**不含斜线段**时才被接受。

| 检查项 | 说明 |
|---|---|
| `seg_clear(x1,y1,x2,y2,skip)` | 整段逐列检查是否穿节点（早期只抽样检查列内空档，漏掉了横穿整列的线段） |
| 斜线段禁止 | 任何同时满足 `dx > 0.5 && dy > 0.5` 的线段被拒绝（斜线视觉上像"乱连"，且易穿节点） |
| `_alloc_track` | 共线的垂直段分配唯一轨道：`base + step × slot`，超出区间就换 base |

### 共线（collinear）为什么必须消除

两条边若在同一 x 上重叠一段，读者会以为是同一条线（分叉错觉），或者完全看不见其中一条。
`TRACK_STEP = 9.0` 让同类垂直段彼此错开；不同类（质量流 / 替代）用不同 base。

## 4. 几何自检指标

`chain_layout.layout_report()` 输出：

```json
{"nodes": 36, "edges": 48, "overlap": 0, "outside": 0,
 "edge_through_node": 0, "edge_collinear": 1, "diagonal": 0, "detour": 7}
```

| 指标 | 通过线 | 含义 | 常见成因 |
|---|---|---|---|
| `overlap` | **0** | 节点框互相重叠 | 节点太宽 / 同列太多 |
| `outside` | **0** | 节点越出画布 | PAD 太小 / 列数太多 |
| `edge_through_node` | **0** | 连线穿过节点框 | 走线算法缺陷 |
| `diagonal` | **0** | 存在斜线段 | 退化情况 |
| `edge_collinear` | ≤ 2 | 两条边在同一 x/y 上重叠 | 密集区的轨道冲突 |
| `detour` | 参考值 | 需要绕行的边数；>40% 说明列布局不合理 |

**判定**：`overlap / outside / edge_through_node / diagonal` 任一非 0 → `ok = false`。
`ok = false` 时 HTML 构建器仍会输出文件，但**默认进入层级表视图**并在页头警告——节点与证据绝不丢失。

## 5. 渲染层规范（`chain_graph.js`）

### 5.1 视觉编码

| 元素 | 编码 |
|---|---|
| 节点类别 | 边框+底色：化学品（蓝）/ 材料（青绿）/ 终端应用（琥珀） |
| 目标品种 | 加粗边框 + 光晕 + 徽标 |
| 关系类型 | 线型 + 颜色：转化（实线）/ 联产（实线粗）/ 副产（短虚线）/ 配方（点线）/ 加工（点线）/ 终端（黄）/ 替代（橙双向）/ 路线（灰） |
| 缺口节点 | 右上角 ⚠ 角标（悬停显示缺口类型） |
| 延长线节点 | 降低不透明度 + 列头标注"延长线" |

### 5.2 视图状态机

```
初始      →「适应」：整图入屏；若缩放低于可读下限(MIN_READABLE_K)，
                    改为可读比例并聚焦目标品种列（此时可拖拽查看）
总览       →「总览」：强制整图入屏（此时不保证文字可读）
节点选中   → 上游血缘高亮 + 下游血缘高亮 + 无关节点变暗 + 侧栏打开
关系选中   → 该边加粗高亮 + 侧栏显示工艺与口径
多选(≥2)   → 价格联动面板
布局失败   → 层级表视图（可切回）
```

### 5.3 交互断言（`verify_html.py` 的 34 项）

| # | 断言 | 防的是什么 |
|---|---|---|
| 1 | 无 JS 运行时错误 | 白屏 |
| 2 | `window.CHAIN` 暴露 | API 契约破坏 |
| 3–4 | 渲染节点/边数 = 数据条数 | 静默丢数据 |
| 5–7 | 覆盖表盘有数值、卡片、口径说明 | 覆盖面板空壳 |
| 8–9 | 放大/缩小生效 | 缩放失效 |
| 10 | 拖拽平移生效 | 画布锁死 |
| 11–15 | 节点侧栏含 CAS/价格/企业/证据 | 侧栏信息不全 |
| 16 | 上下游高亮计数 > 0 | 血缘计算失效 |
| 17–19 | 关系侧栏含工艺/单耗/口径 | 关系详情缺失 |
| 20–21 | 搜索有下拉且过滤画布 | 搜索失效 |
| 22–24 | 关系类型 chip / 筛选 / 工艺下拉 | 筛选失效 |
| 25 | 价格联动面板出现 | 联动失效 |
| 26 | 层级表行数 ≥ 节点数 | 兜底视图丢节点 |
| 27 | 覆盖面板可折叠 | UI 细节 |
| 28 | 节点可读宽度 ≥ 140px | 缩得太小看不清 |
| 29 | 总览视图 0 越界 | 图被裁切 |
| 30 | 节点互不重叠（屏幕空间） | 视觉混乱 |
| 31 | 节点文字不溢出 | 文字被裁 |
| 32 | 小地图渲染 | 导航缺失 |
| 33–34 | 无外部网络请求 | 离线打不开 |

## 6. 页面结构与响应式

```
┌─ header（标题 / 副标题 / 数据截至 / 生成时间）───────────┐
├─ #coverageBar（覆盖表盘 + 卡片 + 缺口 + 口径，可折叠）────┤
├─ .toolbar（搜索 / 类型 chips / 工艺下拉 / 按钮组）────────┤
├─ #selbar（多选芯片）                                    │
├─ .stage ─────────────────────────────────────────────┤
│   #svg（泳道 + 边 + 节点）        │  #sidebar（详情）   │
│   #minimap                       │                    │
│   #legend                        │                    │
├───────────────────────────────────────────────────────┤
├─ #tableMode（层级表兜底，默认隐藏）                       │
└─ #foot（口径声明 / 免责）                                ┘
```

- `#app` 固定 `height:100vh`，内容区 `flex:1 min-height:0`，避免整页出现超长滚动导致拖拽点落在视口外。
- 1440×900 与 1680×1000 都要能完整操作（`verify_html.py` 可换 viewport 复跑）。
- 窄屏（<1100px）时侧栏变为覆盖层。

## 7. 离线自包含要求

生成的 HTML **必须**：
- 无 `<script src>`、无 `<link rel=stylesheet>` 指向外部
- 无 CDN、无字体外链（用系统字体栈）
- 数据以 `window.CHAIN_DATA = {...}` 内联

校验方式：`verify_html.py` 会监听 `request` 事件，断言除 `file://` 外**零请求**。

## 8. 调参指南

| 症状 | 调整 |
|---|---|
| 节点文字被裁 | 缩短 `name`，或调大 `NODE_W_MAX` |
| 一列太挤重叠 | 拆列（把该列按环节拆成两列），或减少该列节点 |
| 大量绕行 | 检查是否有跨多列或逆序的边；考虑把目标节点移到中间列 |
| 共线告警 | 调大 `TRACK_STEP`，或给该类关系换 base |
| 整图太宽 | 减少上游延长线列数（把 -6/-5 合并） |
| 图太矮 | 增加同列节点（把合并节点拆开） |
