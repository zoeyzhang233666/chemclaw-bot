# 06 · 交付前自检清单

> 逐项打勾。任何一项打不了勾，就不要交付。

---

## A. 研究对象与范围（5 项）

- [ ] A1 `meta.json` 写清了品种全名、别名、CAS（或"不适用"）、规格维度
- [ ] A2 `user_params` 记录了上/下层数、支链、是否显示价格与企业
- [ ] A3 图例或页头**明确标注了延长线**（不计入覆盖的额外上游列）
- [ ] A4 `core_checklist.meta.scope_statement` 写明"不覆盖什么"
- [ ] A5 `frozen_at` 有值，且早于数据填充时间（不是事后倒推）

## B. 节点身份（6 项）

- [ ] B1 每个 `commodity` 节点的 CAS 状态是 `verified`，或明确标 `unverified` 并进缺口
- [ ] B2 每个 `material` / `application` 节点的 CAS 是 `{value:"不适用", status:"不适用"}`
- [ ] B3 **没有任何**材料/终端节点带真实 CAS（校验器 FATAL）
- [ ] B4 `node_class` 三分类没有混用（配方料没被当成化学品）
- [ ] B5 `node_role` 与 `segment` 能自证（看名字就知道在链上哪一段）
- [ ] B6 别名覆盖了业务方常用的叫法（搜索得到）

## C. 关系类型（8 项）

- [ ] C1 每条边都通过了"判定三问"，类型不是随手填的
- [ ] C2 **没有**把 `blend` / `processing` / `application` 写成 `conversion`
- [ ] C3 **没有**把终端用途写成转化产品（`forbidden_links` 全通过）
- [ ] C4 `substitution` 边是双向语义，且能说清"在哪个场景替代"并有证据
- [ ] C5 并列工艺路线没有合并成一条（`route_option` 或独立子链）
- [ ] C6 物质流边的 `column` 严格递增（校验器 `DEPTH_INCONSISTENT` 为 0）
- [ ] C7 没有有向环（`CYCLE` 为 0）
- [ ] C8 每条边的 `from` / `to` 都存在于 `nodes.json`（外键无悬空）

## D. 量化参数（5 项）

- [ ] D1 每个有数字的单耗都有 `basis`（怎么算的）和 `basis_grade`（什么规格基准）
- [ ] D2 口径三分法用得对：化学计量 / 工业级 / 配方比
- [ ] D3 多产物装置给的是收率区间，不是单产品单耗点值
- [ ] D4 缺参数的边是 `quant_status: "missing"` + 写明原因，**不是空值**
- [ ] D5 有数字的边都挂了 A~C 级证据（不是只挂 D 级）

## E. 价格（5 项）

- [ ] E1 每条价格序列都有：规格、区域、税制、基准日、来源
- [ ] E2 没有跨规格/跨区域/跨税制求平均
- [ ] E3 没有把自算价差（如 SBS-苯乙烯价差）当作"数据"呈现（要么标注为计算值，要么不做）
- [ ] E4 抓不到的价格登记为缺口，写了"为什么缺 + 到哪里补"
- [ ] E5 `fetched_at` 与页脚"数据截至"一致

## F. 企业与产能（4 项）

- [ ] F1 产能口径写清（单产品 vs 合计装置）
- [ ] F2 合计产能**没有**被表述为"行业总产能"
- [ ] F3 项目状态区分了 已投产 / 在建 / 环评 / 规划
- [ ] F4 每家企业的产能都有 `evidence`

## G. 覆盖完整度（4 项）

- [ ] G1 分母 = 冻结清单条数，且在图上与 Excel 里**都可见**
- [ ] G2 未通过项逐条列出（不是只报一个百分比）
- [ ] G3 覆盖率口径说明写清了每个判定词的含义
- [ ] G4 没有声称"覆盖整个产业链"

## H. 渲染与交互（5 项）

- [ ] H1 HTML 离线可开（零外部请求）
- [ ] H2 布局自检：`overlap/outside/edge_through_node/diagonal` 全为 0
- [ ] H3 `verify_html.py` 34 项全 PASS
- [ ] H4 至少 1680×1000 与 1440×900 两个视口都能完成核心操作
- [ ] H5 布局失败时层级表可用，且表格行数 = 节点数（不丢节点）

## I. Excel（4 项）

- [ ] I1 12 个 sheet 齐全（封面/节点/关系/参数/价格/企业产能/项目事件/证据/覆盖/缺口/禁用边/对账）
- [ ] I2 第 11 页"对账校验"全绿
- [ ] I3 第 09 页缺口清单条数与程序输出一致
- [ ] I4 价格表里缺口序列显式标了"缺口"而不是空白或 0

## J. 交付物本身（4 项）

- [ ] J1 文件名与目录规范（`<chain_id>_chain.html` / `.xlsx`）
- [ ] J2 页脚有免责与口径声明
- [ ] J3 ZIP 内包含 `data/` 全量原始 JSON（可复现）
- [ ] J4 重新跑一遍 `run_all.py` 结果一致（幂等）

---

## 附：三条"绝不能交付"的红线

1. **有编造的关系或数字**（哪怕只有一条）
2. **覆盖率虚高**（用未冻结的清单或隐藏未通过项）
3. **交付物说"全产业链"**（而实际只是 2 层骨架）

---

## 自检命令

```bash
python tools/run_all.py --data-dir examples/sbs/data --out-dir out
```

一次跑完：校验 → 覆盖率 → HTML → XLSX → 34 项交互断言，并打印上表 A~I 的可机检部分。
