# 07 · 换一个品种的操作手册

> 从"用户说了一个品种名"到"交付 HTML + Excel"，按这份清单一步步走。
> 以通用化工品为例，不绑定任何特定品种。

---

## 0. 先问清 5 个参数（没有就用默认值并在产物里注明）

| 参数 | 默认 | 怎么问 |
|---|---|---|
| 品种全名与规格 | 用户给的名字 | "具体是哪个牌号/纯度？有没有同族产品要一起看？" |
| 上/下层数 | 2 / 2 | "上面想看到哪一层原料？下面看到制品还是终端？" |
| 重点工艺路线 | 主流 + 明确并列 | "你关心的是哪条路线？有没有替代路线也要看？" |
| 支链 | 全部主要下游 | "下游你最关心哪几块？其余我先登记成未覆盖。" |
| 价格与企业 | 都显示 | "要不要挂价格和产能？有没有指定的数据源？" |

记进 `meta.json.user_params`。

---

## 1. 起手三件事（别急着铺节点）

### 1.1 写 `meta.json`
品种全名、别名、CAS（去 PubChem/CAS Common Chemistry 查）、规格维度、地理与税制口径。

### 1.2 写 `core_checklist.json`（**冻结**）
- 目标品种（P0）
- 直接原料（通常 2~4 个，P0）
- 关键中间体（P0/P1）
- 主要下游配方材料（P0/P1）
- 终端应用（P0）
- 关键替代品（P1）
- 骨架关系 30~40 条

**这一步不要看数据能不能拿到**，只问"研究这个品种必须知道什么"。拿到之后才发现有些拿不到，那就留成缺口——这才是诚实的覆盖率。

### 1.3 写 `forbidden_links.json`
先想"这条链最容易被画错的 5~10 条边"，写成禁用项。

常见易错模式：
- 产品 → 终端（跳过材料与制品）
- 副产 → 主产品（方向反了）
- 替代品 → 目标（当上下游）
- 两条工艺串成一条（A→B 用路线 1，B→C 用路线 2）

---

## 2. 铺节点（第一轮：20~40 个，只铺骨架）

从目标品种出发，**先向上再向下各走 2 跳**，每跳只放 2~4 个节点：

```
向上：
  target.column = 1
  直接原料 → column 0
  原料的原料 → column -1 ... -6（按需）
向下：
  主要配方材料 → column 2
  制品 → column 3
  终端 → column 4/5
```

每加一个节点，立刻填：`id` / `name` / `node_class` / `node_role` / `segment` / `column` / `cas` / `missing_flags` / `evidence`。

> 提示：`name` 控制在 24 个全角字以内，否则图上会换行挤压。

---

## 3. 铺关系（每加一条，走一遍判定树）

用 `02-relation-taxonomy.md` 的决策树。写完立刻自问：

1. **类型对吗？**（尤其 blend / processing / application / conversion 四者）
2. **方向对吗？**（上游 `column` < 下游 `column`，除 blend/substitution/route_option）
3. **有量吗？有口径吗？**

这一轮不追求量化，先保证结构正确。

---

## 4. 补量化（按"最能影响结论"的顺序）

优先级：
1. **目标品种的直接原料单耗**（成本模型的地基）
2. **主要下游的掺量/配方比**（需求测算的地基）
3. **副产/联产的收率区间**（供给弹性的地基）
4. 其余（能补则补，补不到就 missing）

**每补一个数字，必须同时写**：
- `from_per_to` + `from_unit`
- `basis`（怎么得的）
- `basis_grade`（什么规格基准）
- `quant_status`
- `evidence`（A~C 级，且 `key_quotes` 里有对应原句）

---

## 5. 补价格与企业（可并行）

价格：按 `04-evidence-and-verification.md` 的优先级抓。抓不到就登记缺口。
企业：至少覆盖"主要生产企业"（占行业产能 60%+ 的企业），每家写清产能口径与来源。

---

## 6. 跑校验，清 FATAL

```bash
python tools/validate_chain.py --data-dir <你的 data 目录>
```

FATAL 逐条修：
| 码 | 通常怎么修 |
|---|---|
| `SCHEMA_*` | 补字段 |
| `EVIDENCE_FK` | 来源 id 拼错，或忘在 `sources.json` 里加 |
| `EVIDENCE_TIER_D` | 换 A~C 级来源，或该边降级为 `missing` |
| `FORBIDDEN_LINK` | 你真的画错了；改类型或加中间节点 |
| `NODE_CLASS` | 材料/终端被放到了上游列 |
| `CAS_FAKE` | 材料/终端不该有 CAS |
| `QUANT_NO_BASIS` | 补口径 |
| `DEPTH_INCONSISTENT` | 物质流边逆序，调列或改类型 |
| `CYCLE` | 有环，检查是否把下游写成了上游 |
| `CORE_SCOPE` | 核心清单里的节点/关系在数据里不存在 |

WARN 逐条登记进缺口清单（`missing_flags` + `price_mapped_note`）。

---

## 7. 生成与自检

```bash
python tools/build_chain_html.py --data-dir <data> --out out/<id>_chain.html --title "<品种> 产业链知识图谱"
python tools/build_chain_xlsx.py --data-dir <data> --out out/<id>_chain.xlsx
python tools/verify_html.py out/<id>_chain.html
```

`verify_html.py` 有 FAIL 就逐条看，都是真问题（或测试假设不适用于极小图）。

---

## 8. 最后一遍人眼复核（这步不能省）

虽然布局是机检的，但**语义**只能人工看：

1. 打开 HTML，用「总览」看整体形状：像不像一条链？有没有孤岛节点？
2. 点目标品种：上游血缘里有没有出现"终端应用"？（有就是类型错了）
3. 点每个 `application` 节点：确认它没有出边。
4. 随机抽 3 条量化边，点开看口径，问自己"这个数字换了规格还成立吗"。
5. 打开 Excel 第 09 页：缺口清单是不是"该有的都有"（不是空的，也不是刷屏的废话）。

## 9. 常见品种类型的注意点

| 品种类型 | 特别注意 |
|---|---|
| **聚合物/弹性体**（SBS、PP、PE、ABS） | 牌号维度极端重要；"产能"常是装置可切换的合计值；下游多为 blend 而非 conversion |
| **大宗单体**（乙烯、苯乙烯、PTA、甲醇） | 价格公开且连续（好抓）；但联产/副产多，单耗必须给收率区间 |
| **无机盐/碱**（纯碱、烧碱、钛白粉） | 工艺路线差异大（氨碱/联碱/天然碱），必须分路线；单位常混吨/标方 |
| **精细化工/助剂** | 产能不公开、一单一议；覆盖率会明显偏低，这是正常的，不要为了好看编数据 |
| **新能源材料**（碳酸锂、磷酸铁锂、六氟磷酸锂） | 技术路线迭代快，`route_option` 边多；产能"规划/在建"占比高，状态必须分清 |
| **农化**（草甘膦、尿素） | 有季节性；价格口径（出厂/到站）差异大 |

## 10. 时间预算参考（35 节点规模）

| 阶段 | 时间 |
|---|---|
| 参数确认 + 核心清单冻结 | 20% |
| 节点与关系骨架 | 25% |
| 量化参数补全 | 25% |
| 价格与企业 | 20% |
| 校验 + 生成 + 复核 | 10% |

如果"量化参数"和"价格"加起来超过 60%，说明你在追数据而不是在做图——先保证结构对，再补数据。
