# 01 · 产业链拆解方法

> 这份文档回答一个问题：**给你一个化工品，怎么把它周围的世界拆成一张可信的图。**
> 与具体品种无关，任何化工品都适用。

---

## 1. 先定"研究对象"的边界

品种名称往往不足以定义研究对象。开工前必须把下面 6 项写进 `meta.json`：

| 项 | 为什么重要 | 例（SBS） |
|---|---|---|
| 全名 | 防止与同族产品混淆 | 苯乙烯-丁二烯-苯乙烯嵌段共聚物（TPE-S / SBC 族） |
| 别名 | 搜索与沟通的需要 | SBS、热塑性丁苯橡胶、TPE-S、油胶/干胶 |
| CAS | 身份核验的锚点 | 9003-55-8（聚合物，CAS 为族级） |
| 规格 / 牌号维度 | 决定价格与单耗能否比较 | 干胶 / 充油胶（油胶）；线型 / 星型；S/B 比 |
| 相态与计量单位 | 决定产能与需求能否加总 | 吨（固体粒料） |
| 地理与税制口径 | 决定价格能否直接对比 | 中国大陆、含税出厂/市场价 |

**判据**：如果两个数据源的"规格维度"不一致（例如一个是干胶出厂价、一个是油胶市场价），它们**不能**放在同一条价格序列里，也不能求平均。这一点在 SBS 上尤其致命。

---

## 2. 层数怎么定

用户说"向上 2 层、向下 2 层"时，指的通常是**产业链意义上的层**，不是图的列数。实现上：

```
column 0   目标品种的两大直接原料（聚合单体）
column 1   目标品种本身
column 2+  下游：配方材料 → 制品 → 终端应用
column -1- 上游：中间体 → 基础石化品 → 裂解/重整产物 → 裂解原料 → 原油
```

- **核心层**（计入覆盖清单）：从目标品种出发，向上 2 跳、向下 2 跳。
- **延长线**（不计入覆盖清单）：为了让人看懂"原料是哪来的"，会再多画 1~2 列。**必须在图上和图例里标明延长线**，否则读者会把延长线当成核心结论。
- **缺列是正常的**：没有节点落在某一层就不建那一列。校验只看"物质流边的 column 严格递增"，不要求列号连续。

### 什么时候该加列

- 两条原料路线的上游完全不同（如乙苯脱氢 vs C8 抽提）→ 需要分开的列，否则会逼你把两条路画成一条。
- 上游存在"同一节点被多条路线共用"（如乙烯既是乙苯原料也可来自轻烃裂解）→ 需要独立列 + `route_option` 边。

### 什么时候不该加列

- 只是为了把节点排整齐。列代表**产业环节**，不是排版工具。同环节的多个节点应该在同一列。

## 3. 节点怎么选

### 3.1 三类节点，画法不同

| `node_class` | 含义 | 有 CAS 吗 | 在上游还是下游 | 例 |
|---|---|---|---|---|
| `commodity` | 化学品、单体、中间体、大宗材料 | 通常有（须核验） | 上下游都可能 | 苯乙烯、丁二烯、苯、SBS |
| `material` | 配方材料、改性料、制品、工程材料 | **没有单一 CAS** | 只在下游 | TPR 鞋底料、SBS 改性沥青、防水卷材 |
| `application` | 终端应用市场 | **没有 CAS** | 只在最下游 | 公路建设、鞋类制造、包装物流 |

**硬规则**：
- `material` / `application` 的 `cas` 必须显式写 `{value: "不适用", status: "不适用"}`。校验器会对"材料节点带 CAS"直接 FATAL——因为那几乎一定是编造。
- 材料/终端节点不得出现在目标品种的上游列（校验器 FATAL）。

### 3.2 什么时候该拆成两个节点

拆分的判据是**"它们的价格、产能、单耗是否各自独立"**：

- 各自有独立价格与产能 → 拆。（SBS 与 SEBS 价格不同、产能需分开计 → 拆）
- 一个是另一个的子集/牌号 → 用 `specs` 表达，不拆。（SBS 干胶与油胶 → 同一节点，规格维度）
- 中间有独立的物理/化学步骤 → 拆。（SBS → TPR 鞋底料 → 鞋底 → 鞋，三步四个节点）

### 3.3 什么时候该合并

- 拆分后每个节点都只有 1~2 家企业、数据全是缺口 → 合并成"其他"并注明。
- 同一物质的两种叫法 → 放 `aliases`，不拆。

### 3.4 常见漏掉的节点类型

- **基料/辅料**：基质沥青之于改性沥青，和 SBS 同等重要，但很容易只画 SBS 一条线。
- **替代品**：TPU、EVA、SBR、POE——不是下游，但决定 SBS 的需求弹性。用 `substitution` 边，不进入上下游血缘。
- **同族衍生物**：SEBS（SBS 加氢）、SIS（同族不同单体）。SEBS 是 SBS 的**转化产品**（`conversion`），SIS 是**同族并列品**（`substitution` 或并列下游）。
- **副产/联产**：裂解 C4、裂解汽油。它们是"顺带出来的"，单耗逻辑与主产品不同（用收率区间，不用单耗点值）。

## 4. 关系怎么判（速查）

完整判定标准见 `02-relation-taxonomy.md`。速查表：

| 你的直观描述 | 正确类型 | 常见误判 |
|---|---|---|
| "A 变成了 B" | `conversion` | 有时其实是 blend（物理混合），不是化学变化 |
| "A 和 B 一起出来" | `coproduction` | 与 byproduct 混用（见下） |
| "A 是主产品，顺带出 B" | `byproduct` | 把副产当主链，导致单耗算错 |
| "A 掺到 B 里改性" | `blend` | 写成 conversion：**错**，没有化学变化 |
| "A 加工成 B 形状" | `processing` | 与 application 混 |
| "A 用在 B 领域" | `application` | 写成 conversion：**错**，会把用途当产品 |
| "A 和 B 互相替代" | `substitution` | 写成上下游：**错**，替代没有方向 |
| "A 也可以做 B" | `route_option` | 与 conversion 混：路线要单独登记，不能并成一条 |

**一句话判据**：
> 如果 **B 的分子结构/组成里没有 A 的原子骨架**，那 A→B 不是转化。
> 如果 **A 和 B 可以同时存在于最终产品里**（且没有反应），那是 blend。
> 如果 **A 消失、B 出现，且 B 的用途只是"用得到"**，那是 application，不是 conversion。

## 5. 单耗怎么给

### 5.1 三档口径（必填其一）

| 口径 | 何时用 | 必须同时给出 |
|---|---|---|
| `stoichiometric` / `stoichiometric_derived` | 有明确反应式，且收率有据 | 反应式、收率、分子量基准 |
| `commercial_grade` | 有装置级或行业公开基准 | 基准年份、装置范围、是否含回收 |
| `formulation` | 配方体系（掺量、phr） | 配方总份数基准（每 100 份）、是否含油/填料 |

### 5.2 不许做的事

- ❌ 用"行业经验值"给一个精确到小数点后两位的单耗。
- ❌ 把不同收率口径（催化 vs 热裂解）的数字平均。
- ❌ 把"配方掺量 5%"写成"单耗 0.05 t/t"却不说是配方比——读者会以为这是化学计量。
- ❌ 多产物装置（芳烃联合、裂解）给出"单一产品单耗"。应给**收率区间**并注明是多产品平衡。

### 5.3 缺口怎么写

`quant_status: "missing"` + `quant.basis` 写清"为什么缺"（如"多产品平衡体系，进料为甲苯与 C9，与 C8 无换算关系"）。
**不要**留一个空格子，空格子会被下一个人当成 0。

## 6. 下游怎么展开（最容易出错的地方）

正确链条形态：

```
化学品（commodity）
   ↓ blend（配方共混）
配方材料（material）        例：SBS 改性沥青、TPR 鞋底料、热熔胶
   ↓ processing（成型加工）
制品（material）            例：防水卷材、沥青路面、鞋底
   ↓ application（终端应用）
终端市场（application）     例：建筑防水、公路建设、鞋类制造
```

常见错误：

| 错误 | 为什么错 | 正确写法 |
|---|---|---|
| `SBS → 鞋` | 中间跳过了材料与成型两层，且把用途当产品 | `SBS →(blend) TPR →(processing) 鞋底 →(application) 鞋` |
| `SBS → 公路` | 同上；且 SBS 在公路中的真实载体是改性沥青 | `SBS →(blend) 改性沥青 →(processing) 路面 →(application) 公路` |
| `改性沥青 → 基质沥青` | 方向反了 | `基质沥青 →(blend) 改性沥青` |
| `SBS → 包装` | 热熔胶是中间载体 | `SBS →(blend) 热熔胶 →(application) 包装物流` |
| 一条边同时是 blend 又是 application | 一件事只能有一个类型 | 拆成两条边，中间加材料节点 |

## 7. 覆盖完整度怎么算才算诚实

1. **先冻结**：`core_checklist.json` 的 `frozen_at` 要在开工前写。
2. **分母可见**：图上与 Excel 里都要显示"61/65"，而不只是"93.8%"。
3. **范围声明**：必须写清不覆盖什么。
4. **未通过项要列出来**：不是藏起来，而是列在覆盖面板与 Excel 第 08 页。
5. **别用节点数冒充覆盖率**：节点多不代表研究透。

> 覆盖率是**自评**工具，不是营销指标。它回答的是："我承诺要查的 65 项里，我查实了几项？"
