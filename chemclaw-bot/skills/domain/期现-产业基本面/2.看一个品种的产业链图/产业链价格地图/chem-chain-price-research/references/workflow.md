# 研究流程

这套流程与品种无关：换掉 `SBS`，剩下的步骤对 PP、MDI、纯碱、有机硅、磷酸铁锂都一样适用。

## 第 0 步：把目标问清楚（一次问完）

产业链价格研究的返工几乎都来自目标含糊。开工前确认四件事，用一次提问收集：

| 问题 | 为什么必须问 | 默认值的风险 |
|---|---|---|
| 具体品种与规格 | 干胶 / 油胶、注塑级 / 纤维级，价格能差几千 | 混规格画一条曲线就是错的 |
| 地区范围 | 华东与华南常常不同价 | 全国均价往往不存在对应记录 |
| 时间口径 | "最新"是当日、本周还是月度 | 跨日期混比较无意义 |
| 下游覆盖哪些应用 | 决定图的右端形状与缺口清单 | 漏了应用，产业链不完整 |

若用户明确说"你自己判断"，就**显式写出你采用的默认口径**，并在交付物里重复一遍。

## 第 1 步：定结构（先骨架）

按"为什么它在链上"逐环节确认，而不是按印象罗列：

1. **上游原料**：本体的直接原料（通常 2–3 个），再往上追一层主要起始原料。
2. **中间体**：原料到本体之间的实际中间产物。
3. **溶剂 / 助剂**：工艺需要但**不进入分子**的投入——必须单独标出（生成器用虚线链接），否则读者会误以为它们按化学计量消耗。
4. **本体**：把不同牌号/规格归到同一节点，规格差异体现在 `rows` 里，不要为每个牌号画一个节点。
5. **下游应用**：现实的三大到五大应用方向，即使查不到价也要画出来（`role: application` + 缺口说明）。

结构必须能回答："这个环节为什么会影响本体价格？"答不上来的环节就别画。

**结构关系的证据等级**：通用工艺路径默认是**示意**（`conceptual`）；只有资料明确记载的传导关系才可标为有据。
不要因为"业内都知道"就把示意写成事实。

## 第 2 步：逐环节取价（每个数字一条记录）

- 一个环节一次取价，取回来的每条报价都进 `rows`，**原样保留地区、规格、日期、税制/提货方式与来源**。
- 同一环节多地区多规格时**不要平均**：把记录都列出来，节点上标一个代表值，并在 `basis` 里写明代表规则
  （如"华东主流、含税"）。代表值必须能在 `rows` 里逐字找到。
- 上游只取到"当日/区间"的，就照实写区间或当日值，不要自行推算月度均价。
- 价格趋势/历史接口拿到的序列，只用于说明**趋势**，不要拿它的点值去替代当日报价，除非两者口径一致。
- 单位不一致（元/吨 vs 元/公斤，美元 vs 人民币）时**分开成不同节点或不同表**，不要换算后混排（换算率同样是外部假设）。

## 第 3 步：把"没查到"变成正式内容

下列情况一律进 `gaps`，**不估算、不用 0 占位**：

- 接口观测数为 0（要写明这个事实作为 `evidence`）
- 需要更高权限 / 付费源
- 只在资讯里出现、没有结构化报价
- 明确"无货、暂无报盘、缺货"（这本身是市场信息，写在记录里，标 `missing: true`）

缺口写清楚 `scope`（哪个环节）+ `reason`（为什么没有）+ `evidence`（怎么确认的）。
一份好的交付物，缺口清单往往比价格表更能说明研究的严谨程度。

## 第 4 步：落数据

按 `references/data-contract.md` 写 `chain-data.json`。顺序建议：

1. `meta`（数据日、单位、来源）——先把口径钉死
2. `stages` / `nodes` 骨架 + `links`（此时 figure 已经能画出来）
3. 逐环节补 `rows`，最后回填 `price`
4. `tables`（资讯口径、替代品、参照品等不便混进主图的数据）
5. `gaps` / `notes`

## 第 5 步：校验 → 生成 → 再校验

```bash
python scripts/validate_dataset.py chain-data.json
python scripts/build_chain_html.py chain-data.json -o <product>-chain.html
python scripts/verify_html.py <product>-chain.html --source chain-data.json
node scripts/verify_render.js <product>-chain.html     # 可选
```

校验器报的每一条都要处理：要么改数据，要么改文案（版面预算超限只能缩文案）。
**不要为了通过校验而删掉真实记录**。

## 第 6 步：交付前自检清单

- [ ] 页面上每个价格都能在 `rows` 里逐字找到
- [ ] 每个有价环节都写了 `basis`（地区/规格/税则口径）
- [ ] 单位在 `meta.unit` 与每条记录上都不缺
- [ ] 查不到的环节都进了缺口清单，没有出现 `0`
- [ ] 没有跨地区/规格/币种的平均值或自算价差
- [ ] 产业链关系没有把示意写成事实
- [ ] HTML 是单文件、零外部资源（`verify_html.py` 会查）
- [ ] 聊天回复只给结论与文件链接，长论证在 HTML 里

## 第 7 步：交付话术

- 聊天里给一句核心判断 + 最多两条支撑/局限，然后给文件链接。
- 明确说明：数据日、单位、来源、以及本次没有取到的部分。
- 不要声称做了未做的核验；价格逐条来自原始记录，不等于第三方独立核验。
