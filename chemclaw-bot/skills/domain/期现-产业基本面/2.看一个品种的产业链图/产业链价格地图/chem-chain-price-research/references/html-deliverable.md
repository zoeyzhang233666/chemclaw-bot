# HTML 交付规范

交付物只有一个硬要求：**单文件、可以离线打开、数字可追**。其余（配色、文案）按品种调整。

## 页面结构（由上到下）

```
<header>            标题 + 数据日·单位·检索时间 + 一句话核心结论 + 交互提示
<ul class="legend"> 色块图例：上游 / 中间体 / 直接原料 / 本体 / 下游
<section.gaps>      「本次未取到授权价格的环节」缺口卡片（scope + reason + evidence）
<div class="stage"> 主图区：可横向滚动的 SVG + 右侧 sticky 详情面板 + 跟随鼠标的提示气泡
<section.tables>    「完整报价明细」检索框 + 按环节分组的 <details> 分组 + 附加明细表
<section.notes>     「口径、方法与缺口说明」：价格口径 / 结构口径 / 缺口口径 / 来源
```

这个顺序有意为之：**结论在上、证据在下、缺口单独可见**，读者不必滚动就能判断"哪些数字可信、哪些没有"。

## 交互（生成器已实现，不要删）

| 操作 | 行为 |
|---|---|
| 鼠标移到环节卡片 | 浮层显示该品种最新报价 + 口径 + 记录条数；同时高亮相邻关系 |
| 移到连线 | 显示关系标签与上下游名称 |
| 点击环节 | 右侧面板锁定该环节的完整报价清单（地区/规格/价格/日期/备注），可点击返回默认视图 |
| 明细区检索框 | 按关键词过滤所有分组与行 |
| 展开分组 | 每个环节的完整原始记录（默认折叠第一条） |

默认面板（未选中）显示数据日、单位与整链概览，不能是空白。

## 技术约束

- 零外部资源：不引 CDN、外链字体、图片、`<iframe>`；图标用内联 SVG path 或 CSS 画。
- 数据以 `<script id="chain-data" type="application/json">` 内联，前端脚本只渲染它；
  JSON 必须能被 `json.loads` 解析，`</` 需转义为 `<\/`。
- 静态 HTML 中直接写进标题、数据日、核心结论、缺口卡片与说明区，
  **即使 JS 完全不执行，读者仍能读到结论与缺口**——这是刻意的降级设计。
- 自适应：`svg { width: 100%; min-width: <画布宽>px }`，外层容器横向滚动；窄屏不压缩到不可读。
- 配色只区分"环节角色"，不表示涨跌；涨跌用文字表达，避免颜色误导。

## 版面

- 布局由 `scripts/chain_layout.py` 按 `stages` 分列计算，卡片宽度按文本自适应。
- 有价卡片高的固定 112 px，应用卡片按短句行数变化；同列卡片垂直居中。
- 多条连线汇聚到同一锚点时按数量均匀散开，避免箭头重叠。
- 卡片文本超宽会触发 `verify_html.py` 报错：**缩文案，而不是让它溢出**。

## 定制

改样式直接编辑 `build_chain_html.py` 里的 `PAGE` 常量（CSS）与 `APP_JS`（渲染逻辑）；
改配色改 `chain_layout.py` 的 `PALETTE`（每列 `fill/stroke/text/band` 四个色）。
两处都要保持"字号 → 字宽公式"一致，否则版面校验会失效。

## 命名与交付

- 文件名：`<product>-chain.html`（如 `sbs-chain.html`），数据文件 `chain-data.json`。
- 输出到会话工作区根目录，聊天里用 `[标题](artifact:相对路径)` 给出。
- 同时保留 `chain-data.json`：它是可复核、可复现、可交接的部分，页面只是它的视图。
- 聊天回复只给：一句核心判断 + 最多两条支撑/局限 + 文件链接；完整论证与明细留在 HTML 里。
