# 数据源适配与降级

这套流程不绑定任何一家数据源。不同 agent / 不同机器上能用的取数方式不同，
按下面的顺序尝试即可；**关键不是用什么工具，而是每条数字都要落成一条带来源的记录**。

## 取数优先级

### 1）宿主提供的化工数据工具（首选）
如果所在 agent 挂了化工数据类工具（如 ChemClaw 的数据工具集），一次研究通常需要三类查询：

| 需要什么 | 查询形态 | 落到 `rows` 的字段 |
|---|---|---|
| 某品种现货报价（多地区/多规格） | 按品种名查现货价格快照，例如 `get_compound_prices_live("丁二烯")` | `region` / `spec` / `price` / `date` / `unit` / `source` |
| 时间序列（判断趋势、当日区间） | 按品种查价格趋势，例如 `get_price_trend(...)` | 用于正文趋势描述或 `tables`，不替代当日报价 |
| 市场资讯（无结构化报价时的唯一线索） | 按品种查资讯/日报 | 写进 `tables`（资讯口径）并在 `note` 标明与报价口径不同 |

要点：
- 用**品种的行业叫法**去查（丁二烯、苯乙烯、纯苯、石脑油、SBS 干胶……），别名多试几次。
- 查到的结果如果是"每行一条地区报价"，就逐行进 `rows`；如果是"当日区间/文字描述"，
  就照实写成文字记录，不要自己取中点当价格。
- 查询返回 **0 条观测**（`observations: 0` / `data: []`）是有效结论 → 写进 `gaps`，并把接口返回作为 `evidence`。

### 2）联网检索（有网络时）
行业价格站、资讯网站的日报、上市公司公告都可以用，但要注意：
- 网页上的价格常常**没有明确单位、地区、税制**；能确认的写进 `note`，确认不了的就写"未提供"，
  不要默认成含税、现款、元/吨。
- 只引用能确认到日期的数字；同一天多个来源冲突时**都列出来**并注明来源不同，不要私下选一个。
- 资讯里的"某牌号送到价 14800–14900"是区间 + 送到口径，与"库提含税"不可混算。

### 3）用户自带数据（Excel / CSV / 截图里的表格）
先问清列含义（地区、规格、税制、日期、单位），再映射到 `rows`；
用户没说明的列**宁可不写也不要猜**，缺 `unit` 就补问。

### 4）什么也拿不到
仍然可以交付：产业链结构 + 每个环节的缺口说明 + 方法说明。
此时 `nodes[].role` 全部按 `application` 处理（无价格），
并在 `meta.headline` 与缺口区明确写出"本次未取得授权报价数据"。
**不要为了把页面填满而估算价格** —— 一份诚实的空价格图，比一份编出来的价格图有用。

## 降级矩阵

| 情况 | 页面表现 |
|---|---|
| 某环节有报价 | 卡片显示价格 + 口径，明细区给出全部记录 |
| 某环节只有资讯 | 价格位置显示"仅资讯口径，见明细"，资讯进 `tables` |
| 某环节需要权限/无数据 | 卡片显示 `gap_label`（如"本次无授权报价"），进缺口清单 |
| 明确"无货/暂不报价" | 作为记录写入（`missing: true`），图上不显示价格数字 |
| 完全没有价格数据 | 只出结构 + 缺口 + 方法说明 |

## 跨 agent 落地

同一份技能包在别的 agent 上跑时，只需要替换"第 1 步取数"：

- **ChemClaw / 有化工数据 MCP 的 agent**：直接用 MCP 工具，按上表三类查询。
- **Codex / 通用编码 agent**：通常没有专用数据工具，用它的联网检索能力或让用户提供数据文件。
- **WorkBuddy 等知识工作 agent**：同上，先问用户有没有内部数据源。

无论哪种情况，生成的 `chain-data.json` 与 HTML 完全一致——**数据来源变了，交付物结构不变**。

## 记录来源的最小要求

每条 `rows` 至少要能回答："这个数从哪来、哪天、什么口径"。
`source` 写工具名或网站名即可（如 `现货报价库`、`市场资讯`、`用户提供`），
不需要写长注释；口径写在 `note`，方法说明写在 `notes`。
