# 深度研究一家产业企业（chem-enterprise-deep-dive）

把「一家企业」变成一张**可被质证**的档案：主体是谁 → 股权归谁 → 生产什么、在哪产、多少产能 → 上游靠谁、下游给谁 → 有什么项目在动 → 有哪些公开风险 → 每条结论的证据是什么。

本 Skill 服务的业务场景（同一套数据，切换研究视角）：

| 场景 | `meta.purpose` | 首屏结论重点 |
|---|---|---|
| 我要采购它的货 | `supplier` | 有无资质与许可、实际产能够不够交付、在产/停产、异地基地与物流 |
| 它是我的客户 | `customer` | 它用这个产品做什么、用量与采购结构、装置工艺决定的需求刚性 |
| 它是我的竞争对手 | `competitor` | 产能与工艺路线、成本要素、区域覆盖、在建扩产节奏 |
| 产业基本面研究 | `industry` | 行业地位与份额、产能变化（在建/置换/退出）、供需与价格位置 |

## 0. 五条铁律（做错就等于没做）

1. **先消歧，再研究。** 任何产能、资产、资质必须先落到一个**法人主体**（统一社会信用代码）上。集团 ≠ 上市公司 ≠ 子公司 ≠ 分公司 ≠ 合营企业。近名主体必须逐个列表判定纳入/排除（见 `references/02-entity-disambiguation.md`）。
2. **经营范围 ≠ 实际生产产品。** 执照上的化工品种往往上百条，只有出现「产能/装置/环评/许可/产销表」证据的品种才算产品。
3. **集团资产不计入研究主体。** 关联方（控股股东、兄弟公司、同园区配套企业）的产能与装置必须单列并标注「不并表/不属研究主体」。
4. **不预测未来经营表现。** 不写「预计今年盈利」「明年产能释放后业绩弹性」，不推测非上市企业的营收与利润。公司自己披露的预测（预可研、效益测算）可以引用，但必须原样标注「公司测算口径，非本档案预测」。
5. **没有证据就写「无公开资料」。** 缺口要显式列出并给出核实途径（`gaps[]`），绝不用行业经验值冒充事实；确需估算时必须写 `estimate: true` + `basis`（公式与口径）。

## 1. 工作流（按顺序执行）

```
Stage 1  明确三件事：研究主体候选名 / 研究目的 / 时间窗口
Stage 2  主体消歧：锁定统一社会信用代码，列出全部近名主体并判定纳入或排除
Stage 3  分层取证：官方一手 → 企业自述 → 行业/媒体 → 交叉验证
Stage 4  建结构：主体—股权—工厂—装置—产品—项目 六维关联（先关系后数字）
Stage 5  填数字：产能/产量/价格/财务，每一格带证据编号与等级
Stage 6  出风险与事件：近12个月动态 + 公开可核实风险
Stage 7  写 data.json（规范见 references/03-data-schema.md）
Stage 8  跑脚本生成 HTML + Excel，做口径校验与结论抽检
Stage 9  交付并说明「已核实 / 无公开资料 / 待核验」
```

### Stage 1 必问/必定的三项

- **研究主体**：优先要全称或股票代码；若只给简称，先做消歧（例如「海化」可能指山东海化股份有限公司、山东海化集团有限公司、潍坊海化开发区某企业）。
- **研究目的**：决定后续章节权重（见上表）；不说明时默认 `industry`，但要在交付时写清视角。
- **时间窗口**：默认「截至今天回溯 12 个月」用于动态与事件；财务取最近 3 个完整年度 + 最近一期。

### Stage 2 主体消歧（最容易翻车的一步）

必须产出 `disambiguation[]` 表，一行一个候选主体，字段：名称 / 统一社会信用代码 / 与研究主体的关系 / 判定依据 / 是否纳入 / 证据。

判定动作：
1. 用年报或信用公示拿**统一社会信用代码**，作为唯一主键。
2. 把所有「同城 + 同行业 + 名称含相同字号」的企业都列出来，逐个说明为什么不是它。
3. 分公司（`XX厂`）无独立法人资格，计入母公司产能。
4. 持股 50% 以上但**章程约定共同控制**的合营企业，按权益法处理、**不并表**，产能不得计入。
5. 名称中带「集团」的，默认是母公司；其分子公司资产要单列。

### Stage 3 分层取证顺序（证据等级由来源决定）

| 等级 | 含义 | 典型来源 |
|---|---|---|
| A | 官方一手 | 交易所公告/年报/招股书、政府部门公示（环评、能评、安许、排污、信用中国）、证照原文、法院/执行公开信息 |
| B | 多源或企业自述 | 企业官网/官微的产能与装置介绍、两家以上独立媒体一致报道 |
| C | 单一二手来源 | 单家媒体报道、行业资讯网、聚合平台字段 |
| D | 本档案估算 | 由公开数据直接计算（须写 basis），非披露值 |
| NA | 无公开资料 | 检索后未找到；必须进 `gaps[]` |

检索入口与话术见 `references/01-playbook.md`（含巨潮公告、环评公示、证照、产能、股权、项目的具体查法）。

### Stage 4 六维结构（先建关系，再填数字）

```
实际控制人 → 控股股东（集团） → 研究主体（上市公司/有限公司）
                                   ├── 分公司：XX厂（无独立法人，产能在母公司）
                                   ├── 全资/控股子公司（并表）
                                   ├── 合营/联营（权益法，不并表）
                                   └── 同集团兄弟公司（不属研究主体，易混淆）
```

每一层都要回答：**它的产能算谁的？** 在 HTML 里用节点样式区分「研究主体/国资股东/并表子公司/参股合营/同集团易混淆」。

### Stage 5 填数字的规矩

- 产能只认三种口径，且必须标明：`设计产能`（年报/环评/安评）、`实际产量`（年报产销表）、`企业自述产能`（官网）。
- 一个产品可能有多个产能口径（如「规模240万吨、生产面积口径160万吨、现能力150万吨」），全部并列，不做取舍。
- 价格与成本要带单位、含税口径、时间区间与来源，不要给单一「均价」。
- 财务至少覆盖：营收、归母净利、扣非、经营现金流、总资产、净资产、EPS、ROE，以及**分产品收入/毛利率**、前五大客户与供应商集中度。

### Stage 6 风险与事件

风险只写公开可核实的事实并给状态（`ok / warn / risk / todo`），不做评级、不推断后果。必查清单：
行政处罚、安全/环保事故与整改、诉讼仲裁、被执行/失信、许可到期日、质押冻结、关联交易规模与占比、担保余额、减值与资产核销、停产与复产、管理层变动。

### Stage 8 渲染与自检

```bash
python scripts/build.py data.json -o output --strict
```

- `--strict`：证据编号对不上台账、等级非法、估算缺 `basis` 时直接失败。
- 产出：`企业深研_{公司}_{用途}.html` 与 `企业深研_{公司}_{用途}.xlsx`（缺 openpyxl 时自动降级为同名 CSV 系列）。
- 自检清单见 `references/05-qa-checklist.md`；交互回归可用 `scripts/_shot.py`（CDP 无头校验，需 `--no-sandbox`）。

## 2. 交付物规格

### 2.1 HTML 档案（单文件、可离线、可打印）

固定 12 个区块，顺序即阅读顺序：

1. **Hero**：公司全称、一句话定位、统一社会信用代码、上市信息、研究目的、检索窗口、4–6 个关键数字
2. **主体信息与消歧**：工商登记字段 + 同名主体消歧表
3. **研究结论**：该场景下 4–6 张结论卡（问题 → 答案 → 理由 → 等级 → 证据）
4. **关键指标**：产能/产量/财务 KPI 卡
5. **股权与关联关系**：可交互股权树 + 同集团易混淆主体表
6. **产品、产能与工艺**：产业链五泳道图 + 每个产品的产能口径卡
7. **生产基地与区域布局**：SVG 全国示意图（点选联动基地卡片）+ 基地清单表
8. **项目清单**：在建/拟建/已投产，含投资额、资金来源、时间节点
9. **财务与分业务**：多期对比表 + 口径提示
10. **公开风险与合规记录**：风险表 + 无公开资料/待核验清单
11. **近 12 个月重要动态**：时间线
12. **证据台账 + 全量结论筛选器**：按产品/地区/主体/证据等级/关键词过滤任意结论

交互要求：点击任意 `E编号` 从右侧滑出证据抽屉（含原文摘录与原链接）；地图标记与基地卡片双向联动；筛选栏吸顶。

### 2.2 Excel 台账（17 Sheet）

`01_使用说明`（研究主体、口径约定、免责声明、校验告警数）、`02_企业主体信息`、`03_主体消歧`、`04_股权结构`、`05_子分公司`、`06_生产基地`、`07_装置清单`、`08_产品与产能`、`09_生产工艺`、`10_产业链位置`、`11_区域布局`、`12_项目清单`、`13_财务与分业务`、`14_经营风险`、`15_重要事件`、`16_证据台账`（URL 自动超链接）、`17_待核验清单`。

每张表都带 `证据编号` 列，`证据编号` 与 `16_证据台账` 一一对应，可反查原文。

## 4. 快速开始

```bash
# 1) 复制案例作为起点
cp examples/example-1-shandong-haihua-soda-ash/data.json ./my-company.json

# 2) 按 references/03-data-schema.md 逐字段替换（证据先进 evidence[]，正文只写 E 编号）

# 3) 渲染并严格校验
python scripts/build.py my-company.json -o output --strict

# 4) 打开 output/企业深研_{公司}_{用途}.html 与 .xlsx 交付
```

依赖：Python 3.9+，`openpyxl`（Excel 必需，缺失时降级 CSV）。HTML 无外部依赖。

## 5. 常见错误（照抄可避免 80% 返工）

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 把集团产能写成上市公司产能 | 产能虚高一倍 | 逐主体核对持股与合并范围 |
| 把 51% 合营按子公司并表 | 财务与产能都错 | 看章程/董事会表决机制，权益法则不并表 |
| 把经营范围当产品清单 | 报告不可信 | 只收有装置/产能/许可证据的品种 |
| 用「上半年均价」代表全年 | 价格结论失真 | 标明区间与口径，或并列上/下半年 |
| 分地区收入合计对不上总额 | 口径混淆被质疑 | 标注「披露格式差异，不加总」，不做强行归一 |
| 无证据处留空 | 读者无法判断 | 写「无公开资料」并进 `gaps[]` |
| 写「预计明年扭亏」 | 违反不预测原则 | 只引用公司披露并标注「公司测算，非本档案预测」 |
| 证据只留一句「公开资料」 | 无法溯源 | 一条 URL + 发布方 + 日期 + 原文摘录 |

## 6. 何时该停手

满足以下条件即可交付，不要为了「更完整」而编造或无限延长：九个必答章节全部有结论（含「无公开资料」结论）、每条结论有证据编号、缺口清单已罗列并给出核实途径、口径冲突已显式说明。
