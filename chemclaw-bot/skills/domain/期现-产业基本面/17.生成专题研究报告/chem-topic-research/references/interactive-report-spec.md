# 交互式 HTML 报告规范

## 一、形态

单文件、离线可用、无外部依赖（图表为内联 SVG，不加载 CDN）。双击即可打开，可直接邮件转发。

## 二、首屏（最重要的 800px）

必须回答三件事：

1. **这是什么**：标题 + 受众 + 报告日 + 数据截止。
2. **结论是什么**：6–8 个 KPI（数值 + 单位 + 变化），核心结论卡片按重要性排序。
3. **能信到什么程度**：类型（事实/计算/解释/判断）、置信度、证据数与计算数、缺口数一目了然。

KPI 卡片点击 → 展开证据与计算。结论卡片点击 → 侧栏显示"支撑证据 → 计算过程 → 反证条件"。

## 三、四条交互链（少了就不叫交互式）

| 交互 | 触发 | 结果 |
| --- | --- | --- |
| 结论 → 证据 | 点结论卡片 | 侧栏：证据卡片（机构/标题/日期/口径/链接）+ 计算过程（公式/参数/结果）+ 反证条件 |
| 图表 → 原始数据 | 点"查看原始数据" | 弹窗：全量数据表 + 数据来源 + 该图支撑的结论；可复制为 TSV 粘到 Excel |
| 章节 → 排序 | 点"调整章节顺序" | 章节可拖动，顺序存 localStorage，刷新后保留，可一键还原 |
| 报告 → 导出 | 点"导出" / "打印" | 生成完整 Markdown；或浏览器打印为 PDF（已写 @media print） |

## 四、三个视图

- **研究报告**：正文
- **研究框架**：所有受众的章节设计对照（为什么/验证什么/依赖数据），用于评审研究设计
- **证据总表**：来源与缺口 → 被引用位置；计算过程；缺口清单

## 五、图表规范

- 每图必须有：标题、来源（S 编号）、一句 note（口径/读法）、关联结论按钮、原始数据入口。
- 图型选择：结构用堆叠柱/环形；趋势用折线；区间用区间条；扣减过程用水瀑布图。
- 缺数据时显示"该数据集为空或缺失"，**不要画成 0**。
- 颜色语义固定：绿=正向/低成本，红=负向/高成本，蓝=总量，橙=在建/风险，紫=规划。
- 坐标轴标签过长要截断并加 tooltip。

## 六、可访问性与打印

- 打印样式：隐藏控制栏/侧栏/弹窗，去掉深色背景，避免章节跨页断裂。
- 快捷键：Esc 关闭面板，1/2/3 切视图。
- 文字对比度满足深色底阅读；正文 ≥13px。

## 七、实现要点（给维护者）

- 模板 `scripts/templates/report.html`，占位符只有 `__TITLE__` 与 `__DATA__`。
- 数据通过 `<script type="application/json">` 注入，用 `common.safe_json` 转义（防 `</script>` 注入）。
- 启动分步 try/catch，单模块失败不拖垮整页，并在页面底部显示"渲染警告"。
- 单图渲染失败只在图中显示错误，不影响其他图。
- QA 用 `qa_dom.mjs` 检查：JS 异常、图表渲染数、面板/弹窗/视图切换是否可用。

## 八、验收

```bash
node scripts/qa_dom.mjs 报告.html
```

必须输出 `QA PASS`：图表全部渲染、证据面板可打开且含反证条件、原始数据弹窗有行、三视图可切换、0 JS 异常。
