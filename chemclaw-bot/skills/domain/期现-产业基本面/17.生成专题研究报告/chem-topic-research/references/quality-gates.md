# 质量验收清单

交付前逐项打勾。任何一项未过，都要在交付说明里写明，不得隐瞒。

## A. 结构与可追溯（机器可查）

| # | 检查项 | 通过标准 | 怎么查 |
| --- | --- | --- | --- |
| A1 | case 校验 | 错误 0 | `python scripts/common.py validate case.json` |
| A2 | 引用均已登记 | 无 "未登记" 来源 | 同上 + `01_证据索引` |
| A3 | 来源均被引用 | 无 0 引用的来源 | `12_质量自检` 中"无未引用来源"= PASS |
| A4 | 结论可追溯 | 每条结论有 ≥1 证据 ID | `08_结论` |
| A5 | 判断/解释有反证条件 | 100% 覆盖 | `12_质量自检` |
| A6 | 项目三态合规 | 状态 ∈ {已投产,在建,规划,退出,暂停}，且都有依据 | `04_项目台账` |
| A7 | 缺口已登记 | 每项有 next_step | `10_资料缺口` |
| A8 | 图表数据可解析 | 每个 data_key 有数据 | `12_质量自检` |
| A9 | KPI 数量 | 4–10 个，且至少 1 个挂计算 | `00_使用说明` |
| A10 | 工作簿完整 | 13 页齐全、无空表 | `python scripts/qa_xlsx.py` |

## B. 页面质量（机器可查）

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| B1 | JS 无异常 | `qa_dom.mjs` 输出 JS 异常 0、控制台错误 0 |
| B2 | 图表全部渲染 | `图表 n/n 已渲染` |
| B3 | 结论下钻可用 | 证据面板打开且含"反证条件" |
| B4 | 图表下钻可用 | 原始数据弹窗有数据行 |
| B5 | 三视图切换 | 研究报告 / 研究框架 / 证据总表 均可显示 |
| B6 | 章节排序可用 | 进入排序模式后章节可拖动 |

## C. 内容质量（人工判断）

| # | 检查项 | 不合格表现 |
| --- | --- | --- |
| C1 | 首屏能读懂结论 | 首屏只有背景介绍，没有结论 |
| C2 | 每章都有存在理由 | 某章可整段删除而不影响结论 |
| C3 | 没有行业百科式填充 | 大段介绍工艺/用途却与结论无关 |
| C4 | 数字都有口径 | 出现"约""左右"却不说明来源 |
| C5 | 没有把预计投产当新增供给 | 直接用工名义产能加总得结论 |
| C6 | 口径冲突已处理 | 跨口径相减、混用两机构库存 |
| C7 | 需求侧有约束分析 | 只谈供给不谈下游 |
| C8 | 有历史类比且检验可比性 | 只画两条曲线不作说明 |
| C9 | 结论有决策含义 | 读完不知道要做什么 |
| C10 | 缺口影响被量化 | 只说"数据有限"不说不限量级 |
| C11 | 措辞克制 | "必将""势必""毫无疑问" |
| C12 | 受众适配 | 管理层版出现公式堆砌，研究员版没有口径 |
