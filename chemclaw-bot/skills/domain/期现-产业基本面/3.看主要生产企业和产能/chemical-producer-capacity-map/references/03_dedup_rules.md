# 03 · 重复统计校验规则手册（R1–R14）

`build/pcd_model.py` 中的 `DupChecker` 实现了以下 14 条规则。
本文说明每条规则的**设计意图、触发条件、真实案例与处理方式**。

严重级别：`ERROR`（必须清零）/ `WARN`（必须逐条说明）/ `INFO`（记录即可）

---

## R1 · 孤儿装置（orphan units）

**级别** ERROR　**触发** 装置的 `plant_id` 或 `entity_id` 在数据集中不存在

**为什么重要**：归属链断裂的装置无法归入任何集团/省份，会导致汇总漏计，
且往往是复制粘贴时 ID 拼错。

**处理**：补建基地/法人，或删除该装置。

---

## R2 · 孤儿基地（orphan plants）

**级别** ERROR　**触发** 基地的 `entity_id` 不存在

**处理**：同上。

---

## R3 · 坐标缺失

**级别** WARN　**触发** 基地无 `lat/lon` 或超出中国经纬度范围（lon 73–136, lat 17–54）

**为什么重要**：地图上会丢点，读者以为该地没有产能。

**处理**：至少补到省级/城市级坐标，并如实标注 `coord_precision`。

---

## R4 · 疑似重复装置

**级别** WARN　**触发** 同一 (基地, 口径, 年份, 工艺, 产品) 下有多条装置记录

**为什么重要**：这是**同一装置被两个来源各录一次**的典型信号，
相加后产能虚增一倍。

**真实案例（PVC）**：

```
[ERROR] R4 P100 疑似重复装置：U-P100-01, U-P100-02 具有相同的
        (基地P100, 口径design, 年份2025, 工艺ethylene, 产品聚氯乙烯树脂（悬浮法）)
```

天津渤化：集团官网写「PVC 80 万吨」，另一来源写「二期 40 万吨」。
若两条都按 design/2025 录入，合计 120 万吨 —— 实际总产能是 120 万吨，
但 80 万吨里已经包含了一期 40 万吨 + 二期 40 万吨，直接相加会得到 160 万吨。

**处理**：确认是「一个装置的多个来源」还是「多个真实装置」。
- 前者：保留一条，另一条写进 `capacity_note` 的替代口径
- 后者：拆分产品名/投产年份使二者可区分

---

## R5 · 口径混用

**级别** ERROR　**触发** 同一汇总内出现多种 `basis`

**为什么重要**：design 与 actual 相加是无意义的数字。

**处理**：汇总时按 basis 分组，或用 `Aggregator(basis=...)` 指定。

---

## R6 · 来源缺失

**级别** ERROR　**触发** 装置引用的 `source_id` 不存在于来源表

**处理**：补建来源条目（含 URL、日期、发布机构、可信度）。

---

## R7 · 产能缺失

**级别** WARN　**触发** 装置 `capacity` 为 null

**为什么重要**：**这不是错误，是诚实。** 但同时必须登记进数据缺口表，
否则读者不知道这里漏了东西。

**处理原则**：
- 保留 `null`，`capacity_note` 写明为什么没有
- 登记进 `16_数据缺口`，注明补齐路径与优先级
- **绝对不要**用行业均值、同类装置规模、按基地数量平摊来填空

**真实案例**：中泰化学年报只披露合并口径 260 万吨，不拆到米东/阜康/托克逊/圣雄各厂。
四条厂级装置行的 capacity 全部为 null。

---

## R8 · 工艺路线未核实

**级别** WARN　**触发** `route = unknown`

**为什么重要**：工艺是 PVC 分析的核心维度。把 unknown 强行并入电石法或乙烯法，
会让工艺占比失真。

**处理**：在工艺汇总中单列为「未核实」，不计入电石法/乙烯法占比的分母。

---

## R9 · 集团级与装置级双重计数

**级别** ERROR / INFO　**触发** 同一集团既有一个「集团总计」装置，又有分厂装置

**为什么重要**：这是最经典的重复统计。

**真实案例**：若把天业集团的宣传口径「140 万吨 PVC」录成一条集团级装置，
又把新疆天业上市公司的 134 万吨按厂拆开录入，合计 274 万吨 —— 虚增一倍。

**处理**：数据集中**只保留最细粒度**的装置记录。集团合计由 `Aggregator.by_group()` 实时计算，
不落库。

R9 的另一用途：检测多个基地共用同一注册地址（INFO 级），提示是否同一厂区被拆成两条。

---

## R10 · 项目与存量装置重复

**级别** WARN　**触发**
- 已 `operating` 的项目，若存量层查不到同规模装置 → 可能漏计
- 非 `operating` 的项目，若存量层已有同工艺同产能装置 → 可能重复计

**为什么重要**：项目表和装置表是两个独立的表，很容易两边都记一次。

**真实案例**：

```
[WARN] R10 PR09 项目「广西华谊钦州 PVC 二期 40 万吨/年」阶段为「已运行」，
       应已并入存量；请确认存量装置已录入，且不在增量中重复计。
```

**处理**：`operating` 的项目必须在装置层有对应记录（同基地、同规模）；
项目表的 `operating` 记录仅作**历史事件档案**，不参与增量汇总。

---

## R11 · 置换未扣减

**级别** WARN　**触发** 项目 `replacement_note` 暗示存在置换，但 `retired_capacity` 为 null

**为什么重要**：中国产能置换政策下，新建往往要求先关停等量旧产能。
不扣减会把「净新增」算成「毛新增」，高估供给扩张。

**真实案例**：

```
[WARN] R11 PR01 项目「年产96万吨聚氯乙烯项目」的置换情况为「未查到置换方案」
       但未填写 retired_capacity，毛新增会被当作净新增，导致增量高估。
```

**处理**：
- 查到置换方案 → 填 `retired_capacity`
- 查不到 → `net` 记 null，HTML/Excel 显示「待确认」，**不进基准预测**
- 明确净新增的项目（`replacement_note` 以「净新增」开头）不触发本规则

---

## R12 · 量纲异常

**级别** ERROR / WARN　**触发**
- ERROR：`capacity > 1000`（应为万吨/年，误填吨/年）
- WARN：`0 < capacity < 1`（过小，确认是否小试/中试装置）

**为什么重要**：吨与万吨混用是最高频的数据事故，且一眼看不出。

**处理**：统一为**万吨/年**。

---

## R13 · 可信度与来源等级不一致

**级别** INFO　**触发** 装置自评 `confidence` ≠ 来源 `confidence`

**为什么重要**：通常是有意的人工降级，需记录理由。

**真实案例**：

```
[INFO] R13 U-P041-01 装置 U-P041-01 自评可信度 B 与来源 S08 等级 A 不一致
```

原因：湖北宜化年报（A 级）说新疆宜化新增 PVC 30 万吨，但该厂安全许可证未单列
「聚氯乙烯」条目 —— 由此人工降级为 B。

**处理**：在 `raw` 或备注中写明降级理由。

---

## R14 · 名称碰撞

**级别** WARN　**触发** 两个法人/集团名称规范化后相同

**为什么重要**：同一主体建了两个 ID，分别录了产能，会被合计两次。

**真实案例**：

```
[WARN] R14 E010 法人名称规范化后相同（新疆天业）：['E010', 'E301']，可能造成重复统计
```

E010 是新疆天业股份有限公司（上市），E301 是新疆天业（集团）有限公司（控股股东、非上市）。
两者名字高度相似但是不同主体 —— 属于**误报**，但必须人工确认。

**处理**：确认是同名不同主体（→ 在 `short_name` 上加区分标记，如「天业集团（非上市）」）
还是真重复（→ 合并）。

---

## 校验工作流

```bash
python build/assemble.py
```

输出末尾的校验段。推荐处理顺序：

1. 先清 **ERROR**（R1/R2/R5/R6/R9/R12）
2. 再逐条看 **WARN**，决定「改数据」还是「在报告里说明」
3. **INFO** 扫一眼，把有价值的写进报告备注

**交付标准**：ERROR = 0；WARN 每条都有处置说明；INFO 已归档。

## 添加新规则

新规则写在 `pcd_model.py` 的 `DupChecker` 中，命名 `rNN_英文短名`，
用 `self.add(rule, severity, subject, message, fix)` 登记。
`run()` 会自动按方法名排序执行。
