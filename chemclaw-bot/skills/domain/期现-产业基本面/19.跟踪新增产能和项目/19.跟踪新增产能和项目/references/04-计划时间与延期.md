# 04 · 计划时间与延期

"这个项目什么时候投产"是整份研究里最被追问、也最容易出错的问题。本文给出**不覆盖历史、可回溯、可审计**的处理方法。

## 一、两段式计划时间

任何项目的预计投产时间，都要同时记录两个值：

- **`first_plan_date` 首提预计投产** —— 项目第一次给出明确投产口径时说的话
- **`latest_plan_date` 最新预计投产** —— 目前能拿到的最新口径

**铁律：`first_plan_date` 写入后永不修改。**

`latest_plan_date` 可以更新，但**每一次更新都必须在 `progress.json` 里追加一条带 `plan_change` 的记录**，
写明变更前、变更后、依据、来源。

### 为什么不能只留一个值

如果只保留"最新预计投产"，会发生三件坏事：

1. **无法判断延期。** 没有基线，就不知道现在这个时间是提前还是推迟了
2. **无法追溯谁说的。** 出问题时不知道是哪家机构、哪个口径
3. **无法复盘判断质量。** 一年后回头看，不知道自己当初的判断错在哪、为什么错

> 案例中利华益维远的记录最能说明问题：
> 首提 2023-10（"8 月中交、10 月投产"口径）→ 最新 2026-09（行业口径）→ 延期约 35 个月。
> 而公司 2026-04-27 的原话是"已建设完成，**择机安排试生产**"。
> 这条 35 个月的延期曲线 + 那句"择机"，共同构成了"该装置开车由价差而非工程决定"的结论。
> 如果只留一个"最新预计 2026-09"，这个洞察就完全丢失了。

## 二、变更记录的标准写法

```json
{
  "progress_id": "PG-P1-001-11",
  "project_id": "PP-P1-001",
  "stage": "试车",
  "fact_date": "2026-09-15",
  "msg_date": "2026-09-21",
  "plan_date_noted": "2026-11",
  "plan_change": "延期",
  "plan_from": "2026-08",
  "plan_to": "2026-11",
  "desc": "截至2026年9月中旬，55万吨/年PP-H/R与40万吨/年ICP PP装置均测试开车一次成功...；漳州市发改委口径为2026年11月全面投产",
  "evidence_grade": "A",
  "source_ids": ["SRC-104", "SRC-105", "SRC-110"],
  "note": "相对'8月投产'目标延后约3个月"
}
```

四个必填：`plan_change`、`plan_from`、`plan_to`、`desc`（说明依据）。

## 三、四种 `plan_change` 的区别（最易误判）

| 类型 | 含义 | 是否算延期 | 处理 |
|---|---|---|---|
| `首次` | 第一次给出明确口径 | — | 成为 `first_plan_date` |
| `明确到月` / `明确到年` | 精度提高，但目标未必变了 | ❌ **不算** | 单独标记，避免误判 |
| `延期` | 目标确实往后推 | ✅ 算 | 填 from/to，并分析原因 |
| `提前` | 目标往前推 | ✅（反向） | 需核实是否因并线、试车顺利或口径调整 |

### 精度变化的陷阱

案例：古雷乙烯项目

- 2024-01 FID 时口径：`2026年内`（精度：年）
- 2026-04 目标：`2026-08`（精度：月）
- 2026-09 实际口径：`2026-11`（精度：月）

从"2026年内"到"2026-08"是**精度提高**，不是提前也不是延期——2026-08 本来就在"2026年内"里。
但从"2026-08"到"2026-11"是**真延期**，约 3 个月。

**如果混淆这两者，会得出"这个项目先提前后延期、反复无常"的错误结论。**

### 同一项目的不同生产线可能有不同的计划

古雷 40 万吨线与 55 万吨线：55 万吨线 2026-04-26 中交（比合同节点提前 35 天），
但整个项目"全面投产"的口径是 2026-11。单条线的中交≠项目整体投产。

**处理**：`first_plan_date` / `latest_plan_date` 填**项目整体**的口径；
单条线的进度写进 `desc`。

## 四、延期判定的三步法

### 第一步：确认"原计划"确实存在

**很多"延期"是被编出来的。** 行业资讯常写"原计划 X 月投产，推迟至 Y 月"，
但这个"原计划"在原始文件里根本找不到。

案例：某行业资讯称"东明盛海 PP 原计划 2026 年 6 月投产，推迟至四季度"。
核查结果：

- 环评公示（2024-06）未给投产时间
- 人民网施工通稿（2025-06）未给投产时间
- 2026-01 的行业资讯该项目仍列为"土建施工"阶段

→ **2026 年 1 月还在土建，6 月投产在工程上不可能成立。这个"原计划"无来源支撑，不予采信。**

**判定方法**：拿不到一手来源的"原计划"，一律不作为延期依据，只作为"该说法存疑"记录进 `dup_note`。

### 第二步：量化延期幅度

```
延期月数 = (最新预计投产 − 首提预计投产) 的月数
```

**必须注明这是"口径延期"，不等于工程实际延误。** 两者可能差很多。

### 第三步：区分原因（决定结论的性质）

| 原因 | 特征 | 对结论的含义 |
|---|---|---|
| **工程原因** | 设备安装滞后、施工事故、供应链问题、技术首套放大 | 延期是必然的，但终点可预期 |
| **市场原因** | "择机""结合供需""视市场情况" | **时间不可预测**，不能用工程进度推断 |
| **审批原因** | 环评/核准卡住 | 取决于政策，不可预测 |
| **资金原因** | 投资缩减、项目停工、主业亏损 | 有取消风险 |
| **口径原因** | 不同机构对同一项目给不同时间 | 不是真延期，是信息质量差 |

> 市场原因最容易被忽略，但后果最严重。
> 利华益维远"已建成但择机试生产"——装置的物理状态是"可开车"，
> 但时间完全由一个商业判断决定。这种情况下给任何"预计投产时间"都是不负责任的。
> 正确处理：`latest_plan_date` 保留行业口径，但在 `uncertainty` 里明确写
> "开车与否完全取决于公司对价差的判断，不应给出确定性投产预期"。

## 五、`delay_flag` / `delay_months` 的填法

```json
"delay_flag": "是（约3个月）",
"delay_months": 3
```

| delay_flag 取值 | 何时使用 |
|---|---|
| `否（按期/略提前）` | 延期 ≤ 1 个月 |
| `是（约N个月）` | 明确延期 |
| `无法判断` | 无首提计划，或首提计划本身不可信 |
| `口径未变，但进度存在实质延期风险` | 计划没改，但工程证据显示不可能达成（如荣信：设备安装仅 12% 却报年底出产品） |

最后一种最需要警惕——**计划没变，不等于没有问题**。这类项目会进入"隐性供给缺口"。

## 六、从"计划"到"供应"的三道折扣

判断一个项目能不能在**某个具体年份**形成供应，要连续过三道关：

```
第 1 关：工程关 —— 这个年度的工程进度支持投产吗？
        ├─ 不支持 → 进入"隐性供给缺口"（判定规则见 05 篇）
        └─ 支持 → 继续

第 2 关：开车关 —— 装置会真的开起来吗？
        ├─ 有"择机/视市场"表述 → 时间不可预测，标注风险
        ├─ 历史上该企业有建成不开车的先例 → 打问号
        └─ 无风险信号 → 继续

第 3 关：爬坡关 —— 即使开车，当年能贡献多少量？
        └─ 新装置 1-3 个月爬坡，首年实际产量通常仅为设计产能的 40%-70%
```

**三道关都过，才能说"这个产能会在当年形成供应"。** 只过第 2、3 关不过第 1 关的，就是隐性缺口。

## 七、延期信息的检索时机

延期消息往往不在正式公告里，而是藏在：

1. **季度业绩说明会**（投资者关系问答）——"择机""按市场需求安排"这类表述最先出现在这里
2. **年报/半年报的"在建工程"科目**——工程进度 100% 但未转固，说明建成了没开车
3. **政府月度/季度经济运行会议纪要**——地方统计口径的"计划年内投产项目"名单
4. **施工承包商的中标/结算公告**——工期变化会反映在这里
5. **下一次环评/变更环评**——产能或方案调整会重新走环评

> 案例中最强的一条证据来自年报监管工作函回复：
> "60万吨/年丙烷脱氢及20万吨/年高性能聚丙烯项目"期末账面金额 4.80 亿元、**期末工程进度 100%、尚未进行转固**。
> "工程进度 100% + 未转固"这个组合，是"建成未开车"的财务指纹。
