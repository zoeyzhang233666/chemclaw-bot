# 03 · 进展阶段与证据

本文回答：**一个项目"到哪一步了"怎么判定**、**证据够不够硬**、**记录怎么写**。

## 一、阶段枚举（严格单调）

从早到晚，共 12 个正常阶段 + 2 个异常阶段：

| # | 阶段 | 判定标准（必须满足才可写入） | 能否计入有效供应 |
|---|---|---|---|
| 0 | 拟建 | 有明确的投资意向/签约，但无任何政府批文 | ✗ |
| 1 | 备案 | 取得投资项目备案证，或有备案公示 | ✗ |
| 2 | 环评受理 | 环评报告书被生态环境部门受理并公示 | ✗ |
| 3 | 环评批复 | 取得环评批复文件（有文号） | ✗ |
| 4 | 核准 | 取得发改委核准批复（政府核准类项目） | ✗ |
| 5 | 开工 | 开工仪式/首罐混凝土/桩基开工 | ✗ |
| 6 | 建设 | 土建施工中 | ✗ |
| 7 | 设备安装 | 主要设备开始安装，或框架封顶转入安装 | ✗ |
| 8 | 中交 | 机械竣工、中间交接（施工完成，移交生产单位） | ✗ |
| 9 | 试车 | **已投料开车/已产出过合格品**，但未连续稳定运行、未常规销售 | ✗（关键分界） |
| 10 | 投产 | 已连续生产、产品进入常规销售 | ✓ |
| 11 | 达产 | 完成高负荷标定、达到设计负荷 | ✓ |
| 12 | 运行 | 长期正常运行 | ✓ |
| −1 | 暂停 | 明确中止或无限期搁置 | ✗ |
| −2 | 取消 | 项目终止 | ✗ |

### 三条判定纪律

**1. `stage` 取最新一条有证据的进展事实，绝不凭计划推定。**

一个项目环评批复在 2022 年、计划 2026 年投产、但 2026 年 3 月的最新事实是"设备安装"，
那 `stage` 就是"设备安装"，不是"建设中"更不是"投产"。

**2. "中交"不等于"投产"，"试车"不等于"形成供应"。**

这三个词在中文语境里极易混用。严格区分：

- **中交（机械竣工）**：施工完成，装置交钥匙了。还没进料。案例：镇海二期 2024-12-19 全面机械竣工，5#PP 到 2026 年还没确认开车
- **试车（单机/联动/投料）**：进料了，动起来了，可能产出过合格品。案例：中煤榆林 2026-08 产出第一粒 PP 颗粒
- **投产（出合格品并常规销售）**：连续运行、产品卖给客户了。案例：塔里木二期 2026-10-15 全面商业运营

**3. 阶段倒挂必须解释。**

时间线上如果"投产"之后又出现"环评受理"，只有两种可能：
并线项目（不同生产线进度不同）、或记录错误。校验会告警，必须人工复核。

## 二、证据分级（与 01 篇一致，此处讲实操）

| 等级 | 定义 |
|---|---|
| A | 一手权威：企业公告/定期报告、环评批复与公示原文、政府核准或备案文件、企业官方发布 |
| B | 一手转载或专业数据库：权威媒体对一手文件的完整转述、专业机构数据库、券商研报 |
| C | 二手行业资讯：资讯网站、自媒体的整理与转述 |
| D | 弱证据：百科、自媒体汇编、论坛帖子 |

### 三条硬规则

**规则 1：只有 A/B 级证据能支撑"已试车/已投产"级别的判断。**

C 级能做线索、能证明"有人在这么说"，但不能作为事实基准。
如果某项目的"已投产"只有 C 级来源，正确处理是：`stage` 停在"设备安装/中交"，
并在 `dup_note` 写"投产状态仅见行业资讯，需补证"。案例中广西石化 40 万吨 PP 即如此处理为"投产（需补证）"。

**规则 2：自评等级不得高于其来源的最高等级。**

一条记录声称"证据等级 A"，但它引用的全部来源都是 C——这是造假或误判。校验会直接告警。
如果一条记录综合了 A 级和 C 级来源，等级取 A（因为 A 级已足以支撑）。

**规则 3：等级判定看"文件的原始性"，不看"网站的权威性"。**

`新华网` 转述某企业通稿 → B（因为转述）；`生态环境部` 网站上的批复原文 → A。
`sasac.gov.cn` 转央广网的报道 → 政府背书，可判 A 或 B，但必须注明是转载。

## 三、事实日 vs 消息日（本方法最有用的一个小设计）

每条记录两个日期：

- **`fact_date` 事实发生日期**：事情本身是哪天发生的
- **`msg_date` 消息日期**：这条消息哪天发布的

**为什么要分开**：

1. **衡量信息滞后。** 两者之差就是"这个消息离真相有多远"。滞后超过 1 个月的，引擎会提示复核
2. **正确排序时间线。** 用 `fact_date` 排序才能还原真实的工程节奏；用 `msg_date` 会得到"媒体节奏"
3. **发现"旧闻新炒"。** 一条 2024 年的中交消息在 2026 年被重新发布，用两个日期一对比立刻现形

**典型场景**：

| fact_date | msg_date | 解读 |
|---|---|---|
| 2026-04-26 | 2026-04-26 | 当日通稿，最可靠 |
| 2026-03-27 | 2026-04-01 | 滞后 5 天，正常 |
| 2025-12-25 | 2026-09-28 | 滞后 9 个月，是回顾性报道，需判断是否还有效 |
| 2026-05-05 | 2026-03-05 | **fact > msg**，异常，必是记录错误或预发布 |

## 四、负结果记录法 ★

**"截至某日，未检索到某事项的任何公开报道" 本身就是一条有价值的进展记录。**

这是本方法区别于普通项目表的关键设计。它把"没有证据"和"没查过"区分开了。

写法：

```json
{
  "progress_id": "PG-P1-008-05",
  "project_id": "PP-P1-008",
  "stage": "试车",
  "fact_date": "2026-10-20",
  "msg_date": "2026-10-20",
  "desc": "★信息缺口标记：截至2026-10-20，未检索到任何公开报道确认5#PP是否在2026年5月初如期产出合格产品。行业口径把镇海炼化扩建项目整体列为'50万吨/年PP，计划2026年12月投产'。两种口径相差7个月。",
  "evidence_grade": "C",
  "source_ids": ["SRC-145", "SRC-175"],
  "note": "★本项目最大信息缺口，须向镇海炼化/中石化工程部二次核实"
}
```

**要点**：

1. `fact_date` 填检索日（= 该判断成立的时间点）
2. `desc` 以"★信息缺口标记"开头，明确写"截至某日未检索到"
3. 仍要带 `source_ids`——引用你检索过的相关材料，证明你确实查过
4. `stage` 填该事项应有但未确认的阶段
5. 同时写清"如果该事项成立/不成立，结论会怎么变"

案例中有 8 条负结果记录，它们直接决定了若干项目的结论强度：
东明盛海试车无报道、荣信试车无报道、宝丰四期 PP 无试车报道、镇海 5#PP 开车结果无报道、
华锦阿美 PP 无单独中交通稿、维远第二套 20 万吨无建设报道等。

**为什么这很重要**：如果不写负结果，三个月后别人看到这张表，会以为"没写就是没问题"，
从而把"计划 2026-12 投产"直接当成事实。写了负结果，这张表才有免疫力。

## 五、一条好的进展记录长什么样

```json
{
  "progress_id": "PG-P1-010-05",
  "project_id": "PP-P1-010",
  "stage": "试车",
  "fact_date": "2026-04-23",
  "msg_date": "2026-04-30",
  "plan_date_noted": "2026-09",
  "plan_change": "明确到月",
  "plan_from": "2026年内",
  "plan_to": "2026-09",
  "desc": "45万吨/年聚丙烯装置挤压造粒机组实物料试车成功，各项参数符合设计；中国石油自主聚丙烯技术首次工业化应用、同等规模大型挤压造粒机组首次国产化应用",
  "evidence_grade": "A",
  "source_ids": ["SRC-151"],
  "note": ""
}
```

**要素齐备**：阶段、事实日、消息日、计划变更（如有）、描述、等级、来源。
**描述具体**：不是"试车成功"，而是"挤压造粒机组实物料试车成功，各项参数符合设计"，并点出技术意义。

### 描述写作的四条要求

1. **写具体动作，不写评价。** ❌"项目进展顺利" ✅"挤压造粒框架封顶，用钢 1500 吨、混凝土 8150 m³"
2. **带数字。** 产能、投资额、装置数量、完成率、耗时天数
3. **区分事实与转述。** 事实直接写；行业判断加前缀"行业口径："
4. **重要事项打★。** 让读者一眼看到关键节点

## 六、`plan_change` 字段的取值

| 值 | 含义 | 说明 |
|---|---|---|
| `首次` | 项目第一次给出明确投产口径 | 这是 `first_plan_date` 的来源 |
| `明确到月` / `明确到年` | 精度提高 | **注意**：不一定是时间真的变了，比较时别误判为延期 |
| `延期` | 相对上一版往后推 | 必须同时填 `plan_from` / `plan_to` |
| `提前` | 相对上一版往前推 | 同上，且要核实是否因并线/统计口径调整 |

留空表示该条事实未涉及计划时间变化。

- [ ] 每条记录都有 `source_ids`，且引用的来源都在 `sources.json` 里

- [ ] 中交 / 试车 / 投产 / 达产没有混用
