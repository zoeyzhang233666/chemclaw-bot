# 06 · 交付物规范

两项交付物：**交互式 HTML 看板**、**多表 Excel 工作簿**。两者数据同源，结论必须一致。

## 一、HTML 看板（主交付物）

### 硬要求

- **单文件自包含**：无外部 CDN、无网络请求、无构建步骤，双击即用
- **可离线分发**：发给同事/客户时只传一个文件
- **数据内嵌**：JSON 直接嵌在 `<script>` 里，不 fetch 外部文件（`file://` 下 fetch 会被 CORS 拦）

生成器：`scripts/build_html.py`；自检：`scripts/build_check.py`（含 `node --check` 语法校验）。

### 必备九个区块

| # | 区块 | 必须包含 |
|---|---|---|
| 1 | **概览与结论** | 头部KPI、四类状态条形拆解、按证据强度排序的明确结论、各状态项目清单 |
| 2 | **投产时间线** | 按预计投产年份分组，每组显示项目数/产能合计；每条带阶段色条、性质、延期标记、最新进展摘要 |
| 3 | **年度产能** | 四类互斥堆叠柱状图 + 累计净新增曲线 + 年度汇总表 + 工艺路线结构 |
| 4 | **区域地图** | 省级填色地图（颜色=该省产能），悬停提示，点击筛选到明细表；区域汇总表 |
| 5 | **明细表** | 多维筛选 + 排序 + 筛选结果合计行 + CSV 导出 |
| 6 | **延期与缺口** | 隐性缺口明细（带判定规则）、已延期项目、全库计划变更史 |
| 7 | **去重与剔除** | 剔除清单（带理由与依据来源）、九条去重规则正文、待补证清单 |
| 8 | **自选跟踪** | 收藏（localStorage 持久化）、汇总表、系统推荐优先级、导出清单 |
| 9 | **口径与方法** | 术语定义表、证据等级表、基数口径差异、机构预测分歧、更新制度、不要做的换算 |

### 筛选器（必需六项 + 两项增强）

| 筛选器 | 说明 |
|---|---|
| 阶段 | 试车/中交/设备安装/建设/开工/核准/环评批复/环评受理/备案/拟建/投产/达产/运行 |
| 业主 | 下拉，来自项目库去重后的业主列表 |
| 省份 | 下拉 |
| 工艺路线 | 下拉 |
| 项目性质 | 新建/扩建/置换/技改 |
| 产能阈值 | 数字输入，"≥ N 万吨" |
| *增强* | 预计投产年份、全文搜索（项目/业主/园区）、仅看自选 |

**筛选结果必须显示合计行**——用户真正想看的是"我筛出来这批一共多少万吨"。

### 项目抽屉（点击任一项目弹出）

按顺序展示：

1. **项目档案**：业主、所属集团、所在地区、产品、设计产能、工艺路线、项目性质、当前阶段、最新进展日期
2. **装置/生产线拆分**：unit_id、名称、产能、置换退出
3. **预计投产时间**：首提 vs 最新、延期情况、实质放量年份、计划变更史
4. **投达产不确定性**：★重要事项高亮
5. **统计口径说明**
6. **去重与重复披露说明**（有条目时才显示）
7. **关注要点**
8. **全部进展事实**：按事实日排序，每条带阶段chip、证据等级chip、计划变更chip、描述、来源链接（可点击跳原文）
9. **加入自选**按钮

**抽屉是整套交付物的灵魂。** 它让"一个产能数字"落到"一条有日期、有来源、有等级的事实"上。
如果只能保留一个交互功能，保留抽屉。

### 视觉规范

- 配色：深海军蓝 `#12263f` 主色，状态色 绿`#0b8457`/黄`#b8860b`/蓝`#0f6fc5`/紫`#8b5cf6`/红`#c0392b`
- 字号：正文 13px，表格 12px，表头 11px；`tabular-nums` 用于所有数字列
- 表格：表头 sticky、斑马纹、行悬停高亮、整行可点击
- 中文优先字体栈：`"Microsoft YaHei","PingFang SC","Hiragino Sans GB",...`

### 常见的坑

| 坑 | 后果 | 解决 |
|---|---|---|
| 用 `fetch` 加载 JSON | `file://` 下 CORS 失败，页面空白 | 数据直接内嵌 |
| 用 `location.hash` 做路由 | `file://` 下不触发，所有页签截同一张图 | 用 `go()` 函数显式切换 |
| `title_row()` 少传参数 | `TypeError` | 自检覆盖 |
| `PatternFill` 传 `None` | `fgColor should be <Color>` | 判空后跳过 |
| PowerShell 改文件编码 | 中文注释乱码、`SyntaxError` | 用 write 工具重写，不用 `Set-Content` |
| 只做语法检查不做渲染测试 | JS 无语法错但运行时 `undefined` 报错 | 用 CDP 逐页 `go()` 后抓 DOM 节点数与报错 |

## 二、Excel 工作簿（14 表）

| # | 工作表 | 行数（案例） | 内容 |
|---|---|---|---|
| 0 | 说明与口径 | 45 | 术语定义、证据等级、基数口径、更新制度、免责 |
| 1 | 项目主表 | 40 | 28 列，一项目一行，含全部身份/规模/判断字段 |
| 2 | 装置明细 | 51 | 18 列，一装置一行，**唯一可加总单位** |
| 3 | 进展记录 | 113 | 16 列，全部进展事实，带来源、等级、计划变更 |
| 3b | 预计投产时间变更史 | 56 | 13 列，从进展记录里筛出的所有计划变更 |
| 4 | 来源登记 | 136 | 9 列，id/标题/发布者/URL/日期/类型/等级/备注 |
| 5 | 年度汇总 | 11 | 13 列，含堆叠柱状图 |
| 6 | 隐性供给缺口 | 10 | 9 列，带判定规则与依据 |
| 7 | 口径冲突 | 25 | 5 列，不同来源对同一项目的产能/时间分歧 |
| 8 | 剔除与重复披露 | 19 | 4 列，被排除的记录 + 理由 + 依据来源 |
| 9 | 地区分布 | 20 | 12 列，按省汇总 + 与行业口径对比 |
| 10 | 工艺与路线 | 8 | 9 列，按路线汇总 + 扩张倍数 |
| 11 | 自选跟踪 | 16 | 11 列，推荐优先级清单 |
| 12 | 待补证清单 | 25 | 6 列，明确的"未检索到"+ 影响 + 核实渠道 |

### 样式规范

- 标题行：深海军蓝底 `1F3864` 白字，副标题灰色说明
- 表头：浅蓝底 `DCE6F1`，加粗，冻结窗格
- 警示行：黄 `FFF2CC`；错误/高风险 `F8CBAD`；正常/有利 `E2EFDA`；待核 `FCE4D6`
- 所有数字列右对齐，产能保留 1 位小数
- 每张表顶部有 `title_row()` 说明该表的口径

### 表间一致性的强制要求

Excel 与 HTML 的以下数字必须完全一致（由同一份 JSON 生成，自动保证）：

- 项目数、装置数、进展记录数、来源数
- 年度汇总的每一行每一列
- 隐性缺口的总量与明细
- 地区分布

**自检脚本会核对工作表名称与最小行数**，防止漏表或空表。

## 三、交付前自检清单

运行 `python scripts/build_check.py <项目目录>`，它会自动检查：

- [ ] 14 张工作表齐全，无未登记的额外表，无空表
- [ ] 关键表数据行数不为 0
- [ ] HTML 无未替换的占位符
- [ ] HTML 九个区块 id 齐全
- [ ] 内联 JS 通过 `node --check`
- [ ] 12 个核心渲染函数都存在
- [ ] `project_id` 无重复
- [ ] 所有 `source_ids` 指向的来源都存在
- [ ] 每条进展记录都有 `source_ids`
- [ ] 无记录的自评等级高于其来源最高等级

**此外必须人工做的两项**：

1. **逐页切换渲染测试**（脚本 `smoke.js`）：抓每页 DOM 节点数，确认不是空页面
2. **抽查三个项目抽屉**：确认进展事实条数、来源链接数正确

## 四、交付物之外的第三件东西

**一份 500-1500 字的结论正文。**

看板是给人翻的，Excel 是给人算的，但决策者需要一段能直接读的话。
正文应当包含：

1. 一句话核心结论（现在实际形成多少供应、未来两年名义多少、真实可能多少）
2. 按证据强度排序的 3-5 条发现
3. 最需要关注的 3 个变量及各自的观察时点
4. 本研究的三个主要局限

**不要**把正文写成看板的目录。要写成"如果只看这一段，你会知道什么"。

## 文件命名与存放

```
产物/
  <产品>新增产能与项目跟踪看板.html        # 单文件，随时更新覆盖
  <产品>新增产能与项目跟踪台账_YYYYMMDD.xlsx  # 带日期，保留历史版本
```

Excel 带日期是为了保留历史版本——半年后回看，能知道当时的判断是什么。
HTML 不带日期是因为它内嵌了 `as_of`，版本信息在页面右上角。
