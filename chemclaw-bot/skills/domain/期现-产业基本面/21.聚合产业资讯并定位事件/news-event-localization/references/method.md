# 方法论：从资讯到事件的九步法

本文件是 `SKILL.md` 工作流的完整展开版。每一节都配了来自甲醇案例的判例，说明**为什么**这么规定。

---

## 步骤 1 · 选窗口

### 为什么窗口选择是第一步而不是最后一步

多数人先定窗口再找料，结果窗口里只有标题可读，于是"聚合"退化成"标题列表"。窗口是**可以被证据条件约束的**：先探三个条件，再定窗口。

### 三个前置条件

| 条件 | 检验方法 | 不满足怎么办 |
|---|---|---|
| 有可读官方原文 | 抓一个政府/交易所页，确认正文能取到全文 | 换窗口，或明确本案例无 C1 级事件 |
| 关键装置事件有多来源 | 同一事件搜两家以上机构 | 该事件降为 C3，不做重点 |
| 核心报道正文可读 | 打开正文页，看是否被会员墙拦截 | 换窗口，或整体降为"标题级聚合" |

### 判例：为什么甲醇案例是 10-13~10-19

初始候选窗口 10-06~10-12 覆盖了最戏剧性的事件（渤化、联泓停车、期货逼空），但：

- 隆众正文全部返回 122 字符后被会员墙截断；
- 该窗口内没有可读的政府原文。

改到 10-13~10-19 后同时满足三个条件：

1. **生态环境部环办便函〔2026〕346号**（10-16 生成，10-15 落款）全文可读 → 一个 C1 事件；
2. **金联创《利润不足叠加原料供应问题 港口MTO目前全数停车》**（10-19）经新浪、东方财富两处转载，正文完整 → 一个 C2 事件；
3. **隆众港口库存周数据**（10-14）有可读的转载正文 → 一个 C2 事件。

窗口内重要但只拿到标题的条目（隆众装置快讯）**照样收录**，只是标 `title_only` 并降级——不因为读不到就假装不存在。

### 窗口与"事件日期"的关系

事件发生日可以**早于窗口**（如达拉特旗项目撤销在 10-08，报道在 10-14）。这类事件标记 `outside_window`，但在资讯流中仍显示（虚线边框），并注明"事件日超窗、报道日在窗内"。**不要因为事件日超窗就把报道丢掉。**

## 步骤 2 · 立源

### 分层与优先级

```
T0 官方原文   ← 唯一能支撑 C1 的层级
T1 一手资讯   ← 支撑 C2 的主力（但通常付费）
T2 转载/媒体  ← 支撑 C2 的"可读载体"，但同源不算独立
```

关键认知：**T2 常常是 T1 的转载通道**。金联创原文付费，但它被新浪、东方财富转载后正文可读——这时确认依据是"金联创的内容"，而"两处转载"不构成两家独立机构。

### 每个源必须记录的字段

- `access`：可读 / 部分可读 / 受限 / 不可访问
- `access_note`：**具体**说明怎么受限（"正文返回 122 字符后要求会员热线 400-658-1688"），不是"无法访问"
- `reliability`：A 官方原文 / A 一手资讯（正文受限）/ B 转载媒体 / C 自媒体
- `in_window_items`：窗口内收录条数

### 判例：同源转载如何识别

- 看文首"来源"标注；
- 看正文是否逐段对应；
- 看发布时间差（新浪 14:46 → 东方财富 15:53，差 67 分钟，符合转载节奏）；
- 看是否有"（文章来源：XXX）"文末标注。

## 步骤 3 · 采集

### 六要素与时间陷阱

| 字段 | 取法 | 陷阱 |
|---|---|---|
| 标题 | 页面 `<title>` 或正文标题 | 列表页标题可能被截断 |
| 首发时间 | 发布方页面时戳 | **meta publishTime 可能是爬虫写入的采集时间** |
| 转载时间 | 转载页面的时戳 | 不要把它当首发 |
| 正文要点 | 逐条摘录，不改写数字 | 摘要级来源要标 `summary_only` |
| 链接 | 原始 URL | 保留完整 URL 便于回溯 |
| 内容深度 | full / partial / summary_only / title_only | 决定该条目能支撑多强的结论 |

### 判例：URL 内嵌日期

隆众的 URL 形如 `https://www.oilchem.net/26-1019-15-550ccdf7a1e030e0.html`：

- `26` = 2026，`1019` = 10月19日，`15` = 15 时；
- 这可以作为日期佐证，写入 `url_date_evidence` 字段；
- 但**不能替代精确到分钟的发布时间**，只能说"URL 内嵌 26-1019-15"。

### 判例：meta publishTime 陷阱

抓取隆众页面时，`<meta name="publishTime" content="2026-10-20 10:46:06">` —— 10:46 正是**本次抓取的时间**，不是文章发布时间。若误用，会把所有文章的时间都写成采集时刻。正确做法：用列表页时戳 `[2026-10-19 15:27]` + URL 内嵌日期交叉确认。

## 步骤 4 · 判重

### 六种关系的判定树

```
两条资讯是否同一物理/政策动作？
├─ 否 → 不合并（可能是两个事件，或一条不构成事件）
└─ 是 → 内容是否逐段一致？
    ├─ 是 → republish（同源转载，不增加确认度）
    └─ 否 → 是同一装置的不同日期快讯？
        ├─ 是 → followup（后续更新，保留时间序列）
        └─ 否 → 是列表/数据表形态？
            ├─ 是 → index_entry（非独立报道）
            └─ 否 → 是自媒体/社区转述？
                ├─ 是 → selfmedia（降级为旁证）
                └─ 否 → 关键事实是否矛盾？
                    ├─ 是 → conflict（并置保留）
                    └─ 否 → 视为独立来源（可提升确认度）
```

### 每条合并必须写"判定依据"

反例（不合格）："N09 是 N08 的转载"。
正例（合格）："同一稿件：来源标注'金联创'，正文段落与 N08 逐段对应，标题仅多空格；发布时间晚 67 分钟。"

### 判例：同源不增加确认度

南京诚志事件有 N08（新浪转载金联创）+ N09（东方财富转载金联创）+ N13（隆众标题级）。看起来"3 条来源"，实际是 **2 家机构**（金联创、隆众），所以是 C2 不是 C1。

### 判例：冲突不仲裁

联泓事件里：

- 化销网（N05）："联泓新科 36 万吨/年 DMTO 停车中；联泓格润 36 万吨/年 DMTO 运行暂稳"
- 长安期货（N27）："周末渤化、联泓格润停车"

两份都能读、都是专业机构、说法直接相反。正确做法：该事件降为 **C4**，两说并列展示，`conflict` 关系写进 dedupe，待验证项 Q05 指明"读隆众 10-19 联泓快讯正文即可裁决"。

**错误做法**：选一个"更可信"的写进去，或写成"部分停车"和稀泥。

### 判例：话题 ≠ 事件

"烯烃集中停车"是多篇报道的共同话题，包含渤化、联泓、诚志多个动作。拆成三个事件（E-渤化、E-联泓、E-诚志），各自有编号、发生日、装置、确认度。

反过来，"多家企业复产"被隆众作为一个**周度供应修复**整体发布，那就合并为一个事件（EVT-…-001 国产复产集群），在 `plants` 里保留逐厂信息。

判断标准：**资讯机构是把它当一个整体报的，还是分头报的？**

## 步骤 5 · 立事件

### 编号规则

`EVT-<品种代码>-<YYYYMMDD>-<序号>`

- 品种代码用英文缩写（甲醇 = MEOH）；
- 日期用**事件发生日**，不是报道日；
- 序号在同日内递增（001、002…）。

### 一案多事件时的排序

看板默认按 `occur_date` 倒序。同一天内按 `verify_status` 升序（C1 在前）——让最确定的排最前。

## 步骤 6 · 提实体

### 五级链路

```
事件 → 企业 → 装置 → 产能 → 区域
```

每一级都要能追到来源。

### 易错点 1：同集团不同基地

宁波富德 vs 富德（常州）是**两套装置**。隆众 10-20 发的是"富德(常州)DMTO装置快讯"，不能拿来证明宁波富德的复产状态。

### 易错点 2：同一项目两个量纲

宝丰能源宁东四期：

- "280 万吨/年" = **甲醇装置**规模（生意社摘要）；
- "50 万吨" = **烯烃项目**规模（中财网）；
- 两者不是同一量纲，混用会得出"产能缩水 82%"的荒谬结论。

数据模型里用 `capacity` + `unit` 分开存，并强制 `capacity_source`。

### 易错点 3：存量 vs 新增

装置汇总表上的"停车"可能是 2022 年就停了。必须区分：

- `status_since` 有明确日期 → 可能是窗口内新发生；
- `status_since` 为空（汇总表只给状态不给日期）→ 标为"存量状态"，优先级下调，并列入待验证（"起始日是否落在窗口内"）。

### 产能未取得就留空

南京诚志二期、宁波富德的产能在本窗口资料里没取到。数据模型里 `capacity: null`，Excel 显示"未取得"，HTML 显示红色"未取得"。**不填估计值。**

## 步骤 7 · 定确认度

### 四级标准与判例

| 级别 | 标准 | 案例 |
|---|---|---|
| C1 | 官方原文可读 | 生态环境部 346 号函、财政部 29 号公告 |
| C2 | ≥2 家独立机构，正文可读 | 港口库存（隆众 + 两处独立引用）、诚志停车（金联创 + 隆众标题） |
| C3 | 单一来源或仅标题级 | 西南装置停车（仅隆众汇总）、渤化停车（缺企业确认） |
| C4 | 待核实/冲突 | 联泓格润状态冲突、达拉特旗项目（仅一家二手媒体） |

### 为什么"企业端无公告"会封顶在 C2

资讯机构是二手观察者。企业公告/投资者问答是当事人陈述。没有当事人陈述，理论上永远只能是"多方观察一致"，不能是"已确认"。所以 C2 的上限条款是刚性的。

### 反证样本也要留

财政部 29 号公告（新能源汽车退税率下调）被部分渠道并入"化工品退税调整"话题。本案把它作为 **C1 级否定结论**保留：证明"本窗口无甲醇退税新政"，同时示范"标题 ≠ 事实"。

**保留否定结论**是这套方法的一个特征：证明"某事没发生"需要证据，不能靠"我没搜到"。

## 步骤 8 · 挂节点 + 分三层 + 定量级

### 产业链节点的层级设计

甲醇案例用了 5 层 14 个节点：

```
上游原料   U01煤 U02天然气 U03 CO₂/绿氢
甲醇生产   S02天然气制 S03煤制 S04焦炉气制
流通/进口  I01进口 T01港口库存 T02内地产销
下游需求   D03 MTO/CTO  D05传统下游
衍生路线   S05绿色甲醇  D06甲醇燃料
```

设计原则：**节点必须能被事件挂载**。太粗（"甲醇"）挂不住，太细（单套装置）退化成装置表。判断标准是"能不能回答'这条新闻在产业链哪一段'"。

### 三层事实的写法

- `confirmed_facts`：只放原文明确写了、且来源达到 C1/C2 的；
- `data_supported`：数据支持的推断性描述（"华南累库主导了本周回升"——由分项数据支撑）；
- `unconfirmed`：报道里出现但无确认的（"或均胀库停车"的"或"字句必须放这里）。

**反例**：把"伊朗装置开工不足三成"写进 confirmed_facts —— 原文说的是"该地在三季度平均开工仍不足三成"，属机构统计口径，应放 data_supported。

### 客观规模描述的三条纪律

1. 有可靠产能才写；
2. 写清口径与期间（"10-09 当周，隆众口径"）；
3. 只做量级参照，**不做供需结论**。

判例："100 万吨/年 ≈ 全国甲醇年产量的约 1%。本句仅为量级参照，不做供需结论。"

## 步骤 9 · 列待验证

### 好问题 vs 坏问题

| 坏 | 好 |
|---|---|
| 继续关注诚志复产情况 | 南京诚志是否发布停车公告？→ 巨潮按 000990 检索 10-17~10-20 公告 |
| 核实产能数据 | 诚志二期产能多少？→ 诚志股份年报"主要装置"章节 / 南京江北新区规划公示 |
| 关注伊朗局势 | 9 月进口分来源国明细？→ 海关总署 HS 29051100 / 隆众 26-1020-09 页面 |

四要素缺一不可：**为什么重要 / 需要什么证据 / 去哪里取 / 当前卡点**。

### 卡点要写明

"隆众付费墙 + 站点 451"、"e互动需登录"——这些卡点决定了这条待验证短期内能不能闭环，是给用户看的**预期管理**。

## 附：质量门自检的自动化

```bash
python scripts/validate.py ./src          # 引用完整性、覆盖度、枚举合法性
python scripts/audit_quotes.py ./src ./raw # 引文可追溯性
python scripts/check_outputs.py ./case     # 成品一致性
```

三项全绿再交付。`validate.py` 的覆盖度检查会强制保证：**每条资讯要么挂在事件上，要么进 unassigned 并给出理由**，不允许静默丢失。
