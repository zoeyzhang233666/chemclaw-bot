# 质检清单

交付前逐项过。标 **A** 的项有脚本自动检查，标 **M** 的需要人工确认。

---

## 一、数据完整性（A）

```bash
python scripts/validate.py ./src
```

- [ ] `RESULT: PASS`，零 error、零 warn
- [ ] 所有 id 唯一（source / news / event / company / plant / node / question）
- [ ] 每个 `src_id` / `ent_id` / `plant_id` / `chain_node` / `open_questions` 都能解析
- [ ] `event.dedupe.primary_news` 非空且是 `news_refs` 子集
- [ ] 每条 news 恰好出现在 `dedupe.links` 或 `dedupe.unassigned` 之一
- [ ] `plant.capacity` 非空时 `capacity_source` 非空

---

## 二、引文可追溯（A）

```bash
python scripts/audit_quotes.py ./src ./raw
```

- [ ] `untraced: 0`

> 这一项抓的是**最危险的错误**：把不是原文的话写在引号里。开发本技能时，它抓出了一处真实错误——几个数字被误记在长安期货名下，实际只出现在金联创原文里。

若出现 untraced，三种处置：

1. 原文确实有，但保存的页面不全 → 重新抓取该页
2. 原文措辞不同 → 按原文改写引号内文字
3. 不是引文（是我自己的概括） → **去掉引号**

## 三、判重质量（M）

- [ ] 每个事件的 `dedupe.why_merged` 说清了为什么这些条目是同一件事
- [ ] `republish` 关系的 `basis` 提到了具体证据（文首来源标注 / 逐段对应 / 时间差），不是"应为转载"
- [ ] `republish` 与 `followup` 没被混淆：**同一稿件的复制 = republish；同装置不同日期的快讯 = followup**
- [ ] 确认度计算时 `republish` 未被当作独立来源
- [ ] 冲突项标了 `conflict`，且在 `unconfirmed` 里有对应条目
- [ ] 没有为了"好看"而把冲突强行合并或取舍

---

## 四、信息分级（M）

逐个事件检查：

- [ ] `confirmed_facts` 里的每一条，都能指到某个 C1/C2 来源的明确表述
- [ ] 原文里带"或""预计""可能""拟"的句子，**没有**进入 `confirmed_facts`
- [ ] `data_supported` 是自己的推断，但每条都能由列出的数据支撑
- [ ] `unconfirmed` 覆盖了所有"报道提到但无确认"的内容
- [ ] `verify_basis` 具体到"哪两家机构、哪个时间点、为什么只能到这一级"

**常见错误**：把机构统计口径（"伊朗三季度开工不足三成"）写进 confirmed_facts。它是 data_supported。

---

## 五、产能与规模（M）

- [ ] 每个产能数字都有 `capacity_source`
- [ ] 同一项目的不同量纲没有混用（甲醇装置 280 万吨/年 ≠ 烯烃项目 50 万吨/年）
- [ ] `scale_desc` 里没有供需结论、没有价格方向
- [ ] 量级参照都注明了"仅量级参照"
- [ ] 未取得的产能写 `null`，Excel 显示"未取得"，不是 0 也不是估计值

---

## 六、访问限制披露（A+M）

```bash
python scripts/validate.py ./src   # 会列出 access != 可读 的源
```

- [ ] 每个 `access` 为"受限/部分可读/不可访问"的源都在 `12_访问限制日志` 里
- [ ] `access_note` 写的是**具体现象**（"正文 122 字符后要求会员热线"），不是"无法访问"
- [ ] `limitations` 列出了全局性限制（站点点封、反爬、需登录）
- [ ] 全文检索：没有出现"未发现相关报道"这类把"读不到"说成"不存在"的表述

## 七、待验证可执行（M）

- [ ] 每条都有 `where_to_get`，且是具体路径（"巨潮按 000990 检索 10-17~10-20 公告"）
- [ ] 高优先级问题都挂在最重要的 C3/C4 事件上
- [ ] `blocked_by` 写明了卡点，便于判断能否短期闭环
- [ ] 含至少 1–2 条**全局覆盖度**问题（如"政府侧源是否覆盖够"）
