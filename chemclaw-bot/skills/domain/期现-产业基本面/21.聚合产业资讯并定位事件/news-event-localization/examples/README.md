# 示例目录说明

`01-甲醇-中国-2026年10月第3周/` 是本技能的完整参考案例。换品种/换窗口时，**复制它的结构**，不要从零搭。

---

## 一个合格的案例文件夹应包含

```
<NN>-<品种>-<地区>-<窗口>/
├── README.md      ← 说明窗口选择理由、关键判例、复现方法
├── src/           ← 7 个 JSON（唯一事实来源）
├── out/           ← HTML 看板 + Excel 工作簿
└── raw/           ← 证据页（支撑引文审计）
```

## 复制案例的三条建议

### 1. 先复制 `src/`，用 `new_case.py` 重置 meta

```bash
python scripts/new_case.py --product 纯碱 --code NA2CO3 \
    --start 2026-11-01 --end 2026-11-07 --scope "中国纯碱产业链" --out ./cases/soda
```

生成的是**骨架**（7 个 JSON + README），比复制甲醇案例再删数据更干净。

### 2. `raw/` 不要复制

证据页必须是你**这次**真正抓取保存的页面。复制别人的 `raw/` 会让引文审计对着错误的语料跑，产生假阴性/假阳性。

抓取时按这个思路命名，便于回溯：

```
raw/
├── official_<站点>_<日期>.html      # 政府/交易所原文
├── media_<媒体>_<日期>.html         # 转载正文
├── list_<站点>_<栏目>.txt           # 列表页（提取时间线用）
└── media_<媒体>_<标识>.items.json    # 列表解析结果（含时戳）
```

### 3. 不要照抄"结论"，只照抄"结构"

甲醇案例的 `verify_basis`、`unconfirmed`、待验证项都是**针对甲醇的具体判断**。
新品种必须重新写，尤其：

- `verify_basis` 要说清新品种的"哪两家机构"
- `unconfirmed` 要覆盖新窗口里所有带"或/预计/拟"的表述
- 待验证项的 `where_to_get` 要换成新品种可执行的取证路径（不同品种的海关编码、交易所代码、协会都不同）

## 快速自检

```bash
python scripts/validate.py    <case>/src
python scripts/audit_quotes.py <case>/src <case>/raw
python scripts/check_outputs.py <case>
```

三绿即可交付。若 `audit_quotes.py` 报 untraced，先看是"漏抓页面"还是"引文写错"——两者的修法完全不同。

## 不同品种要换什么

| 品种类型 | 要换的源 | 要换的官方核对点 |
|---|---|---|
| 煤化工（甲醇/尿素/乙二醇） | 隆众、金联创、Mysteel、化销网 | 发改委价格机制、生态环境部环评、海关进口 |
| 盐化工（纯碱/烧碱/PVC） | 卓创、隆众、SMM | 发改委产能政策、生态环境部、能耗双控文件 |
| 新能源材料（碳酸锂/磷酸铁锂） | SMM、鑫椤、隆众 | 工信部、商务部出口管制、海关 |
| 炼化/聚烯烃 | 隆众、金联创、Mysteel | 商务部成品油/配额、海关、安监总局 |
| 精细化工 | 卓创、隆众、行业协会 | 生态环境部（新化学物质）、应急管理部 |

## 常见坑（来自甲醇案例实测）

1. 付费墙下 `content_level` 必须降为 `title_only`，不能凭标题脑补正文
2. 同一项目的不同量纲（装置产能 vs 项目规模）不能混用
3. 汇总表上的"停车"要区分是窗口内新发还是存量状态
4. 转载与首发的时间差是判重的好证据，但不能反推首发时间
5. 旧稿可能被搜索引擎带进窗口，用数据量级交叉核对后拒用，并留痕
