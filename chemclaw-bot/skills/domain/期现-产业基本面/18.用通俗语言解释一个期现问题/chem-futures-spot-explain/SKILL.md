# 用通俗语言解释一个期现问题

## 0. 什么时候用

用户拿来**一个具体问题 + 一个品种**，想要的是“讲明白”，不是“给个结论就完事”。典型触发：

- “库存降了，为什么价格还跌？”
- “基差走强/走弱说明什么？是好是坏？”
- “月差为什么翻了？近月怎么比远月还便宜？”
- “这个价跌到成本线了吗？还有多少空间？”
- “进口有利润了，为什么国内价格没跌？”
- “开工率这么高，价格凭什么涨？”
- “装置出事了先涨停，为什么两天就全跌回去了？”

**不适用**：只想要一张价格走势图（用行情类技能）；要求给出交易建议（本技能只做解释，不做推荐）。

## 1. 一句话原则

> **先回答，再解释；先核对事实，再讲机制；数据缺口必须写在明面上。**

期现解释最常见的失败不是“不懂”，而是三种偷懒：
1. **把教科书机制当成已发生的事实**（“库存降当然该涨，跌说明有别的原因”——但这次库存可能根本没降）。
2. **口径不写就对比**（现货 vs 期货谁减谁、收盘 vs 结算、哪个合约、哪个地区、含不含税）。
3. **把不同时间尺度拼在一句话里**（用 9 月的“去库”解释 10 月中旬的“下跌”）。

## 2. 交付物（固定三件）

| 文件 | 说明 | 硬要求 |
|---|---|---|
| `<品种>期现问题解释_<关键词>_<日期>.html` | 自包含交互页：直接答案 → 尺度核对 → 指标卡 → 图表 → 公式 → 产业逻辑 → 矛盾原因 → 事实/推断/假设 → 数据缺口 → 重算 → 公式校验 → 术语 → 来源 | 单文件、零外部依赖（无 CDN）；入门/专业双模式；数字全部来自 `DATA` JSON，页面内现算 |
| `<品种>期现问题解释_数据与公式_<日期>.xlsx` | 12 表工作簿 | 派生值必须写成 Excel 公式（可点开看怎么算），不留算好的死值；重算后不得出现 `#VALUE!/#N/A/#NAME?` |
| 说明与参考文件 | `SKILL.md` / `README.md` / `reference.md` / `references/*` | 说清口径、公式、来源与缺口 |

## 3. 执行流程（8 步，顺序不可调换）

> 详细规则见 `references/method.md`；概念定义见 `concepts-and-caveats.md`；公式见 `formulas.md`；取数见 `data-sources.md`；产业逻辑见 `industry-logic.md`；问题模板见 `question-types.md`；交付前检查见 `deliverables-checklist.md`。

### S0 解析问题卡（先写下来再动手）
记录：`品种 / 现货地区 / 期货合约 / 时间窗口 / 深度（入门·专业）/ 用户默认值`。
缺失项用默认值并**在页面显式标注“用户未指定”**。若问题里的品种没有对应期货合约，就改做“现货/远期研究”，不得虚构期货价格。

### S1 概念拆解
列出问题涉及的每个概念，逐个给出 **定义 / 符号方向 / 口径五件套**（合约·地区·品质·时间·税）。基差与月差必须写明“谁减谁”——这两处一错，后面全错。

### S2 数据取证
按 `references/data-sources.md` 的顺序取：库存 → 现货 → 期货 → 基差 → 月差 → 开工 → 进口 → 成本 → 事件。每条记录 `date / spec / region / tax_unit / url`。
**进“事实”区的数字必须有 URL 与日期；没有就进“缺口”。**

### S3 事实核对（本技能的命门）
把问题拆成可验证子命题，逐条在**同一时间尺度**上核对，输出：
```
P1 "库存下降"           → 月度成立 / 本周不成立
P2 "价格下跌"           → 成立
P3 "二者同一周期并存"   → 未找到
P4 "所以库存指标没用"   → 属推断，不成立
```
**未找到就写未找到**，并把解释标为“理论假设”。禁止用 A 时段的库存配 B 时段的价格拼成一句。

### S4 指标计算
用 `references/formulas.md` 计算：基差（两种口径都算）、月差、库存变化、表观提货、进口扳平、区间涨跌幅（跨换月只用比值口径）。跑 `scripts/check_formulas.js`，全绿才能继续。

### S5 产业逻辑
至少 6 条可验证路径，每条给：**预期表现 / 用什么验证 / 本次对应情况**。必须覆盖 库存-价格、基差-库存、月差-库存、开工-需求、进口窗口-供给 这五组关系。

### S6 矛盾解释
从这六个抽屉里挑真正用得上、且有数据支撑的：`尺度不同`、`口径不同`、`存量 vs 流量`、`预期 vs 现实`、`被提前定价`、`外生冲击盖过`。

### S7 产出
先写 `data.json`（原始值 + 来源 ID），再由脚本生成 HTML 与 Excel。**禁止手改生成物**——改了下次重跑就没了，而且页面与表格会不一致。

### S8 交付前自检
跑 `scripts/check_formulas.js`、`scripts/probe_html.js`（无头浏览器执行页内 JS，看有没有报错、图表是否渲染）、Excel 重算检查，逐项过 `references/deliverables-checklist.md`。任何一项 FAIL 不得交付。

## 4. 本项目（甲醇 2026-10）的示范结论

> 问题：**甲醇港口库存下降，为什么甲醇价格仍然可能下跌？**

- **能跌，但要把“库存下降”和“价格下跌”放进同一把尺子里量。**
- 月度（2026-09-02 → 10-08）：港口库存 64.15 → 30.51 万吨（-52.4%），**同期价格是暴涨的**（10/8 涨停、10/9 涨超 6%）——这一段不构成“库存降+价格跌”。
- 周度（10-08 → 10-14）：库存 30.51 → 36.72 万吨（**+20.4%，转为累库**），价格同期高位回落——方向是“累库+下跌”。
- **核对结论：本窗口未找到“同一周内库存下降且价格下跌”的组合**。真正成立的说法是：**库存处于统计期最低时，价格仍然可以跌**，因为价格定价的是流量预期，而流量端已转向（到港 3.88 → 15.90 万吨、江浙 MTO 负荷 20.06%、国际周产量 +4.16%）。
- 已证实的下跌解释只有三条：MTO 负反馈、11 月供应恢复预期、地缘溢价回吐；成本支撑因缺同日煤价**无法验证**（见数据缺口）。

## 6. 快速开始

```bash
# 1) 准备数据：照 examples 里的 data.json 结构，把原始值 + 来源 ID 填进去
# 2) 校验公式与符号
node scripts/check_formulas.js path/to/data.json
# 3) 生成 HTML（模板占位符替换）
python scripts/qa_lint.py path/to/page.html
# 4) 生成/检查 Excel：派生列必须写成公式，重算后不得有错误值
```

## 7. 边界与免责

- 只做**解释**，不做投资建议，不预测点位。
- 公开数据只能到“机构转引”这一层（隆众→曲合网/同花顺/金十），正式对外引用写“某某资讯（经××转载）”并保留链接。
- 估价（运保费等）与惯例值（港杂费等）必须在页面标 `estimation / convention`，不得写成事实。
- 记忆里的数字不算数据：**没有 URL 和日期的数字，一律进缺口。**
