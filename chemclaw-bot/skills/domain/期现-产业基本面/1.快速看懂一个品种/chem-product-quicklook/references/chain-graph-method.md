# 产业链图构建方法

产业链图是本技能的门面，也是最容易被做成"一坨方框"的地方。这一页讲怎么建得干净。

---

## 一、列怎么分

默认 5 列，适用于绝大多数化工品：

```
上游原料/能源  →  生产工艺  →  本品种  →  下游产品  →  终端消费
```

**调整规则**
- 有副产物路线的品种（如甲醇有焦炉气路线），上游列会变宽，工艺列对应加卡。
- 无明确"终端"的品种（如某些中间体直接出口），可把第 5 列换成"出口/区域流向"。
- 列数不要超过 6，超过后横向滚动会破坏可读性（QA 会在 1280px 下检测溢出）。

**每列节点数的经验值**

| 列 | 建议节点数 | 说明 |
|---|---|---|
| 上游 | 3–5 | 只放真正影响成本的原料，不放包装、催化剂 |
| 工艺 | 2–5 | 每条主路线一卡，占产能比例写进 meta |
| 本品种 | 1 | 必须是唯一 `is_self: true` |
| 下游 | 4–8 | 按占比排序，前 5 个单独列，尾部合并为"其他" |
| 终端 | 3–5 | 只放能对应到宏观数据的行业 |

> 一列 1 个节点（本品种）vs 一列 8 个节点（下游）的视觉不平衡是正常的，
> engine 会用等高列布局对齐；关键是**不要把"其他"硬拆成多个节点来凑数**。

---

## 二、节点取舍标准

一个节点值得单独列，需要满足**至少两条**：

1. 占本品需求或供应 ≥3%（或产能 ≥500 万吨量级）
2. 有独立的**价格/开工/利润**数据可追踪
3. 存在独立的**装置开停事件**会影响本品供需
4. 是某条**产业链逻辑链**的必经环节

不满足的合并进"其他"，并在 `research.points` 里点名。

---

## 三、每个节点必须有的字段

```json
{
  "id": "mto",                      // 唯一，英文，全小写
  "col": "downstream",              // 属于哪一列
  "name": "甲醇制烯烃（MTO/MTP）",
  "kind": "downstream",
  "meta": "占甲醇消费 48.9%（2025）；MTO 产能 2157 万吨/年",   // 一句话定性 + 关键数
  "cap": "48.9%",                   // 在图上的角标
  "research": {
    "summary": "一句话讲清这个节点为什么重要",   // 抽屉"概览"首屏
    "points": ["3–5 条要点，每条带来源"],
    "share": "48.9%（2025）",
    "single_use": "1 吨烯烃 ≈ 2.66–3.0 吨甲醇",
    "spot": [],                      // 价格锚点，有序列才填
    "price_gap": "为什么没价格数据",
    "indicators": [{"name": "...", "caliber": "...", "why": "..."}],
    "companies": [],                 // 该节点的主要企业
    "companies_gap": "为什么没企业数据",
    "actions": [{"id": "cost_curve", "name": "成本曲线", "desc": "..."}],
    "sources": ["S01"],
    "gaps": ["具体缺什么"]
  }
}
```

**四个"缺口字段"（`price_gap`/`companies_gap`/`gaps`）是必填的**：
即使内容是"不适用"，也要写出来。读者的信任来自"你知道自己缺什么"。

---

## 四、子节点（children）

子节点用于两种情况：
1. **工艺细分**（气化炉型、技术代际）
2. **区域/企业细分**（某个下游的主要玩家）

```json
"children": [
  {"id": "mto_pp", "name": "聚丙烯 PP", "cap": ""},
  {"id": "mto_ext", "name": "外采型 MTO（沿海）", "cap": "利润最敏感"}
]
```

**规则**
- children 只展示 name + cap，不展开抽屉（避免层级混乱）
- children 总数建议 ≤4
- children 的 id 也要全局唯一

---

## 五、action 到 scene 的映射

节点的"深入"按钮不是装饰，它把研究任务丢给其他技能：

```json
"actions": [
  {"id": "cost_curve", "name": "成本曲线", "desc": "煤价 → 甲醇成本敏感性"}
]
```
`id` 必须在顶层 `scenes` 里存在，否则点击报"未登记"。

**推荐的 6 个通用场景**

| id | 名称 | 适合挂在 |
|---|---|---|
| `price_history` | 价格历史与分位 | 本品种、主要下游 |
| `basis_scan` | 基差与月差研判 | 本品种（有期货时） |
| `capacity_survey` | 产能调查 | 上游、工艺、本品种 |
| `news_scan` | 产业新闻 | 所有节点 |
| `cost_curve` | 成本曲线 | 上游、工艺、主要下游 |

---

## 六、视觉平衡的实操

- 每列 `.chcol` 等高（engine 已处理），节点少的那列会留白，属正常。
- 节点 `meta` 控制在一行内（约 24 汉字），超过会在图上换行撑高。
- `cap` 角标只放**最关键的 1 个数**（占比 or 产能），不要塞两个。
- 折叠状态默认只显示一级节点；"全部展开"后才会显示 children。

---

## 七、反模式

| 反模式 | 为什么错 | 改法 |
|---|---|---|
| 把"催化剂""包装""物流"画成节点 | 不构成产业链环节 | 写进上游节点的 note |
| 上游列塞 10 个原料 | 图变宽、重点丢失 | 只留成本占比 >10% 的 |
| 下游全部平铺 15 个 | 无法阅读 | 前 5 单独列，其余合并"其他" |
| 用箭头表示"影响方向" | 产业链图表达的是结构不是方向 | 方向放在 `logic` 块里 |
| 节点名用公司名 | 公司属于 `companies` 不属于节点 | 节点是环节，企业是主体 |
