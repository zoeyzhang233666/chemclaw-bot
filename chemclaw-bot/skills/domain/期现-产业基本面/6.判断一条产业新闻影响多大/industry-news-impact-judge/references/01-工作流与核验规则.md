# 01 · 工作流与核验规则

> 本文件是本 Skill 的**操作手册**。SKILL.md 讲"做什么"，这里讲"每一步怎么做、做到什么程度算过"。
> 通用规则适用于所有化工品种与所有事件类型；品种特有参数放在 `07-化工品种台账（甲醇示例）.md`。

---

## STAGE 0 · 接收与规范化

### 0.1 输入形态处理

| 输入形态 | 处理方式 | 必须留痕的字段 |
|---|---|---|
| 新闻原文（粘贴文本） | 逐段保留，拆出"标题/正文/文中日期/文中引述" | 用户粘贴时间、原文中出现的所有日期 |
| 链接 | 抓取正文 + 页面 `<title>` + 页面发布时间 + 抓取时间 | URL、抓取时间（UTC+8）、HTTP 状态、页面发布时间 |
| 截图 | OCR 后视为"文本"，但**证据等级最高只能到 C**（图片易 PS） | 截图来源（哪个群/哪个平台）、识别可信度 |
| 多个转载版本 | 全部登记，逐条比对差异 | 各版本 URL 与时间 |
| 企业公告 / 政府公示 | 作为**独立证据源**，不是"转载" | 文号、发布日期、发布机构 |

### 0.2 规范化输出（写给下游的"事件对象"）

```json
{
  "raw_quote": "……原文一字不改的一段……",
  "claim": "把新闻的主张压缩成一句可核验的陈述",
  "entities": ["企业名", "装置名", "产品"],
  "numeric_claims": [{"text": "120万吨/年", "value": 1200000, "unit": "吨/年", "role": "设计产能"}],
  "time_claims": [{"text": "5月8日", "normalized": "2023-05-08"}],
  "modality": "已发生 | 计划 | 预计 | 传闻 | 反问"
}
```

**关键：`modality` 字段必须填。** 中文新闻里"将""拟""计划""预计""有望"是**未发生**的信号，下游测算必须按"未发生"处理，或直接标注"事件尚未发生，不测算产量影响"。

### 0.3 常见"偷换"陷阱（自动化检查清单）

| 陷阱 | 表现 | 处理 |
|---|---|---|
| 计划当成事实 | "计划 6 月停车检修 20 天" | 只登记计划，不计算已发生损失；若要测算标"情景测算" |
| 公示/备案当成投产 | "某项目环评批复产能 100 万吨" | 计入"在建/拟建产能"，**不计入**有效产能 |
| 设计产能当成产量 | "拥有 120 万吨/年产能"→ 年产 120 万吨 | 必须乘开工率 |
| 单台设备当成整条线 | "5 号气化炉闪爆"→ 整厂停产 | 需查系列/炉数/是否隔离 |
| 全国产能分母错误 | 用 2020 年产能算 2023 年占比 | 分母必须与事件同年度 |
| 混合口径 | 混用"有效产能/名义产能/批文产能" | 全表统一，注释写清 |

## STAGE 1 · 消息核验（真实性与时效性）

### 1.1 来源溯源四步法

1. **找首发**：用原文中的**唯一性字符串**（如"造气B系列5号气化炉""460.78万元"）做精确检索，而非标题检索；标题会被改写，正文细节不会。
2. **定时间**：优先取①政府/交易所发布页的"发布时间"；②企业公告的"披露日期"；③媒体页面的发布时间戳。**不要**用文章里的"近日/日前/日前从XX获悉"。
3. **画路径**：首发 → 权威转载（党媒/交易所/政府转发）→ 商业媒体加工 → 自媒体二次加工。至少记录 2 条路径；路径越长、二次加工越多，失真的概率越高。
4. **对上游**：新闻引述的原件（公告全文、调查报告全文、批复文件）是否存在？存在则直接引用原件，**以原件为准**。

### 1.2 时效性判定（旧闻重发）

判定为**旧闻重发**，需同时满足：
- (a) 事件发生时间早于本次传播时间 ≥ 30 天；且
- (b) 文中未出现任何"新进展"（如复产、处罚落地、后续评估）；且
- (c) 首发媒体与本次传播的时间差可被证实。

判定为**旧闻+新进展**：事件主体是旧的，但有新的节点（调查结论、处罚、评估报告、复产）。
→ 此类事件**可以**使用，但必须把"旧事件"和"新进展"拆开陈述，影响测算以"新进展"为准。

### 1.3 时效性评分（0–5）

| 分 | 含义 |
|---|---|
| 5 | 24 小时内，且有一手源 |
| 4 | 7 天内，且有一手源 |
| 3 | 30 天内，或 7 天内但只有二手源 |
| 2 | 30–180 天，事件本身已充分传导 |
| 1 | >180 天，或无法确定日期 |
| 0 | 已确认是旧闻重发且无新进展 |

**评分 ≤2 时，HTML 报告必须在其上打"历史回溯 / 已充分传导"标签**，避免被误读为实时信号。

## STAGE 2 · 事实确认

### 2.1 确认源优先级（从高到低）

1. **政府监管文书**：应急管理局事故调查报告、生态环境厅环评批复、发改委核准/备案、应急管理部处罚公示、市场监管局特种设备通报。
2. **交易所信息披露**：临时公告（停产/复产/事故）、定期报告（产量/销量/产能表）、业绩说明会记录。
3. **企业官网/官微/互动平台**：有但非强制披露，等级次之。
4. **第三方产业数据商**：隆众、卓创、金联创、百川盈孚（付费口径），一致性高时可信。
5. **主流财经媒体**（财联社、证券时报、澎湃、新华财经）。
6. **自媒体/群聊/行业公众号**：仅作"线索"，不作"事实"。

### 2.2 交叉验证规则

- **三类源里出现两类独立确认** → 升级为"多方独立确认"。
- **只有政府/公告一类，但内容明确** → "单一权威源确认"，等级 A2。
- **只有解读类报道（"据了解/业内人士称"）** → 最多 B。
- **政府文书与公司公告口径不一致** → 以政府文书为准记录事实，公告口径另列，**不得平均**。

### 2.3 数字确认优先级

同一实数（如产能）出现多个来源时：

```
政府/批复文件 > 交易所年报（设计产能栏） > 公司公告正文 > 行业数据库 > 媒体报道
```

若媒体数字与权威源不符 → 在核验卡中**显式列出冲突**，并按权威源计算。

## STAGE 3 · 事件要素抽取

### 3.1 七要素（缺一不可，缺则标"未获取"）

| 要素 | 抽取要点 | 常见坑 |
|---|---|---|
| **企业** | 全称 + 上市公司主体 + 统一社会信用代码 + 股权关系 | 把子公司事件记到母公司名下而不说明占比 |
| **装置** | 装置全称、系列/炉号、台套数、工艺路线 | "气化炉"与"合成塔"混淆 |
| **产品** | 主产品 + 联产品 + 副产品 | 甲醇联产 LNG，只记甲醇漏掉 LNG |
| **产能** | 设计产能（t/a）+ 实际产能 + 来源 | 把"批复产能"当"在产产能" |
| **地区** | 省/市/县/园区 | "西北"≠"新疆" |
| **时间** | 事件日 + 公告日 + 生效日 + 结束日 | 用"近日"代替具体日 |
| **事件类型** | 见 `04` 的枚举 | "检修"与"停车"混用 |

### 3.2 事件类型枚举（必须使用标准值）

```
ACCIDENT        事故（闪爆/火灾/泄漏/中毒/坍塌）
UNPLANNED_STOP  非计划停车（故障、原料断供、公用工程中断、停电）
MAINTENANCE     计划检修（年度检修、轮检、大修）
RESTART         复产 / 重启 / 开车
CAPACITY_UTIL   限电 / 限气 / 环保限产 / 降负荷
NEW_CAPACITY    新产能投产 / 扩建投产 / 技改达产
SHUTDOWN        永久关停 / 淘汰 / 破产
POLICY          政策（配额、关税、环保标准、出口退税）
RAW_MATERIAL    原料端事件（煤价、气价、天然气保供、进口煤）
DEMAND          需求端事件（下游新装置、出口订单、以旧换新）
LOGISTICS       物流（港口封航、铁路调度、罢工、管道事故）
TRADE           贸易（反倾销、进口配额、海外装置事故）
```

## STAGE 4 · 产业链定位

### 4.1 定位方法（三步）

1. **找直接产品**：事件里被影响的装置**产出什么**（甲醇）。
2. **向上找原料**：该产品用什么原料（煤/天然气/焦炉气），事件是否同时影响原料（如全厂停电影响气化炉）。
3. **向下找用途**：该产品**销售半径与流向**（西北→华东/港口；销往 MTO、醋酸、甲醛、二甲醚、MTBE、燃料）。

### 4.2 传导强度分级

| 等级 | 含义 |
|---|---|
| **强** | 直接影响该产品本身的供需平衡表 |
| **中** | 通过物流/套利窗口影响价格带 |
| **弱** | 仅在特定季节或极端缺口时传导 |

### 4.3 必须回答的三个问题

- 这条新闻**影响的品种是不是你关注的品种**？（不是则说明"间接"）
- 影响是**区域性的还是全国性的**？（看产能占比与物流半径）
- 影响的**时点**在哪？（已发生 / 未来 1 个月 / 未来 1 季度 / 未来 1 年）

## STAGE 5 · 装置档案与产能占比

### 5.1 装置档案必填字段

```yaml
plant_id:              # 唯一编号
company:               # 企业全称
listed_entity:         # 所属上市公司 + 持股比例（如为子公司）
location:              # 省/市/县/园区
product:               # 主产品
capacity_design:       # 设计产能 t/a（含出处）
capacity_actual:       # 实际产量 t/a（近 3 年，含出处）
process_route:         # 气化/原料路线（如 鲁奇碎煤加压气化 + 低温甲醇洗 + 甲醇合成）
units:                 # 装置/炉台套数
commissioned:          # 投产时间
incidents:             # 历史事件清单
```

> **原则：档案里的每一个字段都要能回答"谁说的"。** 没有出处的字段写 `null` 并在报告里显示"未获取"。

### 5.2 产能占比计算规范

```
占比 = 事件装置设计产能 / 同一口径的分母产能
分母三选一（必须写明选的是哪一个）：
  ① 全国有效产能（剔除长期停产/已关停）
  ② 区域有效产能（省 或 大区）
  ③ 品种-工艺细分产能（如"煤制甲醇产能""西北甲醇产能"）

同时给出三个分母的结果，让读者看到"单看全国很小、单看某区域不小"的差异。
```

**必须配套的"折算量"指标**（避免占比太小被误读为"无影响"）：

```
占全国月均产量比 = 装置产能 /12 / 全国月均产量
占区域外发量比   = 装置产能 × 外发率 / 区域外发量
```

## STAGE 6 · 理论影响量测算

完整公式、参数取值依据、敏感性分析模板见 `03-测算公式与敏感性分析.md`。

本阶段的**强制要求**：

1. 时间轴必须双栏：**已确认发生天数** / **假设延伸天数**，两者分开列。
2. 所有假设参数（开工率 r、波及系数 k、天数 d）集中在"假设登记表"，**都可以被用户覆盖**。
3. 敏感区间：天数给 `最短/基准/最长` 三档，开工率给 `低/中/高` 三档，得出矩阵。
4. **缺口不补**：如事故后停产天数未披露，则 `d_已确认 = null`，只输出"日均产能"与"若要计算需补的信息"。

## STAGE 7 · 三分法结论

输出结构（HTML 与 Excel 完全一致）：

```
A. 已确认的事实性影响     ← 证据等级 A1/A2 + 数量可计算
B. 仍存在不确定性的影响   ← 方向明确、幅度未定（区间+假设）
C. 后续需要验证的信息     ← 问谁 / 查哪里 / 何时能看到
D. 未经确认的信息         ← 单独成区，不计入 A/B 汇总
```

每条影响必须带：`影响对象 / 时间窗 / 数量口径 / 证据等级 / 计算式编号`。
