# 案例 1：新疆广汇新能源「5·8」气化炉闪爆

**一条 120 万吨甲醇装置事故新闻，影响到底多大？**

## 一句话结论

> 这是一个**已确认的、有人伤亡的、被行政处罚的事故**（A1 级）。
> 涉事装置 120 万吨/年甲醇，占全国有效产能 **1.13%**、占西北地区 **3.23%**。
> 但**停产时长、波及范围、事故单独造成的产量损失**三项关键数据**均未披露**。
> 因此影响量只能给区间：**约 0.26 万 ～ 8.77 万吨**（34 倍差距），
> 而**不能**给出「实际减产 X 万吨」这样的单点数字。

---

## 三个必须一起看的数字

| 口径 | 数值 | 注意 |
|---|---|---|
| 占全国甲醇有效产能 | 1.13% | 最常被引用的分母 |
| 占西北地区产能（折算） | 3.23% | 主产区内才是「有感觉」的量级 |
| 占全国**月均产量** | 20.14% | ⚠️ 这是「产能÷月产量」，**不是损失**，容易被误读 |

同一个装置，换分母从 1.13% 到 20.14%，**观感差 18 倍**。这就是为什么本工具强制「多口径同出」。

## HTML 报告的交互

- **首屏消息核验卡**：8 要素 + 旧闻判定 + 时效评分（1/5）
- **点击产业链节点** → 弹出抽屉，显示该节点的上下游关系
- **点击企业** → 装置档案
- **「看价格反应」** → 跳到事件时段公开行情事实（只描述状态，不推导方向）
- **「看同区域企业」** → 5 家可比企业产能，判断能否补位
- **S6 滑块**：拖 d（天数）和 r（开工率）、选 k（影响系数），L 与占比实时重算

## 怎么用这个案例做新案例

1. 复制 `case_data.json`
2. 按 `../../assets/templates/case_data.schema.json` 逐字段填
3. **填不出来的字段就留空，并写进 `gaps`** —— 这是设计意图，不是缺陷
4. 生成：
   ```bash
   python ../../scripts/build_report.py my_case.json -o report.html
   python ../../scripts/build_workbook.py my_case.json -o workbook.xlsx
   python ../../tools/self_check.py my_case.json --strict
   ```
5. `self_check` 必须 0 FAIL 才能交付

## 数据缺口一览（这些是「故意的」）

| ID | 缺什么 | 影响什么 |
|---|---|---|
| G1 | 停产/复产天数 | 决定 L 大小 |
| G2 | 波及范围（单炉/B 系列/全厂） | 决定 k，8 倍差距 |
| G3 | A 系列台数与产能 | 无法校正 B 系列占比 |
| G4 | 事故单独造成的产量损失 | 年报未单列，无法拆分 |
| G5 | 新疆甲醇外发率 | 无法折算为销区冲击 |
| G6 | 逐日行情与库存 | 无法做事件研究 |
