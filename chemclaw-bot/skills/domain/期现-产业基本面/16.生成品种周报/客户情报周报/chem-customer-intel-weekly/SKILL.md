# 化工品区域客户情报周报（chem-customer-intel-weekly）

## 0. 目标与产出

对「一个化工品 × 一个区域」产出一期周报：**一个自包含的 HTML 文件**（无外部依赖，双击可开，可打印），结构固定为 6 个板块：

| # | 板块 | 固定数量 | 核心要求 |
|---|------|---------|---------|
| ① | 本周新增与突发 | 3 张卡（1主+2副） | 只放本周新增、或仍直接影响本周判断的事件；主卡放最大事件 |
| ② | 价格行情与产业链关系 | 4 条 SKU 折线 + 3 张关系卡 | 每条序列同SKU同口径、点间不插值；关系卡=上游/成本/下游各1 |
| ③ | 行业政策与本地动态 | 政策3 + 本地3 + 会议展会2 | 政策优先本周新增；本地动态必须有区域关联 |
| ④ | 企业机会池 | 固定 4 家 | 全部真实企业+可点击证据；每家独立评级与AI用量估算 |
| ⑤ | 项目清单 | 5—8 行 | 明确产品在哪个环节使用；“可能涉及”≠采购事实 |
| ⑥ | 数据口径说明 | 1 块 | 写清估算算法、假设与局限 |

**思维方式（比数据更重要）**：价格判断给方向不给结论；客户判断给证据链不给名单；一切推算标明假设。宁可写「工艺待确认」，不写想当然的用途。

## 1. 输入参数（用户未指定时按默认）

| 参数 | 默认 | 说明 |
|------|------|------|
| 产品 | 必填 | 中文通用名 + 关键形态/规格（如：纯碱，重质/轻质） |
| 区域 | 江苏张家港及苏州周边 | 城市或区县；区域变更有专用方法，见 reference.md §6 |
| 报告日 | 今天 | 当周 = 本周一至周日；数据截至 = 报告日当天已发布数据 |
| 存量客户 | 无 | 上期机会池企业滚动进入本期复评 |

## 2. 阶段一：研究（先证据后结论，边查边记「数值+日期+口径+URL」）

按 reference.md《§1 数据源地图》执行五条线，顺序固定：

1. **价格线**：凑齐 4 条 SKU 序列。推荐组成：①行业基准价长线（≥6 个点，看趋势）②主力形态/规格现货 ③另一形态或另一区域现货 ④期货主力（无期货的品种改用第三方市场价或下游价格）。每条序列必须：同 SKU、同报价主体/口径；数据点稀疏不插值；描述性区间点（如周报说“1000—1010整理”）取中值并在 note 里注明口径。
2. **产业链线**：上游原料与能源（价格+成本利润）、下游主力产品（价格/开工率/日熔量等需求指标）。三个关系卡 = 上游成本参考 + 本行业成本利润对照 + 下游需求指标。
3. **动态线**：期货公司周报（供需、库存、检修）、库存数据（多机构口径并存时全部标机构名）、行业协会通知/年会、产业政策。
4. **客户线（核心，占一半时间）**：
   a. 列出该产品全部下游用途 → 对照区域产业集群，筛出 3—4 类用途；
   b. 从「企业官网 / 政府公示 / 招投标 / 上市公司年报」四类入口找真实企业；
   c. **工艺验证（最关键一步）**：确认对方工艺环节确实投加本产品。警惕“深加工≠熔制/反应”陷阱（反面案例：玻璃切割磨边企业不耗纯碱，见 reference.md §5）；
   d. 固定 4 家、≥3 类用途，每家给评级和用量区间。
5. **项目线**：环评受理/批复、招投标公告、清洁生产审核、年报扩产——只留能说明“产品在哪个环节被使用”的项目。

## 3. 阶段二：分析与估算

- 评级用 A / B+ / B / C（定义见 reference.md §3），评级理由必须落在「工艺直接性、项目状态、证据时效、配方确定度」四要素上。
- AI 用量估算：从 reference.md §2《估算公式表》选公式；产线参数非公开时用行业情景区间，并在卡片 basis 字段写明“情景假设”。
- 证据超过 2 年的，eventDate 保留原始日期并标注“（口径）/时效较旧”，judgement 写“需复核”。

## 4. 阶段三：生成 HTML

1. 复制 `assets/template.html` 为 `<区域><产品>区域客户情报周报_<YYYY-MM-DD>.html`。
2. 替换模板中全部 `{{TOKEN}}`（每个 token 在模板内有中文注释说明；两个完整填好的样例见 `assets/example-*.html`，分别演示大宗商品型和水处理药剂型）。
3. 只允许改动：`<title>`、meta description、正文 token、`<script>` 顶部三个数据数组、STORAGE_KEY（同一产品+区域固定同一前缀，跨周延续忽略名单）。
4. **禁止改动**：全部 CSS、JS 函数逻辑、SVG 饼图四等分结构、卡片 DOM 结构与类名。
5. 数量硬约束：突发 3 卡 / SKU 序列 4 条（每条≥3点）/ 关系卡 3 张 / 政策 3 + 本地 3 + 展会 2 / 企业 4 家 / 项目 5—8 行。

## 5. 阶段四：QA（全过才能交付）

- [ ] 全文 `{{` 出现次数 = 0；上一期/其他产品残留词 = 0（检查旧产品名、旧企业名）
- [ ] 提取 `<script>` 内容用 `node --check`（或等价 JS 解析）通过
- [ ] 每个按钮/链接字段都有真实 URL；每个数据点都能溯源
- [ ] 所有数据点日期 ≤ 报告日；情景假设点已在 note/basis 标注
- [ ] 数据数组条数符合第 4 步硬约束；4 家企业 id 互不相同
- [ ] 企业卡片类目与饼图图例（LG1—LG4）一一对应

## 6. 交付

- 交付 HTML 文件 + 一段简报：本周期改了什么、哪些是假设、建议下周跟踪什么。
- 明确声明：公开信息与 AI 区间估算仅用于 B2B 情报筛选，不构成报价、授信或采购量保证。

## 7. 移植到其他电脑 / 其他 Agent

- **支持 Agent Skills 的 harness**（Claude Code 等）：把整个 `chem-customer-intel-weekly/` 目录放入其 skills 目录（如 `~/.claude/skills/`），自动按 description 触发。
- **不认识 skills 的 agent**（codex、chemclaw、workbuddy 等）：在它的 AGENTS.md / 系统提示里加一行——“处理化工品客户情报周报请求时，先完整阅读 `<skill路径>/SKILL.md` 与 `<skill路径>/reference.md`，再按其流程执行。”
- **无联网能力的 agent**：让用户人工提供价格与资讯（阶段一的产出物），从阶段二开始执行；模板与 QA 流程不变。
- 本 skill 只依赖：网页搜索、网页抓取、文件读写、可选的 JS 语法校验。不依赖任何特定工具名。
