# 交付前检查清单（必须全绿）

## A. 数据层（research.json）

- [ ] `meta` 齐全：品种、规格、区间起止、数据截止日、区域、期货基准。
- [ ] `structure` 至少 2 套口径，每套有 `year` + `org` + `basis` + `items`。
- [ ] 每条 evidence 都有 `id / seg / metric / value / unit / date / caliber / src / url`。
- [ ] 拿不到的 `value` 为 `null`，且对应条目已登记到 `gaps`。
- [ ] 每个下游至少 1 个 A 级指标；没有的要在 `gaps` 说明。
- [ ] 所有 `url` 以 `https://` 开头且可打开。
- [ ] 同一指标的连续点来自同一 `caliber`；跨口径点单独标注。

## B. HTML 报告

- [ ] 单文件、零外链：无 `src="http..."`、`link href="http..."`、`@import url(http...)`、CDN 引用。
- [ ] 无 `undefined` / `NaN` / `None` / `${` / `TODO` / `占位`。
- [ ] 无重复 `id`（重复 id 会导致渲染函数覆盖整个容器——本 Skill 踩过：`section#policy` 与 `div.tl#policy` 撞名）。
- [ ] 首屏有：需求结构（环形图 + 多口径切换）、主要变化、KPI 卡。
- [ ] 下游卡片：每个下游显示占比（含年份+来源）、价格/开工/利润/产量等同期变化、指标等级徽标。
- [ ] 筛选可用：按下游、按指标等级（A/B/C/D）。
- [ ] 点击下游可展开抽屉：研判要点、指标序列、口径提示、原始证据（含摘录与链接）。
- [ ] 证据库可按下游筛选，条数与 evidence 数量一致。
- [ ] 口径规范表（A/B/C/D 分级 + 局限）在报告中可读。
- [ ] 缺口清单可见。
- [ ] "反误用"四条边界在页面上明确写出。
- [ ] 打印样式可用（`@media print`），`Ctrl+P` 能出干净的 PDF。

## C. Excel 工作簿

- [ ] 14 张表齐全：00 说明 / 01 结构 / 02 指标库 / 03 分级 / 04 历史比较 / 05 打分 / 06 传导 / 07 政策 / 08 价格库存 / 09 期货分位 / 10 缺口 / 11 来源 / 12 证据明细 / 13 口径规范。
- [ ] 02 与 12 的证据条数 = evidence 数量，数值逐条一致（脚本校验）。
- [ ] 关键表开启 `auto_filter`，冻结表头。
- [ ] 数值列有 `number_format`，不要显示成科学计数或文本。
- [ ] 条件格式对等级/涨跌着色。
- [ ] 表头行高度、列宽可读（不要出现 `####`）。

## D. 跨文档一致性

- [ ] HTML 的每个关键数字都能在 research.json 找到同一条 evidence。
- [ ] HTML 与 Excel 的同一指标数值完全一致（同一份 JSON 生成）。
- [ ] 章节编号连续（01–12），目录锚点可跳转。
- [ ] 报告底部有数据截止日、来源清单、免责声明。

## E. 渲染与交互（自动化或人工）

- [ ] 1600 / 1280 / 420 三个宽度下无横向溢出（表格允许在 `overflow:auto` 容器内滚动）。
- [ ] 抽屉能打开与关闭（Esc 可关）。
- [ ] 筛选按钮点击后卡片数量正确变化。
- [ ] 结构口径切换按钮能换图。

> 本 Skill 自带 `scripts/check_all.py`，B/C/D 三层可由脚本自动判定；
> E 层若环境中没有无头浏览器，用 `--dump-dom` + 注入检查脚本的方式验证（见案例 `_src/check_render.py`）。

## F. 结论层（人工判断）

- [ ] 没有把所有下游平均成一个"整体需求偏强/偏弱"的表述。
- [ ] 没有用价格变化推断消费量变化。
- [ ] 每个"改善/走弱"的判断后面都跟了支撑指标与日期。
- [ ] 对结论敏感的地方（结构口径、指标缺失）已显式说明。
- [ ] 没有预测价格。
