# 03 · 事件去重规则

同一件事被 4 家媒体转载，不能算 4 次减产。去重的核心是**定义"同一件事"**。

---

## 去重键

```
dedupe_key = (unit_id, event_family, time_overlap)
```

- `unit_id`：装置唯一标识（见 `02-企业装置消歧规则.md`）
- `event_family`：人工命名的事件家族，如 `"新奥一期9月检修"`、`"凯越9月检修"`
- `time_overlap`：两段 `[start_date, end_date]` 区间相交

三者同时满足 → **同一条事件**，做法是：

1. 合并 `sources[]`（并列，不覆盖）
2. `source_count` = 去重后的来源数
3. `source_count >= 2` → 标记"多源印证"
4. 写 `dedupe_check` 说明合并依据("四源均指向新奥一期 60 万吨同一次检修")
5. 冲突信息写进 `conflict`

---

## 合并场景与处理

### 场景 A：同一事件的状态序列（最常见）

多家机构在检修全程持续跟踪，每条只报一个状态。

```
8/14 化销网：一期初步计划8/31停车检修，预计20天
9/03 生意社：一期计划9/4停车检修，预计20天
9/16 隆众  ：一期于9月4日停车检修，预计9月23日逐步重启
10/16 生意社：一期运行平稳（已恢复）
```

→ **一条事件** `E-001`，`sources` 4 条，`status_note` 串起状态演变，`status_latest="已复产"`。

判别标志：多条记录的 `unit_id` 相同，时间上前后衔接，描述的是同一段停工期。

### 场景 B：计划日漂移

```
8/14 报道：初步计划 8月31日 停车
9/03 报道：计划 9月4日 停车
```

→ **一条事件**，`start_date` 取**实际执行日 9/4**（多源一致），计划日写进 `conflict`。
不要把"8/31 计划停车"另立一条事件，否则时间线上出现两根相邻的条带。

判别标志：日期相差数天，产能相同，且后一条的表述包含"如期/已/于"等执行语态。

### 场景 C：同名不同装置（必须**不**合并）

```
2026-09-18 甲醇时代：榆林凯越 70万吨 9/4 展开检修
2026-09-18 生意社  ：榆林凯越 50万吨煤制乙醇 9/3–9/28 检修
```

→ **两条独立记录**（甲醇 `E-003`，乙醇不入甲醇台账）。
虽然都叫"凯越"、日期接近，但**产品不同、产能不同**。若强行合并，甲醇影响量会被乙醇的产能污染。

判别标志：产能数字不同、产品名称不同 → 一定不是同一装置。

**同类**：

- "内蒙古巴彦淖尔能源 12 万吨"（新投产报道）vs "神华巴彦淖尔 10 万吨焦炉气"（临停检修）→ 产能与工艺不同，分开建档，并在 `planned_events` 里标注"是否为同一装置待企业口径确认"
- "内蒙古新奥 120 万吨"（合计报道）vs "一期 60 / 二期 60"（分期报道）→ 计入分期，不另立合计事件

### 场景 D：检修与复产成对出现

```
9/04 停车检修
9/26 恢复运行
```

→ **一条事件**（`event_type=计划检修`，`status_latest=已复产`）。
**不要**把"9/26 复产"另立一条 `复产` 事件并计一次正影响量——否则等于把同一段停车算成"停 + 复"两次扰动。

判别标志：复产记录能找到对应的停车记录 → 合并。

**例外**：如果停车起点**无法追溯**（来源只说"已于X日重启"），则只能登记一条 `复产` 事件，`loss_t` 记 0/不计，并在 `11_数据缺口与冲突` 里说明。例：陕西长青 60 万吨 9/14–16 重启，停车起点未知 → 只登记复产。

### 场景 E：合并报道 vs 专条报道

```
隆众汇总表（9/10、9/16、10/13 三期均为同一行）：榆林凯越 9月4日停车检修，为期25天
化销网专条（8/17、9/28）：凯越装置运行平稳 / 目前重启中
```

→ 汇总表的多期版本是**同一行数据的重复**，合并为一条，用最新一期刷状态；专条提供状态变化。

### 场景 F：集团级合并表述

```
"伊朗多套甲醇装置停车"
"Kaveh正常运行；Sabalan维持停车；Kimiya维持停车"
```

→ 前一条是模糊表述，后一条可拆分。**按后者拆成多个 `unit_id`**（`U063`–`U066`），前一条作为旁证来源挂在各装置下。
若只有模糊表述，则整条作为一个事件，产能填"未拆分"，不计入精确汇总。

---

## 反例：不该做的去重

| 错误做法 | 后果 |
|---|---|
| 把"甲醇装置检修"和"下游乙醇装置检修"合并 | 产能污染 |
| 把"一期检修"和"二期停车"合并为"新奥停车" | 状态矛盾 |
| 把伊朗多套装置合并成一个"伊朗 660 万吨停车" | 无法核对单装置，且与他人拆分口径不可比 |
| 把同一装置的"计划"和"实际"各立一条 | 时间线重复，天数重复 |
| 把传闻来源与官方来源并列后仍按多源确认 | 虚假置信度 |

## 去重执行清单

对每条候选事件：

- [ ] 找到 `unit_id`（能不能对上装置档案？对不上说明消歧没做完）
- [ ] 判断 `event_family`（和已有事件是同一件吗？）
- [ ] 检查时间重叠（重叠 → 合并；不重叠 → 新增）
- [ ] 判断是"计划"还是"实际"（同一次事件取实际）
- [ ] 判断是"停车"还是"复产"（成对 → 合并到停车事件）
- [ ] 检查产能与产品是否一致（不一致 → 绝不合并）
- [ ] 写 `dedupe_check`（一句话说明合并/不合并的理由）
- [ ] 更新 `source_count`

**去重做得好不好，看 `dedupe_check` 字段**：写得出来，说明想过；写不出来，说明只是把报道堆在了一起。
