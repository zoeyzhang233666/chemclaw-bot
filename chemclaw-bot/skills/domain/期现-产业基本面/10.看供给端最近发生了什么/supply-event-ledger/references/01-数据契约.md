# 01 · 数据契约

所有数据均为 UTF-8 JSON。`case/` 目录下五个文件构成完整输入，缺一不可。

---

## 1. `datum.json` — 窗口与基准

```json
{
  "meta": {
    "product": "甲醇",
    "window_start": "2026-07-20",
    "window_end": "2026-10-20",
    "as_of": "2026-10-20",
    "national_capacity_wt": 10000,
    "weekly_output_t": 2024235
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `product` | string | ✅ | 品种中文名 |
| `window_start` / `window_end` | `YYYY-MM-DD` | ✅ | 统计窗口，含首尾 |
| `as_of` | `YYYY-MM-DD` | ✅ | 信息截止日，晚于此日的报道不采信为"已发生" |
| `national_capacity_wt` | number | ⬜ | 全国总产能（万吨/年），仅作分母 |
| `weekly_output_t` | number | ⬜ | 参照周产量（吨），用于"折合几周产量" |

> `national_capacity_wt` 与 `weekly_output_t` **必须在报告里标注来源与日期**，且明确说明"仅用于量级参照，不是精确基准"。

## 2. `companies.json` — 企业词典

```json
{
  "process_routes": [
    {"code": "COAL", "name": "煤制", "note": "占产能主体"},
    {"code": "NG", "name": "天然气制", "note": "川渝/青海/海南集中"},
    {"code": "COKE_OVEN", "name": "焦炉气制", "note": "晋陕蒙鲁集中"},
    {"code": "CO2H2", "name": "二氧化碳加氢制", "note": "规模小"},
    {"code": "FURNACE_GAS", "name": "矿热炉尾气制", "note": "规模小"},
    {"code": "UNKNOWN", "name": "未披露", "note": ""}
  ],
  "regions": [
    {"code": "NW-INM-YYL", "name": "西北-内蒙古/榆林", "province": "内蒙古、陕西(榆林)"}
  ],
  "companies": [
    {"id": "C001", "name": "兖矿能源集团", "aliases": ["兖矿", "兖矿集团"], "note": "多基地"}
  ]
}
```

### 工艺路线枚举

不同品种的工艺路线不同，**换品种时必须整组替换**：

| 品种 | 典型工艺路线 |
|---|---|
| 甲醇 | 煤制 / 天然气制 / 焦炉气制 / 二氧化碳加氢制 / 矿热炉尾气制 |
| 尿素 | 煤制 / 天然气制 / 焦炉气制 |
| PVC | 电石法 / 乙烯法 |
| PTA | PX 法（单一，可省略该维度） |
| 纯碱 | 氨碱法 / 联碱法 / 天然碱 |
| 乙二醇 | 乙烯法 / 煤制（合成气） |
| 烧碱 | 离子膜法 |

> 工艺路线**不是可选项**。同一产品不同工艺的原料、成本、检修节奏、限气敏感性完全不同；不区分就等于把两类资产混算。

### 大区划分原则

- 按**物流半径 + 报告体系**划，不按行政区划机械切分
- 例：甲醇的"西北-内蒙古/榆林"自成一个报告单元（隆众即如此分），因为这三地互为替代货源
- 境外装置单独成区（`OVERSEAS-*`），且 `scope=overseas`

## 3. `units.json` — 装置档案

```json
{
  "units": [
    {
      "unit_id": "U012",
      "company_id": "C002",
      "company": "内蒙古新奥（达旗）",
      "site": "内蒙古鄂尔多斯达拉特旗",
      "province": "内蒙古",
      "region_code": "NW-INM-YYL",
      "unit_name": "新奥一期60万吨",
      "product": "甲醇",
      "capacity_wt": 60,
      "route": "COAL",
      "status_base": "运行",
      "capacity_note": "生意社/化销网：一期60万吨",
      "disambig": "一期/二期必须分开，多次报道状态相反"
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `unit_id` | string | ✅ | 形如 `U001`，**全局唯一，一经分配不再复用** |
| `company_id` | string | ✅ | 关联 `companies.json` |
| `company` | string | ✅ | 企业显示名（冗余存储，便于导出） |
| `site` | string | ✅ | 生产基地，精确到园区/县 |
| `province` | string | ✅ | 省/自治区 |
| `region_code` | string | ✅ | 关联 `regions` |
| `unit_name` | string | ✅ | 装置名，**必须体现分期**（如"一期60万吨"） |
| `capacity_wt` | number | ✅ | 产能，万吨/年 |
| `route` | enum | ✅ | 工艺路线 code |
| `status_base` | string | ✅ | 建档时的基准状态 |
| `capacity_note` | string | ✅ | 产能来源与口径 |
| `disambig` | string | ✅ | **消歧要点：说明它最容易和谁混淆** |

### `disambig` 是必填字段

它不是注释，是交付物的一部分——导出到 Excel 的"消歧要点"列，直接给研究员看。写不出消歧要点，说明这个装置还没想清楚。

## 4. `status_events.json` — 已发生事件

```json
{
  "events": [
    {
      "event_id": "E-001",
      "event_family": "新奥一期9月检修",
      "unit_id": "U012",
      "company": "内蒙古新奥（达旗）",
      "site": "内蒙古鄂尔多斯达拉特旗",
      "province": "内蒙古",
      "region_code": "NW-INM-YYL",
      "unit_name": "新奥一期60万吨",
      "capacity_wt": 60,
      "route": "COAL",
      "event_type": "计划检修",
      "start_date": "2026-09-04",
      "end_date": "2026-09-26",
      "duration_days": 23,
      "status_latest": "已复产",
      "status_evidence_date": "2026-10-16",
      "status_note": "9/4如期停车……10/16确认运行平稳",
      "baseline_load": 1.0,
      "downtime_load": 0.0,
      "load_note": "停车期间负荷0",
      "load_assumed": false,
      "confidence": "industry",
      "source_count": 4,
      "sources": [
        {"name": "化销网 装置动态", "date": "2026-08-14",
         "url": "https://...", "quote": "原文引用"}
      ],
      "dedupe_check": "四源均指向同一装置同一次检修",
      "conflict": "计划停车日8/31 vs 实际9/4，取9/4"
    }
  ]
}
```

### `event_type` 枚举

| 值 | 定义 | 计入减产量 |
|---|---|---|
| `计划检修` | 提前公告或按计划执行的停车检修 | ✅ |
| `实际停车` | 实际停车，恢复时间不明 | ✅ |
| `意外故障` | 非计划的临时停车/故障 | ✅ |
| `降负荷` | 未停产但负荷下降 | ✅（按负荷折算） |
| `复产` | 已恢复生产（重启/开车/产出合格品） | ❌（避免重复计算） |
| `新投产` | 新装置正式投产进入商业供货 | ❌（计入新增产能） |
| `试车` | 投料试车阶段，未稳定供货 | ❌（单列） |

### 负荷字段（最容易搞错的地方）

| 字段 | 含义 | 停车类取值 |
|---|---|---|
| `baseline_load` | 事件**之前**的正常负荷 | 通常 `1.0` |
| `downtime_load` | 事件**期间**的实际负荷 | 全停 `0.0`；降负荷 `0.45` 等 |

减产系数 `k = baseline_load - downtime_load`。

> ⚠️ **不要**把 `baseline_load` 填成事件期负荷。曾因此把减产系数算成 0，导致合计归零。
> 若来源只有"低负荷"而无数值：填假设值（如 0.5），并设 `load_assumed=true` + `exclude_from_confirmed=true`。

### `confidence` 枚举

| 值 | 定义 | 是否进确认合计 |
|---|---|---|
| `official` | 企业公告、政府批文、交易所公告 | ✅ |
| `industry` | 隆众/金联创/生意社/甲醇时代等专业资讯 | ✅（`exclude_from_confirmed=false` 时） |
| `rumor` | 社媒、股吧、非专业渠道 | ❌ 强制排除 |

### 其他控制字段

| 字段 | 作用 |
|---|---|
| `scope: "overseas"` | 境外装置，归入境外口径，不进国产合计 |
| `stock_stop: true` | 窗口前已停车且无恢复计划 → 不算窗口内边际变化 |
| `exclude_from_confirmed: true` | 强制排除出确认合计（传闻/待核/假设负荷） |
| `clip_to_window: true` | 事件跨窗口边界，只计窗口内天数 |
| `starts_before_window: true` | 起始日早于窗口（供校验与展示） |

## 5. `planned_events.json` — 未来已披露事项

```json
{
  "planned_events": [
    {
      "plan_id": "F-001",
      "unit_id": "U030",
      "company": "宁夏宝丰能源",
      "unit_name": "宝丰四期甲醇",
      "capacity_wt": 280,
      "event_type": "新投产",
      "planned_date": "2026-10-20",
      "planned_window": "2026-10-14 ~ 2026-10-31",
      "disclosure_type": "行业资讯披露",
      "status": "未发生/未确认",
      "status_note": "计划10月中下旬产出合格甲醇，截至10/20无产出确认",
      "confidence": "industry",
      "sources": [ ... ],
      "potential_supply_wt": 280,
      "potential_supply_note": "投产≠达产，爬坡3-6个月，不纳入确认影响量"
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `disclosure_type` | `企业公告` / `政府批文` / `行业资讯披露` / `口径待确认` |
| `planned_date` | 点估计日期（用于排序与图上定位） |
| `planned_window` | 区间（点估计不可靠时必填） |
| `status` | `未发生` / `未确认` / `已披露未执行` / `口径待确认` |
| `potential_supply_wt` | 潜在影响规模，**仅作规模提示，不参与任何合计** |

> **铁律**：`planned_events.json` 里的任何数字都不得进入 `summarize()` 的合计。它在 HTML 里用橙色虚线空心条带表示，在 Excel 里是独立 Sheet。

## 数据校验

`check_xlsx.py` 与 `check_html.py` 会校验：

- 每套装置 `unit_id` 唯一
- 每个事件 `unit_id` 能在 `units` 中找到
- 每个事件至少一个 `source`，且 `url` 非空
- 国内已确认事件必须有非空 `loss_t`
- 事件起始日落在窗口内（或已标记 `starts_before_window`）
- Excel 各汇总 Sheet 合计 == 引擎合计
