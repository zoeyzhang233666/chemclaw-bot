# 供给端装置事件台账（Supply Event Ledger）

## 这个技能解决什么问题

期现/产业研究里最常被问、也最容易做错的一件事是：**"最近供给端到底发生了什么？"**

做错的方式高度雷同：

| 常见错误 | 后果 | 本技能怎么防 |
|---|---|---|
| 把设计产能直接当减产量 | 影响量虚高数倍 | 强制 `产能/365 × 天数 × (基准负荷−事件期负荷)` |
| 同一装置被多家媒体重复报道，重复计入 | 影响量翻倍 | `unit_id + event_family + 时间重叠` 去重 |
| MTO 停车被写成"甲醇装置停车" | 把需求端当成供给端 | 上下游装置分离建档，`disambig` 字段强制消歧 |
| 一期/二期混为一个装置 | 状态矛盾、产能错配 | 同企业多产线分别建档 |
| 把未来计划检修混进已发生事件 | 时间线失真 | `status_events.json` / `planned_events.json` 物理分文件 |
| 传闻、股吧消息直接进汇总 | 不可核验 | `confidence=rumor` 强制排除出确认合计 |
| 境外装置并入国内合计 | 国产供给虚增 | `scope=overseas` 单独口径 |
| 窗口前已停车的老装置算成"新变化" | 边际变化失真 | `stock_stop=true` 单列 |

**输出定位**：只回答"哪些装置、发生了什么、影响多少产量、哪里还不确定"。**不输出供应预警、价格方向、交易建议。**

## 何时触发

用户说：
- "整理【甲醇】最近3个月供给端装置动态"
- "最近哪些装置在检修/停车/复产"
- "看供给端最近发生了什么"
- "这批检修影响多少产量"
- "帮我做个装置事件时间线"
- "哪些装置的停车还没核实"

## 工作流（6 步）

### 第 1 步：定窗口与口径

写进 `case/datum.json`：

```json
{
  "meta": {
    "product": "甲醇",
    "window_start": "2026-07-20",
    "window_end": "2026-10-20",
    "as_of": "2026-10-20",
    "national_capacity_wt": 10000,
    "weekly_output_t": 2024235
  }
}
```

- `window_end` 一般取当日；`window_start` 按用户要求回推 1 或 3 个月
- `national_capacity_wt` / `weekly_output_t` 只作分母用于量级参照，**必须标注来源与日期**
- 同时确定**工艺路线清单**与**大区划分**（见 `references/01-数据契约.md`）

### 第 2 步：采证（最关键，也最耗时）

按 `references/05-证据渠道与抓取策略.md` 的渠道优先级采集。**渠道的有效性因品种而异，但优先级稳定：**

1. **企业官方公告**（上交所/深交所/巨潮、公司官网、政府核准/环评公示）→ `official`
2. **专业机构装置表/装置动态**（隆众、金联创、卓创、生意社、化销网等）→ `industry`
3. **期货公司研报**（装置清单、开工率、检修量）→ `industry`，但需回溯原始出处
4. **财经媒体转载** → 只作旁证，必须回溯原始机构
5. **社媒/股吧/财富号** → `rumor`，仅登记

采集时**逐条保留原文引用（quote）与链接**，这是后面所有判断的唯一依据。

> 关键经验：装置级事实往往藏在"日评/周报的今日关注点""装置汇总表""竞拍动态"里，而不是在标题含"检修"的文章里。见 `references/05`。

### 第 3 步：建装置档案（消歧）

`case/units.json`，每套装置一条 `unit_id`。**一个企业有几条产线就建几条。** 规则见 `references/02-企业装置消歧规则.md`。

三条硬规则：
- **同一企业不同基地** → 不同 `unit_id`（兖矿国宏 64 万吨 ≠ 榆林兖矿 140 万吨）
- **同一基地不同分期** → 不同 `unit_id`（新奥一期 60 ≠ 二期 60，状态常常相反）
- **上下游一条龙** → 只把目标产品装置建档（斯尔邦的 10 万吨甲醇 ≠ 80 万吨 MTO）

### 第 4 步：登记事件并去重

`case/status_events.json`（已发生）与 `case/planned_events.json`（未发生）**必须分成两个文件**。

每条事件至少要有：`unit_id`、`event_type`、`start_date`、`end_date`、`status_latest`、`confidence`、`sources[]`、`dedupe_check`、`conflict`。

去重规则见 `references/03-事件去重规则.md`：
- 同一 `unit_id` + 同一 `event_family` + 时间窗重叠 → **一条事件，多来源并列**
- 计划日 → 实际执行日的漂移（8/31 计划 vs 9/4 实际）→ **按实际执行日建档，计划日写在 conflict 里**
- 上下游配套装置同名报道（甲醇装置 + 乙醇装置同为"凯越"）→ **不合并，各建各的**

### 第 5 步：算影响量

`skill/scripts/calc_impact.py`，公式见 `references/04-影响量计算口径.md`。

```bash
python skill/scripts/calc_impact.py
```

四条公式：

```
停车/检修/故障：L = 产能/365 × 窗口内天数 × (基准负荷 − 事件期负荷)
降负荷：        L = 产能/365 × 天数 × (基准负荷 − 实际负荷)
新增产能：      A = 产能/365 × 窗口内运行天数 × 爬坡负荷
复产：          不单独计算（可恢复供应已在对应停车事件中体现）
```

**绝对不要**用 `产能 × 天数 / 365` 以外的口径，也不要拿设计产能当减产量。
缺少负荷数值时：给假设值 + `exclude_from_confirmed=true`，让它出现在"未确认"栏而不是确认合计里。

### 第 6 步：出交付物

```bash
python skill/scripts/build_excel.py     # → Excel 台账（12 Sheet）
python skill/scripts/build_html.py      # → 单文件交互式 HTML
python skill/scripts/check_xlsx.py      # → Excel 自检
python skill/scripts/check_html.py      # → HTML 自检
node   skill/scripts/check_html_runtime.js <html>   # → JS 运行期自检
```

**四项自检必须全 PASS 才算完成。**

## 数据契约（一眼看懂）

```
case/
├── datum.json            窗口、分母基准、计算约定
├── companies.json        企业词典（含 aliases）+ 大区 + 工艺路线
├── units.json            装置档案（unit_id 唯一）
├── status_events.json    已发生事件
└── planned_events.json   未来已披露事项（严格分开）
```

字段级定义见 `references/01-数据契约.md`。

## 输出物

### 交互式 HTML（`build_html.py`）
- 装置事件**甘特时间线**（按大区分行、按事件类型着色、可缩放）
- KPI：国内确认减产 / 折合周产量 / 境外影响 / 未确认 / 新增产能 / 建档装置数
- 图表：影响量排行、大区分布、事件类型结构、工艺路线对比
- 明细表：按确认状态、事件类型、大区、工艺、企业筛选 + 关键词搜索
- 点击任意事件 → 抽屉展示企业、装置、产能、起止、**计算公式与中间量**、状态说明、去重核对、全部来源与原文引用
- 一键切换「只看已确认事件 / 含未来计划事件」
- 公式与参数可展开

### Excel 台账（`build_excel.py`）
| Sheet | 内容 |
|---|---|
| 00_说明 | 口径、公式、限制声明、核心结果 |
| 01_装置档案 | 装置主数据 |
| 02_事件清单_已发生 | 已发生事件（含影响量、去重、来源、置信度） |
| 03_事件清单_未来已披露 | 未来事项（物理分表） |
| 04_影响量计算 | 逐事件公式与参数（可审计） |
| 05~08_汇总 | 按企业 / 地区 / 事件类型 / 工艺路线 |
| 09_事件时间线 | 甘特式起止，便于透视 |
| 10_来源与证据链 | 每条事件的链接与原文引用 |
| 11_数据缺口与冲突 | 未知时间 / 未知负荷 / 口径冲突 |

## 三个口径绝不混算

| 口径 | 含义 | 是否进入"国产供给影响" |
|---|---|---|
| `domestic_confirmed` | 国内装置 + 多源印证 | ✅ 是 |
| `overseas` | 境外装置（伊朗、马来、文莱…） | ❌ 只影响进口/到港 |
| `unconfirmed` / `stock_stop` | 传闻、待核、窗口前已停 | ❌ 单列，不并入 |

## 红线

1. **传闻不进确认影响量。**
2. **未来事项与已发生事件分文件、分表、分图例。**
3. **不输出供应预警、价格方向、涨跌预测。**
4. **每个数字都要能追到一个带日期和链接的来源。**
5. **算不出来的就写"算不出来"并给出原因，不要凑数。**
