# 地理数据核验与聚合规则

本文件是 `region-industry-map` 的**硬规则**。任何站点、园区、点位的写入都必须符合这里的规定；
`validate.py` 会机械地拦截其中可机器判定的条目，人负责判不了的那部分。

---

## 0. 一句话版本

> **企业不等于厂区；注册地址不等于装置位置；精确点位必须有可复核的依据；缺数据就写缺，不估算。**

---

## 1. 三级实体模型（先分清你手上的是哪一级）

| 级别 | 是什么 | 例 | 进不进产能合计 | 能不能生成地图点位 |
|---|---|---|---|---|
| **企业（集团）** | 法人主体 / 控股集团 | 山东海化股份有限公司（000822） | 否 | **否**（注册地不是厂） |
| **厂区 / 装置** | 有围墙的实体生产基地 | 海化纯碱厂（老线 120 万吨 + 新线 160 万吨） | 是 | 是（精度达标时） |
| **园区** | 多个厂区的空间容器 | 潍坊滨海化工产业园 | 否 | 是（园区中心） |

写入时：

```json
// companies[]：企业层，只有主体信息
{"id": "haihua", "name": "山东海化股份有限公司", "listed": "000822.SZ"}

// sites[]：厂区层，一行一个厂区，多厂区就多行
{"site_id": "sd-haihua-hs", "company_id": "haihua", "site_name": "山东海化纯碱厂", ...}
```

**最常见的错**：把 `山东海化股份有限公司` 当成一个点，产能 280 万吨，地址写"滨海开发区沂河大街 014201 号"，
经纬度填公司注册地的地理编码结果。这样做的后果是——地图上看着像工厂，其实是工商登记地。

**处理办法**：`site_name` 必须能回答"这个厂区叫什么"，而不是"这家公司叫什么"。
如果只知道公司名不知道厂区名，就写 `site_name = 公司名 + "（厂区未核实）"`，并且 `precision` 最高只能是园区级。

## 2. 地址字段：四个地址，各归各位

一份材料里可能出现四个不同的地址，含义完全不同：

| 地址类型 | 出处 | 能不能代表装置位置 |
|---|---|---|
| **工商注册地址** | 国家企业信用信息公示系统、招股书 | **不能**。可以是一间办公室 |
| **办公/总部地址** | 官网"联系我们"、招聘启事 | **不能** |
| **环评公示建设地址** | 环评报告书/公示的"建设地点" | **能**，且是最可靠的装置位置来源 |
| **生产地址 / 厂区门牌** | 排污许可证、企业"成员企业"页、园区入园名单 | **能** |

落地到字段：

```json
"reg_address": "山东省潍坊市滨海经济技术开发区沂河大街 014201 号",
"reg_address_type": "实际生产地址（注册地同址）",   // 或 "注册地址" / "园区地址" / "镇村地名"
"plant_address": "潍坊滨海经济技术开发区（大家洼）沂河大街 14201 号，潍坊滨海化工产业园内",
"address_type": "园区地址"                          // 或 "实际生产地址" / "镇村地名" / "未核实"
```

### 2.1 "注册地同址" 的正确用法

有些老国企/老厂，注册地址就是厂区门牌（海化即如此）。这时**可以**填
`reg_address_type = "实际生产地址（注册地同址）"`，但：

1. 必须写"同址"两个字，让人一眼看出你核对过，不是复制粘贴；
2. `validate.py` 只有在 `reg_address_type` 含"同址"时才允许"注册地址 == 生产地址 + 精度精确"的组合；
3. 仍然需要独立的坐标来源（门牌号 ≠ 坐标）。

### 2.2 地址里的总部信号词

`plant_address` 里出现以下词，一律不能标"精确"：

```
总部  办公  研发中心  写字楼  大厦  商务区  金融街  CBD  办事处
```

`validate.py` 会拦。真遇到"厂区就在 XX 大厦后面的工业区"，请把工业区名写进 `plant_address`，
门牌号放进 `note`。

## 3. 点位精度四级（决定地图上画什么形状）

```json
"precision": "精确" | "园区级" | "县级" | "市级"
```

| 精度 | 定义 | 判定标准（满足其一） | 地图形状 | 能说"装置在这里"吗 |
|---|---|---|---|---|
| **精确** | 厂区/装置级位置 | ① 有名称匹配的工业用地面（OSM landuse=industrial / 环评附图坐标 / 排污许可坐标）；② 有厂区门牌 + 官方坐标 | ● 圆点 | 能 |
| **园区级** | 知道在哪个园区，不知道在园区哪个位置 | 园区管委会公布位置、园区面心、园区内企业群中心 | ◆ 菱形 | 只能说"在这个园区" |
| **县级** | 只到县/镇 | 镇级地名、镇政府点 | ■ 灰色小方块 | 不能，只作地区记录 |
| **市级** | 只到市 | 城市中心 | ■ 灰色方块 | 不能，只作地区记录 |

**反面规则**：

- 不能因为"镇上的地理编码点离厂址大约 2 公里"就写精确；
- 不能因为"两个点都在同一个园区"就共用一个坐标当两个厂区（`validate.py` 会对 3 个以上站点共用同一坐标报警）；
- **OSM 企业面也要复核**：本 skill 的山东案例里，OSM 的"山东海天生物化工有限公司"多边形落在下营镇以东 7 km 的滩涂，
  与"昌邑下营化工产业园·金晶大道 1 号"矛盾 → 该站点被降级为 **县级**，不用这个面心。
  这类矛盾的处理原则是：**降级，不辩解。**

### 3.1 坐标来源枚举

```json
"coord_source": "企业官网" | "政府公示" | "园区公开资料" | "新闻报道" | "地图地名库" | "人工核对" | "未核实"
```

"地图地名库" = OSM / Nominatim / 高德百度 POI 等，"精确"点位用这个来源时，`note` 里要写清
**是什么要素（node/way/relation、名称、landuse 类型）**，让人能点回复核。

### 3.2 坐标合理性检查

| 检查 | 阈值 | 处理 |
|---|---|---|
| 中国境内 | 经度 73–135，纬度 3–54 | 出界 → error |
| 省内 | 落在目标省范围内（如山东 114.8–122.8E / 34.2–38.5N） | 出界 → 人工复查，多为检索串名（本案例"齐鲁化学工业区"曾检索到新疆工信厅） |
| 重复 | 同一坐标（保留 2 位小数）被 > 2 个站点共用 | warn，要求说明"是否同一园区统一定位" |
| 跨省错配 | 名称含 A 省地名但坐标在 B 省 | 直接作废，重新检索 |

## 4. 产能聚合规则（最容易被抓错的地方）

### 4.1 什么能进合计

进合计的充要条件（三者同时满足）：

```
role == "production"
AND site_type in ("生产工厂", "一体化/配套装置" 中确实是本品种的装置)
AND capacity 是数值（有公开口径）
```

**不进合计**的：

| 类型 | 为什么 | 例 |
|---|---|---|
| 贸易 / 仓储 / 厂库 | 不是产能 | 郑商所交割厂库 3 万吨额度 |
| 以本品为原料的衍生品装置 | 会重复计数 | 小苏打厂（耗纯碱）、过碳酸钠装置 |
| 否证条目（`capacity = null`） | 本来就没有 | 新龙（氯碱企业） |
| 已停产且装置不存在 | 不是当前供给 | 青岛碱业老厂（2015 停） |
| 只有定性描述的"小联碱若干家" | 无口径 | 写进缺口表，不并入 |

### 4.2 多口径并列，不取平均

同一事实常有两个以上公开数字。规则是**并列展示**，用字段说明差异：

```json
"capacity": 280,
"raw_capacity": "年生产能力达 280 万吨（老线 120 万吨 + 新线 160 万吨）",
"capacity_basis": "设计产能（年报'设计产能 280 万吨'，2025 年利用率 97.29%）"
```

省合计有 430（上市公司设计产能）与 450（资讯机构有效产能）两个口径时：
`meta.capacity_scope_total = 450`，`_agg.capacity_sample_total = 430`，两个都在 HTML/Excel 里出现，
`meta.capacity_scope_note` 写明 450 的出处。**不要**把它们平均成 440。

### 4.3 覆盖率与缺口

```
覆盖度 = 样本产能（已落位厂区之和） / 公开口径
```

- 覆盖度 < 100%：差额**不摊派**给已知企业，写进 `narrative.gaps`；
- 覆盖度 < 60%：`validate.py` 报警，产能图与集中度必须标"样本口径"；
- 覆盖度无法算（公开口径未取得）：覆盖度写 `null`，只给样本产能，**不给份额、不给集中度结论**。

### 4.4 城市口径 vs 厂区口径

`cities[].capacity` 是**该城市公开产能口径**，用于和厂区合计数对账：

- 厂区合计 > 城市口径 × 1.02 → `validate.py` **报错**（几乎一定是把姐妹公司/多厂区算重了）；
- 城市口径未取得 → 该字段留空，不要用厂区合计回填（否则覆盖度永远是 100%，掩盖缺口）。

## 5. 项目聚合：毛新增 vs 净增量

```
净增量 = 新增产能 − 退出产能
```

| 项目类型 | 怎么填 | 陷阱 |
|---|---|---|
| 新建 | `capacity` 填新增，`capacity_retired` 填 0 | — |
| 扩建 | 只填**增量**，不是扩建后总产能 | 把"扩至 300 万吨"当成"新增 300 万吨" |
| **技改/置换** | `capacity` 与 `capacity_retired` **都填** | 只填新增 → 系统性高估（山东案例：100 万吨联碱置换 120 万吨氨碱，净减 20 万吨） |
| 退出/关停 | `capacity = 0`，`capacity_retired` 填退出量 | 退出量不可考 → 填 `null` 且**不计入净增合计** |
| 状态未确认 | `net` 留 `null` | 强行给个数字会让合计失真 |

额外要求：

- 每个项目必须有 `status_asof`（状态时点）。项目状态会变，没有时点的项目等于没有状态。
- 项目也要有 `precision` / 坐标或明确写"仅到园区"。
- `impact` 字段写"对区域供需的影响"，但要区分**不同产品**：
  山东案例里"纯碱 -20 万吨，氯化铵 +103 万吨"必须分开写，不能合并成"扩产 100 万吨"。

## 6. 重复计数黑名单

以下情形**几乎一定**导致重复计数，写入前逐条自查：

1. **集团 vs 子公司**：海化集团挂牌 + 山东海化股份上市 + 海化纯碱厂，是同一套装置的三层名字。
2. **一个集团多厂区**：金晶科技 + 山东海天生物化工 + 滕州金晶，是不同厂区，要分列；但"海天纯碱"不能既算在
   "金晶科技（玻璃）"名下又算在"海天（纯碱）"名下。
3. **一期/二期分材料报，但产能已合并披露**：按最新合并口径记，旧口径放 `note`。
4. **"两碱"混写**：烧碱（NaOH）与纯碱（Na2CO3）是不同产品。德州实华"烧碱 39 万吨"、鲁西"烧碱 40 万吨"
   都被误当成纯碱出现过。
5. **衍生品装置**：小苏打、过碳酸钠、硅酸钠的装置耗本品，不是产本品。
6. **停机 ≠ 退出**：海化 2016 年排渣场溃泄临停已恢复；停产检修（海天 2024-09 检修）不是产能退出。
7. **历史产能 vs 当前产能**：青岛碱业 2005 年 80 万吨，2015 年停产，不能计入 2026 年的合计。

## 7. 园区数据的边界

- 园区内"已核实落位厂区数"**只数** `sites[]` 里 `park_id` 指向该园区的站点；
- 园区宣传页上"入驻企业 120 家"是**园区口径**，写进 `supporting` 或 `note`，**不要**变成 `n_parks` 或企业数；
- 园区级别要区分：省级化工园区（有省政府认定名单）/ 市级化工集聚区 / 专业园区（如"玻璃新材料产业园"）；
- 园区坐标多为估算（本案例 11 个园区中 6 个无 OSM 面），必须在 `coord_basis` 写明"以 XX 企业群中心代表，±N km"。

## 8. 上游 / 下游 / 物流的空间规则

| 数据 | 允许的粒度 | 禁止 |
|---|---|---|
| 上游原料产地 | 矿山/盐场/供应商名 + 地市 | 用"全省"当产地还给它坐标 |
| 下游消费企业 | 企业 + 城市 + 产线规模（原文） | 由产线规模反推"年耗碱 X 万吨"（无单耗来源时） |
| 物流节点 | 港口/铁路站/交割库/市场 + 可查吞吐或库容 | 按里程推算运价、按产量推算运量 |
| 流向（flows） | 有公开来源的"某厂→某港/某线" | "该厂大概从内蒙买碱"这类推理 |

## 9. 交付前地理自查清单

- [ ] 每个 `precision = 精确` 的站点，`note` 里能读出"这个坐标是什么要素/什么依据"
- [ ] 没有用注册地址/总部地址生成的点位
- [ ] 同一园区内多个厂区是否被误合并成一个点
- [ ] 已停产/已退出的装置是否被排除了坐标
- [ ] 园区坐标是否写明误差范围
- [ ] 省外/境外的坐标是否被误当成省内（串名检索的典型后果）
- [ ] 跨省参考数据（如"金晶宁夏石嘴山基地"）是否被误算进本省合计
- [ ] 5 个以上城市"无数据"时，是否在缺口表里成体系地说明原因

## 10. 与脚本的对应关系

| 规则 | 代码位置 | 级别 |
|---|---|---|
| 注册地址 == 生产地址 + 精确 + 未注同址 | `validate.py` §2 | error |
| 生产地址含总部/写字楼关键词 + 精确 | `validate.py` §2 | error |
| 坐标越界 / 精确无坐标 | `validate.py` §3 | error |
| 3 个以上站点共用坐标 | `validate.py` §3 | warn |
| 城市站点产能 > 城市口径 × 1.02 | `validate.py` §5 | error |
| 覆盖度 < 60% | `validate.py` §5 | warn |
| 原文数字与 `capacity` 单位不匹配 | `validate.py` §4 | warn |
| 重复站点（同名同址） | `validate.py` §4 | warn |
| 项目缺 `status_asof` | `validate.py` §1 | error |
| 净增量为负却没填 `capacity_retired` | `validate.py` §1 | warn |
| 引用未登记 source id | `validate.py` §1 | error |
| 聚合（按城市/省、CR/HHI、覆盖率、净增量） | `common.normalize()` | — |
| 点位形状（精确=圆、园区=菱形、县市=方块） | `templates/report.html` | — |
