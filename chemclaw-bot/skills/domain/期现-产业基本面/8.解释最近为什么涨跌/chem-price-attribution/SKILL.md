# 期现及产业基本面研究：解释价格为什么涨跌

给产业研究员／交易员一份**经得起反问**的归因底稿。行情涨了，老板问为什么——
这份报告的回答是「哪些因素有数据支持、哪些只是时间吻合、哪些根本没有证据」，
**不是**一个听起来顺耳的单因故事。

品种无关：换品种只换 `case.json` 与 `raw/` 数据。

## 五条硬规矩（违反任何一条，此次交付作废）

1. **先复核涨跌幅，再解释。** 起止日期由真实价格数据确定，不由叙事需要确定。
   同一波行情换个起点能差出十几个百分点，所以报告第一节必须是"到底涨跌了多少"。
2. **不许预测。** 全文禁出现「预计／看涨／看跌／抄底／见底／后市将」。
   说明"发生了什么、什么对得上"，不说明"接下来会怎样"。
3. **不许伪精确。** 除非建立并验证了量化模型，**不得**写"成本解释了 40%、进口解释了 30%"
   这类百分比拆分。排序只是排序工具，不是分解。
4. **每个因素都要有实数或明确标注「无可用数据」。** 不许因为拿不到数据就整段省略，
   也不许用行业经验值（如煤单耗 1.6–1.8 t/t）冒充实际成本。
5. **相关不等于因果。** 时间吻合只写"时间吻合"，必须与"数据支持"分开标记。

## 十因子检查清单（缺一不可）

| # | 因素 | 检查什么 | 常见坑 |
|---|---|---|---|
| 1 | 本品种期现价格 | 现货、主连、**同一合约**三条线 | 主连换月当天的名义价会被误当成行情 |
| 2 | 上游原料成本 | 原料现价、理论成本变化 | 理论成本需要真实单耗，拿不到就写缺口 |
| 3 | 能源价格 | 原油、煤炭、天然气 | 煤炭要用到厂价口径，不是坑口价混用 |
| 4 | 装置检修/复产/开工率 | 停车、复产、周度开工率、周产量 | 检修故事不等于方向，要看开工率是升还是降 |
| 5 | 新增产能 | 投产时间、产能规模 | 已投产 vs 计划投产要分开 |
| 6 | 进出口与贸易政策 | 到港量、进口利润、关税/制裁 | 到港量是滞后指标，别当领先指标 |
| 7 | 库存及结构 | 港口库存、企业库存、期货仓单 | 库存数据和价格常常同步，谁是因谁是果说不清 |
| 8 | 下游需求 | 下游价格、开工率、利润、负反馈 | 下游亏损到停车通常有滞后，滞后几天要算清楚 |
| 9 | 政策/事故/突发事件 | 制裁、航运、事故、限产 | 同一天多条事件必须按影响方向分列 |
| 10 | 期现结构 | 基差、月差、持仓迁移 | **基差/月差是结果变量，不是原因** |

## 七步

### 第 0 步：定口径

问清四件事（用户没说就用括号里的默认，并在报告首屏标注）：
品种与规格、市场/区域、**起止日期（默认：最近一次明显波动的完整区间）**、有无期货。

**日期不能拍脑袋。** 先抓价格序列跑异动识别，让数据决定区间：

```bash
python scripts/detect_anomalies.py --series raw/MA0_daily.json --from 2026-06-01 --to 2026-10-19
```

完成标准：窗口起止日期能被一条具体的价格事实支撑（如"2026-06-30 为两来源共同确认的局部低点"）。

### 第 1 步：抓价格（期货 → 现货 → 结构）

期货用新浪 `InnerFuturesNewService.getDailyKLine`，现货用生意社／100ppi。
**必须同时抓主连和逐合约两条序列**——第 10 项因素和第 1 项复核都要用。
抓完立刻做**换月体检**：找出主连切换日，记录当日主连与主力合约的价差。
本案例中该价差达 412 元/吨，直接决定了"现货涨 41%、期货只涨 29%"是真还是假。

### 第 2 步：抓十个因子

逐项按上表抓数。抓不到的**当场记进 `gaps`**，不要留到最后补。
煤炭用 CCTD 环渤海 5500 大卡现货；原油用 SC 主连；下游用对应期货品种或产业周报。
行情的周度数据（开工率、库存、到港）通常是**周频**，落库时保留原始披露周期，不要伪装成日频。

### 第 3 步：写 `case.json`

这是唯一的手工输入。结构见 `references/case-schema.md`。每个因子下：

- `series[]` — 有逐日数据的指标，脚本会自动算同期变化、z 值、分位、方向一致性；
- `manual[]` — 只有报告披露值的指标（如"周度开工率 83.8%"），必须写清 `date` 与 `src`；
- `events` — 带日期的事件，必须能追到原始链接。

**来源 URL 一律写进文件**，不许只写"据卓创"。

### 第 4 步：一条命令跑完

```bash
python scripts/build_all.py --case examples/01-methanol-huadong-2026Q3/case.json
```

依次执行：异动识别 → 时间对齐 → 证据分级 → 汇总 → 生成 HTML → 生成 Excel → 三道自检。
任何一步失败即中止。全部通过会打印 `HTML 通过 / Excel 通过 / 引擎 通过`。

### 第 5 步：写叙事（`narrative.json`）

脚本能算出所有数字，但**解释的措辞必须人来写**。写的时候守三条：

- 每个阶段的结论都要能被该阶段的数字反驳（写出来就该想到"如果煤价反而在跌呢"）；
- **主动写反证**：本案例第 5 条假设就是"国内装置检修导致供给收缩"，证据等级 **E4，方向相反**
  （开工率 83.8%、环比 +1.1pct，产量在增），这条假设必须留在报告里，不能悄悄删掉；
- "未解释的片段"必须有独立章节。

### 第 6 步：复核

三道自检已由 `build_all.py` 自动跑。人工再确认：

- 打开 HTML，抽查三个因子的抽屉（同期图表、变化幅度、原始来源、证据判断四件齐全）；
- 在"框选区间做局部归因"里拖一段，确认反证因子被点名；
- 打开 Excel 的 `12_复算校验` 表，全部为"是"；
- 全文搜一遍禁用词（脚本已查，人工再确认语感）。

### 第 7 步：交付

HTML + Excel 两个文件，加上"这份报告不能说明什么"一节。
交付话术见 `references/delivery.md`。

## 证据四级（本 Skill 的核心）

| 等级 | 含义 | 判定条件 | 措辞 |
|---|---|---|---|
| **E1** | 数据支持 | 有逐日数据，窗口变化 |z|≥1.0 且方向与价格一致 | "数据显示……" |
| **E2** | 数据 + 时间吻合 | 达到 E1，且事件落在价格阶段起点前 1–3 个交易日 | "数据显示……，且事件时点吻合" |
| **E3** | 仅时间吻合 | 只有可比事件、或指标方向一致但不显著 | "时间上吻合，但缺少数据支持" |
| **E4** | 缺乏证据／无法检验 | 无数据，**或方向相反** | "无法检验"／"方向相反，不能解释" |

方向相反的因子**一律 E4**，即使 z 值很大。详见 `references/evidence-grading.md`。

## 这个 Skill 不做什么

- 不预测价格；
- 不做百分比归因分解；
- 不把"时间吻合"写成"原因"；
- 不在缺数据的位置编数；
- 不因为客户想听某个原因就把它排到第一。
