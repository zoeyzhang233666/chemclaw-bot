# 真实踩过的坑与修法

每一条都是在做华东重质纯碱案例时**真的撞到**的，附现象、根因、修法。

---

## 一、数据获取

### 1.1 100ppi 反爬：返回 636 字节的拦截页

**现象**：请求返回 HTTP 200，但正文只有 636 字节，内容是一个 `HW_CHECK` cookie 校验页。

**根因**：站点先下发 cookie，再校验；连续请求过快时直接放弃。

**错误应对**：`for i in range(4): get(url)` 密集重试。结果**越重试封得越久**。

**正确修法**：

```python
GAP = 2.5          # 全局最小请求间隔（秒），类级别，所有请求共享
COOLDOWN = 60.0    # 被拦后的基础冷却

def fetch(url, max_tries=6):
    for k in range(max_tries):
        time.sleep(GAP)
        r = _get(url)
        if r is not None:
            return r
        time.sleep(COOLDOWN * (1 + k))    # 冷却时间随重试次数线性递增
    return None
```

要点：**降速 + 递增冷却**，而不是提频重试。实际速率约 4 篇/秒是安全的。

### 1.2 频道路径搞错，永远拿到拦截页

**现象**：`chem.100ppi.com/news/list--533-*.html` 100% 拦截。

**根因**：cookie 是按域下发的，`chem.` 域拿不到 `soda.` 域的校验 cookie。

**修法**：用商品自己的子域：`soda.100ppi.com/news/list--12-N.html`。
页码从 **1** 开始（第 0 页是无效页）。

### 1.3 图表页数据解不出

**现象**：ECharts 的数据塞在一段自定义编码里，`f.d` 这种 token 无法直接读。

**根因**：自定义 packer，token 是 36 进制索引。

**修法**（已验证 92 个 token 全对）：

```python
# 值：k[int(token[0], 36)] + "." + k[int(token[-1], 36)]
# 日期：月份段用 36 进制解码；"日"段直接用字面十进制数字
```

**但要认清它的局限**：图表只有约 88 个点。**只有 88 个点算不了 3 年分位。**
图表数据只能用来交叉校验，不能当主序列。

### 1.4 侧边交易站点 SSL 断连

**现象**：`SSL: UNEXPECTED_EOF_WHILE_READING`，第一次成功后续全挂。

**根因**：IP 级限流。

**修法**：换源，不要死磕。案例中放弃 Mysteel 改用 100ppi。

## 二、解析

### 2.1 调整量串产品：轻质的「下调 70」被记到重质头上

**现象**：`2026-07-28` 解析出重质下调 70 元/吨，但原文是「重质下调 50 元/吨，轻质下调 70 元/吨」。

**根因**：`re.search(r"下调\s*(\d+)")` 只取第一个匹配，而正文里轻质可能排前面。

**修法**：**按产品分段抓取**，先在文本中定位「重质纯碱…」与「轻质纯碱…」各自的片段，再在片段内取调整量：

```python
def grab_adj(text, product):
    # 只在 product 之后到下一个产品名词之前的片段里找调整量
    seg = slice_between(text, product, ["轻质纯碱", "重质纯碱"])
    m = re.search(r"(下调|上调)\s*(\d+)", seg)
    ...
```

**校验**：修完后 `2026-07-28` → 重质 1180–1250 下调 50，轻质下调 70，与原文一致。

### 2.2 数据日期 ≠ 发布日期

**现象**：URL 是 `detail-20260728`，正文说的是「7 月 27 日重质纯碱下调 50」。

**根因**：日评次日发布昨日行情。

**修法**：从正文里抽数据日期；抽不到时，若正文提到「昨日/上一交易日」则 `-1` 天。
**入库前必须校验**：序列日期若整体比真实行情晚一天，分位与涨跌幅全部偏移。

### 2.3 不分规格的报价不能硬塞

**现象**：2022–2023 年大量「华东地区纯碱主流报价 1300 元/吨」，无规格。

**错误做法**：当成重质入库（凑数）。
**正确做法**：**排除，并记录排除条数**（案例中 5 条）。

排除要在报告里说明：「早期 5 条为不分规格报价，已排除，未作重质处理」。

## 三、统计

### 3.1 区间位置冒充分位（最危险）

**现象**：当前价恰为窗口最低，`(P-min)/(max-min) = 0.00%`，直接当「历史 0% 分位」上报。

**真相**：真实经验分位是 **0.72%**（含并列）/ **0.36%**（中位秩）——
历史上有 0.72% 的**报价日**不高于今天，不是 0%。

**修法**：三个口径并列输出，区间位置列标题必须写「（非分位）」。

### 3.2 「3 年分位」其实是 2 年

**现象**：报了 3 年分位，但该口径 2024-07 才开始披露。

**修法**：
1. 逐月覆盖率表定位断点月；
2. 窗口表里**必须**同时给 `from / to / n_obs`；
3. 「5 年」与「3 年」样本数相同时，**显式说明**这是口径历史长度所致。

### 3.3 波动率用 √252 算错了

**现象**：年化波动率偏低。

**根因**：现货报价不等距（节假日、漏报），当成每日等距会低估。

**修法**：按**真实自然日差**折算日均收益，再 `× √365`：

```
g_t = ln(P_t/P_{t-1}) / (date_t − date_{t-1}).days
ann_vol = std(g) × √365
```

### 3.4 用均值±kσ 找异常，异常点自己把阈值抬高

**现象**：几个极端值进去后，它们自己不算异常了。

**修法**：用 **MAD 稳健 z**（`0.6745×(x−median)/MAD`），median 与 MAD 不受极端值牵动。

### 3.5 三条判据合并成一句「异常」

**现象**：一次跳变既触发 `jump` 又越 `IQR`，被数了两次，异常总数虚高。

**修法**：三条判据**分别列**，不去重、不合并、不给「异常总数」这个容易误导的合计数。

## 四、交付

### 4.1 中文 print 到控制台是乱码

**现象**：`print("华东")` 在 Windows 控制台显示为乱码。

**修法**：所有 QA 输出写到 UTF-8 文件，再用文件读取工具看；运行前设 `PYTHONIOENCODING=utf-8`。

### 4.2 PowerShell heredoc / 内联正则必坏

**现象**：`Set-Content`、heredoc、`python -c "含有中文和正则"` 各种转义炸裂。

**修法**：Python 源码一律用文件写入工具落盘再执行，不要走 shell 内联。

### 4.3 Excel 公式写进去但客户打开是空/报错

**现象 1**：openpyxl 只写公式不写缓存值 → 不重算就是空白。**修法**：`wb.calculation.fullCalcOnLoad = True`。

**现象 2**：`#NAME?`。**根因**：用了 `MINIFS/MAXIFS/AGGREGATE`，旧版 Excel 与部分 LibreOffice 没有这些函数。

**实测补充（重要）**：`STDEV.S` 也会 `#NAME?`——
openpyxl 存盘时会把函数名规范化成小写 `stdev.s`，部分引擎就解析不了。
**修法：一律用 `STDEV`**（同为样本标准差 n−1，语义完全一致）。同样的道理，`QUARTILE.INC`
也要换成 `QUARTILE`。

**已实测在本环境不可用的写法**（全部会返回错误值或 0）：

| 写法 | 结果 | 换成 |
|---|---|---|
| `MINIFS(...)` / `MAXIFS(...)` | `#NAME?` | 辅助矩阵 + `MIN/MAX` |
| `AGGREGATE(15,6,...)` | `#NAME?` / `#DIV/0!` | 同上 |
| `STDEV.S(...)` | `#NAME?` | `STDEV(...)` |
| `QUARTILE.INC(...)` | `#NAME?` | `QUARTILE(...)` 或不用 |
| `MIN(IF(cond, rng))` 数组 | 返回 0 | 辅助矩阵 |
| `INDEX(IF(...),0)` | `#REF!` | 辅助矩阵 |
| `SUMPRODUCT(MAX(...))` | 返回 0 | 辅助矩阵 |
| 把区间赋给变量再代进 `%` 格式化 | 区间被当文本 | 改用 `.format()` + 显式拼接 |

**唯一 100% 稳的套路**：

```
辅助矩阵：每行一条原始观测，每列一个窗口
单元格 = IF((日期>窗口起)*(日期<=窗口止), 价格, "")     ← 最简标量公式
统计   = MIN(列) / MAX(列) / MEDIAN(列) / STDEV(列) / COUNT(列)
```

> 教训：**Excel 公式不是写完就算数，必须真跑一遍重算再看结果。**
> 这正是 `check_xlsx.py` 存在的意义——它会扫全簿错误值，把 `#NAME?` 一个不漏地揪出来。

**修法**：改用**辅助矩阵 + 普通 MIN/MAX/MEDIAN**：

```
辅助矩阵：每行一条原始观测，每列一个窗口
单元格 = IF((日期>窗口起)*(日期<=窗口止), 价格, "")
统计 = MIN(该列) / MAX(该列) / MEDIAN(该列)
```

每个单元格都是最简标量公式，**不依赖数组求值规则**（数组 `IF`、`INDEX(IF(...))`、
`SUMPRODUCT(MAX(...))` 在不同引擎上行为不一致，实测会返回 `0`、`#REF!`、`#DIV/0!`）。

**现象 3**：公式算出来是对的，但客户说「我改了个价格它没变」——
说明分位列其实是**粘贴的数值**。**修法**：`check_xlsx.py` 检查单元格是否以 `=` 开头。

### 4.4 Python `%` 格式化与公式字符串互殴

**现象**：`'=IF($D%d<1,"",MIN(%s%d:%s%d))' % (...)` 报 `not enough arguments`，
或公式里的 `%s` 被吃掉。

**根因**：单元格引用文本里含 `%s`，被外层 `%` 格式化当成占位符；`$D%d` 里的 `%d` 也在消耗参数。

**修法**：含多个占位符的公式串改用 `.format()`，或用 `％` 之外的拼接方式：

```python
ws.cell(rr, 5, '=IF($D{r}<1,"",MIN({g}))'.format(r=rr, g=rngtxt))
```

### 4.5 HTML 移动端横向溢出

**现象**：1440 宽正常，420 宽溢出 162px。

**根因**：CSS Grid 子项默认 `min-width: auto`，内部 canvas 把网格撑破。

**修法**：

```css
.grid2 > *, .grid3 > * { min-width: 0; }
.tscroll { overflow-x: auto; }        /* 宽表格各自滚动，不撑页面 */
```

**配套**：测溢出前必须等 ECharts `resize()` 完成，否则会把「没重排」误报成「溢出」。

### 4.6 分位带画在错误的序列上

**现象**：多条序列同框时，分位带跑到了辅助序列上。

**修法**：分位带只对**当前单一选中序列**生效；选中「三者对比」时关闭分位带并提示。

## 五、一个反直觉的发现

### 轻质比重质贵，是数据错了吗？

**现象**：2026-07 华东轻质 1270 > 重质 1215，轻质比重质贵。

**判断**：不要急着改数据。先查：
1. 原文是否确实如此（案例中确实如此）；
2. 是否长期如此，还是阶段性反常规。

**处理**：在报告中**如实呈现并标注**「当期轻质报价高于重质，与通常价差方向相反」，
让读者自己判断，而不是替数据打补丁。

> 数据诚实的原则：**异常要标出来，不要修正掉**。修正了就变成编造。
