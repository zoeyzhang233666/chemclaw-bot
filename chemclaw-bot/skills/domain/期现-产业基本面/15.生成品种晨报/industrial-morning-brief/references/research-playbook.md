# 数据采集手册：来源、陷阱与交叉核对

本手册回答一个问题：**每个数字该去哪里拿，拿到后怎么确认它没骗我。**

---

## 1 期货行情

### 可用来源

东方财富公开接口，无需 key：

```
日线： https://{host}/api/qt/stock/kline/get?secid={secid}
        &fields1=f1,f2,f3&fields2=f51,f52,f53,f54,f55,f56,f57,f58
        &klt=101&fqt=0&beg=20250101&end=20500101
合约列表： https://futsseapi.eastmoney.com/list/{market}?...
```

`host` 用 `push2his.eastmoney.com` / `23.push2his.eastmoney.com` / `45.push2his.eastmoney.com` 轮换。

### 陷阱

**① 单 host 会失败**。`Remote end closed connection without response` 是常态，必须 host 轮换 + 指数退避重试。`fetch_futures.py` 已内置。

**② `push2.eastmoney.com/api/qt/clist/get` 会 502**。枚举合约请改用 `futsseapi` 的 list 接口。

**③ secid 前缀与代码大小写**：

| 交易所 | 前缀 | 代码格式 | 示例 |
|---|---|---|---|
| 郑商所 | 115 | 大写 | `115.MAM`（主连）、`115.MA701` |
| 大商所 | 114 | 小写 | `114.ppm`（主连）、`114.pp2701` |
| 上期所 | 113 | 小写 | `113.cum` |
| 上期能源 | 142 | 小写 | `142.scm` |
| 广期所 | 225 | 小写 | `225.lcm` |

**④ 次主连常常取不到**。`115.MAS`、`114.pps` 会返回 0 行。需要次主力时，直接取具体月份合约。

**⑤ 已到期合约返回空**。探活时若 `rc=100`，先确认这个合约月份是否已经交割（例如 2026 年 10 月做研究，`2601` 之前的合约都已到期）。

**⑥ 主连换月跳接**。见 `change-detection.md` 第 7 节。取主连时务必同时取主力实际月份。

### 交叉核对

拿到的期货收盘，用现货网站的「现期表」或「期货结算表」核一遍。本案例中东方财富 10-19 甲醇主力收盘 3,143，与生意社结算表 `MA2701 结算 3,143` 一致后才采用。

## 2 现货价格

### 可用来源

| 来源 | 覆盖 | 特点 |
|---|---|---|
| 同花顺 iFinD 新闻稿 | 甲醇 15 区域、PP 4 区域、PVC 5 规格 | 逐区域逐规格，附涨跌；晚间更新当日全量 |
| 生意社（100ppi） | 基准价、现期图、基差率 | 有 90/180 日均值与历史区间 |
| 隆众/卓创（经新浪、同花顺转载） | 日评、周报 | 有库存、开工、利润等基本面 |
| 我的钢铁网 | 化工品 | 直接抓取常超时或遇验证码 |

### 陷阱

**① 旧闻新发**（最危险）。搜索引擎按标题命中，会把**去年同一天**的稿件端上来。

真实案例：搜「10月20日甲醇价格汇总」，命中的 `licai.jiantou8.com` 页面，正文写着「发布时间：2025-10-20」，价格是 2,275 元/吨——与 2026 年的量级完全不同。另一个命中 `nenghua.m.mysteel.com/a/25102017/...`，URL 里的 `251020` 就是 2025-10-20。

**核对方法**：打开页面看发布时间戳、看 URL 里的日期编码、看价格量级是否与当下吻合。三者任一不符即弃用，并记入 `excluded`。

**② 品牌报价 ≠ 市场成交价**。同花顺给的是「上海 T30S 中油 10,900」，实际市场成交可能低 100–200 元。基差计算要注明用的是品牌报价。

**③ 报价更新不齐**。10-19 收盘稿通常当晚 20:00–23:00 发布；10-20 的盘前报价要等次日 9:00 后。若在 10:00 截稿，当日只有个别企业报价（如临沂），其余区域尚未发布——这时应当**只用已发布的**，把未发布的写进缺口，而不是拿昨天的数据当今天用。

**④ 单位与规格陷阱**。甲醇有「国标/精醇」，PVC 有「电石法/乙烯法、五型/三型」，PP 有「拉丝/注塑/共聚」。混用会让价差毫无意义。

### 交叉核对

同一区域至少两个来源对齐才算数。本案例华东 PVC 电石法：同花顺 4,845.93，与生意社基准价 4,865.00（10-20）方向一致、量级吻合，采信并注明口径差异。

## 3 基差与月差

### 算法

```
基差 = 含税现货 − 不含税期货
月差 = 近月收盘 − 远月收盘（正=近月升水）
```

### 陷阱

**① 极值不等于套利机会**。甲醇基差一度达 822 元/吨（基差率约 20%），看起来「现货比期货贵很多」，但含税与不含税本身就有约 13% 的差，且交割有仓储、运输、品质升贴水成本。**只能作结构观察，不能下套利结论。**

**② 月差要用同一时点**。MA2701 与 MA2705 必须同一天收盘相减，不能一个用 10-19、一个用 10-16。

**③ 近月即将交割时月差失真**。MA2611 临近交割，其与 MA2701 的升水反映的是交割博弈而非供需。

### 交叉核对

生意社「现期表」直接给 90/180 日均基差率，可作为参照。甲醇 180 日均 9.73%、90 日均 11.03%，当前 20% 明显偏离，这个「偏离度」本身就是有信息量的事实。

## 4 库存 / 开工 / 产量 / 下游

### 可用来源

卓创资讯、隆众资讯的周报（常经申银万国、广州期货、中信期货等机构晨报转引，可在同花顺/新浪财经找到），金联创的日度评论。

### 陷阱

**① 周度数据不是当天数据**。库存「截至 10-15」在 10-20 的晨报里出现时，必须写「截至 10-15」，并标 `stale_days=5`。

**② 口径差异大**。同样是「甲醇沿海库存」，卓创样本港口与隆众口径可能差 2–3 万吨。引用时必须写明「卓创样本」，不要混用两家数据算环比。

**③ 机构转引会丢单位**。看到「开工 61.5」要确认是 % 还是万吨/日。

**④ 「大幅累库」这类定性描述没有数字**。这属于 C 级（无量化），要么找到具体数字，要么写进缺口。本案例 PP 社会库存就只有定性描述，因此列入缺口。

### 交叉核对

多口径并列是加分项。本案例 PVC 开工同时拿到「整体 61.50%（环比 -2.99pct）、电石法 67.21%、乙烯法 48.71%」，三个数字互相自洽（加权后落在整体值附近）才采信。

## 5 进出口与政策

- 海关数据经生意社/隆众整理发布，注意**发布日与数据月份不同**（9 月数据在 10 月中下旬发布）。
- 政策类信息必须找到**原文公告**或权威转载，不能只用二手解读。
- 事件日期与数据日期要分开记：装置「10-10 停车」是事件日，机构「10-19 报道」是发布日，晨报应当用事件日。

---

## 6 事件类信息的采集纪律

每条事件至少记七个字段：

```
event_date    事件发生日（不是报道日）
entity        主体（装置名/公司/海峡/机构）
quant         量化影响（产能、百分比、金额、天数）
impact_path   影响路径（上游成本→中游开工→下游需求，写清链条）
status        done 已兑现 / ongoing 持续 / plan 计划未兑现
source + url  来源与链接
event_type    类型（决定去重时的类型族）
```

**写不出 `impact_path` 就不要收这条**。这是 C/D3 规则的人工前置判断。

### 持续型事件的处理

地缘冲突、长期停车这类事件会连续多日报道。第一次出现记为当日事件；此后每次只记「进展」，并在 `repeat_note` 说明。不要每天把「霍尔木兹海峡仍然受阻」当成新的 A 级事件——读者会立刻发现你在凑篇幅。

## 7 检索环境的现实约束

开发本技能时实测的可用性：

| 通道 | 状态 |
|---|---|
| `advanced_search` + `engine: exa / tavily` | 可用 |
| `web_fetch` 抓 同花顺 / 100ppi / 新浪财经 | 可用 |
| 内置 `web_search`（apihub/bing） | 曾返回 HTTP 500 / 超时 |
| sina hq 行情接口、tencent qt.gtimg.cn 期货 | 不可用 |
| mysteel.com 直抓 | 超时或遇验证页 |
| 需要 key 的通道（jina / kimi / doubao） | 无 key |

因此工作流应当设计成：**主力靠公开 API 拿行情，靠 exa/tavily 检索 + web_fetch 抓现货与基本面，任何一路失败都有替代来源**。若某类数据全部来源都不可得，正确做法是写缺口，不是估一个。

## 8 采集完成后的自查

- [ ] 每个价格都有规格、区域、单位、税基？
- [ ] 每个数字都有发布日期，且与事件日期分开记？
- [ ] 期货与现货的时点一致（同为收盘或同为盘中）？
- [ ] 旧闻是否已通过时间戳/URL 排除？
- [ ] 周度/月度数据是否标了「截至 X 日」而非「今天」？
- [ ] 拿不到的是否都进了缺口表，而不是被估算值填满？
- [ ] 每条事件的 `impact_path` 是否真的能写出来？
